:::note 先说结论
便利性上托管平台完胜，但「内容所有权 + 可以随便折腾」这两件事，只有自己的站能给。本文就是折腾过程的第 0 篇记录。
:::

## 三个理由

### 1. 内容所有权 {{badge:核心理由}}

放在平台上的内容，格式、排序、可见性都由平台说了算。自己搭的站，内容就是 `src/content` 下的文本文件，用 git 管理，随时可以搬走{{badge:Markdown 永不过时}}。

### 2. 前端是自己的练兵场

个人站是少有的「需求自己定、代码自己写、线上随便挂」的完整场景。站点目前的配置：{{link:https://vite.dev|Vite|构建工具，内容管线就长在它的 glob 能力上}}{{link:https://vuejs.org|Vue 3|视图层，内容系统最后渲染成 Vue 组件}}

### 3. 小的自由的堆叠

想加个标签云就加个标签云，想换字体就换字体。这些自由单看都微小，堆起来就是「这是我的地方」的感觉。

## 怎么搭的

内容系统是标签驱动的：每篇内容在 frontmatter 里声明 `tags`，首页与博客列表都基于同一个 registry 查询：

```yaml
---
title: 为什么自己搭个人站
tags: [post, 建站]
---
```

正文里还能用一小套扩展语法，比如容器、徽章和标签跳转：

```text
:::warn 注意
::: 开头的容器会渲染成提示框
:::

行内的 {{badge:徽章}} 与 {{tag:建站}} 会渲染成徽章与标签链接。
```

上面代码块里的语法没有被真的转换——这正是管线的约定：代码块里的内容永远是字面文本。

## 代价也说清楚

:::warn 代价
要自己维护构建与部署，流量大了要自己操心，写完还要自己检查排版——没有平台帮你兜底。
:::

这些代价换来的东西对我而言值回票价：这个站本身就是作品的一部分，而不只是内容的容器。技术选型的细节写在 {{tag:前端}} 分类里，站点最初的动机则要回到 {{tag:随笔}} 的第一篇。
