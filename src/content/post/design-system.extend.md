给这个站做视觉的时候，定过一条规矩：**先有令牌，再有界面**。颜色、圆角、间距、字体全部收进 `src/styles/tokens.css`，组件只许引用令牌，不许裸写。这篇就把这套设计系统盘一遍——正好，内容侧刚上线了一批扩展语法组件，本文本身就是它们的演示场。{{badge:全程真实}}

## 地面：极光与玻璃

站点的基础是「夜间极光」：深海军蓝黑的地面，四条斜向光带（蓝、青、绿、紫），玻璃面板一律 1px 冷描边。橙色只作点题——口号里的关键词、旗舰卡的徽章，不做大面积。

这些不是一个个组件里各画各的，而是同一组令牌的投影：`--bg-*` 管地面层级，`--fg-*` 管文字层级，`--glass-*` 管玻璃光学层。改一处令牌，全站跟着变——这也是为什么内容系统的样式（本文里所有组件的样子）只引用令牌，两种主题都能自动成立。

:::note
本节说的令牌体系在 `src/styles/tokens.css`，文件头注释里写着它的来历与规则：新增令牌必须同步契约文档，裸写颜色会被打回。
:::

## 文字里的按键

写建站文章难免提到快捷键。新增的行内语法 {{kbd:Ctrl|K}} 可以把按键排成键帽的样子：在编辑器里 {{kbd:Ctrl|S}} 保存，{{kbd:Cmd|Shift|P}} 打开命令面板，或者终端里 {{kbd:Ctrl|C}} 停掉 dev server。多键用竖线分隔，单键也可以：{{kbd:Esc}}。

## 步骤

想给这个站添一篇用上扩展语法的文章？流程就四步：

:::steps
1. 建文件 | 在 src/content/posts/ 下新建 md，文件名即 slug，全站唯一
2. 写 frontmatter | title 与 tags 必填，tags 记得带上 post
3. 正文用语法 | ::: 容器与 {{}} 行内模板随意组合，代码块里的写法不会被转换
4. push 即上线 | main 分支推送后自动部署，列表页按 date 降序排好
:::

## 问答

:::faq
- 扩展语法在代码块里会生效吗？| 不会。管线对围栏代码块与行内代码保持字面文本，本文后面有反例演示。
- 文章存在哪里？| src/content 下的 markdown 文件，git 管理，随时可以整体搬走。
- 怎么发新文章？| 本地放 md 文件 push，或者在仓库开 issue 打上 blog 标签走自动管线。
- 为什么不用现成的博客框架？| 便利性上框架完胜，但「内容所有权 + 可以随便折腾」只有自己的站能给，理由展开见 {{tag:建站}}。
:::

## 字面文本约定

所有语法对代码块保持原样——所以下面这段演示语法的代码不会被真的转换：

```text
:::timeline

:::

行内写法示例：{{kbd:Ctrl|K}} 与 {{badge:徽章}}。
```

上面这段的渲染结果就是它本身。想看真组件，往上翻。

## 收尾

这套扩展语法都是管线里的 PreTransformer / PostTransformer：`:::` 容器走「抽取 → 递归渲染 → 占位回填 → 重写」，`{{}}` 行内走「代码感知替换」。渲染主流程零改动，写语法的文章不需要注册任何东西。语法速查在 docs/BLOG.md，契约细节在 docs/CONTRACTS.md §2.3。

:::tip
发现哪个组件样式不对劲，多半是令牌被改了而不是组件坏了——顺藤摸瓜去 tokens.css。
:::
