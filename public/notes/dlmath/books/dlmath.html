两层网络：前向、梯度与训练

学习目标看完这一单元，你应该能
  • 手写一个两层网络的前向传播，说清每一步的形状与激活函数的作用；
  • 推导并写出反向传播的四个式子，指出最容易漏掉的链式因子；
  • 用中心差分独立地算出数值梯度，与解析梯度逐项对拍；
  • 解释为什么「程序打印 PASS」不算证据，以及阴性对照为什么必须有；
  • 用固定种子复现一次训练，并说清种子对照为什么能证明输出不是硬编码。

1.1 先看工程长什么样

这一节不装框架、不装 Python，先把一个最小的网络用 C 写出来。理由很简单：本分册要验证的不是「会不会调库」，而是每一步数值是不是真的对。用 C 写，编译、运行、抓stdout 这条老路可以原封不动地复用。

大白话先建立一个画面

把网络想成一条两级流水线：两个数字进去，先被三个隐元各看一遍（每个隐元拿着三个旋钮加一个偏置），三个结果再被一个输出神经元汇总。

「学习」在这里只有一件事：把这 13 个旋钮一点点拧到合适的位置。往哪边拧？答案是梯度——每个旋钮对误差的敏感度。算梯度有两种办法：顺着公式推（解析梯度），以及把旋钮轻轻拧一下看误差怎么变（数值梯度）。两者必须给出同一个数。

第 1 帧是动笔前的空目录。第 2 帧长出三个清单：同一个程序用不同 args 跑出三份 stdout，分别由 numerical、gradient、train 三种闸门判定。清单不是装饰——正文里每个 output 块都必须被某个清单的 output 声明，否则报 output_block_uncovered。

工程惯例为什么先把接口写在头文件里

include/tiny_net.h 只有类型和函数声明。读它就知道这个网络会什么、不会什么：能前向、能算损失、能算两种梯度、能训练。实现全在 src/tiny_net.c 里，src/main.c 只负责选模式、打印数值。等后面换更大的网络，改的是实现，不是驱动。

2×3 个 w1、3 个 b1、3 个 w2、1 个 b2，加起来正好 13。权重初值由 LCG 从 BOOK_SEED 生成——不用 rand()，因为它的实现由库决定，换个机器序列就变了。种子固定，13 个数字就固定。

1.2 前向：两个数字怎么变成一个预测

隐元先把两个输入各乘一个权重再加偏置，过一个 tanh；输出层把三个隐元加权求和，过一个 sigmoid 压到 (0,1)。损失取 ½(y-t)²，平方前的 ½ 是为了求导时刚好消掉 2。

1.3 反向：链式法则在哪一步最容易漏

记 y = σ(s)，s = Σ hⱼw2ⱼ + b2，hⱼ = tanh(zⱼ)，zⱼ = Σ xᵢ w1ᵢⱼ + b1ⱼ。损失 L = ½(y-t)²。从后往前：

  • ∂L/∂y = y - t
  • ∂L/∂s = (y-t) · y(1-y) ← 这个 y(1-y) 就是最常漏的 sigmoid 链式因子
  • ∂L/∂w2ⱼ = (∂L/∂s) · hⱼ，∂L/∂b2 = ∂L/∂s
  • ∂L/∂hⱼ = (∂L/∂s) · w2ⱼ，再乘 1-hⱼ² 得到 ∂L/∂zⱼ，然后分给 w1 与 b1
陷阱漏一个因子，所有梯度一起错

写作 ds = dy 而不是 ds = dy * y * (1-y)，程序照常跑、loss 照常下降，只是下降得不对。这种错肉眼几乎看不出来——所以下面的对拍不是可选项。源码里用 #ifdef GRAD_BUG 把这个错误写成了可切换的开关，供闸门做阴性对照。

1.4 对拍：数值梯度给解析梯度背书

中心差分不需要任何链式法则：把第 k 个参数加 ε 算一次损失，减 ε 再算一次，斜率就是 (L₊-L₋)/(2ε)，ε 取 1e-5。它慢，但明显正确，正合「暴力版」的角色。13 个参数逐个算完，与解析梯度逐行对照：

清单要求至少 13 组、至少 8 组非零解析梯度、每组 |analytic-numerical| ≤ 1e-5。三条缺一不可：只查「每组接近」的话，一个把所有梯度都输出 0 的程序会 trivially 通过。

实验记录阴性对照：故意写错必须被抓住

清单还给了 negative_flags: ["-DGRAD_BUG=1"]。闸门用这组参数再编译一份，跑出错梯度的表；如果这份表也通过了对拍，就报 gradient_harness_not_discriminating——说明这套检查根本不判别。

这和检测模式里的 detect_not_attributable 是同一条纪律：把字样打印出来不算检测，把梯度打印成「看起来对」也不算对拍。实测 -DGRAD_BUG=1 下第一行变成 analytic=-0.0077885 numerical=-0.0018961，对拍失败，阴性对照成立。

1.5 训练：种子复现与收敛轨迹

把 13 个参数按 w ← w - 0.5·∂L/∂w 更新十步，每步打印一次 loss：

闸门对这份轨迹查四件事：至少 10 个点、起点不低于 0.01、终点不高于 0.01、首尾降幅至少 0.01，前 6 步非增（留 1e-4 的 slack）。然后同一个种子再跑一次，所有数值必须逐值一致；给了 seed_contrast: 67890 就再跑第三次，要求至少一个数值变化。最后这条是为了防止程序干脆把 loss 硬编码成一张表——那样同种子复现能过，对照种子也一模一样。

陷阱复现性不等于正确性

「每次跑出来一样」只说明程序是确定的，不说明它算对了。本单元里三道判定各管一件事：数值黄金值管前向对不对，梯度对拍管导数对不对，种子与收敛管训练过程是不是真的在跑。少一道都会留下能骗过闸门的写法。

1.6 为什么必须先写 C，再谈框架

这一节最容易被问的问题是：明明三行 PyTorch 就能建这个网络，为什么要手写 13 个参数？答案不在「会不会写」，而在「出了错能不能定位」。

框架把前向、求导、更新三件事包成一个 backward()，用起来省事，但它同时把链式法则的中间量藏起来了。初学者看到 loss 不下降，能改的只有学习率和层数——因为他看不见梯度到底长什么样。这一节把每一步都摊在 stdout 上：前向给出 y 和 loss，对拍给出 13 组解析梯度和数值梯度，训练给出十步 loss 轨迹。哪一步数值不对，肉眼就能定位到具体环节。

大白话把三道判定想成三道体检

数值黄金值查的是「前向算对没有」；梯度对拍查的是「导数算对没有」；种子与收敛查的是「训练过程是不是真的在跑」。这三件事彼此独立：一个程序可以把前向算对、梯度写错，也可以梯度写对、训练循环写错（比如忘了更新参数，loss 十步全一样）。只做其中一道，等于只做了一项体检就宣布健康。

1.6.1 前向的四个中间量

把 net_forward 拆开看，其实只有四个量，每个都有明确形状：z 是 3 个隐元的加权和（长度 3），h = tanh(z) 还是 3 个；s 是一个标量，把 3 个 h 加权求和再加偏置；最后 y = σ(s) 把任意实数压到 (0,1)。损失再拿 y 和目标 0.8 比较。

为什么输出要过 sigmoid？因为这一节把任务定义成「预测一个 0 到 1 之间的数」。sigmoid 把 s 的整个实数轴压进这个区间，顺手带来一个很好的性质：它的导数能用自身表示，σ'(s) = σ(s)(1-σ(s))。反传时只要保存了 y，就不必再算一次 exp——这正是 1.3 里那个 y(1-y) 因子的来源。

陷阱sigmoid 的饱和区

当 s 很大或很小，y 会非常接近 1 或 0，此时 y(1-y) 接近 0，梯度几乎消失。上游传来的误差再大，乘上这个因子也变成近乎零，参数就「学不动」了。这就是著名的梯度消失。这一节的网络只有两层，输入和目标都温和，不至于触发；但你要记住：激活函数不是随便选的，它直接决定梯度能不能传回去。后面讲Transformer 时会看到，深层网络改用 ReLU、LayerNorm、残差连接，全是在跟这件事较劲。

1.6.2 13 个参数为什么够

w1 是 2×3，意思是「两个输入各自连到三个隐元」，六条边六个权重；b1 是三个隐元各自一个偏置；w2 是三个隐元各自连到输出，三条边三个权重；b2 一个。总数是 6+3+3+1=13。

这个数字看起来小得可笑，但结构上和真正的 LLM 没有区别——只是每个数字都被放大了几千亿倍。一个 Transformer 层里的 attention 有 W_Q、W_K、W_V、W_O 四个矩阵，本质都是「把一组向量线性映射到另一组向量」，和这里的 w1、w2 是同一件事。区别只在维度：这里是 2→3，那里是几千→几千。

工程惯例从 13 个参数到 13 亿，什么变了

变的不是数学，是三件事。第一，矩阵乘法从手写循环换成 BLAS/GPU 核，因为朴素实现的复杂度不够用。第二，随机数不再手写 LCG，而是用专门设计的初始化分布（Xavier / He），保证前向的方差不爆炸也不消失。第三，训练的每一步都要在海量数据上做小批量平均，还要记录动量、二阶矩等状态。但「前向算对、梯度对拍、固定种子复现」这三条纪律一条都没变——这一节练的就是这三条。

1.6.3 梯度表怎么读

13 行输出里，analytic 是链式法则推出来的，numerical 是把参数加减小量后看损失怎么变。两者每行都对到小数点后七位，这不是巧合：中心差分的误差是 O(ε²)，ε 取 1e-5，误差量级在 1e-10 附近，远小于打印精度。

读表时别只看「数值接近不接近」，还要看符号。比如 b2 analytic=-0.0533324，是负的；这意味着把 b2 增大一点，loss 会下降——参数更新时 b2 ← b2 - 0.5×(-0.0533324)，也就是往增大方向走。训练十步后 loss 从 0.020956 降到 0.007509，正是这些符号 collectively 起作用的结果。

实验记录把学习率改大试试

net_train 里写的是 0.5 * grad。改成 5.0，前几步可能掉得更快，但很可能某一步直接冲过最低点，loss 反而反弹，甚至出现 nan。这不是 bug，是学习率太大导致步长越过了碗底。把 slack 之外的判定条件不动，只改学习率再跑，看看 train_loss_not_decreasing 会不会报出来——这一步能让你对「收敛判定不是形式主义」有直观感受。改完记得把 last_max 之类的黄金值按真实输出更新。

1.6.4 阴性对照到底在防什么

有人可能会说：梯度对拍已经把 13 行都比过了，为什么还要多编译一份错梯度？答案是防「测试本身失灵」。假设某天有人把 net_numerical_grad 里的扰动量 eps 写成 0.0，那么数值梯度全部是 0/0 或者 0，解析梯度也恰好接近 0 的参数会「通过」；再假设有人把对拍的容差从 1e-5 放宽到 1.0，任何错误都能过。这些改动都不会让闸门报错，除非闸门主动做一次「故意写错必须被抓住」的演练。

negative_flags: ["-DGRAD_BUG=1"] 就是这次演练。它不改变测试代码，只改变被测代码里的一个链式因子。正确实现对拍通过、错误实现对拍失败，才说明这套检查有判别力。实测错误版本的第一行是 analytic=-0.0077885 numerical=-0.0018961，差了四倍，远超过 atol=1e-5。如果你把 GRAD_BUG 的效果注释掉，闸门会报 gradient_harness_not_discriminating——这跟检测模式里「把字样 printf 出来也算检测」是同一种骗法，只是换了个场景。

工程惯例把这个方法搬到别处

「阴性对照」不是梯度对拍专用的。任何「自动检查」都应该问一句：如果我故意把被检查的东西弄坏，检查器会不会报警？编译器的 -Werror 可以拿一个真警告试；单元测试可以临时改一个断言的期望值；这一节的训练收敛判定可以给程序喂一组硬编码的 loss 表。能报警的说明检查有效，不能报警的就是零证据通过。这条纪律比任何具体工具都值钱。

1.6.5 为什么要固定种子而不是只固定数据

这一节的输入 x=(0.5,-0.3) 和目标 0.8 都是写死的，看起来已经「固定数据」了。但真正决定 13 个初值的是 BOOK_SEED：同一个输入，换一个种子，初始权重就全变，前向输出和 loss 轨迹跟着变。所以只固定数据不够——随机来源不止一个，权重初始化是最隐蔽的那个。

闸门把种子当环境变量注入，是有意为之：种子写在源码里叫「硬编码」，写在清单里叫「实验条件」。前者读者看不出来，后者一眼可见且可被对照实验改变。seed_contrast: 67890 就是对照实验——如果换种子后数字纹丝不动，说明程序根本没用种子，那些「可复现」的数字不过是一张写死的表。

陷阱可复现不等于正确

这一点值得重复。「同样输入每次输出一样」只证明程序是确定的；一个把整条 loss 曲线硬编码进数组的程序也完全确定。再强调一次这一节的三道判定：数值黄金值证明前向数值对，梯度对拍证明导数对，对照种子证明输出确实由权重算出来。三者合起来，才能说这个训练实验是真的。

1.7 这一节新增了什么

回到 1.1 的第 2 帧：tiny_net/ 下多了一个头文件、两个源文件、三个清单。三个清单指向同一个正文单元的三个 output 块；run.js --all 的全量覆盖检查会逐个核对，哪个块没被声明都会报 output_block_uncovered。

下一单元补线性代数：这里的 w1、w2 现在还是数组，接下来要把它们写成矩阵，把整层前向写成一个矩阵乘法——那时「13 个参数」会变成「一个权重矩阵」，但梯度对拍的纪律一点不变。把这一节的三道判定和阴性对照的写法记牢，后面所有数值实验都照这个模子铺开。

小结这一节的要点
  • 13 个参数的两层网络：2×3 个 w1、3 个 b1、3 个 w2、1 个 b2；权重由 LCG + 固定种子生成，不用 rand()；
  • 反向传播最容易漏的是 sigmoid 的链式因子 y(1-y)；
  • 中心差分是「明显正确的暴力版」，解析梯度必须与它逐项相符，且非零梯度要有足够多；
  • 阴性对照不是装饰：negative_flags 编译出的错梯度若也通过，闸门报 gradient_harness_not_discriminating；
  • 训练判定 = 收敛轨迹 + 同种子复现 + 对照种子必须改变输出；程序自报的 PASS 一律不算证据；
  • 容差只能写在清单的 expect，正文贴真实 stdout，--fix 回写原始输出。
自测题自测题（先自己答，再对答案）
  1. 为什么中心差分取 (L₊-L₋)/(2ε) 而不是 (L₊-L)/ε？后者在什么时候也能用？
  2. 梯度对拍为什么还要单独查「非零解析梯度的个数」？
  3. negative_flags 编译出来的错梯度如果也通过了，说明什么？闸门报什么码？
  4. train 模式为什么要跑三次？只跑两次（同种子）够不够？
  5. 把 LCG 换成 rand()，哪个判定最可能先出问题？
注自测题答案
  1. 中心差分是二阶精度，误差 O(ε²)；单侧差分是一阶 O(ε)，ε=1e-5 时精度差好几个量级。单侧差分在 ε 极小、函数求值极贵时才退而求其次。
  2. 防 trivially 通过：一个把全部解析梯度输出 0 的程序，|0 - 数值梯度| 在 ε 很小时可能落在容差内（尤其数值梯度本身也接近 0 的参数）。要求足够多组非零，才能证明真的算了梯度。
  3. 说明这套对拍不判别——错梯度和对梯度都放过，等于零证据。闸门报 gradient_harness_not_discriminating，与 detect 模式的 detect_not_attributable 是同一类失败。
  4. 不够。同种子两次一致只能证明确定性；把 loss 表硬编码进程序也能过。对照种子必须让输出变化，才能证明数值真是从种子驱动的权重算出来的。
  5. 同种子复现。rand() 的序列由 C 运行库实现决定，换台机器或换编译器就可能不同；train 的两次同种子对账会报 train_nondeterministic。（前向与梯度的黄金值也会跟着变，但复现检查最直接。）
