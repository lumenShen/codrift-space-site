30.1 贪心的本质与交换论证范式

贪心法的外观很简单：每一步都选当前看起来最优的决策，且不回头。但"看起来最优"必须被证明为全局最优，否则就是一个漂亮的谎言。证明贪心正确性的主力工具是交换论证（exchange argument）：先取某个最优解 O，若 O 的第一步与贪心选择 G 不同，就通过一次局部交换把 O 改造成以 G 开头的新最优解 O′，同时不降低解的质量；对后续步骤重复这个论证，就能把任意最优解逐步变成贪心解，从而证明贪心解最优。

交换论证的关键不在"交换"动作本身，而在找到那个不变量：交换后哪些量保持不变、哪个量单调不增。常见的论证模板有几种。其一是"相邻交换"：若两个相邻决策的顺序违反某个排序规则（如截止时间晚的排在早的前面），交换它们不会让目标变差；反复消除所有逆序就得到排序贪心。其二是"剪切粘贴"：把最优解中某个元素替换成贪心选的元素，用元素的属性（如结束时间最早）证明替换后仍可行。其三是"保留前缀"：证明贪心的第一步出现在某个最优解中，然后递归到子问题。

与动态规划相比，贪心不做"枚举所有决策再取最好"，而是直接锁定一个决策。这带来 O(n log n) 甚至 O(n) 的速度，也带来更高的证明门槛——只要有一个反例，整个贪心策略就失效。因此写贪心之前，务必先问：这个选择能否用交换论证支撑？它的"不劣性"来自哪个不变量？如果答不上来，先写暴力版或对拍，别急着相信直觉。

交换论证还有一个容易忽略的前提：子问题必须与原问题同构。EDD 里交换掉前两个任务后，剩下的任务仍是"单机调度、最小化最大延迟"，目标函数形式不变；区间调度里选中一个区间、删掉所有冲突区间后，剩下的仍是"选最多不重叠区间"。若交换后问题的约束发生了变化（比如多出一个跨任务的耦合条件），归纳就断了，证明不成立。识别这一点的方法是：写证明时明确写出"交换后子问题的定义"，并逐字比对它和原问题的定义是否一致。另一个实用技巧是用对拍来"寻找证明"——先让随机测试跑通，观察贪心解与最优解在结构上有什么恒定关系（比如总是某个排序的前缀），这种关系常常就是交换论证里那个不变量的线索。

大白话先用直觉把它讲通

贪心就是"每次都拿眼前最好的"，听着很靠谱，其实经常翻车。交换论证是给贪心开的一张证明条：假设有个神仙给出了最优解，我就把它的第一步换成我的贪心选择，然后证明"换完不会更差"。只要每次都能这么换，神仙解就能一步步被改造成我的解，那我的解自然也是最优的。关键是要说清楚"为什么换完不更差"，这句话就是证明的核心。

30.2 交换论证实例：最小化最大延迟（EDD）

问题定义。 有 n 个任务，任务 i 需要连续处理 t[i] 时间，截止时间 d[i]。单机从第 0 时刻开始，一次只做一个任务且不可中断。任务的完成时刻 C[i] 减去 d[i] 是它的延迟 L[i]（可为负，表示提前完成）。求一个处理顺序，使最大延迟 max L[i] 最小。

贪心选择。 按截止时间从早到晚排序（Earliest Due Date，EDD），依次处理。这个规则只依赖 d，与 t 无关——初看有点反直觉，因为长任务似乎该早做。

交换论证。 设某最优解中存在相邻两个任务 i、j，满足 d[i] > d[j] 但 i 排在 j 前面（一个"截止时间的逆序"）。交换这两个任务的顺序：交换前它们的完成时刻是 C 与 C + t[i]；交换后变成 C + t[j] 与 C + t[j] + t[i]。由于两个任务的总完成时刻相同，后续任务的完成时刻完全不变，只需检查这两个任务的最大延迟。交换后 j 的完成时刻从 C+t[i] 提前到 C+t[j]（注意 t[j] 不一定小于 t[i]，但 j 的截止更早），其延迟不会变大；而 i 的完成时刻从 C 变为 C+t[j]，延迟增加 t[j]。关键比较：交换前 i 的延迟是 C+t[i]−d[i]，交换后是 C+t[j]−d[i]。因为 d[i] > d[j]，有 t[j]−d[i] < t[j]−d[j]，再结合交换前 j 的延迟 C+t[i]−d[j] ≥ C+t[j]−d[j]（因 t[i] ≥ t[j]?）——更严谨的写法是：令交换前两者最大延迟为 M，交换后 i 的延迟 ≤ 交换前 j 的延迟（因为 d[i] > d[j] 意味着 i 的截止更晚，把 i 往后挪不会让它比原来 j 更糟），且 j 提前完成只会更优。因此交换不增加最大延迟。反复消除所有这样的逆序，得到的就是 EDD 顺序，它必然最优。

实现与复杂度。 只需对索引按 d 排序，一遍扫描累加当前时刻并更新最大延迟。时间 O(n log n)（排序），空间 O(n)。

下面的程序对随机 t∈[1,8]、d∈[1,21]、n∈[1,7] 生成 200 组，用全排列枚举所有顺序的暴力法对照。

#![allow(dead_code)]
// minimize maximum lateness: EDD (earliest due date) order
fn min_max_lateness(t: &[i64], d: &[i64]) -> i64 {
let mut idx: Vec<usize> = (0..t.len()).collect();
idx.sort_by_key(|&i| d[i]);
let mut cur = 0i64;
let mut worst = i64::MIN;
for i in idx {
cur += t[i];
worst = worst.max(cur - d[i]);
}
worst
}
fn brute(t: &[i64], d: &[i64]) -> i64 {
fn rec(t: &[i64], d: &[i64], perm: &mut Vec<usize>, used: &mut [bool], best: &mut i64) {
if perm.len() == t.len() {
let mut cur = 0i64;
let mut worst = i64::MIN;
for &i in perm.iter() {
cur += t[i];
worst = worst.max(cur - d[i]);
}
if worst < *best { *best = worst; }
return;
}
for i in 0..t.len() {
if used[i] { continue; }
used[i] = true;
perm.push(i);
rec(t, d, perm, used, best);
perm.pop();
used[i] = false;
}
}
let mut best = i64::MAX;
rec(t, d, &mut Vec::new(), &mut vec![false; t.len()], &mut best);
best
}
struct Rng(u64);
impl Rng {
fn next_u64(&mut self) -> u64 { let mut x = self.0; x ^= x << 13; x ^= x >> 7; x ^= x << 17; self.0 = x; x }
fn range(&mut self, lo: u64, hi: u64) -> u64 { lo + self.next_u64() % (hi - lo + 1) }
}
fn main() {
let t = [2i64, 1, 3, 2];
let d = [4i64, 3, 5, 6];
println!("demo edd = {}", min_max_lateness(&t, &d));
let mut rng = Rng(0x1234_5678_9abc_def0);
let mut bad = 0;
for _ in 0..200 {
let n = 1 + rng.range(0, 7) as usize;
let t: Vec<i64> = (0..n).map(|_| rng.range(1, 9) as i64).collect();
let d: Vec<i64> = (0..n).map(|_| rng.range(1, 22) as i64).collect();
let a = min_max_lateness(&t, &d);
let b = brute(&t, &d);
if a != b { println!("MISMATCH edd={} brute={}", a, b); bad += 1; break; }
}
println!("stress edd: {} (200 random cases)", if bad == 0 { "OK" } else { "FAIL" });
}

这个例子说明交换论证的典型形态：只要能找到"逆序"并证明交换不劣，贪心就成立。注意这里的排序只按 d，不看 t——如果写成按 t 从小到大排，对拍会立刻给出反例。贪心的"简单"往往来自一个不那么显然的不变量，切忌凭第一直觉改排序键。

再补充两点边界语义。其一，延迟 L[i] = C[i] − d[i] 允许为负，表示提前完成；目标是让"最坏的那个延迟"尽量小，所以答案可能是负数（所有任务都提前）。程序中用 i64::MIN 初始化 worst、用 i64::MAX 初始化暴力版的 best，正是为了正确处理负值——若误用 0 初始化，所有任务都提前时答案会被错算成 0。其二，任务处理时间允许为 0 吗？本单元对拍取 t∈[1,8]，不为 0；若题目允许 t=0，排序仍然正确，但"完成时刻相同"的边界会让多个任务的延迟相等，交换论证里的不等号要改成非严格形式。写证明时把等号情形纳入考量，是避免"证明看起来对、代码边界错"的关键。

30.3 区间调度：按结束时间贪心

问题定义。 给定 n 个半开区间 [s, e)，从中选尽可能多的互不重叠区间。区间 [1,3) 与 [3,5) 不重叠（前者的右端等于后者的左端）。这是"安排最多会议""选最多不冲突任务"的抽象。

贪心选择。 按区间右端点 e 从小到大排序，每次选结束最早且与已选区间不冲突的那个。直觉是：结束越早，给后面留下的空间越大。

正确性论证（剪切粘贴）。 设贪心的第一步选了结束最早的区间 g。取任一最优解 O，设它的第一个区间是 o。因为 g 的结束时间不晚于 o，把 O 中的 o 替换成 g 后：g 与 O 中其余区间仍不冲突（它们原本都在 o 之后开始，而 g 结束更早），且区间数不变。于是存在一个包含 g 的最优解。接着把所有与 g 冲突的区间从解中删去，问题退化为"在 g 之后开始的区间里选最多不重叠区间"——与原问题同构。归纳即得贪心最优。这个论证也说明为什么按开始时间排序不对：开始早的区间可能很长，霸占后续全部空间。

实现与复杂度。 排序 O(n log n)，一遍扫描 O(n)。判定不冲突的条件是 s >= last_end（半开区间）。若用闭区间，条件要改成 s > last_end——这是最经典的边界错误之一。

下面的程序对随机区间（左端 0..19，长度 1..8）n∈[1,14] 生成 300 组，用枚举所有子集、检查子集中区间两两不冲突的暴力法对照。

#![allow(dead_code)]
// max number of non-overlapping half-open intervals [s, e)
fn max_intervals(mut iv: Vec<(i32, i32)>) -> usize {
iv.sort_by_key(|&x| x.1);
let mut cnt = 0usize;
let mut last_end = i32::MIN;
for (s, e) in iv {
if s >= last_end {
cnt += 1;
last_end = e;
}
}
cnt
}
fn brute(iv: &[(i32, i32)]) -> usize {
let n = iv.len();
let mut best = 0usize;
for mask in 0u32..(1u32 << n) {
let mut chosen = Vec::new();
for i in 0..n {
if mask & (1u32 << i) != 0 { chosen.push(iv[i]); }
}
chosen.sort_by_key(|&x| x.1);
let mut ok = true;
let mut last = i32::MIN;
for &(s, e) in &chosen {
if s < last { ok = false; break; }
last = e;
}
if ok && chosen.len() > best { best = chosen.len(); }
}
best
}

impl Rng {

fn range(&mut self, lo: u64, hi: u64) -> u64 { lo + self.next_u64() % (hi - lo + 1) }
}
fn main() {
let iv = vec![(1, 4), (2, 3), (3, 5), (0, 6), (5, 7), (6, 9), (8, 10)];
println!("demo max_intervals = {}", max_intervals(iv.clone()));
let mut rng = Rng(0xfeed_beef_1234_5678);
let mut bad = 0;
for _ in 0..300 {
let n = 1 + rng.range(0, 14) as usize;
let mut iv = Vec::new();
for _ in 0..n {
let s = rng.range(0, 20) as i32;
let e = s + rng.range(1, 9) as i32;
iv.push((s, e));
}
let a = max_intervals(iv.clone());
let b = brute(&iv);
if a != b { println!("MISMATCH greedy={} brute={}", a, b); bad += 1; break; }
}
println!("stress interval: {} (300 random cases)", if bad == 0 { "OK" } else { "FAIL" });
}

区间调度还有加权版本：每个区间带权重，要最大化权重和。此时"选结束最早"不再最优，因为一个短而轻的区间可能挡住一个长而重的区间。加权版本必须用动态规划（按右端点排序后 dp[i] = max(dp[i-1], w[i] + dp[p(i)])，p(i) 是与 i 不冲突的最后一个区间）。判断该用贪心还是 DP，标准就是看"局部最优是否天然全局最优"——无权时成立，加权时不成立。

30.4 Huffman 编码：最优合并模式

问题定义。 给定 n 个权重 w[0..n)，构造一棵以这些权重为叶子的满二叉树，使带权路径长度最小，即 Σ w[i] × depth[i]。这等价于最优合并模式：每次把两堆合并成一堆，代价是两堆重量之和，求把 n 堆合成一堆的最小总代价。它正是 Huffman 编码压缩后的总码长。

贪心选择。 每次取当前最轻的两堆合并，把合并结果放回。这是典型的"最轻优先"贪心，用最小堆（BinaryHeap + Reverse）实现。

正确性论证。 关键引理：在最优树中，权重最小的两个叶子一定是兄弟，且位于最深一层。理由是最深层的兄弟可以交换而不改变代价，把两个最小的权重放到那里不会增大总代价（把更大的权重换到较浅层只会减小它的贡献）。于是可以先把这两个最小权重合并成一个新叶子（权重为二者之和），问题规模减一；对新问题重复论证。这就是"贪心选择 + 最优子结构"的标准组合：先锁定最小的两堆，再递归解决剩余问题。

实现与复杂度。 用 BinaryHeap<Reverse<u64>> 维护当前堆集合，每次弹两个最小的、求和、累加代价、压回。时间 O(n log n)，空间 O(n)。权重可能很大，累加用 u64。

下面的程序对随机权重（1..39）n∈[1,7] 生成 200 组，用"枚举所有合并顺序、对排序后的权重向量做记忆化搜索"的暴力法对照——这是真正的最优解，不依赖 Huffman 结论。

rustRust · 标准库63 行
#![allow(dead_code)]
use std::cmp::Reverse;
use std::collections::{BinaryHeap, HashMap};
fn huffman_cost(w: &[u64]) -> u64 {
let mut h = BinaryHeap::new();
for &x in w { h.push(Reverse(x)); }
let mut total = 0u64;
while h.len() > 1 {
let a = h.pop().unwrap().0;
let b = h.pop().unwrap().0;
let s = a + b;
total += s;
h.push(Reverse(s));
}
total
}
// brute force over all merge orders, memoized on sorted weight vectors
fn brute(w: &[u64]) -> u64 {
fn rec(mut v: Vec<u64>, memo: &mut HashMap<Vec<u64>, u64>) -> u64 {
if v.len() <= 1 { return 0; }
v.sort_unstable();
if let Some(&x) = memo.get(&v) { return x; }
let n = v.len();
let mut best = u64::MAX;
for i in 0..n {
for j in i + 1..n {
let cost = v[i] + v[j];
let mut nv: Vec<u64> = v.iter().enumerate()
.filter(|&(k, _)| k != i && k != j)
.map(|(_, &x)| x).collect();
nv.push(cost);
let c = rec(nv, memo) + cost;
if c < best { best = c; }
}
}
memo.insert(v, best);
best
}
rec(w.to_vec(), &mut HashMap::new())
}

impl Rng {
fn next_u64(&mut self) -> u64 { let mut x = self.0; x ^= x << 13; x ^= x >> 7; x ^= x << 17; self.0 = x; x }
fn range(&mut self, lo: u64, hi: u64) -> u64 { lo + self.next_u64() % (hi - lo + 1) }
}
fn main() {
let w = [5u64, 9, 12, 13, 16, 45];
println!("demo huffman cost = {}", huffman_cost(&w));

let b = brute(&w);

}
println!("stress huffman: {} (200 random cases)", if bad == 0 { "OK" } else { "FAIL" });
}

Huffman 的一个常见误解是把"最小代价"当成"最小码长"本身。实际上我们优化的是 Σ w[i]×depth[i]，出现频率高的符号权重小（因为码长与频率成反比的构造中权重常取频次），所以高频符号分到短码。若权重为 0，合并它不会增加代价，但会增加树高——对编码无影响，对"合并堆数"有细节影响。n=1 时代价为 0（单节点树深度 0），堆里只有一个元素，循环不执行，代码自然正确。

最优合并问题的暴力对拍之所以有价值，是因为它完全不预设 Huffman 的结论：递归枚举"任选两堆合并"的所有顺序，对合并后排序好的权重向量做记忆化，找到的真正是全局最优代价。当 n 增大到 7 以上，暴力版的分支数迅速膨胀（每一步约有 n²/2 种合并选择），但对拍只需要跑到 7 就足以覆盖绝大多数边界。Huffman 与"合并果子""石子合并"是同一类问题的不同外衣：前者每次合并代价是两堆之和，后者若限制只能合并相邻两堆就变成区间 DP——是否允许"任意两堆"决定了该用贪心还是 DP，这是判断贪心适用性的好例子。

30.5 构造法：Havel-Hakimi 判定度数序列

问题定义。 给定一串非负整数 d[0..n)，判断是否存在一个 n 个顶点的简单无向图（无重边、无自环），使第 i 个顶点的度数恰为 d[i]。这是图论中的"可图性判定"，也是构造法的典型：不仅回答"是或否"，过程本身还能逐步构造出这样的图。

Havel-Hakimi 算法。 把序列按度数降序排列，取最大度数 k（对应顶点 u）。若 k ≥ 剩余顶点数，直接返回否（没有足够的点连边）。否则把 u 与度数最大的 k 个其余顶点各连一条边，这些顶点的度数各减一，u 的度数归零（相当于从图中移除）。重复直到全零（可图）或出现负数/不足顶点（不可图）。

正确性论证。 这是交换论证在构造问题上的变体。若存在某个图实现当前序列，设顶点 u 度数最大为 k。可以证明存在一个实现图，其中 u 恰好连向度数最大的 k 个其余顶点：若原图里 u 连了某个度数较小的 x 而没连度数较大的 y，由于 deg(y) ≥ deg(x)，y 必有一条连向非 u 顶点 z 的边，而 x 没有连向 z（或可做类似调整），通过一次"边交换"把 (u,x) 和 (y,z) 换成 (u,y) 和 (x,z)，度数序列不变。反复交换即可得到 HH 所需的邻接形式，因此"贪心连向最大的 k 个"不损失可图性。递归地应用这一结论，算法正确。

实现与复杂度。 每轮排序 O(n log n)，最多 n 轮，总 O(n² log n)（n 小时足够）。要注意的边界：k >= d.len() 时返回否；连边前检查目标度数为 0（为 0 说明不足顶点）；每轮把 d[0] 置 0 等价于移除该顶点。

下面的程序对随机度数序列生成 200 组，n∈[1,6]，用枚举 n(n−1)/2 条边的所有子集（最多 2^15=32768 个图）、检查是否存在图的度数序列与目标相同的暴力法对照。

#![allow(dead_code)]
// Havel-Hakimi: decide whether a degree sequence is graphical
fn havel_hakimi(deg: &[usize]) -> bool {
let mut d = deg.to_vec();
loop {
if d.iter().all(|&x| x == 0) { return true; }
d.sort_unstable_by(|a, b| b.cmp(a));
let k = d[0];
if k >= d.len() { return false; }
for i in 1..=k {
if d[i] == 0 { return false; }
d[i] -= 1;
}
d[0] = 0;
}
}
// brute: enumerate all simple graphs on n vertices
fn brute_graphical(deg: &[usize]) -> bool {
let n = deg.len();
if n == 0 { return true; }
let m = n * (n - 1) / 2;
let mut target = deg.to_vec();
target.sort_unstable();
for mask in 0u32..(1u32 << m) {
let mut ds = vec![0usize; n];
let mut bit = 0usize;
for i in 0..n {
for j in i + 1..n {
if mask & (1u32 << bit) != 0 { ds[i] += 1; ds[j] += 1; }
bit += 1;
}
}
ds.sort_unstable();
if ds == target { return true; }
}
false
}
struct Rng(u64);
impl Rng {
fn next_u64(&mut self) -> u64 { let mut x = self.0; x ^= x << 13; x ^= x >> 7; x ^= x << 17; self.0 = x; x }
fn range(&mut self, lo: u64, hi: u64) -> u64 { lo + self.next_u64() % (hi - lo + 1) }
}
fn main() {
let d = [3usize, 3, 3, 3];
println!("demo K4 graphical = {}", havel_hakimi(&d));
let mut rng = Rng(0x0bad_f00d_0bad_f00d);
let mut bad = 0;
for _ in 0..200 {
let n = 1 + rng.range(0, 6) as usize;
let deg: Vec<usize> = (0..n).map(|_| rng.range(0, n as u64) as usize).collect();
let a = havel_hakimi(&deg);
let b = brute_graphical(&deg);
if a != b { println!("MISMATCH deg={:?} hh={} brute={}", deg, a, b); bad += 1; break; }
}
println!("stress havel-hakimi: {} (200 random sequences)", if bad == 0 { "OK" } else { "FAIL" });
}

构造法与判定问题常常是一体两面：Havel-Hakimi 在判定的同时记录了"每一步连了哪些边"，把这些边收集起来就得到了一个具体的图。若题目只问可行性，可以省去边的记录；若要求输出方案，就把每轮连边的顶点对存下来。对拍时用"枚举所有图"的暴力法是最强的验证——它完全不依赖任何图论定理，只要实现正确，就是判定结果的标准答案。

30.6 四种方法的横向对照

方法 解决问题 核心不变量 时间 失败信号
交换论证 / EDD 最小化最大延迟 消除截止时间逆序不劣 O(n log n) 排序键选错（如按处理时间）
区间调度 最多不重叠区间 最早结束留出最大空间 O(n log n) 半开/闭区间边界混淆
Huffman 最优合并 / 编码 最小两权重必为最深兄弟 O(n log n) 权重溢出、n=1 未处理
Havel-Hakimi 度数序列可图 最大度数可连向最大 k 个 O(n² log n) 顶点不足、目标度数为 0

四者的共性是"局部最优能推出全局最优"，但支撑它的不变量各不相同：EDD 靠"消除逆序"，区间调度靠"最早结束留空间"，Huffman 靠"最小两权重最深"，HH 靠"边交换可规范化"。写贪心时，先把这句不变量写出来，再用对拍验证——如果找不到一句话支撑，这个贪心多半是错的。

大白话先用直觉把它讲通

四种方法都是"每步拿最好的"，但理由完全不一样。调度的理由是"截止早的先做不会让任何人更晚"，区间的理由是"越早结束越给后面留地儿"，Huffman 的理由是"最轻的两个一定在最底层"，构造图的理由是"最高度数的点一定可以连到度数最大的那几个"。把这四句话记住，比背四个模板有用得多——遇到新题时先问自己能不能说出类似的一句话。

30.7 边界、陷阱与工程取舍

交换论证类。 逆序的定义要与目标函数匹配：EDD 排的是截止时间，若目标改成"最小化总完成时间"就该按处理时间排序（Shortest Processing Time），排序键一变整个结论就变。对拍时特意生成"处理时间与截止时间反相关"的数据，最容易暴露排序键错误。

区间调度。 半开区间 [s,e) 的兼容条件是 s >= last_end；闭区间 [s,e] 则是 s > last_end。用错一个等号，相接的区间会被误判为冲突或重叠。加权版本不能用这个贪心，要退回 DP。区间端点可能相等、区间可能零长，都要在数据生成中覆盖。

Huffman。 权重累加用 u64 甚至 u128，避免溢出；叶子数为 1 时循环不执行，返回 0 是正确的；若还要输出编码，需在合并时记录树结构再 DFS 生成码字，并验证前缀无码性。BinaryHeap 默认是最大堆，必须包 Reverse 才是最小堆——忘了包会得到完全相反的"每次合并最大的两堆"，结果远非最优。

构造法。 HH 每轮要把当前最大度数置零（等价于删点），否则它会反复参与连边；k >= d.len() 与"目标度数为 0"两个失败条件缺一不可；若要输出具体图，须在每轮记录"u 连向了哪 k 个点"，并且注意这些点每轮的顺序会变化，记录的是当前排序后的编号。

工程取舍。 贪心通常比 DP 快一个数量级，但证明门槛高。稳妥的开发流程是：先写暴力版并跑通，再写贪心版，然后随机对拍几百到几千组；对拍通过后再试着写出交换论证的文字证明——如果写不出来，往往说明贪心在某个未覆盖的数据上有反例，应扩大对拍规模而不是硬凑证明。本单元四个程序都坚持"暴力与贪心同源对拍"，正是这个流程的落地。

坑这里最容易踩

坑：区间调度的半开/闭区间之争。对拍用的是半开区间 [s,e)，兼容条件是 s >= last_end；如果把输入改成闭区间 [s,e] 却沿用这个条件，两个端点相接的区间（如 [1,3] 与 [3,5]）会被错误地判为兼容，得到偏大的答案。反过来，半开区间用 s > last_end 则漏掉本可相接的区间。写代码前先明确区间语义，并让随机数据里出现端点相等的情况——本单元对拍专门让 e = s + 随机长度，且 s 的取值密集，正是为了覆盖相接与重叠两种边界。
