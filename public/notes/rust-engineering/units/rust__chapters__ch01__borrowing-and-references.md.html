3.1 动机：不想交出所有权怎么办

上一个单元里，把 String 传给函数就会把它 move 进去，调用方随后再也用不了。这在很多场景下太浪费了：一个函数只是想读一读字符串的长度，凭什么要把它吞掉？更麻烦的是，如果函数用完了也想「还回来」，你就得设计返回值把所有权再传回来，签名变得啰嗦。

Rust 的解法是借用（borrowing）：你可以把一个值的引用交给函数，函数用完就还，所有权始终留在原处。引用就是一个指向数据的指针，但它不是「随便什么指针」，而是被编译器严格检查过的指针——它必须指向有效的、类型正确的数据。这种「有规则约束的指针」正是 Rust 既能避免悬垂指针、又不需要垃圾回收的关键。

引用还有一个容易被忽视的好处：它不复制数据。传一个 &String 给函数，传递的只是栈上那个小小的指针，堆上的字符串内容原地不动。对于大对象，这比 clone 便宜得多。另外，Rust 的引用不可能为空——想表达「可能没有」，请用 Option<&T>，而不是像 C 那样用空指针。把「有没有」显式写进类型，是 Rust 减少 bug 的又一手段。

大白话先用直觉把它讲通

所有权像是把书送人，送出去你手上就没了。借用则是把书借给朋友看：书还是你的，他看完要还。规则也很像现实——你可以把书同时借给好几个人看（大家只读），但如果其中一个人要在书上涂改，那段时间里就绝不能有别人在看，否则大家看到的版本就不一致了。

3.2 不可变引用与可变引用

引用分两种，区别全在一个 mut 上。不可变引用写 &T，表示「我只读，不改」；可变引用写 &mut T，表示「我要改」。函数参数里用哪种，直接决定了调用方能不能同时做别的事。

先看只读的写法。length(&name) 把 name 的引用传进去，函数签名写 &String，函数体内 s.len() 只是读取长度。调用结束后 name 依然完好，还能照常打印。这里的 & 是「取引用」操作符，println! 里直接用 name 而不是 &name，是因为格式化宏会自动按引用捕获——不过写清楚 &name 也不会错。

rustRust · 标准库9 行
fn length(s: &String) -> usize {
s.len()
}
fn main() {
let name = String::from("Rust");
let n = length(&name);
println!("name={name}, 长度={n}");
}

再看可变引用。函数参数写 &mut String，函数体里就能调用 push 修改内容；调用方必须把变量声明成 mut，并用 &mut msg 传参。两处的 mut 缺一不可——这是 Rust 在提醒你「修改的权力」需要双方共同确认，而不是某个函数偷偷获得。

rustRust · 标准库9 行
fn push_exclaim(s: &mut String) {
s.push('!');
}
fn main() {
let mut msg = String::from("hello");
push_exclaim(&mut msg);
println!("{msg}");
}

写函数签名时，你可能纠结参数该写 &String 还是 &str。经验法则是：如果函数不需要调用 String 独有的能力，优先写 &str。因为 &String 会自动解引用（deref coercion）成 &str，所以传 &name 给一个接受 &str 的函数完全没问题；反过来接受 &String 的函数却没法接收字符串字面量。参数越宽泛，函数越通用。

一个小建议：写函数时优先考虑 &T，只在确实需要修改时才升级到 &mut T。因为不可变引用更「宽容」，调用方更容易满足借用规则，函数的适用范围也更广。方法调用时也有自动借用：对 String 调用 len()，实际等价于编译器自动帮你取了引用，所以你不需要手动写 (&s).len()。

3.3 借用规则：编译器是你的图书管理员

借用规则可以浓缩成两条：第一，同一时刻，要么有任意多个不可变引用，要么有且仅有一个可变引用，二者不能同时存在；第二，引用必须始终有效，不能指向已经被释放的数据。第二条会在下一个单元讲生命周期时展开，这里先盯住第一条。

为什么可变引用必须独占？想象一个向量 v，你手里拿着 &v[0] 指向第一个元素，这时如果允许 v.push(4)，向量可能因容量不足而重新分配内存，你手里的引用就变成了悬垂指针，指向一块已经被释放的区域。Rust 直接在编译期禁止这种组合：只要还有不可变引用活着，就不能取得可变引用；反过来也一样。

引用类型 写法 同一时刻数量 典型用途
不可变引用 &T 可以有多个 读取、遍历、计算长度
可变引用 &mut T 只能有一个 修改内容、追加元素
不可变切片 &[T] 可以有多个 只读地访问一段连续元素
可变切片 &mut [T] 只能有一个 原地修改一段连续元素

试着同时持有一个不可变引用和一个可变引用，编译器会给出类似下面的报错（示意输出，行号因文件而异）：

终端真跑一遍
$ rustc --edition 2021 main.rs -o main
error[E0502]: cannot borrow `v` as mutable because it is also borrowed as immutable
--> main.rs:4:5
|
3 | let first = &v[0];
| - immutable borrow occurs here
4 | v.push(4);
| ^^^^^^^^^ mutable borrow occurs here
error: could not compile `main` (bin "main") due to 1 previous error

初学者常被这条规则「卡住」，但它其实是好事：这类并发与内存错误在其他语言里往往要等到线上偶发崩溃才暴露，而 Rust 让你在敲代码时就撞上它。

这条规则还是 Rust 并发安全的基础。所谓数据竞争，指的是两个线程同时访问同一份数据，其中至少一个在写，且没有同步措施。借用规则在编译期就排除了「同时有多个写入者」或「一边读一边写」的可能，于是 Rust 敢说「如果代码能编译通过，共享可变状态就受到约束」。这正是它不靠垃圾回收也能保证安全的另一半答案：所有权管释放，借用规则管并发与别名。

3.4 NLL：借用没你想的那么长

早期的 Rust 里，借用的有效期严格跟随变量的作用域（从声明到花括号结束）。这带来了一些反直觉的失败：明明最后一次使用引用之后你已经不再碰它了，编译器却认为借用还活着。后来的改进叫 NLL（Non-Lexical Lifetimes，非词法作用域生命周期）：借用的有效期从「变量作用域」缩短为「最后一次使用引用之前」。

下面的例子就是 NLL 的典型受益者。first 引用了 v 的第一个元素，打印一次之后就不再使用；紧接着 v.push(4) 取得可变借用。按老规则这会冲突，但在 NLL 下，编译器看到 first 之后没再用，就判定不可变借用已经结束，于是放行。

rustRust · 标准库7 行
fn main() {
let mut v = vec![1, 2, 3];
let first = &v[0];
println!("first={first}");
v.push(4); // first 不再使用，借用到此结束
println!("v={v:?}");
}

理解 NLL 的一个实用技巧是：把借用的有效期想象成「从取引用到最后一次使用这段区间」，而不是整个大括号。写代码时如果遭遇借用冲突，先看看能不能把某次使用提前，或者把引用的作用域用一对额外的小括号缩紧，很多问题就迎刃而解。

要注意，NLL 只看「引用有没有被使用」，不看变量是否还在作用域里。所以像 let r = &mut v; println!("{r}"); v.push(1); 这种顺序能过编译，因为 r 在 push 之前就最后一次出现了。但如果你在 push 之后又用了 r，借用就重新「活」到了那里，冲突立刻出现。把这点想清楚，大部分借用报错都能自己推断出原因。

3.5 as_ref 与 as_mut：从容器里借出引用

有些类型既持有所有权，又需要「借用里面的内容」，Option<T> 是最常见的例子。Option<String> 里的字符串是被 Some 包着的，直接 map 会把所有权 consume 掉；如果你只是想读长度、还想保留原来的 Option，就该用 as_ref()——它把 Option<T> 变成 Option<&T>，借用里面的值而不是拿走它。

对应的 as_mut() 把 Option<T> 变成 Option<&mut T>，让你在 Some 里修改内容。下面这段程序同时演示了两者：show 用 as_ref().map(...) 读长度而不消耗参数；main 里用 as_mut() 拿到可变引用，往字符串后面追加一个字符。

rustRust · 标准库15 行
fn show(opt: Option<String>) -> Option<usize> {
opt.as_ref().map(|s| s.len())
}
fn main() {
let a = Some(String::from("hi"));
let b: Option<String> = None;
println!("{:?}, {:?}", show(a), show(b));
let mut c = Some(String::from("x"));
if let Some(s) = c.as_mut() {
s.push('y');
}
println!("{c:?}");
}

as_ref / as_mut 不是 Option 的专利，Box、Rc 等智能指针也提供类似方法，套路是一致的：当你手上有「拥有者」，但下游只需要「借用」时，就找找有没有 as_ref 这类转换。养成这个习惯，能省掉大量不必要的 clone。
