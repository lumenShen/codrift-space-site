25.1 流网络、残留图与最大流最小割定理

流网络是有向图，每条边有容量 cap(u,v)，并指定源点 s 与汇点 t。一个可行流给每条边分配流量 f(u,v)，满足三条件：容量约束 0 ≤ f ≤ cap；除 s、t 外每点流入等于流出；s 的净流出等于 t 的净流入，即流值。割是把点分成含 s 的 S 与含 t 的 T 两部分，割容量是所有从 S 指向 T 的边容量之和（反向边不计）。任何流的值都不超过任何割的容量，因为流必须穿过某个割，而被计数的正向边容量就是上限。

最大流最小割定理说：最大流值等于最小割容量。证明的关键构造是残留图：对每条原边 u→v，保留剩余容量 cap−f 的正向边，并添加一条容量为 f 的反向边 v→u。若残留图中仍存在 s 到 t 的路径（增广路），就能沿它增加流量；反之，若没有增广路，令 S 为残留图中从 s 可达的点集，则所有 S→T 的原边必定满载（否则残留图里还有那条正向边），所有 T→S 的原边流量必为 0（否则有反向残留边），于是流值恰好等于割容量——这个割就是最小割。

实现上把每条原边拆成一对"正向边 + 反向边"存在同一个邻接表里，用 rev 字段互指下标。增广时正向边 cap -= d、反向边 cap += d，这样"退流"就被统一表示成走反向边，无需单独处理。这个对偶表示是几乎所有最大流算法的基石。

容量守恒的不变量要一直放在心里：每对正反向边的"正向已用流量"等于反向边的残留容量，因此只要每轮增广成对更新，任何中间状态都对应某个合法流。若只更新一边，这个等式立刻失效，算法可能在残留图里走出根本不存在的"退流路径"。容量取整数时，每轮增广至少把 1 单位流量送到汇点，算法必然终止；取浮点数则可能因精度问题陷入无限循环，工程上应把小数容量按精度放大成整数再做。

25.2 Edmonds-Karp：最短增广路与复杂度

Ford-Fulkerson 的框架是"只要还有增广路就沿它增广"，但增广路的选择策略影响巨大：若用 DFS 随便找，可能遇到容量极大时反复绕路，复杂度与容量值相关（伪多项式）。Edmonds-Karp 把"随便找"改成"用 BFS 找边数最少的增广路"，于是每轮增广后，至少有一条边在残留图中消失，且可以证明增广次数上界是 O(VE)，每次 BFS 是 O(E)，总复杂度 O(VE²)，与容量大小无关。

代码里的 residual_bfs 同时记录前驱点 pv 与前驱边下标 pe，因为"沿哪条边到 v"必须精确到边，而不能只记点——两条平行边中走哪一条，增广时更新的对象不同。pv[v] == usize::MAX 表示不可达，与 24 单元的哨兵讨论一脉相承。找到路后先算瓶颈 d，再第二次从 t 回溯到 s 逐边更新；这一步的顺序不敏感，但必须先算完 d 再改容量，否则边改到一半的残留图不再对应任何合法流。

为什么"最短"增广路能带来与容量无关的复杂度？可以证明：随着增广推进，残留图中最短增广路的长度单调不减；每当长度增加，必然是某条边被用尽而从残留图消失，而每条边每个方向至多消失 O(V) 次，故总增广次数 O(VE)。若改用 DFS 随便找路，最短长度不保证单调，容量很大时可能反复绕远路，次数与容量值成正比。这就是 EK 比朴素 Ford-Fulkerson 多一个 BFS 却换来强多项式复杂度的原因。每轮 BFS 只找一条路，是 EK 的主要开销；把它换成"一次 BFS 后推送阻塞流"，就是下一节的 Dinic。

实现里 while v != s 的两次回溯循环写得几乎一样，但职责不同：第一次只读容量求瓶颈，第二次才真正修改。把它们合并会引入"边改了一半"的中间状态，虽然本例单线程不会出问题，但会让不变量难以陈述。flow += d 用 i64 累加，若最大流值可能超过类型上界，必须在建模阶段就换更大整数或拆分成多个单位流处理。

use std::collections::VecDeque;
#[derive(Clone, Copy)]
struct Edge { to: usize, rev: usize, cap: i64 }
struct Flow {
n: usize,
g: Vec<Vec<Edge>>,
orig: Vec<(usize, usize, i64)>,
}
impl Flow {
fn new(n: usize) -> Self {
Flow { n, g: vec![Vec::new(); n], orig: Vec::new() }
}
fn add_edge(&mut self, u: usize, v: usize, cap: i64) {
let fi = self.g[u].len();
let ri = self.g[v].len();
self.g[u].push(Edge { to: v, rev: ri, cap });
self.g[v].push(Edge { to: u, rev: fi, cap: 0 });
self.orig.push((u, v, cap));
}
fn residual_bfs(&self, s: usize, t: usize) -> (Vec<usize>, Vec<usize>, bool) {
let mut pv = vec![usize::MAX; self.n];
let mut pe = vec![usize::MAX; self.n];
let mut seen = vec![false; self.n];
let mut q = VecDeque::new();
seen[s] = true;
q.push_back(s);
while let Some(u) = q.pop_front() {
if u == t { break; }
for (i, e) in self.g[u].iter().enumerate() {
if !seen[e.to] && e.cap > 0 {
seen[e.to] = true;
pv[e.to] = u;
pe[e.to] = i;
q.push_back(e.to);
}
}
}
(pv, pe, seen[t])
}
// Edmonds-Karp：每轮用 BFS 找最短增广路
fn edmonds_karp(&mut self, s: usize, t: usize) -> i64 {
let mut flow = 0i64;
loop {
let (pv, pe, ok) = self.residual_bfs(s, t);
if !ok { break; }
let mut d = i64::MAX;
let mut v = t;
while v != s {
let u = pv[v];
d = d.min(self.g[u][pe[v]].cap);
v = u;
}
v = t;
while v != s {
let u = pv[v];
let ei = pe[v];
let rev = self.g[u][ei].rev;
self.g[u][ei].cap -= d;
self.g[v][rev].cap += d;
v = u;
}
flow += d;
}
flow
}
// 最大流后，从 s 在残留图中可达的点集是最小割的 S 侧
fn min_cut(&self, s: usize) -> (Vec<bool>, Vec<(usize, usize, i64)>) {
let mut seen = vec![false; self.n];
let mut q = VecDeque::new();
seen[s] = true;
q.push_back(s);
while let Some(u) = q.pop_front() {
for e in &self.g[u] {
if e.cap > 0 && !seen[e.to] {
seen[e.to] = true;
q.push_back(e.to);
}
}
}
let cut: Vec<_> = self.orig.iter().copied()
.filter(|&(u, v, _)| seen[u] && !seen[v]).collect();
(seen, cut)
}
}
fn main() {
let mut f = Flow::new(6);
for &(u, v, c) in &[
(0usize, 1usize, 16i64), (0, 2, 13), (1, 2, 10), (2, 1, 4),
(1, 3, 12), (3, 2, 9), (2, 4, 14), (4, 3, 7), (3, 5, 20), (4, 5, 4),
] { f.add_edge(u, v, c); }
let flow = f.edmonds_karp(0, 5);
let (side, cut) = f.min_cut(0);
println!("maxflow = {}", flow);
println!("S side = {:?}", side);
println!("cut = {:?}", cut);
println!("cut sum = {}", cut.iter().map(|&(_, _, c)| c).sum::<i64>());
}

25.3 最小割的构造：残留图可达集就是答案

最大流跑完后，在残留图上从 s 做一次 BFS，可达点集 S 与补集 T 构成最小割。这个构造的证明已在 25.1 给出，这里强调实现要点：必须遍历残留容量大于 0 的边，而不是原边；否则会把本该在 T 侧的点错误纳入 S。orig 数组保存输入时的原始边，用来列出割边与计算割容量——残留图里的容量是"剩余量"，不能直接当割容量用。

割边集合可能有多种，BFS 的遍历顺序不同会得到不同的最小割，但容量之和唯一。输出时要按题目要求决定是给出点集还是边集：前者直接打印 side 布尔向量，后者从 orig 里筛出 side[u] && !side[v] 的边。示例中割容量 12+7+4=23，与最大流值一致，这是定理的一次具体验证，也是 25.8 对拍检查的核心等式之一。

最小割不唯一，但所有最小割的容量相同。不同的 BFS 遍历顺序、甚至更换最大流算法，都可能给出不同的 S 侧划分；若题目要输出"字典序最小"或"包含某点"的最小割，需要额外约定并在构造时固定遍历顺序。最小割还常用于敏感性分析：把这些割边看成"瓶颈管道"，扩容其中任意一条都可能提升最大流，而扩容非割边不会产生任何效果。因此"求最小割"往往比"求最大流值"更有工程价值——它直接告诉你系统里最该加固的环节在哪。

大白话先用直觉把它讲通

把水从源头抽到汇点，管道有粗细限制。最大流是"实际最多能送多少水"，最小割是"掐断哪些管道能让总粗细最小"。定理说这两个数一样大：水送不过去，必然是因为有一组总容量刚好等于流量的管道被用满了；反过来，只需掐断这些用满的管道就能断流。跑完最大流后，从水源还能顺着"有剩余空间"的管道走到哪些地方，那些地方就是割的一侧。

25.4 Dinic：分层图、阻塞流与当前弧优化

Edmonds-Karp 每轮只找一条增广路，重头开销在反复 BFS。Dinic 把同层的增广合并成"阶段"：每阶段先用 BFS 在残留图上给点标层 level[v]，然后只允许从 level k 走到 level k+1 的边（即分层图），在分层图里用 DFS 一次性推送阻塞流——直到 s 再也送不出增广路为止。阻塞流的定义是：在当前分层图中找不到任何新的 s→t 路。每个阶段的 DFS 用 it[u] 当前弧指针跳过已经推不动的边，避免重复检查同一条无效边。

正确性来自两点：分层图只包含"向下一层"的边，所以 DFS 不会绕环，且每次推送都沿一条真实的残留路；一个阶段结束时分层图里无增广路，下一阶段 BFS 给出的层数必然严格增大，因此阶段数最多 V，总复杂度 O(V²E)。当前弧优化是关键：若不记录 it[u]，同一个点的同一条边在多次 DFS 调用里会被反复尝试，复杂度劣化。it[u] += 1 表示"这条边在当前阶段已经榨干"，之后不再试。

坑这里最容易踩

坑：增广时必须同时更新正向边与反向边：self.g[u][ei].cap -= d; self.g[to][rev].cap += d;。只改正向边会破坏残留图的对称性，后续"退流"无法表达，得到的流不合法。Rust 的借用检查还带来一个实操坑：从 self.g[u][ei] 取 to/rev/cap 时先把三者拷成局部变量（Edge 派生 Copy），再递归调用 self.dfs(...)，否则会同时持有对 self 的不可变与可变借用而编译失败。

rustRust · 标准库86 行
use std::collections::VecDeque;
#[derive(Clone, Copy)]
struct Edge { to: usize, rev: usize, cap: i64 }
struct Dinic {
n: usize,
g: Vec<Vec<Edge>>,
}
impl Dinic {
fn new(n: usize) -> Self { Dinic { n, g: vec![Vec::new(); n] } }
fn add_edge(&mut self, u: usize, v: usize, cap: i64) {
let fi = self.g[u].len();
let ri = self.g[v].len();
self.g[u].push(Edge { to: v, rev: ri, cap });
self.g[v].push(Edge { to: u, rev: fi, cap: 0 });
}
fn bfs_level(&self, s: usize, t: usize) -> (Vec<i32>, bool) {
let mut level = vec![-1i32; self.n];
let mut q = VecDeque::new();
level[s] = 0;
q.push_back(s);
while let Some(u) = q.pop_front() {
for e in &self.g[u] {
if e.cap > 0 && level[e.to] < 0 {
level[e.to] = level[u] + 1;
q.push_back(e.to);
}
}
}
let ok = level[t] >= 0;
(level, ok)
}
fn dfs(&mut self, u: usize, t: usize, f: i64, level: &[i32], it: &mut [usize]) -> i64 {
if u == t { return f; }
while it[u] < self.g[u].len() {
let ei = it[u];
let (to, rev, cap) = {
let e = &self.g[u][ei];
(e.to, e.rev, e.cap)
};
if cap > 0 && level[to] == level[u] + 1 {
let d = self.dfs(to, t, f.min(cap), level, it);
if d > 0 {
self.g[u][ei].cap -= d;
self.g[to][rev].cap += d;
return d;
}
}
it[u] += 1; // 当前弧：这条边推不动了，以后不再试
}
0
}
fn maxflow(&mut self, s: usize, t: usize) -> (i64, usize) {
let mut flow = 0i64;
let mut phases = 0usize;
loop {
let (level, ok) = self.bfs_level(s, t);
if !ok { break; }
phases += 1;
let mut it = vec![0usize; self.n];
while let Some(f) = {
let f = self.dfs(s, t, i64::MAX / 4, &level, &mut it);
if f > 0 { Some(f) } else { None }
} {
flow += f;
}
}
(flow, phases)
}
}
fn main() {
let mut d = Dinic::new(6);
for &(u, v, c) in &[
(0usize, 1usize, 16i64), (0, 2, 13), (1, 2, 10), (2, 1, 4),
(1, 3, 12), (3, 2, 9), (2, 4, 14), (4, 3, 7), (3, 5, 20), (4, 5, 4),
] { d.add_edge(u, v, c); }
println!("dinic = {:?}", d.maxflow(0, 5));
let mut d2 = Dinic::new(4);
for &(u, v, c) in &[(0usize, 1usize, 3i64), (0, 2, 2), (1, 3, 2), (2, 3, 3)] {
d2.add_edge(u, v, c);
}
println!("small = {:?}", d2.maxflow(0, 3));
}

与 EK 在同一张图上得到 23，互为印证；(23, 2) 的第二个数是阶段数，说明只需两轮 BFS 分层。i64::MAX/4 作为 DFS 的初始上界足够大又不会在累加时溢出；若容量总和可能逼近该值，应改用 saturating 加法或更大整数类型。

递归 DFS 的深度最多等于分层图的层数，不超过 V；但在 V 达十万级的图上仍有爆栈风险，工程实现可改成显式栈，或把递归改写成"沿当前弧循环推进"的迭代版。phases 返回值不只是调试信息：它直接反映分层图的推进效率，阶段数越少通常越快，25.8 的对拍可以顺便统计它。阻塞流阶段的正确性依赖"本阶段分层图里无增广路"——DFS 返回 0 就代表 s 在当前 it 指针下再也送不出流，此时 BFS 重新分层必然让 t 的层数增加或不可达，保证算法终止。

25.5 二分图匹配：匈牙利算法与交错路

二分图把点分成左右两部，边只在不同部之间。匹配是若干条两两不共享端点的边；最大匹配就是边数最多的匹配。匈牙利算法（Kuhn 版）从左部每个点出发找增广路：一条从左部未匹配点出发、交替经过未匹配边与匹配边、最终到达右部未匹配点的路径。沿这条翻转路上的匹配状态，匹配数就加一。

正确性由 Berge 定理保证：匹配最大当且仅当不存在增广路。因此从左部每个点各尝试一次，若找不到增广路就跳过，遍历结束后的匹配必是最大匹配。实现上 match_r[v] 记录右部点 v 配到的左部点，DFS 用 seen 数组防止在同一轮里反复访问同一个右部点——seen 必须在每个左部点的尝试前重置，否则会漏掉合法的增广路。aug 递归调用 aug(match_r[v], ...) 表示"把右部点 v 的现任左部伴侣改配到别处"，这是交错路的递归表达。

大白话先用直觉把它讲通

把左部想成求职者，右部想成岗位。每个人先随便找个岗位；后来者如果发现心仪岗位已被占，就递归地"劝说"占着它的人去别的岗位，只要整条调换链能顺畅走通，就多成一个匹配。找不到这种调换链时，说明当前安排已经最优。

use std::collections::VecDeque;
// 左部点 0..nl-1，右部点 0..nr-1；adj[u] 存 u 能匹配的右部点
fn hungarian(nl: usize, nr: usize, adj: &[Vec<usize>]) -> (usize, Vec<usize>, Vec<usize>) {
let mut match_r = vec![usize::MAX; nr]; // 右部点匹配到的左部点
let mut match_l = vec![usize::MAX; nl]; // 左部点匹配到的右部点
fn aug(u: usize, adj: &[Vec<usize>], match_r: &mut [usize], seen: &mut [bool]) -> bool {
for &v in &adj[u] {
if seen[v] { continue; }
seen[v] = true;
if match_r[v] == usize::MAX || aug(match_r[v], adj, match_r, seen) {
match_r[v] = u;
return true;
}
}
false
}
let mut matching = 0usize;
for u in 0..nl {
let mut seen = vec![false; nr];
if aug(u, adj, &mut match_r, &mut seen) { matching += 1; }
}
for u in 0..nl {
if match_r.iter().any(|&r| r == u) {
match_l[u] = match_r.iter().position(|&r| r == u).unwrap();
}
}
(matching, match_l, match_r)
}
// König：从未匹配左点出发，走"未匹配边向右、匹配边向左"的交错路
fn min_vertex_cover(nl: usize, nr: usize, adj: &[Vec<usize>], match_l: &[usize], match_r: &[usize]) -> (Vec<usize>, Vec<usize>) {
let mut seen_l = vec![false; nl];
let mut seen_r = vec![false; nr];
let mut q = VecDeque::new();
for u in 0..nl {
if match_l[u] == usize::MAX { seen_l[u] = true; q.push_back(u); }
}
while let Some(u) = q.pop_front() {
for &v in &adj[u] {
if seen_r[v] { continue; }
seen_r[v] = true;
let next = match_r[v];
if next != usize::MAX && !seen_l[next] {
seen_l[next] = true;
q.push_back(next);
}
}
}
let cover_l: Vec<usize> = (0..nl).filter(|&u| !seen_l[u]).collect();
let cover_r: Vec<usize> = (0..nr).filter(|&v| seen_r[v]).collect();
(cover_l, cover_r)
}
fn main() {
let adj = vec![
vec![0, 1],
vec![1, 2],
vec![0, 2],
vec![3],
];
let (m, ml, mr) = hungarian(4, 4, &adj);
println!("matching = {}", m);
println!("match_l = {:?}", ml);
println!("match_r = {:?}", mr);
let (cl, cr) = min_vertex_cover(4, 4, &adj, &ml, &mr);
println!("cover_l = {:?}", cl);
println!("cover_r = {:?}", cr);
println!("cover size = {}", cl.len() + cr.len());
}

25.6 König 定理：从匹配直接得到最小点覆盖

点覆盖是一些点，使每条边至少有一个端点被选中。König 定理说：二分图中最小点覆盖的大小等于最大匹配的大小，而且可以从最大匹配构造出来。构造方法是：从左部所有未匹配点出发，交替走"未匹配边向右、匹配边向左"的路径，标记到达的点；最后取"未标记的左部点 + 已标记的右部点"即为最小点覆盖。

为什么这组点覆盖所有边？若有边 (u,v) 两端都不在覆盖里，则 u 被标记（在左部未标记集合的补集）、v 未被标记（不在右部标记集合）。u 被标记且这条是未匹配边时 v 也应被标记，矛盾；若它是匹配边，u 被标记意味着它是从左部沿匹配边走到的，那它必是右部点走来的左端点，同样推出 v 被标记，矛盾。覆盖大小恰为匹配数的证明用到了"每条匹配边贡献恰好一个覆盖点"。

示例是完美匹配（左部全匹配），所以没有未匹配左点可作为起点，标记集为空，覆盖就是全部左部点，大小 4，与匹配数相同。这个特例看起来平凡，但 25.8 的对拍会在随机非完美匹配上验证一般情形。

König 定理的实际意义在于把"最小点覆盖"这个看起来需要搜索的问题变成"先求最大匹配，再走一次交错 BFS"的线性流程。典型应用是资源冲突：把任务与资源建成二分图，最小点覆盖给出最少需要封锁的资源集合，使其覆盖所有冲突。若还要输出具体方案，按定理构造的覆盖天然给出一组最优解，不需要再做二次优化。注意覆盖里可能同时含左部点与右部点，示例恰好全落在左部只是数据特性。

坑这里最容易踩

坑：seen 数组的作用域决定算法对错。匈牙利里它按"每个左部点一次"重置，因为它只防止单次增广尝试里的重复访问；König 里它全程共享，因为它标记的是可达性闭包。把后者的写法套到前者会导致漏增广，把前者套到后者会导致覆盖不覆盖所有边。两个函数名字像、结构像，语义却完全不同。

25.7 匹配归约为最大流：建模比算法更值钱

二分图最大匹配可以归约为最大流，从而复用 Dinic：加超级源 s 连向每个左部点、容量 1；每个左部点向它能匹配的右部点连容量 1 的边；每个右部点连向超级汇 t、容量 1。因为所有容量都是 1，最大流的每条单位流恰好对应一条匹配边，流值就是匹配数。这个建模的价值不在"再算一遍匹配"，而在于一旦套上流的框架，就能处理带限制的版本：某个左部点最多匹配 k 个右部点，把 s→该点的容量改成 k；某类右部点有总名额上限，加中间层与容量约束即可。

建模时点号的偏移要小心：左部用 0..nl，右部用 nl..nl+nr，超级源汇再往后排 nl+nr 与 nl+nr+1。若把右部点直接写成 0..nr 会与左部冲突，流量在错误的点之间流动。容量全为 1 时 Dinic 的阶段数很少，实际运行很快；对纯二分匹配，匈牙利代码更短、常数更小，但归约法在需要附加约束时更灵活。

更复杂的限制也能套进同一框架：若某个右部点最多被匹配 k 次，把"右部点→汇"的容量从 1 改成 k；若某些左部点之间存在互斥，可加中间层把它们连到一个总容量为 1 的节点。最小割在这里也有解释——由最大流最小割定理，匹配的最大基数等于某个最小割容量，割的结构对应"哪些约束是真正卡住匹配的瓶颈"。建模完成后务必用一个已知答案的小例子手验，例如左右各 1 点且有边时应得到流值 1；点号偏移错误往往在小例子上就能发现，也能防止把超级源汇的边误连到不存在的点号上。

25.8 随机对拍：最小割枚举当裁判

网络流的正确性验证有个天然优势：小规模图上可以枚举所有割，取最小割容量作为裁判，完全独立于增广路算法。对 n≤8 的随机容量网络，枚举中间点是否属于 S 的 2^(n−2) 种划分，计算每种割的容量取最小值；Edmonds-Karp、Dinic 的最大流值以及从残留可达集算出的割容量三者都必须等于它。随机边可能出现平行边与自环，前者不影响流，后者在建模时应跳过（自环不参与割）。

二分图部分用两套独立算法互证：匈牙利算出的匹配数，必须等于把图归约为流网络后 Dinic 的流值；同时用 König 构造出点覆盖，验证它的大小等于匹配数，且每条边确实被覆盖。生成器用 xorshift，随机决定每条左右组合是否存在边，规模控制在左右各 1..=5，保证枚举与递归都便宜。

use std::collections::VecDeque;
struct Rng(u64);
impl Rng {
fn next(&mut self) -> u64 {
let mut x = self.0;
x ^= x << 13; x ^= x >> 7; x ^= x << 17;
self.0 = x; x
}
fn below(&mut self, n: usize) -> usize { (self.next() % n as u64) as usize }
}
#[derive(Clone, Copy)]
struct Edge { to: usize, rev: usize, cap: i64 }
struct Flow { n: usize, g: Vec<Vec<Edge>>, orig: Vec<(usize, usize, i64)> }
impl Flow {
fn new(n: usize) -> Self { Flow { n, g: vec![Vec::new(); n], orig: Vec::new() } }
fn add(&mut self, u: usize, v: usize, c: i64) {
let (fi, ri) = (self.g[u].len(), self.g[v].len());
self.g[u].push(Edge { to: v, rev: ri, cap: c });
self.g[v].push(Edge { to: u, rev: fi, cap: 0 });
self.orig.push((u, v, c));
}
fn ek(&mut self, s: usize, t: usize) -> i64 {
let mut flow = 0i64;
loop {
let (mut pv, mut pe) = (vec![usize::MAX; self.n], vec![usize::MAX; self.n]);
let mut seen = vec![false; self.n];
let mut q = VecDeque::new();
seen[s] = true; q.push_back(s);
while let Some(u) = q.pop_front() {
for (i, e) in self.g[u].iter().enumerate() {
if e.cap > 0 && !seen[e.to] {
seen[e.to] = true; pv[e.to] = u; pe[e.to] = i; q.push_back(e.to);
}
}
}
if !seen[t] { break; }
let (mut d, mut v) = (i64::MAX, t);
while v != s { d = d.min(self.g[pv[v]][pe[v]].cap); v = pv[v]; }
v = t;
while v != s {
let (u, ei) = (pv[v], pe[v]);
let rev = self.g[u][ei].rev;
self.g[u][ei].cap -= d; self.g[v][rev].cap += d; v = u;
}
flow += d;
}
flow
}
fn residual_reachable(&self, s: usize) -> Vec<bool> {
let mut seen = vec![false; self.n];
let mut q = VecDeque::new();
seen[s] = true; q.push_back(s);
while let Some(u) = q.pop_front() {
for e in &self.g[u] { if e.cap > 0 && !seen[e.to] { seen[e.to] = true; q.push_back(e.to); } }
}
seen
}
}
struct Dinic { n: usize, g: Vec<Vec<Edge>> }
impl Dinic {
fn new(n: usize) -> Self { Dinic { n, g: vec![Vec::new(); n] } }
fn add(&mut self, u: usize, v: usize, c: i64) {
let (fi, ri) = (self.g[u].len(), self.g[v].len());
self.g[u].push(Edge { to: v, rev: ri, cap: c });
self.g[v].push(Edge { to: u, rev: fi, cap: 0 });
}
fn dfs(&mut self, u: usize, t: usize, f: i64, level: &[i32], it: &mut [usize]) -> i64 {
if u == t { return f; }
while it[u] < self.g[u].len() {
let ei = it[u];
let (to, rev, cap) = { let e = &self.g[u][ei]; (e.to, e.rev, e.cap) };
if cap > 0 && level[to] == level[u] + 1 {
let d = self.dfs(to, t, f.min(cap), level, it);
if d > 0 { self.g[u][ei].cap -= d; self.g[to][rev].cap += d; return d; }
}
it[u] += 1;
}
0
}
fn maxflow(&mut self, s: usize, t: usize) -> i64 {
let mut flow = 0i64;
loop {
let mut level = vec![-1i32; self.n];
let mut q = VecDeque::new();
level[s] = 0; q.push_back(s);
while let Some(u) = q.pop_front() {
for e in &self.g[u] { if e.cap > 0 && level[e.to] < 0 { level[e.to] = level[u] + 1; q.push_back(e.to); } }
}
if level[t] < 0 { break; }
let mut it = vec![0usize; self.n];
loop {
let d = self.dfs(s, t, i64::MAX / 4, &level, &mut it);
if d == 0 { break; }
flow += d;
}
}
flow
}
}
fn brute_min_cut(n: usize, orig: &[(usize, usize, i64)], s: usize, t: usize) -> i64 {
let mid: Vec<usize> = (0..n).filter(|&i| i != s && i != t).collect();
let mut best = i64::MAX;
for mask in 0..(1usize << mid.len()) {
let in_s = |v: usize| -> bool {
if v == s { return true; }
if v == t { return false; }
mid.iter().position(|&x| x == v).map(|i| (mask >> i) & 1 == 1).unwrap_or(false)
};
let cap: i64 = orig.iter().filter(|&&(u, v, _)| in_s(u) && !in_s(v)).map(|&(_, _, c)| c).sum();
best = best.min(cap);
}
best
}
fn hungarian(nl: usize, nr: usize, adj: &[Vec<usize>]) -> (usize, Vec<usize>, Vec<usize>) {
let mut mr = vec![usize::MAX; nr];
fn aug(u: usize, adj: &[Vec<usize>], mr: &mut [usize], seen: &mut [bool]) -> bool {
for &v in &adj[u] {
if seen[v] { continue; }
seen[v] = true;
if mr[v] == usize::MAX || aug(mr[v], adj, mr, seen) { mr[v] = u; return true; }
}
false
}
let mut m = 0;
for u in 0..nl { let mut seen = vec![false; nr]; if aug(u, adj, &mut mr, &mut seen) { m += 1; } }
let ml: Vec<usize> = (0..nl).map(|u| mr.iter().position(|&x| x == u).unwrap_or(usize::MAX)).collect();
(m, ml, mr)
}
fn konig(nl: usize, nr: usize, adj: &[Vec<usize>], ml: &[usize], mr: &[usize]) -> (Vec<usize>, Vec<usize>) {
let (mut sl, mut sr) = (vec![false; nl], vec![false; nr]);
let mut q = VecDeque::new();
for u in 0..nl { if ml[u] == usize::MAX { sl[u] = true; q.push_back(u); } }
while let Some(u) = q.pop_front() {
for &v in &adj[u] {
if sr[v] { continue; }
sr[v] = true;
let nx = mr[v];
if nx != usize::MAX && !sl[nx] { sl[nx] = true; q.push_back(nx); }
}
}
((0..nl).filter(|&u| !sl[u]).collect(), (0..nr).filter(|&v| sr[v]).collect())
}
fn main() {
let mut rng = Rng(0xFEED_FACE_CAFE_BEEF);
let (mut flows, mut matches, mut bad) = (0, 0, 0);
for _ in 0..1200 {
// 随机容量网络：EK 与 Dinic 的最大流都对最小割枚举
let n = 2 + rng.below(7);
let s = 0; let t = n - 1;
let mut edges = Vec::new();
for _ in 0..rng.below(14) {
let u = rng.below(n); let v = rng.below(n);
if u != v { edges.push((u, v, rng.below(10) as i64 + 1)); }
}
let brute = brute_min_cut(n, &edges, s, t);
let mut f = Flow::new(n);
for &(u, v, c) in &edges { f.add(u, v, c); }
let ek = f.ek(s, t);
let side = f.residual_reachable(s);
let cut: i64 = edges.iter().filter(|&&(u, v, _)| side[u] && !side[v]).map(|&(_, _, c)| c).sum();
let mut d = Dinic::new(n);
for &(u, v, c) in &edges { d.add(u, v, c); }
let din = d.maxflow(s, t);
if ek != brute || din != brute || cut != brute {
bad += 1;
if bad <= 3 { println!("BAD flow n={} ek={} din={} brute={} cut={}", n, ek, din, brute, cut); }
}
flows += 1;
// 随机二分图：匈牙利与网络流最大匹配对照，并核验 König 覆盖
let nl = 1 + rng.below(5);
let nr = 1 + rng.below(5);
let mut adj = vec![Vec::new(); nl];
for u in 0..nl { for v in 0..nr { if rng.below(3) == 0 { adj[u].push(v); } } }
let (m, ml, mr) = hungarian(nl, nr, &adj);
let (s2, t2) = (nl + nr, nl + nr + 1);
let mut d2 = Dinic::new(nl + nr + 2);
for u in 0..nl { d2.add(s2, u, 1); }
for u in 0..nl { for &v in &adj[u] { d2.add(u, nl + v, 1); } }
for v in 0..nr { d2.add(nl + v, t2, 1); }
let mflow = d2.maxflow(s2, t2);
let (cl, cr) = konig(nl, nr, &adj, &ml, &mr);
let cover_ok = (cl.len() + cr.len()) == m && adj.iter().enumerate().all(|(u, vs)| {
vs.iter().all(|&v| cl.contains(&u) || cr.contains(&v))
});
if m as i64 != mflow || !cover_ok {
bad += 1;
if bad <= 3 { println!("BAD match nl={} nr={} hung={} flow={} cover_ok={}", nl, nr, m, mflow, cover_ok); }
}

}
println!("flow_graphs={} bipartite_graphs={} mismatches={}", flows, matches, bad);

}

随机数规模的选择有讲究：n≤8 保证割枚举最多 64 种划分，左右各 ≤5 保证递归与覆盖检查都便宜；如果 n 大到 20，割枚举的 2¹⁸ 次划分会让裁判本身成为瓶颈。种子写死在源码里，任何失败都能重放。若某次对拍报 MISMATCH，先固定种子缩小到最小反例，再检查是容量更新漏了反向边，还是裁判的割枚举漏了某种划分——裁判本身也可能是错的，这点与第 23 单元的负环可达性教训一致。

25.9 工程取舍：容量类型、建模与失败信号

选算法先看规模与结构：n、m 都较小时 Edmonds-Karp 代码最短；一般场景 Dinic 是默认选择；纯二分匹配用匈牙利更轻量，带附加约束时用流建模。复杂度上 EK 是 O(VE²)，Dinic 是 O(V²E)，匈牙利是 O(VE)；这些上界在单位容量或二分图上往往达不到，实际运行快得多。

容量类型要用 i64：若用 i32，累加多个容量时可能溢出成负数，导致残留容量变负、算法提前退出，而且错误很难察觉。i64::MAX/4 作为无穷大上界要给加法留余量。失败信号主要是"无可行流"——若题目要求特定流量 F 而最大流不足，必须显式返回布尔值或 Option，不能默认截断。二分匹配里"未匹配"用 usize::MAX 哨兵，与第 24 单元的讨论一致：合法点号不会取到这个值，所以判定安全。

算法 适用 复杂度 关键结构 典型失败/边界
Edmonds-Karp 一般流网络 O(VE²) BFS 最短增广路 无增广路即最大流
Dinic 一般流网络 O(V²E) 分层图 + 当前弧 level[t] < 0 即结束
匈牙利 二分匹配 O(VE) 交错路 + seen 无增广路即最大匹配
流建模匹配 带约束匹配 取决于流算法 超级源汇 + 单位容量 流值 < 需求即无解
