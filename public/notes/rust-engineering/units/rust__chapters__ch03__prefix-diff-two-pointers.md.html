21.1 前缀和：不变量、哨兵与一维区间查询

问题定义：给定数组，频繁查询任意区间 [l, r) 的元素和。若每次都累加区间内元素，单次是 O(n)，q 次查询就是 O(nq)。

不变量：pref[i] 等于原数组前 i 个元素之和，也就是 [0, i) 的和。为了省掉对 i == 0 的特判，预分配 n + 1 个位置并让 pref[0] = 0 当哨兵。建表用一次循环完成，之后任意区间 [l, r) 的和都是 pref[r] - pref[l]，把 O(n) 的查询降到 O(1)。区间统一用左闭右开：长度直接是 r - l，两个相邻区间的边界不会重叠，空区间 [i, i) 的和自然是 0。

rustRust · 标准库13 行
fn main() {
let a = [1i64, 3, 5, 7, 9, 11];
let mut pref = Vec::with_capacity(a.len() + 1);
pref.push(0i64);
for &x in &a {
let last = *pref.last().unwrap();
pref.push(last + x);
}
let pairs = [(0usize, 3usize), (1, 4), (2, 2), (0, 6)];
for (l, r) in pairs {
println!("[{}, {}) = {}", l, r, pref[r] - pref[l]);
}
}

这里没有写 pref.push(pref[pref.len() - 1] + x)，而是先用 last() 取出旧值再 push。虽然 Rust 的两阶段借用通常允许前者，但先取值的写法意图更明确，也避免了在循环中反复索引 len() - 1。如果原数组元素可能很大，前缀和要用 i64 累加，否则 i32 在一百万个 10⁹ 元素上必然溢出。涉及取模的题目（例如统计子数组和能被 k 整除的个数）要在每次累加后立即取模，并用 HashMap<i64, usize> 统计每个余数出现次数，核心思想仍是"两个前缀同余则其差能被 k 整除"。

复杂度非常清晰：建表 O(n) 时间、O(n) 空间，每次查询 O(1) 时间。当查询次数 q 较大时，总代价从 O(nq) 降到 O(n + q)。这是典型的离线预处理换查询速度——只有查询模式允许提前建表时才适用；如果数组会在查询之间被修改，纯前缀和就力不从心，需要改用树状数组或线段树，把单点修改也降到 O(log n)。

还有一种原地前缀和变体：直接把 a[i] 改成前 i 项之和，不再分配新数组，省内存但会破坏原数据。刷题时若后面还要用原数组，就别这么做；若只用一次，原地版本能少一半内存占用。涉及取模的题目要在每次累加后立即取模，避免中间和溢出；同时注意 Rust 的 % 对负数返回负余数（-3 % 5 == -3），若希望余数落在 [0, k) 区间，要写成 ((x % k) + k) % k。这个小细节在"统计子数组和能被 k 整除"这类题目里经常导致计数偏差，因为负余数和正余数本质上是同一类，却会被当成不同的键。

大白话先用直觉把它讲通

前缀和就像给一排数字提前记好"从开头到每个位置一共多少"。有了这张表，问任意一段的和只要用大计数减小计数，一下就算出来。关键在于多记一个"开头之前是 0"的哨兵，这样连从第一个元素开始的区间也不用特殊处理。

21.2 二维前缀和：整体右移一位避开下溢

二维前缀和把同样的思想扩展到矩阵。ps[r][c] 表示左上角 (0,0) 到右下角 (r-1,c-1) 的矩形和。递推式是 ps[r][c] = a[r-1][c-1] + ps[r-1][c] + ps[r][c-1] - ps[r-1][c-1]，也就是"自己加上方加左方，再把重复算的左上角减一次"。查询 [r1, r2) × [c1, c2) 用同样的容斥：ps[r2][c2] - ps[r1][c2] - ps[r2][c1] + ps[r1][c1]。

关键技巧是把所有下标整体加一：原矩阵 m × n 存进 (m+1) × (n+1) 的前缀数组，让第 0 行和第 0 列全为 0。这样递推里的 r - 1、c - 1 都变成合法的索引运算，彻底绕开 usize 下溢。如果在 0 基数组里硬写 ps[i-1][j]，那么 i = 0 时程序会当场 panic。这不是麻烦，而是 Rust 帮你把"越界读内存"这类经典 bug 提前到开发阶段。

rustRust · 标准库29 行
fn build_prefix_2d(grid: &[Vec<i64>]) -> Vec<Vec<i64>> {
let rows = grid.len();
let cols = if rows == 0 { 0 } else { grid[0].len() };
let mut ps = vec![vec![0i64; cols + 1]; rows + 1];
for r in 0..rows {
for c in 0..cols {
ps[r + 1][c + 1] = grid[r][c]
+ ps[r][c + 1]
+ ps[r + 1][c]
- ps[r][c];
}
}
ps
}
fn sum_2d(ps: &[Vec<i64>], r1: usize, c1: usize, r2: usize, c2: usize) -> i64 {
ps[r2][c2] - ps[r1][c2] - ps[r2][c1] + ps[r1][c1]
}
fn main() {
let g = vec![
vec![1i64, 2, 3],
vec![4, 5, 6],
vec![7, 8, 9],
];
let ps = build_prefix_2d(&g);
println!("whole = {}", sum_2d(&ps, 0, 0, 3, 3));
println!("center = {}", sum_2d(&ps, 1, 1, 2, 2));
}
坑这里最容易踩

三个常见错误。其一，二维递推时把 ps[r][c] 写成 ps[r+1][c+1] 之后忘了对应调整查询公式，导致两者下标体系不一致——建表与查询必须共用同一套"整体加一"约定。其二，用 Vec<Vec<i64>> 的 vec![vec![0; cols+1]; rows+1] 初始化时，内层 Vec 会被克隆，对 Copy 类型没问题，但若换成非 Copy 元素要格外小心共享引用。其三，矩阵元素为负时，容斥公式中的减法顺序不能随意交换：ps[r2][c2] - ps[r1][c2] - ps[r2][c1] + ps[r1][c1] 里最后一项是加回被多减一次的左上角，写成减法就会出错。

查询复杂度 O(1)，建表 O(mn)，空间 O(mn)。二维前缀和常用于"统计满足条件的子矩阵个数"：枚举矩形的上下边界，再把左右边界的判定转化为一维问题。例如求"和不超过 K 的子矩阵个数"，可以先固定上下边界 r1、r2，把每一列 c 上这两行之间的元素和压成一维数组 col[c]，问题就变成"求 col 中和不超过 K 的子数组个数"——用第 20 单元的归并排序或第 19 单元的树状数组都能在 O(n log n) 内解决。整个算法是 O(m² · n log n)，比四重循环的 O(m²n²) 快得多。这个"降维"技巧是二维前缀和最实用的价值：把二维问题拆成若干一维子问题，复用已经掌握的工具。掌握了整体右移这位移技巧，后续二维差分、二维树状数组都能用同样思路处理。

21.3 差分：区间加的 O(1) 端点修改

问题定义：给定数组，频繁对区间 [l, r] 整体加一个值，最后查询各点的值。若每次区间加都遍历区间内元素，单次 O(n)，m 次修改就是 O(nm)。

不变量：diff[i] 定义为 a[i] - a[i-1]（令 a[-1] = 0），对 diff 做前缀和就还原出 a。由此得到一个极强的操作：要把区间 [l, r] 整体加 delta，只需 diff[l] += delta、diff[r+1] -= delta 两处修改——前缀和扫到 l 时开始生效，扫过 r 后被抵消。多次区间加可以全部 O(1) 处理，最后统一 O(n) 还原，总代价从 O(nm) 降到 O(n + m)。

下面的实现预分配 n + 1 个位置，让 r + 1 == n 时仍能安全写入差分边界；只有 r + 1 >= diff.len() 才跳过，而这个判断在合法输入下不会触发。还原时维护滚动变量 cur，避免真的去改差分数组本身——这让差分数组保持"只记录修改"的纯粹语义，便于多次复用。

rustRust · 标准库22 行
fn range_add_diff(n: usize, ops: &[(usize, usize, i64)]) -> Vec<i64> {
// 每个三元组 (l, r, delta) 表示对闭区间 [l, r] 加 delta
let mut diff = vec![0i64; n + 1];
for &(l, r, delta) in ops {
diff[l] += delta;
if r + 1 < diff.len() {
diff[r + 1] -= delta;
}
}
let mut cur = 0i64;
let mut out = Vec::with_capacity(n);
for i in 0..n {
cur += diff[i];
out.push(cur);
}
out
}
fn main() {
let ops = [(0usize, 2usize, 3i64), (1, 3, -1), (2, 4, 5)];
println!("{:?}", range_add_diff(5, &ops));
}

差分与前缀和经常组合使用：先对原数组建一次差分，执行若干次区间加，再对差分求前缀得到新数组，最后对新数组求前缀得到区间和查询表，整体仍是 O(n + m)。二维差分同理，区间加 [x1,x2] × [y1,y2] 变成四个角点的符号修改，公式与二维前缀和互为镜像。

需求 工具 单次修改 单次查询
区间和 前缀和 建表 O(n) O(1)
区间加、单点值 差分 O(1) 还原后 O(1)
区间加、区间和 差分 + 两层前缀 O(1) 还原后 O(1)
单点加、区间和 树状数组 O(log n) O(log n)

要注意差分的离线属性：上面的代码必须先把所有修改收集完，才能统一还原出最终数组。如果题目要求"每做一次区间加就立刻回答一次查询"，纯差分就力不从心了，需要改用树状数组或线段树。区分在线与离线是选择数据结构的第一步：能在读入阶段一次性拿到全部操作时，离线算法往往更简单也更快。另外差分值为负数完全合法，用 i64 存储即可。

表和里"差分 + 两层前缀"值得展开：完成区间加后先对 diff 求前缀得到最终数组 a'，再对 a' 求前缀得到 pref'，此后任意区间和查询就是 pref'[r] - pref'[l]，全程 O(1) 查询。两层前缀看起来只是把同一件事做两遍，但它们的语义不同——第一层把"增量"还原成"值"，第二层把"值"压缩成"可查询的和"。混用或漏掉其中一层，是初学者最常见的错误。二维差分的构造方式与二维前缀和互为镜像：区间加变成四个角点 (x1,y1) 加 delta、(x2+1,y1) 减 delta、(x1,y2+1) 减 delta、(x2+1,y2+1) 加 delta，最后对两个维度分别求前缀即可还原。

21.4 双指针：相向与同向两种流派

双指针有两大流派，适用前提和移动方式完全不同。相向双指针：左指针从开头、右指针从结尾出发，根据当前状态与目标的关系移动其中一个。典型是排序数组的两数之和：和大于目标就让右指针左移，小于目标就让左指针右移。它要求数组有序，每次移动都单调地缩小搜索范围，因此是 O(n)。写这类代码时，l < r 的循环条件要保证 i + 1 不超过 n - 1，把固定元素的循环上界设为 n - 2 最省心；遇到重复元素要跳过，否则结果里有大量重复三元组。

同向双指针（滑动窗口）：左右指针都只向右走，右指针负责扩大窗口，左指针负责在窗口"不合法"时收缩。典型是求最短子数组或无重复最长子串。它的正确性依赖两个不变量：其一，窗口 [left, right] 始终满足题目对右端的扩展要求；其二，每轮收缩后窗口恰好是"以 right 结尾的最优窗口"。左指针绝不回退是关键——如果某个左端位置被排除，那么以更靠右的 right 结尾时它也不可能重新变优。这个单调性一旦不成立（例如窗口合法性与 right 不单调），双指针就会失效，必须换用别的方法。

两种流派的共同点是"每步都有明确的移动依据，且指针不回头"，这正是把 O(n²) 的暴力枚举压到 O(n) 的根本原因。区分题目属于哪一派，可以先看"答案是否需要两端配合"：两数之和、三数之和、接雨水这类需要两端夹逼的属于相向；最长、最短、计数这类"以某个右端为基准找最优左端"的属于同向。选错流派往往意味着写不出正确的移动条件，而不是仅仅常数差一点。

以三数之和为例，排序后固定一个数 a[i]，在 i+1..n 区间用 l、r 夹逼：若三数之和大于 0 就 r -= 1，小于 0 就 l += 1，等于 0 则记录答案并同时跳过重复的 a[l] 与 a[r]。这里的 r -= 1 在 usize 上是安全的，因为循环条件是 l < r 且 l ≥ i+1 ≥ 1，所以 r > 0 必然成立；但如果把循环写成 l <= r 且允许 l = 0，r = 0 时的 r - 1 就会下溢。Rust 强迫你把这类前提想清楚，写出的代码反而比 C++ 更不容易出现隐蔽的越界。排序 + 双指针把原本 O(n³) 的暴力枚举压到 O(n²)，也再次说明"有序"是双指针能工作的重要前提。

21.5 滑动窗口的不变量与收缩条件

下面用两个经典例子展示滑动窗口的写法。最短子数组和：right 每纳入一个元素就累加 sum，只要 sum >= target 就不断记录长度并收缩左端。最长无重复子串：用定长数组 last[256] 记录每个字节最后出现的位置，usize::MAX 表示"从未出现"；当重复字节的上次位置仍在当前窗口内时，把 left 跳到它后面一位。

rustRust · 标准库34 行
fn min_subarray_sum(a: &[i64], target: i64) -> usize {
let (mut left, mut sum, mut best) = (0usize, 0i64, usize::MAX);
for (right, &x) in a.iter().enumerate() {
sum += x;
while sum >= target && left <= right {
best = best.min(right - left + 1);
sum -= a[left];
left += 1;
}
}
if best == usize::MAX { 0 } else { best }
}
fn longest_unique(s: &str) -> usize {
let bytes = s.as_bytes();
let mut last = [usize::MAX; 256];
let mut left = 0usize;
let mut best = 0usize;
for (right, &b) in bytes.iter().enumerate() {
let idx = b as usize;
if last[idx] != usize::MAX && last[idx] >= left {
left = last[idx] + 1;
}
last[idx] = right;
best = best.max(right - left + 1);
}
best
}
fn main() {
let a = [2i64, 3, 1, 2, 4, 3];
println!("min len = {}", min_subarray_sum(&a, 7));
println!("longest unique = {}", longest_unique("abcabcbb"));
}

longest_unique 只适用于 ASCII 字节串；处理中文要用 char 与 HashMap<char, usize>，因为 UTF-8 下一个汉字占多个字节，按字节切片可能切在字符中间导致 panic。判断重复时用 last[idx] >= left 而不是 != usize::MAX，是为了只在"上次出现位置仍在当前窗口内"时才移动左端——若上次出现已被之前的收缩甩在窗口外，就无需再动。返回值用字节下标差值表示长度，对纯 ASCII 串恰好等于字符数；换成 char 版本后，计数单位变成字符数，答案语义也随之改变，题目若要求"最长子串的字符数"就必须用后者。两种实现的复杂度都是 O(n)，差别只在字符集大小与索引方式。

21.6 边界防御：usize、空窗口与溢出

这一类题目出错往往不是算法想错，而是边界处理不细。逐项核对能省很多时间：区间是闭区间还是左闭右开；前缀数组是否多开了一格作哨兵；二维递推是否已经整体右移一位以避开 i - 1；差分修改的右端点是 r 还是 r + 1；收缩窗口时 left 是否会越过 right 导致 right - left + 1 下溢；累加和是否需要 i64。

最危险的三个具体陷阱如下。其一，usize::MAX 是合法的哨兵值，但它加一就会回绕成 0。longest_unique 里先判断 last[idx] != usize::MAX 再执行 left = last[idx] + 1，顺序绝不能颠倒。其二，right - left + 1 只有在 right >= left 时才有意义，min_subarray_sum 的 while 条件里加一道 left <= right 的防线几乎不花成本。其三，累加溢出：sum += x 在 i64 上累加一百万个 10⁹ 也会溢出，若题目数据范围接近类型上限，要用 i128 或在每一步检查 checked_add。

另一个 Rust 专属细节是用 .get(i) 替代直接下标访问，在边界不确定的地方把 panic 变成显式的 if let，调试时定位问题会快很多。"宁可多判断一次，也不要让 usize 偷偷回绕"是这一单元的黄金准则。写不变量注释尤其有效：在滑动窗口里注明"窗口内和小于 target，且 left 是满足条件的最小位置"，在差分里注明"diff 的前缀等于当前增量"，每次循环体内只做保持不变量的事，代码就很难错。

手工推演同样不可或缺。拿 min_subarray_sum 的 [2,3,1,2,4,3]、target=7 走一遍：right=0、1、2 时 sum 依次是 2、5、6，都不达标；right=3 纳入 2 后 sum=8 达标，记录窗口 [0,3] 长度 4，去掉 a[0]=2 后 sum=6 停止；right=4 纳入 4 后 sum=10，先记 [1,4] 长度 4，去掉 a[1]=3 后 sum=7 仍达标，再记 [2,4] 长度 3，去掉 a[2]=1 后 sum=6 停止；right=5 纳入 3 后 sum=9，记 [3,5] 长度 3，去掉 a[3]=2 后 sum=7，再记 [4,5] 长度 2，去掉 a[4]=4 后 sum=3 停止。最终 best=2，与程序输出一致。这个推演验证了"每轮收缩后窗口是以 right 结尾的最短达标窗口"这一不变量：窗口 [4,5] 的值 4+3=7 恰好达标，左端再往右移就不满足了。手工模拟比单步调试更快定位逻辑偏差，等推演与输出一致，再交给随机对拍做大范围验证。

21.7 随机对拍：前缀、差分、双指针一起验

本单元四种工具都容易错在边界，用固定种子 2026 的 LCG 一次性与暴力解法对拍，能把"看起来对"变成"实测都对"。

对照组设计：一维前缀对暴力区间累加；二维前缀对暴力矩形累加；差分对"真的把每次区间加写进数组"；最短子数组对枚举所有子段；最长无重复子串对枚举所有子串并检查字节唯一性。随机数据刻意包含负数（前缀、差分）、重复字符（无重复子串）与达不到的 target（最短子数组），专门压测退化分支。

fn lcg(state: &mut u64) -> u64 {
*state = state
.wrapping_mul(6364136223846793005)
.wrapping_add(1442695040888963407);
*state >> 33
}
fn prefix_1d(a: &[i64]) -> Vec<i64> {
let mut pref = Vec::with_capacity(a.len() + 1);
pref.push(0i64);
for &x in a { pref.push(*pref.last().unwrap() + x); }
pref
}
fn prefix_2d(grid: &[Vec<i64>]) -> Vec<Vec<i64>> {
let rows = grid.len();
let cols = if rows == 0 { 0 } else { grid[0].len() };
let mut ps = vec![vec![0i64; cols + 1]; rows + 1];
for r in 0..rows {
for c in 0..cols {
ps[r + 1][c + 1] = grid[r][c] + ps[r][c + 1] + ps[r + 1][c] - ps[r][c];
}
}
ps
}
fn sum_2d(ps: &[Vec<i64>], r1: usize, c1: usize, r2: usize, c2: usize) -> i64 {
ps[r2][c2] - ps[r1][c2] - ps[r2][c1] + ps[r1][c1]
}
fn sum_2d_slow(grid: &[Vec<i64>], r1: usize, c1: usize, r2: usize, c2: usize) -> i64 {
let mut s = 0i64;
for r in r1..r2 { for c in c1..c2 { s += grid[r][c]; } }
s
}
fn diff_apply(n: usize, ops: &[(usize, usize, i64)]) -> Vec<i64> {
let mut diff = vec![0i64; n + 1];
for &(l, r, delta) in ops {
diff[l] += delta;
if r + 1 < diff.len() { diff[r + 1] -= delta; }
}
let mut cur = 0i64;
let mut out = Vec::with_capacity(n);
for i in 0..n { cur += diff[i]; out.push(cur); }
out
}
fn diff_slow(n: usize, ops: &[(usize, usize, i64)]) -> Vec<i64> {
let mut a = vec![0i64; n];
for &(l, r, delta) in ops { for i in l..=r { a[i] += delta; } }
a
}
fn min_subarray(a: &[i64], target: i64) -> usize {
let (mut left, mut sum, mut best) = (0usize, 0i64, usize::MAX);
for (right, &x) in a.iter().enumerate() {
sum += x;
while sum >= target && left <= right {
best = best.min(right - left + 1);
sum -= a[left];
left += 1;
}
}
if best == usize::MAX { 0 } else { best }
}
fn min_subarray_slow(a: &[i64], target: i64) -> usize {
let mut best = usize::MAX;
for i in 0..a.len() {
let mut s = 0i64;
for j in i..a.len() {
s += a[j];
if s >= target { best = best.min(j - i + 1); }
}
}
if best == usize::MAX { 0 } else { best }
}
fn longest_unique(s: &str) -> usize {
let bytes = s.as_bytes();
let mut last = [usize::MAX; 256];
let mut left = 0usize;
let mut best = 0usize;
for (right, &b) in bytes.iter().enumerate() {
let idx = b as usize;
if last[idx] != usize::MAX && last[idx] >= left { left = last[idx] + 1; }
last[idx] = right;
best = best.max(right - left + 1);
}
best
}
fn longest_unique_slow(s: &str) -> usize {
let b = s.as_bytes();
let mut best = 0usize;
for i in 0..b.len() {
for j in i..b.len() {
let mut seen = [false; 256];
let mut ok = true;
for &x in &b[i..=j] {
if seen[x as usize] { ok = false; break; }
seen[x as usize] = true;
}
if ok { best = best.max(j - i + 1); }
}
}
best
}

对拍里有一个细节：生成查询区间时先随机取两个数再取 min/max 作为左右端点，这样既覆盖了 l == r 的空区间，又避免了生成非法区间。同理，差分区间也用 l.min(r)、l.max(r) 保证合法。构造数据时"先生成再规范化"比"边生成边判断"更简单，也更不容易漏掉边界情况。

前缀和与差分是一对互逆工具——一个负责"快速问"，一个负责"快速改"。双指针则是让两个游标按规矩走路，不走回头路，于是不用把每对组合都试一遍。它们背后的共同思想是：先用预处理或单调性排除掉大量不可能的情况，只在剩下的候选里做文章。

21.8 离线与在线的取舍、练习与自检

前缀和与差分都属于离线工具：必须先拿到全部数据才能建表或还原。一旦题目变成"每做一次修改就立刻回答一次查询"，纯前缀和/差分就力不从心，需要树状数组或线段树把单次修改与查询都降到 O(log n)。区分在线与离线是选择数据结构的第一步：能在读入阶段一次性拿到全部操作时，离线算法往往更简单也更快；反之则老老实实上在线结构，不要试图用离线技巧硬凑。双指针则介于两者之间——它是在一次扫描中边走边算，但需要数组静态（或至少窗口状态可增量维护）。

四类工具的选择可以归纳成一句话：频繁问区间和用前缀和，频繁改区间值用差分，答案具有单调性且可增量维护用双指针，二者都要且必须在线用树状数组。掌握这个分类，遇到区间类问题就能先在纸上画出草图，再决定用哪种结构，而不是上来就套模板。

复杂度上，一维前缀与差分都是"预处理 O(n)、单次 O(1)"，二维版本是"预处理 O(mn)、单次 O(1)"，双指针是单趟 O(n) 或 O(mn) 加排序的 O(n log n)。写代码时不妨在注释里同时记下不变量与复杂度：不变量证明正确性，复杂度说明适用边界。当查询量从几千涨到几百万时，正是这些预先想清楚的量级决定了方案是否需要推倒重来，而不是等到超时才回头找原因。这些数字本身不难，难的是把它们与约束对应：当区间查询达到 10⁶ 次时，O(1) 与 O(n) 的差距是百万倍，离线预处理的收益无可替代；而当数组每步都在变时，再优雅的离线表也用不上，必须换在线结构。工程判断的核心永远是"先看清操作的时序，再选工具"，这一点比记住任何模板都重要。到第 21 单元为止，算法编前五块基础设施——复杂度与对拍、单调栈队列、并查集与堆、排序二分、前缀差分与双指针——已经齐备，后续树、图、DP、字符串等单元都会反复调用它们。
