17.1 Rust 排序 API 与比较器

Vec 和切片都提供了三个常用排序方法：sort 稳定排序，相等元素保持原有相对顺序，需要额外的临时内存，最坏 O(n log n) 比较、O(n) 额外空间；sort_unstable 不保证稳定性，通常更快且只用地毯式堆排与插入排的混合实现，额外空间 O(log n)；sort_by_key 按提取出的关键字排序。判断标准很简单：相等元素是否需要保留输入顺序——按分数排序后还要按名字排第二关键字时用稳定排序，或者干脆把两个关键字写进一个比较器里。

比较器接收两个 &T，返回 Ordering。降序不是把结果取负（Rust 的 Ordering 没有取负运算），而是把参数顺序反过来写：b.cmp(a)。多关键字用 then_with 串联：q.1.cmp(&p.1).then_with(|| p.0.cmp(q.0)) 表示分数降序、同分时名字升序。注意闭包参数名字 p 和 q 的顺序，写反了会得到完全相反的结果，这是排序题最常见的低级错误。

方法 稳定性 额外空间 适用场景
sort() 稳定 O(n) 相等元素需保留原序
sort_unstable() 不稳定 O(log n) 默认首选，更快
sort_by(cmp) 由底层决定 同上 自定义规则、降序
sort_by_key(f) 稳定 O(n) 单一关键字
rustRust · 标准库17 行
fn main() {
let mut a = vec![5, 2, 9, 1, 5, 6];
let mut stable = a.clone();
stable.sort();
println!("ascending: {:?}", stable);
a.sort_unstable();
println!("unstable asc: {:?}", a);
let mut desc = vec![3, 1, 4, 1, 5];
desc.sort_unstable_by(|x, y| y.cmp(x));
println!("descending: {:?}", desc);
let mut v = vec![("tom", 80), ("ana", 95), ("bob", 80)];
v.sort_unstable_by(|p, q| q.1.cmp(&p.1).then_with(|| p.0.cmp(q.0)));
println!("by score: {:?}", v);
}

排序浮点数时要格外小心：IEEE 754 的 NaN 与任何值比较都返回 false，不满足 Ord 要求的全序关系，所以 f64 没有实现 Ord，直接 sort() 编译不过。竞赛数据通常不含 NaN，这时可以用 partial_cmp(...).unwrap()；若数据可能含 NaN，要先把 NaN 过滤掉或映射到无穷大再排。

切片本身还带一个 binary_search 方法，返回 Result<usize, usize>：找到时是 Ok(下标)，没找到时是 Err(应插入位置)，这个"应插入位置"正好等于 lower_bound。若数组里存在重复元素，binary_search 返回的是其中某一个，不保证是第一个或最后一个，所以题目要找边界时还是自己写 lower_bound / upper_bound 更可靠。类似的还有 partition_point，它接受一个谓词，返回第一个使谓词为 false 的位置——把二分模式的意图直接写进名字里，可读性更好。

大白话先用直觉把它讲通

排序就是把一堆东西按规则排队。sort 是"讲礼貌的排队"，分数相同的人保持原来的先后；sort_unstable 是"只关心分数"的排队，同分谁在前都行，所以更快。比较器就是告诉程序"谁该站前面"的那句话，降序只要把两个参数换个位置说一遍。

17.2 归并排序与逆序对

归并排序把数组对半分，分别排好两个半区，再做一次线性合并。它的时间复杂度稳定为 O(n log n)，不像快速排序那样有退化风险，代价是需要一个等长的临时数组。逆序对定义为下标 i < j 但 a[i] > a[j] 的二元组的个数，它衡量数组的"无序程度"。

巧妙之处在于：在合并两个已经有序的半区时，如果右半区的 rbuf[j] 小于左半区的 lbuf[i]，那么 rbuf[j] 不仅小于 lbuf[i]，还小于左半区中从 i 到末尾的所有元素（因为左半区递增），于是逆序对数一次性增加 left_len - i。这样统计逆序对不需要额外的嵌套循环，归并排序的 O(n log n) 复杂度原封不动地继承下来。

Rust 写归并排序的难点不在算法而在借用。递归调用 &mut a[..mid] 和 &mut a[mid..] 是两段互不重叠的可变切片，合法；合并前要先把两半拷进临时数组，用 a.split_at(mid) 拿不可变切片、tmp.split_at_mut(mid) 拿可变切片，拷贝完成后用一个花括号块主动结束这些借用，之后才能写回 a[k]。如果借用没结束就写 a[k] = ...，编译器会报"cannot borrow a as mutable"。另外，把 left.len() 事先存成 left_len 这样的标量，也能减少对借用的依赖。

rustRust · 标准库49 行
fn merge_sort_count(a: &mut [i64], tmp: &mut [i64]) -> i64 {
let n = a.len();
if n <= 1 {
return 0;
}
let mid = n / 2;
let mut inv = merge_sort_count(&mut a[..mid], &mut tmp[..mid]);
inv += merge_sort_count(&mut a[mid..], &mut tmp[mid..]);
let left_len = mid;
let right_len = n - mid;
{
let (left, right) = a.split_at(mid);
let (lbuf, rbuf) = tmp.split_at_mut(mid);
lbuf[..left_len].copy_from_slice(left);
rbuf[..right_len].copy_from_slice(right);
}
let (mut i, mut j, mut k) = (0usize, 0usize, 0usize);
while i < left_len && j < right_len {
if tmp[i] <= tmp[mid + j] {
a[k] = tmp[i];
i += 1;
} else {
inv += (left_len - i) as i64;
a[k] = tmp[mid + j];
j += 1;
}
k += 1;
}
while i < left_len {
a[k] = tmp[i];
i += 1;
k += 1;
}
while j < right_len {
a[k] = tmp[mid + j];
j += 1;
k += 1;
}
inv
}
fn main() {
let mut a = vec![2i64, 4, 1, 3, 5];
let mut tmp = vec![0i64; a.len()];
let inv = merge_sort_count(&mut a, &mut tmp);
println!("sorted = {:?}, inversions = {}", a, inv);
}

合并条件写成 <= 而不是 <，保证相等元素先取左边的，因此这个排序是稳定的，也避免把相等元素误计为逆序对。临时数组只分配一次，由递归各层复用；若在每层递归里都新建 Vec，总分配量会上升，性能明显变差。

递归深度是 log₂n，远小于递归爆栈的阈值，所以归并排序用递归是安全的，这与后面图中的深链 DFS 不同。若数据的值域不大（例如都在 10⁶ 以内），统计逆序对还有另一种做法：从右往左扫描，用树状数组（Fenwick tree）统计已出现过且小于当前值的元素个数，复杂度同样是 O(n log n)，内存只需一个计数数组。两种方法的结果应当一致，互为对拍的参照很合适。归并排序的额外好处是天然稳定，如果题目同时要求"按值排序且同值保持原序"，它就是首选。

17.3 二分的四种边界写法

二分查找的 bug 几乎都出在区间约定上。推荐全程使用左闭右开 [l, r)：初始 l = 0, r = len，循环条件是 while l < r，中点 m = l + (r - l) / 2。这写法的好处是循环结束时 l == r，答案就是 l，不需要讨论"最后 l 和 r 谁大"。中点用 l + (r - l) / 2 而不是 (l + r) / 2，可以避免两个大下标相加溢出。

四种常见需求只差一个判定条件：找第一个大于等于 target 的位置（lower_bound）用 a[m] < target 时右移；找第一个大于 target 的位置（upper_bound）用 a[m] <= target 时右移。"第一个等于"是先做 lower_bound 再校验，"最后一个等于"是先做 upper_bound 再减一——而减一之前必须判断 i > 0，否则 i = 0 时会触发 usize 下溢。

rustRust · 标准库51 行
fn lower_bound(a: &[i32], target: i32) -> usize {
let (mut l, mut r) = (0usize, a.len());
while l < r {
let m = l + (r - l) / 2;
if a[m] < target {
l = m + 1;
} else {
r = m;
}
}
l
}
fn upper_bound(a: &[i32], target: i32) -> usize {
let (mut l, mut r) = (0usize, a.len());
while l < r {
let m = l + (r - l) / 2;
if a[m] <= target {
l = m + 1;
} else {
r = m;
}
}
l
}
fn first_equal(a: &[i32], target: i32) -> Option<usize> {
let i = lower_bound(a, target);
if i < a.len() && a[i] == target {
Some(i)
} else {
None
}
}
fn last_equal(a: &[i32], target: i32) -> Option<usize> {
let i = upper_bound(a, target);
if i > 0 && a[i - 1] == target {
Some(i - 1)
} else {
None
}
}
fn main() {
let a = [1, 2, 2, 2, 3, 4];
println!("lower=({}, {})", lower_bound(&a, 2), lower_bound(&a, 5));
println!("upper=({}, {})", upper_bound(&a, 2), upper_bound(&a, 5));
println!("first={:?} last={:?}", first_equal(&a, 2), last_equal(&a, 2));
println!("count={}", upper_bound(&a, 2) - lower_bound(&a, 2));
}

上界减下界就是某个值出现次数，这是 lower_bound / upper_bound 最实用的组合。注意所有返回类型都是 usize，"找不到"用 a.len() 表示，而不是 -1；想表达"不存在"的语义就用 Option<usize>，让类型系统替你记账。

还有一个常被忽略的要点：二分的前提是数组有序。如果题目给的是无序数据，别忘了先排序，并记得排序会打乱原始下标——若答案需要输出原位置，就要先和值一起打包成结构体或二元组再排。二分本身只要求"谓词单调"，不要求数组严格递增：对于形如"前半段满足某条件、后半段不满足"的判定序列，同样可以用同样的框架找分界点。把二分理解为"在一个单调布尔序列里找 true/false 的交界"，比死记四种模板更通用。

17.4 二分答案：从判定到最优

当题目要求"最大化最小值"或"最小化最大值"时，答案往往具有单调性：如果某个上限 limit 可行，那么比它更大的上限一定也可行；如果不可行，更小的也不可行。有了单调性，就能对答案本身二分，把在巨大值域上的搜索压缩到 O(log V) 次判定。

"把数组切成 m 段、最小化最大段和"是标准范例。判定函数 feasible(limit) 贪心地从左往右累加，一旦加上当前元素超过 limit 就另起一段；若段数超过 m 则不可行。二分时 lo 取数组最大值（任何一段至少装得下最大的单个元素），hi 取全数组之和（一段装下全部），循环写法同样用 lo + (hi - lo) / 2，可行就把 hi 压到 mid，否则把 lo 抬到 mid + 1。

rustRust · 标准库38 行
fn feasible(a: &[i64], pieces: usize, limit: i64) -> bool {
let mut used = 1usize;
let mut sum = 0i64;
for &x in a {
if x > limit {
return false;
}
if sum + x > limit {
used += 1;
sum = x;
if used > pieces {
return false;
}
} else {
sum += x;
}
}
true
}
fn minimize_largest_sum(a: &[i64], pieces: usize) -> i64 {
let mut lo = *a.iter().max().unwrap();
let mut hi: i64 = a.iter().sum();
while lo < hi {
let mid = lo + (hi - lo) / 2;
if feasible(a, pieces, mid) {
hi = mid;
} else {
lo = mid + 1;
}
}
lo
}
fn main() {
let a = [7i64, 2, 5, 10, 8];
println!("answer = {}", minimize_largest_sum(&a, 2));
}

写二分答案前必须先证明单调性，否则二分会悄悄给出错误答案。一个快速验证办法是拿几组小数据穷举所有切分，再把结果与判定函数对照；建立直觉后再推广到大数据。还要注意 lo 和 hi 的初值必须分别落在"一定不可行/一定可行"或包含答案的区间内：若 lo 设得太大，真正的答案会被排除在外；若 hi 设得太小，二分永远收敛不到可行解。

二分答案的题目形形色色，但套路高度一致："求最大的最小距离"可以判定为能否放下至少 k 个物品，"求最小的最大耗时"可以判定为能否在限定时间内完成所有任务，"求最少天数"可以判定为限定天数能否运完。判定函数几乎都是贪心：从左到右尽可能塞，塞不下就新开一组。写完判定函数后，先用极端数据自检——limit 取最大值时应恰好可行，limit 取最小值时通常不可行——再交给二分，能省掉大量调试时间。
