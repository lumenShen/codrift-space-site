18.1 前缀和：一维与二维

前缀和数组的不变量是：pref[i] 等于原数组前 i 个元素之和，也就是 [0, i) 的和。为了省掉对 i == 0 的特判，预分配 n + 1 个位置并让 pref[0] = 0 作哨兵。建表用一次循环完成，之后任意区间 [l, r) 的和都是 pref[r] - pref[l]，把 O(n) 的区间查询降到 O(1)。注意区间统一用左闭右开：长度直接是 r - l，两个相邻区间的边界不会重叠。

rustRust · 标准库13 行
fn main() {
let a = [1i64, 3, 5, 7, 9, 11];
let mut pref = Vec::with_capacity(a.len() + 1);
pref.push(0i64);
for &x in &a {
let last = *pref.last().unwrap();
pref.push(last + x);
}
let pairs = [(0usize, 3usize), (1, 4), (2, 2), (0, 6)];
for (l, r) in pairs {
println!("[{}, {}) = {}", l, r, pref[r] - pref[l]);
}
}

这里没有写 pref.push(pref[pref.len() - 1] + x)，而是先用 last() 取出旧值再 push。虽然 Rust 的两阶段借用通常允许前者，但先取值的写法意图更明确，也避免了在循环中反复索引 len() - 1。如果原数组元素可能很大，前缀和要用 i64 累加，否则 i32 在一百万个 10⁹ 元素上必然溢出。

另一种常见变体是原地前缀和：直接把 a[i] 改成前 i 项之和，不再分配新数组，省内存但会破坏原数据。刷题时若后面还要用原数组，就别这么做。涉及取模的题目（例如统计子数组和能被 k 整除的个数）要在每次累加后立即取模，并用 HashMap<i64, usize> 统计每个余数出现次数，核心思想仍是"两个前缀同余则其差能被 k 整除"。把前缀和看成"压缩的信息"，很多看似无关的题型都能归入这个框架。

二维前缀和把同样的思想扩展到矩阵。ps[r][c] 表示左上角 (0,0) 到右下角 (r-1,c-1) 的矩形和。递推式是 ps[r][c] = a[r-1][c-1] + ps[r-1][c] + ps[r][c-1] - ps[r-1][c-1]，也就是"自己加上方加左方，再把重复算的左上角减一次"。查询 [r1, r2) × [c1, c2) 用同样的容斥：ps[r2][c2] - ps[r1][c2] - ps[r2][c1] + ps[r1][c1]。

关键技巧是把所有下标整体加一：原矩阵 m × n 存进 (m+1) × (n+1) 的前缀数组，让第 0 行和第 0 列全为 0。这样递推里的 r - 1、c - 1 都变成合法的 r、c，彻底绕开 usize 下溢。如果在 0 基数组里硬写 ps[i-1][j]，那么 i = 0 时程序会当场 panic。

rustRust · 标准库29 行
fn build_prefix_2d(grid: &[Vec<i64>]) -> Vec<Vec<i64>> {
let rows = grid.len();
let cols = if rows == 0 { 0 } else { grid[0].len() };
let mut ps = vec![vec![0i64; cols + 1]; rows + 1];
for r in 0..rows {
for c in 0..cols {
ps[r + 1][c + 1] = grid[r][c]
+ ps[r][c + 1]
+ ps[r + 1][c]
- ps[r][c];
}
}
ps
}
fn sum_2d(ps: &[Vec<i64>], r1: usize, c1: usize, r2: usize, c2: usize) -> i64 {
ps[r2][c2] - ps[r1][c2] - ps[r2][c1] + ps[r1][c1]
}
fn main() {
let g = vec![
vec![1i64, 2, 3],
vec![4, 5, 6],
vec![7, 8, 9],
];
let ps = build_prefix_2d(&g);
println!("whole = {}", sum_2d(&ps, 0, 0, 3, 3));
println!("center = {}", sum_2d(&ps, 1, 1, 2, 2));
}
大白话先用直觉把它讲通

前缀和就像给一排数字提前记好"从开头到每个位置一共多少"。有了这张表，问任意一段的和只要用大计数减小计数，一下就算出来。二维版本则是给整个棋盘记每个左上角矩形的累计值，减去几次就能框出任意长方形。

18.2 差分：区间加与单点查询

差分是前缀和的逆运算。diff[i] 定义为 a[i] - a[i-1]（令 a[-1] = 0），对 diff 做前缀和就还原出 a。这个性质带来一个极强的操作：要把区间 [l, r] 整体加 delta，只需 diff[l] += delta、diff[r+1] -= delta 两处修改，因为前缀和扫到 l 时开始生效，扫过 r 后被抵消。多次区间加可以全部 O(1) 处理，最后统一 O(n) 还原。

需求 工具 单次修改 单次查询
区间和 前缀和 建表 O(n) O(1)
区间加、单点值 差分 O(1) 还原后 O(1)
区间加、区间和 差分 + 两层前缀 O(1) 还原后 O(1)
单点加、区间和 树状数组 O(log n) O(log n)

下面的实现预分配 n + 1 个位置，让 r + 1 == n 时仍能安全写入差分边界；只有 r + 1 >= diff.len() 才跳过，而这个判断在合法输入下通常不会发生。还原时维护滚动变量 cur，避免真的去改差分数组本身——这让差分数组保持"只记录修改"的纯粹语义，便于多次复用。

rustRust · 标准库22 行
fn range_add_diff(n: usize, ops: &[(usize, usize, i64)]) -> Vec<i64> {
// 每个三元组 (l, r, delta) 表示对闭区间 [l, r] 加 delta
let mut diff = vec![0i64; n + 1];
for &(l, r, delta) in ops {
diff[l] += delta;
if r + 1 < diff.len() {
diff[r + 1] -= delta;
}
}
let mut cur = 0i64;
let mut out = Vec::with_capacity(n);
for i in 0..n {
cur += diff[i];
out.push(cur);
}
out
}
fn main() {
let ops = [(0usize, 2usize, 3i64), (1, 3, -1), (2, 4, 5)];
println!("{:?}", range_add_diff(5, &ops));
}

差分与前缀和经常组合使用：先对原数组建一次差分，执行若干次区间加，再对差分求前缀得到新数组，最后对新数组求前缀得到区间和查询表，整体仍是 O(n + m)。二维差分同理，区间加 [x1,x2] × [y1,y2] 变成四个角点的符号修改，公式与二维前缀和互为镜像。

要注意差分的"离线"属性：上面的代码必须先把所有修改收集完，才能统一还原出最终数组。如果题目要求"每做一次区间加就立刻回答一次查询"，纯差分就力不从心了，需要改用树状数组或线段树，把每次修改与查询都降到 O(log n)。区分在线与离线是选择数据结构的第一步：能在读入阶段一次性拿到全部操作时，离线算法往往更简单也更快。另外差分值为负数完全合法，用 i64 存储即可，不必特殊处理。

18.3 双指针与滑动窗口

双指针有两大流派。相向双指针：左指针从开头、右指针从结尾出发，根据当前和与目标的大小关系移动其中一个，典型是排序数组的两数之和。它要求数组有序，每次移动都单调地缩小搜索范围，因此 O(n)。同向双指针（滑动窗口）：左右指针都只向右走，右指针负责扩大窗口，左指针负责在窗口"不合法"时收缩，典型是求最短子数组或无重复最长子串。

滑动窗口的正确性依赖两个不变量：其一，窗口 [left, right] 始终满足题目对右端的扩展要求；其二，每轮收缩后窗口恰好是"以 right 结尾的最优窗口"。左指针绝不回退是关键——如果某个左端位置被排除，那么以更靠右的 right 结尾时它也不可能重新变优。这个单调性一旦不成立（例如窗口合法性与 right 不单调），双指针就会失效，必须换用别的方法。

rustRust · 标准库34 行
fn min_subarray_sum(a: &[i64], target: i64) -> usize {
let (mut left, mut sum, mut best) = (0usize, 0i64, usize::MAX);
for (right, &x) in a.iter().enumerate() {
sum += x;
while sum >= target && left <= right {
best = best.min(right - left + 1);
sum -= a[left];
left += 1;
}
}
if best == usize::MAX { 0 } else { best }
}
fn longest_unique(s: &str) -> usize {
let bytes = s.as_bytes();
let mut last = [usize::MAX; 256];
let mut left = 0usize;
let mut best = 0usize;
for (right, &b) in bytes.iter().enumerate() {
let idx = b as usize;
if last[idx] != usize::MAX && last[idx] >= left {
left = last[idx] + 1;
}
last[idx] = right;
best = best.max(right - left + 1);
}
best
}
fn main() {
let a = [2i64, 3, 1, 2, 4, 3];
println!("min len = {}", min_subarray_sum(&a, 7));
println!("longest unique = {}", longest_unique("abcabcbb"));
}

longest_unique 用定长数组 [usize::MAX; 256] 记录每个字节最后出现的位置，用 usize::MAX 表示"从未出现"，省掉 Option 的判断开销。它只适用于 ASCII 字节串；处理中文要用 char 与 HashMap<char, usize>，因为 UTF-8 下一个汉字占多个字节。判断重复时用 last[idx] >= left 而不是 != usize::MAX，是为了只在"上次出现位置仍在当前窗口内"时才移动左端。

相向双指针的经典例子是三数之和：先排序，再固定一个数，用 l = i + 1、r = n - 1 从两侧夹逼。三数之和大于目标就让 r 左移，小于目标就让 l 右移；遇到重复元素要跳过，否则结果里有大量重复三元组。排序 + 双指针把原本 O(n³) 的暴力枚举压到 O(n²)，这也再次说明"有序"是双指针能工作的重要前提。写这类代码时，l < r 的循环条件要保证 i + 1 不超过 n - 1，把固定元素的循环上界设为 n - 2 最省心。

18.4 边界、不变量与调试清单

这一类题目出错往往不是算法想错，而是边界处理不细。逐项核对能省很多时间：区间是闭区间还是左闭右开；前缀数组是否多开了一格作哨兵；二维递推是否已经整体右移一位以避开 i - 1；差分修改的右端点是 r 还是 r + 1；收缩窗口时 left 是否会越过 right 导致 r - l + 1 下溢；累加和是否需要 i64。"宁可多判断一次，也不要让 usize 偷偷回绕"是这里的黄金准则。

另一个好习惯是写出并维护不变量注释。例如在滑动窗口里注明"窗口内和小于 target，且 left 是满足条件的最小位置"，在差分里注明"diff 的前缀等于当前增量"。每次循环体内只做保持不变量的事，代码就很难错。调试时先用小规模输入手工模拟两三轮，再和程序输出比对；若有对拍环境，用暴力枚举所有子数组的答案与双指针结果比较，往往几十行代码就能覆盖全部边界。

前缀和与差分这对工具一个负责查询、一个负责修改，理解它们的互逆关系后，面对区间类问题就能先在纸上画出前缀或差分的草图，再决定用哪种结构，而不是上来就套模板。特别提醒一个 Rust 专属陷阱：usize::MAX 是合法的哨兵值，但它加一就会回绕成 0。上面 longest_unique 里先判断 last[idx] != usize::MAX 再执行 left = last[idx] + 1，顺序绝不能颠倒。同理，right - left + 1 只有在 right >= left 时才有意义，循环条件里加一道 left <= right 的防线几乎不花成本。把这些防御动作写成肌肉记忆，才能在 debug 构建下避免突如其来的 panic。
