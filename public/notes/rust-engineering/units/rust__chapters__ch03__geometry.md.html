33.1 整数几何的底座：为什么尽量不用浮点

计算几何最容易被低估的地方，是"看起来简单的浮点比较其实不可靠"。两条理论上相交的线段，用 f64 算出的交点可能因舍入差 1e-16，导致 == 判断失败；凸包上三点共线，浮点叉积可能是 1e-15 而非 0，于是本该丢弃的中间点被保留。本单元全部用整数坐标，所有方向判断都化为叉积符号，彻底避开这些问题。代价是只能处理整数输入、面积可能是半整数——但这在竞赛与多数工程场景（像素、网格、栅格地图）里完全够用。

几何算法在现实中的身影比想象中多：地图服务的矩形范围查询、游戏里的碰撞检测、CAD 的轮廓提取、图像处理中的连通区域统计，底层都是同一组谓词。它们对"边界情况"极其敏感——一个共线点判断错，可能让整条边界多出一个锯齿。选择整数而非浮点，本质上是把"数值稳定性"这个难以测试的属性，换成"整数运算精确"这个可证明的属性。当输入本来就是像素坐标或格点坐标时，这个交换几乎免费；当输入来自传感器浮点数据时，则需要先做量化并明确误差范围，而不是假装浮点比较可靠。

问题定义如下。给定点 p、q、r，叉积 cross(p,q,r) = (q-p)×(r-p) 的符号表示从 pq 转到 pr 的方向：正为逆时针、零为共线、负为顺时针。凸包问题：给定 n 个整数点，求包含全部点的最小凸多边形的顶点，按逆时针输出。扫描线问题：给定若干轴对齐矩形，求它们并集的面积。三者层层递进：叉积是基本谓词，凸包是它的栈式应用，扫描线则把它换成"事件驱动的区间覆盖"。

大白话先用直觉把它讲通

叉积就像你站在 p 点看 q 和 r——如果 r 在你的左手边，叉积为正；右手边为负；正前方或正后方就是零。凸包像用一根橡皮筋套住所有钉子：从最左边开始沿下边界走，遇到"右转"就把刚才那个点弹掉，再从上边界走回来。扫描线像拿一把竖直的尺子从左往右扫，每遇到矩形的左边界就记一笔"这里开始盖住"，遇到右边界就记一笔"这里结束"，两次事件之间盖住的长度是固定的，乘上扫过的宽度就是面积。

33.2 叉积：方向、面积与线段相交

叉积的代数定义是 (b.x-a.x)*(c.y-a.y) - (b.y-a.y)*(c.x-a.x)。几何意义是以 a、b、c 为顶点的有向三角形的两倍面积：值为正说明 a→b→c 是逆时针，为负是顺时针，为零则三点共线。代码里把坐标差先转 i128 再相乘，是因为坐标到 1e9 时差可达 2e9，乘积达 4e18，已逼近 i64 上限 9.22e18；若坐标再大一点就会溢出。换成 i128 后上界约 1.7e38，完全安全，代价只是几条额外指令。

为什么叉积符号等于方向？把向量 b-a 与 c-a 看作复数，叉积是它们构成的 2×2 行列式，其符号正是从前者旋转到后者时经过的最短角度方向：逆时针为正、顺时针为负；共线时两向量平行，行列式为 0。这个解释也说明叉积与点积互补：点积判"夹角是否小于 90 度"，叉积判"往哪边转"，二者组合可完成绝大多数几何谓词。cross_vec((3,2),(1,5)) = 13 就是 3×5-2×1=13，为正说明从 (3,2) 转到 (1,5) 是逆时针。

多边形面积用鞋带公式：按顶点顺序累加 x_i*y_{i+1} - y_i*x_{i+1}，取绝对值再除以 2。这个公式可理解为把多边形拆成从原点出发的若干三角形，有向面积相加后内部相互抵消，只剩多边形轮廓。注意"两倍面积"始终是整数，但面积可能是 .5（例如顶点 (0,0)、(1,0)、(0,1) 的两倍面积是 1），所以代码里 area2 用 i128、显示时才转 f64，二者不要混用。线段相交测试用四个方向谓词：若 c、d 分别在 ab 两侧且 a、b 分别在 cd 两侧，则严格相交（对应代码里 c1、c2 异号且 c3、c4 异号）；再补充四种"某端点恰好落在另一线段上"的共线边界情况，用 on_seg 判断共线且落在包围盒内。缺了这四种边界，端点接触的相交会被漏判——演示中 (2,0)-(2,3) 与 (0,0)-(4,0) 的接触就属于此类。

#![allow(dead_code)]
#[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord)]
struct Pt { x: i64, y: i64 }
/// 叉积 (b-a) x (c-a)：>0 为逆时针，=0 共线，<0 为顺时针。
/// 用 i128 承接乘积，坐标到 1e9 时也不会溢出。
fn cross(a: Pt, b: Pt, c: Pt) -> i128 {
(b.x as i128 - a.x as i128) * (c.y as i128 - a.y as i128)
- (b.y as i128 - a.y as i128) * (c.x as i128 - a.x as i128)
}
fn cross_vec(a: Pt, b: Pt) -> i128 {
a.x as i128 * b.y as i128 - a.y as i128 * b.x as i128
}
fn area2(poly: &[Pt]) -> i128 {
let mut s = 0i128;
for i in 0..poly.len() {
let j = (i + 1) % poly.len();
s += poly[i].x as i128 * poly[j].y as i128 - poly[i].y as i128 * poly[j].x as i128;
}
s.abs()
}
fn on_seg(a: Pt, b: Pt, p: Pt) -> bool {
cross(a, b, p) == 0
&& p.x >= a.x.min(b.x) && p.x <= a.x.max(b.x)
&& p.y >= a.y.min(b.y) && p.y <= a.y.max(b.y)
}
fn seg_intersect(a: Pt, b: Pt, c: Pt, d: Pt) -> bool {
let c1 = cross(a, b, c); let c2 = cross(a, b, d);
let c3 = cross(c, d, a); let c4 = cross(c, d, b);
if ((c1 > 0 && c2 < 0) || (c1 < 0 && c2 > 0))
&& ((c3 > 0 && c4 < 0) || (c3 < 0 && c4 > 0)) { return true; }
if c1 == 0 && on_seg(a, b, c) { return true; }
if c2 == 0 && on_seg(a, b, d) { return true; }
if c3 == 0 && on_seg(c, d, a) { return true; }
if c4 == 0 && on_seg(c, d, b) { return true; }
false
}
fn main() {
let o = Pt { x: 0, y: 0 };
let b = Pt { x: 4, y: 0 };
let up = Pt { x: 1, y: 3 };
let down = Pt { x: 1, y: -2 };
println!("cross((0,0),(4,0),(1,3)) = {}", cross(o, b, up));
println!("cross((0,0),(4,0),(1,-2)) = {}", cross(o, b, down));
println!("cross((0,0),(4,0),(2,0)) = {}", cross(o, b, Pt { x: 2, y: 0 }));
println!("cross_vec((3,2),(1,5)) = {}", cross_vec(Pt{x:3,y:2}, Pt{x:1,y:5}));
let tri = [o, b, up];
println!("triangle area2 = {} area = {}", area2(&tri), area2(&tri) as f64 / 2.0);
println!("intersect (0,0)-(4,4) with (0,4)-(4,0) = {}",
seg_intersect(Pt{x:0,y:0}, Pt{x:4,y:4}, Pt{x:0,y:4}, Pt{x:4,y:0}));
println!("intersect (0,0)-(4,0) with (5,0)-(6,0) = {}",
seg_intersect(Pt{x:0,y:0}, Pt{x:4,y:0}, Pt{x:5,y:0}, Pt{x:6,y:0}));
println!("intersect (0,0)-(4,0) with (2,0)-(2,3) = {}",
seg_intersect(Pt{x:0,y:0}, Pt{x:4,y:0}, Pt{x:2,y:0}, Pt{x:2,y:3}));
}

33.3 凸包：Andrew 单调链的不变量

Andrew 算法先把点按 (x,y) 字典序排序并去重，然后分两趟构造：下凸壳从左到右，上凸壳从右到左。每趟维护一个栈，加入新点 p 时反复检查"栈顶两点与新点是否构成左转"——若 cross(次栈顶, 栈顶, p) <= 0，说明栈顶点使路径右转或共线，弹掉它，再继续检查；否则压入 p。最后把两趟的结果各去掉最后一个重复端点再拼接。

不变量是：每一趟结束时，栈里的点从左到右构成一条严格凸的链，且任何连续三点都满足叉积 > 0（严格左转）。加入新点可能破坏末尾的局部凸性，但只会影响靠近末尾的点，所以 while 循环弹出有限次后恢复不变量。这个"只影响末尾"的性质是算法线性的关键：每个点入栈一次、出栈至多一次，两趟总共 O(n) 次栈操作；即便某个新点一次弹出多个旧点，摊还到每个被弹点也只是一次。用 <= 0 而非 < 0 决定弹出，意味着共线点不会留在链上——得到的是"严格凸包"，只保留共线边的两个端点。若改成 < 0，中间共线点会被保留，凸包顶点数变多，但形状与面积不变；两种约定在竞赛里都合法，关键是全程一致，并且对拍裁判也用同一约定。

为什么先按 (x,y) 字典序排序？因为排序后下凸壳的点天然按 x 递增，上凸壳按 x 递减，两趟各走一遍就能覆盖整个轮廓；若不排序，就退化为 Graham scan——先找最低点、再按极角排序，代码更复杂且极角比较需要叉积与距离双重判据。Andrew 的巧妙之处在于用字典序替代极角序，让比较变成 Pt 派生的 Ord，一行 sort_unstable() 搞定。对重复点先 dedup 也顺理成章：排序后相同点相邻，去重只需线性扫描。若直接对原始 Vec<Pt> 建包而不排序，凸包结果会依赖输入顺序，对拍时同一组点的不同排列给出不同顶点序列，产生假 mismatch。

复杂度：排序 O(n log n) 是主导项，两趟扫描每点最多入栈一次、出栈一次，共 O(n)；空间 O(n)。若输入已按 x 有序，可跳过排序，总复杂度降为 O(n)。Vec::with_capacity(len+1) 预分配避免中途扩容，既减少分配次数，也让引用失效风险更低。

33.4 凸包实现、共线处理与复杂度

#![allow(dead_code)]
#[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord)]
struct Pt { x: i64, y: i64 }
fn cross(a: Pt, b: Pt, c: Pt) -> i128 {
(b.x as i128 - a.x as i128) * (c.y as i128 - a.y as i128)
- (b.y as i128 - a.y as i128) * (c.x as i128 - a.x as i128)
}
/// Andrew 单调链凸包，返回逆时针严格凸包（共线点只保留端点）。
fn convex_hull(mut pts: Vec<Pt>) -> Vec<Pt> {
pts.sort_unstable();
pts.dedup();
if pts.len() <= 1 { return pts; }
let mut lower: Vec<Pt> = Vec::with_capacity(pts.len() + 1);
for &p in &pts {
while lower.len() >= 2
&& cross(lower[lower.len() - 2], lower[lower.len() - 1], p) <= 0 {
lower.pop();
}
lower.push(p);
}
let mut upper: Vec<Pt> = Vec::with_capacity(pts.len() + 1);
for &p in pts.iter().rev() {
while upper.len() >= 2
&& cross(upper[upper.len() - 2], upper[upper.len() - 1], p) <= 0 {
upper.pop();
}
upper.push(p);
}
lower.pop();
upper.pop();
lower.extend(upper);
lower
}
fn area2(poly: &[Pt]) -> i128 {
let mut s = 0i128;
for i in 0..poly.len() {
let j = (i + 1) % poly.len();
s += poly[i].x as i128 * poly[j].y as i128 - poly[i].y as i128 * poly[j].x as i128;
}
s
}
fn main() {
let pts = vec![
Pt{x:0,y:0}, Pt{x:4,y:0}, Pt{x:4,y:4}, Pt{x:0,y:4},
Pt{x:2,y:2}, Pt{x:1,y:1}, Pt{x:3,y:1}, Pt{x:1,y:3},
Pt{x:2,y:0}, Pt{x:0,y:2}, Pt{x:4,y:2}, Pt{x:2,y:4},
];
let hull = convex_hull(pts.clone());
println!("input points = {}", pts.len());
println!("hull vertices = {:?}", hull);
println!("hull size = {}", hull.len());
println!("signed area2 = {} area = {}", area2(&hull), area2(&hull) as f64 / 2.0);
// collinear 边上多点：应只留端点
let line = vec![Pt{x:0,y:0}, Pt{x:1,y:0}, Pt{x:2,y:0}, Pt{x:3,y:0}];
println!("collinear hull = {:?}", convex_hull(line));
}

实现上还有一个容易忽略的 Rust 细节：for &p in &pts 与 for &p in pts.iter().rev() 都以不可变借用遍历 pts，而修改的是另一个 Vec（lower / upper），所以不存在借用冲突；若试图原地复用 pts 当栈，就会同时需要可变借用与不可变遍历，编译直接失败。用两个独立 Vec 不仅规避了借用问题，也让"下凸壳"与"上凸壳"两段逻辑对称，便于单独测试各自的左转不变量。这个函数接收 Vec<Pt> 按值而不是切片，是为了能原地排序而不影响调用方的原始数据；若你希望保留输入，就在调用处 clone，把所有权语义显式化。

坑这里最容易踩

这里是坑：凸包结果至少要有 3 个点才构成多边形。若所有点共线，严格凸包只有 2 个点，area2 的循环对两个点仍然成立（累加两次互为相反数的叉积，结果 0），但任何假设"hull.len() >= 3"的后续代码都会越界。另一个坑是重复点：不先 dedup 的话，排序后相邻重复点会让 cross(...,p) == 0 反复弹出，虽然多数情况下结果仍对，但栈内容与复杂度分析都被污染；显式去重更安全。第三个坑是把 <= 0 写成 < 0 却以为"只是风格不同"——它会让共线中间点留在凸包里，顶点计数类题目（如"凸包上有几个点"）答案会完全不同。

33.5 扫描线：矩形面积并的事件模型

扫描线把二维问题降成一维：把所有矩形的竖边拆成事件，按 x 从小到大扫。事件记为 (x, y1, y2, delta)：矩形左边界产生 +1（开始覆盖 y 区间），右边界产生 -1（结束覆盖）。两次相邻事件之间，覆盖的 y 区间集合不变，因此这段 x 宽度乘以"当前被覆盖的 y 总长"就是这块面积，累加即可。

不变量是：cover[i] 表示第 i 个 y 基本段 [ys[i], ys[i+1]) 当前被多少个矩形覆盖；在每个事件处理之前，cover 准确反映"左边界在 prev_x、右边界在 x 之间"的覆盖状态，所以可以先累加面积再应用事件。坐标压缩把任意实数 y 映射到有序下标，因为覆盖状态只可能在矩形的水平边界处改变，相邻边界之间的整段要么全被覆盖要么全不被覆盖——这是扫描线合法的核心理由。若改用半开区间 [y1,y2)，相邻边界共享的点不会被重复计数；用闭区间则会让边界点被两个相邻段同时覆盖，虽然面积不变，但覆盖计数语义混乱。本单元代码用 [ys[i], ys[i+1]) 的半开约定，与 cover 的"段"语义一致。

事件排序用 sort_unstable_by_key，同 x 的事件顺序不影响结果，因为面积为 0 的零宽条带贡献为 0；但必须先累加面积再逐个应用该 x 的所有事件，否则会多算或漏算一条零宽条带（虽然宽度为 0，结果仍不受影响，但语义更清晰）。prev_x 初始化为第一个事件的 x，而不是 0——若初始化为 0，在矩形 x 坐标很大时会凭空多出一块 covered * (first_x - 0) 的面积，这是扫描线实现里最经典的错误之一。代码里 cover 用 i32 足够：覆盖层数最多等于矩形数，1e5 也远小于 2^31。若矩形数超过 2e9（不现实），才需要更大的类型。

复杂度：事件数 2R，排序 O(R log R)；每事件扫描 k 段求覆盖长度，k ≤ 2R，故最坏 O(R²)。本单元用线性扫描换取代码简洁；若 R 达到 1e5，应把"覆盖长度"也用线段树维护，将每事件降到 O(log R)，总复杂度 O(R log R)。空间 O(R)。

33.6 扫描线实现与坐标压缩

实现分四步：收集所有矩形的上下边界 y 并排序去重得到 ys；把每个矩形的 y 区间映射成下标区间 [a,b)，在 x1 处压入 (x1,a,b,+1)、在 x2 处压入 (x2,a,b,-1)；按 x 排序全部事件；从左到右扫，每次先按当前 cover 累加 covered*(x-prev_x)，再把该事件的 delta 加到 cover[a..b] 上。注意 cover[a..b] 用半开区间，正好对应 ys 里的 k = ys.len()-1 个基本段，数组不会越界。

事件表用 Vec::with_capacity(rects.len()*2) 预分配，避免反复扩容；ys.binary_search(&y1).unwrap() 把边界值换成下标，若某矩形的 y 边界未被收集（构造事件时漏写），unwrap 会立刻 panic，而不是静默算错。cover 用 i32 是安全的：覆盖层数不超过矩形总数，即使有一百万个矩形也远小于 i32 上限。求覆盖长度时线性扫过 k 段，代码只有三行，便于核对；当矩形数量很大时，这一步可替换为线段树维护"被覆盖的总长度"，复杂度从 O(R²) 降到 O(R log R)，但主循环结构不变，对拍裁判也无需改动。这体现了好结构的价值：把可优化的部分封装在一个小函数里，替换时不会影响正确性论证。扫描线的另一条不变量也值得单独检查：任意时刻 cover 的所有分量非负，且每个矩形恰好贡献一对 +1/-1 事件；后者保证扫到最后一个事件时全部归零。把"终态归零"写成 debug_assert!，等于给事件配对加了一道免费的自检，开发期就能发现漏配对或符号写反这类隐蔽错误。

/// 扫描线求矩形面积并。矩形记为 (x1,y1,x2,y2)，半开区间 [x1,x2)×[y1,y2)。
fn sweep_area(rects: &[(i64, i64, i64, i64)]) -> i64 {
if rects.is_empty() { return 0; }
let mut ys: Vec<i64> = rects.iter().flat_map(|r| [r.1, r.3]).collect();
ys.sort_unstable();
ys.dedup();
if ys.len() < 2 { return 0; }
let k = ys.len() - 1;
// 事件：(x, y 段下标起点, 终点, delta)
let mut events: Vec<(i64, usize, usize, i32)> = Vec::with_capacity(rects.len() * 2);
for &(x1, y1, x2, y2) in rects {
let a = ys.binary_search(&y1).unwrap();
let b = ys.binary_search(&y2).unwrap();
events.push((x1, a, b, 1));
events.push((x2, a, b, -1));
}
events.sort_unstable_by_key(|e| e.0);
let mut cover = vec![0i32; k];
let mut area = 0i64;
let mut prev_x = events[0].0;
for (x, a, b, d) in events {
let mut covered = 0i64;
for i in 0..k { if cover[i] > 0 { covered += ys[i + 1] - ys[i]; } }
area += covered * (x - prev_x);
for c in &mut cover[a..b] { *c += d; }
prev_x = x;
}
area
}

33.7 几何陷阱与数值边界

大白话先用直觉把它讲通

整数几何的可靠，来自"所有判断只看叉积的正负号"，而不是"算出来的坐标差看起来差不多"。凸包上弹栈的条件必须用 <= 0 保证严格左转；扫描线上必须先算面积再更新覆盖计数；对拍的暴力版必须真的笨到不会错——这三条做到了，几何题就从"调图画线"变成"调代数不变量"。

陷阱 错误现象 正确做法
i64 叉积溢出 坐标约 1e9 时符号随机翻转 先转 i128 再做乘法
浮点共线判断 该为 0 的叉积变成 1e-15 全整数 + 符号判断
凸包共线处理 顶点数偏多或偏少 统一约定，<= 0 弹栈
扫描线事件顺序 同 x 事件处理错导致多算 先累加面积再应用 delta
暴力裁判重复计数 共线边子段与整段都被统计 只统计极大支撑线段
坑这里最容易踩

这里是坑：cover 数组中合法的值是"当前覆盖层数"，可以为 0 但不能为负。若 delta 顺序或符号写反，覆盖数会变负，cover[i] > 0 的判断就会漏算，结果为负面积。防御办法是在每个事件后 debug_assert!(cover.iter().all(|&c| c >= 0))，开发期立刻发现问题。另一个坑是 ys.binary_search(&y1).unwrap()：若 y1 没被收集进 ys（漏写了某个矩形的水平边界），unwrap 会 panic——这其实是好事，它把"事件表构造遗漏"变成显式失败，而不是静默算错面积。

再补一个凸包相关的坑：lower.pop(); upper.pop(); 这两行不能省。两趟各自把起点重复了一次（下趟以最小点为始、上趟以最大点为始，拼接时这两个端点会出现两次），增长两个体积相同的拓扑副本；若不弹出，结果数组首尾会重复同一个顶点，鞋带公式虽不受影响（重复点贡献为 0），但顶点计数、点在多边形内判定等后续算法会因重复点而产生错误分支。若所有点共线，两趟各只剩 2 个点，弹出后各剩 1 个，拼接结果是 2 个点——这就是前面说的"退化凸包"，后续代码必须容忍这种情况。

33.8 随机对拍：三套独立裁判与一次真实 bug

对拍程序用种子 20261124 的 xorshift64，三套裁判互不复用被测逻辑：叉积符号对 f64 斜率比较（把三点按 x 排序后比较两段斜率）、凸包顶点集对礼物包裹法、凸包面积对"枚举支撑线"的暴力、扫描线面积对网格逐格点计数。任何不一致都计数并打印样本。

f64 斜率裁判有个前提：三点必须按 x 严格递增，否则斜率之差的符号与叉积符号的对应关系会翻转。程序因此先 sort_unstable() 再跳过 x 相同的样本——这也是实际只跑了 427 次而非 500 次的原因。网格积分裁判的实现刻意"笨"到极致：遍历 20×20=400 个单位格，对每个格检查其中心是否被任一矩形覆盖，覆盖就加 1。它不压缩坐标、不排序事件、不做任何优化，因此几乎不可能与被测代码共享同一个 bug；其代价是只能处理坐标在 0..20 的小矩形，而这正是对拍规模"暴力可行"的要求。礼物包裹法虽然比 Andrew 慢（O(nh)），但它从最低点出发每次选最右转，是完全不同的构造路径，用来交叉验证顶点集再合适不过；共线时选最远点的规则保证它与严格凸包约定一致。

这里要复盘一次真实发生过的裁判 bug。第一版暴力面积的实现是：枚举所有有序点对 (i,j)，若其余点都在 ij 左侧（含共线），就把原点叉积加进总和。这看起来完全正确，却在 200 组随机样本里报出 10 次 mismatch。样本之一：conv_hull 面积 3598，暴力面积 4920。原因不是凸包错，而是暴力裁判把共线边上的重叠子段也算了进去——一条边上有 p0、p1、p2 三个共线点时，p0→p1、p1→p2、p0→p2 三条"支撑线段"都通过检查，前两条的和恰好等于第三条，于是整段被算了两次。修正办法是加入"极大性"检查：若存在第三点严格落在 i、j 之间且共线，就跳过这对点。修正后输出 area_mismatch=0，样本二从 4920 变成 3598，与凸包面积完全一致。这个教训与第 32 单元逆元对拍的教训一样：裁判自身的假设才是第一嫌疑人。

struct Rng { s: u64 }
impl Rng {
fn new(seed: u64) -> Self { Self { s: if seed == 0 { 1 } else { seed } } }
fn next(&mut self) -> u64 {
let mut x = self.s;
x ^= x << 13; x ^= x >> 7; x ^= x << 17;
self.s = x; x
}
fn below(&mut self, n: i64) -> i64 { (self.next() % n as u64) as i64 }
}
#[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord)]
struct Pt { x: i64, y: i64 }
fn cross(a: Pt, b: Pt, c: Pt) -> i128 {
(b.x as i128 - a.x as i128) * (c.y as i128 - a.y as i128)
- (b.y as i128 - a.y as i128) * (c.x as i128 - a.x as i128)
}
fn dist2(a: Pt, b: Pt) -> i128 {
(a.x as i128 - b.x as i128).pow(2) + (a.y as i128 - b.y as i128).pow(2)
}
fn convex_hull(mut pts: Vec<Pt>) -> Vec<Pt> {
pts.sort_unstable(); pts.dedup();
if pts.len() <= 1 { return pts; }
let mut lo = Vec::new();
for &p in &pts {
while lo.len() >= 2 && cross(lo[lo.len()-2], lo[lo.len()-1], p) <= 0 { lo.pop(); }
lo.push(p);
}
let mut up = Vec::new();
for &p in pts.iter().rev() {
while up.len() >= 2 && cross(up[up.len()-2], up[up.len()-1], p) <= 0 { up.pop(); }
up.push(p);
}
lo.pop(); up.pop(); lo.extend(up); lo
}
/// 独立的礼物包裹法：每步取最右转（共线取最远），应得到同一组严格凸包顶点。
fn jarvis(pts: &[Pt]) -> Vec<Pt> {
let mut start = 0;
for i in 1..pts.len() {
if pts[i].y < pts[start].y || (pts[i].y == pts[start].y && pts[i].x < pts[start].x) { start = i; }
}
let mut hull = Vec::new();
let mut cur = start;
loop {
hull.push(pts[cur]);
let mut nxt = (cur + 1) % pts.len();
if nxt == cur { nxt = (cur + 1) % pts.len(); }
for i in 0..pts.len() {
if i == cur { continue; }
let c = cross(pts[cur], pts[nxt], pts[i]);
if c > 0 || (c == 0 && dist2(pts[cur], pts[i]) > dist2(pts[cur], pts[nxt])) { nxt = i; }
}
if nxt == start { break; }
cur = nxt;
if hull.len() > pts.len() { break; }
}
hull
}
fn signed_area2(poly: &[Pt]) -> i128 {
let mut s = 0i128;
for i in 0..poly.len() {
let j = (i + 1) % poly.len();
s += poly[i].x as i128 * poly[j].y as i128 - poly[i].y as i128 * poly[j].x as i128;
}
s
}
/// 暴力面积：枚举有序点对 (i,j)，若所有其他点都在 ij 左侧（含共线），
/// 则 ij 是一条逆时针支撑线段。只统计"极大"线段（中间没有别的共线点），
/// 否则共线边上的重叠子段会被重复累加。
fn brute_area2(pts: &[Pt]) -> i128 {
let n = pts.len();
let mut s = 0i128;
for i in 0..n {
for j in 0..n {
if i == j { continue; }
let mut ok = true;
for k in 0..n {
if k == i || k == j { continue; }
if cross(pts[i], pts[j], pts[k]) < 0 { ok = false; break; }
}
if !ok { continue; }
// 极大性：不允许有第三点落在 i、j 之间且共线。
let span = dist2(pts[i], pts[j]);
let mut maximal = true;
for k in 0..n {
if k == i || k == j { continue; }
if cross(pts[i], pts[j], pts[k]) == 0
&& dist2(pts[i], pts[k]) < span && dist2(pts[j], pts[k]) < span {
maximal = false; break;
}
}
if maximal { s += pts[i].x as i128 * pts[j].y as i128 - pts[i].y as i128 * pts[j].x as i128; }
}
}
s
}
fn sweep_area(rects: &[(i64, i64, i64, i64)]) -> i64 {
if rects.is_empty() { return 0; }
let mut ys: Vec<i64> = rects.iter().flat_map(|r| [r.1, r.3]).collect();
ys.sort_unstable(); ys.dedup();
if ys.len() < 2 { return 0; }
let k = ys.len() - 1;
let mut ev: Vec<(i64, usize, usize, i32)> = Vec::new();
for &(x1, y1, x2, y2) in rects {
let a = ys.binary_search(&y1).unwrap();
let b = ys.binary_search(&y2).unwrap();
ev.push((x1, a, b, 1)); ev.push((x2, a, b, -1));
}
ev.sort_unstable_by_key(|e| e.0);
let mut cover = vec![0i32; k];
let mut area = 0i64;
let mut px = ev[0].0;
for (x, a, b, d) in ev {
let mut len = 0i64;
for i in 0..k { if cover[i] > 0 { len += ys[i+1] - ys[i]; } }
area += len * (x - px);
for c in &mut cover[a..b] { *c += d; }
px = x;
}
area
}
fn grid_area(rects: &[(i64, i64, i64, i64)]) -> i64 {
let mut cells = 0i64;
for x in 0..20 { for y in 0..20 {
if rects.iter().any(|&r| r.0 <= x && x + 1 <= r.2 && r.1 <= y && y + 1 <= r.3) { cells += 1; }
} }
cells
}

33.9 自检与练习

本单元的三套工具共享同一个方法论：把几何对象化为整数谓词，再用一个可检验的不变量串起算法。叉积把"方向"变成符号，凸包把"外包络"变成栈的左转性质，扫描线把"面积"变成事件间的覆盖计数。调试时不要先看图，而应先问：哪条不变量被破坏了？是叉积溢出了吗？是弹栈条件写反了吗？是事件应用早了一步吗？把这些问句写进代码注释，比事后打日志有效得多。下一单元转向随机化与对拍工程，会把本单元反复使用的"独立裁判 + 随机数据"做法系统化。
