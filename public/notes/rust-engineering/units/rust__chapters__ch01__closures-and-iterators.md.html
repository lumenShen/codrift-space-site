7.1 闭包：可以当值传递的函数

函数只能定义一次、名字固定；闭包（closure）则像「匿名函数 + 它能看见的周围环境」，可以存进变量、当作参数传递、从函数里返回。语法是 |参数| 表达式，参数类型通常可以省略，因为编译器会从调用方式推断出来。下面的 add 明确写了类型，而 |n| n * 2 则让编译器从 iter() 产出的元素类型推断出 n 是 &i32。

闭包最特别的能力是捕获（capture）：它可以引用定义时所在作用域里的变量。let x = 10; let plus_x = |n| n + x; 里的 x 并没有通过参数传进来，而是被闭包「顺手带走」了。捕获的方式取决于闭包体怎么用这个变量：只读就按引用捕获，要修改就按可变引用捕获，要拿走所有权就用 move 关键字。

大白话先用直觉把它讲通

闭包像一个随身带着行李的小帮手。普通函数只能用它手里临时的东西，闭包却能把「当时桌上的东西」一起打包带走。迭代器则像一条传送带：你在传送带旁挂上几个工位（map、filter），东西只有被推到最后要用到时才真正加工——这叫惰性求值，好处是不用先造出一堆中间产物。

下面的程序把三种场景放在一起：一个纯粹的二元闭包、一个捕获了 x 的闭包，以及闭包作为 map 参数的使用。最后一个 collect() 会把迭代器收集成 Vec<i32>，目标类型由变量注释决定。

rustRust · 标准库12 行
fn main() {
let add = |a: i32, b: i32| a + b;
println!("3 + 4 = {}", add(3, 4));
let x = 10;
let plus_x = |n: i32| n + x;
println!("5 + x = {}", plus_x(5));
let nums = [1, 2, 3];
let doubled: Vec<i32> = nums.iter().map(|n| n * 2).collect();
println!("{doubled:?}");
}

闭包的类型是编译器为它匿名生成的，你写不出「闭包的类型名」。正因如此，接收闭包的函数必须写成泛型 F: Fn...，而不能写具体类型。这也是理解下一节三个 trait 的入口。

编译器推断闭包参数类型的方式很实用：第一次调用时看到你传了整数，就确定参数是整数；如果一直不调用、上下文也没有类型信息，它就会报错，这时给参数补上类型即可。另外，move 关键字不只是「把变量搬进闭包」的语法糖——在把闭包交给另一个线程时，它几乎是必需的，因为新线程的生命周期可能超过当前栈帧，闭包不能依赖对局部变量的借用。

7.2 Fn、FnMut、FnOnce：按「怎么用」分类

Rust 用三个 trait 描述闭包能怎样被调用，它们的约束强度依次递减：Fn 最宽松（可以重复调用，不消耗任何东西），FnMut 次之（可以重复调用，但需要可变引用来修改状态），FnOnce 最弱（只能调用一次，因为会消耗捕获的值）。

trait 调用次数 对捕获值的操作 典型例子
Fn 任意多次 只读借用 || x，|a, b| a + b
FnMut 任意多次 可变借用、修改状态 计数器 || { count += 1; count }
FnOnce 仅一次 取得所有权并消耗 move || drop(s)

这套分类的价值在于：函数在签名里声明 F: Fn，就向调用方保证「我不会拿走你的闭包，也不会修改它」；声明 F: FnMut 则需要把闭包声明成 mut。如果参数写成 F: FnOnce，调用函数时闭包本身会被消耗掉——它最适合那些「只跑一次」的回调场景。

三者之间是包含关系：所有 Fn 闭包都自动是 FnMut，所有 FnMut 又都是 FnOnce。所以写 F: FnOnce 是对调用方最宽松的约束（几乎任何闭包都能传进来），而写 F: Fn 最严格。设计 API 时有个实用原则：按「你实际需要的最弱能力」来选——只要调用一次就够，就别要求 Fn；这样调用方能传进来的闭包类型更多。

下面的程序分别写了三个接收者。call_mut 的形参必须写 mut f，否则调用 f() 时会报「不可变地借用可变闭包」的错误。call_once 里用 move 把 String 的所有权移进闭包，闭包被调用后 s 就被 drop 了。

rustRust · 标准库25 行
fn call_once<F: FnOnce() -> i32>(f: F) -> i32 {
f()
}
fn call_mut<F: FnMut() -> i32>(mut f: F) -> i32 {
f()
}
fn call<F: Fn() -> i32>(f: F) -> i32 {
f()
}
fn main() {
let s = String::from("hello");
println!("FnOnce: {}", call_once(move || s.len() as i32));
let mut count = 0;
println!("FnMut: {}", call_mut(|| {
count += 1;
count
}));
let x = 7;
println!("Fn: {}", call(|| x));
}

7.3 迭代器：惰性求值的数据流

迭代器（iterator）是对「一串可以逐个取出的值」的抽象。它的核心只有一个方法 next()，返回 Option<Item>——有元素就给 Some(值)，取完了给 None。for 循环其实就是迭代器的语法糖：for x in v 会把 v 转成迭代器，反复调用 next() 直到结束。

迭代器最重要的性质是惰性（lazy）：光创建它不会做任何计算，只有真正调用 next()（或者被 collect、sum 这类消费器驱动）时才逐步产出值。这意味着你可以把多个步骤串成一条流水线，而中间结果不需要先存成完整的 Vec，既省内存又能早停。

下面的程序先算一个「偶数平方和」，链上 filter 和 map，最后由 sum() 消费。第二半段用一个带打印的 map 演示惰性：创建之后什么都没打印，直到调用 next() 才看到输出。

rustRust · 标准库16 行
fn main() {
let nums = [1, 2, 3, 4, 5, 6];
let result: i32 = nums
.iter()
.filter(|&&n| n % 2 == 0)
.map(|&n| n * n)
.sum();
println!("偶数平方和 = {result}");
let mut lazy = nums.iter().map(|n| {
println!("正在计算 {n}");
n * 2
});
println!("此刻还没有任何计算发生");
println!("第一个结果: {:?}", lazy.next());
}

注意 iter() 产出的是引用 &i32，所以 filter 的闭包收到 &&i32、map 的闭包收到 &i32。用 |&n| 这样的模式可以把引用解构掉，直接拿到值。如果你拿到的是迭代器本身而不是切片，比如 .into_iter() 产出的是 i32，闭包参数就不用带 & 了。三种常见入口的区别值得记牢：iter() 借用集合，iter_mut() 可变借用（可以原地修改元素），into_iter() 消耗集合、把所有权逐个交出。选哪个取决于你之后还想不想继续使用原集合。

7.4 适配器：map、filter、fold

适配器（adapter）是「接收一个迭代器、返回另一个迭代器」的方法，可以无限串联。map 做一对一转换，filter 按条件保留元素，take(n) 只取前 n 个，enumerate() 给元素配上下标。它们都是惰性的，不会立即遍历数据。

fold 则是消费器：它带一个初始累加值，把闭包依次应用到每个元素上，最后返回累加结果。下面的程序用 fold 实现字符串拼接，同时演示 take 和 enumerate 的惰性链条。

rustRust · 标准库16 行
fn main() {
let nums = [1, 2, 3, 4, 5];
let txt = nums
.iter()
.take(3)
.map(|n| n.to_string())
.fold(String::from("结果:"), |acc, n| {
format!("{acc} {n}")
});
println!("{txt}");
for (i, n) in nums.iter().enumerate() {
println!("下标 {i} -> 值 {n}");
}
}

这里要提醒一点：fold 的闭包里用 format! 每次生成新字符串，数据量很大时会有额外分配。追求性能时可以改成可变累加器，或者用 write! 直接写入 String。这属于优化层面的考虑，初学阶段先用最直观的写法把逻辑写对更重要。先跑通，再优化，永远是比较稳妥的顺序。

7.5 collect 与类型推断

collect() 把迭代器收集成集合，是迭代器世界里最常用的「出口」。它之所以能工作，是因为 FromIterator trait：Vec、BTreeSet、HashMap 等类型都实现了它，知道怎么从一个迭代器构造自己。正因为如此，collect() 的返回类型必须由上下文给出——变量注释、函数返回值或后续用法都可以，但如果完全没有类型信息，编译器就会报错。

下面的程序把同一组单词分别收集成 Vec、BTreeSet 和 HashMap。注意 Vec<usize> 的注释是必需的；而 BTreeSet 会自动去重；HashMap 的构造稍微特殊，这里用 entry API 手动统计词频，展示迭代器与常规写法的配合。

rustRust · 标准库17 行
use std::collections::{BTreeSet, HashMap};
fn main() {
let words = ["rust", "go", "rust", "c"];
let lens: Vec<usize> = words.iter().map(|w| w.len()).collect();
println!("长度列表 {lens:?}");
let unique: BTreeSet<&str> = words.iter().copied().collect();
println!("去重后 {unique:?}");
let mut counts: HashMap<&str, i32> = HashMap::new();
for &w in &words {
*counts.entry(w).or_insert(0) += 1;
}
println!("词频 {counts:?}");
}

collect() 还有一个进阶用法：如果迭代器的元素本身是 Result<T, E>，你可以把它收集成 Result<Vec<T>, E>——遇到第一个 Err 就整体失败，否则得到装满成功值的向量。这在「批量解析、任一失败就报错」的场景里非常顺手，因为类型系统会自动帮你把错误冒泡出来。

什么时候该用迭代器、什么时候写普通循环？一个简单判断：如果是在「对一串数据做连续的变换和筛选」，迭代器链通常更短、更不容易写出边界错误；如果逻辑里充满了提前返回、复杂状态机或需要修改多个外部变量，for 循环往往更清晰。两者不是高低之分，而是工具箱里的不同工具。迭代器链会消耗原始迭代器，收集完想再用一遍，记得重新调用 iter() 建一条新链，不能直接拿旧链重复收集。
