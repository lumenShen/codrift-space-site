24.1 DFS 生成树上的 dfn 与 low：强连通的判据

Tarjan 的所有变体都建立在一次 DFS 上。给每个点两个时间戳：dfn[u] 是首次访问的次序，low[u] 是 u 或其子树内的点通过至多一条非树边能回到的最小 dfn。树边构成 DFS 生成树；非树边分三类：指向祖先的回边、指向子树中已访问点的前向边、指向已完成其他分支点的横叉边。只有回边能降低 low，因为前向边与横叉边指向 dfn 更大的点，取 min 没有意义。

从定义可推出强连通分量的判据：当 DFS 从 u 的一棵子树返回时，若 low[u] == dfn[u]，说明 u 的子树没有任何边能逃到更早的祖先，u 就是它所在分量的"根"。把从 u 开始、仍在辅助栈上的点全部弹出，恰好得到一个强连通分量。反过来，若 low[u] < dfn[u]，u 的子树与更早的祖先互通，暂不能封口。

实现有几个必须固化的细节。第一，dfn[v] == 0 表示未访问，所以计时器必须从 1 开始——若从 0 开始，0 号点会被反复当成未访问而重复入栈，这是真会出错的坑。第二，辅助栈用 in_stack 布尔数组标记，扫描到指向栈内点的边才更新 low；指向已弹出点的边不更新，否则会把两个不同的分量错误合并。第三，子树的 low 在孩子帧弹出时才能合并到父，且必须先判断孩子是否封口弹栈，再按 in_stack[child] 决定是否传播——顺序反了就会把不该继承的低值传给父节点。

帧 (u, next_idx) 里的下标在扫描每条边之前先加一，这样即使遇到需要 continue 的回边或已访问点，也不会把同一条边处理两次。帧数最多等于当前 DFS 路径的长度，而不是已访问点的总数，因此在星形图上内存依然很小。若改用递归写法，代码会短三分之一，但十万节点的链会让调用栈溢出；Rust 主线程栈有限，这一点在工程里不是理论风险。对不连通的有向图，外层循环必须对每个未访问点重新启动一次 DFS，并在每轮开始时把辅助栈清空——虽然上一轮结束时它本应为空，但显式保证能省去调试时的猜测。

// Tarjan 强连通分量：迭代版，避免深图爆栈
fn tarjan_scc(n: usize, edges: &[(usize, usize)]) -> Vec<Vec<usize>> {
let mut g = vec![Vec::new(); n];
for &(u, v) in edges {
g[u].push(v);
}
let mut dfn = vec![0usize; n];
let mut low = vec![0usize; n];
let mut in_stack = vec![false; n];
let mut stack: Vec<usize> = Vec::new();
let mut comps: Vec<Vec<usize>> = Vec::new();
let mut timer = 1usize;
for root in 0..n {
if dfn[root] != 0 {
continue;
}
dfn[root] = timer;
low[root] = timer;
timer += 1;
stack.push(root);
in_stack[root] = true;
let mut frames: Vec<(usize, usize)> = vec![(root, 0)];
while let Some(&(u, idx)) = frames.last() {
if idx < g[u].len() {
frames.last_mut().unwrap().1 += 1;
let v = g[u][idx];
if dfn[v] == 0 {
dfn[v] = timer;
low[v] = timer;
timer += 1;
stack.push(v);
in_stack[v] = true;
frames.push((v, 0));
} else if in_stack[v] {
low[u] = low[u].min(dfn[v]); // 指向栈内点 = 回边/横叉边
}
} else {
let u = frames.pop().unwrap().0;
if low[u] == dfn[u] {
let mut comp = Vec::new();
while let Some(v) = stack.pop() {
in_stack[v] = false;
comp.push(v);
if v == u {
break;
}
}
comps.push(comp);
}
if let Some(&(p, _)) = frames.last() {
if in_stack[u] {
low[p] = low[p].min(low[u]);
}
}
}
}
}
comps
}
fn main() {
let edges = [
(0usize, 1usize), (1, 2), (2, 0), // 环 {0,1,2}
(2, 3), (3, 4), (4, 3), // 环 {3,4}
(5, 4), // 单点 {5}
];
let mut comps = tarjan_scc(6, &edges);
for c in comps.iter_mut() {
c.sort_unstable();
}
comps.sort();
println!("sccs = {:?}", comps);
}

24.2 缩点：把强连通分量压成一个点

Tarjan 返回的分量表可以立即用于"缩点"：把每个分量看作一个超级节点，原图中跨分量的边变成超级节点之间的有向边，得到的必然是有向无环图（DAG）。若有环，环上的分量会互相可达，它们在 Tarjan 里本应属于同一个分量，矛盾。缩点后可以做很多原图上困难的事：统计"入度为 0 的分量个数"就是至少要选多少个起点才能遍历全图；在 DAG 上做拓扑 DP，可以求最长可达链、可达点集大小等。

正确性论证依赖两条：其一，同一 SCC 内的点互相可达，压缩不会丢失内部连通信息；其二，跨 SCC 的边方向单一，若存在 u∈A、v∈B 的边和 v'∈B、u'∈A 的边，则 A、B 互通，应合并为同一分量。实践中给每个点记 comp[v]，遍历原边只在 comp[u] != comp[v] 时建缩点边，并用集合去重。分量编号的顺序是逆拓扑序（Tarjan 先弹出下游分量），直接拿来当拓扑序往往也成立，但不依赖这个性质更安全。

大白话先用直觉把它讲通

强连通分量就是"互相能走到的一伙人"。把每伙人看成一个整体，整体之间只可能单向通行——否则两伙人就该合成一伙。这样一来，复杂的有向图就变成了一条没有环的依赖链，很多原本绕来绕去的问题在链上一下就清楚了。

复杂度 O(n+m)：每点入栈出栈各一次，每条边扫描一次。迭代版用帧 (u, next_idx) 显式记录"下一次该检查哪个邻居"，栈深等于当前 DFS 路径长度；与递归版相比，它把最坏 O(n) 的调用栈搬到堆上的 Vec，避免深链爆栈。外层 for root in 0..n 保证不连通图也被完整覆盖——这是有向图算法常被忽略的一点：从 0 号点出发的 DFS 看不到其他弱连通块。

缩点的应用很广。最经典的是 2-SAT：每个变量拆成"取真"与"取假"两个点，蕴含关系建成有向边，若某个变量的两种取值落在同一 SCC 则无解；否则按 SCC 的逆拓扑序给每个分量赋值。另一个常见场景是"可达性统计"：在缩点 DAG 上按拓扑序做集合并，复杂度从原图上的 O(nm) 降到 O(n+m) 级别。把分量编号规范化（例如按最小点号）能让对拍与调试更容易，但正式的缩点图只用 comp[u] 这个编号即可，不必真的排序。

24.3 无向图的桥与割点：边号、重边与根的特例

无向图的 Tarjan 与有向版形态相似但语义不同。low[u] 定义为 u 的子树经至多一条非树边能回到的最小 dfn；判据是：对树边 u→v，若 low[v] > dfn[u]，说明 v 的子树没有任何边能回到 u 或更早，删掉这条边就把图切开，它是桥；若 low[v] >= dfn[u] 且 u 不是 DFS 根，说明删掉 u 后 v 那一支与 u 的父方向断开，u 是割点。根是特例：它只有一个孩子时不是割点，只有孩子数 ≥2 才是。

关键实现细节是用边号跳过父边，而不是用父节点编号。无向图的每条逻辑边往邻接表加两次，若只按"邻居等于父"跳过，一条重边的另一份会被当成回边，错误地降低 low，把本该是桥的边判成非桥。给每条输入边编号 id，邻接表存 (neighbor, id)，扫描时 if eid == parent_edge[u] { continue; } 只跳过来自父的那一份，重边的另一份照常参与更新。这个细节在随机对拍里很容易被构造出来。

自环也值得单独考虑：自环在邻接表里出现两次，指向自己，会把 low[u] 更新为 dfn[u]，不改变任何判定，因此桥与割点算法无需特判自环。但"删掉一条边后是否连通"的暴力裁判要小心：自环删掉后图当然不变，暴力判定与 Tarjan 一致。根的孩子数 children[root] 只在每个根的本轮 DFS 里计数，换根时要重新累计；若图不连通，每个弱连通块各有一个根，割点只可能出现在自己那一块里，外层循环天然处理了这种情况。

// 无向图的桥与割点：用边号跳过parent边，正确处理器重边
fn bridges_and_articulations(n: usize, edges: &[(usize, usize)]) -> (Vec<(usize, usize)>, Vec<usize>) {
let mut g = vec![Vec::<(usize, usize)>::new(); n];
for (id, &(u, v)) in edges.iter().enumerate() {
g[u].push((v, id));
g[v].push((u, id));
}
let mut dfn = vec![0usize; n];
let mut low = vec![0usize; n];
let mut parent = vec![n; n];
let mut parent_edge = vec![usize::MAX; n];
let mut children = vec![0usize; n];
let mut is_art = vec![false; n];
let mut bridges = Vec::new();
let mut timer = 1usize;
for root in 0..n {
if dfn[root] != 0 { continue; }
dfn[root] = timer;
low[root] = timer;
timer += 1;
let mut frames: Vec<(usize, usize)> = vec![(root, 0)];
while let Some(&(u, idx)) = frames.last() {
if idx < g[u].len() {
frames.last_mut().unwrap().1 += 1;
let (v, eid) = g[u][idx];
if eid == parent_edge[u] { continue; }
if dfn[v] == 0 {
parent[v] = u;
parent_edge[v] = eid;
children[u] += 1;
dfn[v] = timer;
low[v] = timer;
timer += 1;
frames.push((v, 0));
} else {
low[u] = low[u].min(dfn[v]);
}
} else {
let u = frames.pop().unwrap().0;
if let Some(&(p, _)) = frames.last() {
if low[u] > dfn[p] {
bridges.push((p.min(u), p.max(u)));
}
if p != root && low[u] >= dfn[p] {
is_art[p] = true;
}
low[p] = low[p].min(low[u]);
}
}
}
if children[root] > 1 {
is_art[root] = true;
}
}
let arts: Vec<usize> = (0..n).filter(|&i| is_art[i]).collect();
(bridges, arts)
}
fn main() {
let edges = [
(0usize, 1usize), (1, 2), (2, 0), // 三角形
(2, 3), // 桥
(3, 4), (4, 5), (5, 3), // 三角形
(5, 6), // 桥
];
let (mut bridges, arts) = bridges_and_articulations(7, &edges);
bridges.sort();
println!("bridges = {:?}", bridges);
println!("arts = {:?}", arts);
}

手验：2 连接左侧三角形与 3，删掉它就把 {0,1} 与其余分离，故 2 是割点；3 与 5 同理；(2,3) 与 (5,6) 是桥，其余边都在环上。注意桥一定是割点的必要条件不成立：删桥分离的是两个连通块，但端点未必各自是割点。

24.4 对拍抓到的两个真实 bug：哨兵与零点

本节值得单独记一笔，因为下面 24.8 的对拍在开发中真的抓到过两个 bug，而且都不是"算法思路错"，而是边界约定没对齐。第一个：根的父节点初始化为哨兵 n，割点判定写成 if parent[p] != root 时，根 p 的 parent[p] = n，于是 n != root 恒成立，根被错误标记为割点。正确写法是直接比较 p != root，或者把根的父设为它自己。第二个：dfn 用 0 表示未访问，但计时器也从 0 开始，导致 0 号点的 dfn 为 0，被后续扫描误判为"未访问"而重复入栈，low 值被污染。

坑这里最容易踩

坑：这两个 bug 的共同点是"0 和哨兵撞车"。Rust 的 usize 没有负值，习惯用 0 或 n 当哨兵时，必须确认真实数据不会取到同一个值。若用 parent[root] = root、dfn 从 1 开始计数，这类冲突就从根上避免了。对拍用"暴力删边/删点"作裁判，几秒内就能把错误定位到具体点号，比盯着 low 的递推式有用得多。

这也说明为什么算法笔记不能只贴"看起来对"的代码：把两个实现放在同一组随机输入上比一比，很多隐蔽的约定错误会立刻现形，尤其是那些在最小样例上恰好不触发的边界。写模板时把"未访问用什么表示""根的父亲是谁"这两句话写在注释里，是性价比极高的防御。

推广开来，凡是"哨兵值与合法值可能撞车"的地方都要先列一张表：usize::MAX、n、0 各自代表什么，真实数据能否取到这些值。parent[root] = root 让根的父指针落在合法点号上，是最省心的约定；dfn 从 1 开始让 0 专门表示未访问，同样干净。相比之下，parent[root] = n 加 dfn 从 0 开始虽然也能工作，但要求每一处判定都记得排除哨兵，任何一处漏掉就是隐蔽的错。Rust 的类型系统不会替你检查这种语义约定，只有对拍和注释能守住。

24.5 拓扑排序：Kahn 入度与 DFS 逆完成序

拓扑排序针对有向无环图（DAG），输出一个序列使每条边 u→v 都满足 u 在 v 前。Kahn 算法从入度为 0 的点开始：把它们全入队，依次弹出并记录，每弹出一个点就把后继的入度减一，减到 0 的再入队。若最终输出点数不足 n，说明有环。indeg[v] -= 1 在 usize 上安全，因为 v 出现在 u 的后继表里就表示有一条来自 u 的入边尚未扣减，而 u 只弹出一次。

DFS 版的依据是：在有向图中，点的完成时间逆序就是拓扑序——先完成的点不可能有一条指向未完成点的边（否则它会等那点完成）。实现时把三色 DFS 的完成序列整体反转。三色中的灰色（在栈中）还顺带提供了环检测：遇到灰点即存在回边。Kahn 按入度剥层，结果常不唯一；DFS 的结果依赖邻接表顺序。两者都是 O(n+m)，返回 Option 把"有环"编码进类型，比返回空 Vec 更不易误用。

rustRust · 标准库61 行
use std::collections::VecDeque;
fn topo_kahn(n: usize, edges: &[(usize, usize)]) -> Option<Vec<usize>> {
let mut g = vec![Vec::new(); n];
let mut indeg = vec![0usize; n];
for &(u, v) in edges {
g[u].push(v);
indeg[v] += 1;
}
let mut q = VecDeque::new();
for i in 0..n {
if indeg[i] == 0 { q.push_back(i); }
}
let mut order = Vec::with_capacity(n);
while let Some(u) = q.pop_front() {
order.push(u);
for &v in &g[u] {
indeg[v] -= 1; // v 出现在 u 的后继里，说明这条入边尚未扣减
if indeg[v] == 0 { q.push_back(v); }
}
}
if order.len() == n { Some(order) } else { None }
}
fn topo_dfs(n: usize, edges: &[(usize, usize)]) -> Option<Vec<usize>> {
let mut g = vec![Vec::new(); n];
for &(u, v) in edges { g[u].push(v); }
let mut color = vec![0u8; n]; // 0 白 1 灰 2 黑
let mut finish = Vec::with_capacity(n);
for s in 0..n {
if color[s] != 0 { continue; }
color[s] = 1;
let mut frames = vec![(s, 0usize)];
while let Some(&(u, idx)) = frames.last() {
if idx < g[u].len() {
frames.last_mut().unwrap().1 += 1;
let v = g[u][idx];
match color[v] {
0 => { color[v] = 1; frames.push((v, 0)); }
1 => return None, // 灰点 = 环
_ => {}
}
} else {
color[u] = 2;
finish.push(u);
frames.pop();
}
}
}
finish.reverse();
Some(finish)
}
fn main() {
let dag = [(0usize, 1usize), (0, 2), (1, 3), (2, 3), (3, 4)];
let cyclic = [(0usize, 1usize), (1, 2), (2, 0)];
println!("kahn dag = {:?}", topo_kahn(5, &dag));
println!("dfs dag = {:?}", topo_dfs(5, &dag));
println!("kahn cyclic = {:?}", topo_kahn(3, &cyclic));
println!("dfs cyclic = {:?}", topo_dfs(3, &cyclic));
}

两个 DAG 序列不同但都合法：Kahn 用队列，DFS 用完成序逆序。若题目要求"字典序最小的拓扑序"，把 Kahn 的队列换成 BinaryHeap<Reverse<usize>> 即可；平行边会让入度多加多减，不影响结果。

Kahn 的四类数据结构里，VecDeque 与 BinaryHeap 都只存点号，空间 O(n)；若需要在拓扑序上做 DP（例如求最长路径），可在弹出的同时把状态转移写到后继上，与入度递减合并在同一个循环里。DFS 版在遇到灰点时立即返回 None，不需要等整个遍历结束——这让它能更早发现环，但也意味着它不会给出"已处理部分"的信息。两种实现的结果顺序都依赖邻接表的插入顺序，若要求输出确定，应在建图后对内层向量排序，或改用优先队列固定选择规则。

24.6 Kruskal：按边排序与并查集的切分不变式

最小生成树（MST）在无向连通带权图上选 n−1 条边，使总权最小且连通无环。Kruskal 的贪心是：把边按权从小到大排序，逐条尝试加入，若两端尚未连通就合并。正确性由切分定理保证：对任意一个切分，跨越它的最小权边必属于某棵 MST；每次选当前最短的"安全边"不会破坏这个性质。实现上"是否连通"用并查集回答，路径压缩加按大小合并的摊还复杂度是 O(α(n))，几乎常数。

代码里 Dsu::find 写成两段循环：第一趟找到根 r，第二趟把沿途节点直接挂到 r（路径压缩）。不能写成递归，因为深链仍可能爆栈；也不能只在第一趟改父指针而不继续走到根，否则返回的是半压缩路径上的中间点。union 按 sz 合并小树到大树，避免退化成链。for (k, &(w,u,v)) in es.iter().enumerate() 里的 k 是排序后的边号，用来在返回值中记录选了哪些边；若只要总权值，可以省掉 used。

大白话先用直觉把它讲通

并查集像一群小帮派，开始时每人自成一派。Kruskal 把道路按造价从便宜到贵排好，一条条看：如果这条路连接两个不同帮派，就合并它们并收下这条路；如果两端本来就是一个帮派，收下它会形成环，果断丢掉。最后剩下 n−1 条路，所有点合成一派，总造价最小。

复杂度 O(m log m) 主要来自排序。注意 kruskal 对不连通图会返回一片森林：used.len() < n−1 时说明图不连通，调用方必须检查这个计数，不能只看总权值。示例里断开的图返回 (2, [0,1])，正是森林的权值与选边数。

find 的两趟循环值得再解释：第一趟沿父指针走到根 r，第二趟把沿途每个节点的父指针直接改成 r。若边走边改而不先找到根，就会把半途节点当成根返回，合并出错误的树。sz 数组记录每棵树的节点数，合并时把小的挂到大的下面，保证树高是 O(log n)；再加上路径压缩，m 次操作的摊还复杂度接近 O(m)。若边权相等，sort_unstable 会任意打乱同权边的次序，MST 的总权仍然唯一，但具体选边可能不同；想让输出确定可用稳定排序或把边号作为 tie-breaker。边权为负也不影响 Kruskal，排序后照常处理即可。

24.7 Prim：从已选集合向外的另一种贪心

Prim 换了一个角度：维护一棵不断长大的树，初始只有源点，每轮选一条"一端在树内、一端在树外"的最小权边，把外面的点加进来。正确性同样来自切分定理——这条边正是跨越"树内/树外"切分的最小边。low[v] 表示 v 当前到树内点的最小边权，用 BinaryHeap<Reverse<(w,v)>> 每次取最小；点入树后打 in_tree 标记，堆里的旧记录用 in_tree[u] || d > low[u] 跳过，与 Dijkstra 的过期项模式一致。

与 Kruskal 相比：Prim 不需要先把所有边排序，复杂度 O(m log n)，在稠密图上更优；Kruskal 需要排序 O(m log m)，但实现更简单、更容易并行。Prim 若不连通，cnt < n，示例返回 −1 表示无生成树；这个失败状态必须显式返回，不能默默给一个偏小的总权值。选哪个取决于图的疏密与是否需要"边的集合"：Kruskal 天然给出边表，Prim 更擅长从小源点扩展。

Prim 的起点可以任取，因为生成树总要覆盖所有连通点；换一个起点只改变加入顺序，不改变最小总权。堆里的重复项与 Dijkstra 同理：一条边可能让同一个点多次降低 low，旧记录弹出时 d > low[u] 即丢弃。若图权全相等，Prim 等价于从源出发的 BFS 生成树；若边权有负，Prim 依然正确，因为它只依赖切分定理而非贪心的"距离单调"。空间上，low、in_tree 各 O(n)，堆 O(m)；在稠密图里堆里同时存在 O(m) 条记录，是 Prim 的主要内存开销。若要点数极大而边相对稀疏，可把邻接表换成分层存储来改善局部性，但算法本身不变。生成树的边表可以在成功加入点 v 时顺带记录 parent[v] = u，回溯即得选边集合，无需额外排序。

use std::cmp::Reverse;
use std::collections::BinaryHeap;
struct Dsu { p: Vec<usize>, sz: Vec<usize> }
impl Dsu {
fn new(n: usize) -> Self { Dsu { p: (0..n).collect(), sz: vec![1; n] } }
fn find(&mut self, x: usize) -> usize {
let mut r = x;
while self.p[r] != r { r = self.p[r]; }
let mut v = x;
while self.p[v] != v { let next = self.p[v]; self.p[v] = r; v = next; }
r
}
fn union(&mut self, a: usize, b: usize) -> bool {
let (mut ra, mut rb) = (self.find(a), self.find(b));
if ra == rb { return false; }
if self.sz[ra] < self.sz[rb] { std::mem::swap(&mut ra, &mut rb); }
self.p[rb] = ra;
self.sz[ra] += self.sz[rb];
true
}
}
fn kruskal(n: usize, edges: &[(usize, usize, i64)]) -> (i64, Vec<usize>) {
let mut es: Vec<(i64, usize, usize)> = edges.iter().map(|&(u, v, w)| (w, u, v)).collect();
es.sort_unstable();
let mut dsu = Dsu::new(n);
let mut total = 0i64;
let mut used = Vec::new();
for (k, &(w, u, v)) in es.iter().enumerate() {
if dsu.union(u, v) {
total += w;
used.push(k);
if used.len() == n - 1 { break; }
}
}
(total, used)
}
fn prim(n: usize, edges: &[(usize, usize, i64)], src: usize) -> i64 {
let mut g = vec![Vec::<(usize, i64)>::new(); n];
for &(u, v, w) in edges {
g[u].push((v, w));
g[v].push((u, w));
}
let inf = i64::MAX / 4;
let mut low = vec![inf; n];
let mut in_tree = vec![false; n];
let mut pq: BinaryHeap<Reverse<(i64, usize)>> = BinaryHeap::new();
low[src] = 0;
pq.push(Reverse((0, src)));
let mut total = 0i64;
let mut cnt = 0usize;
while let Some(Reverse((d, u))) = pq.pop() {
if in_tree[u] || d > low[u] { continue; }
in_tree[u] = true;
total += d;
cnt += 1;
for &(v, w) in &g[u] {
if !in_tree[v] && w < low[v] {
low[v] = w;
pq.push(Reverse((w, v)));
}
}
}
if cnt == n { total } else { -1 }
}

24.8 随机对拍：四类算法对暴力裁判

这一单元的算法都适合用"慢但显然对"的对照验证。对拍程序生成 1500 组数据，每组同时检查四件事：其一，随机有向图的 SCC——Tarjan 的分量编号与 Floyd 求出的互达关系对照；其二，随机连通无向图的桥与割点——与"逐条删边后是否仍连通""逐点删除后是否仍连通"的暴力结果对照；其三，同图的带权 MST——Kruskal 与 Prim 总权必须相等且边数为 n−1；其四，随机 DAG——Kahn 必须成功且结果长度等于 n。

生成器用 xorshift，连通无向图先造随机生成树（令点 i 的父在 [0,i) 中选）再加随机额外边，既保证连通又能制造环与重边。暴力删边/删点用 BFS 判连通，n≤9 时开销可忽略。Floyd 的互达闭包把 reach[i][i] 初始化为 true，两层循环传递闭包后，i 与 j 同分量当且仅当 reach[i][j] && reach[j][i]。把 Tarjan 每个分量规范化为"最小点号"，就能与暴力分组逐位比较。

坑这里最容易踩

坑：剖分"不连通/连通"的图要做成两类独立数据。若只在不连通图上测桥与割点，根的特例会被大量无意义的孤立点淹没；若只在连通图上测，又漏掉"多根 DFS"的覆盖。本对拍对无向图保证连通（因为桥割点语义在这种图上最清晰），对 SCC 则允许任意不连通——不同算法用不同数据分布，是对拍设计的基本功。

// 有向图：Tarjan SCC（与正文同一模板，计时器从 1 开始）
fn tarjan_scc(n: usize, edges: &[(usize, usize)]) -> Vec<Vec<usize>> {
let mut g = vec![Vec::new(); n];
for &(u, v) in edges { g[u].push(v); }
let (mut dfn, mut low) = (vec![0usize; n], vec![0usize; n]);
let mut ins = vec![false; n];
let mut stk = Vec::new();
let mut comps = Vec::new();
let mut timer = 1;
for root in 0..n {
if dfn[root] != 0 { continue; }
dfn[root] = timer; low[root] = timer; timer += 1;
stk.push(root); ins[root] = true;
let mut fr = vec![(root, 0usize)];
while let Some(&(u, i)) = fr.last() {
if i < g[u].len() {
fr.last_mut().unwrap().1 += 1;
let v = g[u][i];
if dfn[v] == 0 {
dfn[v] = timer; low[v] = timer; timer += 1;
stk.push(v); ins[v] = true;
fr.push((v, 0));
} else if ins[v] { low[u] = low[u].min(dfn[v]); }
} else {
let u = fr.pop().unwrap().0;
if low[u] == dfn[u] {
let mut c = Vec::new();
while let Some(v) = stk.pop() {
ins[v] = false; c.push(v);
if v == u { break; }
}
comps.push(c);
}
if let Some(&(p, _)) = fr.last() {
if ins[u] { low[p] = low[p].min(low[u]); }
}
}
}
}
comps
}
fn brute_scc(n: usize, edges: &[(usize, usize)]) -> Vec<usize> {
let mut r = vec![vec![false; n]; n];
for i in 0..n { r[i][i] = true; }
for &(u, v) in edges { r[u][v] = true; }
for k in 0..n { for i in 0..n { for j in 0..n { if r[i][k] && r[k][j] { r[i][j] = true; } } } }
(0..n).map(|i| (0..n).find(|&j| r[i][j] && r[j][i]).unwrap()).collect()
}
// 无向图：桥与割点（与正文同一模板，根用 p != root 判定）
fn bridge_art(n: usize, edges: &[(usize, usize)]) -> (Vec<(usize, usize)>, Vec<usize>) {
let mut g = vec![Vec::<(usize, usize)>::new(); n];
for (id, &(u, v)) in edges.iter().enumerate() { g[u].push((v, id)); g[v].push((u, id)); }
let (mut dfn, mut low) = (vec![0usize; n], vec![0usize; n]);
let (mut par, mut pe) = (vec![n; n], vec![usize::MAX; n]);
let mut ch = vec![0usize; n];
let mut art = vec![false; n];
let mut br = Vec::new();
let mut timer = 1;
for root in 0..n {
if dfn[root] != 0 { continue; }
dfn[root] = timer; low[root] = timer; timer += 1;
let mut fr = vec![(root, 0usize)];
while let Some(&(u, i)) = fr.last() {
if i < g[u].len() {
fr.last_mut().unwrap().1 += 1;
let (v, id) = g[u][i];
if id == pe[u] { continue; }
if dfn[v] == 0 {
par[v] = u; pe[v] = id; ch[u] += 1;
dfn[v] = timer; low[v] = timer; timer += 1;
fr.push((v, 0));
} else { low[u] = low[u].min(dfn[v]); }
} else {
let u = fr.pop().unwrap().0;
if let Some(&(p, _)) = fr.last() {
if low[u] > dfn[p] { br.push((p.min(u), p.max(u))); }
if p != root && low[u] >= dfn[p] { art[p] = true; }
low[p] = low[p].min(low[u]);
}
}
}
if ch[root] > 1 { art[root] = true; }
}
(br, (0..n).filter(|&i| art[i]).collect())
}
fn connected(n: usize, edges: &[(usize, usize)], skip_edge: Option<usize>, skip_node: Option<usize>) -> bool {
let start = match skip_node { Some(0) if n > 1 => 1, _ => 0 };
let mut seen = vec![false; n];
let mut q = VecDeque::new();
seen[start] = true; q.push_back(start);
while let Some(u) = q.pop_front() {
for (id, &(a, b)) in edges.iter().enumerate() {
if Some(id) == skip_edge { continue; }
let v = if a == u { b } else if b == u { a } else { continue };
if Some(v) == skip_node { continue; }
if !seen[v] { seen[v] = true; q.push_back(v); }
}
}
(0..n).all(|i| Some(i) == skip_node || seen[i])
}
fn brute_bridge_art(n: usize, edges: &[(usize, usize)]) -> (Vec<(usize, usize)>, Vec<usize>) {
let mut br = Vec::new();
for id in 0..edges.len() {
if !connected(n, edges, Some(id), None) {
let (u, v) = edges[id];
br.push((u.min(v), u.max(v)));
}
}
let art = (0..n).filter(|&v| !connected(n, edges, None, Some(v))).collect();
(br, art)
}
// 带权 MST：Kruskal 与 Prim
fn kruskal(n: usize, edges: &[(usize, usize, i64)]) -> (i64, usize) {
let mut es: Vec<_> = edges.iter().map(|&(u, v, w)| (w, u, v)).collect();
es.sort_unstable();
let mut p: Vec<usize> = (0..n).collect();
fn root(p: &mut [usize], x: usize) -> usize {
let mut r = x; while p[r] != r { r = p[r]; }
let mut v = x; while p[v] != v { let nx = p[v]; p[v] = r; v = nx; }
r
}
let (mut total, mut cnt) = (0i64, 0usize);
for (w, u, v) in es {
let (a, b) = (root(&mut p, u), root(&mut p, v));
if a != b { p[b] = a; total += w; cnt += 1; }
}
(total, cnt)
}
fn prim(n: usize, edges: &[(usize, usize, i64)]) -> i64 {
use std::cmp::Reverse;
use std::collections::BinaryHeap;
let mut g = vec![Vec::<(usize, i64)>::new(); n];
for &(u, v, w) in edges { g[u].push((v, w)); g[v].push((u, w)); }
let inf = i64::MAX / 4;
let (mut low, mut used) = (vec![inf; n], vec![false; n]);
let mut pq = BinaryHeap::new();
low[0] = 0; pq.push(Reverse((0i64, 0usize)));
let (mut total, mut cnt) = (0i64, 0usize);
while let Some(Reverse((d, u))) = pq.pop() {
if used[u] || d > low[u] { continue; }
used[u] = true; total += d; cnt += 1;
for &(v, w) in &g[u] {
if !used[v] && w < low[v] { low[v] = w; pq.push(Reverse((w, v))); }
}
}
if cnt == n { total } else { -1 }
}
fn topo_kahn(n: usize, edges: &[(usize, usize)]) -> bool {
let mut deg = vec![0usize; n];
let mut g = vec![Vec::new(); n];
for &(u, v) in edges { g[u].push(v); deg[v] += 1; }
let mut q = VecDeque::new();
for i in 0..n { if deg[i] == 0 { q.push_back(i); } }
let mut cnt = 0;
while let Some(u) = q.pop_front() {
cnt += 1;
for &v in &g[u] { deg[v] -= 1; if deg[v] == 0 { q.push_back(v); } }
}
cnt == n
}

for i in 0..n { for j in i + 1..n { if rng.below(4) == 0 { de2.push((i, j)); } } }

}

三类图共 4500 组，加上 MST 的 1500 组，零分歧。这组对拍在开发中先报出 900 余次割点不一致，才引出 24.4 的两个 bug；修正后一次性清零。它同时验证了 24.4 强调的"用边号跳过父边"——随机的额外边经常制造重边，若写成按父节点跳过，这里必然报错。

读对拍输出时，mismatches=0 只是必要条件，还要确认每类计数都非零：若某类生成器因为参数写错而从不产生有效输入，零分歧毫无意义。本例里 neg_cycles 之类的分支在 23 单元出现过，这里四类图都稳定生成 1500 组。若出现 MISMATCH，打印的 n 与具体数组能让你用同种子重放，先缩小到最小反例，再决定是改算法还是改裁判——这个流程在 24.4 的排错里被完整走了一遍。

24.9 工程取舍：复杂度、连通性与失败状态

把四类算法的适用边界列成表，选型时先对照数据形态再动手。Tarjan SCC 与桥割点都是一次 DFS 的副产品，线性时间，适合超大图；缩点后的 DAG 可以衔接拓扑 DP。Kruskal 的瓶颈是排序，Prim 的瓶颈是堆，按图密度选择即可。所有实现都必须处理不连通图：SCC 用外层循环遍历所有根，桥割点同理，Kruskal 要检查选边数，Prim 要检查计数。

算法 对象 复杂度 失败/边界信号 典型用途
Tarjan SCC 有向图 O(n+m) 分量表覆盖所有点 缩点、入度为 0 的分量数
桥与割点 无向图 O(n+m) 根孩子数、边号跳父边 网络可靠性
拓扑排序 DAG O(n+m) 结果长度 < n 即有环 依赖调度
Kruskal 无向带权图 O(m log m) 选边数不足即不连通 稀疏图 MST
Prim 无向带权图 O(m log n) cnt < n 返回 −1 稠密图 MST

还有一个常被忽略的工程点：失败状态要用类型表达。拓扑排序返回 Option<Vec<usize>>，Prim 返回 −1 或 Option<i64>，Kruskal 返回选边数让调用方判断森林。若把"有环""不连通"都压成空 Vec 或零权值，上层很容易把错误结果继续参与计算。Rust 的枚举和 Option 在这里不是形式主义，而是把算法的前置条件写进签名——调用方想忽略都难。
