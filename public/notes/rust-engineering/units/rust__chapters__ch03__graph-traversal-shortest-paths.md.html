23.1 建图约定：邻接表、有向边与 0 基编号

图的存储首选邻接表 Vec<Vec<usize>>：第 u 个内层向量存 u 的所有出边终点。无向边要往两个方向各加一次，有向边只加一次；带权图把元素换成 (usize, i64)。空间是 O(n+m)，与邻接矩阵的 O(n²) 相比，稀疏图下差距悬殊：十万点十万边的图，邻接表只占几 MB，邻接矩阵要 10¹⁰ 个单元。建图时统一把题目常见的 1 基编号减一转成 0 基，把转换集中在读入处，算法内部只认 0 基，这样所有下标运算与哨兵约定才不会互相打架。

还有一个工程细节：vec![Vec::new(); n] 会做 n 次堆分配，内层向量各自增长。若事先知道边数上界，可用 Vec::with_capacity 预分配每个内层，减少扩容搬移；若边数到百万级，则应换成扁平的前向星（一个 to 数组加 head/next），用空间局部性换缓存命中。对本章的算法演示，邻接表的可读性更重要。读边时若出现自环或重边，要确认题目语义：BFS/DFS 天然容忍它们，Dijkstra 也正确（只是多几次松弛），但 Bellman-Ford 的负环判定会被自环影响——负权自环本身就是负环。

读入阶段的另一个常见问题是"点编号不连续"或"编号从 1 到 n 但数据里有 0"，这类脏数据会在建表时直接越界 panic，比算法错更容易定位：错误往往发生在 g[u].push(v) 而不是在最短路循环里。若数据来自文件或网络，建议读入后立刻做一次断言 assert!(u < n && v < n)，把问题拦在最靠近源头的位置。若事先能统计出每个点的度数，还可先把边读进临时向量、统计度数后用 Vec::with_capacity 预分配邻接表，再二次扫描填入；在边数上万时能省下多次扩容搬移。程序其余部分不应该再关心输入是 0 基还是 1 基，这个约定只在读入这一处完成转换。

大白话先用直觉把它讲通

图就是城市加道路。邻接表相当于给每个城市记一张"从这儿能直接去哪"的清单。无向路双向登记，有向单行道只登记一个方向。编号统一从 0 开始，就像门牌号从 0 排起，省掉到处减一的麻烦。

23.2 BFS 的队列不变式：入队即定距

BFS 用 VecDeque 当队列，按"离源点的边数"一层层向外推进。它的核心不变式是：队列里的点始终按距离非递减排列，且每个点的 dist 在入队那一刻就已确定。写法上，dist[v] == -1 表示未访问；弹出 u 后遍历邻居，只在 dist[v] == -1 时设置 dist[v] = dist[u] + 1 并 push。若等到出队才标记，同一层的多个点都指向 v 时 v 会被重复入队，队列长度从 O(n) 膨胀到 O(m)，复杂度退化。

正确性是归纳式的：源点距离 0 正确；假设队列中距离 ≤ d 的点都已按层处理完，那么从距离 d 的点松弛出的邻居距离 d+1，被追加到队尾，队列仍有序。因为每条边只在u 出队时被检查一次，且所有更短的路径会先被处理，第一次赋给 v 的距离必是最短边数。这就是无权图上 BFS 给出最短路的原因。对不连通图，必须对每个未访问点再跑一次 BFS，才能覆盖全部连通块。

BFS 的遍历顺序还带来一个附带好处：在无向图上从 src 出发，第一次访问某点 v 时经过的边恰好是广度优先生成树的一条边，dist[v] 就是树上的深度。若题目要求"字典序最小的路径"，只要把邻接表提前排序、并保证队列先进先出，就能得到按字典序最小的那条最短路径；若要求路径本身，只需再加一个 pre[v] = u 数组，访问到终点后沿 pre 回溯。注意 dist 用 i32 是刻意选择：−1 同时充当"未访问"标记，省掉一个等长的布尔数组；若改用 usize，就必须另开 visited，且不能写 dist[u] - 1 这类式子，因为 usize 下溢会 panic。BFS 的空间峰值出现在被展开的那一层，最坏 O(n)，VecDeque 的容量可用 with_capacity(n) 一次到位。

rustRust · 标准库94 行
use std::collections::VecDeque;
fn build_undirected(n: usize, edges: &[(usize, usize)]) -> Vec<Vec<usize>> {
let mut g = vec![Vec::new(); n];
for &(u, v) in edges {
g[u].push(v);
g[v].push(u);
}
g
}
fn bfs(g: &[Vec<usize>], src: usize) -> Vec<i32> {
let mut dist = vec![-1i32; g.len()];
let mut q = VecDeque::new();
dist[src] = 0;
q.push_back(src);
while let Some(u) = q.pop_front() {
for &v in &g[u] {
if dist[v] == -1 {
dist[v] = dist[u] + 1;
q.push_back(v);
}
}
}
dist
}
// 三色 DFS：0 未访问，1 在栈中（灰），2 已完成（黑）
fn dfs_colors(g: &[Vec<usize>], src: usize) -> (Vec<usize>, Vec<usize>, usize) {
let n = g.len();
let mut color = vec![0u8; n];
let mut enter = vec![0usize; n];
let mut finish = Vec::with_capacity(n);
let mut st: Vec<(usize, usize)> = vec![(src, 0)];
color[src] = 1;
let mut timer = 0usize;
let mut back_edges = 0usize;
while let Some((u, idx)) = st.last_mut() {
let (u, idx) = (*u, *idx);
if idx < g[u].len() {
st.last_mut().unwrap().1 += 1;
let v = g[u][idx];
match color[v] {
0 => {
color[v] = 1;
enter[v] = timer;
timer += 1;
st.push((v, 0));
}
1 => back_edges += 1, // 指向灰点 = 回边
_ => {}
}
} else {
color[u] = 2;
finish.push(u);
st.pop();
}
}
(enter, finish, back_edges)
}
fn components(g: &[Vec<usize>]) -> usize {
let n = g.len();
let mut seen = vec![false; n];
let mut cnt = 0usize;
for s in 0..n {
if seen[s] {
continue;
}
cnt += 1;
seen[s] = true;
let mut st = vec![s];
while let Some(u) = st.pop() {
for &v in &g[u] {
if !seen[v] {
seen[v] = true;
st.push(v);
}
}
}
}
cnt
}
fn main() {
let edges = [(0usize, 1usize), (0, 2), (1, 3), (2, 3), (3, 4), (5, 6)];
let g = build_undirected(7, &edges);
println!("bfs = {:?}", bfs(&g, 0));
let (enter, finish, back) = dfs_colors(&g, 0);
println!("enter = {:?}", enter);
println!("finish= {:?}", finish);
println!("back = {}", back);
println!("comps = {}", components(&g));
}

样例里 5、6 两点与源点 0 不连通，BFS 距离是 −1；components 返回 2，两者相互印证。dist 用 i32 而不是 usize，就是为了让 −1 充当"未访问"哨兵，避免额外的布尔数组。

23.3 迭代 DFS 的三色标记：回边、完成序与连通块

递归 DFS 在大图上会爆栈，所以这里用显式栈模拟。难点是递归版在"进入 u"和"退出 u"两个时机都有动作，单纯压入点号丢失了退出时机。解决办法是压入帧 (u, next_child_index)：帧在栈顶时，next_child_index 指向尚未检查的邻居；全部检查完才弹出，弹出那一刻就是"退出 u"。三色标记 color 让状态显式：白（0）未访问，灰（1）在栈中，黑（2）已完成。遇到白点就染灰入栈；遇到灰点说明存在回边（在有向图里是环路信号）；遇到黑点则忽略。

enter 记录首次进入时间，finish 按弹出的先后顺序记录完成时间。它们在高级图论里是 Tarjan 算法的基础：第 24 单元的低链接值就建立在这套"进入/完成"框架上。components 用最简单的栈加布尔数组，对每个未访问点启动一次 DFS；它统计的是无向图的连通块数。

坑这里最容易踩

坑：无向图里"指向灰点的边"会把父子边各算一次，因此 back 的计数不是环的个数——样例中 5 条树边被计成 5 条回边。若真要判断无向图有环，应跳过父边再判断灰点；若要判断有向图有环，则灰点判定是准确的。不要把一个算法的计数语义直接套到另一种图上。

复杂度与 BFS 相同：O(n+m) 时间、O(n) 辅助空间。color 用 u8 而非 bool 三元组，省空间且 match 一目了然。帧里的下标用 usize，st.last_mut().unwrap().1 += 1 先把下标推进再处理邻居，避免重复检查同一个邻居；这是显式 DFS 与递归版在语义上等价的关键。若邻接表用 [Vec<usize>] 切片传入，函数不取得所有权，调用方能重复使用同一张图做多种遍历。

完成序 finish 的用途远不止计数：对有向无环图，把 finish 倒过来就是合法的拓扑序；对一般有向图，按完成序逆序处理多个起点，正是 Kosaraju 求强连通分量的第一步。这与第 24 单元的 Tarjan 算法形成对照——Tarjan 只需一遍 DFS 加低链接值，Kosaraju 需要两遍但思路更直观。三色数组在这里只是 u8，每个点 1 字节；帧 (usize, usize) 占 16 字节，最坏 n 帧，对十万节点约 1.6 MB，远小于调用栈溢出的代价。若邻接表的某个点度数极大（星形图中心），帧的栈深仍只有 O(n)，因为帧数等于当前路径长度而非已访问点数——这是帧式 DFS 与"把所有邻居一股脑压栈"写法的关键区别。

23.4 Dijkstra：最小堆、过期项与贪心正确性

Dijkstra 解决非负权图的单源最短路。它维护一个已确定最短路的点集：每次从"尚未确定"的点里取当前 dist 最小的 u，则 dist[u] 已是最终答案，再用 u 松弛所有出边。贪心的正确性依赖非负权：若存在从某个未确定点 v 到 u 的更短路径，那条路径的最后一条边权重非负，则路径上倒数第二个点的距离不会大于 dist[u]，它应当先于 u 被取出，矛盾。一旦所有权都为非负，这个"距离一旦确定就不会再变小"的不变量就成立。

标准库 BinaryHeap 是最大堆，套一层 std::cmp::Reverse<(i64, usize)> 就变成最小堆；元组第二维放点号，距离相同时按点号比较，行为确定可复现。同一个点可能因多次松弛被压入堆，弹出旧记录时它的 d 已大于 dist[u]，必须 continue 跳过——称为"过期堆项"。用 visited 数组代替跳过看似可行，但那要在压堆前排除重复项，代码更绕；惰性丢弃是更简洁的常态写法。

rustRust · 标准库37 行
use std::cmp::Reverse;
use std::collections::BinaryHeap;
fn dijkstra(n: usize, edges: &[(usize, usize, i64)], src: usize) -> Vec<i64> {
let mut g = vec![Vec::<(usize, i64)>::new(); n];
for &(u, v, w) in edges {
g[u].push((v, w));
}
let inf = i64::MAX / 4;
let mut dist = vec![inf; n];
let mut pq: BinaryHeap<Reverse<(i64, usize)>> = BinaryHeap::new();
dist[src] = 0;
pq.push(Reverse((0, src)));
while let Some(Reverse((d, u))) = pq.pop() {
if d > dist[u] {
continue; // 过期记录
}
for &(v, w) in &g[u] {
let nd = d + w;
if nd < dist[v] {
dist[v] = nd;
pq.push(Reverse((nd, v)));
}
}
}
dist
}
fn main() {
let edges = [
(0usize, 1usize, 4i64), (0, 2, 1), (2, 1, 2),
(1, 3, 5), (2, 3, 8), (3, 4, 3),
];
let d = dijkstra(5, &edges, 0);
println!("dist = {:?}", d);
println!("as_i64 = {:?}", d.iter().map(|&x| if x == i64::MAX / 4 { -1 } else { x }).collect::<Vec<_>>());
}

手验：0→2→1 的长度是 1+2=3，优于直连的 4；0→2→1→3 是 8，优于 0→2→3 的 9；再到 4 是 11。复杂度 O((n+m) log n)，堆里最多积累 O(m) 条记录，空间 O(n+m)。无穷大取 i64::MAX / 4，给 d + w 留足余量；若权值总和可能逼近 2⁶²，就必须换更大类型或做溢出检查。边权全为 1 时 BFS 更快，别无脑上堆。

如果还需要输出具体路径，可以在松弛成功时同步更新 pre[v] = u，终点确定后沿 pre 回溯到源再反转；pre 数组与 dist 等长，空间 O(n)，不影响主流程。堆中元组的第二维取点号，除了让比较确定，还避免了 Reverse<(i64, usize)> 在距离相等时比较不可比较类型的编译错误——元组字典序要求每一维都实现 Ord，usize 天然满足。若图很稠密（m 接近 n²），堆操作次数接近 m，此时 O((n+m) log n) 反而不如朴素 O(n²) 的"每次线性扫描找最小 dist"版本；n 只有几百时后者常数更小。这些取舍都不影响正确性，却直接决定了算法在大数据上的可用性，值得在写模板时就固化下来，而不是每次现场权衡。工程上还应考虑用 BinaryHeap::with_capacity(m) 预分配，避免堆在增长过程中反复搬移元素；这对百万边图是可见的收益。

23.5 Bellman-Ford：n−1 轮松弛与负环判定

Bellman-Ford 不依赖贪心，而是对全部边做 n−1 轮"松弛"：若经边 u→v 能让 dist[v] 变小就更新。它的不变式是：第 k 轮结束后，dist[v] 不超过所有"至多用 k 条边"的路径长度。归纳显然——k=0 只有源点为 0；第 k 轮用第 k−1 轮的结论再走一条边，覆盖所有 k 边路径。任意最短路在不含环时可化简为至多 n−1 条边（含环只会更长，除非有负环），所以 n−1 轮后 dist 就是最短路。

若 n−1 轮后仍能松弛，说明存在从源可达的负环：沿环每走一圈距离就再降一点，最短路不存在。代码中额外做一轮扫描，若发现可松弛就返回 None。n.saturating_sub(1) 避免 n=0 时 usize 下溢；实际 n≥1，但写成 saturating 更稳妥。加了 changed 提前退出：若某一轮没有任何更新，后续轮次也不会有，直接结束。

大白话先用直觉把它讲通

Dijkstra 像每次挑最近的未定城市确定下来，只在路费不为负时靠谱，因为"最近的"不会突然变近。Bellman-Ford 不挑，它把全部道路反复扫 n−1 遍，每遍都问"借道这条路能不能更近"。扫完还能更近，说明路上藏着一个能无限刷低费用的负环，题目就无解了。

rustRust · 标准库39 行
fn bellman_ford(n: usize, edges: &[(usize, usize, i64)], src: usize) -> Option<Vec<i64>> {
let inf = i64::MAX / 4;
let mut dist = vec![inf; n];
dist[src] = 0;
for round in 0..n.saturating_sub(1) {
let mut changed = false;
for &(u, v, w) in edges {
if dist[u] == inf {
continue;
}
if dist[v] > dist[u] + w {
dist[v] = dist[u] + w;
changed = true;
}
}
if !changed {
println!("early stop at round {}", round + 1);
break;
}
}
for &(u, v, w) in edges {
if dist[u] != inf && dist[v] > dist[u] + w {
return None; // 仍可松弛 => 存在从源可达的负环
}
}
Some(dist)
}
fn main() {
let good = [
(0usize, 1usize, 4i64), (0, 2, 5), (1, 3, -2),
(2, 3, 1), (3, 4, 3),
];
let bad = [
(0usize, 1usize, 1i64), (1, 2, -3), (2, 1, 1), (2, 3, 2),
];
println!("good = {:?}", bellman_ford(5, &good, 0));
println!("bad = {:?}", bellman_ford(4, &bad, 0));
}

bad = None

注意负环判定的措辞："从源可达"。若图中某处有负环但从 src 走不到它，Bellman-Ford 从 src 出发永远松弛不到那条边，应当返回正常距离；而全源的 Floyd 会报告存在负环。这不是算法 bug，而是两者判定范围不同——23.7 的对拍正是踩到这个细节后才修正了裁判逻辑。复杂度 O(n·m)，n=10⁵、m=10⁵ 时约 10¹⁰ 次松弛，不可接受；它的价值在于能处理负权，以及作为小规模对拍的"慢但可靠"裁判。

Bellman-Ford 的队列优化版俗称 SPFA：只把本轮距离变小的点放入队列，避免扫描所有边。它在随机数据上通常很快，但最坏复杂度仍是 O(n·m)，某些精心构造的数据能让它退化得比朴素版本更慢，因此不推荐作为唯一实现。判断用 SPFA 还是朴素版，取决于数据是否有负权、规模多大：n、m 都在几千以内时朴素版足够，代码也更容易证明正确。changed 提前退出不影响正确性：若某一轮没有任何距离更新，由归纳可知下一轮也不会有，此时 dist 已满足所有边的不等式，即已收敛。不可达点的处理是"跳过 dist[u] == INF 的边"，这不是优化而是必需——否则 INF + w 会溢出成一个看似有限的值，把不可达点错误地松弛进结果。

23.6 0-1 BFS 与差分约束：特殊权值的两个变体

当所有边权只取 0 或 1 时，可以甩掉堆：用双端队列，松弛成功且权为 0 就 push_front，权为 1 就 push_back。不变式是队中点的距离至多相差 1、且按非递减排列；权 0 的边把点放到队首，保证它先于所有距离更大的点被处理。这是 Dijkstra 在特殊权值下的退化，复杂度从 O(m log n) 降到 O(m)。若权取任意小整数且最大权为 W，可推广成"桶队列"（Dial 算法），复杂度 O(m + nW)。

坑这里最容易踩

坑：0-1 BFS 里不要写 if dist[u]+w < dist[v] 之前先判断 dist[u] == INF。虽然从 src 出发入队的点都有有限距离，但如果把不可达点也压进队列或忘记初始化，就会拿 INF + 1 做加法。保险做法是入队前显式跳过 dist[u] == INF，或者像示例一样只从 src 开始扩散。

差分约束把形如 x[v] ≤ x[u] + w 的一组不等式转成图：每条约束是一条 u→v、权 w 的有向边。跑 Bellman-Ford（或加超级源 0 连向所有点，保证可达）得到的一组 dist 就满足全部约束，因为最短路性质天然保证 dist[v] ≤ dist[u] + w。若存在负环，约束无解。注意样例中第二条约束写成 (2,1,-1)，表示 x[1] ≤ x[2] − 1，与第一条共同给出 x[2] ≤ x[1]+3 的可行区间；超级源的边权取 0，只是把解整体平移到非正，不影响可行性。

use std::collections::VecDeque;
// 0-1 BFS：边权仅为 0 或 1，用双端队列替代堆
fn zero_one_bfs(n: usize, edges: &[(usize, usize, i64)], src: usize) -> Vec<i64> {
let mut g = vec![Vec::<(usize, i64)>::new(); n];
for &(u, v, w) in edges {
g[u].push((v, w));
}
let inf = i64::MAX / 4;
let mut dist = vec![inf; n];
let mut dq = VecDeque::new();
dist[src] = 0;
dq.push_front(src);
while let Some(u) = dq.pop_front() {
for &(v, w) in &g[u] {
if dist[u] + w < dist[v] {
dist[v] = dist[u] + w;
if w == 0 {
dq.push_front(v);
} else {
dq.push_back(v);
}
}
}
}
dist
}
// 差分约束：x[v] <= x[u] + w 建模成边 u -> v 权 w，求一组可行解
fn difference_constraints(n: usize, cons: &[(usize, usize, i64)]) -> Option<Vec<i64>> {
let mut edges = vec![(0usize, 0usize, 0i64)];
for i in 1..n {
edges.push((0, i, 0)); // 超级源保证所有点可达
}
edges.extend_from_slice(cons);
let inf = i64::MAX / 4;
let mut x = vec![inf; n];
x[0] = 0;
for _ in 0..n {
let mut changed = false;
for &(u, v, w) in &edges {
if x[u] != inf && x[v] > x[u] + w {
x[v] = x[u] + w;
changed = true;
}
}
if !changed {
break;
}
}
for &(u, v, w) in &edges {
if x[u] != inf && x[v] > x[u] + w {
return None; // 约束无解
}
}
Some(x)
}

let edges = [
(0usize, 1usize, 0i64), (1, 2, 1), (0, 2, 1), (2, 3, 0), (1, 3, 1),
];
println!("zero_one = {:?}", zero_one_bfs(4, &edges, 0));
// x2 <= x1 + 3, x1 <= x2 - 1, x3 <= x2 + 2
let cons = [(1usize, 2usize, 3i64), (2, 1, -1), (2, 3, 2)];
println!("feasible = {:?}", difference_constraints(4, &cons));
println!("infeasible = {:?}", difference_constraints(2, &[(0usize, 1usize, -1i64), (1, 0, -1)]));

feasible 给出的解满足 x[2] ≤ x[1]+3（0 ≤ −1+3），也满足 x[1] ≤ x[2]−1（−1 ≤ 0−1）；差分约束的解不唯一，任何满足不等式的向量都对，对拍时应验证约束而非逐位比对某个"标准解"。

差分约束的建模方向极易写反：x[v] ≤ x[u] + w 对应的是 u→v 的边，因为最短路的三角不等式恰好形如 dist[v] ≤ dist[u] + w(u,v)。若题目给的是 x[v] − x[u] ≥ c，先改写成 x[u] ≤ x[v] + (−c)，对应 v→u、权 −c 的边；方向错了会得到完全错误的可行域。超级源的边权取 0 意味着"所有变量都不超过 0"，这只是把解整体向下平移，不影响任何差值约束——若题目额外要求某变量的最小值，可在约束里加一条 x[0] ≤ x[t] + (−L) 来固定下界。最后要注意，Bellman-Ford 给出的是满足全部约束的某个解；若还要求最大化或最小化某个变量，需要在图里做变换后再跑最短路，这已超出本单元范围。

23.7 随机对拍：Floyd 当裁判，四类实现互证

最短路的正确性依赖多种边界，单靠样例不够。这里用 std-only 的 xorshift 生成器造 2000 张 n∈[2,8] 的有向图，边数最多 11，再用 Floyd-Warshall（O(n³)，实现几乎显然）当裁判，分四类互证：非负权下 Dijkstra 与 Bellman-Ford 对 Floyd；全 1 权下 BFS 与 Dijkstra 对 Floyd；0/1 权下 0-1 BFS 对 Dijkstra；含负权下 Bellman-Ford 对 Floyd，并额外核对负环判定。不可达统一用 INF = i64::MAX/4 表示，BFS 则用 −1。

一个真实的坑：Floyd 一旦发现任意位置的负环就没法给出有意义的距离矩阵，而 Bellman-Ford 只关心从源可达的负环。初版对拍直接比较"Floyd 说有负环"和"BF 说有负环"，在小图上出现了约 100 次假阳性。修正方法是：先 BFS 求出 src 的可达集，只有当某点 i 可达且 f[i][i] < 0 时，才要求 BF 返回 None；否则要求两者距离一致。修正后 2000 张图中 401 张含可达负环，全部判定一致。

随机图的形状也影响覆盖度：边数 m 在 0..12 之间随机，既有大量孤立点也有较稠密的连通块；n 限制在 8 以内，是因为 Floyd 的 O(n³) 在更大图上会成为对拍本身的瓶颈，而小图上最短路的分支（自环被跳过、平行边、多个最短路、不可达）已经足够丰富。源点也随机选取，避免总是从 0 出发而漏掉"源在环外"的情形。若要把对拍扩展到更大的图，可把裁判换成"小规模 Bellman-Ford 对 Dijkstra"而不再用 Floyd，或者把 n 提高后只比较 Dijkstra 与 Bellman-Ford 的结果是否一致——两者前提相同，不需要第三方裁判。无论哪种，固定种子是底线：可复现的失败才是能修的失败。

坑这里最容易踩

坑：写对拍时，"两个算法结果不同"未必是被测算法错，也可能是裁判的适用条件没对齐（如此处的负环可达性）。遇到 MISMATCH 先构造最小反例，再问"两边的前提是否相同"，不要急着改主算法。

const INF: i64 = i64::MAX / 4;
struct Rng(u64);
impl Rng {
fn next(&mut self) -> u64 {
let mut x = self.0;
x ^= x << 13;
x ^= x >> 7;
x ^= x << 17;
self.0 = x;
x
}
fn below(&mut self, n: usize) -> usize {
(self.next() % n as u64) as usize
}
}
fn floyd(n: usize, edges: &[(usize, usize, i64)]) -> Vec<Vec<i64>> {
let mut d = vec![vec![INF; n]; n];
for i in 0..n {
d[i][i] = 0;
}
for &(u, v, w) in edges {
d[u][v] = d[u][v].min(w);
}
for k in 0..n {
for i in 0..n {
if d[i][k] == INF { continue; }
for j in 0..n {
if d[k][j] != INF && d[i][j] > d[i][k] + d[k][j] {
d[i][j] = d[i][k] + d[k][j];
}
}
}
}
d
}
fn reachable(n: usize, edges: &[(usize, usize, i64)], src: usize) -> Vec<bool> {
use std::collections::VecDeque;
let mut g = vec![Vec::<usize>::new(); n];
for &(u, v, _) in edges { g[u].push(v); }
let mut seen = vec![false; n];
let mut q = VecDeque::new();
seen[src] = true;
q.push_back(src);
while let Some(u) = q.pop_front() {
for &v in &g[u] {
if !seen[v] { seen[v] = true; q.push_back(v); }
}
}
seen
}
fn dijkstra(n: usize, edges: &[(usize, usize, i64)], src: usize) -> Vec<i64> {
use std::cmp::Reverse;
use std::collections::BinaryHeap;
let mut g = vec![Vec::<(usize, i64)>::new(); n];
for &(u, v, w) in edges { g[u].push((v, w)); }
let mut dist = vec![INF; n];
let mut pq = BinaryHeap::new();
dist[src] = 0;
pq.push(Reverse((0i64, src)));
while let Some(Reverse((d, u))) = pq.pop() {
if d > dist[u] { continue; }
for &(v, w) in &g[u] {
if d + w < dist[v] {
dist[v] = d + w;
pq.push(Reverse((d + w, v)));
}
}
}
dist
}
fn bellman_ford(n: usize, edges: &[(usize, usize, i64)], src: usize) -> Option<Vec<i64>> {
let mut dist = vec![INF; n];
dist[src] = 0;
for _ in 0..n.saturating_sub(1) {
for &(u, v, w) in edges {
if dist[u] != INF && dist[v] > dist[u] + w { dist[v] = dist[u] + w; }
}
}
for &(u, v, w) in edges {
if dist[u] != INF && dist[v] > dist[u] + w { return None; }
}
Some(dist)
}
fn bfs_unit(n: usize, edges: &[(usize, usize, i64)], src: usize) -> Vec<i32> {
use std::collections::VecDeque;
let mut g = vec![Vec::<usize>::new(); n];
for &(u, v, _) in edges { g[u].push(v); }
let mut d = vec![-1i32; n];
let mut q = VecDeque::new();
d[src] = 0;
q.push_back(src);
while let Some(u) = q.pop_front() {
for &v in &g[u] {
if d[v] == -1 { d[v] = d[u] + 1; q.push_back(v); }
}
}
d
}
fn zero_one(n: usize, edges: &[(usize, usize, i64)], src: usize) -> Vec<i64> {
use std::collections::VecDeque;
let mut g = vec![Vec::<(usize, i64)>::new(); n];
for &(u, v, w) in edges { g[u].push((v, w)); }
let mut dist = vec![INF; n];
let mut dq = VecDeque::new();
dist[src] = 0;
dq.push_front(src);
while let Some(u) = dq.pop_front() {
for &(v, w) in &g[u] {
if dist[u] + w < dist[v] {
dist[v] = dist[u] + w;
if w == 0 { dq.push_front(v); } else { dq.push_back(v); }
}
}
}
dist
}

23.8 工程取舍：无穷大、溢出与算法选择

选算法先看权值：无权用 BFS；权为 0/1 用 0-1 BFS；一般非负权用 Dijkstra；有负权用 Bellman-Ford（或 SPFA，但最坏复杂度相同且常数不稳定）。全源最短路若 n 不过几百，Floyd 的三重循环最省心；更大规模则跑 n 次 Dijkstra。信息不确定时，优先写"慢但显然对"的版本，再用随机对拍守住正确性，最后按数据规模替换实现。

INF 的取值是常见 bug 源。取 i64::MAX / 4 给加法留余量，但松弛前仍要判断 dist[u] == INF 跳过，否则 INF + w 可能越过边界。若边权可负，"更大"的 INF 不是问题，关键是别把真的最短路误判成 INF：路径长度上界必须远小于 INF。输出时按题目要求把 INF 转成 −1 或忽略，别把 i64 的大数直接打印出去。空间上，Dijkstra 的堆会积累 O(m) 条记录，BinaryHeap 预分配可用 BinaryHeap::with_capacity(m) 减少扩容。

算法之间还可以组合：先用 BFS 判断连通性，只在含源点的连通块里跑 Dijkstra，能把不连通图的无用工作剪掉；先跑一遍 Bellman-Ford 检测负环，确认无解后就不必再调 Dijkstra。Rust 的类型系统在这里也帮得上忙：把"可能无解"的结果编码成 Option<Vec<i64>>，调用方必须显式处理 None，就不会把"存在负环"误当成某个巨大的距离继续参与计算。反过来，若把不可达与负环都用同一个 INF 值表示，二者在输出时无法区分，属于典型的信息丢失。多起点问题可以加一个虚拟超级源，连向每个起点、边权取 0，然后跑一次单源算法；这与差分约束里加超级源是同一个技巧，值得一起记牢，遇到多源或不等式组时直接套用。

算法 权值要求 单源复杂度 核心结构 失败信号
BFS 无权 O(n+m) VecDeque dist 仍为 −1 即不可达
0-1 BFS 0 或 1 O(n+m) VecDeque 双端 同上
