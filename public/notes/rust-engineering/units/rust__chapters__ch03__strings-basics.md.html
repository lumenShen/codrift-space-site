28.1 字符串问题的两条主线：比对与索引

字符串算法看似庞杂，拆开只有两件事：比对（两段字符是否相同、最长公共前缀多长）和索引（某个模式在哪里出现、哪些单词共享前缀）。朴素做法是逐字符比较，长度 m 的模式在长度 n 的文本上逐个位置试，最坏 O(n·m)；本节四种工具都通过某种预处理把这个乘积降下来。

理解"预处理换查询"的代价模型很重要。如果只比对一次，预处理的 O(n+m) 反而不如直接的 O(m) 划算；只有当查询次数足够多、或文本固定而模式反复变化时，预处理才摊薄成本。哈希与 Trie 是典型的"建一次、查多次"结构：前者把每次子串比较压成 O(1)，后者把每次前缀查询压成 O(词长)。KMP 与 Z 函数则不同，它们针对"单次全量匹配"就把总时间压到线性，因为匹配过程中每个字符只被有效比对常数次。读题时先数清"建库几次、查询几次、文本换不换"，就能排除掉一半不适用工具。

第一条主线里，哈希把字符串映射成一个定长整数，于是"子串是否相等"变成"两个整数是否相等"，比较从 O(m) 降到 O(1)。代价是引入了极小的碰撞概率，工程中用双模或 128 位自然溢出把概率压到可忽略。KMP 与 Z 函数走的是另一条路：不依赖概率，而是利用模式自身的结构——KMP 记录"失配后能复用多少已匹配前缀"，Z 函数记录"每个后缀与整个串的最长公共前缀"。两者都保证严格的线性时间，区别只在组织方式。

第二条主线里，Trie 把一组字符串的公共前缀合并成树，查询一个词或一批前缀时，沿着字符边走一遍即可，复杂度只与查询词长度有关，与字典大小几乎无关。它是后面 AC 自动机（多模式匹配）的结构基础。

大白话先用直觉把它讲通

暴力比对就像每次都从头念一遍课文。哈希给每段文字盖一个"指纹章"，看两个指纹一样就当文字一样，快但有小概率撞章。KMP 和 Z 函数是"记住上次念到哪儿了"，失配时不从头念，直接从已经念对的地方接着念，绝不撞章。Trie 是把一堆单词按共同开头搭成一棵树，查"app"开头的词时只要走到 app 那个岔路口，不用把每个词都翻出来。

28.2 字符串哈希：前缀哈希与子串等性

问题定义。 给定文本 text 与模式 pat，找出 pat 在 text 中所有出现位置。用哈希可把每次子串比较降到 O(1)，整体 O(n+m)。

机制。 选一个基数 base 与模数 M，把字符串看作 base 进制数：h(s) = ((s[0]·base + s[1])·base + ...) mod M。预处理文本的前缀哈希 h[0..n+1]，其中 h[k] 是前 k 个字符的哈希；同时预处理 pw[k] = base^k mod M。则子串 text[l..r) 的哈希是 h[r] − h[l]·base^(r−l) mod M——因为前缀 r 等于前缀 l 左移 (r−l) 位再拼上子串。这一步是不变量：只要 h 与 pw 的定义一致，减法就精确给出子串的多项式值。

双模防碰撞。 单个 64 位模数下，精心构造的输入可能碰撞。用两个互质大素数（如 10^9+7 与 10^9+9）分别取模，只有当两个模下的哈希都相等才判定相等，碰撞概率降到约 10^-18，竞赛与工程都够用。基数要小于模数且随机取，进一步降低被构造碰撞的风险。

Rust 实现要点。 用 u64 存哈希，乘法前先 % M，因为 base < M 且 h < M，乘积 < 10^18，不会溢出 u64。sub(l, r) 里减法要先加 M 再取模，避免下溢。预处理 pw 与 h 同步推进。比较时把模式的哈希 (hp.sub(0, m)) 算一次，然后在文本上滑窗比对。

还有一个值得讲清的细节：为什么不直接维护"滑动窗口哈希"逐位滚动，而要存全部前缀哈希？滚动更新每次要做 h = (h - s[i]·pw[m-1])·base + s[i+m]，需要窗口内每个字符的值与一次减法，代码更绕；而前缀哈希把任意区间的查询统一成同一个 sub(l, r) 公式，既能查定长模式，也能查任意长度的子串等性（比如最长公共前缀的二分），通用性更好。两种做法时间都是 O(n)，前缀法多用一个长度 n+1 的数组，换来的是查询接口的统一。基数 base 要显著大于字符集大小，否则不同字符串容易算出相同多项式值；取 911382323 这类接近模数的大质数、或在安全区间随机取，都是常见做法。

复杂度。 预处理 O(n+m) 时间与 O(n+m) 空间，查找 O(n)；相比 O(n·m) 的暴力是质变。

下面的程序用双模哈希（基数随机取自 [256, 10^6]）找出所有出现位置，与逐字节比较的朴素版在随机小写串上对照 400 组。

#![allow(dead_code)]
const M1: u64 = 1_000_000_007;
const M2: u64 = 1_000_000_009;
struct DHash {
h1: Vec<u64>, h2: Vec<u64>,
pw1: Vec<u64>, pw2: Vec<u64>,
}
impl DHash {
fn new(s: &[u8], base: u64) -> Self {
let n = s.len();
let (mut h1, mut h2) = (vec![0u64; n + 1], vec![0u64; n + 1]);
let (mut pw1, mut pw2) = (vec![1u64; n + 1], vec![1u64; n + 1]);
for i in 0..n {
h1[i + 1] = (h1[i] * base + s[i] as u64) % M1;
h2[i + 1] = (h2[i] * base + s[i] as u64) % M2;
pw1[i + 1] = pw1[i] * base % M1;
pw2[i + 1] = pw2[i] * base % M2;
}
Self { h1, h2, pw1, pw2 }
}
fn sub(&self, l: usize, r: usize) -> (u64, u64) {
let len = r - l;
let a = (self.h1[r] + M1 - self.pw1[len] * self.h1[l] % M1) % M1;
let b = (self.h2[r] + M2 - self.pw2[len] * self.h2[l] % M2) % M2;
(a, b)
}
}
fn find_all(text: &[u8], pat: &[u8], base: u64) -> Vec<usize> {
let (n, m) = (text.len(), pat.len());
if m == 0 || m > n { return vec![]; }
let ht = DHash::new(text, base);
let hp = DHash::new(pat, base);
let target = hp.sub(0, m);
let mut res = Vec::new();
for i in 0..=n - m {
if ht.sub(i, i + m) == target { res.push(i); }
}
res
}
fn naive_all(text: &[u8], pat: &[u8]) -> Vec<usize> {
let (n, m) = (text.len(), pat.len());
if m == 0 || m > n { return vec![]; }
let mut res = Vec::new();
for i in 0..=n - m {
if &text[i..i + m] == pat { res.push(i); }
}
res
}
struct Rng(u64);
impl Rng {
fn next_u64(&mut self) -> u64 { let mut x = self.0; x ^= x << 13; x ^= x >> 7; x ^= x << 17; self.0 = x; x }
fn range(&mut self, lo: u64, hi: u64) -> u64 { lo + self.next_u64() % (hi - lo + 1) }
}
fn main() {
let text = b"ababababa";
let pat = b"aba";
println!("demo hash find = {:?}", find_all(text, pat, 911382323));
let mut rng = Rng(0x1234_5678_9abc_def0);
let mut bad = 0;
for _ in 0..400 {
let n = 1 + rng.range(0, 200) as usize;
let m = 1 + rng.range(0, 20) as usize;
let t: Vec<u8> = (0..n).map(|_| b'a' + rng.range(0, 4) as u8).collect();
let p: Vec<u8> = (0..m).map(|_| b'a' + rng.range(0, 4) as u8).collect();
let base = 256 + rng.range(0, 1_000_000) as u64;
let a = find_all(&t, &p, base);
let b = naive_all(&t, &p);
if a != b { bad += 1; break; }
}
println!("stress hash: {} (400 random cases)", if bad == 0 { "OK" } else { "FAIL" });
}

哈希的软肋是碰撞：本单元用双模把概率压到可忽略，但仍不是严格算法。在需要绝对正确性的场景（如密码学、判定性答案），要么改用 KMP/Z 函数，要么在哈希命中后再做一次逐字节确认——命中数通常很少，这一步几乎不增加成本。另一个陷阱是空串与模式长于文本：m == 0 或 m > n 时减法下标会越界，必须先返回。

28.3 KMP：前缀函数与失败跳转

问题定义。 同样是在 text 中找 pat 的所有出现位置，但要求严格线性且无概率。KMP 的核心是：匹配过程中文本指针 i 永不回退，只回退模式指针 j。

前缀函数。 定义 pi[i] 为 pat[0..=i] 的最长真前缀长度，使它同时也是该子串的后缀。例如 ababaca 的 pi 是 [0,0,1,2,3,0,1]。pi 的不变量是：pat[0..pi[i]] == pat[i+1-pi[i] ..= i]，即"以 i 结尾的后缀里，能与开头对齐的最长长度"。计算 pi 本身也是 KMP 式的：用前一个位置的 pi[i−1] 作为候选 j，若 pat[i] 与 pat[j] 不等，就沿 j = pi[j−1] 回退，直到匹配或 j=0。

匹配过程。 用 j 表示当前已匹配的 pat 前缀长度。每读入一个 text[i]：若 text[i] == pat[j]，j 加一；否则沿 pi 回退 j（文本指针不动）。当 j == pat.len() 时记录一次匹配，起点是 i+1−j，然后把 j 设为 pi[j−1] 以寻找下一次匹配。这里的精妙之处在于：失配时 we already know 前 j 个字符都匹配，而 pi[j−1] 告诉我们其中有多大一段同时也是 pat 的前缀，这段无需重新比对——这就是"失败跳转"节省的时间。

正确性。 文本指针单调右移，j 的每次回退都严格减小，摊还后总操作数 O(n+m)。回退之所以安全，是因为 pi[j−1] 保证了被复用的那段确实是 pat 的前缀，与 text 中对应位置一定相等。摊还分析可以这样做：把 j 看作一个"势能"，每读入一个文本字符，j 最多增加 1，所以整个过程中 j 的总增量不超过 n；而每次回退都让 j 至少减少 1，因此回退的总次数不超过总增量，也就是不超过 n。匹配成功后的 j = pi[j-1] 同样是一次减小，也计入这个上界。于是 while 循环的总执行次数是 O(n)，加上预处理 pi 的 O(m)，总时间严格线性。这个"势能法"是分析所有带回退指针算法（包括下一节的 Z 函数）的通用工具。

Rust 实现要点。 pat.is_empty() 要先返回，否则访问 pat[j] 会越界。while j > 0 && text[i] != pat[j] 的回退循环用 pi[j-1]，注意 j>0 保证下标合法。完整匹配后用 pi[j-1] 而不是 0，这样才能找到重叠出现（如 aaaa 中找 aa）。

下面的程序先打印 ababaca 的 pi 与一个示例匹配结果，再对随机串做 500 组与朴素法的对拍。

#![allow(dead_code)]
fn prefix_function(p: &[u8]) -> Vec<usize> {
let mut pi = vec![0usize; p.len()];
for i in 1..p.len() {
let mut j = pi[i - 1];
while j > 0 && p[i] != p[j] { j = pi[j - 1]; }
if p[i] == p[j] { j += 1; }
pi[i] = j;
}
pi
}
fn kmp(text: &[u8], pat: &[u8]) -> Vec<usize> {
if pat.is_empty() { return vec![]; }
let pi = prefix_function(pat);
let mut res = Vec::new();
let mut j = 0usize;
for i in 0..text.len() {
while j > 0 && text[i] != pat[j] { j = pi[j - 1]; }
if text[i] == pat[j] { j += 1; }
if j == pat.len() {
res.push(i + 1 - j);
j = pi[j - 1];
}
}
res
}
fn naive(text: &[u8], pat: &[u8]) -> Vec<usize> {
let (n, m) = (text.len(), pat.len());
if m == 0 || m > n { return vec![]; }
let mut res = Vec::new();
for i in 0..=n - m { if &text[i..i + m] == pat { res.push(i); } }
res
}

KMP 的难点从来不是代码而是 pi 的含义。一个有效的自检方式是打印 pi 数组，逐位核对 pat[0..pi[i]] 是否等于 pat[i+1-pi[i]..=i]。若你发现匹配结果漏掉了重叠出现，八成是完整匹配后把 j 直接清零了——改成 pi[j-1] 即可。

28.4 Z 函数：把模式匹配变成数组比对

问题定义与定义。 对字符串 s，z[i] 是 s 与后缀 s[i..] 的最长公共前缀（LCP）长度，约定 z[0] = 0。有了 Z 数组，模式匹配只需构造 pat + 分隔符 + text，在拼接串上求 z，凡是 z[i] ≥ pat.len() 的位置 i 就对应一次匹配，起点为 i − m − 1。分隔符必须是模式与文本字符集中不出现的值，否则会跨越边界误匹配。

线性求解机制。 维护当前已知的最右匹配区间 [l, r]。处理 i 时：若 i ≤ r，则 s[i..] 与 s[i−l..] 处在同一个已匹配盒子里，可先取 z[i] = min(r−i+1, z[i−l]) 作为下界（盒子内的对齐部分必定相等），再从下界继续向后暴力扩展；若 i > r，则从 0 开始扩展。每次扩展成功后更新 [l, r] = [i, i+z[i]−1]。关键不变量是：盒内 z 值可直接复用，因为盒子保证 s[l..=r] == s[0..=r−l]，于是 s[i+k] == s[i−l+k] 对盒内所有 k 成立。

与 KMP 的对比。 KMP 的前缀函数描述"模式每个前缀的自我重复"，Z 函数描述"整个串与每个后缀的公共前缀"。Z 函数更直观、代码更短，适合单模式匹配与回文相关变换；KMP 的 pi 在自动机、周期判定等场景更自然，且不需要拼接串与分隔符。两者都是严格 O(n+m)。从信息量看，Z 数组比 pi 数组更"全局"：pi 是模式内部的前后缀关系，Z 是整串对每个后缀的关系，Z[i] 的值域可能远超 pi[i]。因此 Z 函数还能直接回答"从第 i 位开始与原串相同多长"这类查询，而 pi 只能回答"前缀的重复长度"。若你要处理的是字符串周期、最小表示、回文半径等问题，Z 数组往往是更趁手的中间产物；若要做状态机式的逐字符扫描（比如把 KMP 扩展成 AC 自动机），pi 的失败链语义则不可替代。

Rust 实现要点。 z[i] = (r−i+1).min(z[i−l]) 只在 i ≤ r 时成立；扩展循环 while i+z[i] < n && s[z[i]] == s[i+z[i]] 用下标 z[i] 同时索引前缀与后缀。更新盒子前要判断 z[i] > 0，否则 i + z[i] − 1 在 i=0 时会下溢——虽然循环从 i=1 起，但写成显式判断更稳妥。

下面的程序对 aaaa 打印 z 数组（应为 [0,3,2,1]），对 ababababa 找 aba 给出匹配位置，再对随机串把 Z 数组与逐字符朴素版对照 400 组。

#![allow(dead_code)]
fn z_function(s: &[u8]) -> Vec<usize> {
let n = s.len();
let mut z = vec![0usize; n];
let (mut l, mut r) = (0usize, 0usize);
for i in 1..n {
if i <= r { z[i] = (r - i + 1).min(z[i - l]); }
while i + z[i] < n && s[z[i]] == s[i + z[i]] { z[i] += 1; }
if z[i] > 0 && i + z[i] - 1 > r {
l = i; r = i + z[i] - 1;
}
}
z
}
fn naive_z(s: &[u8]) -> Vec<usize> {
let n = s.len();
let mut z = vec![0usize; n];
for i in 1..n {
let mut k = 0;
while i + k < n && s[k] == s[i + k] { k += 1; }
z[i] = k;
}
z
}
fn z_find(text: &[u8], pat: &[u8]) -> Vec<usize> {
if pat.is_empty() { return vec![]; }
let mut s = Vec::with_capacity(pat.len() + 1 + text.len());
s.extend_from_slice(pat);
s.push(1u8);
s.extend_from_slice(text);
let z = z_function(&s);
let m = pat.len();
let mut res = Vec::new();
for i in m + 1..s.len() {
if z[i] >= m { res.push(i - m - 1); }
}
res
}

28.5 Trie：前缀共享与批量查询

问题定义。 给定一组字符串（字典），支持插入一个词、查询某词是否在字典中、统计有多少词以某前缀开头。朴素做法每次遍历整个字典，O(字典大小 × 词长)；Trie 把公共前缀合并成树，查询只与查询词长度相关。

结构机制。 每个节点保存一张字符到子节点的映射、一个 end 标志（是否有词在此结束）、一个 pass 计数（有多少词经过此节点）。插入时从根出发，沿字符逐层走，缺边则新建节点，途中 pass 加一，末尾置 end。查询整词就是走到末节点看 end；统计前缀就是走到前缀末节点读 pass。根节点的 pass 等于字典总词数。

不变量与正确性。 不变量是：从根到任意节点的路径恰好拼成某个前缀，且 pass 等于字典中以该前缀开头的词数——插入时每个词给它路径上所有节点（含根）的 pass 加一，正好维护了这个计数。end 标志则区分"前缀"与"完整词"。因此查询只需一次路径遍历，无需扫描字典。

Rust 实现要点。 字符集固定且很小时，用 [usize; 26] 加 NIL = usize::MAX 哨兵比 HashMap 更快也更省内存；插入时 let k = (c - b'a') as usize 直接下标。若字符集是任意字节或 Unicode，改用 Vec<(u8, usize)> 或 HashMap<u8, usize>。三个 Vec（ch、end、pass）按下标对齐表示同一批节点，新建节点时三者同步 push——这是"结构体数组 vs 数组结构体"取舍里典型的 SoA 写法，缓存友好。

复杂度。 插入与查询均为 O(L)，L 是词长；空间 O(总字符数 × 字符集大小)（定长数组实现）或 O(总字符数)（链式实现）。定长数组在 26 字母下每个节点 26×8=208 字节，字典很大时要留意内存。三个平行 Vec 的 SoA（Structure of Arrays）布局在这里很有代表性：访问某节点的第 k 个孩子只需 ch[u][k] 一次索引，而若把 ch、end、pass 塞进同一个 struct Node 放进 Vec<Node>（AoS），单次访问会连带把相邻字段也拉进缓存行，对 Trie 这种随机跳转的访问模式并不更优。两种布局性能接近时，选代码更清晰的那一种即可；真正影响性能的往往是节点数量而非布局。若字典里的词有大量公共前缀（如一棵词库），Trie 的节点数远小于"总字符数"，压缩收益明显；若词彼此毫无前缀重叠，Trie 反而比直接排序后二分更费内存。

下面的程序构造含 app、apple、banana、app 的字典（app 出现两次），随后对随机字典与随机查询词把 Trie 的整词查询、前缀计数与朴素遍历对照 200 组。

#![allow(dead_code)]
const NIL: usize = usize::MAX;
struct Trie {
ch: Vec<[usize; 26]>,
end: Vec<bool>,
pass: Vec<usize>,
}
impl Trie {
fn new() -> Self {
Self { ch: vec![[NIL; 26]], end: vec![false], pass: vec![0] }
}
fn insert(&mut self, w: &[u8]) {
let mut u = 0usize;
self.pass[u] += 1;
for &c in w {
let k = (c - b'a') as usize;
if self.ch[u][k] == NIL {
self.ch[u][k] = self.ch.len();
self.ch.push([NIL; 26]);
self.end.push(false);
self.pass.push(0);
}
u = self.ch[u][k];
self.pass[u] += 1;
}
self.end[u] = true;
}
fn walk(&self, pre: &[u8]) -> Option<usize> {
let mut u = 0usize;
for &c in pre {
let k = (c - b'a') as usize;
u = self.ch[u][k];
if u == NIL { return None; }
}
Some(u)
}
fn contains(&self, w: &[u8]) -> bool {
match self.walk(w) { Some(u) => self.end[u], None => false }
}
fn prefix_count(&self, pre: &[u8]) -> usize {
match self.walk(pre) { Some(u) => self.pass[u], None => 0 }
}
}
struct Rng(u64);
impl Rng {
fn next_u64(&mut self) -> u64 { let mut x = self.0; x ^= x << 13; x ^= x >> 7; x ^= x << 17; self.0 = x; x }
fn range(&mut self, lo: u64, hi: u64) -> u64 { lo + self.next_u64() % (hi - lo + 1) }
}
fn rand_word(rng: &mut Rng) -> Vec<u8> {
let n = 1 + rng.range(0, 6) as usize;
(0..n).map(|_| b'a' + rng.range(0, 3) as u8).collect()
}
fn main() {
let mut trie = Trie::new();
for w in [&b"app"[..], b"apple", b"banana", b"app"] { trie.insert(w); }
println!("demo contains(app)={} contains(apx)={} prefix(app)={}",
trie.contains(b"app"), trie.contains(b"apx"), trie.prefix_count(b"app"));
let mut rng = Rng(0x0bad_f00d_0bad_f00d);
let mut bad = 0;
for _ in 0..200 {
let cnt = 1 + rng.range(0, 40) as usize;
let mut words: Vec<Vec<u8>> = Vec::new();
let mut trie = Trie::new();
for _ in 0..cnt {
let w = rand_word(&mut rng);
trie.insert(&w);
words.push(w);
}
for _ in 0..40 {
let q = rand_word(&mut rng);
let c1 = trie.contains(&q);
let c2 = words.iter().any(|w| w == &q);
let p1 = trie.prefix_count(&q);
let p2 = words.iter().filter(|w| w.starts_with(&q)).count();
if c1 != c2 || p1 != p2 { bad += 1; break; }
}
if bad > 0 { break; }
}
println!("stress trie: {} (200 random dictionaries)", if bad == 0 { "OK" } else { "FAIL" });
}

Trie 的一个语义陷阱：重复插入同一个词时，pass 会累加但 end 仍是 true。本单元把"字典"当多重集处理（app 出现两次，prefix(app)=3），若业务要求集合语义，插入前应先用 contains 去重，或在 end 处记录出现次数而非布尔值。定长 26 数组的实现只覆盖小写字母，遇到大写、数字或 Unicode 必须先做归一化或换用映射结构。

28.6 四种工具的横向对照

四者解决的都是"字符串比对/索引"，但代价模型完全不同。哈希用概率换常数时间，KMP/Z 用确定性的结构复用换线性保证，Trie 用空间换批量查询的前缀共享。

工具 核心预处理 查询/匹配复杂度 是否确定性 适用场景 主要成本
双模哈希 前缀哈希 + 幂表 O(1) 子串等性 否（概率可忽略） 大量子串比较、字符串相等判定 模乘常数、碰撞风险
KMP 前缀函数 pi O(n+m) 匹配 是 单模式匹配、周期判定、自动机 回退逻辑较难调试
Z 函数 Z 数组 O(n+m) 匹配 是 单模式匹配、LCP 批量查询 需分隔符、拼接额外空间
Trie 前缀树 O(L) 每查询 是 词典查询、前缀统计、多模式基础 定长数组空间开销

如何选择：若只需判断两段子串是否相等且能接受极小概率，哈希最简；若要在线性时间内严格找出单模式所有出现，KMP 或 Z 二选一——需要分隔符-free 或要做自动机选 KMP，想要代码短、顺带算 LCP 选 Z；若是一次建库、多次按前缀查询，或要扩展到多模式匹配，选 Trie。注意这四者可以组合：先用哈希快速筛出"可能匹配"的候选位置，再用 KMP 或逐字节确认排除碰撞，是工程里兼顾速度与确定性的常见套路；Trie 的每个节点也可以挂一个哈希值，用来快速判断两条路径是否指向相同的前缀集合。工具之间没有互斥关系，真正的取舍标准是你的查询模式与可接受的出错概率。

大白话先用直觉把它讲通

四种工具其实是四种"记笔记"的方式。哈希是给每段文字盖章，比章快但可能撞章；KMP 是记"这个词自己哪里重复"，失配时跳到重复处；Z 函数是记"整串和每个后缀能对齐多少"，一次算完大家共用；Trie 是把词按开头搭成家谱树，找同开头的词只要走到那个分支。它们之间没有谁全面胜出，看你是要比对、要匹配还是要查前缀。

28.7 碰撞、字符集与工程边界

哈希边界。 双模仍非零碰撞概率，绝对正确性场景要么用确定性算法，要么在哈希命中后追加逐字节确认。基数是随机取的，若输入可能被对抗性构造，固定基数会引入风险。m==0 与 m>n 必须先返回，否则 n-m 在 usize 下下溢。前缀哈希的减法要先加模数再取模，否则 u64 下溢成巨大值。

KMP/Z 边界。 空模式要显式处理：KMP 里访问 pat[j] 会越界，Z 里的拼接串若模式为空则分隔符位置错乱。分隔符必须是文本与模式字符集中不出现的值——ASCII 文本用字节 1 是常见选择，任意字节流则需要更谨慎的编码或改用 KMP。Z 更新盒子时 i+z[i]-1 的减法要求 z[i] > 0。

Trie 边界。 定长 26 数组只适用于小写拉丁字母，其他字符集要先归一化或换 HashMap。空词插入会在根节点置 end，查询空词应返回根节点的 end；前缀计数对不存在的路径返回 0。NIL = usize::MAX 哨兵要保证不会与合法节点下标冲突（节点数远小于 usize::MAX，实际不可能）。

工程取舍。 字符用 &[u8] 而非 String，让算法与编码解耦：UTF-8 下按字节处理对 ASCII 模式是安全的（多字节字符不会与 ASCII 模式字节产生跨字符匹配，因为首字节都在 0x80 以上），但按字符匹配中文时就要先切成 Vec<char> 或按 char_indices 重建字节边界。内存上，Trie 的定长数组每个节点 208 字节，百万节点就是 200MB，字典极大时改用压缩 Trie 或 HashMap<u8, usize>。

坑这里最容易踩

坑：Z 函数匹配时的分隔符不是"随便一个特殊符号"。若你在英文文本上用 pat + "#" + text，而文本里恰好出现 '#'，Z 值可能跨越分隔符，导致把文本内部的一段误判为匹配。正确做法是从字符集里挑一个确定不出现的值（如字节 1），或干脆用不需要分隔符的 KMP。本单元对拍刻意只生成 'a'..'d'，用字节 1 作分隔符才安全。
