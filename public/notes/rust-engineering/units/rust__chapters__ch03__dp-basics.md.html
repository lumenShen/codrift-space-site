26.1 状态定义三要素：范围、目标与阶段

动态规划不是模板，而是"消重"思想：当问题同时具备最优子结构（大局最优由子问题最优组合而来）与重叠子问题（同一子状态被反复用到）时，把每个子状态的答案存进表，就能避免指数级重复计算。写 DP 的第一步永远是定义状态，一句话必须交代三件事：范围（考虑前 i 个元素、区间 [l,r]、还是以 i 结尾）、目标（最大/最小/计数/可行性）、阶段（是否需要额外维度区分决策状态）。"dp[i] 是前 i 家的最大收益"比"dp[i] 是答案"清晰得多，后者无法判断转移是否漏解。

第二步是转移：枚举当前阶段的若干种决策，在它们的结果里取 max/min/求和。每种决策必须对应一条实际可行的构造路径，不能漏也不能重。第三步是初始化与计算顺序：base case 覆盖最小子问题，循环顺序保证"转移时依赖的状态已经算好"。把这三句话写成注释贴在代码上方，是调试 DP 最有效的手段——绝大多数错误都出在状态定义含糊、边界写错、顺序颠倒，而不是转移式本身。

估算复杂度有个简单公式：状态数 × 每状态转移数。线性 DP 是 O(n·k)，背包是 O(n·cap)，区间 DP 是 O(n²·n)=O(n³)。写代码前先用它判断可行性，能省下大量无效调试。Rust 实现常用 Vec<T> 或 Vec<Vec<T>>，下标统一 usize；需要"前一项"时多开一格哨兵，避免 i - 1 在 i=0 时下溢。

大白话先用直觉把它讲通

DP 就是"把算过的答案记在小本本上"。面对大问题先拆成同类小问题，把每种小问题的答案记下来，大问题查小本本再做一次选择就行。关键是每条记录都要写清楚"管的是哪一段、求的是什么"，查错行就全盘皆输。滚动数组则是把小本本上暂时用不到的旧页扔掉，只留最近几页。

26.2 线性 DP：打家劫舍的转移表与滚动数组

"打家劫舍"是线性 DP 的标准起点：一排房屋，不能偷相邻两家，求最大金额。定义 dp[k] 为"偷完前 k 家的最大金额"，对第 i 家（0 基）只有两种选择：不偷，答案 dp[i+1]；偷，答案 dp[i] + a[i]。于是 dp[i+2] = max(dp[i+1], dp[i] + a[i])。数组长度 n+2，让 i=0 时访问 dp[0] 合法，省掉边界特判——这正是"多开哨兵"技巧的用武之地。

先保留完整转移表，打印出来与手工推演逐格对照；确认无误后再改成滚动数组：只需要两步之前的 prev2 与一步之前的 prev1。更新顺序是最常见的坑：必须先用旧的两者算出 cur，再依次 prev2 ← prev1、prev1 ← cur。若先把 prev2 = prev1 写下去，prev2 + x 用的就不是两步前的值，而是刚被覆盖的新值，结果错得悄无声息。调试技巧是让完整表版与滚动版在同一组随机输入上对拍（见 26.8），两者不等就说明覆盖顺序写反了。

// 打家劫舍：dp[k] = 前 k 家能偷到的最大金额
fn rob(a: &[i64]) -> (i64, Vec<i64>) {
let n = a.len();
let mut dp = vec![0i64; n + 2];
for i in 0..n {
dp[i + 2] = dp[i + 1].max(dp[i] + a[i]);
}
(dp[n + 1], dp)
}
fn rob_rolling(a: &[i64]) -> i64 {
let (mut prev2, mut prev1) = (0i64, 0i64);
for &x in a {
let cur = prev1.max(prev2 + x);
prev2 = prev1;
prev1 = cur;
}
prev1
}
fn main() {
let a = [2i64, 7, 9, 3, 1];
let (ans, dp) = rob(&a);
println!("answer = {}", ans);
println!("dp = {:?}", dp);
println!("rolling = {}", rob_rolling(&a));
}

手验：dp[4]=11 来自偷 2 与 7 与 9 中的 7+9=16？不对——dp[4] 表示前 4 家 [2,7,9,3] 的最优，不能相邻，选 2+9=11 或 7+3=10，所以是 11；最后加第 5 家的 1，dp[6] = max(dp[5]=11, dp[4]+1=12) = 12。表格让这种推演变得可查。

边界方面，空数组时 dp 长度为 2、循环不执行，返回 dp[1]=0，符合"没有房屋可偷"。若金额可能为负，初始化 0 就意味着"可以什么都不偷"，题目若强制至少偷一家，必须把初值改成负无穷并单独处理。滚动数组把空间从 O(n) 降到 O(1)，时间不变；它牺牲的是"输出中间方案"的能力——若需要知道偷了哪几家，应保留完整表或额外记录决策来源，不能盲目滚动。完整表还方便观察单调性：这个例子的 dp 序列是非递减的，因为多考虑一家房屋总不会让最优值变差；若打印出的表出现下降，基本可以断定转移式写反了。

26.3 LIS：O(n²) 填表与 tail 数组的二分优化

最长严格递增子序列（LIS）的朴素 DP：定义 dp[i] 为"以 i 结尾的 LIS 长度"，转移是枚举所有 j < i 且 a[j] < a[i] 的位置取 dp[j]+1 的最大值；答案为全表最大。这是 O(n²) 的线性 DP，状态定义里的"以 i 结尾"至关重要——若写成"前 i 个元素的 LIS"，转移时无法保证新元素接在末尾。

优化版维护 tail[k]：长度为 k+1 的严格递增子序列的最小可能结尾值。这个定义的不变量是 tail 数组严格递增：对每个新元素 x，用 partition_point(|t| t < x) 找到第一个 ≥ x 的位置 k（严格小于保证不取相等元素），用 x 替换 tail[k]；若 k 在末尾就追加。替换不会缩短任何已有长度，却为后续元素留下更小的结尾，使它们更容易接入。最终 tail.len() 就是 LIS 长度，O(n log n)。

坑这里最容易踩

坑：partition_point 的谓词必须是严格 <，写成 <= x 会允许相等元素接入，求出的是"最长不下降子序列"，与严格递增不是同一个问题。另一个坑是 tail 数组不代表真实的一条 LIS：例如 [5,1,6,2,7,3,4] 的 tail 最终可能被更新成 [1,2,3,4]，这条子序列确实存在，但对别的数据 tail 的元素可能来自不同子序列，绝不能把它当答案序列输出。要输出序列本身，得额外记录前驱。

rustRust · 标准库34 行
// LIS：O(n^2) 填表版
fn lis_sq(a: &[i64]) -> usize {
let n = a.len();
let mut dp = vec![1usize; n];
for i in 0..n {
for j in 0..i {
if a[j] < a[i] {
dp[i] = dp[i].max(dp[j] + 1);
}
}
}
dp.iter().copied().max().unwrap_or(0)
}
// LIS：tail[k] = 长度 k+1 的严格递增子序列的最小结尾
fn lis_fast(a: &[i64]) -> usize {
let mut tail: Vec<i64> = Vec::new();
for &x in a {
let k = tail.partition_point(|&t| t < x); // 严格小于 => 严格递增
if k == tail.len() {
tail.push(x);
} else {
tail[k] = x;
}
}
tail.len()
}
fn main() {
let a = [5i64, 1, 6, 2, 7, 3, 4];
println!("lis_sq = {}", lis_sq(&a));
println!("lis_fast = {}", lis_fast(&a));
println!("equal = {}", lis_sq(&a) == lis_fast(&a));
}

严格递增的答案是 4（例如 1,2,3,4）。两种实现的复杂度差一个数量级，但对拍时用的是暴力枚举全部子序列当裁判，与两者都独立，避免"两个错得一样的算法互相验证"。

partition_point 是标准库在有序切片上做的二分查找，返回第一个使谓词为假的下标；tail 数组的不变量保证它始终有序，因此每次查询是 O(log n)。空数组时 tail 为空、答案为 0；全是相等元素时每个元素都替换 tail[0]，答案为 1，正是严格递增的正确结果。若要求最长不下降子序列，谓词改成 <= x 即可——但那是另一个问题，必须在状态定义里写清楚。O(n²) 版本的价值不在性能，而在它直接体现状态定义，容易加入额外限制（例如"相邻元素差不超过 k"），这类变体往往无法用 tail 数组优化。

26.4 0/1 背包：容量倒序的不变量

背包是 DP 最重要的一族。0/1 背包：每件物品最多选一次；定义 dp[c] 为"容量不超过 c 时能取得的最大价值"，初始全 0。对每件物品 (w,v)，容量必须倒序枚举：从 cap 递减到 w。原因是不变量——倒序时 dp[c-w] 在本次更新前还是"尚未处理这件物品"的值，于是 dp[c-w]+v 表示"选了当前物品一次"；若正序枚举，dp[c-w] 可能已经在本轮被当前物品更新过，等于允许重复选择，变成了完全背包。

for c in (weight[i]..=cap).rev() 在 weight[i] > cap 时是空区间：RangeInclusive 起点大于终点时不产生元素，循环自然跳过，不需要额外判断。若题目要求"恰好装满"，把 dp 初始化为负无穷、只留 dp[0]=0，最后 dp[cap] 为负即无解；复杂度仍是 O(n·cap)。价值可能是大整数，用 i64 累加；容量是 usize，c - weight[i] 在循环起点 weight[i] 的保证下永不下溢。

dp 是一段连续的 Vec<i64>，倒序遍历按递减地址访问，缓存行为与正序没有本质差别；真正影响性能的是 cap 的大小。若物品总重量远小于 cap，可先把 cap 收缩到总重量，把状态数从 n·cap 降到 n·Σw。若需要输出选了哪些物品，可额外维护 choose[i][c] 布尔表（空间 O(n·cap)），从最终容量倒推：选中则 c 减 weight[i]，否则 i 减一。滚动数组无法支持这种回溯，因为历史决策已被丢弃。0/1 背包还有一个常见变体"每组选一件"，那要把状态扩展到 dp[group][c]，并在每组内先拷贝上一组的表再更新，避免同组内多件被选。调试时可以打印每一件物品处理后的 dp 行，检查它是否恰好等于"上一行"与"上一行加当前价值"的逐格最大值。

大白话先用直觉把它讲通

倒序就像从后往前填表。每件的重量从最后一格往前推，用到的"前一格"还是旧表里的值，代表这件东西还没被拿过，所以最多拿一次。正序呢，刚填好的新格子马上被后面的格子用到，同一件就能被反复拿——那正好是完全背包。

26.5 完全背包与多重背包：正序的语义与拆分技巧

完全背包每件可无限选，容量改为正序枚举：从 w 递增到 cap。此时 dp[c-w] 是本轮已经更新的值，可能包含当前物品，于是"再拿一件"被自然允许。两个模板只差一个 .rev()，语义天差地别；用自己的话复述一遍"为什么倒序是 0/1、正序是完全"再写代码，能避免最常见的混淆。

多重背包限制每件最多选 cnt[i] 次，最直接的写法是再套一层"选几件"的循环，复杂度 O(n·cap·cnt)。更高效的做法是二进制拆分：把 cnt 件拆成 1,2,4,… 以及余下的零头，每份看成一个"捆绑物品"，套 0/1 背包的倒序模板。因为任意 0..cnt 的选择都能由这些 2 的幂组合出来，且每个捆绑包最多选一次，正确性由二进制表示保证；复杂度降到 O(n·cap·log cnt)。

坑这里最容易踩

坑：完全背包的正序遍历天然允许重复，但它依赖于"物品间顺序无关"的最优子结构——只要物品价值可加，正序就是对的。若题目附加"每件最多选两次"之类的限制，正序会失控，必须改成倒序加计数维，或做二进制拆分。把"遍历方向 ↔ 选取次数"的对应写在注释里，是防止现场写反的最稳办法。

二进制拆分的实现也有坑：余下的零头不能丢。例如 cnt=13 应拆成 1、2、4、6 四份，而不是 1、2、4、8（8 超过剩余数量，会让"最多 13 件"变成"最多 15 件"）。每份捆绑物品的重量与价值都要乘以份数，再整体套 0/1 的倒序模板；拆分本身是 O(log cnt) 个新物品，因此总复杂度 O(n·cap·log cnt)。若 cnt 很大而 cap 很小，直接按"枚举件数"的 O(n·cap·cnt) 版反而更简单，先用公式估一下再决定。

rustRust · 标准库31 行
// 0/1 背包：每件最多选一次，容量倒序
fn knap01(weight: &[usize], value: &[i64], cap: usize) -> i64 {
let mut dp = vec![0i64; cap + 1];
for i in 0..weight.len() {
for c in (weight[i]..=cap).rev() {
dp[c] = dp[c].max(dp[c - weight[i]] + value[i]);
}
}
dp[cap]
}
// 完全背包：每件可无限选，容量正序
fn knap_complete(weight: &[usize], value: &[i64], cap: usize) -> i64 {
let mut dp = vec![0i64; cap + 1];
for i in 0..weight.len() {
for c in weight[i]..=cap {
dp[c] = dp[c].max(dp[c - weight[i]] + value[i]);
}
}
dp[cap]
}
fn main() {
let w = [1usize, 3, 4];
let v = [15i64, 20, 30];
println!("01 = {}", knap01(&w, &v, 6));
println!("complete = {}", knap_complete(&w, &v, 6));
let w2 = [5usize, 4];
let v2 = [10i64, 8];
println!("01(skip) = {}", knap01(&w2, &v2, 3));
}

26.6 区间 DP：石子合并与按长度递增

区间 DP 的状态是 dp[l][r]，表示闭区间 [l,r] 上的最优值。它的计算顺序不能按 l 或 r 的字典序，而要按区间长度从小到大：先算所有长度为 2 的区间，再算长度 3 的，依此类推。因为长度 len 的区间要由两个更短的区间合并而来，长度递增天然保证依赖已就绪。

"石子合并"是标准例题：一排石子两两合并，每次代价是两堆总数，求全部合成一堆的最小总代价。枚举断点 k，把 [l,r] 拆成 [l,k] 与 [k+1,r]，转移 dp[l][r] = min(dp[l][k] + dp[k+1][r] + sum(l,r))。区间和用前缀和 O(1) 取得，避免每次累加。for l in 0..=n-len 中 n-len 恒非负（len 最大为 n），r = l+len-1 最大 n-1，访问 dp[k+1][r] 安全。

rustRust · 标准库34 行
// 区间 DP：石子合并，按区间长度递增
fn merge_stones(a: &[i64]) -> (i64, Vec<Vec<i64>>) {
let n = a.len();
if n <= 1 {
return (0, vec![vec![0; n]; n]);
}
let mut pref = vec![0i64; n + 1];
for i in 0..n {
pref[i + 1] = pref[i] + a[i];
}
let inf = i64::MAX / 4;
let mut dp = vec![vec![0i64; n]; n];
for len in 2..=n {
for l in 0..=n - len {
let r = l + len - 1;
let sum = pref[r + 1] - pref[l];
let mut best = inf;
for k in l..r {
best = best.min(dp[l][k] + dp[k + 1][r] + sum);
}
dp[l][r] = best;
}
}
(dp[0][n - 1], dp)
}
fn main() {
let a = [4i64, 3, 3, 4];
let (ans, dp) = merge_stones(&a);
println!("answer = {}", ans);
for row in &dp {
println!("{:?}", row);
}
}

上三角矩阵里 dp[l][l]=0 是边界：单堆无需合并。打印二维表是区间 DP 的标准调试手段——先确认对角线为 0，再逐层检查长度为 2、3 的值与手算是否一致。空间 O(n²) 通常无法滚动压缩，因为长区间会用到所有短区间的结果。

石子合并还有"环形"变体：n 堆围成一圈，每次合并相邻两堆。做法是把数组复制一遍接在后面，在长度 2n 的序列上做普通区间 DP，最后取所有长度为 n 的区间的最小值 min(dp[l][l+n-1])。原理是任意环形合并都对应展开后某个长度为 n 的连续段。n-len 下标计算在环形版里变成 2n-len，仍保持非负。这类"复制一遍化环为链"的技巧在区间 DP 里很常见，值得和基础的线性版一起记。

复杂度方面，三重循环的层次不能交换：必须 len 在最外层、l 在中层、k 在最内层，因为 k 的依赖是更短的长度。若把 l 放外层，计算 dp[l][r] 时 dp[l+1][r] 可能还没算出来。调试时还可以先关掉前缀和、改用循环累加区间和验证转移，确认是转移错还是前缀和错。若题目把"合并代价"改成区间长度的平方或其他函数，只需替换 sum 的计算，循环结构完全不变——这正是区间 DP 模板的价值。

26.7 自顶向下与自底向上：备忘录与栈深度

DP 有两种实现路线。自顶向下（记忆化搜索）从原问题递归拆分，用 Option<T> 或哨兵数组存已算结果；思路最贴近状态定义，天然只访问可达状态，但递归深度可能爆栈，且 Rust 里"递归函数 + 可变备忘录"需要处理借用，常用 Cell/RefCell 或把备忘录放进结构体。自底向上（填表）按循环顺序计算所有状态，顺序明确、性能更好、无爆栈风险，是竞赛与工程的默认选择。

选择时要看状态空间：若很多状态根本不可达，记忆化能省下大量计算；若几乎所有状态都要用到，填表更直接且缓存友好。两者结果必须一致，这正好可以作为对拍的两个实现。对区间 DP 而言，递归版写起来极短（solve(l,r) = min_k solve(l,k)+solve(k+1,r)+sum），可用它当自底向上版的裁判；n 不大时递归深度是 O(n)，不会爆栈。

Rust 里写记忆化搜索有个具体的难点：递归函数要同时读状态定义与写备忘录，直接用 &mut Vec<Option<T>> 参数会与借用检查打架，因为函数持有切片引用的同时又要修改它。常见解法有三：把备忘录放进结构体、用 Cell/RefCell 提供内部可变性、或把状态编号成一维下标后用裸指针包一层 unsafe（不推荐）。相比之下，自底向上的填表版没有任何借用冲突，也不需要 Option 包装，这正是竞赛代码几乎都是迭代版的原因。折中方案是"先写递归版确认转移正确，再翻译成填表版"，把两个版本都留在测试里互相对拍，既保证可读性又保证性能。对线性 DP 而言，递归深度等于 n，十万项的链同样会爆栈，因此"递归版只用于小规模验证"是通用原则。记忆化的另一个优势是只算可达状态，在状态空间稀疏的问题上可能比填表快很多；判断依据是"可达状态数"与"总状态数"的比值，比值很小时优先考虑递归加备忘录。

26.8 随机对拍：五类 DP 对暴力枚举

DP 最容易写错的是边界与顺序，而不是转移式本身，所以随机对拍要与"显然正确但慢"的暴力版比对。本单元用 xorshift 生成 2500 组数据，同时检查五件事：打家劫舍 DP 对子集枚举（相邻位不能同时为 1）；LIS 的 O(n²) 与 O(n log n) 版都对"枚举全部子序列"的暴力版；0/1 背包对子集枚举；完全背包对递归枚举每个物品拿几件；石子合并区间 DP 对递归枚举所有断点。

规模都压得很小：n≤11 的子集枚举最多 2048 种，LIS 的 n≤9 最多 512 个子序列，背包 n≤9、cap≤14，石子 n≤7。小数据足以覆盖"空输入、单元素、恰好装满、放不下任何物品"等边界，而暴力版跑得飞快。任何不一致都会打印输入数组，配合固定种子可以立即复现。

struct Rng(u64);
impl Rng {
fn next(&mut self) -> u64 {
let mut x = self.0;
x ^= x << 13; x ^= x >> 7; x ^= x << 17;
self.0 = x; x
}
fn below(&mut self, n: usize) -> usize { (self.next() % n as u64) as usize }
}
fn rob(a: &[i64]) -> i64 {
let mut dp = vec![0i64; a.len() + 2];
for i in 0..a.len() { dp[i + 2] = dp[i + 1].max(dp[i] + a[i]); }
dp[a.len() + 1]
}
fn brute_rob(a: &[i64]) -> i64 {
let mut best = i64::MIN;
for mask in 0..(1usize << a.len()) {
let mut sum = 0i64;
let mut ok = true;
for i in 0..a.len() {
if (mask >> i) & 1 == 1 {
if i > 0 && (mask >> (i - 1)) & 1 == 1 { ok = false; break; }
sum += a[i];
}
}
if ok { best = best.max(sum); }
}
best
}
fn lis_sq(a: &[i64]) -> usize {
let mut dp = vec![1usize; a.len()];
for i in 0..a.len() { for j in 0..i { if a[j] < a[i] { dp[i] = dp[i].max(dp[j] + 1); } } }
dp.iter().copied().max().unwrap_or(0)
}
fn lis_fast(a: &[i64]) -> usize {
let mut t: Vec<i64> = Vec::new();
for &x in a {
let k = t.partition_point(|&v| v < x);
if k == t.len() { t.push(x); } else { t[k] = x; }
}
t.len()
}
fn brute_lis(a: &[i64]) -> usize {
let mut best = 0;
for mask in 0..(1usize << a.len()) {
let seq: Vec<i64> = (0..a.len()).filter(|&i| (mask >> i) & 1 == 1).map(|i| a[i]).collect();
if seq.len() <= best { continue; }
if seq.windows(2).all(|w| w[0] < w[1]) { best = seq.len(); }
}
best
}
fn knap01(w: &[usize], v: &[i64], cap: usize) -> i64 {
let mut dp = vec![0i64; cap + 1];
for i in 0..w.len() { for c in (w[i]..=cap).rev() { dp[c] = dp[c].max(dp[c - w[i]] + v[i]); } }
dp[cap]
}
fn brute_01(w: &[usize], v: &[i64], cap: usize) -> i64 {
let mut best = 0;
for mask in 0..(1usize << w.len()) {
let (mut cw, mut cv) = (0usize, 0i64);
for i in 0..w.len() { if (mask >> i) & 1 == 1 { cw += w[i]; cv += v[i]; } }
if cw <= cap { best = best.max(cv); }
}
best
}
fn knap_complete(w: &[usize], v: &[i64], cap: usize) -> i64 {
let mut dp = vec![0i64; cap + 1];
for i in 0..w.len() { for c in w[i]..=cap { dp[c] = dp[c].max(dp[c - w[i]] + v[i]); } }
dp[cap]
}
fn brute_complete(w: &[usize], v: &[i64], cap: usize, i: usize, left: usize) -> i64 {
if i == w.len() { return 0; }
let mut best = brute_complete(w, v, cap, i + 1, left);
let mut k = 1;
while k * w[i] <= left {
let rest = brute_complete(w, v, cap, i + 1, left - k * w[i]);
best = best.max(rest + k as i64 * v[i]);
k += 1;
}
best
}
fn merge_stones(a: &[i64]) -> i64 {
let n = a.len();
if n <= 1 { return 0; }
let mut pre = vec![0i64; n + 1];
for i in 0..n { pre[i + 1] = pre[i] + a[i]; }
let mut dp = vec![vec![0i64; n]; n];
for len in 2..=n {
for l in 0..=n - len {
let r = l + len - 1;
let sum = pre[r + 1] - pre[l];
dp[l][r] = (l..r).map(|k| dp[l][k] + dp[k + 1][r] + sum).min().unwrap();
}
}
dp[0][n - 1]
}
fn brute_merge(pre: &[i64], l: usize, r: usize) -> i64 {
if l >= r { return 0; }
let sum = pre[r + 1] - pre[l];
(l..r).map(|k| brute_merge(pre, l, k) + brute_merge(pre, k + 1, r) + sum).min().unwrap()
}
fn main() {
let mut rng = Rng(0x0DEF_ACED_1234_5678);
let (mut cases, mut bad) = (0, 0);
for _ in 0..2500 {
// 打家劫舍：DP 对子集枚举
let n = 1 + rng.below(11); // 1..=11
let a: Vec<i64> = (0..n).map(|_| rng.below(20) as i64 + 1).collect();
if rob(&a) != brute_rob(&a) {
bad += 1; if bad <= 3 { println!("BAD rob {:?}", a); }
}
// LIS：三种实现互证
let m = 1 + rng.below(9); // 1..=9
let b: Vec<i64> = (0..m).map(|_| rng.below(12) as i64).collect();
let (s, f, bf) = (lis_sq(&b), lis_fast(&b), brute_lis(&b));
if s != bf || f != bf {
bad += 1; if bad <= 3 { println!("BAD lis {:?} sq={} fast={} brute={}", b, s, f, bf); }
}
// 0/1 背包与完全背包
let k = 1 + rng.below(9);
let w: Vec<usize> = (0..k).map(|_| 1 + rng.below(5)).collect();
let v: Vec<i64> = (0..k).map(|_| rng.below(12) as i64 + 1).collect();
let cap = 1 + rng.below(14);
if knap01(&w, &v, cap) != brute_01(&w, &v, cap) {
bad += 1; if bad <= 3 { println!("BAD knap01 w={:?} v={:?} cap={}", w, v, cap); }
}
if knap_complete(&w, &v, cap) != brute_complete(&w, &v, cap, 0, cap) {
bad += 1; if bad <= 3 { println!("BAD complete w={:?} v={:?} cap={}", w, v, cap); }
}
// 石子合并：区间 DP 对递归枚举
let q = 1 + rng.below(7); // 1..=7
let c: Vec<i64> = (0..q).map(|_| rng.below(10) as i64 + 1).collect();
let mut pre = vec![0i64; q + 1];
for i in 0..q { pre[i + 1] = pre[i] + c[i]; }
if merge_stones(&c) != brute_merge(&pre, 0, q - 1) {
bad += 1; if bad <= 3 { println!("BAD merge {:?}", c); }
}
cases += 1;
}
println!("cases={} mismatches={}", cases, bad);
if bad == 0 { println!("RESULT: PASS"); }
}

对拍规模的选择遵循"暴力跑得动、边界覆盖够"两条原则。n≤11 保证子集枚举不超过 2048 种，2500 轮总计算量在秒级；规模再大就该换更聪明的裁判，而不是让对拍本身变成瓶颈。数据分布也有讲究：价值全为正、重量全为 1、序列全相等这类退化输入很少自然出现，若想专门覆盖它们，可以在生成器里按一定概率强制产出。若某轮报 MISMATCH，打印的输入数组与固定种子能让你重放现场；先把 n 缩小到最小反例，再打印完整 dp 表逐格对照，通常一眼就能看出是边界初值、循环方向还是下标偏移出错。对拍还应覆盖"暴力裁判自己有 bug"的情况：用两个独立暴力版交叉验证，或在已知答案的手工样例上先跑一遍裁判。

26.9 工程取舍：初始化、溢出与调试清单

四类基础 DP 的适用边界列在下表。选型时先估算"状态数 × 转移数"：线性 DP 通常最便宜，区间 DP 的 O(n³) 决定了 n 只能到几百；背包对 cap 敏感，cap 很大时需要换思路（例如按价值定义状态）。

模型 状态 转移数 复杂度 关键顺序
线性 DP dp[k]：前 k 项 O(1)~O(k) O(n) 或 O(n²) 下标递增
LIS dp[i]：以 i 结尾 O(i) O(n²) / O(n log n) tail 须严格递增
0/1 背包 dp[c]：容量 c O(1) O(n·cap) 容量倒序
完全背包 dp[c]：容量 c O(1) O(n·cap) 容量正序
区间 DP dp[l][r]：区间 O(len) O(n³) 区间长度递增

初始化是另一大坑源。"恰好装满"要与"不超过容量"用不同的初值：前者把 dp 全设为负无穷、只留 dp[0]=0，后者全设 0。求最小值时负无穷与正无穷别混用，否则 min 会把边界吞掉。整数量用 i64，先估算最大可能值再决定类型；i64::MAX/4 作为哨兵要给加法留余量。DP 调试有固定流程：写出状态定义 → 手推最小例子的转移表 → 打印完整表与手工结果逐格对照 → 确认后改滚动优化 → 最后用暴力对拍守大数据。绝大多数错误都能在前两步被拦住。
