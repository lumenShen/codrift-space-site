29.1 字符串进阶的三个方向

基础单元里，哈希、KMP、Z 函数与 Trie 解决的是"一个模式对一段文本"的问题。现实需求往往更大：敏感词过滤要同时匹配成千上万个模式；字符串排序、不同子串计数要用到全串后缀的全局信息；回文相关查询要求对每个中心快速得到半径。本单元三个工具正好对应这三个方向。

AC 自动机把 Trie 的每条边补成状态转移，再用失败链把模式之间的后缀重叠关系串起来，于是一次文本扫描即可报告所有模式的出现——复杂度与模式个数几乎无关，只与文本长度和匹配数有关。后缀数组把所有后缀按字典序排成一列；有了这个序，LCP 数组、不同子串计数、后缀排序查询等一大类问题都能在线性或近线性时间内解决。Manacher 用"已知回文区间内的镜像复用"把回文半径计算从 O(n²) 降到 O(n)，思想和 KMP 的指针回退、Z 函数的盒子复用一脉相承。

三者还有一个共同点：它们都不是靠"算得更快"取胜，而是靠"少算重复的东西"。AC 自动机复用了模式之间的公共前缀与后缀；后缀数组把每对后缀的两两比较，压缩成相邻后缀的 LCP 比较；Manacher 则把回文内部的对称位置成对压缩。理解这一点，就能判断一个新问题该用哪件工具：先问"重复劳动藏在哪里"，再问"哪种结构能把它消掉"。其次要注意，这些工具的预处理成本并不低——AC 要建完整的转移表，后缀数组要跑 log n 轮计数排序——只有当查询量足够大或数据规模足够大时，预处理才划算。小规模输入下，一个写得好的暴力法往往比这些结构更快也更容易写对。

大白话先用直觉把它讲通

上次我们一把钥匙开一把锁。这次是三种升级。AC 自动机是"一把万能钥匙串"，把所有模式词先编成一本字典树，再让文本从头走到尾，每走一步就能报出所有在这结束的词。后缀数组是"把一本书的所有后缀按字典顺序排好队"，排好之后很多统计问题只要看相邻两项的共同开头。Manacher 是"找回文时记住已经确认的对称区间"，区间里的位置直接照镜子抄答案，不用重新比对。

29.2 AC 自动机：多模式匹配的一次扫描

问题定义。 给定一组模式串，统计它们在文本中出现次数之和（重复模式分别计数）。朴素做法是每个模式跑一次 KMP，总时间 O(模式总长 + 模式个数 × 文本长)，模式多起来就不可行。AC 自动机把它压到 O(模式总长 + 文本长 + 匹配数)。

结构机制。 第一步，把所有模式插入 Trie，在每个模式末尾节点把 cnt 加一。第二步，BFS 为每个节点计算失败链 fail[u]：它是"当前已匹配串的最长真后缀，且恰好是某个模式前缀"对应的节点。第三步，计算输出链 out[u]：指向 fail 链上最近的终止节点，这样统计时不必沿整条 fail 链逐段检查。

不变量与正确性。 扫描文本时维护状态 u：从根到 u 的路径拼成的字符串，恰好是当前文本后缀与某个模式前缀的最长匹配。读入字符 c 时，若 u 有 c 边就直接走；否则沿 fail 回退直到有 c 边或回到根。这一步与 KMP 的失败跳转完全同构，文本指针同样不回退，摊还线性。每到一个状态，以该状态结尾的模式数为 cnt[u] + cnt[out[u]] + ...，沿输出链累加即可不重不漏地统计所有在此结束的模式。失败链的正确性由 BFS 保证：处理 u 的孩子 v 时，u 的 fail 已算好，从 fail[u] 出发沿 fail 链找有 c 边的节点，就得到 v 的最长可复用后缀。

Rust 实现要点。 用 [usize; 26] 存孩子、usize::MAX 作哨兵。BFS 用 VecDeque。计算 fail 时不能只查一次 ch[fail[u]][k]——若该位置是 NIL，必须沿 fail 链继续找直到根；若只查一次就直接置 0，会漏掉像"adb"应失败到"b"这样的转移。这是本单元真实踩过并修复的坑。输出链在 fail 算好后顺手得到：若 fail 节点是终止节点就指向它，否则继承它的 out。

复杂度。 建树 O(模式总长)，BFS 计算 fail/out 每个节点每条边摊还 O(1)，扫描 O(文本长 + 匹配数)。空间 O(模式总长 × 26)。输出链的价值在匹配密集时尤其明显：若模式集包含 a、aa、aaa 一直到 a^k，扫描一串 a 会在每个位置产生 k 个匹配，沿输出链只需走到最近的终止 fail 祖先再逐级传递；若没有输出链而沿整条 fail 链检查，每位置要做 k 次判断，总复杂度退化为 O(文本长 × 最长模式长)。因此"输出链"不是锦上添花，而是保证匹配阶段线性的关键结构。另一个工程细节是 BFS 的计算顺序：必须按层处理，保证算 v 的 fail 时 fail[u] 已经就绪；若用 DFS 就可能引用到尚未算出的 fail 值，得到错误链。

下面的程序用四个模式在文本 ushers 上演示（结果为 3：she、he、hers 各一次），再对随机字典与随机文本做 250 组与朴素枚举的对拍。

#![allow(dead_code)]
use std::collections::VecDeque;
const NIL: usize = usize::MAX;
struct Node {
ch: [usize; 26],
fail: usize,
out: usize,
cnt: usize,
}
impl Node {
fn new() -> Self { Self { ch: [NIL; 26], fail: 0, out: 0, cnt: 0 } }
}
struct AcAutomaton { nodes: Vec<Node> }
impl AcAutomaton {
fn new() -> Self { Self { nodes: vec![Node::new()] } }
fn insert(&mut self, w: &[u8]) {
let mut u = 0usize;
for &c in w {
let k = (c - b'a') as usize;
if self.nodes[u].ch[k] == NIL {
self.nodes[u].ch[k] = self.nodes.len();
self.nodes.push(Node::new());
}
u = self.nodes[u].ch[k];
}
self.nodes[u].cnt += 1;
}
fn build(&mut self) {
let mut q = VecDeque::new();
for k in 0..26 {
let v = self.nodes[0].ch[k];
if v != NIL { self.nodes[v].fail = 0; q.push_back(v); }
}
while let Some(u) = q.pop_front() {
for k in 0..26 {
let v = self.nodes[u].ch[k];
if v == NIL { continue; }
let mut f = self.nodes[u].fail;
while f != 0 && self.nodes[f].ch[k] == NIL { f = self.nodes[f].fail; }
let nxt = self.nodes[f].ch[k];
self.nodes[v].fail = if nxt == NIL { 0 } else { nxt };
let ff = self.nodes[v].fail;
self.nodes[v].out = if self.nodes[ff].cnt > 0 { ff } else { self.nodes[ff].out };
q.push_back(v);
}
}
}
fn count_matches(&self, text: &[u8]) -> usize {
let mut u = 0usize;
let mut total = 0usize;
for &c in text {
let k = (c - b'a') as usize;
while u != 0 && self.nodes[u].ch[k] == NIL { u = self.nodes[u].fail; }
if self.nodes[u].ch[k] != NIL { u = self.nodes[u].ch[k]; }
let mut v = u;
while v != 0 {
total += self.nodes[v].cnt;
v = self.nodes[v].out;
}
}
total
}
}
fn naive(text: &[u8], pats: &[Vec<u8>]) -> usize {
let mut total = 0usize;
for p in pats {
if p.is_empty() || p.len() > text.len() { continue; }
for i in 0..=text.len() - p.len() {
if &text[i..i + p.len()] == p.as_slice() { total += 1; }
}
}
total
}
struct Rng(u64);
impl Rng {
fn next_u64(&mut self) -> u64 { let mut x = self.0; x ^= x << 13; x ^= x >> 7; x ^= x << 17; self.0 = x; x }
fn range(&mut self, lo: u64, hi: u64) -> u64 { lo + self.next_u64() % (hi - lo + 1) }
}
fn rand_word(rng: &mut Rng) -> Vec<u8> {
let n = 1 + rng.range(0, 5) as usize;
(0..n).map(|_| b'a' + rng.range(0, 3) as u8).collect()
}
fn main() {
let pats: Vec<Vec<u8>> = vec![b"he".to_vec(), b"she".to_vec(), b"hers".to_vec(), b"his".to_vec()];
let mut ac = AcAutomaton::new();
for p in &pats { ac.insert(p); }
ac.build();
let text = b"ushers";
println!("demo ac count = {}", ac.count_matches(text));
let mut rng = Rng(0x1234_5678_9abc_def0);
let mut bad = 0;
for _ in 0..250 {
let cnt = 1 + rng.range(0, 10) as usize;
let mut pats = Vec::new();
let mut ac = AcAutomaton::new();
for _ in 0..cnt {
let w = rand_word(&mut rng);
ac.insert(&w);
pats.push(w);
}
ac.build();
let t = rand_word(&mut rng).repeat(6);
let a = ac.count_matches(&t);
let b = naive(&t, &pats);
if a != b { println!("MISMATCH ac={} naive={}", a, b); bad += 1; break; }
}
println!("stress ac: {} (250 random cases)", if bad == 0 { "OK" } else { "FAIL" });
}

坑这里最容易踩

坑：计算 fail 时只查一层是不够的。考虑模式集 {adb, b}，处理"adb"的"b"孩子时，父节点"ad"的 fail 指向"d"，而"d"没有"b"边——正确的 fail 应继续沿链找到根节点下的"b"。若写成 fail[v] = ch[fail[u]][k] 且该位置为 NIL 就直接置 0，会漏掉模式"b"的匹配。本单元对拍第一版正是因此失败（ac=6，naive=12），修复方式是 while f != 0 && ch[f][k] == NIL { f = fail[f] }。另一个坑是文本字符集必须落在 26 个小写字母内，否则 (c - b'a') 会下溢成巨大下标——demo 文本里带一个空格就触发过这个 panic。

29.3 后缀数组：把所有后缀排成序

问题定义。 给定字符串 s（长度 n，只含小写字母），输出一个数组 sa，使得 s[sa[0]..] < s[sa[1]..] < ... 按字典序排列。banana 的后缀数组是 [5,3,1,0,4,2]，对应 "a"、"ana"、"anana"、"banana"、"na"、"nana"。

倍增机制。 直接排序所有后缀要 O(n² log n) 的比较。倍增法利用长度 2^k 的排名推导长度 2^(k+1) 的排名：后缀 i 的前 2^(k+1) 个字符由两段长度 2^k 组成，其序对是 (rank[i], rank[i+2^k])。对序对排序即可得到新排名。排序用两次计数排序（基数排序）：先把位置按第二关键字 rank[i+2^k] 排，再稳定地按第一关键字 rank[i] 排，整体 O(n)。k 从 0 到 ⌈log n⌉，总时间 O(n log n)。

哨兵的作用。 在串尾追加一个比所有字符都小的哨兵（rank 为 0，真实字符 rank 从 1 起）。它保证任一后缀都是另一后缀的前缀时，短的那个因提前遇到哨兵而更小，字典序定义自洽；同时让"越界"的第二关键字统一取 0，不必写复杂的边界分支。构造完成后把哨兵位置从 sa 中过滤掉。

不变量与实现。 循环不变量是：p 按长度 2^k 的前缀排好序，c[i] 是该前缀的等价类编号（相同前缀同类）。每轮先用 pn[i] = p[i] − 2^k (mod n) 得到按第二关键字有序的序列，再按 c[pn[i]] 做稳定计数排序，最后用相邻序对是否相等更新类名。while (1<<h) < n_total 保证长度覆盖全串。

复杂度。 O(n log n) 时间，O(n) 空间。下面的程序对随机串把倍增结果与 sort_by 直接比较后缀的朴素法对照 300 组。

为什么计数排序能在这里大显身手？因为类名 c 的取值范围只有 0 到 classes−1，且 classes 不超过 n。对这样的整数键做计数排序是 O(n + classes) = O(n)，比基于比较的排序 O(n log n) 省掉了一个 log。倍增的每一轮都做两次计数排序，log n 轮下来总复杂度仍是 O(n log n)，但常数远小于逐对比较后缀。这也解释了为什么 suffix array 在竞赛中能处理十万量级的字符串：真正的瓶颈是轮数而非单轮成本。类名更新时还要检查"相邻两个位置的序对是否完全相同"，只有两维都相等才归入同一类；若只比较其中一个维度，等价类会划分过粗，后续排序依据失真。

#![allow(dead_code)]
fn suffix_array(s: &[u8]) -> Vec<usize> {
let n = s.len();
let ntot = n + 1; // include sentinel
let mut a = vec![0usize; ntot];
for i in 0..n { a[i] = (s[i] - b'a' + 1) as usize; }
a[n] = 0; // sentinel smaller than all real chars
let mut p = vec![0usize; ntot];
let mut c = vec![0usize; ntot];
// initial counting sort by first character
let mut cnt = vec![0usize; 27];
for &x in &a { cnt[x] += 1; }
let mut pos = vec![0usize; 27];
for i in 1..27 { pos[i] = pos[i - 1] + cnt[i - 1]; }
for i in 0..ntot { let x = a[i]; p[pos[x]] = i; pos[x] += 1; }
c[p[0]] = 0;
let mut classes = 1usize;
for i in 1..ntot {
if a[p[i]] != a[p[i - 1]] { classes += 1; }
c[p[i]] = classes - 1;
}
let mut pn = vec![0usize; ntot];
let mut h = 0usize;
while (1usize << h) < ntot {
let shift = 1usize << h;
for i in 0..ntot {
pn[i] = if p[i] >= shift { p[i] - shift } else { p[i] + ntot - shift };
}
let mut cnt2 = vec![0usize; classes];
for i in 0..ntot { cnt2[c[pn[i]]] += 1; }
let mut pos2 = vec![0usize; classes];
for i in 1..classes { pos2[i] = pos2[i - 1] + cnt2[i - 1]; }
for i in 0..ntot {
let key = c[pn[i]];
p[pos2[key]] = pn[i];
pos2[key] += 1;
}
let mut cn = vec![0usize; ntot];
cn[p[0]] = 0;
let mut new_classes = 1usize;
for i in 1..ntot {
let cur1 = c[p[i]];
let cur2 = if p[i] + shift < ntot { c[p[i] + shift] } else { 0 };
let pre1 = c[p[i - 1]];
let pre2 = if p[i - 1] + shift < ntot { c[p[i - 1] + shift] } else { 0 };
if cur1 != pre1 || cur2 != pre2 { new_classes += 1; }
cn[p[i]] = new_classes - 1;
}
c = cn;
classes = new_classes;
h += 1;
}
p.into_iter().filter(|&i| i != n).collect()
}
fn naive_sa(s: &[u8]) -> Vec<usize> {
let n = s.len();
let mut v: Vec<usize> = (0..n).collect();
v.sort_by(|&i, &j| s[i..].cmp(&s[j..]));
v
}

impl Rng {

}

}

}

倍增法里有两个高频错误。一是"按第二关键字排序后，稳定排序的第一关键字取错"：正确的做法是对 pn[i] = p[i] − shift 按 c[pn[i]] 做计数排序，因为 pn 在修改前已按第二关键字有序，稳定排序保留了这个次序。若误写成按 c[pn[i]+shift] 排序，排名会完全错乱。二是类名更新的序对要用 (c[p[i]], c[p[i]+shift])，越界取 0；这两个位置的组合唯一决定了长度为 2^(k+1) 的前缀，不能只比较其中一个。

29.4 Kasai LCP 与不同子串计数

问题定义。 给定 sa，求 lcp[r] = LCP(s[sa[r]..], s[sa[r+1]..])，即字典序相邻后缀的最长公共前缀。进而统计 s 中不同的非空子串个数。

Kasai 不变量。 直接逐对比较是 O(n²)。Kasai 的关键引理是：若 LCP(s[i..], s[j..]) = k > 0，则 LCP(s[i+1..], s[j+1..]) ≥ k−1——两个后缀各去掉首字符后，原来公共的前缀整体左移一位，至少还剩 k−1。按 i 在原串中的顺序处理，用上一轮的 k 减一作为当前比较起点，每轮的比较次数摊还 O(1)，总时间 O(n)。实现上要先把 rank 数组建好：rank[sa[i]] = i，然后按 i 递增处理，与 sa[r]+1 对应的后缀比较。

不同子串计数。 每个后缀 sa[r] 贡献 n − sa[r] 个前缀子串，但其中与前一名后缀共享的前 lcp[r−1] 个已经出现过（因为按字典序，与某个已有后缀的最长公共前缀一定出现在它最近的邻居里）。所以不同子串数 = n(n+1)/2 − Σ lcp[r]。这个公式的正确性依赖后缀数组的有序性：共享前缀的后缀在 sa 中必然相邻（否则中间的后缀字典序夹在中间，与共享前缀矛盾）。

复杂度。 Kasai O(n) 时间、O(n) 空间；计数 O(n)。LCP 数组的用途远不止计数不同子串：最长重复子串就是 max(lcp)；后缀树可以视作后缀数组加 LCP 的等价结构；两个字符串的最长公共前缀可以在合并后的后缀数组上查询相邻 LCP 的最小值得到。可以说，后缀数组给出"序"，Kasai 给出"相邻序之间的相似度"，两者合起来就把一整类后缀问题变成了数组上的区间最值查询。摊还复杂度的证明也值得多说一句：k 在内层 while 中每成功加一，对应的 i 就右移一位（因为 j 也相应右移），所以 k 的总增量不超过 n；而下一轮开始时 k 减一，保证了它不会在小范围内反复增长。这与 KMP 的势能分析是同一套论证。

下面的程序在 banana 上打印 LCP [1,3,0,0,2,0]、不同子串数 15，并对随机串用 HashSet 枚举全部子串的朴素法对照 300 组。

#![allow(dead_code)]
use std::collections::HashSet;
fn suffix_array(s: &[u8]) -> Vec<usize> {
let n = s.len();
let ntot = n + 1;
let mut a = vec![0usize; ntot];
for i in 0..n { a[i] = (s[i] - b'a' + 1) as usize; }
a[n] = 0;
let mut p = vec![0usize; ntot];
let mut c = vec![0usize; ntot];
let mut cnt = vec![0usize; 27];
for &x in &a { cnt[x] += 1; }
let mut pos = vec![0usize; 27];
for i in 1..27 { pos[i] = pos[i - 1] + cnt[i - 1]; }
for i in 0..ntot { let x = a[i]; p[pos[x]] = i; pos[x] += 1; }
c[p[0]] = 0;
let mut classes = 1usize;
for i in 1..ntot { if a[p[i]] != a[p[i - 1]] { classes += 1; } c[p[i]] = classes - 1; }
let mut pn = vec![0usize; ntot];
let mut h = 0usize;
while (1usize << h) < ntot {
let shift = 1usize << h;
for i in 0..ntot { pn[i] = if p[i] >= shift { p[i] - shift } else { p[i] + ntot - shift }; }
let mut cnt2 = vec![0usize; classes];
for i in 0..ntot { cnt2[c[pn[i]]] += 1; }
let mut pos2 = vec![0usize; classes];
for i in 1..classes { pos2[i] = pos2[i - 1] + cnt2[i - 1]; }
for i in 0..ntot {
let key = c[pn[i]];
p[pos2[key]] = pn[i];
pos2[key] += 1;
}
let mut cn = vec![0usize; ntot];
cn[p[0]] = 0;
let mut nc = 1usize;
for i in 1..ntot {
let c1 = c[p[i]];
let c2 = if p[i] + shift < ntot { c[p[i] + shift] } else { 0 };
let d1 = c[p[i - 1]];
let d2 = if p[i - 1] + shift < ntot { c[p[i - 1] + shift] } else { 0 };
if c1 != d1 || c2 != d2 { nc += 1; }
cn[p[i]] = nc - 1;
}
c = cn; classes = nc; h += 1;
}
p.into_iter().filter(|&i| i != n).collect()
}
fn kasai(s: &[u8], sa: &[usize]) -> Vec<usize> {
let n = s.len();
let mut rank = vec![0usize; n];
for i in 0..n { rank[sa[i]] = i; }
let mut lcp = vec![0usize; n];
let mut k = 0usize;
for i in 0..n {
let r = rank[i];
if r + 1 >= n { k = 0; continue; }
let j = sa[r + 1];
while i + k < n && j + k < n && s[i + k] == s[j + k] { k += 1; }
lcp[r] = k;
if k > 0 { k -= 1; }
}
lcp
}
fn distinct_substrings(s: &[u8]) -> usize {
let n = s.len();
let sa = suffix_array(s);
let lcp = kasai(s, &sa);
let total = n * (n + 1) / 2;
let sum: usize = lcp.iter().sum();
total - sum
}
fn brute_distinct(s: &[u8]) -> usize {
let n = s.len();
let mut set = HashSet::new();
for i in 0..n {
for j in i + 1..=n {
set.insert(&s[i..j]);
}
}
set.len()
}
struct Rng(u64);
impl Rng {
fn next_u64(&mut self) -> u64 { let mut x = self.0; x ^= x << 13; x ^= x >> 7; x ^= x << 17; self.0 = x; x }
fn range(&mut self, lo: u64, hi: u64) -> u64 { lo + self.next_u64() % (hi - lo + 1) }
}

println!("demo lcp = {:?}", kasai(s, &sa));

Kasai 的实现有两个易错点。一是 rank 数组必须按 sa 反填 rank[sa[i]] = i，若用 sa 的原顺序当 rank 会让 i 的遍历顺序与 k 的复用前提脱节，摊还 O(n) 就不成立了。二是当前后缀是 sa 中最后一个时没有"下一个"，此时要把 k 清零而不是沿用——否则下一次比较会从一个已经失效的长度开始，LCP 值偏大。

29.5 Manacher：线性求回文半径

问题定义。 对每个中心求最长回文半径：奇数中心用 d1[i] 表示以 i 为中心的最长奇数回文半径（半径 1 表示只有字符本身，回文长 2·d1[i]−1）；偶数中心用 d2[i] 表示以 i 与 i−1 之间的缝隙为中心的最长偶数半径（回文长 2·d2[i]）。进而求最长回文子串长度。朴素做法对每个中心向两边扩展，O(n²)。

镜像复用机制。 维护当前已知最右回文区间 [l, r]。对奇数中心 i：若 i ≤ r，则中心 i 关于区间中心 (l+r)/2 的镜像位置是 l+r−i，由于整个 [l,r] 是回文，以镜像为中心的回文半径在区间内的部分可以直接复制，取 d1[i] = min(d1[l+r−i], r−i+1) 作为起点再向外扩展。偶数中心类似，镜像位置是 l+r−i+1。每次扩展结束后若右端超过 r，就更新 [l,r]。每个位置的扩展次数摊还 O(1)，总时间 O(n)。

不变量与正确性。 区间 [l,r] 是已确认的回文；回文的对称性保证镜像中心在区间内的半径与原中心相等，因此直接复用不会高估——用 min 截断到区间边界则确保不会越过尚未确认的区域。向外扩展只发生在区间边界或区间外，且每次成功扩展都推进 r，故总扩展次数 O(n)。

Rust 实现要点。 奇数半径至少为 1，偶数半径可为 0。偶数分支在 i=0 时没有镜像可查，要直接取 0；更新 [l,r] 前要判断半径大于 0，否则 i + k − 1 在 k=0 时会下溢成 usize::MAX，把 r 污染成巨大值，下一次镜像下标越界——这是本单元真实踩过的坑。while 条件里 i >= k 与 i - k > 0 分别守住奇、偶扩展的左边界。

复杂度。 O(n) 时间与 O(n) 空间（两个半径数组）。半径数组的语义值得再强调：d1[i] 是以 i 为中心的奇数回文的"层数"，从长度 1 的长度 3、5……依次展开，因此 d1[i]=3 同时贡献了长度 1、3、5 三个回文；d2[i] 是以 i 左侧缝隙为中心的偶数回文层数，d2[i]=2 贡献长度 2 与 4 两个回文。于是所有回文子串个数就是 Σd1 + Σd2，最长回文长度是 max(2·d1−1, 2·d2)。有了这两个数组，回文相关的大多数查询都能在 O(1) 内回答——这正是"预处理换查询"思路在回文问题上的落地。要注意奇数与偶数中心的总数都是 n，两种回文互不重叠也不会遗漏：任何回文的中心要么落在一个字符上，要么落在两个字符之间，二者必居其一。

下面的程序在 ababa 上打印 d1=[1,2,3,2,1]、d2 全 0、最长回文 5，并对随机串把半径数组与逐中心朴素扩展的结果对照 400 组。

rustRust · 标准库64 行
#![allow(dead_code)]
fn manacher(s: &[u8]) -> (Vec<usize>, Vec<usize>) {
let n = s.len();
let mut d1 = vec![0usize; n];
let (mut l, mut r) = (0usize, 0usize);
for i in 0..n {
let mut k = if i > r { 1 } else { d1[l + r - i].min(r - i + 1) };
while i >= k && i + k < n && s[i - k] == s[i + k] { k += 1; }
d1[i] = k;
if i + k - 1 > r { l = i - (k - 1); r = i + k - 1; }
}
let mut d2 = vec![0usize; n];
l = 0; r = 0;
for i in 0..n {
let mut k = if i > r || i == 0 { 0 } else { d2[l + r - i + 1].min(r - i + 1) };
while i - k > 0 && i + k < n && s[i - k - 1] == s[i + k] { k += 1; }
d2[i] = k;
if k > 0 && i + k - 1 > r { l = i - k; r = i + k - 1; }
}
(d1, d2)
}
fn naive(s: &[u8]) -> (Vec<usize>, Vec<usize>) {
let n = s.len();
let mut d1 = vec![0usize; n];
let mut d2 = vec![0usize; n];
for i in 0..n {
let mut k = 1;
while i >= k && i + k < n && s[i - k] == s[i + k] { k += 1; }
d1[i] = k;
let mut k2 = 0;
while i - k2 > 0 && i + k2 < n && s[i - k2 - 1] == s[i + k2] { k2 += 1; }
d2[i] = k2;
}
(d1, d2)
}
fn longest_pal(s: &[u8]) -> usize {
let (d1, d2) = manacher(s);
let mut best = 0;
for i in 0..s.len() { best = best.max(2 * d1[i] - 1).max(2 * d2[i]); }
best
}

Manacher 与 KMP、Z 函数在思想上完全同构：都是维护一个"已确认区间"，区间内直接复用、区间外才开始真正的比对，并用摊还分析证明总比对次数线性。区别只在复用的对称关系——KMP 是前后缀对齐，Z 是整串与后缀对齐，Manacher 是回文左右镜像对齐。把这三种"复用"讲清楚，就抓住了字符串线性算法共同的魂。

29.6 三种结构的对照与选择

结构 解决问题 预处理 单次查询 确定性 主要成本
AC 自动机 多模式匹配 O(模式总长) O(文本长 + 匹配数) 是 每节点 26 项转移表
后缀数组 后缀排序、全局统计 O(n log n) O(1) 查排名 是 倍增的多次计数排序
Kasai + SA LCP、不同子串 O(n log n) O(n) 一次算完 是 需先有 sa 与 rank
Manacher 回文半径、最长回文 O(n) O(1) 读半径 是 两个半径数组

选择逻辑：多个模式一次匹配选 AC；需要后缀排序、不同子串、最长重复子串等全局信息选后缀数组 + Kasai；只关心回文选 Manacher。AC 与后缀数组可以组合——在 AC 的文本扫描中记录匹配位置区间，再用后缀数组做重复检测。三者的确定性都优于哈希，适合对错判零容忍的场景。

大白话先用直觉把它讲通

三种工具其实在回答三个不同的问题。AC 自动机问"这段文字里有没有这些词、各有几个"，一次走完就全知道。后缀数组问"这本书的所有结尾片段按字典序怎么排队"，排好之后像"有多少种不同片段"这种问题就变成简单加法。Manacher 问"每个点往两边能对称多远"，靠照镜子把重复劳动全省掉。它们都用了同一个诀窍：别每次从头来，记住上次的结果接着干。

29.7 边界、实现陷阱与工程取舍

AC 自动机。 只查一层 fail 会漏转移，必须沿 fail 链走到有对应边的节点；字符集固定 26 字母时 (c - b'a') 对非小写字符会下溢，输入要先归一化或显式过滤；输出链只指向最近的终止 fail 祖先，不能在统计时沿整条 fail 链线性扫描，否则退化。

后缀数组与 Kasai。 哨兵必须严格小于所有真实字符且唯一，否则短后缀的序会出错；第二关键字越界取 0 的约定要与哨兵 rank 一致；计数排序的键必须是 c[pn[i]] 而非 c[pn[i]+shift]；Kasai 的 rank 要按 sa 反填，且遇到 sa 末位要把 k 清零。字符串很长时 n*(n+1)/2 要用 usize 甚至 u128 防溢出。

Manacher。 偶数半径为 0 时不可更新 [l,r]，否则 i+k−1 下溢污染右端点；i=0 时偶数分支无镜像可查，直接取 0；镜像下标 l+r−i（奇）与 l+r−i+1（偶）要求当前区间左端严格小于 i，初始化与更新顺序要保证这一点。

工程取舍。 三个结构都用定长数组追求缓存友好，代价是字符集受限——处理 Unicode 时要先把文本转成 Vec<char> 并重新编号，或用 HashMap。AC 的 26 项转移表在模式很多、节点数大时内存可观，可改用稀疏边 + fail 回退的链式实现换空间。后缀数组 O(n log n) 已足够优秀；若追求 O(n) 可用 SA-IS，但实现复杂度陡增，非必要不上。验证策略上，本单元四个程序都把朴素版放进同一个文件：AC 对每个模式独立枚举，后缀数组用标准库排序后缀，Kasai 用 HashSet 枚举子串，Manacher 对每个中心重新展开。这种"同源对拍"能第一时间暴露实现细节错误，比手工构造用例覆盖面广得多。

坑这里最容易踩

坑：三个工具对'输入字符集'都有隐含假设。AC 的 26 字母转移表、后缀数组的 s[i] - b'a' + 1 映射、Manacher 按字节比较，都默认输入是小写 ASCII。对 UTF-8 中文串按字节做 Manacher 会把一个汉字的多个字节当成多个字符，得到错误回文；对混合大小写的文本做 AC 会下标越界。正确做法是先明确字符集：要么归一化到目标字母表，要么按字符切分后重新编号，绝不能把字节序列直接喂给假设 ASCII 的实现。
