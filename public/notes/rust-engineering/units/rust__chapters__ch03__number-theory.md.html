32.1 模运算的代数底座与问题全景

数论算法在竞赛与工程里出现的频率不高，但一旦出现就是"不会就完全做不出"的硬门槛。本单元围绕五个工具展开：快速幂 a^e mod m、扩展欧几里得、乘法逆元、中国剩余定理、素数判定。它们的共同底座是同余类环 Z/mZ：加减乘在模 m 下封闭，加法有单位元 0，乘法有单位元 1，但乘法逆元并非总存在——只有与 m 互质的元素才有逆元。把这一点记牢，后面一半的边界条件都能自己推出来。

这些工具并非纯理论摆设。快速幂与逆元是 RSA、Diffie-Hellman implementations 里最基础的操作；CRT 让大模数运算拆成几个小模数并行计算后再合并，是许多密码库提速的手段；素数判定用于生成密钥参数；扩展欧几里得则常用于有理数化简与线性同余求解。即便不做密码学，组合数取模、哈希函数、随机种子生成也处处用到它们。理解了应用场景，就明白为什么这些函数对"结果必须精确、失败必须显式"有如此高的要求——它们在系统里往往是正确性的最后一道防线，而不是可有可无的优化。

问题定义要精确。快速幂：给定 a、e、m，求 a^e 除以 m 的余数，e 可达 1e18。逆元：给定 a、m，找 x 使 a·x ≡ 1 (mod m)，不存在时明确报告。CRT：给定若干 (rᵢ,mᵢ)，找 x 使 x ≡ rᵢ (mod mᵢ) 全部成立，返回最小非负解与 lcm，矛盾时报告无解。素数判定：给定 n < 2^64，判断其是否为素数。

再往深一层看，Z/mZ 与整数的本质差异在于"除法不是总运算"。整数里 a·x=b 总有 x=b/a（只要整除），模世界里却要看 gcd(a,m) 是否整除 b；这正是线性同余方程与逆元存在条件的来源。另外，模运算满足 (a+b) mod m = ((a mod m)+(b mod m)) mod m，这条"先取模再运算"的同态性质是所有快速幂与 CRT 算法合法性的根源——它允许我们把大数拆成小段，而不改变最终余数。Rust 的整数除法对负数向零取整，-3 % 11 得到 -3；在数论代码里若需要规范余数，应写 ((x % m) + m) % m，否则负数余数会让对拍出现"值不同但同余"的假失败。

大白话先用直觉把它讲通

模运算就像钟面上的算术——过了 12 点又回到 1。快速幂是"把指数写成二进制，看到一位 1 就乘一次、每走一位就把底数平方"，十几步就能算完 10 亿次方。扩展欧几里得像倒着走辗转相除的台阶，顺便记下"每一步余数是怎么由原来的两个数拼出来的"。逆元就是除法在钟面上的替身：不能真除，就乘上那个"抵消它"的数。CRT 是把几条不同模数的余数线索拼成唯一答案。Miller-Rabin 则是拿几个特殊底数去"试探"一个数是否装得像素数。

32.2 快速幂：二进制指数与 mul_mod 的溢出防线

快速幂（binary exponentiation）的核心恒等式是 a^e = (a²)^(e/2) 当 e 为偶数，a·a^(e-1) 当 e 为奇数。把 e 写成二进制后，从低位到高位扫描：当前底数 a 依次代表 a¹、a²、a⁴、a⁸……；若当前位为 1，就把这个幂乘进答案。不变量可以写成：每轮循环开始时，res · a^e == 原始 a^原始e (mod m)。位为 1 时 res 乘 a、e 减 1；随后 a 平方、e 右移一位；两步都保持等式，循环结束 e=0，res 即答案。

Rust 里最关键的一行是 mul_mod：((a as u128 * b as u128) % m as u128) as u64。两个 u64 相乘的最大值是 (2^64-1)² = 2^128 - 2^65 + 1，严格小于 2^128，所以 u128 恰好装得下，不会溢出。若 m 也是 u128 量级就不能这么做，需要蒙哥马利乘法或 Russia-peasant 加倍法。另一个边界是 m=1：所有余数都是 0，必须提前返回，否则 a %= 1 后虽然也得到 0，但显式处理更清晰。e=0 时任何 a 的 0 次幂都是 1（包括 a=0，约定 0^0=1），循环不进入，res 保持 1，正确。

手动走一遍 3^13 mod 17 能看清循环：13 的二进制是 1101。初始 res=1、a=3、e=13（1101）；第 1 轮最低位 1，res=3，a=9，e=6（110）；第 2 轮最低位 0，res 不变，a=81≡13，e=3（11）；第 3 轮最低位 1，res=3·13=39≡5，a=13²=169≡16，e=1；第 4 轮最低位 1，res=5·16=80≡12，e=0 结束。答案 12 与程序输出一致。注意循环次数是 e 的二进制位数（这里 4 次），不是 e 本身（13 次）——这就是 O(log e) 的直观来源。进入循环前 a %= m 不是可有可无：若 a 远大于 m，第一次 mul_mod(a,a,m) 的 a 虽已在 u64 范围内但平方会触发中间量问题，先约简能保证每轮底数都小于 m。

补一句值得记住的细节

若指数 e 本身大到无法装进 u64（例如以十进制字符串给出），可以在已知 m 为素数时用费马小定理把 e 约简到 e mod (m-1) 再计算；若 m 为合数则要用欧拉定理 e mod φ(m)，而计算 φ(m) 需要 m 的素因子分解。这是"把指数降维"的常见技巧，也是快速幂与素数判定经常成对出现的原因。约简指数时别忘了处理 e=0 的约定：任何非零底数的 0 次幂为 1，即使约简后也是 1，二者一致。

#![allow(dead_code)]
// u64 相乘的中间结果最大 (2^64-1)^2 < 2^128，故 u128 一定装得下。
fn mul_mod(a: u64, b: u64, m: u64) -> u64 {
((a as u128 * b as u128) % m as u128) as u64
}
/// 快速幂：O(log e) 次模乘，指数按二进制位从低到高消费。
fn mod_pow(mut a: u64, mut e: u64, m: u64) -> u64 {
if m == 1 { return 0; }
let mut res = 1u64;
a %= m;
while e > 0 {
if e & 1 == 1 { res = mul_mod(res, a, m); }
a = mul_mod(a, a, m);
e >>= 1;
}
res
}
fn main() {
println!("2^10 mod 1000 = {}", mod_pow(2, 10, 1000));
println!("3^13 mod 17 = {}", mod_pow(3, 13, 17));
println!("7^0 mod 13 = {}", mod_pow(7, 0, 13));
println!("123456789^987654321 mod 1e9+7 = {}", mod_pow(123456789, 987654321, 1_000_000_007));
// 费马小定理求逆：p 为素数时 a^(p-2) 是 a 的逆元。
println!("inv(3) mod 1e9+7 = {}", mod_pow(3, 1_000_000_007 - 2, 1_000_000_007));
}

32.3 扩展欧几里得：不变量 ax+by=gcd

普通欧几里得算法反复用 gcd(a,b) = gcd(b, a mod b) 把规模缩小，终止于 b=0。扩展版多记一组系数：递归到底时 a·1 + b·0 = a = gcd；回溯时若 b*q + (a mod b)*t = g，其中 q、t 是子问题的系数，把 a mod b = a - ⌊a/b⌋·b 代入得 a*t + b*(q - ⌊a/b⌋*t) = g，于是当前系数是 x = t、y = q - (a/b)*t。这就是代码里 *x = y1; *y = x1 - (a/b)*y1; 的来历。

不变量是 a*x + b*y == gcd(a,b)，且递归参数满足 b < a（a,b 为正时），因此深度 O(log min(a,b))。注意 a 或 b 为 0 的边界：exgcd(0, b) 会进入 b≠0 分支，递归调用 exgcd(b, 0 % b = 0) 返回 g=b、x=1、y=0，回溯得 x=0、y=1，验证 0·0 + b·1 = b，正确。代码用 i128 而非 i64，是因为回溯中的 x1 - (a/b)*y1 可能达到量级 b，a、b 接近 1e18 时 i64 会溢出。

这条等式还有一个名字——贝祖等式（Bézout's identity）：gcd(a,b) 是形如 a·x+b·y 的最小正整数。它不只用来求逆元，也是 CRT 中"diff 能否被 g 整除"判据的理论来源：a·x ≡ b (mod m) 有解当且仅当 gcd(a,m) | b。递归版代码短小，但每层都有一次函数调用与两个 &mut i128 参数传递；追求常数时可改写为迭代版，用四个滚动变量维护系数。本单元选递归版，是因为回溯公式与推导一一对应，读者能直接从数学证明映射到代码，减少"知道结论但不知道为什么"的风险。实践中还有一种常见错误：把 x1 - (a/b)*y1 写成 y1 - (a/b)*x1，这在对 a=17、b=5 的手推里立刻暴露（会得到 7 与 -2，验算 17·7+5·(-2)=109≠1）。

补一句值得记住的细节

系数并不唯一：若 (x,y) 是一组解，则 (x+k·(b/g), y-k·(a/g)) 也是解，k 为任意整数。exgcd 返回的是绝对值较小的一组，但不保证 x 落在 [0,m) 内；mod_inv 里那次 (x % m + m) % m 才是把它规范成最小非负代表。对拍时若忘记归一化，"值不同但同余"的两个逆元会被判定为不等，产生假 mismatch——这类问题不是算法错，而是输出表示不统一。把归一化写在函数内部，是避免调用方各自犯同一错误的最省事做法。

#![allow(dead_code)]
/// 扩展欧几里得：返回 gcd(a,b)，并把系数写进 x、y 使 a*x + b*y = gcd(a,b)。
/// 要求 a, b 为非负整数（不同时为 0）。
fn exgcd(a: i128, b: i128, x: &mut i128, y: &mut i128) -> i128 {
if b == 0 {
*x = 1;
*y = 0;
return a;
}
let mut x1 = 0i128;
let mut y1 = 0i128;
let g = exgcd(b, a % b, &mut x1, &mut y1);
*x = y1;
*y = x1 - (a / b) * y1;
g
}
/// 用 exgcd 求 a 在模 m 下的乘法逆元，不存在（gcd != 1）时返回 None。
fn mod_inv(a: i128, m: i128) -> Option<i128> {
let (mut x, mut y) = (0i128, 0i128);
let g = exgcd(a % m, m, &mut x, &mut y);
if g != 1 { return None; }
Some(((x % m) + m) % m)
}
fn main() {
for (a, b) in [(240i128, 46i128), (30, 12), (17, 5)] {
let (mut x, mut y) = (0i128, 0i128);
let g = exgcd(a, b, &mut x, &mut y);
println!("exgcd({},{}) g={} x={} y={} check={}", a, b, g, x, y, a * x + b * y);
}
for (a, m) in [(3i128, 11i128), (10, 17), (6, 9)] {
println!("inv({},{}) = {:?}", a, m, mod_inv(a, m));
}
// 验证逆元：a * inv(a) mod m 必须为 1。
let a = 123456789i128;
let m = 1_000_000_007i128;
if let Some(inv) = mod_inv(a, m) {
println!("inv(123456789,1e9+7) = {} check = {}", inv, a * inv % m);
}
}

32.4 逆元：存在条件与两种求法

乘法逆元定义在 Z/mZ 中：找 x 使 a·x ≡ 1 (mod m)。存在当且仅当 gcd(a,m)=1。证明很短：若 a·x + m·y = 1 有解，则 a·x ≡ 1；反之若 a·x ≡ 1，则 a·x - 1 被 m 整除，即存在 y 使 a·x + m·y = 1，故 gcd(a,m) 整除 1。这个充要条件决定了所有边界：inv(6,9)=None，因为 gcd=3；inv(10,17)=Some(12)，因为 10×12=120=7×17+1。

两种求法各有适用场景。exgcd 法对任意 m 有效，只要互质，复杂度 O(log m)，代码直接复用上一节。费马小定理法只在 m 为素数时成立：a^(m-1) ≡ 1，故 a^(m-2) 是逆元；它依赖快速幂，复杂度也是 O(log m)，但实现更短，且容易与模幂代码共享。工程里常见 1e9+7、998244353 这类素数模数，用费马法最省事；若模数是合数（例如某些哈希取模），必须回退到 exgcd，否则会得到错误答案。

用一个反例把费马法的边界钉死：m=9、a=2，gcd=1 所以逆元存在（是 5，因为 2×5=10≡1），但费马公式给出 2^(9-2)=2^7=128≡2 (mod 9)，完全不对。原因很简单：费马小定理的前提"m 是素数"不成立。因此接口设计上，费马法函数体里要么用 debug_assert!(is_prime(m)) 守住前提，要么干脆在文档里写清"调用方保证 m 为素数"，不能让调用者误以为它和 exgcd 等价。另一个细节：mod_inv 返回 Option<i128> 而不是直接返回 i128，把"不存在"编码进类型系统，迫使调用方用 if let 或 ? 处理；这比返回 0 或 panic 更安全——毕竟 0 永远不是任何模数下的逆元，把它当错误哨兵看似可行，但一旦有人忘记检查就会静默算错。

坑这里最容易踩

这里是坑：别把"m 是素数"和"a 与 m 互质"混为一谈。费马法只校验前者，若 m 是合数而 a 恰好互质（如 m=9、a=2），a^(m-2)=2^7=128≡2 (mod 9)，并不是逆元（正确逆元是 5）。另一个坑是负数：a % m 在 Rust 中可能为负，mod_inv 里对 x 做 ((x % m) + m) % m 才是规范非负余数；直接用 x 会得到负逆元，虽在数学上等价，但打印出来或与暴力比对时会不一致。

补一句值得记住的细节

逆元的用途远不止"做除法"。组合数 C(n,k) mod p 需要 k! 与 (n-k)! 的逆元；线性同余方程 a·x ≡ b (mod m) 的解是 x ≡ b·inv(a)；许多哈希与随机算法的归一化步骤也要除以模数。把逆元当成"模世界的除法"来记，比背公式更有用。

32.5 CRT：逐条合并同余方程

中国剩余定理解决"多个模数下的余数能否拼成一个数"。先讲经典情形：模数两两互质时，解模 M=∏mᵢ 唯一。构造法用 Mᵢ=M/mᵢ 与 tᵢ=inv(Mᵢ mod mᵢ)，则 x = Σ rᵢ·Mᵢ·tᵢ 是解。但构造法要算大数乘积；增量合并法更实用：维护当前解 x 与当前模数 mod_now（初始 0、1），读入新方程 x ≡ r (mod n)，设新解为 x + mod_now·t，代入得 mod_now·t ≡ r - x (mod n)。若 g=gcd(mod_now,n) 不整除 r-x，则无解；否则两边除 g，用 exgcd 求 mod_now/g 模 n/g 的逆，得到 t 的最小非负代表，更新 mod_now ← lcm(mod_now,n)。

不变量是：每轮结束后，x 满足目前已合并的全部同余式，且 mod_now 是这些模数的 lcm。初始 vacuously 成立；增量步骤保证新解满足新方程且不破坏旧方程（因为加的是 mod_now 的整数倍）；模数更新为 lcm 保证解在模 lcm 下唯一。这个视角自然涵盖不互质的情形：crt([1,3],[4,6]) 中 gcd(4,6)=2 整除 3-1，故有解 x=9，模 12；crt([0,1],[2,4]) 中 gcd=2 不整除 1-0，故无解。手算校验：9 mod 4=1、9 mod 6=3，正确。

把 crt([2,3,2],[3,5,7]) 的增量过程完整展开，能看到每一步的数从哪里来：初始 x=0、mod_now=1。第一条 x≡2 (mod 3)：exgcd(1,3) 得 s=1，diff=2，step=2，lcm=3，x=2。第二条 x≡3 (mod 5)：exgcd(3,5) 得 3·2+5·(-1)=1，s=2；diff=3-2=1，coef=1·2=2，step=2，lcm=15，x=(2+3·2) mod 15=8。第三条 x≡2 (mod 7)：exgcd(15,7) 得 15·1+7·(-2)=1，s=1；diff=2-8=-6，coef=-6，step=(-6 mod 7)=1，lcm=105，x=(8+15·1) mod 105=23。程序输出 Some((23,105))，与手算逐位一致。这里 step 为什么要取模 n/g？因为 t 的合法取值是一族等差数列，取最小非负代表既保证 x 落在 [0,lcm)，又让结果可复现；若不取模，x 会随 exgcd 返回的系数大小漂移，对拍时"同一个解的不同代表"会造成假 mismatch。增量合并的顺序不影响最终的最小解与 lcm，只影响中间 x 的数值，因此不同教材给出的构造式长得不同却结果一致；实现时保持固定顺序即可，不必纠结哪条方程先合并。

fn exgcd(a: i128, b: i128, x: &mut i128, y: &mut i128) -> i128 {
if b == 0 { *x = 1; *y = 0; return a; }
let (mut x1, mut y1) = (0i128, 0i128);
let g = exgcd(b, a % b, &mut x1, &mut y1);
*x = y1;
*y = x1 - (a / b) * y1;
g
}
/// 合并同余方程组 x ≡ rem[i] (mod m[i])，返回 (最小非负解, 所有模数的 lcm)。
/// 若存在矛盾则返回 None。
fn crt(rem: &[i128], m: &[i128]) -> Option<(i128, i128)> {
let (mut x, mut mod_now) = (0i128, 1i128);
for i in 0..rem.len() {
let n = m[i];
let (mut s, mut t) = (0i128, 0i128);
let g = exgcd(mod_now, n, &mut s, &mut t); // mod_now*s + n*t = g
let diff = rem[i] - x;
if diff % g != 0 { return None; }
// mod_now * s ≡ g (mod n)，两边同除 g 后求 step。
let coef = (diff / g) * s;
let step = ((coef % (n / g)) + (n / g)) % (n / g);
let lcm = mod_now / g * n;
x = (x + mod_now * step) % lcm;
if x < 0 { x += lcm; }
mod_now = lcm;
}
Some((x, mod_now))
}

32.6 素数判定：从试除到 Miller-Rabin

试除法用 d 从 2 扫到 √n，复杂度 O(√n)：n=1e12 时要 1e6 次除法，尚可；n<2^64 时 √n 达 4e9，不可行。Miller-Rabin 基于费马小定理的逆否：若 n 是奇素数，对任意 a 与 n 互质有 a^(n-1) ≡ 1 (mod n)。把 n-1 写成 d·2^s（d 为奇数），考察序列 a^d, a^(2d), ..., a^(2^(s-1)d)。若 n 为素数，该序列要么首项为 1，要么某一项为 n-1（因为 1 的平方根模素数只有 ±1）。若某个 a 使这两条都不满足，a 就是"合数见证"，n 必为合数。

确定性版本的关键是底数集合：对 n < 2^64，取 [2, 325, 9375, 28178, 450775, 9780504, 1795265022] 这七个数已证明足够。代码先做小素数试除，命中就直接返回，既加速又避免对偶数跑完整流程。分解 d·2^s 时 s 用 u32 足够（n<2^64 时 s<64）。base % n == 0 的底数要跳过，否则 a=0 会让首项为 0 而误判。

为什么只做一次费马测试不够？存在卡米耶尔数（如 561、1105、1729），它们对所有与自身互质的底数都满足 a^(n-1)≡1，却不是素数。Miller-Rabin 的加强在于检查"平方根只能是 ±1"：若 a^d ≡ 1 或序列中出现 n-1，则通过；否则任何一步出现非 ±1 的平方根，就证明 n 不是素数。这个加强让卡米耶尔数无处遁形——561 在本实现里直接被小素数 3 筛掉，而对 1105 等数，七个底数中至少一个会给出见证。若把底数改成随机选取并重复 k 轮，就得到概率版 Miller-Rabin：单轮误判率不超过 1/4，k=20 时低于 10^-12；本单元选确定性底数集合，牺牲了极小量常数换取"无随机、可复现"的判定结果，适合对拍与回归测试。工程上若 n 超过 u64（如大数库场景），只能用概率版并显式声明置信度。

32.7 复杂度、数值边界与工程取舍

五个工具的复杂度都很轻：快速幂 O(log e)，exgcd 与逆元 O(log m)，CRT 合并 k 个方程 O(k·log M)，Miller-Rabin 每轮 O(log³ n)（用 u128 模乘时退化为 O(log² n) 的常数因子）。真正的工程风险不在时间复杂度，而在整数表示：中间量用 u128/i128 是底线，除非你能证明所有乘积都在目标类型范围内。

测试层面也有讲究。数论函数适合写"性质测试"而非只写固定样例：例如对任意互质 a、m，逆元必须满足 a*inv(a,m) % m == 1；对任意 e≥0，mod_pow(a,e+1,m) == mul_mod(mod_pow(a,e,m),a,m)；CRT 返回的解代回每个原方程都必须成立。这些性质不依赖具体数值，用随机数据批量验证，覆盖比手写十个用例更广。本单元末尾的对拍程序就是这类性质测试的完整样板。同时保留 3^13 mod 17 这类手算可核对的小样例，作为"理解正确"的锚点——性质测试保证不回归，手算样例保证没把定义理解反，两者缺一不可。

大白话先用直觉把它讲通

数论代码看着短，翻车几乎都在"数字装不下"和"前提没检查"两件事上。模乘先升位再取模，逆元先看互质，CRT 先看余数差能否被 gcd 整除，Miller-Rabin 先跳过模为 0 的底数。把这些前提写成代码里的显式分支，而不是脑子里的默认假设，代码就稳了。

再强调一个容易被忽视的取舍：i128 不是免费的。它的乘除在软件里展开成多条指令，比 u64 慢数倍；若你的算法在热点路径上执行上亿次模乘，应该先用 u128 保证正确，再用基准测试确认是否需要引入蒙哥马利乘法等优化。反过来，若输入范围明确小于 1e9（例如数组下标相关的组合数），全程 u64 甚至 u32 就够了，盲目用 i128 只会拖慢速度。选择位宽的正确顺序是：先证明上界，再选最小够用类型，最后在边界处显式升位——本单元代码把升位集中在 mul_mod 与 exgcd 的回溯式里，正是这个原则的体现。

坑这里最容易踩

这里是坑：CRT 里 lcm = mod_now / g * n 的除法必须在乘法之前。写成 mod_now * n / g 会先溢出，即使数学结果相同。同理，step 取模时用 n/g 而不是 n——因为 mod_now/g 与 n/g 才互质，逆元只在模 n/g 下存在；若误用 n，((coef % n) + n) % n 得到的 t 在模 n/g 意义下也许不是最小代表，虽仍满足方程，但可能与暴力枚举的最小解不一致，导致对拍假失败。

API 设计上还有两处值得较真。其一，CRT 返回 (解, lcm) 而不只是解：调用方往往需要知道解的唯一性模数，例如把解再代入另一个方程时，lcm 就是新的 mod_now。其二，逆元与 CRT 都用 Option 表达"无解"，而不是 panic。数论函数的失败是正常业务分支（输入不满足前提），用 panic 会把可恢复的错误变成进程崩溃；用 Result<_, MathError> 也可以，但当错误信息只有"不互质"一种时，Option 更轻。对拍代码因此可以写成 assert_eq!(crt(...), brute)，直接比较 Option 的相等性，无需额外解包——Option<(i128,i128)> 派生了 PartialEq，这让裁判代码异常简洁。

32.8 随机对拍：四组独立裁判

对拍程序用固定种子 31415926 的 xorshift64，四组裁判互不复用被测逻辑：快速幂对朴素连乘、exgcd 对独立 gcd 循环并验算 ax+by、逆元先独立判断 gcd 再比对存在性与乘积、CRT 对"枚举 0..lcm 所有 x"、Miller-Rabin 对试除法遍历 2..5000。任何一处 mismatch 都计数并打印样本。

固定种子的价值在于"失败可复现"：若某天把种子改成一个新值后出现 mismatch，只要把这个值和失败样本一起记录，任何人都能在任意机器上重跑同一序列。相比之下，用系统时间做种子看似"覆盖更广"，但失败无法复现，调试成本极高。xorshift64 的状态只有一个 u64，移位异或三步即可推进，关键性质是周期 2^64-1（种子非 0）；它不保证低位均匀，但对"生成 a、e、m"这种用途完全够用。CRT 裁判选择小模数池 [3,4,5,6,7,11]，最大 lcm 为 4620，枚举全部 x 只需几千步；若把模数换成 1e9+7 级别，暴力枚举就跑不完，这正是"对拍规模要小到暴力可行、大到覆盖分支"的原则。

值得单独讲一个真实发生的教训：对拍第一版把"逆元一定存在"当成隐含前提，对所有 a∈[1,60) 都期待 Some(inv)，结果报出 13 次 mismatch。排查后发现这些样本是 a=11、m=11 之类——根本不互质，None 才是正确答案。也就是说，错的是对拍自己，不是被测代码。修正版先用独立的 gcd 循环判定可逆性，再分两路比较：可逆则验 a*inv % m == 1，不可逆则要求 None。最终输出里 non_invertible=13 mismatches=0，正好把这 13 个样本从"错误"翻转成"正确覆盖的边界"。这件事说明：对拍的裁判必须比被测代码更笨、更可证明，任何"理所当然"的假设都要显式检查。

}
fn crt(rem: &[i128], m: &[i128]) -> Option<(i128, i128)> {

for i in 0..rem.len() {
let n = m[i];
let (mut s, mut t) = (0i128, 0i128);

if diff % g != 0 { return None; }

x = (x + mod_now * step) % lcm;
if x < 0 { x += lcm; }

32.9 自检与练习

回顾本单元，五个工具其实共享一条思路：把"大"问题拆成可验证的"小"步骤，再用一个不变量把步骤串起来。快速幂拆的是指数位，不变量是 res·a^e 不变；exgcd 拆的是辗转相除，不变量是 a·x+b·y=g；CRT 拆的是逐条同余，不变量是 x 满足已合并方程且模数为 lcm；Miller-Rabin 拆的是平方序列，判据是平方根只能为 ±1。写这类代码时，先问自己"这一步之后什么没变"，比先写代码再调试高效得多。下一单元转向计算几何，会把同样的"符号即不变量"思想用在叉积与凸包上，读者可以留意两编之间的呼应：数论里的同余等式与几何里的叉积符号，都是把复杂对象压缩成一个可判定的量。

自检合上书之前问自己
  • 快速幂的不变量 res · a^e == a0^e0 (mod m) 在"当前位为 1"和"位为 0"两种分支下分别如何保持？
  • 为什么 exgcd 的系数回溯公式是 x = y1、y = x1 - (a/b)*y1？试着用 a=17、b=5 手推一遍。
  • 逆元存在的充要条件是什么？为什么费马法不能用于合数模数？
  • CRT 中 diff % g != 0 为什么等价于方程组无解？
  • Miller-Rabin 中为什么要把 n-1 拆成 d·2^s，而不是直接做一次费马测试？

动手动脑

  • 练习 1：实现"线性同余方程求解器" solve(a,b,m)，返回 a·x ≡ b (mod m) 的全部解（提示：g=gcd(a,m)，若 b%g≠0 无解，否则化归为 b/g · inv(a/g mod m/g)，解为 x0 + k·(m/g)）。用 100 组随机 a,b,m 与暴力枚举对拍。
  • 练习 2：把 CRT 改成"经典构造法"（x = Σ rᵢ·Mᵢ·inv(Mᵢ)），与增量合并法在 100 组两两互质模数上对拍；再各自处理一组不互质模数，观察构造法为何失效。
  • 练习 3：给 Miller-Rabin 加一个 witness_count(n)，返回 7 个底数中有几个是合数见证；对 561、1105、1729 等卡米歇尔数打印计数，确认它们至少被一个底数识破。
  • 练习 4：把本单元对拍种子改成你的生日（8 位数字），重跑 v32_cross.rs；四组 mismatch 应仍为 0。若不为 0，打印失败样本并判断是算法错误还是裁判前提写错——本单元 32.8 的真实教训可以借鉴。
