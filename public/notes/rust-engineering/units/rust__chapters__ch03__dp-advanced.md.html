27.1 进阶的起点：状态维度与转移结构

基础 DP 的核心是把子问题答案存进表里。进阶 DP 并没有脱离这件事，而是沿两个方向把它推到极端：改变状态的编码方式，或者改变转移的候选枚举方式。状压 DP 和数位 DP 属于前者——状态不再是简单的一维下标，而是一个二进制集合或一串尚未确定的十进制位；换根 DP 属于遍历结构的改造；单调队列优化和斜率优化属于后者——转移方程里那个"对所有 j 取 min"的循环，被数据结构压缩到摊还常数时间。

判断该用哪件工具，先看题目卡在哪里。如果瓶颈是"选出哪些元素"无法用顺序下标表达，而且规模 n 不超过二十几，就该想到状压；如果题目要求统计满足某种十进制性质的整数个数、且上界很大（比如 10^18），就该想到按位处理；如果问题定义在树上且要求每个点的答案，普通树形 DP 只能求以固定根为基准的值，换根才能铺开到所有点；如果转移是对一个滑动窗口取最值，单调队列几乎总是答案；如果转移是对所有前驱 j 取 min，且代价能拆成只与 j 有关、只与 i 有关、以及 i·j 乘积三部分，那就是斜率优化的信号。

无论哪种优化，正确的论证方式都一样：先写出暴力版本作为定义，再证明优化版本丢弃的状态或候选永远不会影响最优值。状压丢弃的是"同一集合的不同访问顺序"（因为边权只依赖于集合与终点）；数位 DP 丢弃的是"贴界前缀的具体数值"（因为一旦不贴界，剩余位的选择自由度就与前缀无关）；单调队列丢弃的是"窗口内被更新且更优的旧候选"；斜率优化丢弃的是"被前后两条直线夹住的中间直线"。把丢弃理由写成不变量，就是这类题目最可靠的调试锚点。

大白话先用直觉把它讲通

DP 进阶不是学新魔法，而是两件事。第一件是"把小本本上那条记录写得更聪明"——比如用一串 0/1 表示哪些城市已经去过，或者只记住"当前填到第几位、还剩多少数位和"。第二件是"查小本本时少翻几页"——本来每次要翻遍所有前面的记录，现在用一个队列或一把尺子直接告诉你要翻哪一页。记住这个二分：改状态，还是改转移。

坑这里最容易踩

坑：不要在没写出暴力版本之前就上优化。状压 DP 里一个非常真实的错误是"把值为 INF 的状态当成不可达而提前 continue"——可所有状态初始化都是 INF，提前跳过会让它们永远得不到计算。优化版必须和一个小规模暴力版对拍通过之后，才可信。本单元每个例子都附了 std-only 随机数据 + 暴力对照的真实运行结果。

27.2 状压 DP：TSP 的状态编码与子集枚举

问题定义。 给定 n 个城市与距离矩阵 dist，从城市 0 出发，把 1 到 n-1 每个城市恰好访问一次后回到 0，求最短回路长度。n 不超过 15。朴素做法枚举访问顺序，共有 (n-1)! 种，n=12 时已近四千万，不可接受。

状态与不变量。 定义 dp[mask][i]：已经访问的集合是 mask（二进制第 k 位为 1 表示城市 k 已访问，且第 0 位必为 1），当前停在城市 i 时的最小花费。这里 i 必须在 mask 中——因为下一条边的起点就是 i，不记录终点就无法转移。核心不变量是：对任意 mask 与其中任意 i（i≠0），dp[mask][i] 等于所有从 0 出发、恰好覆盖 mask 且终于 i 的路径的最小长度。归纳基础是 dp[1][0] = 0：只访问 0、停在 0，花费为零。归纳步骤是把 i 从路径末尾摘掉：prev = mask ^ (1<<i) 是去掉 i 后的集合，最后一个访问的城市 j 必在 prev 中，于是 dp[mask][i] = min_{j∈prev} dp[prev][j] + dist[j][i]。因为 prev < mask（去掉一个置位使整数变小），按 mask 数值递增枚举就能保证依赖已算好。

Rust 实现要点。 用 Vec<Vec<i32>> 存表，外层下标是 mask，内层是 i。位运算用 1usize << i。INF 取 i32::MAX / 4，留出加法余量。注意上一节 warn 提到的坑：不能因为 dp[mask][i] == INF 就跳过，那个判断会误伤所有尚未计算的可达状态——正确做法是只跳过"i 不在 mask 中"的无效格。最后答案是 min_{i≠0} dp[full][i] + dist[i][0]，把回程边补上。

复杂度。 状态数 2^n · n，每个状态枚举至多 n 个 j，所以时间 O(2^n · n²)，空间 O(2^n · n)。n=15 时约 1600 万状态、64MB，尚可；n=20 时状态数暴涨到两千万以上、内存超过 80MB，就要换思路了。

下面的程序同时包含状压实现、暴力排列枚举（递归回溯），以及 xorshift 随机生成器驱动的 200 组对拍。随机数据是对称距离矩阵，边权 1 到 40，城市数 3 到 7，暴力枚举 (n-1)! 种顺序仍很快。

#![allow(dead_code)]
// 状压 DP：旅行商（返回起点 0 的最短哈密顿回路）
fn tsp(dist: &[Vec<i32>]) -> i32 {
let n = dist.len();
let size = 1usize << n;
let inf = i32::MAX / 4;
let mut dp = vec![vec![inf; n]; size];
dp[1][0] = 0;
for mask in 0..size {
if mask & 1 == 0 { continue; }
for i in 0..n {
if mask & (1 << i) == 0 { continue; }
let prev = mask ^ (1 << i);
for j in 0..n {
if prev & (1 << j) != 0 {
let cand = dp[prev][j] + dist[j][i];
if cand < dp[mask][i] { dp[mask][i] = cand; }
}
}
}
}
let full = size - 1;
let mut ans = inf;
for i in 1..n {
let cand = dp[full][i] + dist[i][0];
if cand < ans { ans = cand; }
}
ans
}
fn brute(n: usize, dist: &[Vec<i32>]) -> i32 {
fn rec(perm: &mut [usize], k: usize, dist: &[Vec<i32>], best: &mut i32) {
if k == perm.len() {
let mut cost = 0;
let mut prev = 0;
for &p in perm.iter() { cost += dist[prev][p]; prev = p; }
cost += dist[prev][0];
if cost < *best { *best = cost; }
return;
}
for i in k..perm.len() {
perm.swap(k, i);
rec(perm, k + 1, dist, best);
perm.swap(k, i);
}
}
let mut perm: Vec<usize> = (1..n).collect();
let mut best = i32::MAX;
rec(&mut perm, 0, dist, &mut best);
best
}

x ^= x << 13; x ^= x >> 7; x ^= x << 17;
self.0 = x; x
}
fn range(&mut self, lo: u64, hi: u64) -> u64 { lo + self.next_u64() % (hi - lo + 1) }
}

子集枚举还有一个等价写法：先枚举 mask，再枚举 mask 的非空子集 sub = (sub-1) & mask，适合"集合划分"类问题（如把 n 个元素分成若干组）。两种枚举的复杂度都是 O(3^n) 或 O(2^n·n)，选择依据是转移需要"子集"还是"去掉一个元素"。要格外留意 mask 中是否必须包含起点 0：TSP 要求闭合回路所以必须包含，而"选若干城市使价值最大"类问题则不必，起始条件会完全不同。

27.3 数位 DP：按位枚举与上界记忆化

问题定义。 给定区间 [L, R]，统计其中十进制表示下各位数字之和恰好等于 S 的整数个数。R 可能高达 10^18，逐个枚举显然不可行。

为什么普通记忆化失效。 如果按"前 i 位的取值"设计状态，上界 R 会让不同前缀产生不同约束：前缀越接近 R，后面能填的数越少。若把前缀值也塞进状态，状态数又爆炸。数位 DP 的关键观察是引入 tight 标志：它表示当前已选前缀是否完全贴着上界。一旦某一位选了比上界对应位更小的数字，tight 就变为 false，此后剩余位的取值不再受任何上界约束，子问题只由"还剩几位"和"还剩多少数位和"决定——这正是可以记忆化的时刻。

状态与不变量。 定义 dfs(pos, sum_left, tight)：从最高位向最低位填数，已经填好 pos 位，还需要让剩下的数位和恰好等于 sum_left 的方案数；tight 表示前缀是否贴界。不变量是：函数返回值只依赖这三个参数的语义，且当 tight=false 时与前缀的具体数值无关。终止条件是 pos == digits.len()：若 sum_left 归零则找到了一个合法数，返回 1，否则返回 0。转移是枚举当前位可填的数字 d（贴界时上限是 digits[pos]，否则是 9），仅在 d ≤ sum_left 时递归到 (pos+1, sum_left-d, tight && d==limit)。前导零自然贡献 0，因此数字 0 的数位和为 0，被正确统计。区间答案 = F(R, S) − F(L−1, S)，其中 F(x, S) 统计 [0, x] 内满足条件的个数。

实现细节。 把 x 转成字符串再逐字节取位，避免反复取模的边界判断；memo 用 -1 表示未计算，维度为 (len+1) × (9·len+1)，只在 !tight 时读写——贴界状态绝不写缓存，因为它依赖具体前缀，复用会出错。若目标 S 超过最大可能数位和 9·len，直接返回 0。

复杂度。 设位数为 len，状态数约 len · 9·len，每个状态枚举 10 个数字，时间 O(len² · 90)，对 10^18（len=19）也不过几万次操作，空间 O(len²)。

#![allow(dead_code)]
fn digit_count(m: i64, target: i32) -> i64 {
if m < 0 { return 0; }
let digits: Vec<i32> = m.to_string().bytes().map(|b| (b - b'0') as i32).collect();
let n = digits.len();
let maxsum = 9 * n as i32;
if target > maxsum { return 0; }
let mut memo = vec![vec![-1i64; maxsum as usize + 1]; n + 1];
fn dfs(digits: &[i32], pos: usize, sum: i32, tight: bool, memo: &mut Vec<Vec<i64>>) -> i64 {
if pos == digits.len() { return if sum == 0 { 1 } else { 0 }; }
if !tight && memo[pos][sum as usize] != -1 { return memo[pos][sum as usize]; }
let limit = if tight { digits[pos] } else { 9 };
let mut res = 0i64;
for d in 0..=limit {
if sum >= d {
res += dfs(digits, pos + 1, sum - d, tight && d == limit, memo);
}
}
if !tight { memo[pos][sum as usize] = res; }
res
}
dfs(&digits, 0, target, true, &mut memo)
}
fn digit_sum(m: i64) -> i32 {
let mut x = m; let mut s = 0;
while x > 0 { s += (x % 10) as i32; x /= 10; }
s
}
fn range_count(l: i64, r: i64, t: i32) -> i64 { digit_count(r, t) - digit_count(l - 1, t) }

impl Rng {
fn next_u64(&mut self) -> u64 { let mut x = self.0; x ^= x << 13; x ^= x >> 7; x ^= x << 17; self.0 = x; x }
fn range(&mut self, lo: u64, hi: u64) -> u64 { lo + self.next_u64() % (hi - lo + 1) }
}
fn main() {
println!("count[0,100] digitSum=9 = {}", range_count(0, 100, 9));

let mut bad = 0;
for _ in 0..300 {
let a = rng.range(0, 2000) as i64;
let b = rng.range(0, 2000) as i64;
let (l, r) = if a < b { (a, b) } else { (b, a) };
let target = rng.range(0, 28) as i32;
let dp = range_count(l, r, target);
let mut brute = 0i64;
for x in l..=r { if digit_sum(x) == target { brute += 1; } }
if dp != brute { println!("MISMATCH l={} r={} target={} dp={} brute={}", l, r, target, dp, brute); bad += 1; break; }
}
println!("stress digit: {} (300 random cases)", if bad == 0 { "OK" } else { "FAIL" });
}

数位 DP 的变体极多：统计不含某数字的个数、统计能被 m 整除的个数（把余数加入状态）、统计恰好有 k 个某数字等。共同套路是把"附加条件"塞进 pos 之外的维度，并坚持只在 !tight 时记忆化。一个常见错误是在 tight=true 的分支里也写 memo，导致同一个缓存项被不同前缀污染——记住：贴界状态的值依赖前缀，绝不能共享。

27.4 树形 DP 进阶：换根求全源距离和

问题定义。 给定一棵 n 个点的无根树，对每个点 u 求它到所有其他点的距离之和。朴素做法对每个点跑一次 BFS/DFS，复杂度 O(n²)，n 到 10^5 就吃不消。换根 DP 把它降到 O(n)。

第一遍：自底向上。 任取 0 为根，先做一次 DFS 得到访问序 order，再用 order 的逆序（后序）计算两个量：sz[u] 是 u 的子树大小，sub[u] 是 u 到其子树内所有点的距离和。合并孩子 v 时：sz[u] += sz[v]，sub[u] += sub[v] + sz[v]——后者是因为 v 子树内每个点到 u 的距离都比到 v 多 1，共 sz[v] 个点，故加 sz[v]。此时 ans[0] = sub[0] 就是根的答案。

第二遍：自顶向下换根，核心公式。 考虑把根从 u 移到它的孩子 v。原本在 v 子树内的 sz[v] 个点，到 v 的距离比到 u 少 1，总共减少 sz[v]；其余 n − sz[v] 个点，到 v 的距离比到 u 多 1，总共增加 n − sz[v]。于是 ans[v] = ans[u] − sz[v] + (n − sz[v]) = ans[u] + n − 2·sz[v]。这个与具体形状无关、只依赖子树大小的增量公式，正是换根 DP 的交换论证核心。按 order 的前序处理每个点，就能把答案从根传播到全树。

不变量与正确性。 不变量是：处理到 u 时 ans[u] 已是以 u 为根的正确全源距离和；由上面的增量推导，传给每个孩子 v 的 ans[v] 也正确。两遍遍历分别保证子树量就绪与父方向答案就绪。

实现细节。 用显式栈做 DFS 避免深树爆栈；parent 数组初始化为 n（哨兵），从 0 出发时 parent[0]=0。第二遍仍沿 order 正序，跳过父节点即可。注意 n as i64 - 2 * sz[v] 的符号：sz[v] 可能大于 n/2，结果为负是正常的（说明 v 子树内点更多，距离和下降）。

复杂度。 两遍遍历各 O(n)，空间 O(n)（邻接表、parent、sz、sub、ans、order、栈）。

下面的程序对随机树（父节点编号恒小于子节点，保证连通无环）n=1..40 生成 150 组，用每个点 BFS 的 O(n²) 暴力法对照。

#![allow(dead_code)]
use std::collections::VecDeque;
fn dist_sums(n: usize, edges: &[(usize, usize)]) -> Vec<i64> {
let mut g = vec![Vec::<usize>::new(); n];
for &(u, v) in edges { g[u].push(v); g[v].push(u); }
let mut parent = vec![n; n];
let mut order = Vec::with_capacity(n);
let mut st = vec![0usize];
parent[0] = 0;
while let Some(u) = st.pop() {
order.push(u);
for &v in &g[u] {
if v == parent[u] { continue; }
parent[v] = u;
st.push(v);
}
}
let mut sz = vec![1i64; n];
let mut sub = vec![0i64; n];
for &u in order.iter().rev() {
for &v in &g[u] {
if v == parent[u] { continue; }
sz[u] += sz[v];
sub[u] += sub[v] + sz[v];
}
}
let mut ans = vec![0i64; n];
ans[0] = sub[0];
for &u in &order {
for &v in &g[u] {
if v == parent[u] { continue; }
ans[v] = ans[u] + (n as i64 - 2 * sz[v]);
}
}
ans
}
fn brute(n: usize, edges: &[(usize, usize)]) -> Vec<i64> {
let mut g = vec![Vec::<usize>::new(); n];
for &(u, v) in edges { g[u].push(v); g[v].push(u); }
let mut res = vec![0i64; n];
for s in 0..n {
let mut dist = vec![-1i64; n];
let mut q = VecDeque::new();
dist[s] = 0; q.push_back(s);
while let Some(u) = q.pop_front() {
for &v in &g[u] {
if dist[v] == -1 { dist[v] = dist[u] + 1; q.push_back(v); }
}
}
res[s] = dist.iter().sum();
}
res
}

27.5 单调队列优化：跳跃游戏的分段最值

问题定义。 n 个点排成一行，从 0 走到 n−1，每次可前进 1 到 k 步；落在点 i 需要支付费用 a[i]。求最小总费用。暴力转移是 dp[i] = a[i] + min(dp[j])，其中 j ∈ [max(0, i−k), i−1]，直接算是 O(nk)。

结构观察。 j 的取值窗口随 i 向右滑动：i 增加 1，窗口右端加 1、左端也加 1。窗口内的最小值可以用单调队列在摊还 O(1) 时间内维护——这正是"滑动窗口最值"的经典结构（本系列单调结构单元已铺垫过）。这里队列里装的不是数组元素本身，而是候选下标 j，并按 dp[j] 的值单调递增排列。

不变量。 队列满足三条：(1) 下标从小到大；(2) 对应的 dp 值严格递增（因为插入时会从队尾弹出所有 dp ≥ 新值的旧下标）；(3) 队首的下标一定在当前窗口 [i−k, i−1] 内（过期下标从队首弹出）。于是队首就是当前窗口 dp 最小者的下标。更新顺序很关键：先把过期的 j < i−k 从队首弹掉，再用队首更新 dp[i]，最后把 i 从队尾插入（先弹掉所有 dp ≥ dp[i] 的下标）。

Rust 实现要点。 用 VecDeque<usize>；i.saturating_sub(k) 避免 usize 下溢（i < k 时窗口左端是 0）；dp 用 i64::MAX / 4 作 INF，防止 dp[j] + a[i] 溢出。队尾弹出用 while let Some(&back) = dq.back() 加条件判断，简洁且无越界风险。

复杂度。 每个下标最多入队一次、出队一次，时间 O(n)，空间 O(k)（队列长度不超过 k+1）。相比暴力 O(nk)，当 k 与 n 同阶时是数量级的提升。

下面的程序对随机 n=1..40、k=1..8、a[i] ∈ [0,30] 生成 300 组，用 O(nk) 双循环暴力法对照。

rustRust · 标准库58 行
#![allow(dead_code)]
use std::collections::VecDeque;
// dp[i] = a[i] + min(dp[j]) for j in [i-k, i-1]
fn jump_min(a: &[i64], k: usize) -> i64 {
let n = a.len();
let mut dp = vec![i64::MAX / 4; n];
dp[0] = a[0];
let mut dq: VecDeque<usize> = VecDeque::new();
dq.push_back(0);
for i in 1..n {
while let Some(&front) = dq.front() {
if front < i.saturating_sub(k) { dq.pop_front(); } else { break; }
}
if let Some(&j) = dq.front() { dp[i] = dp[j] + a[i]; }
while let Some(&back) = dq.back() {
if dp[back] >= dp[i] { dq.pop_back(); } else { break; }
}
dq.push_back(i);
}
dp[n - 1]
}
fn brute(a: &[i64], k: usize) -> i64 {
let n = a.len();
let mut dp = vec![i64::MAX / 4; n];
dp[0] = a[0];
for i in 1..n {
let lo = i.saturating_sub(k);
for j in lo..i {
let cand = dp[j] + a[i];
if cand < dp[i] { dp[i] = cand; }
}
}
dp[n - 1]
}
struct Rng(u64);
impl Rng {
fn next_u64(&mut self) -> u64 { let mut x = self.0; x ^= x << 13; x ^= x >> 7; x ^= x << 17; self.0 = x; x }
fn range(&mut self, lo: u64, hi: u64) -> u64 { lo + self.next_u64() % (hi - lo + 1) }
}
fn main() {
let a = [3i64, 1, 4, 1, 5, 9, 2, 6];
println!("demo jump_min k=3 = {}", jump_min(&a, 3));
let mut rng = Rng(0xdead_beef_dead_beef);
let mut bad = 0;
for _ in 0..300 {
let n = 1 + rng.range(0, 40) as usize;
let k = 1 + rng.range(0, 8) as usize;
let a: Vec<i64> = (0..n).map(|_| rng.range(0, 30) as i64).collect();
let x = jump_min(&a, k);
let y = brute(&a, k);
if x != y { println!("MISMATCH n={} k={} mono={} brute={}", n, k, x, y); bad += 1; break; }
}
println!("stress monotone: {} (300 random cases)", if bad == 0 { "OK" } else { "FAIL" });
}

单调队列优化的判定信号很清晰：转移里的候选 j 构成一个连续下标区间，且区间随 i 单调滑动。若候选 j 不是连续区间（比如受另一个数组的值限制），单调队列就不适用。另一个变体是"多重背包单调队列优化"，那里把容量按余数分类后，每类内部同样是滑动窗口最值——本质完全相同。写这类代码时最常见的 bug 是更新顺序颠倒：若先用队首更新 dp[i] 再弹过期下标，就可能用一个已经滑出窗口的 j；务必把"弹过期 → 取值 → 插入"三步固定下来。

27.6 斜率优化：平方代价与单调凸包

问题定义。 给定严格递增的数列 x[0] < x[1] < ... < x[n−1]，定义 dp[0] = 0，dp[i] = min_{j<i} dp[j] + (x[i] − x[j])²。暴力对每个 i 枚举 j，复杂度 O(n²)。

代数展开：把转移变成直线查询。 展开平方项：dp[j] + x[j]² − 2·x[i]·x[j] + x[i]²。其中 x[i]² 与 j 无关，可以提到 min 外面；剩下的部分对每个 j 是一条关于变量 x[i] 的直线 y = m·t + b，斜率 m = −2·x[j]、截距 b = dp[j] + x[j]²。于是对每个 i，我们要在所有已插入的直线里，查询 t = x[i] 处的最小 y，再加上 x[i]² 就是 dp[i]。

单调凸包。 两个单调性让结构简化：因为 x 递增，插入的斜率 m = −2x[j] 严格递减；查询点 x[i] 也严格递增。这正好是单调凸包（monotonic CHT）的标准场景：直线按斜率顺序插入 deque，查询点按序推进，队首一旦被次首支配就弹出。维护凸包时用一个"交叉相乘"判定中间直线是否无用：若相邻两条直线的交点横坐标不满足单调递增（即中间直线被前后夹住），则它永远不会是最优，直接删除。

不变量与正确性。 凸包不变量是：deque 中的直线按斜率递减排列，且相邻交点横坐标严格递增——这保证了对任意查询 x，最优直线必然在 deque 中按查询顺序依次出现。查询不变量是：当前队首在所有直线中于 x[i] 处取值最小；弹出被支配的队首后，新的队首接管。用 i128 做交叉相乘，避免 b 与 m 相乘溢出。

实现细节。 useless(a, b, c) 判定用交叉相乘 (b.b−a.b)(b.m−c.m) ≥ (c.b−b.b)(a.m−b.m)，等价于"交点(a,b) ≥ 交点(b,c)"。插入新直线后从队尾循环删除无用直线。注意 head 指针：弹出队首后 head 前移，但插入只追加到队尾，需保证 head 不越界。

复杂度。 每条直线最多入队出队一次，每个查询点也单调推进，摊还 O(n) 时间与 O(n) 空间。相比暴力 O(n²) 是巨大提升。

下面的程序对随机严格递增 x（首项 0，步长 1..6）、n=2..41 生成 300 组，用 O(n²) 暴力法对照。

rustRust · 标准库68 行
#![allow(dead_code)]
#[derive(Clone, Copy)]
struct Line { m: i128, b: i128 }
fn f(l: Line, x: i128) -> i128 { l.m * x + l.b }
// slopes inserted strictly decreasing; b useless if cross(a,b) >= cross(b,c)
fn useless(a: Line, b: Line, c: Line) -> bool {
(b.b - a.b) * (b.m - c.m) >= (c.b - b.b) * (a.m - b.m)
}
// dp[0]=0, dp[i]=min_{j<i} dp[j]+(x[i]-x[j])^2, x strictly increasing
fn slope_dp(x: &[i64]) -> i64 {
let n = x.len();
let mut dp = vec![0i128; n];
let mut hull: Vec<Line> = Vec::new();
hull.push(Line { m: -2 * x[0] as i128, b: 0 });
let mut head = 0usize;
for i in 1..n {
let xi = x[i] as i128;
while head + 1 < hull.len() && f(hull[head], xi) >= f(hull[head + 1], xi) { head += 1; }
dp[i] = f(hull[head], xi) + xi * xi;
let nl = Line { m: -2 * xi, b: dp[i] + xi * xi };
while hull.len() >= 2 && useless(hull[hull.len() - 2], hull[hull.len() - 1], nl) {
hull.pop();
}
hull.push(nl);
if head >= hull.len() { head = hull.len() - 1; }
}
dp[n - 1] as i64
}
fn brute(x: &[i64]) -> i64 {
let n = x.len();
let mut dp = vec![0i64; n];
for i in 1..n {
let mut best = i64::MAX / 4;
for j in 0..i {
let d = x[i] - x[j];
let cand = dp[j] + d * d;
if cand < best { best = cand; }
}
dp[i] = best;
}
dp[n - 1]
}
struct Rng(u64);
impl Rng {
fn next_u64(&mut self) -> u64 { let mut x = self.0; x ^= x << 13; x ^= x >> 7; x ^= x << 17; self.0 = x; x }
fn range(&mut self, lo: u64, hi: u64) -> u64 { lo + self.next_u64() % (hi - lo + 1) }
}
fn main() {
let x = [0i64, 2, 5, 9, 14, 20];
println!("demo slope_dp = {}", slope_dp(&x));
let mut rng = Rng(0x0bad_f00d_0bad_f00d);
let mut bad = 0;
for _ in 0..300 {
let n = 2 + rng.range(0, 40) as usize;
let mut x = Vec::with_capacity(n);
let mut cur = 0i64;
for _ in 0..n { x.push(cur); cur += rng.range(1, 7) as i64; }
let a = slope_dp(&x);
let b = brute(&x);
if a != b { println!("MISMATCH n={} slope={} brute={}", n, a, b); bad += 1; break; }
}
println!("stress slope: {} (300 random cases)", if bad == 0 { "OK" } else { "FAIL" });
}

斜率优化的适用前提很苛刻：查询点必须单调（否则不能用 deque，要改用李超线段树或三分），斜率最好也单调（否则要排序或用动态凸包）。本题平方代价天然满足两条。工程上有两个高频陷阱：一是用 i64 做交叉相乘时溢出，务必升到 i128；二是 useless 里的大于等于与大于的选择——在斜率严格递减、求最小值的设定下用 >= 删除中间直线是正确的，但若改成求最大值或斜率递增，符号要全部重新推导，最好用小数据对拍兜底。

27.7 五种手段的横向对照与选择地图

把五种手段放在一起看，差异就清楚了。状压与数位改变的是"状态空间怎么编码"，换根改变的是"树上怎么遍历"，单调队列与斜率优化改变的是"转移时怎么少枚举"。

手段 状态/结构变化 优化对象 时间复杂度 适用信号 典型陷阱
状压 DP 集合编码成整数 状态维度 O(2ⁿ·n²) n ≤ 20 且涉及"选哪些" 把 INF 状态误跳过
数位 DP 按位 + tight 状态维度 O(len²) 统计满足数位条件的数 贴界时写 memo 污染缓存
换根 DP 两遍遍历 遍历顺序 O(n) 树上求每个点的答案 父方向增量公式写错
单调队列 deque 存候选 转移候选 O(n) 转移是滑动窗口最值 弹过期与取值的顺序颠倒
斜率优化 凸包维护直线 转移候选 O(n) 代价可拆成 j 项 + i·j + i 项 交叉相乘溢出、符号错

选择时先问"状态能不能直接写出来"。若题目自然地按位置、按容量推进，状态没问题，瓶颈在转移，那就看转移结构：候选是连续窗口用单调队列，候选是全前驱且代价可拆用斜率优化。若题目根本无法用位置下标描述（状态里必须装一个集合），才考虑状压。若题目在树上且要所有点的答案，直接换根。若题目要统计区间内满足十进制性质的数，直接数位。

大白话先用直觉把它讲通

把这五种工具想成五金工具箱。状压是"把一堆东西编号成一个二进制串"，数位是"一位一位填数字并且记住有没有顶到天花板"，换根是"先算子树再从上往下把答案传一遍"，单调队列是"一个自动淘汰赛，永远把当前最强的候选放在队首"，斜率优化是"把每个前驱画成一条直线，用尺子量出哪条最低"。看题目长什么样，就伸手拿哪件工具。

27.8 工程取舍、边界陷阱与调试清单

边界条件清单。 状压：mask 是否必须含起点、n=0 时的空集、1 << i 的 usize 类型与溢出（n 太大直接放弃该法）；数位：m<0 返回 0、目标 S 超过 9·len 提前返回、m=0 的数位和视为 0；换根：n=1 时 sz 与 ans 都平凡、树必须连通（随机数据生成时父节点编号要严格小于子节点，否则会出现自环或断连——本单元的真实对拍就踩过这个坑）；单调队列：i<k 时窗口左端是 0 要用 saturating_sub、n=1 时直接返回；斜率：n=2 时凸包只有一条直线、x 必须严格递增（相等斜率要特殊处理）、i128 防止溢出。

调试流程。 第一步永远是把暴力版写出来并跑通；第二步用最小的手工例子（n=3 的 TSP、两位数区间、三点链、k=1 的跳跃、三点斜率）核对状态定义；第三步接上随机对拍，先跑几百组小规模，再逐步放大规模与参数范围；第四步才考虑把暴力版删掉或移到 #[cfg(test)]。本单元五个例子都把暴力版与优化版放进同一个程序，正是为了让读者能一键复现整个验证闭环。

工程取舍。 状压的内存 2^n·n 增长极快，n=20 已约 80MB，必要时改用只存一维 i 的滚动式（仍 2^n 项）或 meet-in-the-middle；数位 DP 的 memo 维度要随附加条件（余数、计数）扩展，维度越多越要确认状态是否真的有限；换根用迭代 DFS 而非递归，是为了避免 10^5 深链爆栈；单调队列用标准库 VecDeque 而非手写数组，省去循环队列的下标取模；斜率优化用 i128 是廉价的保险，性能敏感时可证明界后降回 i64。
