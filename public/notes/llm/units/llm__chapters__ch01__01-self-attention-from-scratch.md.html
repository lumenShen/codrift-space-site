1.1 先看工程长什么样

这一册要做的第一件事，是把前面几册攒下的矩阵、概率、梯度与 PyTorch 能力汇到一条完整的语言模型链路上。链路的起点是注意力。你可能已经在别处见过那张著名的公式：Attention(Q,K,V) = softmax(QKᵀ/√d)V。公式很短，短到容易让人误以为它只是三行代码；真正动手时你会发现，转置的约定、头与头之间的形状搬运、缩放的位置、数值稳定的细节，每一步都能让程序「跑得通但数字不对」。这一单元不追求规模，只追求把每一步的形状和数字钉死：三个 token、四维嵌入、两个头，小到能把每个格子在纸上算出来，又完整到能长出真实的注意力实现。

例子放在 books/llm/examples/ch01/attn_from_scratch/。src/attn.py 装全部数学：固定的投影矩阵、拆头与拼头、手写多头注意力，以及把同一组矩阵塞进框架的适配函数；src/main.py 是入口，负责固定三种随机源、造输入、调用两条路径、打印证据。清单 lm01-attn.json 用 mode=numerical 声明黄金值与 atol=1e-6，程序只打印，不判定。第 1 章从这一单元开始，所以这里还没有上一章的目录可以继承；但工程纪律完全一致：入口必须 import 本地模块，数值行用等号，张量行用冒号加方括号。

第 2 帧把两个源文件一次标出，因为它们属于「这一节新增的那一批文件」：缺任何一个，入口都不是多文件工程。第 3 帧只多了一个清单——它的作用是给闸门提供黄金值与容差。读这张树时要记住，帧 1 是本节故事里的起点，不是说仓库此刻真的空着；同样，帧 3 省略了帧 2 里已经出现的文件名前缀，但在真实目录里它们都还在。

工程惯例为什么数学与调度要放在两个文件里

因为这一单元之后，注意力会被位置编码、掩码、残差和前馈网络一层层包起来。如果投影矩阵、拆头函数和打印格式全写在一个文件里，将来改一处就要在几百行里翻找。现在把它们分家：attn.py 只回答「注意力怎么算」，main.py 只回答「算哪组数、按什么格式打出来」。改多头拆法时只动前者，改打印精度时只动后者。代价是多一条 import 语句，还要保证入口从 attn 导入的名字确实存在；换来的是接缝可见、错误好定位。这个习惯会从本单元一直用到最后一单元。

1.2 Q、K、V：同一份输入的三种角色

注意力的输入是一张 n 行 d 列的表 X：每行是一个 token，每列是嵌入空间里的一个坐标。同一个 token 在这张表里只占一行，却要在注意力里扮演三种角色。扮演「问询卡」的叫查询 Q，回答「我在找什么」；扮演「身份证」的叫键 K，回答「我是谁」；扮演「可取内容」的叫值 V，回答「你能从我这里拿走什么」。三种角色来自同一份 X，却乘三张不同的矩阵，所以它们是同一份数据的三种看法，不是三份独立数据。

本例把三张矩阵写死成常量，而不是随机初始化。这一点很重要：如果 Wq、Wk、Wv 由随机数生成，手写路径与框架路径只要初始化不同就会给出不同的输出，你根本分不清差来自实现还是来自权重。写死之后，两条路径拿到的是完全相同的数字，任何差异都只能是实现细节。种子照样固定，是为了让整个工程保持可复现的纪律，而不是因为这一步真的用到了随机数。

第 8 行的注释「行是输出维、列是输入维」是整套约定的钥匙。wq[i, j] 说的是「第 j 个输入分量对第 i 个输出分量的贡献」。因此投影写成 x @ wq.T：x 的一行是 1×4，乘上 4×4 的转置，得到 1×4 的新行。如果你习惯线性代数分册里 Q = XWq 的写法，那是把矩阵存成「列是输出维」；PyTorch 的 nn.Linear 存的是「行是输出维」，两者是同一张矩阵的两种摆放，不是两套数学。

第 2 帧里三张表形状都是 3×4，因为本例让输入维与输出维相等。真实模型里查询与键的维度通常等于值维度，也等于模型隐维，所以投影前后形状不变是常态。第 3 帧的三条边都从同一个 X 出发，这正是在提醒：Q、K、V 不是三份独立输入。

陷阱把投影矩阵存反了，程序照跑但数字全变

你会看到：程序正常退出，输出也是漂亮的六位小数，只是与手算结果对不上。你会怀疑 softmax 写错、怀疑精度不够，真相常常是投影约定写反了。若把 Wq 当成「列是输出维」直接写 x @ wq，等于用了 Wqᵀ，投影结果整体转置了一项。框架里 nn.MultiheadAttention.in_proj_weight 按 [Wq; Wk; Wv] 纵向拼接，每块都是「行是输出维」。本例把矩阵写死并在注释里钉死约定，就是为了让这种错位一眼能查：拿第 0 行的 Q 手算一遍，看是否等于 q00=0.750000。程序不会替你检查语义，只有黄金值会。

1.3 Split、计算、Concat：多头到底多在哪里

单头注意力把四维空间整体拿来匹配；多头注意力把四维切成两份，每份两维，用同一套公式在两个子空间里各算一次注意力，再把两份结果拼回去。本例有两个头，heads=2，每个头的键维 dk = d_model / heads = 2。拆头这一步只改视图形状，不复制数据：view(n, heads, dk) 把一行四维切成两行两维，再 transpose(0, 1) 把头维挪到前面，让后续矩阵乘法对每个头独立发生。拼头是逆操作：转置回来，再把头维与 dk 维摊平。

第 48 行有三个细节值得逐个拆开。第一，k.transpose(-2, -1) 把 (h, n, dk) 变成 (h, dk, n)，于是 Q 的 (h, n, dk) 乘上去得到 (h, n, n) 的分数表：第 h 个头、第 i 行、第 j 列，就是「这个头里，第 i 个 token 对第 j 个 token 的匹配分」。第二，除以 math.sqrt(dk) 用two头自己的维度，不是模型总维度；本例 dk = 2，所以除数是约 1.414，而不是 2。第三，F.softmax(..., dim=-1) 沿最后一维归一化，使每个头的每一行独立成为概率分布。

五帧各自重画了本帧要用的节点，所以单独看第 4 帧也能读懂。第 3 帧的星号落在分数表上，因为它是整个机制里唯一「平方」出来的中间量；第 5 帧的星号落在最终输出上，形状回到 (n, d)，这正是注意力层可以一层层堆起来的原因。

大白话多头不是省算力，而是换观察角度

如果你数乘法次数，会发现 h 个头各算 d/h 维，合起来仍是 n²d，和单头同阶。多头真正解决的是「所有信息只能挤在一个 d 维空间里做匹配」的限制：一个头可以盯相邻位置，另一个头可以盯指代关系，第三个头也许只关注标点。它们各自 softmax、各自取 V，最后才拼起来。本例两个头、每头两维，表达能力有限，但形状账与大模型完全一致——把 n、d、h 放大，这套代码一行不用改。

1.4 为什么要除以 √d：从方差饱和说起

假设 q 与 k 的每个分量是均值零、方差一、互相独立的随机数。点积 q·k = Σᵢ qᵢkᵢ 是 d 个乘积之和，每项方差是 1，所以点积的方差约是 d，标准差约是 √d。d 越大，分数的绝对值越容易变得极端。softmax 是指数归一化：当某个分数比同行其他分数大出几十，它的指数会吃掉几乎全部概率，其余位置的权重趋近于零。这时最大权重的梯度也趋近于零——softmax 进入饱和区，反向传播几乎传不回去。

除以 √d 把分数的标准差拉回 1 附近。本例 dk = 2，未缩放的点积是 0.812500，缩放后是 score00=0.574524；如果换成 dk = 64，不缩放的点积会落在几十的量级，softmax 会尖锐得多。缩放不是为了输出好看，而是为了让训练能继续：分数落在几附近时，softmax 的各个权重都不为零，梯度有路可走。

实验记录亲手去掉缩放，看看权重怎么变

把第 48 行的 / math.sqrt(dk) 删掉，真跑一次。你会看到 score00 从 0.574524 变成 0.812500，attn00 与 attn01 也跟着改变，闸门报 numeric_value_mismatch。这里数值变化不大，是因为 dk 只有 2；把 d 改成 64、头数改成 1 再试，权重会明显向某一格集中。做完把缩放加回去，黄金值对应带缩放的版本。

陷阱用「softmax 反正会归一化」为不缩放辩护

你会想：softmax 本来就把分数变成概率，分数大一点小一点无所谓。真相是归一化只保证和为 1，不保证梯度可用。极端分数让概率分布退化成one-hot，反向时除了最大位置，其余位置的 softmax 雅可比几乎为零；同时最大位置的梯度也很小，因为它的概率已经接近 1，再增大也几乎不变。判断方法很简单：打印每一行的最大权重，若长期是 0.999999 而其余全是零，先怀疑缩放与分数尺度，再怀疑学习率。

1.5 框架对账：让两条独立路径给出同一个数

nn.MultiheadAttention 默认随机初始化输入投影与输出投影。如果直接调用它，输出当然与手写版对不上，那种比较毫无信息量。正确做法是把本例写死的 Wq/Wk/Wv 拷进框架，把输入偏置清零，再把输出投影设成单位阵。这样两条路唯一可能的差别只剩实现细节，diff 才真的是对账证据。

第 57 行把头数设成 2，与手写版一致；batch_first=True 让张量形状按 (batch, 序列长度, 嵌入维) 排。第 59 行的 torch.cat([wq, wk, wv], dim=0) 把三张 4×4 矩阵纵向拼成 12×4，这正是框架内部的存储顺序。第 61 行把输出投影设成单位阵：若留着随机初始化，框架输出会再乘一张随机矩阵，差自然很大，但你分不清差来自输入投影还是输出投影。第 60 行的偏置清零同样必要，否则框架会给每个投影加一个手写版没有的常数。

调用侧同样简短。入口先手写，再框架，最后取最大绝对差：

第 36 行的三个 x 分别是 query、key、value；本例是自注意力，三者同源。换成编码器—解码器注意力时，query 来自目标序列，key 与 value 来自源序列，那条调用语句就会变成两个不同的张量。average_attn_weights=False 让返回的权重保持每个头一张表，本例没有拿它做对账，但保留它是为了提醒你：框架默认会先把多头权重平均成一张摘要表，那是另一回事。第 37 行的 diff 取所有输出元素里最大的绝对差，比只看某一个元素严格得多。

1.7 手算核对：从 q00 到 out00 的完整链路

这一节把 stdout 里的每个关键数字用手算对一遍，证明框架没有在背后偷偷改公式。输入第 0 行是 x₀ = [1.0, 0.5, −0.5, 1.0]。按 x @ wq.T，q₀ 的第 0 个分量是 x₀ 与 Wq 第 0 行的点积：1.0×1.0 + 0.5×0 + (−0.5)×0.5 + 1.0×0 = 0.75，正是 q00=0.750000。同法可得 q₀ = [0.75, 1.0, 0, 1.25]；拆成两个头后，头 0 拿到 [0.75, 1.0]，头 1 拿到 [0, 1.25]。

再算键。Wk 的第 0 行是 [0.5, 0.5, 0, 0]，点积得 0.75；第 1 行 [0, 1.0, 0.5, 0] 得 0.25；第 2 行 [0, 0, 1.0, 0.5] 得 0；第 3 行 [0.5, 0, 0, 1.0] 得 1.5。所以 k₀ = [0.75, 0.25, 0, 1.5]，头 0 的键是 [0.75, 0.25]。点积 q₀·k₀ = 0.75×0.75 + 1.0×0.25 = 0.8125，除以 √2 得 0.574524，正是 score00=0.574524。注意这里除的是每个头的维度 2，不是模型总维度 4。

再算同一行的另外两个分数。用第 1 个 token 的输入 x₁ = [0, 1, 1, −1]，投影后头 0 的键是 [0.5, 1.5]，于是 q₀·k₁ = 0.75×0.5 + 1.0×1.5 = 1.875，除以 √2 得约 1.325825。用 x₂ = [0.5, −1, 0.5, 0.5]，头 0 的键是 [0, −0.5]，点积是 −0.5，除以 √2 得约 −0.353553。三个分数合起来是 [0.574524, 1.325825, −0.353553]。减去最大值 1.325825 得 [−0.751301, 0, −1.679378]，指数约为 [0.4718, 1, 0.1865]，归一化后得 [0.293265, 0.621651, 0.085084]，与 weights00:[0.293265,0.621651,0.085084] 逐格相同，三数相加为 1，row_sum=1.000000。

输出还要乘回 V。头 0 的 V 由 x @ wv.T 拆出，三行分别是 [0.5, 1.0]、[1.0, 0]、[0, 0.5]。加权求和的第 0 个分量是 0.293265×0.5 + 0.621651×1.0 + 0.085084×0 = 0.768291；头 1 也有自己的一份贡献，两个头拼起来再取第 0 维，得到 out00=0.683199。这里手算只做校验思路的示范，逐格算完四个分量需要把两个头都展开；重要的是每一步的形状与归一化都对得上。

陷阱手算时最容易在头维与归一化上翻车

第一种错：算 q₀·k₀ 时用了完整的四维 q 与 k，忘了已经拆头，结果除以 √2 之后仍然对不上 score00。记住拆头之后每个头只持有两维，点积在头内部发生。第二种错：softmax 沿错了维度。若写成 dim=0，归一化发生在 token 维上，头 0 第 0 行的三个数不再和为 1，row_sum=1.000000 这条手算核对立刻失败。第三种错：缩放用了 √4 而不是 √2，分数整体偏小，权重会更平均。程序照样跑，但黄金值先失败。

1.8 softmax 的数值稳定：框架替你减了最大值

F.softmax 看着只是「指数、求和、相除」，框架在里面多做了一步保命操作。朴素写法是 exp(xᵢ)/Σⱼ exp(xⱼ)：当某个分数大到几百，exp 会溢出成正无穷，分子分母都是无穷，结果变成 NaN；当所有分数都很负，指数全部下溢成零，分母为零，同样得到 NaN。注意力分数经过 √d 缩放后一般落在几到几十的量级，离溢出很远，但你也见过那些因为一行坏数据就把损失打成 NaN 的训练——softmax 往往是第一个倒下的地方。

稳定写法先减去这一行的最大值：m = maxⱼ xⱼ，然后算 exp(xᵢ − m)/Σⱼ exp(xⱼ − m)。数学上分子分母同乘 exp(−m)，结果完全不变；数值上最大的那个指数变成 exp(0) = 1，其余都不超过 1，永远不会溢出，至少有一项不为零，分母也不会下溢成零。F.softmax 内部正是这么做的。上面手算时已经用了这一步：分数 [0.574524, 1.325825, −0.353553] 先减最大值，才得到那三个权重。

第 2 帧的星号落在最大值上，是因为「减谁」决定了溢出风险；第 3 帧把权重又完整写了一遍，单独看也能读懂。若把分数整体加上 1000，减最大值之后得到的仍是同一组权重；朴素写法则会全部溢出。这就是稳定 softmax 的意义：它让归一化只取决于分数之间的相对差，而不是绝对大小。

工程惯例什么时候值得自己实现 softmax

教学与排查时值得：写出减最大值的三行代码，你能指着 weights00 说清它从哪来。生产环境通常用框架实现，因为它还处理了不同 dtype、不同后端与梯度。判断自己写的版本对不对，有两个廉价检查：把一行分数整体加一个大常数，权重必须不变；把一行分数整体减一个大常数，权重也必须不变。任一检查失败，说明减最大值那一步漏了或减错了轴。

1.9 复杂度：n² 是从哪一张表里冒出来的

注意力的成本可以数乘法次数。设序列长 n、模型维 d、头数 h，每头维度 dk = d/h。投影阶段把 (n, d) 乘 (d, d) 得到 Q、K、V，三块合计约 3nd²，与序列长度线性相关。分数阶段每个头算 (n, dk) 乘 (dk, n)，约 n²dk 次乘加，h 个头合计 n²d。权重乘 V 同样是 (n, n) 乘 (n, dk)，也是 n²d。softmax 是 n² 量级的指数与除法，不含大矩阵乘加。主导项是 O(n²d)。

本例 n = 3、d = 4、h = 2、dk = 2，分数阶段每个头 3×3×2 = 18 次乘加，两个头 36 次；乘 V 又是 36 次；合计几十次，纸上能数完。把序列长度从 3 加到 3000、其他不变，成本不是涨一千倍，而是涨约一百万倍。这就是长上下文模型的注意力层成为瓶颈的原因，也是各种「线性注意力」「稀疏注意力」想要绕开那一整张 n×n 表的原因。

第 2 帧是本单元最该记住的一张图：QKᵀ 产生 h 张 n×n 的表，序列里任意两个位置在每张表里都有一格，这就是「二次」的来源。第 3 帧把信息压回 n×d，形状回到输入的样子，所以注意力层能一层层堆起来。把这两帧连起来读，你就明白为什么优化注意力首先要盯那张表。

工程惯例为什么生产环境不直接物化整张表

n = 4096 时，一张单精度分数表约 64 兆字节，仅一层的一个头就占这么多；几十层、几十个头会把显存吃光。工程惯例是用分块计算、不落盘整张表的实现：数学上仍是 softmax(QKᵀ/√d)V，但只在片上算一小块就立刻累积结果，省掉显存往返。这是惯例而非标准，代价是实现复杂、对硬件依赖强；收益是长序列能跑得动。本例故意把整张表算出来，因为它只有 3×3，正好能看清每一步。

1.10 黄金值为什么这样选：沿链路每隔几步钉一个

清单里八个黄金值不是从第一次运行的输出里随手抄的。它们分布在计算链的不同位置：q00 在最上游，检验投影约定；score00 在缩放之后，检验头维与除数；attn00 与 attn01 在 softmax 之后，检验归一化轴；row_sum 检验每行概率和为 1；out00 在最下游，检验乘 V 与拼头；fw00 与 diff 横跨两种实现，检验框架适配。中间的某一步写错时，下游数字当然也会错，但上游黄金值先失败能帮你少走很多弯路。

容差 atol=1e-6 的依据是打印精度。程序用六位小数输出，四舍五入带来的误差不超过五乘十的负七次方；双精度浮点运算本身的误差在十的负十五次方量级。所以一乘十的负六次方的容差既容得下打印误差，又远小于任何真实错误会造成的偏差。若把黄金值改成程序输出后硬凑的数，闸门照样会绿，但你会失去发现错误的机会——这个纪律在之前的最大似然与对拍单元里已经反复强调过。

张量行为什么不写成 out=0.683199, 0.335807, ...？因为闸门把形如 key=value 且 value 是有限十进制数的行当数值行，逗号串不是合法数值，会报 numeric_value_invalid。方括号文本走逐字对账，参与容差比较的标量单独打成六位小数。这不是审美问题，而是机器可执行的约定：你得让程序自己打印证据，让闸门自己重算判定。

陷阱只钉最终输出，不钉中间量

你会觉得「只要 out00 对，其它肯定对」。真相是多条错误路径能凑出同一个最终值：投影转置写反、同时 softmax 轴写错，某些对称输入下最终输出可能碰巧接近。更常见的情况是，下游值先失败但你不知道错在哪一层，只能从头查到尾。沿链路每隔两三步钉一个标量，等于给计算图装了几个检查点；排查时看第一个失败的检查点就够了。代价只是清单多写几行，换来的是数十倍的排查效率。

1.12 反向也能走通：注意力不是只能前向

本例在调用手写与框架注意力时都包了 torch.no_grad()，因为我们在做数值对账，不需要梯度，也就没必要为计算图付内存。可一旦把注意力放进真正的训练，这些包围圈就得去掉：Q、K、V 来自可学习的 Wq/Wk/Wv，softmax 的权重也是由它们算出来的，损失对投影矩阵的梯度必须沿着「输出 → 权重 → 分数 → Q/K → Wq/Wk」这条链一路传回去。

这条链上的每一步都可微。矩阵乘 QKᵀ 对 Q 的导数是 K，对 K 的导数是 Qᵀ；除以 √dk 只是乘常数；softmax 有自己的雅可比，框架已经实现好；乘 V 对 V 的导数就是权重表。你不需要手推这些导数，之前手推的链式法则在这里由 autograd 自动完成——但要知道它们确实存在，否则「为什么注意力层的参数能被训练」就成了一个黑箱。下一单元我们会把位置与掩码加进来，第三单元再把残差与归一化接上，那时一次前向—反向会把这些可微部件全部串起来。

陷阱为了让数字稳定，把 no_grad 包在整个训练前向

你会看到：loss 打出来正常，跑几百步也不降，检查参数发现 .grad 全是空。你会怀疑数据标签错位、怀疑学习率。真相是前向被 no_grad() 包住，计算图根本没建，反向时无图可走。本例包 no_grad 只在「比较两个固定权重的实现」这个场景成立；写训练代码时，正确做法是先正常前向拿 loss、反向、更新，只在评估或计算指标时包 no_grad。判断方法很简单：在 loss 后打印 loss.requires_grad，训练路径应该是 True，推理路径才是 False。

1.13 从这一单元到下一单元

学完注意力，你可能以为它就是 Transformer 的全部。其实注意力只负责「让不同位置交换信息」这一件事：它本身对顺序一无所知。把三个 token 换一种排列，注意力公式照样算，只是分数与权重跟着行重排——它没有一个格子写着「我是第几个词」。这正是下一单元要补的第一块：位置信息。另一个缺口是「未来不可见」：本例每个位置都能看到所有位置，做续写时等于偷看了答案，需要用因果掩码把上三角屏蔽掉。

再往后，完整的一层还要有残差连接、层归一化与逐位置前馈网络。残差给梯度开直达通道，归一化稳住数值尺度，前馈对每个位置单独加工。所有后续操作的形状仍然是 (n, d)，所以本单元建立的形状账本能一直用下去。复杂度讨论也要接着盯住 n²：前馈的成本是 O(nd²)，与序列长度线性相关；注意力的 O(n²d) 才会随着上下文变长反超。任何「优化 Transformer」的说法都要先说明优化的是哪一块、在什么长度下成立。

把这一单元与前几册接起来看：矩阵分册教的是「注意力就是三组投影加两次矩阵乘加一次 softmax」，概率分册教的是「softmax 把分数变成概率，负对数似然把概率变成损失」，PyTorch 桥接册教的是「同一套数学写成框架代码会长什么样」。这里真正的新东西只有头维缩放、拆头拼头的形状搬运、以及 O(n²d) 的成本意识；矩阵乘法与 softmax 还是你早就认识的那两个操作。

1.14 为什么把实验做得这么小：可手算、可对账、可迁移

你可能会嫌弃这个例子：三个 token、四维嵌入、两个头，离真实模型差着好几个数量级，学它有什么用？答案不在于规模，而在于「每个数字都能被独立复算」。真实模型的注意力权重表有几千行几千列，你不可能逐格核对；但它的每个格子用的就是本例这套公式。把小规模里的 score00、attn00、out00 手算一遍，你就获得了一把尺子：以后看到任何一个注意力实现，都能先在小规模上用同样的方法量一量，再谈优化与变体。

选 n = 3 而不是 n = 2，是为了让 softmax 有三项可比较。n = 2 时一行只有两个权重，attn00 + attn01 = 1 的约束太强，很多错误写法都能碰巧满足；n = 3 时权重是三项，归一化轴写错、掩码填错、缩放漏掉都会立刻显形。选 d_model = 4、heads = 2，是为了让 dk = 2 既能拆成两个可手算的分量，又能体现「每个头独立算分数」这件事。若 d_model = 2、heads = 2，每头只剩一维，点积退化成标量相乘，多头的形状搬运反而看不出来。

固定三种随机源也有讲究。random.seed、np.random.seed、torch.manual_seed 分别管住三条独立的随机流：标准库的随机数、NumPy 的全局生成器、PyTorch 的张量初始化。本例的矩阵全是常量，理论上不依赖随机数，但仍然把它们固定，是为了让这个实验成为后续实验的模板。下一单元会用到 NumPy 的位置编码，第三单元会用 PyTorch 初始化两层 block；那时漏掉任何一种种子，黄金值就会在不同机器上漂移。现在养成习惯，后面就不用回头补。

实验记录把规模放大一次，看看哪些量会变、哪些不变

把输入改成六个 token、嵌入维改成八、头数改成四，其余不动，真跑一次。q00 与 score00 会变，因为投影矩阵与头维都变了；但 row_sum 仍然是 1.000000，diff 仍然接近零，因为归一化与两条路径等价性与规模无关。再把手写路径的 dim=-1 改成 dim=0，row_sum 会立刻失败——这个失败与规模无关。放大实验的价值正在这里：它把「机制」与「具体数字」分开，让你知道哪些结论可以迁移，哪些只是本例的巧合。做完把代码改回原样，黄金值对应小规模版本。

还有一个容易被忽略的细节：打印顺序与清单声明顺序互不影响。闸门按行解析 stdout，先把等号行放进数值表，再逐行与正文的 output 块对账；黄金值检查只关心某个键出现没有、值在不在容差内。因此你可以先打实验条件、再打证据、最后打张量，也可以反过来。真正不能犯的错是同一个键打两遍：即使两次数值相同，也会报 numeric_key_duplicate。设计自己的实验时，建议按计算链的上游到下游顺序打印，这样一旦某个检查点失败，日志里第一个失败的行号就指向出错的那一层。

小结这一节的要点
  • X 乘 Wq/Wk/Wv 的转置得到 Q、K、V；矩阵按「行是输出维」存，与线性代数分册的写法差一次转置；
  • 多头是 Split → 缩放点积 → softmax → 乘 V → Concat，本例两个头、每头两维，缩放除的是 √dk；
  • 稳定 softmax 先减行最大值，数学不变而数值安全；本例 row_sum=1.000000；
  • 把同一组矩阵拷进框架并把输出投影设为单位阵后，out00=fw00=0.683199、diff=0.000000；
  • 分数表是 n×n，注意力复杂度 O(n²d)；本例 n = 3、d = 4，两个头的两次矩阵乘加各约三十六次；
  • 标量用 key=0.123456、张量用方括号文本，黄金值与容差只写在清单，手算与真跑互相验证。

注自测题答案
  1. PyTorch 的 nn.Linear 把矩阵存成「行是输出维、列是输入维」，所以前向是 xWᵀ；线性代数分册把 Wq 存成「列是输出维」，写法是 XWq。两者是同一张矩阵转置后的两种摆放，投影结果相同；把元素抄错位置则会让结果整体转置。
  2. x₀ = [1.0, 0.5, −0.5, 1.0]，Wq 第 0 行是 [1.0, 0, 0.5, 0]，点积为 1.0 − 0.25 = 0.75，即 q00=0.750000。头 0 的 q = [0.75, 1.0]，k = [0.75, 0.25]，点积 0.8125；除以 √2 得 0.574524，与 score00 一致。
  3. 拆头把 (n, d) 视作 (n, h, dk) 再转置成 (h, n, dk)；拼头反过来，把 (h, n, dk) 转置成 (n, h, dk) 再摊平为 (n, d)。本例 h = 2、n = 3，每头分数表是 3×3，整体是 (2, 3, 3)。
  4. q 与 k 的点积方差随 dk 增长，dk 大时分数极端，softmax 饱和，几乎把所有概率给一个位置，其余位置梯度趋近于零。除以 √dk 把方差拉回 1 附近。除成 √d 会让缩放过头、权重过于平均。减最大值保证指数不超过 1、分母不为零，避免溢出与下溢。
  5. 框架默认随机初始化输入与输出投影。若只调用而不拷贝，输出会经过另一组随机矩阵，差来自初始化而非实现；拷贝同一组矩阵、清零偏置、把输出投影设为单位阵后，两条路的唯一差别才是实现细节，diff 才是对账证据。
  6. QKᵀ 是 (n×dk)(dk×n) → n×n，每头约 n²dk，h 头合计 n²d；权重乘 V 同阶，softmax 是 n² 量级。总成本 O(n²d)，序列长度扩大 10 倍、d 不变时约涨 100 倍。
  7. 闸门把 key=value 当数值行解析，逗号串不是有限十进制数，会报 numeric_value_invalid。方括号文本按字面量逐字对账；真正参与容差比较的标量单独打成六位小数，例如 attn00=0.293265。
