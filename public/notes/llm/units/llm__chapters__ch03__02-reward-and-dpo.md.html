3.1 先看工程长什么样

上一单元我们把一条标准答案拆开，看掩码怎样决定模型为谁负责。这一单元换一种监督信号：不再只给一个正确答案，而是给一对回答，告诉你哪个更好。这种「chosen 与 rejected」的偏好对，是当代对齐流程的核心数据形态。围绕它有两种做法：先训一个奖励模型给回答打分，再用强化学习优化策略；或者绕过奖励模型，直接用一个分类式的损失优化策略，这就是 DPO。本例把两条路都手写一遍，让你看到它们其实是同一个对数似然故事的两种写法。

例子叫 dpo_loss，工程骨架与上一单元一致：src/dpo.py 放全部数学——偏好数据、序列对数概率、奖励模型特征、两种损失及框架对账；src/main.py 固定三种随机源、调度计算、打印证据。清单 lm08-dpo.json 是 numerical 模式，七个黄金值全部来自真跑，容差一乘十的负六次方。入口必须导入本地模块，所以 main.py 第一行 import 之后紧跟着 from dpo import ...。

第 1 帧保留了上一单元的例子，因为两节共用同一个 examples/ch03/ 项目目录；带加号的三行才是本节的全部新增。第 2 帧的 dpo.py 里有两组损失：一组是奖励模型的 pairwise logistic loss，另一组是 DPO 损失，两者共用同一个稳定的逻辑函数。第 3 帧的清单同时声明这两个损失和它们与框架实现的差，等于把两条路径都钉住。

工程惯例为什么把两种损失放进同一个例子

因为它们共享同一个数学核心。奖励模型的损失是「奖励差越大越好」的 logistic 分类，DPO 的损失是「隐式奖励差越大越好」的 logistic 分类；差别只在奖励差从哪里来。放进同一个文件、同一张打分表、同一个入口，读者才能一眼看出两者的同构。若拆成两个例子，你会把注意力浪费在两套数据格式上，而错过真正的主线。

3.2 从标准答案到偏好对：监督信号变了什么

SFT 的数据是「一个问题配一个标准回答」。它只告诉你正例长什么样，从不明说错在哪里。在回答空间很大的任务里，这个缺陷很明显：两个回答都事实正确，但一个啰嗦、一个简洁，SFT 的损失对它们一视同仁；一个回答悄悄带了一点偏见，只要它出现在训练集里，模型照样学着生成它。正例最大似然无法表达「比另一个更好」这种相对关系。

偏好对把信号变成三元组「问题、较好回答、较差回答」。标注者不需要写出完美答案，只需要在两个候选里选一个——这既降低了标注难度，也扩大了可标注的任务范围。更关键的是，比较提供了方向：模型不仅知道该往哪里走，还知道该远离哪里。本例造了三对玩具数据，每对有一个 chosen 和一个 rejected，都是四个 token 的短序列。词表大小是八，所有编号都合法。

第 1 帧给出数据结构，第 2 帧给两条回答各打一个分，第 3 帧把分数差送进 logistic 损失。三帧自包含：第 3 帧把两条路径的分数都重写了一遍，因为打印版里每帧独立成图。整条链路的关键在 gap：只要较好回答的分数高于较差回答，损失就小；反过来的话损失会迅速变大。这与交叉熵惩罚「给正确词分配低概率」是完全同一种思路，只是把「词」换成了「整条回答」。

大白话用大白话说偏好对

SFT 像老师只给满分作文，让学生照着写；偏好对像老师拿两篇作文让学生挑哪篇更好。后者不需要老师自己写出满分作文，只要能判断高下，而且学生能从比较里知道什么样的毛病要避开。把「哪个更好」变成一个可微的数字，就是这一单元全部数学的出发点。

3.3 奖励模型：把比较压成一个标量

经典 RLHF 的第一件事是训奖励模型。它的输入是一条问题和一条回答，输出一个标量分数，分数越高表示标注者越可能喜欢这条回答。本例用一个极简的线性奖励模型：r = w·φ，特征 φ 只有三项——常数一、回答长度除以八、以及高分词的占比。权重 w 固定为 [0.2, 0.6, 1.1]，不参与训练；因为本单元要验证的是损失写法，不是优化过程。

有了分数，pairwise_rm_loss 把每对数据的两个分数相减，送进 Bradley-Terry 模型。这个模型假设「较好回答被选中的概率」等于 sigmoid(r_w - r_l)：分差越大，选对的概率越接近一；分差为零时两边各半。取负对数就得到要最小化的损失，形式与二分类交叉熵一模一样。三对数据的损失再取平均，就是 loss_rm。

数值稳定在这一步同样重要。-log(sigmoid(x)) 在 x 很大负数时，sigmoid 会下溢成零，损失变成无穷大。写法上是 logaddexp(0, -x)：利用恒等式 -log(sigmoid(x)) = log(1+exp(-x))，而 logaddexp 内部会先取较大者做基准，避免指数溢出。这与上一单元先减最大值再算 log softmax 是同一个技巧的不同外衣。

框架版本把分差当成 logits，把「较好回答胜出」当成标签一，交给带 logits 的二分类交叉熵。两条路不共享中间量：手写版走 logaddexp，框架版走自己的稳定实现。双精度下两者逐位一致，所以 diff 与 rm_diff 都应该是零。若哪天你把手写版改成先算 sigmoid 再取对数，在普通分差上也许还是零，但把分差调到很大负数就会跳成无穷——把对账写成黄金值，就是为了让这种隐患有机会暴露。

实验记录亲手制造一次下溢

把 logistic_loss 改成 -np.log(1/(1+np.exp(-x)))，然后把一对分差强制改成负一千。你会得到无穷大的损失和运行时警告；而 logaddexp 版本会给出约一千的有限值。再把改动撤回去。这个对照说明稳定写法不是洁癖：优化过程里分差完全可能走到很大的负数，尤其在训练早期策略还很乱的时候。

3.4 序列对数概率：把整条回答当成一个事件

DPO 不需要显式奖励模型，它直接从策略模型里读出「隐式奖励」。要读它，先得会算一条回答的序列对数概率。本例的回答都是四个 token，seq_logp 对四个位置各做一次稳定的 log softmax，取出实际 token 的对数概率，再求和。求和来自序列的联合概率分解：给定提示词之后，整条回答出现的概率等于每个位置条件概率的乘积；取对数，乘积就变成和。你在第 2 册最大似然那一节已经见过完全相同的变换。

打分表有两套：ref 是参考策略，policy 是当前策略。两者都由固定种子生成，但 make_tables 给当前策略的 chosen 序列每个位置加 0.35 分、给 rejected 序列每个位置减 0.15 分，模拟一个「已经朝着偏好方向更新过」的策略。参考策略保持原样。于是当前策略相对参考策略，会更偏向 chosen、更远离 rejected，隐式奖励差自然为正。

第 2 帧把四条路径都写全了：每条回答都要分别在参考策略和当前策略下算一次对数概率，共四个数。第 3 帧只显示参与最后相减的量，但把 pi_w、pf_w 重写一遍，保证读者单看这一帧也知道差从哪来。这里有个容易混淆的点：pi_w - pf_w 是「较好回答相对参考提升了多少」，不是奖励本身；真正的偏好信号是两个相对提升再相减。

工程惯例为什么序列对数概率用求和而不是求平均

这里求的是整条回答的联合概率，长度不同的回答如果求平均，会把长度信息抹掉，也让分差失去可比性。求和忠实于概率的链式分解：四个位置的条件概率相乘，取对数就是相加。副作用是长回答天然有更大的对数概率绝对值，这也是真实偏好数据里「长度偏好」的一个来源，后面讲局限时会再提。

3.5 DPO 的隐式奖励：β 从哪里来

现在做这一单元最要紧的推导。经典 RLHF 的优化目标可以写成：在策略 π 上最大化奖励模型的期望得分，同时用一个系数 β 惩罚它偏离参考策略 π_ref 的 KL 散度。写成式子就是 max E[r(x,y)] - β·KL(π || π_ref)。这个 KL 约束在概率优化分册的对偶单元里出现过：给约束配一个乘子，把硬约束换成软惩罚，β 就是那个乘子，决定「偏离参考」这件事有多贵。

这个目标有闭式最优解：π*(y|x) ∝ π_ref(y|x) · exp(r(x,y)/β)。把它反过来解出奖励，得到 r(x,y) = β·log(π*(y|x)/π_ref(y|x)) + 常数。常数项与回答无关，在比较两个回答时会相减抵消。关键的一步来了：既然奖励可以用策略与参考策略的对数概率比表示，那就不需要单独训一个奖励模型——我们把这个表达式代进上一节的 Bradley-Terry pairwise loss，得到的就是 DPO 损失：

L_DPO = -log σ( β·[ (log πθ(y_w|x) − log π_ref(y_w|x)) − (log πθ(y_l|x) − log π_ref(y_l|x)) ] )

括号里那一大坨，正是 dpo_terms 返回的 gaps；再乘 β、送进 logistic_loss，就是 loss_dpo。DPO 的名字来源于此：直接偏好优化，把偏好比较直接变成策略上的分类损失。

beta=0.100000 是超参数，控制两个量：一是 KL 约束的强度，β 越大越不许偏离参考策略；二是奖励的尺度，因为隐式奖励被定义成 β 乘对数概率比。尺度本身会被 logistic 的相减消掉一部分，但 β 同时决定梯度的大小，所以它不是可以随手设一的摆设。实践里常见的取值在零点零几到零点几之间，本例取零点一。

陷阱别把 β 当成学习率

β 不是更新步长，它出现在损失里、改变的是目标函数本身：不同的 β 定义不同的最优策略。学习率出现在优化器里、改变的是走向最优点的快慢，不改变最优点在哪。把两者混着调，你会得到「调大 β 就发散」这种错误直觉——真正的原因是目标被改了，不是步子迈大了。

3.6 奖励模型损失与 DPO 损失：同构的两个分类问题

把两节的内容并排看，结构完全一样。奖励模型版本：gap = r_w − r_l，损失是 -log σ(gap)。DPO 版本：gap = β[(logπ_w − logπ_ref_w) − (logπ_l − logπ_ref_l)]，损失还是 -log σ(gap)。区别只在 gap 的来源：前者来自一个学到的打分函数，后者来自策略与参考策略的对数概率比。一个是显式奖励，一个是隐式奖励。

这种同构不是巧合，而是上一节那个闭式最优解的直接后果：DPO 把奖励模型的参数和强化学习的优化步骤一起消掉了，只留下偏好比较本身。工程上的好处很实在——不需要训练奖励模型、不需要在线采样、不需要价值网络和 PPO 的裁剪技巧，整套训练退化成一个类似监督学习的分类任务，稳定性和可复现性都好得多。代价是把奖励模型和在线探索提供的能力也一起丢掉了，这一点后面会详细讲。

r[0::2] - r[1::2] 依赖数据排列顺序：每对数据先放 chosen、再放 rejected，所以偶数下标是较好回答的分数，奇数下标是较差回答的。这个约定写进注释比写在读者脑子里可靠。框架对照走的是 softplus(-gap)，与 logaddexp(0, -gap) 数学等价，于是得到第二个 rm_diff=0.000000。

实验记录把数据顺序打乱会怎样

在 pairwise_rm_loss 里改用 r[1::2] - r[0::2]，相当于把好坏标号反过来。你会看到 loss_rm 从 0.662903 跳到大约 1.662903——因为分差变负，损失大约是原来的差加上分差的绝对值量级。这个实验说明配对顺序是数据契约的一部分，不是可以随意调整的排列。做完把切片改回去。

3.8 数怎么读：把七行输出还原成一句话

reward_gap_vec 的三个数分别是 0.167765、0.175123、0.170302，都是正数，说明当前策略在三对数据上都把 chosen 的相对对数概率抬得比 rejected 更高。它们的平均是 0.171063，就是 reward_gap。acc=1.000000 只是「三对里有几对分差为正」的比例，三对全对所以是一。别把 acc 当成模型能力：这里的策略是人为构造的，准确率满分为真跑提供了「方向没错」的 sanity check，不代表它真的会聊天。

loss_dpo=0.611270 是三个 -log σ(gap) 的平均。手算核对：sigmoid(0.171063) 大约是零点五四三，负对数约零点六一一，与打印一致。分差只有零点一七，离饱和还很远，所以损失落在零点六九（也就是完全随机时的损失，ln 2）稍下的位置。如果策略更强、分差做到一点五，损失会降到约零点二；如果分差为零，损失恰好是零点六九三一四七。拿这个基准去读真实训练日志，立刻能判断模型有没有学到偏好。

loss_rm=0.662903 来自另一个奖励模型的分差，它比 DPO 损失略低，说明线性奖励模型在这三对数据上的分差更极端一些。两个数没有可以直接比较的含义——不同的奖励尺度、不同的空隙定义——但它们各自与框架实现对账为零，这才是重点。diff=0.000000 与 rm_diff=0.000000 分别守住 DPO 与奖励模型两条路径。

第 3 帧把随机基准一并画出来，因为单看零点六一一你不知道它是好是坏。有了基准，就知道模型只是略微优于瞎猜——这与 acc=1 并不矛盾：排序全对，但把握不大。把排序正确率和损失一起看，是读所有偏好优化日志的基本功。

这里还要提醒一次量纲问题。loss_rm 与 loss_dpo 虽然都用逻辑损失，括号里的空隙来自完全不同的定义：前者是线性奖励模型的分数差，后者是策略相对参考的对数概率比乘上 β。两个尺度之间没有换算关系，所以零点六六二九零三与零点六一一二七零谁大谁小，并不能解读成「奖励模型比 DPO 更好」或相反。它们唯一可比的共同点是各自与随机基准的关系。真正要比较两种方法，必须在同一批偏好数据、同一套提示词上做人工或模型评测，看生成结果本身的质量。

工程惯例为什么奖励差要打印成张量行

标量均值会掩盖分布形状。三对分差都为零点一七和一对为零点五一、一对为负，均值可能碰巧一样，但后者说明策略在某些问题上根本没学到偏好。张量行让闸门能逐字对账每一对的结果，也让读者自己能看出方差。本例三对数很接近，是因为构造策略时用了统一的加分幅度；真实数据上分差往往参差不齐。

3.9 DPO 与 PPO/RLHF 的关系：同一目标的两条路

经典 RLHF 有三段式流程。第一段做 SFT，得到最初的助手；第二段用偏好对训奖励模型；第三段用强化学习优化策略——从当前策略采样回答，让奖励模型打分，再用 PPO 更新参数，同时加一条 KL 惩罚防止策略偏离参考模型太远。这条链路很完整，但也很重：要维护策略网络、参考网络、奖励网络，有时还要价值网络；在线采样费时；PPO 的裁剪、优势估计和多个损失项都要调。

DPO 的出发点是问：既然 KL 约束下的最优策略有闭式表达，而奖励又可以用最优策略与参考策略的对数比表示，为什么不把这个表达式直接代进偏好损失？代进去之后，奖励模型消失了，在线采样消失了，PPO 消失了，只剩下在固定偏好数据上做一次分类式的优化。所以 DPO 不是「另一种对齐哲学」，而是同一个 KL 约束目标在消元之后的等价写法——前提是最优策略确实能被那个闭式表达，并且数据分布覆盖了我们要优化的区域。

第 2 帧是两座桥的中间那块：无论走 PPO 还是走 DPO，目标里那个 β·KL 都在，参考模型也都在。第 3 帧显示 DPO 把闭式解代进损失之后，偏好对可以直接落到策略上。注意参考模型没有被消掉——它仍然出现在对数概率比的分母里。很多实现为了省显存而共享参考与策略的权重，那其实是在假设两者还没分开，与 DPO 的本意不同。

大白话用大白话说两者的分工

RLHF 像请一位教练先打分、再带着运动员反复试跑，边跑边纠动作；DPO 像把教练的打分规则翻译成一张习题册，运动员直接对着习题册练。前者能探索新动作，但贵且难稳；后者便宜稳定，但习题册之外的动作练不到。两者的教材都是偏好对，差别只在有没有那个「边跑边打分」的环节。

3.10 DPO 的四条局限：简单不是免费

第一，离线数据的分布束缚。DPO 只在固定偏好对上优化，策略一旦偏离数据分布，就没有新的比较来告诉它好坏。PPO 在线采样能看到自己当前的输出并让奖励模型打分，因此可以纠正新出现的坏行为；DPO 没有这个回路。结果是 DPO 模型常常在训练分布附近表现不错，一旦被提示到分布外就露出旧毛病。

第二，分差可被利用。既然损失只鼓励「chosen 的对数概率比更高」，策略可以通过放大某些无关特征来刷分——比如把回答写得特别长、堆砌某些高频词。这叫奖励黑客，在显式奖励模型里也存在，但在线训练至少能用奖励模型的重新打分发现它；纯离线的 DPO 更容易在指标变好的同时真实质量下降。本例的线性奖励模型特征里恰好有「长度」这一项，就是在提醒你这种偏差有多容易混进去。

第三，对参考模型与 β 敏感。参考模型选得不好，分母就歪了；β 太大策略几乎不动，太小则容易过拟合偏好数据里的噪声。同一批数据换一个参考检查点，结论可能明显不同。这与对偶单元里「乘子依赖约束写法」的教训类似：符号与尺度约定必须先固定，再谈数值。

第四，偏好标注本身的噪声。人类标注不一致、有偏好偏见，有些性质（事实正确性）很难靠两两比较完全表达。DPO 把这些噪声直接当成训练信号，没有任何缓冲。实践中常见的缓解办法包括过滤低置信度标注、引入更高质的比较、或者改用对噪声更稳的目标函数变体。

陷阱以为 DPO 不需要参考模型就能跑

有些实现把参考项省掉，写成只最大化 chosen 的对数概率。那已经不是 DPO，而是另一种带正例权重的监督微调——它失去了「相对参考的提升」这个核心，也就失去了 KL 约束带来的保护。判断办法很简单：损失里如果看不到参考策略的对数概率，就不是 DPO。

3.11 β 的手感与调参顺序

β 的第一重含义是尺度。隐式奖励等于 β 乘对数概率比，所以 β 越大，同样大小的概率比被翻译成越大的奖励差，logistic 损失越小、梯度越弱。第二重含义是约束强度：它来自 KL 惩罚项的系数，越大越不允许策略远离参考。两种含义其实是同一件事的两面——约束越紧，策略越不敢大幅改变概率比，隐式奖励的绝对尺度也就越保守。

调参顺序建议这样：先固定参考模型与数据，扫几个 β 看验证集上的偏好准确率和损失；若准确率上不去而损失已经很低，说明策略过拟合了偏好对，考虑增大 β 或增加数据；若准确率上去了但生成质量变差、出现冗长或重复，说明策略偏离参考过远，同样增大 β。只有在 β 稳定之后才去调整学习率与轮次，否则两个旋钮一起转，你分不清改善来自哪一个。

本例把 β 写死在模块常量里，因为这是数值模式的机制验证；真实训练里它应该是实验条件的一部分，和种子、数据版本一起记录。这一点与第 5 单元「种子写进清单而不是源码」的纪律一致：凡是你日后要拿来对比的旋钮，都不该藏在实现细节里。

实验记录把 β 加倍，看三个数怎么动

把 BETA 从零点一改成零点二，真跑一次。三个 reward_gap 都会翻倍，变成约零点三三五、loss_dpo 降到约零点五一九，acc 仍然是满分。这个实验把 β 的尺度作用量化了：它不改变排序，只改变把握程度与梯度强度。记得把清单里的黄金值一起更新，或者更稳妥的做法是改完再改回来，保持清单对应原始实验。

3.12 奖励模型不是万能裁判

显式奖励模型有一个诱人的承诺：任何回答都能打一个分，于是优化就不必局限于已有偏好对。但打分器本身是学出来的，它会出错，也会被利用。本例的线性奖励模型只有三个特征，权重还是手定的，所以它给出的 loss_rm 只是一个形状演示；真实奖励模型是一个神经网络，它的误差分布很难完全刻画。第 2 册讲过的过拟合在这里同样成立：奖励模型在训练偏好对上准确率很高，换一批标注就一塌糊涂。

更微妙的是「可比较性」问题。奖励模型擅长比较风格相近的回答，面对风格差异巨大的两个答案，分数可能没有意义。偏好数据里如果绝大多数比较都是「同一段文字的两种改写」，模型就学不到「简洁胜过啰嗦」这种跨风格判断。这又回到数据覆盖：监督信号能教什么，取决于你把哪些比较摆到它面前。

这也是为什么 DPO 与 PPO 并不是谁取代谁。工业系统里常见的是组合用法：先用 DPO 在高质量偏好数据上快速对齐，再用在线方法在真实流量里继续纠偏；或者用奖励模型做自动评测与数据筛选，再拿筛出的数据做离线偏好训练。理解两者的共同地基，比记住某一派的口号更有用。

工程惯例一条实际的检查清单

做偏好优化前先问六个问题：偏好对是否来自目标分布；chosen 是否真的更好、标注是否一致；参考模型是否就是对应用户会看到的基线；β 是否有验证集依据；回答长度与风格是否造成伪相关；有没有留出一批不参与训练的数据做最终评测。六项都过得去，再谈损失曲线。这与前面训练循环那套六项检查是同一种思路：把失败模式变成能逐项核对的观察量。

3.13 黄金值从哪里来：两对独立路径互相验证

七个黄金值里，beta=0.1 与 pairs=3 是实验条件；reward_gap 来自三对隐式奖励差的算术平均；acc=1 来自三对全为正的计数；loss_dpo 与 loss_rm 分别来自两个稳定逻辑损失的平均；两个 diff 来自手写实现与框架实现的绝对差。每个值都有独立来源，没有任何一个是「第一次跑出来什么就抄什么」。

手算核对并不难。reward_gap_vec 三项之和约零点五一三一九零，除以三得零点一七一零六三。sigmoid(0.171063) 约零点五四三二，其负对数约零点六一一，与 loss_dpo 一致。奖励模型那一路的分差由手定权重与特征点积产生，也可以用纸笔逐对算出来。把这两个手算结果写进正文，是为了让黄金值不依赖程序的第一次输出。

容差仍是一乘十的负六次方。六位小数打印带来最多五乘十的负七次方的舍入误差，双精度运算的误差在十的负十五次方量级，所以这个容差既有余量又足够严。若把 loss_dpo 的黄金值改成凑出来的数，闸门照样会绿，但你就失去了发现「分母写错」「符号反了」这类问题的能力。

实验记录用对照种子确认数字不是硬编码

把 SEED 从 2026 改成 2027，真跑一次：两套打分表都变了，三个分差、loss_dpo、reward_gap 都会跟着变。若你手写了一个把七个值全打死的假程序，这些数不会动。做完把种子改回去。注意本例是数值模式，种子写在源码里；若换成训练模式，种子必须由闸门通过环境变量注入，那是另一套纪律。

3.15 从偏好优化走向解码与评测

到这里，第 3 章的三段主线已经走完：SFT 把续写器变成助手，loss mask 决定模型为谁负责；奖励模型把偏好比较压成分数；DPO 把奖励消掉，直接在策略上优化比较。三者共用一个骨架——负对数似然与单调变换，变的只是统计范围与比较对象。把这条主线记住，后面看到各种新算法时先问两个问题：它的损失统计哪些位置，它的「正确」是怎么定义的。

还有一个悬而未决的问题：本例始终把「概率更高」「分差更大」当成成功，可这些数字和用户体验之间还隔着一道关卡。一个 DPO 损失很低的模型，解码时可能因为策略太尖而不断重复；一个偏好准确率满分的模型，可能在你没见过的问法上胡说。第 4 章会先把解码策略拆开，看贪心、温度、截断怎样改变同一组 logits 上的输出分布；再讲评测与幻觉，给「模型到底好不好」这个问题补上更硬的尺子。

小结这一节的要点
  • 偏好对提供相对监督：chosen 与 rejected 的分差进 logistic 损失，比单条标准答案信息更丰富；
  • 奖励模型用 Bradley-Terry loss 学打分器，DPO 把 KL 约束下的闭式最优策略代进去，消掉显式奖励模型；
  • 隐式奖励差是 β 乘两组对数概率比之差，β 同时是奖励尺度与 KL 约束强度，不是学习率；
  • 真跑给出 loss_rm=0.662903、loss_dpo=0.611270、reward_gap=0.171063、acc=1.000000，两个对账差都是零；
  • DPO 与 PPO/RLHF 共享 KL 约束目标，前者离线消元、简单稳定，后者在线采样、能纠偏但复杂；
  • 局限有四：受离线数据分布束缚、分差可被利用、对参考模型与 β 敏感、偏好标注噪声直接进损失。

注自测题答案
  1. 它提供了方向：不仅告诉模型该靠近哪个回答，还告诉它该远离哪个回答。标注者只需在两个候选里选一个，不必自己写出完美答案，所以许多难以生成标准答案的任务也能标注。

  3. 目标是 max E[r] − β·KL(π||π_ref)，最优解 π*(y|x) ∝ π_ref(y|x)·exp(r(x,y)/β)；反解得 r(x,y)=β·log(π*/π_ref)+常数，常数在比较两个回答时相减抵消。

  5. 三个分差 0.167765、0.175123、0.170302 的平均是 0.171063。分差为零时损失是 ln 2 约 0.693147；本例分差为正，损失降到 0.611270，说明只是略优于随机。
