3.1 先看工程长什么样

前两个单元把注意力、位置编码与因果掩码补齐了。现在手里有一台能「让位置之间交换信息」的机器，但它还不能直接堆深：注意力子层的输出尺度会随输入漂移，梯度要连穿许多层矩阵乘，每层对每个 token 的加工也只是一次线性投影。这一单元把三个零件接上来——层归一化稳住尺度、残差连接给梯度开直达通道、逐位置前馈网络做非线性加工——拼成一个完整的 Transformer block，并把两个 block 叠起来跑一次真正的前向与反向。

例子放在 books/llm/examples/ch01/transformer_block/。src/block.py 装全部结构：手写 LayerNorm、单个 Pre-LN block、两层堆叠，以及参数计数函数；src/main.py 固定三种随机源、造输入与目标、算均方误差、反向传播、打印范数与参数量。清单 lm03-block.json 用 mode=numerical 声明九个黄金值与 atol=1e-6。入口必须 import 本地模块，这是第 1 章从第一个单元起就守着的纪律。

第 2 帧的加号只落在新增的两个源文件上，清单单独放在第 3 帧——图元一次只讲一件事。第 3 帧里旧目录不再展开，是因为它们与本节的论点无关；真实目录里它们当然还在。

工程惯例为什么把 LayerNorm 也手写一遍

因为它是本单元最容易「跑对但算错」的地方。沿哪条轴求均值、方差用有偏还是无偏估计、eps 加在根号里面还是外面、缩放平移的乘除顺序——每一项写错都不会报错，只会让数值尺度悄悄变化。手写一遍再与框架对账 ln_diff，你能指着这个数字说「我的公式和框架的实现是同一个」。将来读任何大模型代码，看到归一化层就不会只当它是一个黑箱调用。

3.2 一层 block 的零件表：四个部件，两条通路

标准的 Transformer 编码器层由四样东西拼成：多头自注意力、两层前馈网络、两个层归一化、两条残差连接。数据流是这样的：输入 x 先过第一个 LayerNorm，再进注意力子层，子层输出与原始 x 相加；相加结果过第二个 LayerNorm，再进前馈网络，前馈输出再与第一阶段的残差流相加。每个子层都被「归一化包裹、残差绕行」的结构包着，所以整层输出与输入形状相同，都是 (序列长, 模型维)。

第 2 帧与第 3 帧都把 x 或 sum1 的恒等通路重写了一遍，这是「帧自包含」的纪律：单独打印任何一帧，都能看到残差旁边那条绕行的边。第 3 帧的星号落在最终输出上，它仍是 (3, 4)——所以两个 block 可以直接串起来。

3.3 LayerNorm：每个 token 自己标准化自己

层归一化的公式很短。对某个位置的特征向量 x = (x₁, …, x_d)，先算均值 μ = (1/d)Σᵢxᵢ 与方差 σ² = (1/d)Σᵢ(xᵢ−μ)²，再做标准化 x̂ᵢ = (xᵢ−μ)/√(σ²+ε)，最后用可学习的 γ 与 β 缩放平移：yᵢ = γᵢ·x̂ᵢ + βᵢ。ε 是防除零的小常数，本例取框架默认值。γ 与 β 是可训练参数，初值通常是一和零，让归一化层在训练开始时不改变输入输出关系。

第 8 行与第 9 行的 dim=-1 是全篇最关键的一处：输入形状是 (n, d)，沿最后一维求统计量意味着「每个 token 在自己的 d 个特征上求均值方差」，与其他 token 无关。若写成 dim=0，统计量来自同一特征在不同 token 上的取值，那就是 BatchNorm 的语义，而且会让样本之间互相泄露信息。第 9 行的 unbiased=False 对应框架的总体方差定义；若用默认的无偏估计，分母是 d−1，结果会与框架差一个可测量的量，ln_diff 就不为零了。

第 3 帧最后一条边是自环，强调「逐位置独立」。这正是序列模型偏爱 LayerNorm 的原因：一条序列里每个位置都是一条独立样本，逐位置标准化对变长输入天然友好；推理时一次只来一个 token，也不需要先攒一个 batch 来估计统计量。

陷阱把方差算成无偏估计

你会觉得「统计学课上都用 n−1 分母，框架应该也一样」。真相是框架的 LayerNorm 用总体方差，分母是 n；本例显式写 unbiased=False 才与它一致。若不写，d = 4 时标准差会放大 √(4/3) 倍，输出尺度随之改变。程序不会报错，只是 ln_diff 从零变成一个明显的值。判断方法：把手写结果与 nn.functional.layer_norm 的最大绝对差打出来，若不为零，先查分母再查 eps。

3.4 Pre-LN 与 Post-LN：顺序换一下，梯度就换一条路

归一化放在子层之前还是之后，是 Transformer 实现里一个真实的设计选择。Pre-LN 的写法是本例采用的：x + Sublayer(LN(x))，恒等通路完全不经过归一化，浅层梯度有一条干净的直路。Post-LN 写成 LN(x + Sublayer(x))，相加之后才归一化，输出尺度被严格约束，但反向时要穿过归一化层才能到达残差相加处，深层训练通常需要更仔细的学习率预热。

两种写法都能收敛，差别在稳定性与梯度尺度上。Pre-LN 的浅层梯度更稳，深层模型常用；Post-LN 的输出尺度更规整，在较浅的模型里也表现良好。本例只演示 Pre-LN，不评价优劣——那是需要看具体深度、宽度与优化器的经验问题。重要的是你得能看出代码属于哪一种：看 LN 调用出现在子层之前还是残差相加之后即可。

两帧各自重写了 x 与关键节点，单独看也知道区别。第 1 帧的星号落在 ln 与 sum 上，是因为「先归一化」和「原样相加」这两件事同时发生；第 2 帧把 ln 移到最后，梯度回传时必须先穿过它。

工程惯例怎么在代码里一眼认出 Pre-LN

看 forward 的前三行：若第一行就是 h = self.ln1(x)，随后才把 h 喂给注意力，并把 a 与原始 x 相加，那是 Pre-LN。若第一行直接把 x 喂给注意力，相加之后才调用 ln1，那是 Post-LN。本例 block.py 第 28 到 30 行是标准 Pre-LN 写法。改排布时记得黄金值会变——归一化位置改了，out_norm 与 grad_norm 都会跟着动。

3.5 残差路径：雅可比里的那个恒等项

残差连接写成 x = x + Sublayer(x)。它的前向效果很朴素：把子层输出加到原输入上。真正值钱的是反向效果。设子层映射是 F，残差块是 G(x) = x + F(x)，它的雅可比是 I + J_F，其中 I 是恒等矩阵，导数恒为一。即使子层的雅可比 J_F 因为权重小、激活饱和而接近零，梯度仍能沿 I 那条路原样传回浅层。这就是「梯度高速路」这个比喻的数学来源：主路要经过子层的矩阵乘与激活，辅路是恒等映射，两条路在加法处汇合。

它可以解释一个常见现象：去掉残差后，深层网络的浅层参数几乎不动，损失早早变平；加回残差后，浅层开始有可观的更新。残差不是「多加一个数字」这么简单，它改变了整条雅可比乘积链的结构。代价也要记：通道数必须匹配，形状不一致要用线性投影对齐；相加会让尺度变大，所以有些实现会给残差分支乘一个缩放因子。

第 2 帧的星号落在恒等项上，这是整节的收束。第 3 帧把两条路重新画出来并指向总梯度，单独看也知道残差为什么有用。本例的 residual_norm=2.851002 量的是第二条残差相加之后、前馈输出尚未加入之前的残差流范数；它是「干净通路」的尺度快照，与最终输出范数 out_norm=3.222034 相比略小，说明前馈分支贡献了一部分增量。

陷阱以为残差可以随便加在任何地方

你会把残差写成 x = LN(x + F(x))，以为「反正有加号就是残差」。真相是这条恒等路被随后的归一化改写了：梯度从相加处回头时，要先穿过 LayerNorm 的雅可比，恒等项不再原样保留。Pre-LN 把归一化放在子层之前，就是为了保住相加处的恒等通路。判断方法：从输出往回画一条不经过任何可学习参数的路径，能一路走到输入才是真正的恒等高速路。

3.6 FFN：先升维再降维，逐位置加工

注意力负责让不同位置交换信息，FFN 负责对每个位置单独加工。本例的 FFN 是两层线性加一个 GELU 激活：Linear(d, hidden) 把四维升到十六维，GELU 引入非线性，Linear(hidden, d) 再压回四维。hidden 取 16，正好是 d_model 的四倍，这是常见经验比例；升维给模型一个更宽的中间空间做特征组合，降维则把形状收回，好让残差相加与下一层继续工作。

第 21 到 25 行是 FFN 的全部结构。为什么不用一层线性就够？一层线性后面接残差与下一层线性，整体仍然等价于一次线性变换，堆叠再多也没有非线性表达能力；中间那层 GELU 才是真正的非线性来源。为什么升维？在 d 维空间里，两层线性加激活能拟合的函数类受限于宽度；把中间层撑到 4d，模型有更多「临时特征槽」来组合信息，代价是参数量与计算量增加。

第 2 帧强调 FFN 对每个位置单独作用：三行之间没有任何矩阵乘法，所以它的成本是 O(nd²) 量级（这里 n=3、d=4、hidden=16），与序列长度线性相关。第 3 帧的自环提醒输出形状回到输入，残差相加因此合法。

大白话注意力和 FFN 的分工

把 block 想成一个编辑部。注意力是编辑会议，让不同位置的稿子互相引用、交换信息；FFN 是每位编辑在自己的工位上改稿，不跟别人商量。残差像原稿一直摆在桌上，改完的稿子与原稿并排放着，总有一次机会保留原稿的优点。归一化像统一的排版规范，保证每一轮交出来的稿子格式一致。四者缺一，流程都不完整。

3.7 两层堆叠：每一层都重复同一套形状

单个 block 的输入输出形状相同，所以堆叠只是循环。TinyStack 把两个 TinyBlock 放进 ModuleList，forward 里逐个调用，并把最后一次残差相加之前的流单独返回。这个「额外返回值」是本例的一个小设计：它让入口能打印 residual_norm，从而看到干净通路的尺度，而不只是最终结果。真实模型通常只返回最后的输出；这里多返回一个量，是为了让梯度高速路有一个可观测的锚点。

第 41 行用 ModuleList 而不是普通 Python 列表，是为了让 PyTorch 能注册每一层的参数。若写成普通列表，model.parameters() 看不到它们，参数计数会变成零，反向时这些参数也不会被优化器更新——这是一个不报错但后果严重的错误。第 48 行逐层更新 x 与 residual，第二层看到的是第一层的输出，因此信息确实在逐层传播。

层数从 2 改成 4 时，唯一变化是循环次数：参数量翻倍，前向计算量翻倍，梯度路径也变成原来的两倍长。这也是深层难训的根源：每多一层，反向时就要多乘一次雅可比，残差带来的恒等项是唯一的保底。

3.8 真跑：forward 与 backward 一次走完

入口先造输入与目标，再用固定种子初始化模型，跑前向、算均方误差、清零梯度、反向，最后打印范数与参数量。均方误差取所有元素差的平方均值，本例十二个元素（三行四列），所以 loss 是一个标量，能直接调用 backward()。

第 35 行的 .double() 把模型参数转成双精度，与输入张量的 dtype 对齐；忘了这一步会报类型不匹配。第 38 行的 zero_grad() 不能省：若不清零，多次反向的梯度会累加，范数不再是这一次损失对应的值。第 40 到 42 行把每个参数的梯度平方求和再开根号，得到全局梯度范数。这个量常用于观察训练是否稳定：突然暴涨可能意味着爆炸，长期接近零可能意味着梯度消失。

3.9 参数量：488 是怎么数出来的

参数计数看着只是几行求和，真正价值在于让你把架构超参和模型规模对应起来。本例 d_model = 4、hidden = 16、heads = 2、layers = 2。一个 block 的账如下：两个 LayerNorm 各有 γ、β 两个向量，合计 2×2d = 16 个；注意力有输入投影 3d×d = 48、输入偏置 3d = 12、输出投影 d×d = 16、输出偏置 d = 4，合计 80 个；FFN 第一层 d×hidden + hidden = 64 + 16 = 80，第二层 hidden×d + d = 64 + 4 = 68，合计 148 个。一个 block 共 16 + 80 + 148 = 244 个，两层就是 488 个。

注意 ln_params=16 是一个 block 内两个归一化层的合计，不是全模型的。全模型有两个 block，所以归一化参数总数是 32。清单把三类子层分别钉住，是为了让「总数对但结构错」的情况无处藏身：若你把 FFN 的 hidden 从 16 改成 8，总数会从 488 变成 408；若误把某一层从 ModuleList 里漏掉，总数也会变。单独钉住三类，能一眼看出变化来自哪里。

第 2 帧给出通式：一个 block 的参数量是 12d² + 13d（在 hidden = 4d 的前提下），代入 d = 4 得 192 + 52 = 244。第 3 帧再乘层数得到 488，与 stdout 逐字一致。把通式记住，你看到任何 hidden = 4d、Pre-LN 的配置，都能先估算规模再读代码。

大白话参数量与计算量不是一回事

参数量决定模型占用多少存储，计算量决定一步前向要多少次运算。本例 FFN 参数比注意力多（148 对 80），但注意力有 n×n 的分数表，长序列时它的计算增长更快。短序列里 FFN 可能是大头，长序列里注意力必然反超。谈「模型多大」看参数量，谈「为什么慢」看复杂度口径；把两者混为一谈，优化方向就会跑偏。

3.10 梯度范数：2.564057 说明了什么

grad_norm=2.564057 是把所有可训练参数的梯度平方加起来再开根号得到的标量。它不是损失值，也不是某个参数的梯度；它是整张梯度向量的长度。这个量在训练里有三个典型用法。第一，健康检查：初始点的梯度若全是零，说明前向被 no_grad 包住，或者参数没被注册。第二，趋势监控：训练中梯度范数突然放大几十倍，往往是学习率过大或数据里有异常样本。第三，配合裁剪：设定阈值后按范数比例缩放梯度，防止一次更新走太远。

本例的梯度来自一个固定目标上的均方误差，模型停在初始化点，不做更新。所以这个数只是一个快照，它的作用是让「反向真的走通了」变成可核对的证据。若把 loss.backward() 注释掉，grad_norm 会变成零或报错；若把 zero_grad() 漏掉，它会累加成另一个值。这两种阴性对照都能被黄金值抓住。

out_norm=3.222034 是最终输出张量的 L2 范数，residual_norm=2.851002 是最后一个 block 内第二条残差相加后、FFN 加入前的流范数。两者相差约零点三七，说明 FFN 分支确实贡献了增量，但没有把尺度炸开。若去掉 LayerNorm，尺度会在两层之间漂移，这两个数会明显变大或变小；若去掉残差，梯度范数通常会缩小。把三个范数一起钉住，等于从输出、残差通路、反向信号三个侧面给同一份模型拍了三张照片。

陷阱把梯度范数当成「越大越好」

你会觉得梯度范数大说明学得快，于是看到范数小就想调大学习率。真相是大范数常常意味着不稳定：一次更新把参数推到很远的位置，下一次梯度更大，几步之后损失变成 NaN。合理做法是观察若干步的趋势，而不是单步绝对值；配合残差、归一化与梯度裁剪一起看。本例的单步数字只用来证明反向走通，不承载任何「训练好不好」的结论。

3.11 为什么堆层数会难 train：连乘的账再算一次

把 L 个 block 串起来，反向时梯度要穿过 L 条雅可比链。每条链里都有残差项 I 与子层项 J_F，所以整体近似是 ∏(I + J_F)。若每个 J_F 的谱半径普遍小于 1，连乘之后信号指数衰减，浅层收不到更新；若普遍大于 1，梯度指数放大，一次更新就把参数推飞。初始化与归一化做的事情，是把 J_F 的尺度拉到一附近；残差做的事情，是给每条链保底一个 I。

这也是为什么本例要把 ln_diff 与 grad_norm 同时打印。前者保证归一化这一环没写错，后者告诉我们整条链在初始点是否健康。层数从 2 增到 8 时，你可以不改别的，只跑一次看 grad_norm 怎么变：若它明显缩小，说明信号在衰减；若明显放大，说明有失衡。这个「冻结初值体检」不需要训练时间，却能把初始化、归一化与拓扑问题分开。

实验记录把层数改成四层，观察三个范数

把 LAYERS = 2 改成 LAYERS = 4，真跑一次。参数量会从 488 涨到 976，out_norm 与 grad_norm 都会变；ln_diff 仍应为零，因为它只检验单层的归一化公式，与层数无关。这个对照很好地说明了「哪些量属于机制、哪些量属于配置」。做完把层数改回 2，黄金值对应两层版本。

工程惯例深层网络的六步体检

第一步，打印每层输入输出范数，看是否逐层放大或衰减一个数量级；本例的 out_norm 与 residual_norm 是最小模板。第二步，确认归一化公式与框架一致，ln_diff 必须为零。第三步，确认初始化与激活匹配，本例用框架默认初始化配 GELU。第四步，确认残差分支形状匹配，并且恒等通路没有被后续归一化改写。第五步，打印梯度范数，看是否在合理量级。第六步，最后才动学习率与裁剪。六步都不需要读框架源码。

3.12 与前面两个单元接起来：一条完整的自回归链路

把第 1 章三个单元连起来读，你会看到一条自回归语言模型的骨架。第一个单元给出注意力：Q/K/V 投影、缩放点积、softmax、乘 V、拆头拼头。第二个单元给这条链路补上位置与因果约束：绝对编码或 RoPE 让模型知道顺序，上三角掩码让第 t 个位置只看 0 到 t。第三个单元把注意力包进 block：Pre-LN 稳尺度、残差保梯度、FFN 做逐位置加工，然后把两个 block 叠起来。

还差什么？差 token 化与预训练目标——模型到底在预测什么、困惑度怎么算；差训练循环——数据怎么打包、loss 怎么降；差推理优化——生成时为什么不能每步重算全部历史；差对齐——怎么把续写器变成助手；差解码与评测——怎么选下一个词、怎么知道它在胡说。这些是后面七单元的事。但它们的共同底座，正是本单元这个能前向能反向的 block。

第 3 帧把最终结果单列出来，读图时能看到前两单元的产出如何被这一单元消费。所有中间形状仍是 (n, d)，这正是堆叠可行的原因。

3.13 黄金值与复现条件

清单九个黄金值各有来源：out_norm 与 residual_norm 来自真跑前向的张量范数；ln_diff 来自手写公式与框架实现的等价性，理论为零；grad_norm 来自一次反向的梯度向量长度；params、attn_params、ln_params、ffn_params 来自可数的结构账；loss 来自固定目标上的均方误差。四个整数可以直接手算核对，三个范数需要用真跑值反推，ln_diff 有理论支撑。

复现条件必须一起记住：种子 2026、d_model = 4、hidden = 16、heads = 2、layers = 2、双精度、Pre-LN、GELU、框架默认初始化、均方误差取均值、只反向一次且先清零梯度、打印六位小数、容差一乘十的负六次方。漏掉任何一条，重跑时都可能对不上。这与前两个单元的纪律一致：种子、形状、dtype、打印精度与容差，都是实验条件的一部分。

陷阱改了架构超参却只更新清单里的总数

你会把 hidden 从 16 改成 32，然后把 params 改成新值，以为闸门会绿。真相是 ffn_params 也会变，总数与分项必须同时更新；更重要的是 out_norm、grad_norm、loss 全都变了，因为你动了模型本身。正确做法是：先真跑拿完整 stdout，再按新结构手算参数账核对，最后更新所有受影响的黄金值。只改一个数，等于把实验变成「硬凑」，失去发现错误的能力。

3.14 从 block 到完整模型：下一步路标

这一单元结束时，你已经有了一个能前向、能反向、参数量可手算的两层解码器骨架。它没有词表、没有 tokenizer、没有训练循环，所以它还不能说人话；但它包含了大模型里最核心的那一块。后面的单元会依次接上：把文本切成 token 并定义 next-token 目标，把训练循环跑起来并看损失曲线，用 KV cache 把生成加速，用 SFT 与偏好优化把基座变成助手，最后用解码策略与评测判断它到底好不好。

每一块新零件都会沿用本单元建立的方法：小规模真跑、标量用等号、张量用方括号、黄金值写进清单、沿计算链每隔几步钉一个量。规模会变大，但方法不变。你现在能手算 params=488，将来看到报出几百亿参数的模型，也知道那个数字是怎么按 d_model、层数、hidden 一层层数出来的；你现在能解释 grad_norm=2.564057，将来看到训练曲线里的梯度尖峰，也知道该先查哪一层。

3.15 从方差账本到归一化：方法上的复用

机器学习分册里已经用过「方差」当诊断工具：把五层同形网络的每层激活方差打出来，看信号从第几层开始失控。本单元用的是同一把尺子，只是量的是范数而不是方差。out_norm 与 residual_norm 是前向信号的尺度快照，grad_norm 是反向信号的尺度快照。两者互为镜像：前者失控，后面的层看到的输入已经没有区分度；后者失控，浅层参数收不到更新或者被一次更新推飞。

区别在于本例不更新参数。它把模型冻在初始化点，只做一次前向与一次反向，所以读数不受优化器、学习率与数据顺序干扰，可以当作纯粹的结构体检。机器学习分册那边的七条链也是这个思路：不训练，只看方差。这种「冻结初值体检」的成本只有几行打印，却能把初始化、损失缩放、反向实现三类原因分开。真正训练时若发现 loss 不降，先做一次体检再调超参，往往比盲目试学习率省时间。

手写 LayerNorm 的 ln_diff=0.000000 则承接了PyTorch 桥接册的纪律：独立手算一次，再让框架算一次，两个数字相减。这条路径不共享中间量——手写版直接按公式求均值方差，框架版调用自己的融合算子——所以差为零才说明两边都对。若哪天框架改了 eps 的默认位置，手写版不会跟着改，ln_diff 会立刻跳起来。这种「一改就失败」的性质，比任何口头保证都可靠。

3.16 常见变体会怎样改写黄金值

把 block 里的某个零件换掉，哪些黄金值会动？这是理解架构最有效的练习。把 GELU 换成 ReLU，参数量不变，loss、out_norm 与 grad_norm 会变，因为逐位置非线性改了；ln_diff 不变，因为它只检验归一化层。把 hidden 从 16 改成 32，ffn_params 与 params 都会变，前向与反向的三个范数也会变。把 heads 从 2 改成 1，注意力参数量不变（投影矩阵形状只依赖 d_model），但数值会变，因为拆头方式变了。

把 Pre-LN 改成 Post-LN，所有前向与反向数值都会变，参数量却不变——归一化参数还是那些。这说明参数量只数张量与形状，不数连接顺序。把残差分支乘一个缩放因子，参数量仍不变，但 residual_norm 会明显变化。把某一层从 ModuleList 里漏掉，参数量会少一半，out_norm 与 grad_norm 一起变。每一类改动都有可预测的后果，这就是把五个维度（参数量、两个前向范数、梯度范数、归一化差）分别钉住的价值。

实验记录亲手做一次结构变体

把 nn.GELU() 改成 nn.ReLU()，真跑一次。params 仍是 488，ln_diff 仍是零，但 loss、out_norm 与 grad_norm 都会变，闸门报 numeric_value_mismatch。再改成原来版本，确认 stdout 逐行回到黄金值。这个对照说明清单不只是「记录结果」，它其实是在描述架构本身：改了架构却没更新清单，等于声称一个不同的模型通过了原来的检验。

工程惯例什么时候该更新黄金值，什么时候该修 bug

判据是「改动是否有意为之」。有意改了架构或超参，就先真跑拿完整 stdout，手算核对受影响的整数，再更新清单里所有相关黄金值；无意改错了实现，就修回源码，黄金值一字不动。最难判断的是「我改了精度」这类情况：它不改变数学，却会改变六位小数末位，此时应把精度当作实验条件的一部分重新取数，并在正文里写清新条件。总之别反过来——为了让闸门变绿去凑黄金值，那就把检验工具关掉了。

3.17 一个容易混淆的词：block 与 layer

这一册里会反复出现「层」这个词，但它在两处含义不同。本单元说的是 Transformer block，一个由注意力、归一化、残差与 FFN 组成的复合单元；LAYERS=2 指的是把两个这样的复合单元叠起来。机器学习分册里说的「五层网络」通常指五个线性加激活的简单层。两者的共同点是都能用雅可比连乘来分析，不同点是一个 block 内部已经有残差与归一化，信号条件比裸线性层好得多。

读代码时别被命名绕住：这里的 blocks 是一个 ModuleList，里面每个元素都是 TinyBlock；每个 TinyBlock 内部又有两个 LayerNorm、一个注意力和一个由两层线性组成的 FFN。若把 FFN 里的线性层也算成「层」，那么两个 block 一共包含四个线性层与四个归一化层。计数时必须说明口径——清单里的 params=488 按可训练张量数，不按「层数」数。把口径写清，是避免讨论中互相误解的最省事办法。

最后提醒一句：本节的模型停在初始化点，既没有优化器也没有数据批次，因此十三行 stdout 描述的是「结构是否正确」，不是「训练效果好不好」。后面接上预训练循环、学习率与数据打包之后，你才会看到 loss 曲线下降、梯度范数起伏。到那时回头看这份冻结体检，它的价值反而更清楚：任何训练异常都能先在这里排除结构问题，再去查数据与优化器。

小结这一节的要点

  • Pre-LN 把归一化放在子层之前，残差恒等通路不被改写；残差雅可比含恒等项 I，保住浅层梯度；
  • FFN 先升维到 hidden=16 再降回四维，提供非线性逐位置加工；

  2. Pre-LN 与 Post-LN 的连接顺序分别是什么？为什么 Pre-LN 的恒等通路更干净？
  3. 残差块的雅可比为什么是 I + J_F？这对浅层梯度意味着什么？
  4. FFN 为什么要升维再降维？本例 hidden 取多少，参数量分别是多少？
  5. 手算一个 block 的参数量：注意力、两个 LayerNorm、FFN 各多少？两层合计多少？
  6. out_norm、residual_norm、grad_norm 各自量的是什么？为什么三个要一起钉？
  7. 把层数从 2 改成 4，哪些黄金值会变、哪些不会？说明你的判断。
注自测题答案
  1. 输入形状是 (n, d)，沿最后一维表示每个 token 在自己的 d 个特征上求统计量，与其他 token 无关；写成 dim=0 就变成跨 token 的同一特征统计，属于 BatchNorm 语义并会让样本互相泄露。框架 LayerNorm 用总体方差，分母是 d，所以要写 unbiased=False，否则标准差放大 √(d/(d−1)) 倍。
  2. Pre-LN 是 x + Sublayer(LN(x))，归一化在子层之前；Post-LN 是 LN(x + Sublayer(x))，归一化在相加之后。Pre-LN 的恒等通路从输入直接到相加处，不穿过归一化层，浅层梯度更稳。
  3. 残差块 G(x)=x+F(x)，求导得 I+J_F。即使 J_F 接近零，恒等项 I 的导数仍为一，梯度可沿辅路直达浅层，避免多层连乘导致消失。
  4. 升维给模型更宽的中间空间做特征组合，非线性由中间的激活提供，降维把形状收回以便残差相加与堆叠。本例 hidden=16，一个 block 的 FFN 有 148 个参数，注意力 80 个，两个归一化共 16 个。
  5. 注意力 3d²+3d+d²+d = 48+12+16+4 = 80；两个 LayerNorm 共 4d = 16；FFN 为 d×16+16+16×d+4 = 64+16+64+4 = 148。一个 block 244，两层 488。
  6. out_norm 是最终输出张量的 L2 范数，residual_norm 是最后一个 block 内第二条残差相加后的流范数，grad_norm 是全部参数梯度的向量长度。三者分别从输出尺度、干净通路尺度与反向信号强度三个侧面描述同一份模型，一起钉住才能排除「单个量凑对」。
  7. params 从 488 变成 976，out_norm 与 grad_norm 也会因层数增加而改变，loss 同样会变；ln_diff 不变，因为它只检验单层归一化公式与框架是否一致，与层数无关；attn_params、ln_params、ffn_params 是单个 block 内的分项，也不变。
