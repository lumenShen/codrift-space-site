2.1 先看工程长什么样

上一单元把注意力从 QKᵀ 一路写到乘 V，还用手写多头与框架结果对上了账。但那份实现有一个致命缺口：它不知道「第几个」这个概念。把三行输入换个顺序，注意力照样算，每个输出行都跟着它对应的输入行走——公式里没有任何一项在说「我在序列里的位置」。对续写任务来说更糟：第 0 个位置在算权重时会看到第 1、第 2 个位置，等于偷看了还没生成的答案。这一单元就补这两块：位置与掩码。

例子放在 books/llm/examples/ch01/position_and_mask/。src/posmask.py 提供四个能力：正弦余弦位置编码、因果掩码、带可选掩码的缩放点积注意力、RoPE 旋转；src/main.py 固定三种随机源，跑「不加位置」「加位置」「加位置且加掩码」三条路径，再单独验证 RoPE 的模长不变性。清单 lm02-mask.json 声明 mode=numerical，把十一个黄金值与 atol=1e-6 写在证据声明里。入口从本地模块导入函数，这是第 1 章统一的工程纪律。

第 2 帧保留了上一单元的文件名，是为了看清本单元新增了什么；图元只画与论点有关的结构，不必把每个文件都展开到完整目录深度。第 3 帧的清单是闸门的入口：没有它，正文里的 output 块就没有人声明，也就不存在机器可执行的对账。

工程惯例为什么把位置编码和掩码放在同一个模块

因为它们都作用在「注意力之前」同一层：位置编码改输入张量，掩码改分数表，二者最终汇进同一次 softmax。把它们分开写在不同文件里当然也可以，但你会失去一个重要的对照——同一份 attention 函数，传不传 mask 就得到双向与单向两种行为。现在四条能力都在 posmask.py，入口按顺序调用，读者一眼能看出「加位置」与「加掩码」是两次独立的改动。

2.2 置换等变性：注意力本身没有顺序感

先做一个思想实验。把输入三行换成另一种排列，比如把第 0 行与第 2 行对调，其余不动。注意力公式里只有行向量之间的点积与 softmax，没有任何「这是第几行」的信息，所以算出来的分数表只是行列同时重排，输出表也只是跟着重排。这种性质叫置换等变性：输出随输入一起变，但不产生「位置变了」之外的额外语义。换句话说，注意力把序列当成一组带内容的集合，而不是一条有先后的线。

这对机器翻译之类的任务其实无所谓——源句子里的词本来就要根据内容互看；但对语言建模是致命的。「猫 吃 鱼」和「鱼 吃 猫」包含同样的三个词，若没有位置信息，两句话的输入在注意力眼里只是同一组向量的不同排列，模型原则上无法区分谁吃谁。人类读句子时靠词序判断主宾，模型必须靠某种显式的顺序信号。补顺序的方式很多，最直观的是给每个位置的嵌入向量加一个只依赖位置编号的向量，让「第 0 个位置的猫」与「第 2 个位置的猫」变成两个不同的输入。

第 3 帧的星号落在输出上，是因为「输出跟着重排」正是置换等变性的表现：它说明注意力没有额外的顺序知识。若加入位置编码，帧 3 就要改写——同一个 token 在不同位置拿到不同的位置向量，分数表不再只是简单重排。这就是下一节要做的事。

大白话用大白话说位置编码

给每个座位发一张座位号牌，把它贴到坐在那儿的人身上。人的长相没变，但你看到「三号位的这个人」和「一号位的同一个人」时， input 已经不同了。正弦余弦编码就是一套固定的编号规则：低位维像秒针，转得快；高位维像时针，转得慢。把两套周期信号拼在一起，每个位置都拿到独一无二的波形组合。

2.3 正弦余弦位置编码：不同维度用不同波长

本例用最经典的绝对位置编码：对每个位置 pos 与每个维度 i，偶数维取 sin(pos / 10000^(2i/d))，奇数维取 cos(pos / 10000^(2i/d))。这里 i 是「第几对维度」，不是列号本身；相邻两维共用同一个角速度，一个用正弦、一个用余弦。分母里的 10000 是底数，指数随维度对数式增长，于是低维的波长短、变化快，高维的波长长、变化慢。模型既能读到「相邻位置差一位」这种细粒度信息，也能读到「相隔很远」这种粗粒度信息。

第 9 行把位置编号做成列向量，第 10 行把维度编号做成行向量，两者相除时靠 NumPy 广播得到一张 n×d 的角度表——第 pos 行第 i 列就是那个位置在那个维度上的相位。第 11 行的 dim // 2 让相邻两维共享波长，指数最大约为 (d−2)/d，所以最小角速度约是 1/10000。第 12 行用 np.where 一次性选正弦或余弦，偶数下标取正弦，奇数下标取余弦。

本例 n = 4、d = 4，位置 0 的编码是 [sin0, cos0, sin0, cos0] = [0, 1, 0, 1]，正是 pe0:[0.000000,1.000000,0.000000,1.000000]；位置 1 的前两维是 [sin1, cos1]，约 [0.841471, 0.540302]，后两维是 [sin0.01, cos0.01]，约 [0.0099998, 0.99995]。同一个小数值在第 0 对维度上变化明显，在第 1 对维度上变化极小——这就是「多尺度」的直观含义。

第 2 帧的星号落在角度表上，因为「波长不同」这件事在这一步已经确定；第 3 帧单独把编码表写出来，单独看也知道它从哪来。编码表是常量：它不随训练更新，不需要梯度，也不是参数。这一点很重要——位置编码是「写进输入的坐标」，不是模型学出来的权重。

陷阱把位置编码加到注意力输出上

你会想：反正都是同一个形状的张量，加在输入或加在输出有什么区别？区别很大。加在输出上，位置信息只影响这一层的最终表示，下一层又变回「无编号」的集合；加在输入上，每一层都能从编码里读出位置。更隐蔽的问题是：加在输出上会让残差连接把位置信号一路带下去，尺度逐层累积，数值容易失控。判断方法很简单：打印第一层的输出与输入的差，若位置编码应该起作用而这个差里看不到它，说明加错了地方。

2.4 加位置到底改变了什么：三条路径的数字对照

入口跑了三条路径。第一条是上一单元的注意力，输入就是原始 x，得到 base_out 与 base_w；第二条把位置编码加到 x 上再算，得到 pos_out；第三条在第二条基础上再加因果掩码，得到 masked_out 与 mw。三条路径共用同一个 attention 函数，唯一差别是输入与掩码参数，因此任何输出差异都能归因到「加了位置」或「加了掩码」其中一个改动。

第 34 行把 NumPy 编码转成同 dtype 的张量再相加，这一步既能让形状对齐，也避免浮点类型不一致。第 35 行取所有输出元素里最大的绝对差，得到一个跨全部 token 的单一证据。真跑给出 base00=0.610838、withpos00=0.975415：第 0 行的第 0 个分量确实变了。pos_diff=1.326088 是全局最大差，说明有些位置的改动比第 0 行更大。

为什么要量最大差而不是只看一个点？因为位置编码对不同位置的影响不同：位置 0 的编码全是 0 和 1，改动相对温和；位置 3 的编码涉及多个角度，可能让分数表发生更大重排。只看一个点容易以偏概全；取最大值能回答「有没有哪个位置被明显改变」这个问题。清单同时钉基线与加位置后的单点值，再加上全局差，三个量互相支撑：若只钉差值，程序可以随便改两个值保持差不变；同时钉住绝对值和差，假实现就很难蒙混。

实验记录把位置编码整体乘零

把第 34 行的 x + torch.tensor(pe, ...) 改成 x + 0 * torch.tensor(pe, ...)，真跑一次。你会看到 withpos00 退回 base00，pos_diff=0.000000，闸门立刻报 numeric_value_mismatch。这个阴性对照说明那些数字不是「反正都会有的浮点噪声」，而是真的由位置编码引起的。做完把代码改回去。

2.5 因果掩码：上三角填负无穷

位置编码解决了「谁在第几位」，还没解决「不许看未来」。做自回归生成时，模型在预测第 t 个词时只能看到 0 到 t 的位置，否则训练时它直接抄到答案，推理时却根本没有未来可看，训练和推理的分布就不一致。因果掩码的表达非常简洁：生成一张 n×n 的布尔表，严格上三角（行号小于列号）为 True，其余为 False；True 表示「这个位置不允许被注意」。

第 17 行的 diagonal=1 是关键：对角线保留，对角线右上方全部为 True。若写成 diagonal=0，连自己都被屏蔽，每行会变成「只看过去」，第 0 行一个可看的位置都没有，softmax 会得到 NaN。第 25 行用 masked_fill(..., float("-inf")) 把分数表里的未来位置变成负无穷，softmax 的指数严格为零，权重严格为零。第 26 行仍沿最后一维归一化，所以每一行的有效位置重新加起来为 1。

第 3 帧把三行各自写全，是因为「每一帧自包含」：单独打印第 3 帧时，读者也要能看出三角结构的含义。第 0 行只有一个非零格，所以它的输出就是自己的 V；这正是下一节 masked00=1.000000 与 first_self=1.000000 的来源。

陷阱把掩码当成「给分数乘零」

你会想当然地以为「屏蔽就是把这个位置的分数乘零」，于是写出 scores = scores * (~mask)。你会看到输出确实变了，但权重不再满足每行和为 1：被屏蔽位置的分数变成 0，指数 e⁰ = 1 仍在分母里占一份。真相是屏蔽必须发生在 softmax 之前，且要让该位置的指数严格为零，所以填负无穷而不是乘零。另一个相邻陷阱是布尔语义写反：PyTorch 的布尔 attn_mask 里 True 表示禁止注意，某些库里「1 表示保留」，混用会让「加掩码」变成「只注意被屏蔽的位置」，而且往往不报错。

2.6 第一行的证据：只看自己意味着什么

入口专门量了四个与掩码有关的量。upper_max 是从权重表严格上三角取出的最大绝对值，真跑为 upper_max=0.000000——所有未来位置的权重都是零，一个不漏。first_self 是权重表第 0 行第 0 列，first_self=1.000000；first_future 是第 0 行第 1 列，first_future=0.000000。row_sum=1.000000 说明第一行仍然是一个合法概率分布。四个数合起来，把「第一行只看自己」这件事从文字变成了机器可复算的证据。

第 39 行用 masked_select(mask) 只挑出严格上三角的元素，再取绝对值最大；这比逐格目视检查严格得多，也更容易写成黄金值。第 40 与第 41 行分别钉住「自己」与「下一个位置」，前者应为 1，后者应为 0。为什么要单独钉 first_future？因为如果只钉 upper_max，一个把掩码对角线与上三角整体反转的错误实现也可能让上三角为零；同时钉住自己与未来，语义反了就藏不住。

第 3 帧解释了 masked00=1.000000：第 0 个位置的输入 x₀ 加上位置编码后是 [1.0, 1.5, −0.5, 2.0]，加权求和只取这一行自己的值，第 0 个分量就是 1.0。这不是巧合，而是因果掩码在第一个位置上必然的结果——它没有任何过去可看，只能看自己。

2.8 双向注意力与单向注意力：同一个函数，两种语义

把上一节的 attention 函数与掩码参数连起来看，你会发现双向与单向注意力在数据流上只差一个布尔表。不传掩码时，每个位置都能看到全部位置，这叫双向注意力，适合编码器式的理解任务：一个词的含义常常由它后面的词决定。传入因果掩码时，每个位置只能看到自己与过去，这叫单向注意力，适合自回归生成：预测下一个词时未来还没产生。

两帧都把分数表与输出重写了一遍，所以单独看第 2 帧也知道变化发生在哪里。第 3 帧强调用途差异：这不是两种数学，而是同一个数学在两种信息约束下的用法。工程里最强的注意力模型往往是「编码器双向、解码器单向」，再用交叉注意力把两者接起来；本例只做自注意力，但那套交叉注意力使用的掩码语义与这里完全一致。

工程惯例为什么 decoder-only 模型也要因果掩码

因为它把「理解」与「生成」统一成同一个任务：给定前缀，预测下一个词。训练时整条序列已经在那儿了，如果不加掩码，模型可以直接从后面的 token 抄到答案；推理时后面的 token 还没生成，模型突然失去这条捷径，表现断崖式下降。加了掩码之后，训练时每个位置看到的信息量与推理时逐字生成完全一致。这种「训练与推理信息一致」的原则，比「掩码能防偷看」这句话更本质。

2.9 RoPE：把位置写成一次旋转

正弦余弦编码是「加到输入上」的绝对位置信号。另一条主流路线是相对位置编码，其中 RoPE 的想法特别漂亮：不把位置加到向量上，而是把向量按位置旋转一个角度。把相邻两维 (x₍₂ᵢ₎, x₍₂ᵢ₊₁₎) 看作平面上的一个点，位置 m 让它逆时针转 m·θᵢ 弧度，位置 n 让另一个向量转 n·θᵢ。旋转之后再做点积，结果只依赖它们的夹角 (n−m)·θᵢ，也就是相对距离，而不是绝对位置。

第 32 行给每对维度算一个角速度，第 33 行用位置编号乘角速度得到相位。第 37 与第 38 行是标准的二维旋转矩阵：第一分量是 a·cos − b·sin，第二分量是 a·sin + b·cos。最后一行的 stack 与 flatten 把奇偶维交错还原成原来的形状。旋转矩阵是正交的，所以向量的模长不会变；入口专门量了这一点：rope_norm_diff=0.000000。

为什么模长不变值得单独钉一个黄金值？因为一旦实现时把 cos 与 sin 的位置写反、或者只旋转了一半维度，模长通常就会变。模长变了意味着信息被人为放大或缩小，深层堆叠后尺度会失控。相比「旋转之后注意力更好」这类难以量化的说法，模长不变是一个清晰、便宜、可机器检查的性质：把旋转前后的范数相减取最大值，真跑为零。

陷阱把 RoPE 当成「另一种位置编码向量，直接加到输入上」

你会看到 RoPE 也涉及 sin 与 cos，于是把它和上一节的编码混为一谈，写出 x + rope_vector。真相是 RoPE 改的是向量的方向，不是坐标值；它作用在 Q 与 K 上，而且要在拆头之后、算点积之前。直接相加会破坏模长不变性，也让「点积只依赖相对距离」这个结论失效。判断方法：把两个同样内容、不同位置的向量做点积，若旋转实现正确，结果只依赖它们的距离；若你写成了加法，结果还依赖绝对位置。

2.10 绝对位置、相对位置与外推：各自的边界

绝对位置编码给每个编号一张固定牌，优点是简单、无需额外参数，缺点是模型没见过的长度就没有对应的牌。训练时最长 2048，推理时给到 4096，后半段的牌从没在训练里出现过，行为很难预测。相对位置编码换一种问法：不关心绝对编号，只关心「我们俩差几位」。RoPE 通过旋转把相对距离写进点积，因而在长度外推上通常更稳健，但它也不是魔法：超出训练长度的相位仍可能落在模型没充分学习的区间。

本例的 d = 4 让角速度只有两个值，外推讨论只能停留在直觉层面。真实模型里 d_k 常常是 64 或 128，角速度按 10000 的幂次铺开，涵盖从相邻到极远的距离尺度。理解这套铺法有一个好用的比喻：低位维是秒针，走一格就是一秒；高位维是时针，走很久才动一点。模型同时读秒针与时针，既能分辨相邻词，也能感知长距离结构。

大白话把两种位置方案说成人话

绝对编码像是给每个人发一张写着座位号的胸牌，你一看就知道他坐第几排；相对编码像是记录两个人之间隔了几排，你不知道他们各自坐哪，但知道距离。胸牌实现简单、信息直接；距离记录在换座位或扩展到更大的礼堂时更稳。RoPE 的巧妙之处在于：它看起来是在给每个向量转一个绝对角度，但两个向量做点积时，绝对角度相减，只剩相对角度。

2.11 填充掩码：另一类「不许看」

因果掩码不是唯一的掩码。一个 batch 里句子长短不一时，短句尾部要补占位符，这些位置不该被任何 token 注意，否则模型会把占位符当成内容。填充掩码通常是一个长度为 n 的布尔向量，占位位置为 True，再广播成 n×n：每个 query 都不能看占位列。它与因果掩码可以叠加，逻辑或起来就是「既不能看未来，也不能看占位」。

第 3 帧把两类约束合到一张表里，这是实际系统里的常态。广播这一步很容易写错形状：框架常要求掩码形状是 (batch, 头数, 序列长, 序列长)，少一个维度就会报形状错，或者更糟——悄悄按错误方向广播。本例没有 batch 维，掩码就是朴素的 4×4，正好把语义讲清；真正接 batch 时，先用 unsqueeze 补维，再打印形状确认。

陷阱混淆布尔掩码与浮点掩码

布尔掩码里 True 表示禁止注意，masked_fill 把它变成负无穷。浮点掩码则是直接加到分数上的偏置，0 表示不屏蔽，一个很大的负数表示屏蔽。两者语义几乎相反：把布尔表当浮点表用，True 会变成 1，等于给位置加一分，模型反而更注意它。判断方法：打印两张掩码的类型与取值，布尔表只有真假，浮点表是分数偏置；调用框架前先确认它接受哪一种。

2.12 黄金值从哪里来：手算、真跑与阴性对照

清单里的十一个黄金值各有独立来源，没有一个是「程序打了什么就写什么」。pe00 与 pe01 来自公式 sin0 与 cos0，手算即可；base00 与 withpos00 来自两条真跑路径，可以拿权重表手算核对；pos_diff 是全局最大差，反映编码影响的范围；upper_max、first_self、first_future、row_sum 描述因果掩码的三角结构，由布尔表的定义决定；rope_norm_diff 来自旋转矩阵的正交性，理论上严格为零。

容差 atol=1e-6 的依据仍是打印精度：六位小数输出带来的舍入误差不超过五乘十的负七次方，双精度运算本身的误差在十的负十五次方量级。一乘十的负六次方的容差容得下打印误差，又远小于任何真实错误会造成的偏差。若把黄金值改成程序输出后硬凑的数，闸门照样会绿，但你会失去发现错误的机会。

实验记录三个阴性对照，确认黄金值不是摆设

第一，把 sin_cos_positions 里的 np.sin 改成 np.cos，pe00 会从 0 变成 1，编码表整体改变，多个数值同时失败。第二，把 causal_mask 的 diagonal=1 改成 diagonal=0，first_self 失败，第一行权重全零导致 NaN。第三，把 rope_rotate 里的减号改成加号，模长不再守恒，rope_norm_diff 失败。三个变体一次只改一处，跑完记得改回原样。闸门报的码分别是 numeric_value_mismatch、numeric_value_invalid 与 numeric_value_mismatch。

你会觉得「只要输出层保证不看未来就行」。真相是残差连接会把浅层信息原样送到深层，浅层偷看到的未来内容会沿残差通道一路上传到输出，输出层再加掩码已经来不及。正确做法是每一层自注意力都用同一张因果掩码。判断方法：在中间层打印权重表的上三角最大值，若不是零，说明那一层 leaked。这也是为什么掩码通常作为模型配置的一部分传进每一层，而不是只在最后调用一次。

2.14 从位置与掩码到完整 block

现在手里的零件有：投影出 Q/K/V、缩放点积、softmax、乘 V、拆头拼头、位置编码、因果掩码、RoPE。把它们拼起来，就得到真实 Transformer 解码器里最重要的一段。还差三样：残差连接让梯度有直达通道，层归一化稳住数值尺度，逐位置前馈网络对每个 token 单独加工。下一单元会把这三样接进来，做一个两层的完整 block，跑一次前向与反向，并报告梯度范数与参数量。

所有后续操作的形状仍然是 (n, d)。位置编码的输入输出是 (n, d)，掩码是 (n, n) 或带 batch 与头维的扩展，注意力输出回到 (n, d)，残差相加与层归一化都不改形状。正因为形状稳定，这些部件才能像搭积木一样堆起来。复杂度账也要接着看：本单元的注意力仍是 O(n²d)，位置编码是 O(nd)，掩码构造是 O(n²)；真正随长度平方增长的只有分数表那一块。

工程惯例复现这个实验要记哪些条件

序列长 4、模型维 4、三种种子固定为 2026、位置编码底数 10000、因果掩码取 diagonal=1、掩码位置填负无穷、分数沿末维 softmax、RoPE 底数同为 10000、打印六位小数、容差一乘十的负六次方。清单保存黄金值与容差，源码保存怎么算，正文保存这些数为什么是这个值。三者合起来才是一份别人能照着重做的记录；缺任何一条，重跑时就可能出现「明明一样却对不上」的尴尬。

2.15 为什么这里全用双精度：小例子里的数值纪律

你可能会注意到，本例的输入张量显式写了 dtype=torch.float64，位置编码也用 np.float64 生成。真实大模型训练常用半精度或混合精度，这里为什么反其道而行？原因不是「双精度更高级」，而是本单元要把机制钉死：黄金值对应的是六位小数，任何额外舍入误差都会混淆「机制写错」与「精度不够」两类问题。双精度让计算误差落在十的负十五次方量级，远小于打印误差，于是闸门失败时几乎一定是语义错误，而不是浮点噪声。

这也解释了为什么 upper_max=0.000000 与 rope_norm_diff=0.000000 敢写成严格零。被掩码屏蔽的位置填的是负无穷，softmax 的指数严格为零，结果是数学意义上的零；RoPE 的旋转矩阵在双精度下正交到十的负十六次方，范数差打印成零。若换成半精度，这两个量可能落在十的负三次方量级，虽然机制完全正确，六位小数的黄金值却会失败。换精度时应当重新取真跑 stdout 并更新清单，而不是硬把黄金值改成零之外的数去迁就实现。

种子纪律也值得再强调一次。位置编码是常量，理论上与随机数无关；但 random、numpy、torch 三条随机流仍然固定为 2026。下一单元会引入 PyTorch 初始化的两层 block，那时随机源直接决定 out_norm 与 grad_norm。如果本单元不养成固定三种种子的习惯，到了下一单元遇到黄金值漂移，你就要回头猜是哪条流没管住。现在多写两行 seed(...)，换来的是整章实验的可复现性。

实验记录把 dtype 降成单精度会发生什么

把 main.py 里输入张量的 dtype=torch.float64 改成 dtype=torch.float32，其余不动，真跑一次。你会看到大部分数值在六位小数的末位漂移，rope_norm_diff 可能不再是零，闸门报 numeric_value_mismatch。这并不说明 RoPE 错了，只说明黄金值对应双精度。做完改回双精度。这个对照的教训是：精度是实验条件的一部分，必须写进复现记录，和种子、形状、底数一样重要。

2.16 掩码与训练推理一致性：再往前一步

因果掩码最容易被低估的一点是：它不只是「防止偷看」，而是让训练时每个位置看到的信息量与推理时完全一致。推理时我们一个字一个字往外吐，第 t 步只有前缀；训练时整条序列同时摆在那里，如果不 masked，第 t 个位置就能直接读到第 t+1 个词。两边信息量不同，模型学到的策略就会在部署时失效。这个原则比任何关于「伦理」或「防作弊」的说法都更工程：它讲的是分布一致性。

在 KV cache 之类的推理优化里，这条原则还会以另一种形式出现：缓存里只存已经生成过的 key 与 value，新 token 的查询只对缓存做注意力。这等价于把因果掩码应用到已经截断的序列上，形状不同但语义相同。你现在把 upper_max=0.000000 这一个数字理解透，将来看到缓存版解码代码里那些形状变换就不会迷路。

工程惯例怎么把本单元的知识迁移到带 batch 的实现

第一步，确认掩码形状是 (batch, 头数, 序列长, 序列长)，或用可广播的简化形状；第二步，确认布尔语义是 True 表示禁止；第三步，在每层自注意力之前应用，而不是只在最后一层；第四步，打印一张小 batch 的权重表，检查严格上三角是不是全零。四步都不依赖具体框架，换成任何实现都能照做。本例没有 batch 维，正好把语义讲清；接 batch 时多出来的只是形状搬运，不是新的数学。

小结这一节的要点
  • 注意力本身具有置换等变性，必须显式补上位置信息才能区分「谁在第几位」；
  • 正弦余弦编码在不同维度用不同波长，位置 0 的编码是 [0,1,0,1]；
  • 真跑 base00=0.610838、withpos00=0.975415、pos_diff=1.326088，说明加位置确实改变输出；
  • 因果掩码取严格上三角为 True，masked_fill(-inf) 让未来位置的权重严格为零；
  • upper_max=0.000000、first_self=1.000000、first_future=0.000000 把「第一行只看自己」变成机器证据；
  • RoPE 把位置写成旋转，模长不变，rope_norm_diff=0.000000；双向用于理解，单向用于生成。

  1. 什么是置换等变性？为什么注意力本身分不清「猫吃鱼」和「鱼吃猫」？

  3. base00、withpos00 与 pos_diff 分别说明什么？为什么只钉差值不够？
  4. 因果掩码为什么取 diagonal=1 而不是 diagonal=0？为什么填负无穷而不是把分数乘零？
  5. 真跑里 upper_max、first_self、first_future 各是多少？它们合起来证明了什么？
  6. RoPE 为什么能保住模长？为什么它体现的是相对位置？
  7. 填充掩码与因果掩码怎么叠加？布尔掩码与浮点掩码有什么语义差别？
注自测题答案
  1. 置换等变性指输出随输入的行重排而重排，公式里不含位置编号。三句话的 token 集合相同、顺序不同时，注意力只能看到相同的词向量集合，无法区分主宾关系，除非显式加入位置信号。
  2. 位置 0 的四个分量是 [sin0, cos0, sin0, cos0] = [0,1,0,1]；位置 1 约为 [0.841471, 0.540302, 0.0099998, 0.99995]。分母里的指数随维度增长，低维角速度接近 1、高维接近万分之一，于是同时提供细粒度与粗粒度的顺序信息。
  3. 前两个是同一位置在加位置前后的输出绝对值，第三个是全局最大改动。只钉差值，程序可以随便改两个绝对值保持差不变；同时钉住绝对值和差，才能排除这种凑数。
  4. diagonal=1 保留对角线，位置还能看自己；取 0 会把对角线也屏蔽，第 0 行没有任何可看位置，softmax 得到 NaN。乘零会让被屏蔽位置的指数 e⁰ = 1 仍占分母一份，权重不再和为 1；只有负无穷让指数严格为零。
  5. 分别是 0.000000、1.000000、0.000000。三者说明所有未来格权重严格为零，第 0 行把全部概率给了自己，且这一行仍是合法分布。
  6. RoPE 用二维旋转矩阵，正交变换保持向量模长，真跑差为零。两个向量分别旋转 m·θ 与 n·θ 后做点积，角度只差 (n−m)·θ，绝对位置被消掉，只剩相对距离。
  7. 填充掩码标出占位列，因果掩码标出未来格，两者逻辑或即可同时约束。布尔掩码里 True 表示禁止注意，靠 masked_fill(-inf) 实现；浮点掩码是直接加到分数上的偏置，0 表示不屏蔽，混用会让语义反转。
