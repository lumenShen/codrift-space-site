3.1 先看工程长什么样

前两章我们把注意力、位置、Transformer block 和预训练目标走了一遍，模型已经会「续写」，但它不会「听指令」。一个只会续写的基座模型，你给它一句「中国的首都是哪里」，它可能接着写「……是北京，北京是中国的政治中心，中国的历史……」，而不是干脆回答「北京」。监督微调（supervised fine-tuning，SFT）要做的，就是用一批「指令—回答」样例，把这个续写机器改造成一个助手。这一单元不训练大模型，而是把 SFT 最容易被忽略的那个零件——loss mask——拆到能逐位置手算的程度。

例子叫 sft_loss_mask，工程骨架与前几册的 Python 例子一致：src/ 放两个文件，main.py 是入口，负责种子、调度和打印；sft.py 放全部数学，包括造样本、造打分表、手写稳定交叉熵、构造掩码和两种损失。清单 lm07-sft.json 声明模式为 numerical，把六个黄金值和容差写在证据声明里。第 3 章的例子从本地模块导入开始，入口必须 import 另一个 .py，这不是形式主义——它让「造数据」与「算损失」的接缝可见，读者读模块就知道这个例子提供什么能力。

第 2 帧的两个源文件分工很干净：sft.py 里 build_sample 拼出一条 11 个 token 的样本，make_logits 造一张固定的打分表，ce_per_token 算逐位置交叉熵，build_mask 与 masked_loss 完成掩码与两种损失；main.py 固定三种随机源、把中间量打印成等号行和张量行。第 3 帧的清单保存容差与黄金值，程序只负责打印，判定由闸门从 stdout 重算。注意第 1 帧是「本节故事里的起点」，不是说整个仓库此刻真的空着——本章另一个例子由下一单元补齐。

工程惯例为什么要把「算损失」单独放进一个模块

因为你迟早要改它。把 prompt 端的损失也加回来、换成只算最后一个 token、改成带权重的损失，这些改动都只落在 sft.py 的 masked_loss 一个函数里，入口的打印格式一行不动。数学与调度分家，是这一套例子从 Python 桥接册起就守着的习惯。代价是多写一次 from sft import ...，还要保证导入的名字与模块里定义的名字一致；换来的是改一处不会碰坏另一处。

3.2 从预训练到 SFT：目标函数没变，数据变了

先破除一个常见误解：SFT 不是换了一套损失函数。它用的还是第 2 单元的 next-token 交叉熵，也就是第 2 册最大似然那一节的负对数似然。变的只有两件事。第一，数据从「任意网页文本」变成「一问一答的成对样例」，每条样本都有明确的指令部分和回答部分。第二，损失的统计范围从「整条序列所有 token」缩小到「只统计回答部分的 token」。第二件事就是 loss mask。

为什么第二件事这么重要？如果照搬预训练的口径，把 prompt 部分的 token 也算进损失，模型就会把力气花在学习「如何复述指令」上。可指令是用户给的，模型不需要学会生成它；模型需要学会的只是「给定这个指令，该输出什么」。更糟的是，prompt 往往模板化、重复度高、容易预测，它的交叉熵很低；把大量低损失的 prompt 位置混进来平均，会把真正要优化的回答位置的梯度稀释掉。掩码的作用就是把这个稀释效应掐断：让优化器只在回答位置上使劲。

大白话用一句话说清 SFT 与预训练的关系

预训练教会模型「像语言一样说话」，SFT 教会它「在听到指令时说该说的话」。教材和网页文本里没有稳定的问答结构，所以预训练目标必须对全序列负责；问答样例里指令是人给的、回答才是模型要学的，所以 SFT 目标只对回答负责。同一个交叉熵公式，换一个统计范围，训练出来的行为就完全不同。

这个「统计范围」在框架里的实现叫 ignore_index：把不想统计的目标位置标签改成一个特殊值（框架通常是负一百），损失函数在计算时把这些位置丢掉。本例没有直接调用一个现成的 SFT 训练器，而是手写掩码、再与框架的 cross_entropy(ignore_index=-100) 对账。这样你能同时看到两件事：掩码在数学上到底做了什么，以及你的手写实现和工业实现是不是同一个数。

3.3 一条样本长什么样：指令与回答的接缝

例子里的样本只有一条，故意做得极小。PROMPT = [1, 4, 7, 2, 9] 是指令部分的五个 token，ANSWER = [3, 6, 8, 5, 10, 11] 是回答部分的六个 token，拼起来是 11 个 token 的序列。词表大小是 12，所以这些编号都合法。真实系统里 prompt 会是一段带角色标记和对话模板的文本，回答会是一串子词 token；但「前面是指令、后面是回答」这个结构完全一样，接缝的位置也完全由数据格式决定。

关键是：交叉熵不是对「第 i 个输入 token」算的，而是对「用第 i 个输入 token 预测第 i+1 个 token」这件事算的。所以 11 个 token 只产生 10 个预测位置。最后一个 token 没有下一个词可供预测，它只作为别人的目标出现，不产生自己的损失。这个错位是理解掩码的第一道门槛：掩码的长度是 10，不是 11。

第 1 帧把样本拆成指令与回答两段，split 记录回答从哪个 token 开始。第 2 帧把输入序列错位一位得到 target：第 0 个预测位置的目标是 token 1，第 3 个预测位置的目标是 token 4，也就是指令段的最后一个 token。第 3 帧给出掩码：前四个预测位置的目标是指令词，记零；从预测 token 5（回答的第一个词）开始，目标都落在回答段，记一。注意第 3 帧把 target 又写了一遍——每个帧都得自包含，打印出来单独看也要能读懂。

为什么 mask[split-1:] = 1 这个下标是 split - 1 而不是 split？因为错位之后，回答的第一个 token（下标 split）是由预测位置 split - 1 负责生成的。我们要保留的正是「生成回答第一个词」这一步。如果把起点写成 split，就会漏掉回答的第一个 token，模型学不到「接到指令后如何开口」。这个一位之差是 SFT 实现里最常见的off-by-one错误之一。

陷阱把掩码打在输入 token 上

你会想当然地写「前五个 token 掩码为零，后六个为一」，得到长度 11 的掩码。可交叉熵要的是长度 10 的目标序列，长度一对不上，框架会直接报形状错误；更隐蔽的情况是你把长度 11 的掩码截断后硬套上去，于是回答的第一个 token 被错杀。判断办法永远是先问「这个位置预测的是谁」，再决定记零还是记一。掩码描述的是监督信号，不是输入本身。

3.4 掩码落在目标上：从张量形状看懂错位

把上一段的结论写成形状表，会更清楚。输入 token 序列形状是 [11]，错位后的目标形状是 [10]，打分表形状是 [10, 12]（十个预测位置、每个位置对 12 个候选词打一分），逐位置损失 loss_vec 形状是 [10]，掩码形状也是 [10]。loss_full 是这 10 个数的算术平均；loss_masked 是掩码为一的那 6 个数的平均；mask_tokens 是掩码为零的位置数，这里是 4；answer_tokens 是掩码为一的位置数，这里是 6。四个加回十个，正好对上。

第 2 帧强调 loss_vec 与 mask 长度相同，这是逐元素相乘的前提。第 3 帧把两种平均并列：全量平均的分子是十项之和、分母是十；掩码平均的分子是六项之和、分母是六。注意分母必须是六而不是十——如果把分子筛过了、分母还用总长度，得到的数会被稀释成原来的十分之六，梯度也跟着缩小。这类「分子筛了分母没筛」的 bug 不会报错，只会让训练慢得莫名其妙。

实验记录自己改一次分母，看看损失怎么变

把 masked_loss 里的分母从 np.sum(keep) 改成 len(loss_vec)，重跑一次。你会看到 loss_masked 从 2.202339 变成大约 1.321403，正好是原值乘以十分之六。闸门会报 numeric_value_mismatch，因为黄金值对应的是正确的分母。这个阴性对照说明：掩码不是「把不要的损失置零再平均」这么简单——置零之后还必须改分母，否则平均值失去了原来的含义。做完把分母改回去。

3.5 手写交叉熵：负对数似然回到眼前

ce_per_token 只有三行，背后却是第 2 册最大似然那一节的完整逻辑。对每个预测位置，模型对词表里的 12 个词给出一组打分；先做 softmax 变成概率分布，再取出正确词的概率，取负对数就是这一位置的负对数似然。把这 10 个位置的负对数似然平均起来，就是全量交叉熵；按掩码筛过再平均，就是 SFT 损失。换句话说，SFT 没有发明新目标，它只是对「哪些样本该进入似然」做了筛选。

这里没有先算 softmax 再取对数，而是直接在 log 域算。原因和逻辑回归那一节一样：如果某个词的概率下溢成零，log(0) 会得到负无穷，损失和梯度一起坏掉。先把每行减去最大值，最大的指数就变成 exp(0)=1，其余都是很小的正数，指数和不会溢出，对数也永远作用在正数上。z - log(sum(exp(z))) 与 log(softmax(z)) 数学上完全相同，数值上却稳得多。

工程惯例为什么打分表要固定，而不是真的训练一个小网络

因为这个单元要钉死的是掩码，不是优化。如果再加一个会更新的网络，损失变化里就混进了「网络学没学会」这个变量，你无法判断 loss_gap 来自掩码还是来自训练状态。固定打分表让每次运行给出完全一样的 10 个逐位置损失，掩码前后差多少一目了然。等这个机制钉死，再去接真实的训练循环，就是水到渠成的事。

3.6 打分表怎么造：让回答比指令更难

sft.py 的 make_logits 用固定种子造一张 [10, 12] 的打分表，然后给正确词加分。指令段那四个预测位置加 1.6 分，回答段那六个位置只加 0.2 分。这是个故意的偏心：指令段的正确词分数高、概率大、交叉熵小；回答段的正确词分数低、概率小、交叉熵大。真跑出来的 loss_vec 前四项在 1.0 到 1.6 之间，后六项在 1.9 到 2.4 之间，正好印证这个设计。

为什么要故意造出这种差异？因为它是理解 loss_gap 的关键。如果两类位置的难度一样，掩码前后的损失差就接近零，你根本看不出掩码在做什么。让回答更难，掩码后的平均损失就明显高于掩码前——这个正向的差直接告诉你：全量口径被简单的 prompt 位置拉低了，那个较低的数并不能代表模型回答问题的能力。真实 SFT 里这个现象普遍存在，因为指令模板往往比自由回答容易预测得多。

np.random.default_rng(seed) 与 np.random.seed 是两条不同的随机流：前者是局部生成器，只影响打分表；后者是全局流，与 random 和 torch 的全局种子一起固定。把打分表绑在局部生成器上，是为了让「换全局种子但打分表不变」成为可能，方便做对照。本例是数值模式，种子写死在源码里；训练模式才需要把种子通过环境变量注入，那是第 5 单元的纪律。

陷阱别把 loss 下降当成「回答变好」

在 SFT 的训练日志里，全量 loss 下降可能有两个来源：模型回答能力提升，或者模型对 prompt 的复述更熟练了。只看全量 loss，你分不清这两种。看掩码后的 loss 才靠谱。这也是为什么真实训练框架里 ignore_index 不是可选项——它不是为了省算力，而是为了让日志里的那个数真的对应「回答能力」。

3.7 掩码与两种损失：四个数字撑起全部证据

build_mask 造出长度 10 的零一向量，masked_loss 用它算出三个量：全量均值、掩码均值、被屏蔽的位置数。三个量加上入口算出的回答位置数、损失差和框架对账差，构成全部数值证据。清单里六个黄金值都用 atol=1e-6：两个位置数是固定整数，允许误差极小；三个损失是固定种子下的确定性浮点，六位小数的打印误差不超过半个末位；框架对账差应当精确为零。

第 54 行开始的 torch_masked_diff 是独立的第二条路径：它把掩码为零的目标位置改成负一百，交给框架自带的交叉熵去算，再与手写的 masked 比差。两条路径不共享中间量——手写版用布尔索引求和，框架版用 ignore_index 跳过——所以这个差为零才真正说明两边都对。若哪天你把手写版的分母写错，框架版不会跟着错，torch_diff 会立刻跳起来。

实验记录把 ignore_index 改成 None 会怎样

把框架调用里的 ignore_index=-100 去掉，标签里的负一百就会被当成合法类别，而打分表只有 12 列，框架大概率报下标越界。即使不报错，它算出来的也是另一个问题的损失。这个反例说明 ignore_index 不是一个优化开关，而是「这些位置不该被统计」这件事在框架里的唯一表达。做完把参数改回去，黄金值对应的是带忽略位的版本。

3.9 数怎么读：把六位小数还原成含义

mask_tokens=4.000000 与 answer_tokens=6.000000 加起来是 10，正好等于预测位置数；再加上最后一个只当目标、不产生预测的输入 token，就是序列长度 11。三者互相咬合，任何一个对不上都说明错位或掩码起点写错了。

loss_full=1.845395 是十项逐位置损失的平均，把前四个小值和后六个大值混在一起。你可以手算核对：前四项之和约 5.239917，后六项之和约 13.214034，总和约 18.453951，除以十得 1.845395，与打印一致。loss_masked=2.202339 只除后六项，13.214034 除以六正好是 2.202339。两个平均的分母不同，这正是掩码的实质。

loss_gap=0.356944 是 loss_masked - loss_full，正值说明全量口径被容易的 prompt 位置拉低了约零点三六。换算成概率的感受：loss_full 对应正确词的平均概率约百分之十六，loss_masked 对应约百分之十一。同一个模型，换个统计口径，看起来差了这么多——这就是为什么跨阶段比较 loss 没有意义。torch_diff=0.000000 则说明手写掩码与框架忽略位给出同一个数，双精度下逐位一致。

第 3 帧把 full 又写了一遍，并在两者之间画出差值箭头。读图时要意识到，这里的差不是「掩码让损失变大了」——掩码没有改动任何一项逐位置损失，它只是换了平均的范围。把这句话说清楚，才算真的理解了 loss mask。

工程惯例为什么黄金值里要同时放 loss_full 与 loss_masked

一个程序可以硬编码 loss_gap=0.356944 骗过单项检查，但要同时让全量平均、掩码平均、两个位置数与框架的差都对上，就很难不真算。清单同时声明六个值，等于把同一个实验的六个独立侧面钉在一起。这与之前对拍实验里同时核对两条路径的做法一脉相承：证据越多，假实现越难蒙混。

3.10 数据质量为什么比数量重要

真实 SFT 的经验规律是：几千条高质量问答常常胜过几万条敷衍标注。原因可以从本例的掩码视角直接看出来。掩码把注意力全部集中在回答上，于是回答的每一个 token 都直接决定梯度。如果回答里有错误答案、含糊其辞、或者把不该说的东西说了出来，模型就会认认真真地把这些坏模式学进去。掩码越彻底，坏数据的破坏力反而越强——它没有别的 token 来稀释这些错误。

第一条理由是标注一致性。同一个问题，两个标注员给出风格迥异的回答，模型接收到的信号就互相打架；它学到的是「这类问题怎么回答都行」，于是输出变得发散。第二条理由是任务覆盖。一千条全是天气查询的数据，再干净也教不会模型写代码；覆盖率比绝对条数更决定下游表现。第三条理由是回答的完整性。SFT 学的是「从第一个回答 token 开始一步步生成」，一个半截子回答会教模型在半途停下，而且因为掩码保留了回答的每个位置，这个坏习惯会被完整地学走。

大白话用大白话说数据质量

把 SFT 想成师傅带徒弟。徒弟只看师傅怎么回答，不看师傅怎么听问题——因为掩码把「听」那部分从考核里去掉了。那么师傅回答得是否准确、是否完整、风格是否统一，就全变成了徒弟要模仿的范本。请一百个师傅、每人教一句互相矛盾的话，不如请十个师傅、每人教一种干净的做法。

3.11 过拟合与灾难性遗忘的引子

本例只有一条样本，如果真的拿它反复训练，模型会迅速把这条问答背下来：11 个 token 上的交叉熵可以降到接近零，但换一个问法就完全不会。这就是过拟合在 SFT 里的形态——训练损失很好看，泛化能力为零。玩具规模把这件事放大到一眼可见，真实数据上它只是没这么显眼：几万条样本里反复出现的模板会被背得滚瓜烂熟，少见的问题仍然答不好。

另一个风险是灾难性遗忘。基座模型在预训练阶段见过海量文本，参数里沉淀了广泛的语言与知识；SFT 用少量问答数据做微调，如果学习率过大或步数过多，参数会被拉向这批数据的分布，把原来会的东西冲掉。你会看到一个诡异的现象：SFT 之后模型回答格式变得规整了，但一些常识问题反而答错。这不是幻觉，是参数被小数据重写的结果。工程上的对策包括更小的学习率、更少的轮次、以及在微调数据里掺回一部分预训练风格的样本。

第 2 帧里两个损失一起下降，但解释不同：掩码 loss 下降是回答能力真的提升，全量 loss 下降有一部分来自模型更熟练地复述模板。第 3 帧把过拟合与遗忘分开画，因为它们的成因不同——前者是样本量不足，后者是参数被小数据重写。两帧都把不变量重新写了一遍，符合帧自包含的纪律。

陷阱用 SFT 损失当唯一的早停信号

掩码损失在过拟合时仍然会下降，因为它衡量的正是「对这批回答的拟合程度」。拿它做早停，等于让模型朝着背答案的方向一路走。可靠的做法是留一部分不参与训练的验证问答，在验证集上算同样的掩码损失；训练集继续下降而验证集开始抬头，才是该停的时刻。这一册最后一单元讲评测时会把这套检查展开。

3.12 与预训练 loss 曲线对比：两个口径别混着看

第 5 单元的预训练循环打印的是全量 next-token loss，十几个点一路下降。把 SFT 的 loss_full 和那类曲线摆在一起，会发现它们数值尺度可能完全不同：预训练数据的 token 分布更散、更难预测，损失往往更高；SFT 数据格式固定，损失往往更低。于是有人得出「SFT 之后模型变强了」的结论，其实他只是在比较两堆不同数据上的平均负对数似然，就像拿语文考试平均分和数学考试平均分比谁更聪明。

正确的比较方式有三种。第一，在同一批数据上比较，比如都在 SFT 验证集上算掩码损失，观察它随训练步数怎么变。第二，比较同一口径下的相对变化，而不是跨数据集的绝对值。第三，把 loss 换成与任务直接相关的指标，比如回答是否包含正确事实、是否遵循了格式要求。第三类指标在下一章的解码与评测部分会成为主角。

本例把 loss_full 与 loss_masked 同时打印，正是为了让你看到「同一个模型、同一批数据、两个口径」能差出零点三六。既然连同一批数据上的两个口径都差这么多，跨数据集、跨阶段的比较就更没有意义。记住这个数量级的警告，比记住任何一条调参经验都值钱。

实验记录把 prompt 也加回损失，看梯度会怎样变

写一个 masked_loss_all，把 mask 全部改成一，用它算出来的平均损失反传（或手算梯度方向），再与只算回答的版本比较。你会发现梯度里混进了一大堆「预测模板词」的信号，回答词的梯度占比被压低。把这件事和 loss_gap 的零点三六联系起来看，就能明白为什么掩码不是省算力的技巧，而是决定模型学什么的关键开关。做完把改动撤掉，黄金值对应原版。

3.13 黄金值从哪里来：手算与真跑互相验证

清单里六个黄金值不是从第一次运行的输出里抄的。mask_tokens=4 与 answer_tokens=6 来自序列结构：split=5，错位后指令侧贡献 5-1=4 个预测位置，回答侧贡献 11-5=6 个。loss_full 与 loss_masked 可以用打印出来的十项逐位置损失手算核对，前面 3.9 节已经做过。loss_gap 是两者相减，torch_diff 来自框架实现与手写实现的数学等价性。六个数各有独立来源，没有一个是「程序打了什么就写什么」。

容差 atol=1e-6 的依据是打印精度。程序用六位小数输出，四舍五入带来的误差不超过五乘十的负七次方；高斯双精度运算本身的误差在十的负十五次方量级。所以一乘十的负六次方的容差既容得下打印误差，又远小于任何真实错误会造成的偏差。若把黄金值改成程序输出后硬凑的数，闸门照样会绿，但你会失去发现错误的机会——这个纪律在之前的最大似然与对偶单元里已经反复强调过。

工程惯例复现这个实验要记哪些条件

词表大小 12、指令五个 token、回答六个 token、打分表由局部生成器在种子 2026 下产生、指令位置加 1.6 分、回答位置加 0.2 分、掩码起点是 split-1、分母是掩码为一的位置数、打印六位小数、容差一乘十的负六次方。清单保存容差与程序该打印什么，源码保存怎么算，正文保存这些数为什么是这个值。三者合起来才是一份别人能照着重做的记录。

3.15 从 SFT 到偏好优化：下一步要解决什么

SFT 有一个天花板。它只告诉模型「正确答案长什么样」，却从不明说「错误答案错在哪」。在回答空间很大的任务里，正确的写法可能有很多，错误的写法更有很多；只用正例做最大似然，模型会把所有见过的正确回答的概率抬高，但不一定学会区分微妙的好坏。比如两个回答都事实正确，一个啰嗦、一个简洁，SFT 的损失对它们一视同仁，只要都在训练集里就被同样鼓励。

偏好优化换了一种监督信号：不再只给一个标准答案，而是给一对回答，标注哪个更好。有了比较，模型就能学到「沿着这个方向走更好，沿着那个方向走更差」。下一单元的手写例子会把这种比较变成 pairwise logistic loss，再推到不需要显式奖励模型的 DPO。你会看到那边的损失形状与今天的交叉熵一脉相承——都是负对数似然，只是把「单个正确词」换成了「一对里的正确回答」。

本单元最值得带走的一句话是：掩码决定了模型为谁负责。把它打在全部 token 上，你训出的是续写器；只打在回答上，你训出的是助手；将来把比较也纳入负责范围，你才有机会训出懂得取舍的助手。公式一直是那个交叉熵，变的是你让谁进入统计口径。

3.16 模板与角色标记：真实系统里的接缝在哪里

玩具例子里接缝是一个整数 split，真实系统里它来自对话模板。一条多轮对话会被拼成「系统提示、用户第一轮、助手第一轮、用户第二轮、助手第二轮」这样的一长串，中间夹着角色标记和分隔 token。掩码要把所有助手说的话都记为一，把系统提示、用户的话和分隔符都记为零。也就是说，真实掩码往往不是「从某个位置开始后面全一」，而是一串零一交替的区间。本例只有一轮，所以掩码看起来是一段连续的六；多轮场景下它是好几段。

模板本身也有讲究。如果训练时用了一种模板，推理时换了另一种，模型会看到没见过的格式，回答质量断崖式下降。这不是模型忘了知识，而是掩码让模型从未学习过「在新模板下开口」这件事——模板 token 全被屏蔽了，模型只学过在旧模板的接缝之后生成回答。所以模板要和掩码一起看成数据格式的一部分：你屏蔽掉什么，就等于宣布模型不必学习什么。一旦推理时的输入落在被屏蔽的分布里，问题就会暴露。

工程惯例多轮对话怎么扩展本例的掩码

把 build_mask 改成接受一个区间列表，每个区间标出一段助手回答的起止；对每个预测位置，检查它的目标下标落在哪个区间里。这样第二轮用户提问的 token 仍然被屏蔽，而第二轮的助手回答重新记一。注意接缝仍然要错位一位：助手段第一个 token 由它前面那个位置负责预测。这个扩展不改 masked_loss 一行代码，因为掩码已经把「谁该统计」全部编码好了。

小结这一节的要点
  • SFT 沿用 next-token 交叉熵，变的只有数据格式与损失的统计范围；
  • 十一 token 产生十个预测位置，掩码打在错位后的目标上，起点是 split - 1；
  • 全量损失对十项取平均，掩码损失只对六项取平均，分子分母必须一起筛；
  • 真跑给出 loss_full=1.845395、loss_masked=2.202339、loss_gap=0.356944 与 torch_diff=0.000000；
  • 掩码后的损失更高，说明全量口径被容易的 prompt 拉低，两个口径不能跨阶段直接比较；
  • 对齐数据质量比数量重要，过拟合与灾难性遗忘分别是轮次过多与学习率过大的典型后果。

  5. loss_gap 为正说明什么？为什么说它不能用来跨阶段比较模型能力？
  6. torch_diff=0.000000 是怎么算出来的？为什么它算一条独立证据？
  7. 从掩码的视角解释：为什么 SFT 里坏回答比坏 prompt 更具破坏力？
注自测题答案
  1. 交叉熵预测的是「下一个 token」，第 i 个位置用 token i 预测 token i+1。11 个 token 里下标 0 到 9 都有下一个词，下标 10 是最后一个，只能作为别人的目标，不产生自己的预测，所以是 10 个位置。
  2. 损失是对「预测出的目标词」算的，掩码要决定哪些目标词参与统计。打在输入上会得到长度 11 的掩码，与打分表的 10 行对不上；即便硬截断，也会把回答的第一个 token 错杀。
  3. 错位后回答的第一个 token（下标 split）由预测位置 split - 1 负责生成，保留这个位置才能学到「接完指令怎么开口」。写成 split 会漏掉回答第一个词，本例会丢掉交叉熵最大、最该学的那一项。
  4. 十项之和约 18.453951，loss_full 的分母是 10，得 1.845395；后六项之和约 13.214034，loss_masked 的分母是 6，得 2.202339。分子筛过分母也必须筛。
  5. 为正说明回答位置的平均交叉熵高于全量口径，全量口径被容易的 prompt 位置拉低了。两个口径的数据分布与统计范围都不同，跨阶段比较等于拿两把不同的尺子量东西。
  6. 它把掩码为零的目标改成忽略标记，交给框架的交叉熵实现算一遍，再与手写掩码平均取绝对差。两条路径不共享中间量，差为零才说明两边都算对了。
  7. 掩码把 prompt 从统计范围里去掉，回答的每个位置都直接贡献梯度。坏回答的错误模式不会被稀释，反而因为掩码的聚焦被学得更彻底；坏 prompt 根本不进入损失，影响很小。
