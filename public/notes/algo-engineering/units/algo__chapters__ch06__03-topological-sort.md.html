6.1 先看工程长什么样

上一课（最短路）解决的问题是「从 A 走到 B，代价最小」；这一课的问题反过来：「有一堆任务，任务之间有先后约束，给它们排一个能执行的顺序」。排序的依据不是距离，是依赖。这个「顺序」叫拓扑序，算法本身只有二十行，但它有一半的分数在建模（怎么把题目变成边）、一半在正确性（凭什么说排不出来就是有环）。所以照本书的规矩，先看这一节的工程长什么样。

大白话这一节想让你先建立一个画面

把每个任务想成一块带编号的积木，依赖关系想成积木上的箭头贴纸：u -> v 表示「贴了箭头的 u 必须摆在 v 前面」。

  • 排拓扑序，就是把这些积木排成一行，让每一张贴纸的箭头都从左指向右；
  • 入度，是一块积木身上「被几支箭头指着」——被指着的积木还不能摆，一支都不被指的随手就能摆；
  • 摆好一块，就从它身上把射出去的箭头撕掉：被它指着的那几块，「被指次数」减一，减到零的当场解锁。

整个 Kahn 算法就是「挑能摆的 → 摆上去 → 撕箭头」这三步循环。剩下的所有内容（判环、字典序、DP）都是在这个画面上加东西。

第 1 帧是动笔前的样子：图论基础这一章里，存图与遍历、最短路两课的工程已经在了。第 2 帧新增 topo_basic/——原理层 C 手写的 Kahn，配暴力对拍与性能实验，这是本节的主体。第 3 帧新增 topo_lexicographic/——整套用 C++/STL 写的应用层程序（std::priority_queue 版字典序拓扑），它自己也是一份对拍工程。第 4 帧新增 dag_longest_path/——拓扑序 DP 求最长路，带路径还原，外加一份「链状数据上递归爆栈」的真实会话。六个清单（*.json）把六份真实 stdout 接进对账流水线，两份 session-*.txt 会话文件在 6.7 逐字注入。

这一课会把前两课的家底全部用上：邻接表还是存图单元的 CSR（6.3），「每次取最优」的容器还是堆单元的 priority_queue（6.5），「按顺序保证转移来源是终值」的思路和最短路单元的 Dijkstra 是同一个哲学——Dijkstra 是「每次确定一个最近点」，Kahn 是「每次确定一个无依赖点」。区别只在比较的键：一个比距离，一个比入度。学完这一课你再回头看 Dijkstra，会发现它的「已确定集合不断扩张」写法本质就是一张拓扑序——按确定顺序处理，后面用不到回头。

工程惯例工程惯例：算法单元的「正解 + 暴力 + 对拍」三件套

每个例子都是三个编译单元：src/<例名>.c（正解）、src/<例名>_brute.c（暴力，写得慢而明显正确）、src/main.c（生成随机数据、逐组比对、打印 OK 200）。这是惯例，不是标准；代价是每个例子多写一份暴力，收益是结论被机器验证而不是被感觉验证。一条命令编完（本机没有 make/cmake，参数与机器事实一致）：gcc -std=c17 -Wall -Wextra -Wpedantic -O2 -g -Iinclude src/main.c src/topo_basic.c src/topo_basic_brute.c -o app。

6.2 依赖关系建模：把「先修课」翻译成有向边

拓扑排序的输入是一张有向图，输出是一个序列。它能不能用，取决于你把题目翻译对没有。约定只有一条，但必须固定下来：

语法规则语法规则：边的方向就是「先做谁」
  1. u -> v 表示「u 排在 v 之前」：课程表里「离散数学是数据结构的先修」就建边 离散数学 -> 数据结构。整张图里所有推理（入度、解锁、DP 转移）都建立在这一个方向约定上，建反了程序照跑、答案全错。
  2. 拓扑序是「让每条边都从左指向右」的排列：形式化说，order 是 0..n-1 的一个排列，对每条边 u -> v 都有 pos[u] < pos[v]。合法序通常不止一个——这一点是 6.5 讲字典序的原因。
  3. 合法序存在，当且仅当图里没有环。有环时不是「这道题难」，是「无解」——循环依赖谁也满足不了。

「必须按顺序」这类约束在题面里长什么样？下面这些全部翻成加边：先修课（先修 -> 后修）、编译依赖（被依赖 -> 依赖者）、任务调度（前置工序 -> 后续工序）、判定顺序（小的先算，大的才引用得到）、状态转移（DAG DP：状态 -> 后继状态）。反向的写法（v -> u）也能做，但「入度」就要换成「出度」——约定一条，全篇一致。

建模的四个常见动作，值得在动手前先想清楚：

  1. 判可行，还是求方案？「课程表排得出来吗」是判定问题，Kahn 的返回值直接回答；「把课表打出来」是构造问题，要的就是那个 order。两者的代码只差一行 printf，但你要清楚自己在答哪一问。
  2. 无解 = 有环，这个对应本身就值分。数据校验类的题（「这份依赖表自相矛盾吗」）其实是在问「图里有没有环」——不需要输出任何序，判环就是全部工作。
  3. **多个合法序怎么办？**题目多半会指定：字典序最小（6.5）、或者任意一个都算对（special judge）。看清楚再动手，否则答案对了判题机也说错。
  4. 多入口的图，想加虚拟源点再建模：所有入度 0 的点接到一个超级源 S，问题就从「多源」变成「单源」，DP 与最短路的写法都简化一档——这个技巧在 6.6 的多源最长路里其实已经隐含（每个入口都算一条路径的起点）。

还有一条更隐蔽的用途：给「谁先算谁后算」排序。任何「算 i 之前必须先算完 j」的流程——DP 的状态依赖、记忆化的调用顺序、甚至编译单元的链接顺序——都是一张依赖图，拓扑序就是合法的计算顺序。第 8 单元讲 DP 时你还会反复用到这个视角。

再往深处走一步：有些题目图是看不见的，要你自己把「大小关系」造成图。经典例子是「确定比赛名次」：给一批两两比赛的结果，a 赢 b 就建边 a -> b，拓扑序就是一个与所有结果一致的排名——拓扑序还给了这个问题更深的注脚：它就是偏序关系的「线性化」。比较器的排序处理的是全序（任意两个可比），而依赖关系常常只是偏序（有的对儿没比过、先后随意）——拓扑排序就是把偏序补成全序的一种方式。字符串字典序推导、家谱辈分、术语定义的引用闭合，全是同一个形状。看到「由若干两两关系推出一个全局顺序」，先想想这张图建不建得出来。

陷阱你怎么会被坑到：把边建成 v -> u，图还是连通的

表现：程序不崩、判环也正常、输出的序「看起来是个序」。误判：拿肉眼扫一遍输出，觉得「反正每门课都在」，直接交。真相：方向反了之后，你算的是「反图的拓扑序」——它和你要的序恰好互为倒序，图复杂一点就连「倒序」都不对。判法是拿一条真实约束检查：题面说「离散数学是数据结构的先修」，输出的序里离散必须排在数据结构前面；对拍时 brute_check_order 逐边检查的就是这一条（6.4 的代码）。修法：写代码前在注释里写死「u -> v 表示 u 先于 v」，读入时只做一次方向转换。

方向问题旁边还住着它的老邻居——下标换算。题目给的点编号几乎都是 1..n，C/C++ 数组是 0..n-1：要么读入时统一减一（内部全 0 基），要么数组开 n+1（内部全 1 基，下标 0 空着）。两种都对，一个程序里只能选一种——混用是这个家族的经典静默错误（第 5 单元实测过：症状是「有时对有时错，加一行打印就变好」，因为越界写到了别人的内存）。本单元三个工程全部按 0 基写死（边表、indeg、start、dp 数组开到 n 就够），你若选 1 基，把 n+1 的开销算进内存账再开。

6.3 Kahn：入度表 + 队列

现在正式写算法。先给一句直觉（开头的 plain 块已经画了画面）：入度表记录「谁还被几支箭头指着」，队列收集「一支箭头都不剩的点」。弹出队头 = 把这块积木摆进序列，同时撕掉它射出去的所有箭头（把邻点入度减一）；减到 0 的点当场入队。

原理层用 C 手写，邻接表用 CSR 分桶（上一课存图单元的同款结构：start 是行首、adj 是出边终点）：

第 14 行就是「加边时维护入度」的落点：每读一条边 u -> v，indeg[v] 加一。重边天然正确——同一对点连两条边，入度就加二，弹出时也会减二。自环 v -> v 也天然正确——它给 indeg[v] 自己加一，这个点永远凑不齐入度 0，最后会被「排不完」抓住，判环结论照旧成立。入度表是整个算法唯一的事实来源：它错了，后面全错。

邻接表为什么用 CSR 而不是 vector<vector<int>>（那是 6.5 应用层的写法）？原理层要的是「内存里到底放了什么」：两遍扫描建表——第一遍数每个点的出边条数，第二遍按行首位置把终点填进 adj——这就是把边表做了一次计数排序，O(n+m)、零动态扩容、整块连续。副作用是建好的结构是只读的，所以 topo_sort 每次把 indeg 拷一份副本再跑（第 44 行前的 memcpy），同一个图可以反复排而不被减坏。这两件事——「结构只读、状态带副本」——是数据结构与算法分离的基本功，第 5 单元的并查集也是这么写的。

队列值得单独看一眼。它是个数组队列：弹出用 qh++、入队用 qt++，弹出去的元素留在原地不搬动——反正 qh 已经越过它们了。这比 std::deque 或链表都快，而且队列容量正好是 n：一个点最多入队一次，因为入度只在邻点弹出时减少，--indeg[v] == 0 对一个点只可能成立一次（再减只会变负数，而负数进不了 == 0 的分支）。第 8 单元的 DAG DP 还会复用这个数组队列——order 排完之后本身就是拓扑序，队列和结果共用同一块内存，一分钱不花。

顺手记一个反向的变体：把「入度」换成「出度」、把队列初始化成「没有出边的点」，同样的三步循环得到的序列倒过来就是拓扑序（先排「不被任何人依赖」的，再倒过来）。这个方向正好是 6.6 里记忆化 DFS 的口径（从 v 出发往后算），两个口径谁顺手用谁，别混着记。

复杂度的拆账也一句话说清：每个点至多入队一次（上一段的证明），每条边在它起点被弹出时恰好被扫一次——两边加起来 O(n+m)，这就是「线性」的全部内容。拓扑排序还有另一个流派：DFS 的后序遍历倒过来（一个点只有在所有后继都弹完栈后才进后序，倒序后自然排在前面）。它写起来更短，但带着 DFS 的全部家当——递归深度等于最长链，本机两万层就开始危险（第 5 单元实测过 4.4 万帧被杀），而且判环要靠染色。竞赛里首选 Kahn：迭代、自带判环、队列顺手就是答案。DFS 版留个印象就好，第 7 章讲 Tarjan 时你会再见到它的后序花名册。

陷阱你怎么会被坑到：只建边，忘了在加边处维护入度

你会看到什么：编译干净通过，一跑，队列瞬间装下了所有点（或者大部分点），输出的「拓扑序」顺序乱七八糟，判环永远说无环。你怎么会误判：测试数据是个明显的链，肉眼一看「顺序差不多嘛」，就放过去了。真相：indeg 全是 0，算法认为所有点同时可用，「解锁机制」整个失灵——它退化为「按队列顺序随便排」，环也永远抓不到。修法：把入度的维护收进一个函数（本单元是 topo_build / add_edge），其他任何代码不许碰 indeg；topo_lex.h 的注释里写的就是这句话。另外两个常被一起问到的：重边要各算各的入度（本单元天然正确）；自环会让点永远进不了队——这正是想要的行为，它就是环。

陷阱你怎么会被坑到：弹出之后，忘了给邻点减一

你会看到什么：判环开始谎报——明明无环的图，返回值却说「有环」（弹出的个数少于 n）；或者序列中途断掉。你怎么会误判：第一反应是怀疑图建错了，回去检查边表半天。真相：减一这个动作就是「解锁」，漏了它，下游的点入度永远不归零，永远进不了队——你亲手制造了假环。这个 bug 与上一条正好相反：一个是「人人都能入队」，一个是「没人能入队」。修法：弹出与减一写在同一个循环体里，代码审查时把 --indeg[v] == 0 当成弹出动作的一部分看，不要当成可选的优化。

6.4 为什么有环就排不完：把不变式说穿

算法写完了，「为什么对」得说清楚。先给直觉，再给形式化论证。

大白话「弹出即安全」在说什么

队列不是随便收人的：一个点想进队，必须先把身上的箭头被撕干净——也就是所有排在它前面的点都已经进了输出序列。所以「从队列弹出一个点」这个动作，永远是把一个「前面的人都到齐了」的点接进队伍，序当然还是合法的。

反过来，如果队列空了还有点没排进去，说明这批点里每一个身上都还有没撕完的箭头——每一个都在等别人，而别人也在等别人。互相等的这一圈，就是环。

形式化的论证靠一条不变式撑着：

不变式：任意时刻，队列里的每个点都满足「它的所有前驱都已经在输出序列里」，而输出序列本身就是已弹出点的一个合法拓扑序。 初始成立：入队的就是入度为 0 的点，它们没有任何前驱。归纳步成立：弹出 u 时它入度为 0，即所有指向 u 的边都来自已弹出的点，把 u 接在序列尾部，每条从已弹出点指向 u 的边依然从左指向右，序列仍合法；弹出后给邻点减一，一个点的入度只在它的前驱被弹出时减少，所以它减到 0 的那一刻，恰好是它最后一个前驱进序列的时刻——它入队时不变式依旧成立。

终止论证（排不完必有环）：假设队列空了，还有点没弹出，且剩下的子图无环。无环图必有入度 0 的点——两个等价的看法：一是沿入边往回走，DAG 不允许回头，有限步内必撞到一个没人指它的点；二是反证，若每个点都有入边，从任一点沿入边回走，n 步之内必重复，重复即环。这个「剩余子图里入度 0」的点，它在原图中的入边只能来自已弹出的点（剩余点里没有它的入边）——可入边来自已弹出点就意味着入度早被减光了，它应当已经入队，与「队列空了」矛盾。所以剩下的点里存在环。反过来，只要无环，每轮至少能弹出一个点，n 轮之内必弹完。这就是「拓扑序存在 ⇔ 无环」的算法化证明，而 Kahn 同时给了你「序」（弹完时）和「坏账名单」（弹不完时剩下的点）。

终止论证里那个「无环必有入度 0 的点」还有第三种看法，它解释了整个算法为什么总能推进：从原 DAG 里删掉一个入度 0 的点，剩下的还是 DAG（子图当然无环），于是还能再删一个——归纳下去直到删空。Kahn 做的就是这个「不断删最小元」的过程，队列只是「当前所有最小元」的花名册。

坏账名单还有一层实用性质值得单独记住：剩下的点 = 环上的点 ∪ 环的下游。6.2 的造环演示里卡住的 5 门课（数据结构、离散数学、算法、操作系统、编译原理）里，真正在环上的只有两门，其余三门全是「被环连累」的下游。所以拿到「弹出 < n」的结果，别把名单全当成环来修——名单里混着无辜者；想精确找环上的点，用三色 DFS 顺着回边抓，或把名单导出成子图再判一遍。

说穿了就一句话：队列里永远只有「前驱全齐」的点，所以弹出一个安全一个；弹不完，剩下的必然互相指着——那就是环。

6.5 字典序最小：把队列换成小根堆

普通 Kahn 给的序取决于「谁先入队」，合法序又不止一个，于是有一类题多问一句：输出字典序最小的那个。先把「字典序最小」翻译成人话：把所有合法拓扑序当成字符串排队，最前面那个。做法是把 Kahn 的先进先出队列换成小根堆——每一步不按「先来后到」弹，按「当前可用的点里编号最小」弹。

大白话先建立一个画面

队列像食堂打饭：先到先得，与编号无关。小根堆像叫号系统：每一步都叫当前候场的人里号码最小的。「候场」= 入度已经减到 0（所有前驱都排完了）。同一个图，两种取法给出的合法序可能不同——因为「先入队」不等于「编号小」。

先看一张故意造的反例图，再上理论。4 个点、两条边：2 -> 0、3 -> 1。初始可用集是 {2, 3}：

应用层的完整实现（M14 的 C++ 程序本体）：add_edge 是入度唯一的维护入口，topo_lex 把队列换成 priority_queue。C++ 的 priority_queue 默认是大根堆，第三个模板参数给 std::greater<int> 才是小根堆——这是本单元第一个语言坑：

为什么「每步取最小可用点」恰好是字典序最小？交换论证，两步。 设最优序 O 在某一步没有取最小可用点：当时可用集里有 u < v，O 却先排了 v（u 排在后面）。构造新序 O'：把 u 从后面临时挪到 v 的位置（其余不动）。O' 合法吗？u 可用，说明 u 的全部前驱都在已排好的前缀里，把 u 提前不违反它的约束；u 提前也不会违反别人的约束——「u 在 x 前」这类约束只会更满足。O' 与 O 第一个不同处就是 u 与 v 互换，而 u < v，所以 O' 的字典序严格更小，与 O 是最优矛盾。所以每一步必须取最小可用点，而小根堆干的正是这件事：取最小 O(log n)，插入 O(log n)，总复杂度 O((n+m) log n)。

注意这个论证依赖「可用」的判定是当前入度——所以入度表必须跟着每一步弹出实时减。这也解释了为什么「先随便排一个拓扑序，再 sort」是错的：sort 之后的序列很可能连合法都算不上（四点例里把 FIFO 的 2 3 0 1 排序成 0 1 2 3，边 2 -> 0 立刻从右指左）。

复杂度的总账也摊开算一遍，你就知道堆省了什么：n 步弹出、每条边只触发一次「减一 + 可能入队」，所以基础工作量 O(n+m)；堆把「找最小」从 O(n) 的线性扫描降到 O(log n)，但堆里同一时刻最多存多少点？每个点只入队一次，所以堆的总插入次数就是可用点的总数——摊下来每个点进出堆各一次，O((n+m) log n)。而「每轮收集全部可用点再 sort」呢，每轮 O(可用点数 × log) 还要重建集合，n 轮加起来轻松过 O(nm)。这就是 6.7 表里 0.8 ms 对 540 ms 那五百倍差距的来源。

一个顺带的判定技巧：什么时候拓扑序唯一？当且仅当每一步的可用集大小恰好为 1——等价地说，图里存在一条哈密顿路径（按拓扑序相邻的两个点都有边相连）。可用集一旦出现两个，就有两种先后都合法，序就不唯一了。题目要求「字典序最小」其实是在暗示你：这张图的拓扑序大概率不唯一，直接贪心取最小就是出题人要的方案。

堆的细节再抠两个，都是真会踩的。其一，堆里的点不会重复：一个点入堆的唯一条件是入度减到 0，这个事件对一个点只发生一次，所以堆的大小上界就是 n，std::priority_queue 默认构造够用。其二，判环的返回值和普通版一样是「排完没排完」——堆排空了但 order.size() < n，剩下的依旧是被环堵住的点，坏账名单的性质原样保留。另外手写堆版（原理层）在塞 pair 进堆时注意键的次序：把「比较键」放在 first，点号放 second，greater<pair<int,int>> 直接就是「键小者优先、同键点号小者优先」，很多字典序题的同分规则恰好就是这个。

陷阱你怎么会被坑到：字典序用 sort，不用堆

两种死法，症状完全不同。死法一：每轮把可用点收集起来 sort 再取头——结果是对的，复杂度从 O((n+m) log n) 掉到 O(nm) 级别，n=1e4 时本机实测就要五百多毫秒（6.7 的表），n=1e5 直接超时。你怎么会误判：样例都过、答案都对，以为是常数问题。真相：堆的存在意义就是「动态集合里反复取最值」，每轮重新收集再排序等于把堆的工作重复做了 n 遍。死法二：先跑普通拓扑，再对结果 sort——答案直接错，而且常常能过样例：sort 完的序列大概率连合法拓扑序都不是（上面四点例就是现成反例）。修法：见到「字典序最小 + 依赖约束」，直接写小根堆版，别在输出上动刀。

原理层的对应写法是手写小根堆（第 6 单元二叉堆的 push/pop 直接换进来即可，接口与这里的 heap.push/heap.top 一一对应）；应用层直接用 priority_queue，代价是多一层堆的封装，换来的是不用手写下沉上浮。什么时候直接用 STL：点数与边数在 1e6 以下、比较器是内置类型的小于号——都满足时，priority_queue 的常数完全可以接受。

6.6 DAG 上的 DP：最长路与最短路

拓扑序的第二大用途：在 DAG 上做 DP。为什么非要 DAG？一句话：环上「最长路」根本不存在——每绕一圈权重只增不减，答案发散到无穷。把图限制成 DAG，「从入口到 v 的最长路」立刻有了扎实的递推结构。顺便说一句：一般图的最长路（简单路径版）是 NP-hard 的，DAG 恰好是让它变简单的那个前提，所以「这题是不是 DAG」永远值得先判一次。

大白话拓扑序 DP 在保护什么

DP 最怕「用半成品算半成品」。拓扑序就是一张保证书：按这个顺序处理，轮到任何一个点时，它能引用的所有前驱都已经是成品（终值）。

环为什么毁掉这张保证书？环上没有「第一个」：A 等 B 的终值，B 等 A 的终值，谁也等不来——于是硬算的人只能拿半成品凑半成品，错值顺着出边一路传染下去（下面的陷阱块有真实的假数组）。所以 DAG DP 的第一道工序永远是拓扑排序，返回值不对就停手。

本例子的故事接着课程表讲：每门课有学分（点权），问按先修顺序修课，最多能攒多少学分、以及从高数出发，最省学分修到编译原理的路径。定义 dp[v] = credit[v] + max(dp[u] : u -> v)——「修到 v 为止（含 v）最多学分」；最短路把 max 换成 min、把「多源」换成「单源」。

为什么对（归纳论证）：按拓扑序处理时，轮到 u 的那一刻，所有指向 u 的边的前驱都比 u 先处理过，它们的 dp 值已经不会再变——所以 dp[u] 在此刻就是终值，拿它松弛 u 的出边，dp[v] 收到的候选值没有一个是半成品。归纳基例是最前面的点（入度 0，没有前驱，dp 就是自己的点权）。第 63 行的检查是本节的安全带：返回值小于 n 时绝不给数——你要的答案在环图上根本不存在（下面会给你看硬算的下场）。

最短路的写法只差三处：max 换 min、初值换 INF、多源换单源。INF 的纪律沿用最短路那一单元的：用一个「怎么加都不溢出」的值（这里 DAG_INF = 0x3f3f3f3f），并且别拿 INF 去松弛别人：

同一副骨架还能再变出两个常用变体。边权版：把「学分挂在点上」换成「耗时挂在边上」——dp[v] 的初值改成 0（或单源时改成「src 是 0、其余 INF」），松弛式从 dp[u] + credit[v] 换成 dp[u] + w(u, v)，语义从「点权和」变成「边权和」；工程上的关键路径（CPM）就是它。方案数版：把松弛式的 max/min 换成求和——cnt[v] = Σ cnt[u]（u -> v 有边），初值只有入口是 1，其余 0，按同样的拓扑序递推，取模照加；「从入口走到 v 有多少种走法」这类计数题的复杂度一样是 O(n+m)。三个变体共享同一张拓扑序花名册，变的只有初始化和合并算符——这是「拓扑序 DP」能当模板记而不是每题重想的原因。

和最短路那一课对齐一下知识位置：DAG 上的最短路不需要堆。Dijkstra 靠堆的原因是「下一轮该确定谁」要现场比大小；DAG 不用比——拓扑序就是确定的顺序，一遍线性扫完，而且负权边随便有（没有环就没有负回路，DAG 上的最短路对负权免疫），Bellman-Ford 的活它一个人全包了。所以「图是不是 DAG」在赛场上是一道分岔口：是，走拓扑序 DP 这条 O(n+m) 的窄路；不是，才轮到 Dijkstra、SPFA 那一族。长链长图上那条窄路还有一个隐藏红利：没有递归，没有栈深问题。

陷阱你怎么会被坑到：无视「弹出 < n」，在环图上硬算 DP

你会看到什么：dag_longest 返回 2（弹出了 2 个点），你检查了一下「返回值好像不是 -1，应该没事」，继续往下跑 DP——每个数都有模有样，样例甚至可能蒙对。你怎么会误判：把这 7 个 dp 值拿去交题，前几个测试点或许能过，你以为 DP 本身没问题。真相：环图上「最长路」根本不存在（绕圈学分无限涨），硬算出来的数字是把环边视而不见后的假象——上面输出块第 6 行的 dp = [16, 5, 4, 10, 15, 9, 19] 就是这么来的。硬算长什么样，见下面这段反面教材；它的破绽与传染机制写在代码块后面两段。

这段假 DP 的数组自带一个破绽：dp[0] = 16 的算式用到了 dp[3] = 10，而 dp[3] = 10 的算式里又用到了当时还没抬升的 dp[0] = 6——环上两个点互相抬轿，谁的值都不是「前驱全齐后的终值」，没有一个可信。传染的机制也在这里：环上每个点的 dp 都「被环里的邻居抬过」，假值还会顺着出边流向下游所有无辜的点——最小反例就是「三点环 + 一条尾巴」，尾巴上的 dp 值 100% 是错的。这就是「DAG 前提被破坏」的最小代价：不是一个点错，是一整片错。修法只有一条：Kahn 的返回值小于 n 就停，别算。

陷阱你怎么会被坑到：路径还原，忘了回走是反的

你会看到什么：pre 从终点一路回走，得到一条「看起来是路径」的序列，直接打印——路径是从终点讲到起点的，方向反了。你怎么会误判：序列本身没毛病（每相邻两项真的是边），肉眼查不出，交上去路径类题直接 WA。真相：pre[v] 存的是「谁更新了我」，语义天然是「从 v 指回过去」，回走收集到的数组是终点在前、起点在后。修法：收尾加一个原地反转（6.6 的 dag_path），再用双向验证兜底——本单元对拍里对还原路径逐项查「起点入度为 0、相邻两项是真边、权和等于 dp 值」，方向反了立刻挂在第一条。

把表里的数换算成「能过的 n」：拓扑排序与 DAG DP 的线性写法，1 秒的预算在本机能吃下 n、m 到千万级（瓶颈是读入与内存）；小根堆版吃 1e6 无压力；每轮扫描的暴力 1e4 就到顶。内存账算到字节：n=1e5、m=5e5 时，入度表 4n = 400 KB、CSR 行首 4(n+1) ≈ 400 KB、邻接数组 4m = 2 MB、order/队列 400 KB、dp 与 pre 各 400 KB——合计 4 MB 上下，竞赛 256 MB 上限里的零头；真正该防的是把邻接矩阵开成 n×n（1e5 的方阵是 40 GB，第 14 单元实测过 malloc 都给的是页文件的空头承诺）。

顺带交代这张表怎么测出来的，因为方法本身就是纪律：耗时全部由程序内的 clock()（C）与 std::chrono::steady_clock（C++）在「建图之后、算法本体的那一段」取值，打给 stderr；stdout 只放跨次稳定的东西（弹出个数、合法性标志、校验和），清单对账盯的是后者——时间每次都抖几毫秒，混进 stdout 会让输出对账天天失败。每个数字跑三次取区间而不是取单次：clock() 的分辨率是 1 毫秒，单次读数受机器当时的负载影响，三次区间才敢写进正文。你复现时跑自己的机器，拿到的是你自己的区间——量级应当一致，具体数字不必强同。

选型只有三条，照着对就行：只要判环或任意一个序——数组队列 Kahn，O(n+m)，本机 1e5/5e5 五毫秒；要字典序最小——小根堆版，多花十几毫秒买正确性；要在图上做 DP——先拓扑排序再按序递推（迭代，无栈深风险），记忆化 DFS 只在「最长路明显不长」的图上用。三条里唯一不能碰的是「每轮线性扫描」——它的岗位只在 n≤1e4 的对拍里。

小结这一节的要点
  • 建模只有一条方向约定：u -> v 表示 u 先于 v；拓扑序 = 让每条边从左指向右的排列，存在 ⇔ 无环，「必须按顺序」的题面全部翻成加边；
  • Kahn = 入度表 + 队列：加边处维护入度，弹出时给邻点减一；不变式「队里的点前驱全齐」保证弹出即安全，弹不完剩下的点构成环——同时给出序与坏账名单；
  • 字典序最小 = 把队列换成小根堆，每步取编号最小的可用点；交换论证保证贪心对，复杂度 O((n+m) log n)；「先排再 sort」直接错，「每轮收集再 sort」退化 O(nm)；
  • DAG 上的 DP：按拓扑序处理保证转移来源已是终值；最长路（多源）与最短路（单源）同一副骨架；记忆化 DFS 是等价的递归写法，但深度 = 最长路，链上就是 n，1e5 爆栈（本机实测 exit 127）；
  • 环图上最长路不存在：无视「弹出 < n」硬算，假值会沿出边污染下游一整片；pre 还原路径回走是反的，收尾必须反转；
  • 实测：Kahn 与拓扑 DP 在 1e5/5e5 上个位数毫秒，小根堆版二十几毫秒，每轮扫描暴力 1e4 就要五百毫秒——它只配待在对拍里。

  1. 「拓扑序存在 ⇔ 无环」的两个方向，Kahn 分别是怎么给的？把「弹不完必有环」的论证复述一遍。
  2. 数组队列里，弹出去的元素为什么可以留在原地不搬走？一个点最多入队几次，为什么？
  3. 四点例（边 2->0、3->1）里，FIFO 给 2 3 0 1，小根堆给 2 0 3 1。用交换论证的语言说清：FIFO 的序在哪一步输掉了？
  4. 「先随便排一个拓扑序再 sort，就得到字典序最小」为什么错？构造一个最小反例。
  5. 拓扑序 DP 与记忆化 DFS 算的是同一个东西吗？dp[v] 与 memo[v] 的口径差在哪，什么量两者必相等？
  6. 还原路径时 pre 回走得到的序列方向如何？本单元的对拍用哪三条检查抓「方向反了」这类错？
注自测题答案
  1. 无环 ⇒ 弹完：每轮队列非空（DAG 必有入度 0 的点，删掉一个还是 DAG），n 轮弹完，输出即拓扑序。有环 ⇒ 排不完：队列空时若还有剩余点且剩余子图无环，则剩余子图必有「在剩余点中入度为 0」的点，而它的原图入边全来自已弹出点（入度早该减光），该入队而没入队，矛盾——所以剩余点互相指着，构成环。Kahn 弹完给出序，弹不完给出「坏账名单」（剩余点）。
  2. 弹出只是 qh++，逻辑上移走了，物理位置没人再用；入队只会把新点写到 qt 之后，永远不会覆盖还没弹的区间。一个点最多入队一次：入度只在邻点弹出时减，--ind[v] == 0 在一个点的生命周期里只可能成立一次。
  3. 第 2 步。第 1 步两者都选 2；此时可用集是 {0, 3}，FIFO 按「先入队先弹出」选了 3（3 在初始就入了队），而字典序最小要求选 0。交换论证：把 0 提到 3 前面得到的新序依然合法（0 的前驱 2 已在前缀），且第一个不同处 0 < 3——FIFO 的序严格更大。
  4. 四点例即可：普通拓扑（FIFO）给出 2 3 0 1，sort 后得 0 1 2 3，而边 2->0 要求 2 在 0 前——sort 结果连合法拓扑序都不是。字典序最小必须在构造过程中每步取最小可用点，不能事后重排。
  5. 同一个「最长路」问题，口径相反：dp[v] 是「从某个入口修到 v（含 v）的最大点权和」（终点口径），memo[v] 是「从 v 出发沿出边的最大点权和」（起点口径）。全局最优两者必相等（最长的那条路既是某点的终点口径值，也是它起点的起点口径值）；逐点值一般不同。本单元对拍正是拿「全局最优相等」+「逐点与全路径枚举各口径相等」三方验证的。
  6. 反的：从终点沿 pre 回走，收集到的是终点在前、起点在后，必须原地反转才是正向路径。三条检查：起点必须是入度 0 的点（反转错了起点就在尾巴上）、相邻两项必须是图里真实存在的边、路径点权和必须等于 dp 的全局最优值——方向反了挂在第一条，假边挂在第二条，假值挂在第三条。
