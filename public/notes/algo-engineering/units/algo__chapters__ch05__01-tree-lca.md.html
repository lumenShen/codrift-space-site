11.1 先看工程长什么样

第 4 章的树上差分（4.6 节）用「朴素爬祖先」求 LCA——深度对齐、两点同爬，一条路径 O(深度)。在随机树上这已经够快；可一旦树长成一条链，深度就是 n，爬一次祖先就是 O(n)。这一单元把「爬」升级成「跳」，顺手把树本身的三样基础设施一次讲透：怎么存树（11.2）、怎么把子树变成区间（11.3）、怎么在树上快速问答（11.4、11.5、11.6）。最后 11.7 交一笔很多教材不交的账：递归 DFS 在本机的栈上到底能活多深——数字全部来自本单元自己的程序。

大白话先建立一句话的画面

树上所有问题的总背景是：树是「带唯一路径的图」——任何两点之间恰有一条简单路径。你以后写的一切树上算法，本质都是在利用这条唯一性：

  • LCA 问的是：从 u 和 v 分别往根爬，最后一段公共的路从哪个点岔开；
  • 子树问的是：岔开之后的「下半段」里有哪些点、它们的和是多少；
  • 直径问的是：哪两个点之间的那条唯一路径最长。

把「唯一路径」这四个字记住，本单元每个论证都会顺理成章。

顺手把 LCA 这个主角的定义也放进来（11.4 会再正式钉一遍）：从 u 和 v 分别沿父亲边往根走，两条路迟早汇合——汇合处就是最近公共祖先（LCA），树上任何两点的路径必经它。所以「u 到 v 的距离」永远可以拆成「u 上到 LCA」加「LCA 下到 v」，这一拆是 11.4 距离公式、4.6 树上差分、以及后面几乎一切树上路径问题的公共起点。

第 1 帧是动笔前的空目录。第 2 帧是三个对拍工程，骨架与全书一致：include/ 放声明、src/ 里正解与暴力各一个编译单元、main.c 只管造数据与逐组比对。第 3 帧是本单元的加码：三个 perf_main.c（耗时打 stderr，stdout 只放跨次稳定的结论）、一个 C++/STL 应用层（M14 要求的双层之二）、欧拉序 + ST 的第四份对拍，以及本单元最特别的 tree_recdepth/——递归 DFS 的栈深实验，带两份真实会话（边界探测与对照）。

11.2 树怎么存：父亲数组、邻接表与前向星

树的边数恰好是 n−1（连通无环），所以存树永远只有两个问题：每条边存几次、按什么顺序取。竞赛里常用的三种答案：

存法 内存 加边 遍历某点的邻居 什么时候用它
父亲数组 par[i] n 个 int 只能由父到子 只能看父亲 树的形状已经定向、只往上爬（4.6 树上差分）
vector<vector<int>> 邻接表 指数级小对象 push_back 一次 for 循环，顺序清晰 C++ 应用层、图不深、不想管内存
链式前向星（数组版邻接表） 2(n−1)+n 个 int，一次性 手工头插两条 沿 nxt 链走 C 原理层、n 到 1e6、要控制缓存与内存

本单元 C 原理层全用链式前向星：三根数组 head / nxt / to，head[v] 是 v 的第一条边编号，nxt[e] 是同一条链里的下一条，to[e] 是这条边通向谁。无向边插两次（两个方向各占一个槽），总槽位 2(n−1)：

链上的顺序与建树无关——DFS、BFS、LCA 都不在乎邻居的先后。所以「头插法让链序与输入序相反」在这里不构成任何坑。值得慢走一步的是槽位账：每条无向边占两个槽（2i 与 2i+1），n−1 条边共 2(n−1) 个，加上 n 个链头，三根数组合计 3n−2 个 int——一条 1e6 个点的树约 12 MB，一次分配、零扩容。对比 vector<vector<int>>：每个点一个对象（对象头 + 堆指针 + 容量字段），n 个点就是 n 次堆分配、2(n−1) 次 push_back（每次都可能触发扩容拷贝），同样的树内存要多出三到五成，还要多背一个「扩容时迭代器失效」的心智负担。这不是说 vector 不好——它是 C++ 层的默认，11.4 末尾的应用层程序就用它；而是在 C 原理层，你要看得见这些手工活省掉了什么、代价记在了哪里。

顺带把「树的边数恰好是 n−1」这件事用归纳钉死，后面反复用：一个点，0 条边，成立；设 k 个点的树有 k−1 条边，往树上挂第 k+1 个点（树加一个叶子仍是树），恰好新增 1 条边——k+1 个点 k 条边。反过来也成立：n 个点 n−1 条边且连通，就一定无环（有环的话删掉环上一条边仍连通，边数会少于 n−1，矛盾）。本单元所有 lca_build(&t, edges, n-1, n) 式的入参检查（第 7 行的 m != n - 1）依据的就是这条性质：给的边数不对，它就不是树。

头插法值得用三行文字走一遍：插边 (a, b) 时，nxt[槽] = head[a] 先把新槽接到旧链头上，head[a] = 槽 再把链头换成新槽——顺序反了就把整条链丢了（2.3 的 next 临时变量、11.3 的 iter[u]，全是同一个「先存旧的再改」）。三条链插入完成后，从任何 head[v] 出发沿 nxt 走到 −1，恰好经过 v 的全部邻居一遍：这就是「遍历某点的邻居」的全部实现，没有 rehash、没有二级指针。

11.3 DFS 序：把子树和变成区间减法

第一个应用不需要 LCA，只需要一个时间戳。DFS 进入每个点时发一个号 tin[v]，离开时收一个号 tout[v]——于是有本单元第一条定理：

大白话子树是一段连续区间

DFS 像说话的括号：进点是左括号，出点是右括号。括号序列里，一对括号包住的永远是连续的一段——没有任何别人的括号能插进你和你的后代中间，因为在你收口之前，笔尖根本出不了你的子树。所以「v 的子树」在 DFS 序上恰好是区间 [tin[v], tout[v]]，一个点不漏、一个点不多。子树求和就此变成前缀和的两次减法——第 4 章的整套装备直接搬进树里。

这是帧级手动栈：每格存「点 + 它下一条待处理的边」，进栈发 tin，出栈收 tout。它与递归 DFS 的访问顺序逐点一致（每一帧都是「从上次走到的边继续」），所以下面所有关于访问顺序的论证对递归版同样成立。用小树走一遍，四个帧看得最清楚：

第 3 帧是关键：tout[u] = timer - 1 写在 u 出栈那一瞬，此时 u 的整棵子树都已发号、别的分支还没开始——所以闭区间 [tin[u], tout[u]] 既不会混进别人的点，也不会漏掉自己的点。归纳论证：叶子在进栈后立刻收口，区间是单点，成立；设 u 的每个儿子的区间都等于其子树，则 u 收口前最后发的号恰是其最后一个儿子的 tout，u 的区间 = 各儿子区间加上 u 自己，拼成连续一段，恰好覆盖 u 的子树。归纳完成。

这一手的价值值得放大说：DFS 序把树「拍扁」成了数组。树的形状是不规则的、指针式的，第 4 章以前你学的一切数组技巧——前缀和、差分、二分、双指针——在树上原本都施展不开；拍扁之后，位置 0..n−1 就是一个普通数组，第 4 章的全部装备原样可用。「树上问题 → DFS 序 → 序列问题」是本书后三章反复出现的转化路线：本节的子树和、11.8 表里的子树加，还有第 6 章的树上路径统计，走的都是这条路。

它还顺手送你一个免费的祖先判定：u 是 v 的祖先（或相等）当且仅当 tin[u] ≤ tin[v] && v 的区间被 u 的区间包含（tin[v] ≤ tout[u]）。一句话读法：u 进门比 v 早、出门比 v 晚——u 的括号包住了 v 的括号。这个判定 O(1)、零预处理，比倍增轻得多；判断「v 在不在 u 子树里」时别动用 LCA，大炮打蚊子。

DFS 序的用场清单最后归拢一遍，都是「拍扁」直接买到的：子树和（本节）、子树加（4.5 差分两笔账）、判祖先（上面这句话）、子树计数（区间长度 = tout−tin+1）、按子树切段的树形 DP 转序列 DP（第 8 章的树上背包就是靠「DFS 序 + 括号匹配」把树拍平做的）。它们的共同姿势是：建一次序，之后全部操作都落在 0..n−1 的数组上，树的存在感只剩 tin[] 查表。

pre 数组有两个容易忽略的口径问题。其一，长度是 n+1 不是 n：pre[i] 定义成「位置 0..i−1 的和」（第 61–63 行的 pre[0] = 0 哨兵），区间 [l, r] 的和写成 pre[r+1] − pre[l]——r+1 这个下标就是哨兵买来的：不用它，tout[v] = n−1 时你得写一个特判分支。4.2 讲过的这条纪律在树上原样生效。其二，前缀和挂在 DFS 序的位置上而不是点号上：at[tin[v]] = val[v] 那一摆（第 57 行）就是「重编号」，此后一切区间操作都发生在 DFS 序的世界里，点号只能进 tin[] 查表——两个世界各管各的，混着用就是把下标当点号（2.8 的混用陷阱的树上版）。

还有一个预告要挂在这里：本节发的号是「进点一次」的 DFS 序（长 n），11.5 会用「进点 + 每次回头」的欧拉序（长 2n−1）。名字像、用途不同：DFS 序管「子树在哪一段」，欧拉序管「回头路上的深度起伏」——前者服务子树统计，后者服务 LCA。看到「欧拉序」三个字先确认长度，2n−1 才是它的身份证。

11.4 倍增 LCA：把「爬祖先」变成「跳 2^k」

朴素爬祖先的账很好算：深度差多少就爬多少步，链上一次询问 O(n)。倍增的思路是预支：先花 O(n log n) 建一张表，把「从我这里往上跳 1、2、4、8……步落到谁」全部记下来；之后每次询问只用 O(log n) 次「跳」完成。表建得越厚，跳得越远。

大白话up 表是一张「电梯楼层表」

把每个点的祖先链想成一部楼梯，up[k][v] 就是「从 v 出发坐 2^k 站电梯落在哪层」。1 站电梯（up[0]）就是父亲；2 站电梯不用走——先坐一次 1 站，再从落点坐一次 1 站，两个一半拼起来；4 站电梯 = 两个 2 站拼起来。任何楼层都能用这些 2 的幂拼出来（二进制分解），所以任意深度的对齐、任意距离的对跳，都变成「从最大的电梯往下试，够得着就坐」。

先把 LCA 本身钉死成一条定义，后面所有论证都挂在这句话上：u 与 v 的最近公共祖先，是「同时是 u 和 v 的祖先」的那些点里深度最大的那个。两个推论马上能用：根是所有点的公共祖先，所以 LCA 恒存在（最坏就是根）；u 自己是 v 的祖先时 LCA(u, v) = u（查询函数第 68 行的 if (u == v) return u 处理的正是「对齐后同点」这个情形，包括 u = v 本身）。祖先的定义是「沿父亲边能走到」——所以 LCA 问题的一切讨论都建立在 par[] 这一个数组上，11.2 的 BFS 把它一次定好。

11.5 欧拉序 + ST 表：另一种 LCA

倍增把「跳」预支好了；另一种思路把区间最小值预支好。把 DFS 写成欧拉序——每沿一条边走一步（去和回都算）就记下走到谁：长度恰为 2n−1（根出现 1 + 儿子数次，每个点都是「1 + 儿子数」次）。于是有一条极漂亮的转化：

大白话LCA 变成区间最小深度

u 和 v 在欧拉序里各有一个首次出现的位置。这两点之间那段序列里，深度最小的点就是 LCA。为什么：从 u 的首次出现走到 v 的首次出现，笔尖恰好扫过「u 抬头、分岔、低头到 v」的全程——期间出现过的点全在 LCA 的子树里（深度 ≥ dep(LCA)），而 LCA 自己必然出现在这段里（u、v 不同子树时，回溯序列正好路过它；同子树时往深处再看一层就是它）。区间最小深度问题叫 RMQ，ST 表是它的经典 O(n log n) 预处理、O(1) 查询解法——形状与倍增表一模一样，只是存的从「祖先」换成「区间内最浅的位置」。

长度 2n−1 也有一个两行的归纳：根出现 1 + 儿子数次；归纳设每个点都出现「1 + 儿子数」次，则总长 = Σ(1 + 儿子数) = n + Σ儿子数 = n + (n−1) = 2n−1（每条边恰好贡献一个「儿子」，树有 n−1 条边）。叶子出现 1 次（进去就回头，没有儿子可回）、根出现儿子数 + 1 次——都是这条通式的特例。写代码时若某点出现次数超过「1 + 儿子数」，说明回头账记重了；少于则漏了回头，两种都会在 first[] 上留下「没被踩过的点」，对拍第一轮就能抓到。

first[] 的另一个用途是自查：建完表立刻扫一遍，first[v] == -1 的点就是没被遍历到的点——树不可能漏，出现 −1 只有一个解释：建表代码有 bug（本单元真抓到过一次，malloc(es) 漏了 sizeof(int)，堆被写穿、邻接表成了半截链，DFS 只走到 21 个点就「以为遍历完了」；对拍当场报错，gdb 定位到堆损坏）。这种「自查行」在 OJ 代码里是多余的，在你自己的工程里是保险丝——代价是一次 O(n) 扫描，收益是 bug 在建表处暴露而不是在 1e7 次询问里随机爆。

ST 表查询为什么敢重叠也值得一句：区间 [l, r] 拆成 [l, l+2^k) 与 [r-2^k+1, r] 两半，k 取 floor(log2(区间长))，两半至少盖满全区间、中段可能重复。min 这种「可重复贡献」运算，重复读不改变结果；换成 sum 就不行（重复段算两遍），换成「区间最值的位置」要小心平局——本节代码用 <= 让平局时取左半，与暴力扫描的取法一致，对拍里专门掺了平局树（多点同深度）。可重复贡献这个判据，和 4.1「前缀和必须有逆运算」正好是一对：能减的用前缀和，不能减、能重叠的用 ST 表。

11.6 直径：两遍 DFS 与它的交换论证

直径 = 树上相距最远的两点之间的距离。暴力是 O(n²)：每个点当一次起点量到所有点的距离（对拍侧就是这么写的）。正解只要两遍 DFS：

为什么「从任意点出发的最深点」一定是某条直径的端点？ 这是本单元第二条正式论证，用交换论证。先把两遍的过程说全：第一遍从任意点 s 出发，找到离 s 最远的点 a；第二遍从 a 出发，找到离 a 最远的点 b。要证 dist(a, b) 等于直径长。取一条真正的直径，两端 u、v。关键角色是一个分岔点 p：s→u 与 s→v 两条路径的同走前缀在 p 处分开——树上这样的点存在且唯一（它是 s→u、s→v、u→v 三条两两路径的公共交点），且 p 一定落在 u−v 路径上（u−v 的唯一路径 = p→u 段 + p→v 段）。逐步来：

  • 第一步（路径拆分，用路径唯一）：p 在 s→u 路径上，所以 dist(s, u) = dist(s, p) + dist(p, u)；对 v 同理。
  • 第二步（绕路上界）：s 到 a 的路径长度不会超过「先绕到 p 再下去」：dist(s, a) ≤ dist(s, p) + dist(p, a)——树上这是度量不等式的平凡形态（两点间唯一路径是最短的那条）。
  • 第三步（两式相减）：a 是离 s 最远的点，dist(s, a) ≥ dist(s, u) = dist(s, p) + dist(p, u)，与第二步相减得 dist(p, a) ≥ dist(p, u)；对 v 重复得 dist(p, a) ≥ dist(p, v)——p 到 a 比到直径两端都不近。这一步还顺手排除了一个位置：a 不可能严格落在 p 的「s 侧」（那里的点到 s 距离小于 dist(s, p) ≤ dist(s, u) ≤ dist(s, a)，矛盾）。
  • 第四步（a 的位置只有三种）：a 只能在 p 的 u 侧、v 侧，或挂在 p 自己的分支上（第三步已排除 s 侧）。无论哪种，p 必在 a→u 与 a→v 两条路中至少一条上——a 在 u 侧时 a→v 要穿过 p，a 在 v 侧时 a→u 要穿过 p，挂在 p 上则两条都穿。
  • 第五步（收口）：在 p 穿过的那条路上，dist(a, ·) = dist(a, p) + dist(p, ·)；结合第三步的「双不近」：dist(a, v) = dist(a, p) + dist(p, v) ≥ dist(p, u) + dist(p, v) = dist(u, v) = 直径（a 在 u 侧的情形，u、v 角色对调）。而「从 a 出发的最长距离」不可能超过直径（直径是全树最大点对距离），所以第二遍找到的最深点 b 恰好把这条最长路走满——dist(a, b) = 直径长。

三个值得圈出来的点。其一，第一遍的起点 s 真的随便：论证只用了「a 离 s 最远」，没用 s 的任何特殊性——起点选错只会让第一遍「绕远」，不会让结论失效。其二，直径可以不唯一（链上加一个分叉的树有多条），但「最长距离」这个数唯一，两遍 DFS 输出的是其中一条直径的端点，对拍只比长度、不比端点，原因就在这。其三，所有「离 a 最远」的点都是某条直径的端点，所以直径两端点是成对出现的：想找「直径中点」或树的重心，从 (a, b) 这对端点出发推。论证只用了两条树上铁律：路径唯一（拆路径经过 p 不产生歧义）与边权非负（距离沿路径累加不减）。第二条正是算法的边界——

陷阱你怎么会被坑到：负权树上两遍 DFS 安静地给错

（先说你会看到什么）树的边权可以是负数（「走这条路有代价」的题），你套了两遍 DFS，样例对、随机数据错。 （再说你会怎么误判）你怀疑第二遍起点选错、怀疑 far 更新时机——因为它「大多数时候」还是对的。 （最后说真相）交换论证的第二条铁律断了：边权为负时，「离 s 最深」的点不再「离直径两端都远」（绕路可能更短），最深点可以完全不在任何直径上。负权树上求直径没有两遍 DFS 的便宜，要么接受 O(n²) 枚举，要么把「最大距离」问题转成树形 DP（第 8 章）。两遍 DFS 的适用前提写进注释：边权非负。

实验记录本机实测：直径的两笔账
  • 工具链：本机 gcc 16.1.0（-std=c17、-O2），clock() 计时，目标三元组 x86_64-w64-mingw32；
  • 两遍 DFS 在 n=1e5：链上 1 ms、随机树 3–4 ms——两次 O(n) 遍历，慢就慢在 7.2 MB 换不到这里（直径根本不用建表）；
  • 暴力 O(n²) 在 n=150：不到 1 ms，但它到 n=1e5 就是 1e10 次操作（分钟级起步）——对拍可以小，性能必须大；
  • 直径的副产物值得记住：端点对 (a, b) 本身，「从某点出发最远能到哪」一类题直接用。

为什么直径值得一个专门算法？因为它是很多树上问题的第一步量尺：网络布点问「选两个服务器让最远节点到最近服务器的距离最小」，答案是直径两端各放一个（直径的中点性质）；树的搜索剪枝问「最深还能有多深」，拿直径或带端点的两遍 DFS 垫底；甚至第 7 章的「直径上每条边都要被某种覆盖压一遍」的贪心，也先要直径。两遍 DFS 的 O(n) 版本几乎总够用，唯一的成本是接受它只对非负权成立（上面的论证）。

还有一个一眼的变体：把单遍 DFS 换成 BFS，两遍 BFS 同样正确——深度=距离时（边权全 1），BFS 的层数就是距离，论证一字不改。选 DFS 还是 BFS 看你要不要「进出时刻」（要就 DFS + 手动栈，见 11.3、11.7），只要距离就 BFS 更短。两个版本在本单元的直径工程里都真实存在：正解用栈式 DFS（dia_dfs_farthest），暴力用 BFS 逐点对——互不沾光这条对拍纪律的又一次落地。

顺手把帧的算术摆一下：2 MB 栈 = 2 097 152 字节。-O2 边界 26000 帧，折算每帧约 80 字节（2097152 ÷ 26010 ≈ 80.6，含对齐与保护页的零头）；-O0 边界 32600 帧，每帧约 64 字节。80 对 64 的方向与直觉相反，机制就是其二说的被调用方保存寄存器：rec_body 的循环里有跨递归调用存活的量（e、w->depth、w->check 的累加），-O2 把它们放进 rbx/r12 这类寄存器，每一个这样的寄存器都要在被调用前压进帧里，寄存器用得越多帧越大；-O0 反而把什么都丢在栈上，不欠寄存器这笔账。所以「开优化会欠更多栈」不是悖论，是这台机器上真实发生的权衡——预算栈深度时按最紧的那档算。

这一行「遗言」能留下来，靠的是驱动里那次显式的 fflush(stdout)（main.c 第 30 行）。机制：stdout 接管道时是全缓冲的，printf 的内容先攒在缓冲区里，攒满或正常退出才写出；进程被系统杀死属于「没得正常退出」，缓冲区整段丢失——你连「链长 100000」这行都看不到，调试时只剩一个哑巴退出码。所以崩溃实验的每次打印后面跟一句 fflush 是本单元定下的纪律，2.8 的死亡登记用的同一招。这也反过来提醒：正常程序的打印不需要 fflush，滥用只会让性能白丢。

对照的两行是本节的结论：同一台机器，1e5 的随机树递归只活 25 层深（安然无恙），1e5 的链当场死亡；1e6 的链手动栈照样跑完——栈峰值 1000000 格全在堆上。深度跟形状走，不只跟规模走；而手动栈对两个维度都不敏感。

有读者会问：栈不能调大吗？能，但不归你调。Windows 的可执行文件把栈保留量写在 PE 头里（本机 2 MB），链接器改得了、编译命令行也够得着；Linux 上是 ulimit -s，启动环境说了算。可你的代码要交到评测机上跑——评测机的栈保留、开关的优化档、进程的启动方式全是别人的决定，你能依赖的只有「语言标准的保证」和「堆的大小」。所以竞赛代码的正确姿势不是把栈调大，而是让栈用量与输入规模无关：深度可能到 n 的递归一律手动栈，这条规则从 2.8 的递归 find、4.6 的无递归树上差分，到本节的实验，已经是本书第三次落地。

手动栈写法本身有三种形态，按「你要的信息」选：帧级模拟（本单元的 rdf_frame_t：点 + 下一条边，两格 int）——访问顺序与递归版逐点一致，tin/tout、欧拉序这类「进出时刻」敏感的统计必须用它；点栈（栈里只放点号，弹出时展开全部邻居）——实现最短，但访问顺序与递归版不同（后进先出把邻居倒过来），只统计「可达性/距离」时够用，11.6 的直径 DFS 就是它；显式状态机（把「进入/处理/离开」编成状态压栈）——最啰嗦，只在要模拟「离开时刻」又想省那格边号时用。本单元四份工程里三种形态都出现了：subtree.c 帧级（要 tout）、diameter.c 点栈（只要距离）、recdfs.c 帧级（要访问序一致）。选错形态的症状很典型：需要 tout 的题用点栈，tout 全变成「最后一次见到它」的错值——子树区间直接失效。

最后给一张「深度敏感」清单，赛场过一遍只需十秒：递归 DFS / DFS 序（深度 = 链长风险）、递归版并查集 find（2.8）、递归线段树 build 与修改（深度 = log n，通常安全，但动态开点会加深）、递归求 LCA 的「逐层上跳」写法、树形 DP（深度 = 树高）。前两个是惯犯，后三个视数据而定——共同的自保动作就是本节的手动栈三形态，或者像 lca.c 那样干脆用 BFS 代替「遍历型递归」（定 par/dep 从不需要递归）。

陷阱你怎么会被坑到：本地样例全对，评测机上一交就 RE

（先说你会看到什么）递归 DFS 三行核心，样例（几十个点）秒过；交到 n=1e5 的链状数据上，RE，本地重跑却复现不出来。 （再说你会怎么误判）你怀疑数组开小、怀疑数组越界——因为 RE 的第一嫌疑总是它们；改大数组毫无效果。 （最后说真相）栈溢出。本机 2 MB 栈、这份函数 -O2 下 2.6 万帧就是天花板，评测机的栈通常更紧。诊断特征：进程无声死亡（没有段错误横幅）、stdout 缓冲区整段丢失（除非像本单元这样显式 fflush）。规则写在 2.8 也写在 4.6，这里第三次：凡是「深度可能等于输入规模」的递归——DFS、递归 find、递归线段树——一律手动栈，或者确认题目的树高有保证（比如声明「随机生成」）。

小结这一节的要点
  • 树的三种存法各有分工：父亲数组只往上爬，链式前向星在 C 里一次建好 2(n−1) 个槽，vector<vector<int>> 是 C++ 层的默认——遍历用「已访问挡住来路」，重边自环天然免疫；
  • DFS 序把子树变成区间 [tin[v], tout[v]]：子树和 = 一次前缀和减法；「v 的子树」必须有根方向，只挡来路的暴力会爬出子树（对拍真抓过）；
  • 倍增表 up[k][v] 的正确性是纯归纳：「跳 2^k = 两个 2^(k-1) 拼起来」，地基是祖先链唯一；查询两步——深者对齐深度、两点从高往低同跳（uu != vv 才跳）；
  • dist(u,v) = dep(u) + dep(v) − 2·dep(lca)，带权树把 dep 换成到根的边权和原样成立；
  • 本机实测的反直觉结论：随机树上暴力爬祖先（30 ns）比倍增（105 ns）快；倍增的 170 倍优势只在链上兑现——算法的胜负手在最坏形状；
  • 欧拉序 + ST 把 LCA 变成区间最小深度：查询 O(1)、只回答 LCA 本身；倍增慢一点但「跳」能携带路径信息；
  • 两遍 DFS 求直径的交换论证只用两条铁律：路径唯一 + 边权非负——负权树上它会安静地错；
  • 递归 DFS 的深度边界必须自己测：本单元程序 -O2 下 2.6 万帧（26010 被杀）、-O0 下 3.25 万帧，与 2.8 并查集的 4.4 万方向都相反；深度可能等于 n 的递归一律手动栈。

注自测题答案
  1. 归纳。奠基：up[0][v] = par[v] 定义即真。归纳步：跳 2^k 步拆成「先跳 2^(k-1) 步到 w，再从 w 跳 2^(k-1) 步」——用到的树性质是祖先链唯一：v 的 2^(k-1) 倍祖先只有一个（w 唯一），从 w 再跳一半也只有一种走法；图上有环时「跳」没有唯一定义，递推不成立。
  2. 「跳过头无法撤销」：若 2^k 祖先相同（LCA 或其祖先），跳过去就错过了 LCA，后面没有信息能把它找回来；从高往低试，每个「uu != vv」的跳都保证仍在 LCA 之下，跳少的部分由更低的层补齐。从 k=0 往高试，会先做大量无效小跳，且无法判断哪些大跳安全，最坏退化成逐层爬。
  3. 18 层。链的最大深度差 99999，2^17 = 131072 ≥ 99999 才够一次跳到位，所以需要下标 0..17 共 18 层 = ceil(log2(1e5)) + 1。只开 17 层（0..16）时，深度差超过 65536 的对齐跳不完，LCA 答错——错误在深链上才暴露，样例与小随机数据全对。
  4. 规则看深度分布而不是 n：题目保证树随机（深度 ~ln n）或给出树高上界 O(log n)，直接暴力爬祖先；可能出现链状/菊花改造数据、或要配合路径信息，建倍增表——7.2 MB 换「最坏形状下 170 倍」。一句话：赌得起形状就爬，赌不起就建表。
  5. 两条前提：路径唯一（论证中把 u−v 拆成经过 p 的两段、比较 a 的两条路，靠的是树上路径唯一不歧义）与边权非负（由 dist(s,a) ≥ dist(s,u) 推出 dist(p,a) ≥ dist(p,u)，靠的是距离沿路径累加不减）。负权时第二步断裂，最深点可能不在任何直径上。
  6. 边界数是「栈余量 ÷ 本程序每帧大小」，帧大小随程序、随优化档变，连 -O0 与 -O2 谁活得多都可能反过来。所以：别人的数（含本书其他单元的）只当量级；换程序、换优化档、换机器，都用 -D 开关 + 退出码 0/127 的方法重测一遍，几秒钟的事。
