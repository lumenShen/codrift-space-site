4.1 先看工程长什么样

前缀和与差分是一对互逆的记账法：前缀和把「求一段的和」变成两次减法，差分把「给一段加一个数」变成两次单点改。它们都不算难写，真正让你掉分的是三件事——类型（int 装不下前缀和）、符号（容斥式写反）、收尾（差分忘了还原、树上差分忘了累加）。这三件事全在工程里，所以照本书的规矩，先看文件。

三个工程共用一套约定，先立在这：对外坐标一律 0 基（题目给的 1..n 读进来就减一，混用的下场 2.8 讲过）；区间一律闭区间 [l, r]（两端都含，公式里会看到对应的 +1/−1）；累计值一律 long long（4.5 有真现场）；每个工程带一场 200 组对拍（alg02 的纪律，本单元三个公式全部交给随机数据验证）。阅读路线建议照节的顺序走：4.2–4.3 把一维的正反两面拿下（它们共用一份头文件），4.4 的容斥要对着四帧图把符号数一遍，4.5 的溢出现场值得亲手复现一次，4.6 的树上差分重在「LCA 配合」与「根上多 1」两处论证，4.7 是应用层的装备，4.8 的表留给赛时查。

大白话这一节想让你先建立一个画面

把前缀和想成汽车的里程表：它只增不减，每一个刻度都是「从起点到现在一共走了多远」。问「第 3 站到第 7 站走了多远」，不用重走一遍，拿 7 站的读数减 3 站的读数就行——区间问题变成了两次端点查询。

差分就是里程表的反操作：手里只有相邻两站读数的差（每一段走了多远），把差一路加回去，就还原出整张里程表。想「让第 3 到第 7 站集体多走 10 公里」？里程表上根本不用动 5 个刻度，只要在进第 3 站前把时速 +10、出第 7 站后把时速 −10——区间加变成了两次单点改。二维前缀和是把里程表铺成「从原点出发的矩形累计」，树上差分是把「到根的链」当成那根数轴。全部技巧都长在同一根骨头上。

第 1 帧是动笔前的样子：第 4 章还是两个空目录。第 2 帧把三个工程一次摆齐——diff_range_add 管一维前缀和与差分（它们共用一份接口，4.2、4.3 会看到为什么），prefix_2d 管二维容斥，tree_diff 管树上点差分；每个都是「头文件 + 实现 + 暴力 + 驱动」四件套，暴力都是定义的直接翻译。第 3 帧补齐对照面：三个 perf_main.c 支撑 4.8 的复杂度表，ovf 三件套把 int 溢出的现场抓给你看（含一份被 -ftrapv 杀死的进程），prefix_2d_cpp.cpp 是 STL 应用层，四份 session-*.txt 是真实抓下来的终端会话。九份清单全部 mode: "run"（其中一份是 runtime_error——它登记的就是那次真死），本单元所有 stdout 都被流水线逐字对账。

4.2 一维前缀和：把区间和变成两次减法

先立约定。全书的前缀和一律带哨兵：pre 有 n+1 格，pre[0] = 0，pre[i] 是「前 i 个元素的和」。问区间 [l, r]（闭区间、0 基）的和，答案是 pre[r+1] - pre[l]。接口只有两个函数：

为什么对？两步论证。递推是对的（归纳）：pre[0] = 0 是「空数组的和」，这是定义；若 pre[i] 是前 i 个元素的和，则 pre[i] + a[i] 恰是前 i+1 个元素的和——归纳成立。区间和是对的（望远镜求和）：pre[r+1] - pre[l] = (a[0]+…+a[r]) - (a[0]+…+a[l-1])，写开来看，a[0] 到 a[l-1] 的每一项都在两个前缀里各出现一次，相减时两两抵消，剩下的恰好是 a[l] + … + a[r]——不多不少。

拿 5 个元素走一遍：a = [3, 1, 4, 1, 5]，递推得 pre = [0, 3, 4, 8, 9, 14]。问区间 [1, 3]（元素 1、4、1）的和，公式给 pre[4] - pre[1] = 9 - 3 = 6，逐个加是 1+4+1 = 6——对上了。再问 [0, 4]（整段），公式给 pre[5] - pre[0] = 14 - 0 = 14：右端点的 +1 把最后一个元素装进来，左端点恰好是哨兵格，整段查询也走同一条路。

顺手排掉一个高频混淆：有的教材用「不含右端」的半开区间约定，区间和写成 pre[r] - pre[l-1]——那不是另一套数学，只是把「+1」从 r 挪到了 l-1。两种约定各自自洽，但一个程序里只能有一种；混用的症状与 4.3 的端点错位一模一样（头部或尾部差一个元素）。本书全册统一闭区间加「右下标 +1」，你抄模板时先看一眼约定再抄。

pre[0] 这个哨兵格值回票价：没有它，l = 0 的查询就得写 if (l == 0) return pre[r+1]; 这样的特判；有了它，「空前缀的和是 0」把边界吸收进公式，任何区间都是同一行减法。这一个格子，就是「把边界情况变成普通情况」的经典手法，二维版（4.4）和树上版（4.6）还会各买一次。

建表一次 O(n)，之后每次区间和 O(1)——对比暴力的每次 O(n)，这笔账在 4.8 用本机实测结清。同一根骨头还能长出别的形状：前缀积（pre[i] = pre[i-1] * a[i]，回答区间积，注意 0 会破坏可逆性，得配合 0 的计数）、前缀异或（pre[i] = pre[i-1] ^ a[i]，回答区间异或，因为异或自己减自己：x ^ x = 0，「减法」天然成立）。认出「这个问题能只靠端点回答」就是认出该用前缀和。

语法规则语法规则：前缀和的四个约定
  1. pre 开 n+1 格，pre[0] = 0：哨兵吸收「空前缀」，l = 0 不特判。
  2. 区间用闭区间 [l, r]，查询公式固定是 pre[r+1] - pre[l]——加的是 r+1 不是 r，写错就少算一个元素。
  3. 累计值用 long long：1e6 个 1e9 量级的元素，和约 9.5e14，int 的上限只有约 2.1e9（4.5 有现场）。
  4. 建表 O(n) 只做一次，之后随便查；别在「每次查询前重新建表」的循环里翻车。

建表也有不划算的时候，判据是一笔小账：暴力 q 次的总代价约 q × 平均区间长，前缀和的总代价 n + q。n=1e6、q=100、平均区间长 3e5（区间均匀随机时的量级）——暴力约 3e7 次加法（本机十几毫秒），前缀和建表 1e6 次加 100 次查询（一两个毫秒）：前缀和赢，但没赢到数量级；q=1 且区间很短时，暴力连表都不用建，直接赢。前缀和的甜点区是「查询成千上万」或「区间极长」——把 q 和区间长度估出来再选，这个动作本身就是 alg01「用规模反推算法」的一次具体应用。

4.3 差分：把「区间加」变成两次单点改

反过来想。如果操作是「给区间 [l, r] 整体加 v」，暴力要逐格加，一次 O(r-l+1)；q 次操作就是 O(nq) 的量级。差分把这个操作压到两次单点改：

为什么只动两个格子就够了？答案是差分与「差分的前缀和」互为逆操作。定义 d[i] = a[i] - a[i-1]（约定 a[-1] = 0，所以 d[0] = a[0]），那么对 d 做一遍前缀和，每一格都还原回 a：d[0] + d[1] + … + d[i] = (a[0]-a[-1]) + (a[1]-a[0]) + … + (a[i]-a[i-1])——还是望远镜，中间项全部抵消，只剩 a[i]。所以「改 d 再还原」等价于「直接改 a」。而 d[l] += v 之后，还原出的数组从 a[l] 起每格都多出 v；d[r+1] -= v 再把 r+1 往后的部分抵消回来。中间那一段正是 [l, r]。

单点查有两种姿势，账要算清。姿势一是现算 da_diff_point：把 d[0..i] 加起来，一次 O(i)——对拍里验的是它，因为它代表「不还原就读答案」的语义；姿势二是先 da_diff_restore 一次性 O(n) 还原成数组，之后每次单点查就是一次普通数组读，O(1)。q 次查询的总账：姿势一 O(qn)，姿势二 O(n + q)——只要 q 不止一两次，还原的投资必赚。什么时候真的需要姿势一？「加一笔、查一笔」交错的序列——那已经超出静态差分的能力，该换树状数组了（alg12 的「区间改单点查」正好是这个问题的数据结构解法，本单元先把账算清，结构留到那一单元）。

差分的建模能力也值得看一眼，因为它经常穿着故事的外衣出场：「n 排座位、m 张团体票，每张票占 [a, b] 连座，最后问每排坐了几人」——每张票就是一次区间加；「走廊里的灯，每次拉开 [l, r] 段的开关拨一下，最后问每盏灯被拨几次」——还是区间加。「最后才问、中间不问」是识别差分的信号句；反过来「每次操作后都要报数」，就是 alg12 要解的问题。识别出「区间加」三个字，剩下的全是 4.3 那两行代码。

陷阱你怎么会被坑到：端点 +1/-1 错位

（先说你会看到什么）对拍打出 FAIL 组 0 第 0 位，或者更阴一点——样例全对（样例的区间从不贴着数组两端），随机数据一上，头部或尾部差一个 v。

（再说你会怎么误判）你去检查 da_diff_add 的加法方向，或者怀疑 LCG 出了错数；甚至把 v 的符号改了又改——越改越乱。

（最后说真相）错位有三种标准姿势：写成 d[l] -= v; d[r] += v（把「到 r 为止」理解成「从 r 开始」）；写成 d[r] -= v（少减了一格，r 自己还在多 v 的状态里）；区间没排序就 d[l] += v; d[r+1] -= v（l 比 r 大时彻底乱套）。判据只有一句话：d[l] += v 管「l 及以后都多 v」，d[r+1] -= v 管「r+1 及以后还回去」——把这两句话对着代码念一遍，错位立刻现形。随机对拍必须覆盖「区间贴两端」的组（本单元的区间是均匀随机出的，n 小的时候自然撞到边界）。

为什么是「上 + 左 − 左上 + 本格」？S[i][j] 要覆盖矩形 (0,0)~(i-1,j-1)。S[i-1][j]（上）盖住了这个矩形除最后一行外的全部；S[i][j-1]（左）盖住除最后一列外的全部。两块并起来确实盖住了目标矩形，但左上角的 (i-1, j-1) 小块被两块各盖了一次——重复的部分减掉一次，再补上两块都没盖到的本格 a[i-1][j-1]。归纳基例是第 1 行第 1 列：那里「上」「左」都是哨兵 0，公式退化为 S[i][j] = S[i-1][j] + a[...]，正是递推的起点。

为什么 int 的错值「稳定可复现」？因为本机把有符号溢出编译成回绕（加上去，高位丢了）。但这在标准里是未定义行为：

标准原文标准原文：有符号溢出是未定义行为

If an exceptional condition occurs during the evaluation of an expression (that is, if the result is not mathematically defined or not in the range of representable values for its type), the behavior is undefined.

大意：表达式求值若出现「例外条件」——结果在数学上没有定义，或者超出该类型的可表示范围——行为未定义。int 前缀和越过上限正中这条：编译器有权假设它永不发生，并据此重排、删除你的代码。

出处：ISO/IEC 9899:2018（C17）§6.5「Expressions」第 5 段。

还要给 LCA 本身记一笔账，因为它才是这个算法的瓶颈。朴素爬祖先单次 O(深度)：随机树上深度是对数量级（本单元 perf 里 n=1e5 的随机树最大深度 24），40 ns 一次，便宜；但树退化成链时深度是 O(n)——n=1e5 的链上 q=1e5 次查询就是 1e10 次爬升，1 秒预算直接爆掉。这就是 4.8 表里「能过的 n」那一格写着「随机树」的原因。升级路径在 alg11：倍增 LCA 预处理 O(n log n)、单次 O(log n)，链状树也不怕；DFS 序 + ST 表是另一条路。选型规则简单到可以背：深度有保证（随机树、平衡树）朴素爬就够；深度没保证（链、菊花接链）上倍增。另一个小提醒：本单元的 parent[i] < i 约定让「根不是 0 号点」的树没法直接用——题目里根是任意点时，先做一次从根出发的遍历把父亲数组与深度算出来（用迭代栈而不是递归，理由见 2.8），再交给这套差分。

树上差分还有一个常考的搭档场景要分清：「子树整体加、单点查」。子树在 DFS 序上是一段连续区间（alg11 会专门讲），所以它根本不需要 LCA——进点时 +v、出点时 −v（或在 DFS 序区间端点做两次差分），收尾同样沿树累加。一句话分工：路径加找 LCA，子树加找 DFS 序；把两者混为一谈（给子树加也去求 LCA）是考场上真实的浪费时间。至于树上「路径加 + 路径查」这种两边都要的豪华需求，静态差分管不了，那是树链剖分与线段树的领地（alg13），这里先认出边界在哪就好。

竞赛代码里，一维前缀和日常就用 std::partial_sum——三行写完、语义直白、边界（哨兵格）由你自己控制。但两件事 STL 不替你管：类型（partial_sum 的结果类型跟着输出迭代器走，忘了开 long long 的 vector，溢出照旧）与二维的收尾（列方向那一步还是要自己写一行循环）。手写完全版（4.2、4.4 的 C 版）的价值在两处：赛场上没有你熟悉的模板头时要能白手起家；以及调试时能对「每一步为什么对」给出论证——应用层封装掉的恰好是这两样。代价另一面也说清：容器版多一层抽象（vector<vector<long long>> 的行指针跳转），本机实测与 C 版同在毫秒级，对拍规模下无感——先选写得对的，再谈跑得快的。

std::partial_sum 还有一个第四参数的形态值得认识：std::partial_sum(first, last, out, binop) 用自定义二元运算替换默认的加法——传 std::multiplies<>() 就是前缀积，传 std::bit_xor<>() 就是前缀异或（4.2 说的「前缀一族」在 STL 里共用同一个函数，换的只是运算符）。本单元的对拍程序没有用它，因为对拍要的是「与 C 版同一张考卷」；日常写题时它是首选。反过来，差分没有 STL 对应物——d[l] += v; d[r+1] -= v 两行就是它的全部，包装成类反而遮住端点语义，手写两行是正解。最后提一句边界：partial_sum 的输出区间与输入区间不允许重叠（标准要求 out 不在 [first, last) 内），想「原地前缀和」就先拷一份或开带哨兵的新向量——本单元两处调用都写进了带哨兵的独立向量，顺手把这个坑绕开了。

表里最值得琢磨的一行是树上差分：它没有赢暴力。原因诚实地说：随机树的深度只有 24，朴素 LCA 爬祖先的步数与暴力逐点加同量级——这一局里 LCA 才是瓶颈，差分省下的「逐点」本来就便宜。差分的真正优势有两处：记账便宜且可推迟（每条路径只写 4 个格子，什么时候想看覆盖次数，一次 O(n) 收尾随叫随到；暴力是「每加一条路径就必须动整条路径」）；以及换掉 LCA 就换掉瓶颈——朴素爬祖先换成倍增（alg11 的内容），单次路径加降到 O(log n)，链状树上那 40 ns 会变成 1000 倍的差距。

拿到题先做三步再选工具：认操作——题面要的是「区间和」（查得多）还是「区间加」（改得多），还是两者都要？只要其一，本单元的表直接给出工具与能过的规模；两个都要，记下边界（静态差分 + 一次还原管不了「加一笔查一笔」，那是 alg12 树状数组的信号）。算类型——把「元素最大值 × 个数」与「区间加次数 × v 上界」两个乘积算出来，任何一个越过 2e9，全链 long long（4.5 的三查）。估常数——查表第三列「能过的 n」，拿题面的 n 对一下；表里的实测耗时按 1 秒预算折算（比如二维矩形查 1e5 次实测 20 ms，意味着同样规模扩到 1e6 次也只有 0.2 秒，放宽心写）。三步做完还选不出来，就回到最笨的判据：先写暴力能拿的分拿到手，再按 4.3、4.4 的公式换正解——前缀和与差分恰恰是「换正解」成本最低的两类算法，因为它们不动主体逻辑，只换记账方式。

再把前两行的差距读出味道来：一维区间查单次约 1 ns，二维矩形查约 9–11 ns，差的不是公式（都只是两四次访存加减），是访存模式——一维的 pre 是 8 MB 的连续数组，随机两次读大多落进缓存；二维的表同样 8 MB，但一次查询要跳四行（S[r2+1][...]、S[r1][...] 相隔近千列），四条访存的局部性更差。复杂度同为 O(1)，常数差一个量级——这就是 alg01 说的「缓存友好」在真实数据上的样子。还有一行反直觉的对照值得记：差分的区间加（单次约 2 ns）比前缀和的区间查（约 1 ns）还慢一点点，因为它是两次写（写比读贵，还可能撞缓存行）；而暴力区间加同规模要 0.2–0.3 s——O(1) 与 O(区间长) 的差距，比任何常数纠结都大两个数量级。

看表选工具的口诀也在这三行里：区间和查得多、改得少 → 前缀和；区间加得多、最后才看一眼 → 差分；树上路径记账 → 树上差分 + 你写得起的最好 LCA。反过来，查询次数 q 很小（几十次）时别急着建表：1000×1000 网格、q=10，暴力约 2.5e6 次加法对建表 1e6 次——同量级，暴力省下 8 MB 与一次 O(n²) 的等待；前缀和为「成千上万次查询」而生。空间账顺手记一笔：前缀表 (n+1)×(C+1) 个 long long（1000×1000 网格约 8 MB）、差分表 n+1 格、树上差分 cnt 数组 n 格——全在 256 MB 限制内绰绰有余，本单元唯一要盯的空间不是这些表，是 4.5 那句「类型别用错」。

小结这一节的要点
  • 前缀和与差分是同一根骨头的两面：前缀和把「区间和」变成两次减法，差分把「区间加」变成两次单点改；互相还原靠的都是「望远镜求和」——中间项两两抵消；
  • 哨兵是边界的朋友：pre[0] = 0 免掉 l=0 特判，二维的第 0 行/列免掉边界 if，差分数组开 n+1 格是为尾区间的 d[r+1]；
  • 二维容斥两条公式符号正好相反：建表「+上+左−左上+本格」（左上被加两次要减），查询「−上−左+左上」（左上被减两次要加）；写反时差值恰好是重复那块的两倍；
  • 前缀和的值一律 long long：1e6 个 1e9 元素前缀和约 9.5e14，int 第 3 个元素就回绕；溢出是未定义行为，本机 -ftrapv 构建当场中止（退出码 3221226505）；
  • 树上点差分四笔账：cnt[u]++、cnt[v]++、cnt[lca]--、LCA 非根时 cnt[parent[lca]]--（根上多 1 靠跳过吸收）；沿树累加（子树和）之后才是覆盖次数，忘了累加读到的是差分原样；
  • 树上差分的瓶颈在 LCA：随机树上朴素爬祖先与暴力打平（各 4 ms），换倍增 LCA 才能在大深度上拉开差距（alg11）；

注自测题答案
  1. 展开后是 (a[0]+…+a[r]) - (a[0]+…+a[l-1])：下标 0 到 l−1 的每一项在两个前缀里各出现一次，相减时两两抵消，剩下 a[l..r]。pre[0] 是「空前缀的和 = 0」这条定义的落点——没有它，l = 0 时 pre[l] 没有合法含义，公式要加 if (l == 0) 特判；有了它，任何闭区间都是同一行减法。
  2. 建表时「上块 + 左块」把左上小块盖了两次，−S[i-1][j-1] 是把重复的那次减掉（再补上谁都没盖到的本格）；查询时「整块 − 上条 − 左条」把左上小块减了两次，+S[r1][c1] 是把它加回来。写反成 −S[r1][c1]，答案比真值恰好少 2 倍左上角的值（该 +1 的地方成了 −1，差 2）。
  3. 还原数组 = 差分的前缀和。d[l] += v 使还原后 l 及以后每格多 v；d[r+1] -= v 使 r+1 及以后再少回 v——两笔叠加，只有 [l, r] 净多 v。r 是最后一个元素时 d[r+1] 就是第 n 格（0 基的哨兵格），所以差分数组要开 n+1 格；少开一格，这次 -= v 会写到数组外的内存，症状是结果时对时错、加打印就变好（2.6 的越界现场）。
  4. 那一笔负责「把两条链在 LCA 之上多出来的部分抵消掉」：u、v 的两个 +1 各自沿着到根的链向上流（累加时子树和逐层上送），不减父(LCA) 的话，LCA 的所有祖先的子树和都会多 1。LCA 是根时 parent[root] 还是根自己（根自指），照写等于在根上多减一次——整棵树每个点的覆盖次数都错 1（通常全部变成 0 或负数）。代码里的 if (a != 0) cnt[t->parent[a]]--; 就是处理：LCA 是根时跳过这一笔。
  5. 选差分（区间加多、最后才看一眼：2e5 次区间加每次 O(1)，收尾一次 O(n)）。两个决策：其一，累计类型——元素 ≤ 1e9 但区间加可以叠 2e5 次，中途和最大约 2e14，差分数组、还原累加变量、输出值都必须 long long；其二，差分数组开 n+1 格（右端点贴尾时 d[r+1] 是第 n 格），别按 n 开。
  6. 前缀异或的「减法」天然成立：pre[i] = pre[i-1] ^ a[i] 之后，区间 [l, r] 的异或是 pre[r+1] ^ pre[l]——因为 x ^ x = 0，相同的项两两抵消（异或里「抵消」就是「出现偶数次」），不需要也不能用减法。工具分工：「子树加、单点查」走 DFS 序把子树变成一段区间，用普通一维差分即可，不需要 LCA；「路径加、单点查」才需要树上点差分配合 LCA（本单元 4.6），两者混用是常见的时间浪费。
