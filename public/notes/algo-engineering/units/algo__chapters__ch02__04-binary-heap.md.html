2.1 先看工程长什么样：三个例子，各配一份清单

堆只有两个动作——「新来的往上浮」和「补位的往下沉」——但它赛场上有一半的坑不在动作里，在下标里：0 基还是 1 基、右孩子存在不存在、堆空怎么回答、删除怎么实现。照本书的规矩，先看文件。

大白话这一节想让你先建立一个画面

把堆想成一棵只允许「最后一层缺右边」的树，按层序住进数组：最优先的那个永远坐在树根，也就是数组的第一个格子；任何人找父亲、找孩子都不用存指针，用下标一算就有。

  • 「谁最优先」＝ 看 a[0]，一步就到；
  • 「插入」＝ 新元素放到数组末尾，跟父亲比，输了就往上搬一格；
  • 「弹出」＝ 拿走 a[0]，末尾那个搬到根，跟孩子比，输了就往下搬一格。

整个二叉堆就是这三件事。后面所有技巧（建堆、懒删除、多路归并）全是在这两条搬运规则上省次数。

第 1 帧是动笔前的样子：栈、单调队列与并查集的工程已经在 ch02 里。第 2 帧是本单元的三个例子，分工很清楚：heap_build 量「建堆与逐个插入到底差多少」，lazy_delete 解决「堆怎么删元素」，heap_pq_compare 把手写堆与 std::priority_queue 放在一起对拍。第 3 帧是三份清单——没有它们，正文里的输出就没人对账。

2.2 一句话说清：堆在维护什么

一句话：它维护一个「只关心最值」的集合——任何时候问「谁最大」，a[0] 一步回答；插入、弹出都只花 O(log n)。 注意它不承诺别的：想找「第二大」没有一步的做法，想随手删除中间某个元素更是它的短板——2.6 会给你一个补救办法。

heap_t 里唯一「不是堆的功能」的字段是 swaps——它是本单元的仪器：把「建堆」和「逐个插入」各自搬动元素的次数分开记账，2.5 的实验全靠它说话。heap_ok 是校验器，检查堆序不变式是否处处成立。

返回值的约定也值得在接口层面就看清，因为三个工程的答案并不整齐划一：heap_pop 用「1 成功 / 0 堆空」，heap_push 用「正常返回累计交换数 / 堆满 -1」，lq_push 用「0 成功 / -1 堆满」。没有哪条标准规定这些数字——这是每个工程自己立的规矩，所以它必须写在头文件注释里，接手的人才不会把 -1 当成「交换了负数次」。你在赛场上抄模板时，第一件事就是把这类约定改成自己顺手且统一的版本；改的代价远小于把返回值看错的代价。

语法规则语法规则：数组表示的三条约定
  1. 下标从 0 开始：a[0] 是根，也是最大值（大根堆）。左孩子是 2i+1、右孩子是 2i+2、父亲是 (i-1)/2——三条式子全靠整数除法的下取整，不需要任何额外存储。
  2. 堆序不变式：每个父亲都不小于它的孩子（对所有 i ≥ 1 有 a[(i-1)/2] >= a[i]）。注意有序的只有父子这一条边，兄弟之间、两棵子树之间没有任何承诺——这是堆和「排好序的数组」的本质区别。
  3. 右孩子不一定存在：2i+2 可能越过 n。所以进循环先看 2i+1 < n（左孩子在），挑孩子前再看 child+1 < n（右孩子在才比较）。

第 1 帧的十个数不是编的，是 heap_build 在 n=10 的固定随机数据上建堆之后打出来的真实数组（2.5 的 output 里那一行）；画成树就能看出「父亲都不小于孩子」这个形状。第 2 帧把三条式子贴到具体下标上：a[4] 的父亲 (4-1)/2 = 1，正是 a[1]。第 3 帧解释「完全」二字为什么不能少：只有中间不留空位，下标换算才成立；普通二叉树东缺一块西缺一块，只能老老实实存指针。

(i-1)/2 里的下取整值得亲手验一次，因为它是三条式子里唯一让人不安的：奇数下标是左孩子、偶数下标是右孩子，同一个式子要同时罩住两种情况。拿第 1 帧的数据验：a[5]（奇数，左孩子）的父亲是 4/2 = 2，对；a[6]（偶数，右孩子）的父亲是 5/2 = 2（下取整），也对——右孩子的下标是 2i+2，减一再除以二正好是 i + 0.5，下取整把它拉回 i。三条式子在任何下标上都自洽，你不需要第二个公式。

大白话大白话：堆和排好序的数组，各赢了什么

把「最值在手」这个需求放在天平上。有序数组：问最值一步，问「第二大」也一步，还能二分，但插一个新元素要挪后面一整段，平均 O(n)。堆：插入、弹出都只要 O(log n)，可除了最值，问别的都要自己想办法——它把全部聪明都花在「最值」这一件事上。所以选择题很简单：数据只进不出、反复取最值，用堆；建好之后还要反复随机查询，先排序。 堆是「最值专业户」，不是「缩小版的排序」。

「只关心最值」这个限制不是缺陷，恰恰是它 O(log n) 的全部来源：正因为不用管兄弟之间谁大谁小、不用管中间元素怎么排，插入才只需要在「根到叶子」这一条路上做修理，其他任何位置纹丝不动。后面学的树状数组、线段树都在算同一笔账——维护的东西越少，单步越便宜；堆是这条原则最便宜的版本，连「孩子之间的顺序」都不要。

2.3 上浮与下沉：堆怎么修理自己

两条搬运规则各是一个小循环。先看下沉：

下沉的循环不变式：每一轮开始时，以 i 为根的那棵子树里，除 i 自己外处处满足堆序。循环只做一件事：把 i 跟它较大的孩子换（要挑较大的那个——换小的会把大孩子留在下面压着刚沉下来的数，堆序当场就破），换完 i 落到孩子位置，不变式对新的 i 依然成立。三个出口：没有孩子（沉到底）、孩子不比它大（站对了）、否则换。

再看上浮：

上浮只跟父亲一个人比。为什么不看叔叔伯伯？因为堆序只约束父子这条边，父亲那一侧的兄弟子树跟它毫无交集——把父亲换上来就修好了这一段，父亲自己的堆序由下一轮负责。

两个循环各有一个容易忽略的边界。上浮的循环条件是 i > 0：新元素落在叶子，若父亲本来就不小于它，一次都不换——插进堆里最便宜的就是小元素，它落下的位置可能一步都不用动。下沉的第一个条件 2*i+1 < h->n：叶子根本进不了循环，所以对叶子调用 sift_down 是安全的，也是免费的（2.4 的建堆正要靠这一点）。再看一个「挑错孩子」的反例：假设某父亲是 10，两个孩子是 9 和 8——你跟 8 交换，9 变成 8 的孩子，父亲 8 < 孩子 9，堆序在你亲手换完的那一格就被破坏了；跟较大的孩子换，被换下去的数落到的位置，下面没有任何一个数比它大，这一步才真正「修好」。

为什么这样修出来的堆顶就是最大值？ 反证：设最大值在 a[i] 且 i ≥ 1。堆序不变式给出 a[(i-1)/2] ≥ a[i]，沿父链一步步上去，每一步祖先都不小于它，于是 a[0] ≥ a[i]——最大值同时也在根上，与「不在 a[0]」矛盾。同理，弹出时每次拿走的都是当时活着的元素里最大的一个，弹出序列天然一路降序。

heap_ok 为什么敢只查父子这一条边？因为堆序有传递性：若每个父亲都不小于孩子，沿任何一条从根往下的路径，数值单调不增——查完全部 n-1 条父子边，就等于查了所有路径。它不直接查「根是不是最大」这种表象，查的是不变式本身：不变式成立，最大值在根上是推论，不用单独验证。这也是你赛场上自测堆的最便宜手段——三行循环，n=1e6 也就几毫秒。

分工到这里齐了：push 只用上浮，pop 只用下沉，Floyd 建堆只用下沉，2.6 懒删除的 remove_top 也是下沉——上浮管「新来的」，下沉管「补位的」，写模板时把这两个函数写对，堆的全部操作都是从它们俩拼出来的。

2.4 建堆：从最后一个非叶子倒着修

逐个插入能把堆建起来（2.5 有一半戏份在这），但手头已经有一整批数据时，有更省的修法：

为什么从 n/2-1 开始、为什么倒着走？ 这是一条归纳论证：

  • 归纳基例：下标 n/2 .. n-1 是叶子，单个节点天生的合法堆；
  • 归纳步：处理 i 时，它的两棵子树（下标都大于 i）已经处理完，是堆——这正是下沉的前置条件「除根外子树是堆」；sift_down(i) 修完，以 i 为根的子树整体是堆；
  • 归纳收口：i 走到 0，整棵树是堆。

正着扫不行——这不是「风格问题」，是能造出四元素反例的硬错误。取数组 [3, 1, 2, 4]：正着扫，i=0 时它的两个孩子是 1 和 2，都比 3 小，一次不换；i=1 时它的孩子是 4，4 > 1，换——数组变成 [3, 4, 2, 1]。此时检查堆序：a[0]=3 < a[1]=4，不是堆。坏在哪？节点 0 已经「处理过」了，可它当时看到的子树还没修好，4 是后来才被顶上来的，没有任何人回头再修一次。同一份数据倒着扫：先修 i=1（4 上来），再修 i=0（4 再上一层），得到 [4, 3, 2, 1]，是堆。归纳的前置条件就是「先修孩子再修父亲」，倒着走不是习惯，是论证本身。

为什么是 O(n)？逐层求和。 高度为 h（到最深的叶子要走 h 步）的节点最多 ⌈n/2^(h+1)⌉ 个，每个下沉最多换 h 次。总交换次数的上界：

Σ_(h≥1) ⌈n/2^(h+1)⌉ · h ≤ n · Σ_(h≥1) h/2^(h+1) = n

最后那个级数恰好收敛到 1（它是 Σ h·x^h = x/(1-x)² 在 x=1/2 的值再除以 2）。所以建堆的交换次数不超过 n——2.5 会看到升序数据实测 999988 次，正好压在这条界下面。

大白话大白话：为什么建堆这么便宜

把树按高度分层看：一半的节点是叶子，一次都不用搬；四分之一住在高度 1，最多搬 1 次；八分之一住在高度 2，最多搬 2 次……每一层「人数」乘以「最多搬几次」加起来，是 n × (1/4 + 2/8 + 3/16 + …)，括号里加出来正好是 1。绝大多数节点住在低层、根本没什么可搬，贵的是稀稀拉拉住在顶部的那一小撮。逐个插入就不同了：后插入的元素可能要一路浮到顶，而顶部恰恰是每一次插入都可能去的地方。

选择标准随之而来。 数据已经整批在手（读完了、要重建、要一次性处理），用 Floyd 建堆；数据是流式的（边读边处理、随时要查最值），只能逐个插入——「先攒一批再建」在交互式的问题里根本不存在。赛场上最常见的还是前者：读完全部数据、一次建堆、然后弹 k 次，这正是「求前 k 小/大」的标准姿势，2.8 会把它展开成套路。

其二，升序数据才见真章：18.0 倍。 升序插入的上浮次数可以精确算出来：第 i+1 个元素落在下标 i 的叶子上，深度是 ⌊log₂(i+1)⌋，它又比堆里所有数大，所以一次不少全浮到根——上浮次数恰好是 ⌊log₂(i+1)⌋。n=10 手算：0 上浮 0 次、1 和 2 各 1 次、3 到 6 各 2 次、7 到 9 各 3 次，合计 19，与 output 里「n=10：逐个插入交换 19 次」一字不差；求和 Σ_(k=1..n) ⌊log₂k⌋ 在 n=1000000 时等于 17951445，与实测一字不差。O(n log n) 不是修辞，就是这三个数。

其三，建堆这边撞到上界。 升序数据让每个非叶子都要沉到自己子树的最深处，把 2.4 的上界填得满满的：n=1e6 实测 999988 次交换，小于但贴近 1000000——建堆 O(n) 里那个 n 看得见摸得着。顺带看随机那列：743635 次，也在 n 的量级附近——建堆的 O(n) 在两种分布上都不骗人，骗人的只是「插入在随机数据上显得不慢」。

为什么数交换次数，不数比较次数？ 因为比较次数两边都带系数：下沉一层要先比两个挑大的（最多 2 次）、再跟自己比（1 次），上浮一层 1 次——比较次数大约是交换次数的一到三倍，趋势一致但噪音大。交换次数是「搬运」的真实代价，也是两种建法差异最干净的读数。这也解释了实验框里那句话：耗时上随机插入和升序插入几乎一样（比较占主导），把两者区分开的是交换次数，不是毫秒数。

这套实验自己也有纪律，四条都能在你自己的实验里复用。其一，数据完全确定：随机数来自固定种子的 LCG，今天跑和明天跑、这台机器和那台机器，交换次数一个字都不差——所以它有资格进 stdout 被闸门逐字对账。其二，结论双保险：每轮跑完都查堆性质、查弹出序列降序，交换次数这个「读数」作不了假，因为正确的结构才产得出正确的读数。其三，分布要成对出现：随机与升序各测一遍，一个回答「平均怎样」，一个回答「最坏怎样」，缺一个结论都立不住。其四，stdout 与 stderr 分家：确定的量（次数、倍数）进 stdout，抖动的量（毫秒）进 stderr——不然输出对账天天失败，你会烦到把耗时删掉，然后忘掉它。

陷阱你怎么会被坑到：拿随机数据给 O(n log n) 定罪

（你会看到什么）写完两种建法，随手生成一列随机数据一测：1.7 倍。你顺手写下结论：「建堆的 O(n) 没多大用，插入也就慢一点点。」（你会怎么误判）你会以为自己的实测推翻了教科书——毕竟数字是你亲手跑出来的，1.7 倍明明白白。（真相）O(n log n) 说的是最坏情形；随机插入的期望上浮距离本来就是 O(1)，随机数据只能测出「平均」，测不出「最坏」。要看到教科书说的差距，得喂它最坏的数据：每个新元素都比堆里所有数大——升序数据就是。同一份工程，换一列数据，1.7 倍变成 18.0 倍。规矩只有一条：复杂度结论要用它最坏的那类数据去验证，随机数据只配回答「平均怎样」。

均摊这笔账可以再算细一点，因为它和 alg01 讲过的 vector 扩容是同一个记账法：丢条目这个动作只发生在 top/pop 里，每丢一个记一步；一个条目从压入到被丢，至多付一次。所以「丢条目」的总步数 ≤ 总压入数，把它平摊到每一次 top/pop 头上，每次只多背一个 O(1) 的常数——均摊复杂度仍然是 O(log n)，没有隐藏的坏情况。erase 是真的一行赋值，O(1) 是字面意义的。

大跑一笔自洽的账：n=1000000（id 空间 300000）压入 666454 个，弹光时真弹出 220194 个、丢过期条目 446260 个——220194 + 446260 = 666454，一个不多一个不少；弹光得校验和 580119。耗时（stderr perf 行）：push 加 erase 10.0ms、弹光 57–61ms。对照组暴力版一次操作 O(n)，n=20000 就要 484–506ms——按这个单价跑到 1e6 次操作是万倍以上的代价，直接出局。

懒删除的软肋也看得见：erase 只记账、从不清理。如果一场操作里 erase 远多于 top（反复作废却很少取最值），堆里会积压大量过期条目：内存被死条目占着，top 的第一趟也要多丢几步。工程上的补丁是定期重建——当过期条目占比过半，就把堆整个弹出来、只留活条目、一次 Floyd 建堆装回去：重建 O(n)，摊到「积压的那一批 erase」头上仍是 O(1) 均摊。本单元的例子没做这个阀门（赛题操作数有限，不至于爆），但你该知道它装在哪、什么时候拧。

再跟「索引堆」比一下，看清懒删除在工具箱里的位置：索引堆额外维护「id → 堆内下标」的映射，erase 真的把那个条目从堆里拿走，还能支持改键、随时读任意一个元素——代价是堆里每一次交换都要同步改映射，常数翻倍、代码长一倍。赛题只需要「作废 + 取最值」时，懒删除是更便宜的那一版；要反复修改同一个元素（Dijkstra 的 decrease-key 是典型）时，才值得上索引堆——而 Dijkstra 自己用懒删除（把改小的点重复入堆、出堆的点作废）恰恰就能免掉 decrease-key，两句话不矛盾：懒删除让 Dijkstra 不再需要 decrease-key，索引堆留给真要做 decrease-key 的题。

陷阱你怎么会被坑到：把 erase 当成「拿掉，回头还能再放回来」

（你会看到什么）你把 erase(id) 理解成「这个元素先挪出去，之后我还要 push 回来」。于是同一个 id 先 erase 再 push——程序不报错、样例也过，但之后所有的 top 都看不见这个 id 的新条目。（你会怎么误判）怀疑 push 写坏了，或者怀疑堆序被搞乱，翻来覆去检查上浮下沉。（真相）dead[id]=1 是永久记账，没有「复活」操作；再 push 的条目 id 还是那个，堆顶一看见就把它当过期条目丢掉。这个语义是刻意选的——它对应「出过堆的点不再入堆」（Dijkstra 正是如此），写在头文件注释里。要「删了还能回来」，得换索引堆，或者每次换一个新 id。还有一条相邻的坑：lq_size 返回的是堆内条目数（含过期条目），不是活元素个数——拿它判断「队里还有几个人」会数多。

2.8 多路归并：堆里只放 k 个队首

堆最常见的出场方式是当零件。第一个套路：k 个已排好序的序列，合成一个有序序列（合并多个有序文件、合并多条有序链表）。逐个「挑全局最小」的暴力是每步 O(k)、共 N 步 O(Nk)；用堆把它压到 O(N log k)：

  1. 堆里只放 k 个候选——每个序列的队首；
  2. 每次弹出候选里最小的，输出，并把弹出者所在序列的下一个元素压进堆；
  3. 堆里永远最多 k 个，共 N 次弹出、N 次压入，单次 O(log k)。

第 1 帧是开局：三条队列的队首 (1,乙) (2,甲) (3,丙) 组成候选堆——图里的数字是示意，不是实测。第 2 帧弹出 1，输出它，乙队的下一个 4 补进候选堆。第 3 帧再弹 2，甲队的 9 补进——如此往复，堆里始终保持「每队至多一个代表」。

为什么全局最小一定在候选里？ 反证：设某轮全局最小 x 不在候选中，x 在某序列队首 y 的后面；序列有序给出 y ≤ x，而 y 在候选里。若 y < x，与「x 是全局最小」矛盾；若 y = x，则 x 也在候选中。两种情况都推翻「不在候选中」，所以每轮从候选里弹出的就是全局最小。

这个套路的最大用户是外排序：文件大到内存装不下时，分块读入、每块排序后写盘，再对磁盘上的 k 个有序块做一次 k 路归并——k 由「内存里能同时开多少输入缓冲」决定，堆把每一步「从 k 个块头挑最小」压到 O(log k)。k 通常只有几十到几千，log k 小到可以当作常数；总代价 O(N log k) 里的 N 才是大头。

第二个套路：流式求前 k 小（或前 k 大）。 数据一条一条来，你只要「目前最小的 k 个」：用大根堆装 k 个候选，新元素先跟堆顶比——比堆顶还大就扔掉（它进不了前 k 小），否则压入、再把堆顶弹出，堆里永远恰好 k 个。直觉先建立起来：求 k 小反而用大根堆，因为新元素需要一条「入场线」——就是 k 个候选里最差的那个；大根堆一步给出它。总代价 O(N log k)、内存 O(k)：k=1e5、N=1e7 也跑得动。求前 k 大就是镜像：小根堆装 k 个候选，堆顶是「k 个里最差的」。注意它跟排序求前 k 的区别：排序要先看完全部数据，堆是流式的——来一个判一个，数据没到头也能随时回答「目前的前 k 个」。

第三个套路：对顶堆求动态中位数。 数据流随时插入、随时问中位数。直觉：把数据从中间豁开成两半，中位数就是两半交界处那两个值——只要能一步拿到这两个值，就不需要排序。做法：小的一半装进大根堆（堆顶是较小一半的最大值），大的一半装进小根堆（堆顶是较大一半的最小值），两堆大小始终只差一。插入时按大小进该进的堆，如果两堆大小差超过一，把一个堆顶搬到另一边——每次搬运 O(log n)。查询中位数就是较大那半的堆顶（两堆等大时取两堆顶的平均）。为什么对？大根堆里所有数都 ≤ 它的堆顶 ≤ 小根堆里所有数 ≥ 它的堆顶——两个堆顶恰好是「整个数据集从小到大排在正中间」的那一两个位置，这是由「两半的划分规则」直接保证的，不需要额外验证。

候选怎么比较？ 候选是「值 + 来源序号」，比较规则就是 2.6 的 (key, id) 字典序、2.7 的 pair 比较——value 相同时谁先出由来源序号定，弹出的顺序因此完全确定。这个单元没有为归并单独立工程：它是「把堆当零件」的用法示范，工程化留给你在场上的模板里。

两个边界情形写代码时要想到。其一，某条序列耗尽了：它的队首不再入堆，堆里候选少于 k 个，算法照样工作——弹到堆空为止，输出就是全部；所以循环的终止条件是「堆非空」，不是「弹了 k 次」。其二，同值条目的顺序：候选带来源序号，value 相同时来源序号小的先出——如果每个来源内部的相对顺序保住了，归并出来的全序对「来源顺序」也是稳定的（相同 value 按来源编号依次出）。这不需要你做任何额外的事，是 (key, id) 比较规则白送的性质；反过来说，如果你的候选不带序号（只放裸值），同值条目谁先谁后就取决于堆内部的交换路径了——输出不再可复现，调试时会很痛苦。

陷阱你怎么会被坑到：0 基与 1 基换算混用

（你会看到什么）教材里的堆常按 1 基写：i 的孩子是 2i 与 2i+1，父亲是 i/2；本书的工程全部按 0 基：2i+1、2i+2、(i-1)/2。两套各自自洽，抄模板的时候左边抄一句 1 基、右边抄一句 0 基，编译照样通过。（你会怎么误判）小数据全对——因为第一处错位往往落在很靠后的下标上，n=10 根本走不到；一上 1e5 就开始「偶尔」答案错。（真相）两套换算差的正是同一位移：0 基的下标整体比 1 基小 1，孩子、父亲的公式全跟着错一位。修法：约定写进头文件注释（heap_build.h 开头两行就是），整个文件只用一套；题目给 1..n 就在读入时统一减一，或数组整体多开一格。跟并查集那节的下标混用是同一类病，解法也一样。

边界与溢出的清单（每个都来自例子工程里真实写着的判断）：

  • 容量与空堆：heap_init 对 cap ≤ 0 返回 -1；heap_push 对堆满返回 -1，调用方要接——main.c 里 insert_ok = (insert_swaps >= 0) && ... 就是在接它；heap_pop 对空堆返回 0 不崩；lq_top 空堆返回 0；
  • 右孩子的存在性：sift_down 先判 2i+1 < n 再判 child+1 < n，两个条件各挡一个越界，省掉任何一个都会读到别人家的内存；
  • 计数与键值的宽度：交换计数与 key 都用 long long。本单元最大的计数 17951445 其实 int 也装得下，但记账字段没有理由省成 int——赛场上 key 动辄 1e9 量级还要相加，一处溢出全盘皆输；
  • 下标本身的溢出：2*i+1 里的 2*i 在 n 逼近 2^30 时会溢出 int（负下标）。本单元 n ≤ 1e6 安全；写通用模板时把下标换成 size_t——heap_pq_compare 的 HandHeap 就是这么写的（sift_up(std::size_t i)）；
  • 递归深度：sift 的深度只有 ⌊log₂n⌋ ≈ 20 层，递归写法不会爆栈——这与并查集「深度等于链长」的风险完全不同。但两个 C 例子全用循环：零递归、单步打断点容易，你也少背一条「栈还够不够」的心事。

最后回答一遍「这题该不该上堆」。题面特征对着工具选，别一上来就排序：

题面在问什么 该用什么 理由
反复「取最值」+ 随时插入 堆（默认 priority_queue） 单次 O(log n)，接口刚好够
一次性数据，只要静态答案（排序、一次最值） 排序或一次线性扫描 堆的动态性用不上，白付 log n
流式数据，只要「前 k 小/大」 大/小根堆限长 k（2.8 套路二） O(N log k)，内存 O(k)
k 个有序来源轮流取 k 路归并（2.8 套路一） 堆里只放 k 个队首
随时插、随时问中位数 对顶堆（2.8 套路三） 两个堆顶卡住正中间
删除某个指定元素 懒删除（2.6）或 multiset 堆本身做不到 O(log n) 删指定元素

堆从来不是「万能容器」，它是一笔交易：用 O(log n) 的单步，换掉每次 O(n) 的重排。你的操作序列里取最值的次数越多，这笔交易越划算；只取一两次，排序反而更便宜。

小结这一节的要点
  • 堆 = 完全二叉树按层序住进数组：0 基换算 2i+1 / 2i+2 / (i-1)/2；堆序不变式只有一句「父亲 ≥ 孩子」，兄弟之间无承诺；只有完全二叉树可以这样存；
  • 上浮只跟父亲比，下沉挑较大的孩子（左孩子在才进循环、右孩子在才比较）；弹出 = 记下 a[0]、末元素补位、下沉修复；堆顶最大由堆序不变式反证而得；
  • 建堆从 n/2-1 倒着下沉：叶子天生是堆，归纳可证整棵是堆；逐层求和给出交换次数 ≤ n（Σ h/2^(h+1) = 1），实测升序 999988 次正好压界——建堆是 O(n)；
  • 逐个插入的 O(n log n) 要在最坏数据上看：升序插入上浮 Σ⌊log₂i⌋ 次，n=1e6 时 17951445，与实测一字不差；随机数据只有 1.7 倍（均摊 1.28 次交换/元素）——复杂度结论用最坏数据验证；
  • 懒删除：erase 一行记账 O(1)，看堆顶才丢过期条目；每条目至多丢一次，top/pop 均摊 O(log n)；id 永久作废、lq_size 是条目数不是活元素数；软肋是只记账不清理，过期条目过半就全量重建；
  • std::priority_queue 默认大根堆，greater<T> 翻小根堆（三个模板参数写全），pair 先比 first 再比 second；空堆 top/pop 是未定义行为（本机 -O0 断言中止退出 3、-O2 访问违例 3221225477）；裸数组用 make_heap / push_heap / pop_heap，不必手写 sift；
  • 堆当零件的三个套路：k 路归并（堆里只放 k 个队首，O(N log k)）、流式前 k 小（大根堆限长 k，堆顶是入场线）、对顶堆（两堆顶卡住正中间的动态中位数）；候选的比较规则都是 (key, id) 字典序；
  • 两个 OK 200 由闸门真跑：懒删除堆对全量扫描（每步比堆顶+收尾弹光）、手写堆对 priority_queue（每步比 size+top）。

注自测题答案
  1. 左孩子 2i+1、右孩子 2i+2、父亲 (i-1)/2（整数除法下取整）。普通二叉树的节点分布有洞，层序抄进数组后下标不连续，2i+1 算出来的位置可能是空洞或别人的节点——换算失效，只能存指针。
  2. 2*i+1 < h->n 挡住「这个节点是叶子」（没有左孩子就不进循环）；child+1 < h->n 挡住「有左孩子但没有右孩子」（右孩子下标越界）。漏掉第二个，最后一个单独的左孩子会被拿来跟堆数组之外的那格内存比，比较结果随机，堆序被随机破坏。
  3. 归纳的前置条件决定的：处理 i 时要求「以 i 为根的子树除根外已是堆」，这需要两棵子树都先处理完——子树下标都大于 i，倒着走恰好满足。正着扫时孩子的堆还没修好，下沉的前置条件不成立，修完不保证是堆。
  4. 不能。O(n log n) 说的是最坏情形，随机插入的期望上浮距离是 O(1)（实测均摊 1.28 次交换/元素），随机数据只测出「平均」。要换「每个新元素都比堆里所有数大」的升序数据：插入上浮 Σ⌊log₂i⌋ 次，n=1e6 时 17951445 次，与建堆 999988 次差 18.0 倍——差距这才兑现。
  5. lq_size 返回堆里的条目数，含还没丢掉的过期条目，不是活元素个数——判「还剩几个活元素」会数多。erase 之后 id 永久作废（dead[id]=1 没有复活操作）：对同一 id 再 push 的条目，一到堆顶就被当过期条目丢掉，等于白压。要「删了能回来」，换索引堆或每次换新 id。
  6. std::priority_queue<int, std::vector<int>, std::greater<int>>——三个模板参数都得写：第二个是底层容器、第三个才是比较器。只写两个，greater<int> 会被当成容器类型，编不过。空堆 top() 是未定义行为：本机 -O0 下 libstdc++ 断言开着，打印 Assertion '!this->empty()' failed 并以退出码 3 中止；-O2 下断言关掉，解引用空 vector 的空指针，访问违例，退出码 3221225477（0xC0000005）。
