15.2 Dijkstra：出堆即定型，凭什么

先把问题本身钉准，后面四个算法才有的放矢。输入：一张有向图（无向图按 15.5 的规矩拆成两条有向边）G = (V, E)，边权 w(e) 可以是任意非负整数，一个源点 s。输出：数组 dist——dist[v] 是「从 s 走到 v 的所有路径里，边权总和的最小值」；v 不可达时约定 dist[v] = INF。附带产物：pre 数组（最短路树，15.5）。注意两个边界语义：dist[s] = 0（空路径也是路径）；「不可达」与「距离为 0」是两回事，所以 INF 必须是与任何真实距离都不可能混淆的值——这就是 15.4 要专门算 INF 算术的原因。本单元的四个算法输出的都是同一个 dist 数组，所以它们能在同一批随机图上逐点对拍：这是本单元工程形态的根基。

大白话先给一句直觉

Dijkstra 在维护一条「已经定案」的边界线：边界外的点距离还没定，边界内的点距离不可能再变好。每一轮，它从边界外挑一个「当前看起来最近」的点拉进边界——因为所有边权都非负，绕路只会更贵，所以这个点已经拿到了它的最终答案。整个算法就是「拉边界」这一件事重复 n 次。

现在把「出堆即定型」写成可证明的不变式。不变式：在第 k 轮结束时，已定型集合 S 里的每个点 v，其 dist[v] 都等于 s 到 v 的真实最短路；且边界外所有点的 dist 都不小于「只经过 S 内部」能达到的最短值。证明用归纳法：

  • 奠基：k=0 时 S 为空（或只有 s，dist[s]=0），平凡成立。
  • 归纳步：设第 k 轮前不变式成立。这一轮选出的 u 是「未定型点中 dist 最小」的。要证 dist[u] 已是真实最短路。反证：若存在一条更短的 s→u 路径 P，看 P 上第一个不属于 S 的点 v——P 走到 v 之前全在 S 里，所以 dist[v] 至多是「S 内的最优前缀 + 一条非负边」，即 dist[v] ≤ len(P 的前缀到 v)。而 P 的后半段（v 到 u）非负，所以 len(P) ≥ dist[v]。又因为 v 未定型且 dist[v] ≤ dist[u]（u 是未定型里最小的），推出 len(P) ≥ dist[v] ≥ dist[u]，与「P 更短」矛盾。所以 dist[u] 是真实值，定型它不破坏不变式。
  • 用到「非负」的位置：划线那一步——「P 的后半段非负，所以 len(P) ≥ 前缀到 v 的长」。有负权边时后半段可以越走越便宜，这个不等式塌掉，证明失效。这不是实现问题，是算法前提。

把整个算法换一个角度看，松弛其实是在维护一条三角不等式：终态时对所有边 (u,v) 都有 dist[v] ≤ dist[u] + w(u,v)，且至少有一个点的等号在每条最短路上成立。算法开始前不等式处处残缺（INF），每一次松弛就是补一处；补到不能再补，所有等号串起来就是最短路树。这个视角在 15.7 还会再用一次——Bellman-Ford 不挑点、全表松弛，就是「不挑补哪儿，反正每轮把所有缺口都补一遍」。

两版各自的生存空间也要说清。O(n²) 版不是废物：稠密图上它反而更快——m 接近 n² 时，堆版的 O(m log n) ≈ O(n² log n) 多了一个 log，而 O(n²) 版的松弛总量 O(m) 被全表扫描的 O(n²) 吞掉了，n=500 的稠密图上两者都是几十万次基本操作，O(n²) 版还少一堆堆操作的开销。所以赛场上「n≤3000 的稠密图」可以无脑 O(n²)，堆版留给「n 到 1e5、m 到 5e5」的稀疏大图（15.12 实测 13–19 ms）。还有一个小优化别忘：O(n²) 版第 25 行在「选出的最小值已是 INF」时直接 break——剩下的点全部不可达，再扫 n² 也是白扫。

那能不能「加个偏移量把负边抬正，再跑 Dijkstra」？这是考试里最常见的自作聪明，值得单独拆穿。给每条边加常数 C，一条 k 条边的路径总长增加 kC——路径边数不同，抬升量就不同，比较基准被扭曲：原图的最短路是 A（3 条边、总权 5）还是 B（7 条边、总权 6），加完偏移后答案取决于 C 的正负。只有两种情况偏移合法：题目保证所有路径边数相同（很少见），或者用 Bellman-Ford 先算一遍势函数 h(v)（Johnson 重加权，负权图全源的标准姿势，费用流里还会再见）——把每条边 (u,v) 改成 w + h(u) − h(v)，它对所有路径都等量变形。15.9 的对拍暴力用的正是「负权小图直接上 Floyd」而不是偏移，因为前者诚实。

大白话负权边在现实建模里是什么
  • 退款与返现：城市间的路费有正有负（某段铁路搞活动倒贴钱），「最便宜的走法」就是负权最短路；
  • 汇率与套利：把货币当点、汇率取 −log 当边权，负环就是「绕一圈钱变多」的印钞机——正因如此，外汇套利检测的教科书实现就是 Bellman-Ford 的负环判定；
  • 约束的矛盾：差分约束系统把「x ≤ y + c」全部化成边，无解的判定恰好是「图里有负环」。 所以负权不是出题人刁难你，它本身就是一类真实问题；Dijkstra 不管这个场景，Bellman-Ford 管。
陷阱你怎么会被坑到：样例过了，就以为 Dijkstra 能吃负权边

你会看到：本地测试全对，包括几组带负权的——因为你的实现恰好是「懒删除堆」版，负边更新会重新入堆，小图上它总能把答案修正回来。你会怎么误判：既然跑出来是对的，说明 Dijkstra 也能处理负权，「前提」是教材吓唬人的。真相是：这版算法在负权图上等价于一个标签修正算法，答案常常对，复杂度没有保证，且存在让它答错的数据（vis 版在 3 个点的小图上就错了）。而你在赛场上交的是哪一版，取决于你抄的模板——「测试过」证明不了任何事，这正是 alg02 反复强调的。判据是定理不是运行结果：归纳证明用的不等式在负权下不成立，前提破了，任何实现都不再背书。

两个设计决定值得停下来想一遍。为什么堆条目存 (dist, node) 二元组，而不只存 node？ 因为懒删除的核对靠的就是「堆里记的账」和「当前 dist」对不上：只存 node 的话，弹出时拿不到「当初报价多少」，无法判断过期，只能退化成「每个点第一次弹出就定型」（写 vis），那又回到了信仰路线——非负权下它其实也对，但代码里同时维护 vis 和 dist 两份状态，初学者十个有九个把两者的更新顺序写错。为什么弹出相等值（==）不跳过？ 并列最短的多条路都要参与松弛：dist[u] 相等的两次弹出，第二次照样可能把某个 dist[v] 修到更小（first 相等时松弛贡献相同的值，不冲突，但 pre 会被更新成后弹出的 u——两条并列路里取哪条都合法）。第 69 行写 > 不写 !=，就是这个道理。

陷阱你怎么会被坑到：忘了第 69 行的核对，或者把它写反

你会看到：图一大，程序明显变慢，图小的时候毫无异常。你会怎么误判：以为是自己手写堆写坏了，或者数据太刁钻。真相是：漏掉过期核对后，每份过期条目弹出时都会把整个邻接表白扫一遍——15.2 第 5 帧那次「扔掉」如果不扔，2→1、2→3 两条边就白松弛一次。债越滚越多，复杂度从 O(m log n) 掉向 O(m²)。还有一种更隐蔽的写反：核对条件写成 top.d < dist[u]) continue，把有效条目扔了、过期条目留下，dist 被旧值污染，答案静默变错。修法：核对只能是「堆里的值 大于 当前值就跳过」，相等要放行（可能有并列最短的多条路要松弛）。

INF 的选取是这一段另一个容易翻车的地方。本书的两种取法与它们的算术：

语法规则语法规则：两种 INF，两条算术
  • int 版：const int INF = 0x3f3f3f3f;（1061109567 ≈ 1.06e9）。它相加不溢出的算术：INF + INF = 2122219134 < 2147483647 = INT_MAX——正好压线。它是 int 上界 0x7fffffff 的约 49%，保证「两个 INF 相加一次」安全；但三次相加就爆（0x3f3f3f3f × 3 ≈ 3.18e9 > INT_MAX）。memset(dist, 0x3f, sizeof(dist)) 能用它，因为每个字节都是 0x3f，拼出来恰好是这个数。
  • long long 版（本书推荐）：#define DIJ_INF (LLONG_MAX / 4)，即 2305843009213693951 ≈ 2.3e18。取四分之一而不是一半，是为了给「INF + INF + w」这类算式留一倍余量：INF+INF ≈ 4.6e18，再加一条边权也远够不着 LLONG_MAX ≈ 9.2e18。
  • memset 陷阱：想用 memset 刷 long long 的 INF，得每个字节填 0x3f，得到 0x3f3f3f3f3f3f3f3f ≈ 4.55e18——它乘 2 也恰好不溢出，所以也是合法 INF；但 memset(dist, 0x7f, ...)（≈ 9.2e18，贴着上界）相加一次就溢出，不能当 INF。
陷阱你怎么会被坑到：INF + INF 自己溢出了

你会看到：某个「明明不连通」的点对，dist 被打成了一个巨大的负数或者奇怪的负值。你会怎么误判：松弛写错了，或者边读错了。真相是：在 Floyd 或 Bellman-Ford 里，dist[i][k] 和 dist[k][j] 可能同时是 INF，INF + INF 已经压线，如果这个和又被当作「新的 dist」存下来，下一轮它还会再和别的 INF 相加——两三轮之后就有符号溢出，负权图上尤其热闹（见 15.7 的守卫写法）。修法只有一条：相加前先判 INF（if (a >= INF || b >= INF) continue;），或者干脆用 long long 的 INF 给足余量。别把「判 INF」当成可有可无的优化，它是正确性的一部分。

15.7 Bellman-Ford：轮数的意义与负环判定

负权边的问题必须正面解决。Bellman-Ford 的前提放宽成「可以有负权边，但不允许有 s 可达的负环」——负环让「最短路」这个词本身失去定义（可以无限绕圈无限便宜），所以算法的第一职责是把这个情况检测出来，而不是硬算。输入输出与 Dijkstra 相同，复杂度 O(nm)、空间 O(n)，n、m 都到 1e5 的题它是坐不下的，它的存在意义是「负权 + 小图」与「负环判定」。

想法朴素到近乎笨拙：不挑点了，每轮把所有边都松弛一遍，重复 n-1 轮。它对得起来的不变式是：第 r 轮结束后，dist[v] 不超过「s 到 v、最多经过 r 条边」的最短走法。归纳：第 1 轮全表松弛后，所有「一条边直达」的 v 都被修到位；第 r 轮又把「r-1 条边最优 + 一条边」全部合并进来。而任何最短路最多只含 n-1 条边（更多必然重复点，重复点则有环，非负环可以去掉，负环直接见下一段），所以 n-1 轮必收敛：

15.9 Floyd：k 必须在最外层，不是习惯是定义

全源最短路（任意两点之间都要）用 Floyd：n³ 次加比，n² 个 long long 的矩阵，代码五行。前两个算法算「单源」（一个 s 到所有点），Floyd 把 n 个源点一次算完——前提是图不能有（任何点可达的）负环，负权边本身允许。它的正确性论证是所有最短路里最「DP」的一个，值得逐字读。设 dp[k][i][j] = 「从 i 到 j、中途只允许经过编号小于 k 的点作为中转」的最短路长。它有干净的递推：

  • 不经过 k：dp[k][i][j] = dp[k-1][i][j]；
  • 经过 k：路径拆成 i→k 与 k→j 两半，两半的中转点都还小于 k（k 只出现一次），所以 dp[k][i][j] = dp[k-1][i][k] + dp[k-1][k][j]。

15.10 0-1 BFS：边权只有 0 和 1 时，队列就够

大白话先给一句直觉

BFS 能求无权最短路，是因为「每一层往外走一步，代价都一样」。0/1 权图里代价只差一档：走 0 边等于「原地踏步进同层」，走 1 边才是「下一层」。于是队列两头分工——0 边的发现塞回队头（同层），1 边的发现排到队尾（下一层）——双端队列里任意时刻最多两个「价位」，弹出的距离天然不降。这就是 Dijkstra 的两个价位特例版，复杂度 O(n+m)。

把 0-1 BFS 放回谱系里看更清楚。全部边权为 1：它退化成普通 BFS（双端队列里永远只有一个价位，push_front 一次都不会发生）；全部边权为 0：同层无限扩张，等价于把连通块缩成一个点（并查集的活）；权重出现 0..k（k≥2）：双端队列的「两个价位」保不住了，需要 k+1 个桶的分段队列（0-1 BFS 的桶排序推广）或者直接堆优化 Dijkstra。所以 0-1 BFS 的生态位精确地卡在「权恰好是 0 和 1」上——网格图走迷宫（墙 = 1，空地 = 0）、开关翻转题（按一次开关 = 1）、状态机里「操作免费/收费一次」的题，见到这类边权就条件反射想到它。

陷阱你怎么会被坑到：把 0-1 BFS 的双端队列写成普通队列

你会看到：小图全对，稍大一点的图 dist 偏大几个单位。你会怎么误判：松弛条件写错，或者边权读入出错。真相是：普通队列里，权 0 的改进被压在「下一层」的一堆记录后面，弹出顺序不再按 dist 不降——Dijkstra 的选点规则被破坏，先弹出的「贵」记录会把 dist 抬高，后到的「便宜」修正又被已定型的判断（如果你写了 vis）挡住。判据：0/1 权图上，「队列」和「双端队列」的差别就是「BFS 的分层纪律」保不保得住；权超过 1（比如 0..k）就该换分段队列或直接堆优化 Dijkstra，别硬撑。

15.11 分层图最短路：把「状态」编进点号

有一类题的最短路带着附加状态：「最多免费搭 k 次航班」「剩余体力是多少」「已经用过几次传送门」。解法不是发明新算法，而是把状态折叠进点号：原图的点 v 复制成 k+1 份「层」，第 i 层的点 v 写成 i*n + v；「用一次免费机会」就是从第 i 层的 u 连一条边到第 i+1 层的 v。图变大 k 倍，然后原封不动地跑堆优化 Dijkstra 或 0-1 BFS——没有任何新算法，只有更大的图。

拿「最多免费搭 2 次航班」做个完整的建模示范。n 座城市、m 条航线（每条有权），点号 0..3n-1：第 0 层 0*n+v 是「还没用免费额度」的城市 v，第 1 层 1*n+v 是「用过 1 次」，第 2 层同理。层内连边：每条航线 (u,v,w) 在每一层内部各连一条（共 3m 条），代表「不免费地飞」；跨层连边：每条航线再从第 i 层的 u 连到第 i+1 层的 v，权 0（共 2m 条），代表「这一趟免费」。从 0*n+起点 跑一遍堆优化 Dijkstra，答案是 min(dist[0*n+t], dist[1*n+t], dist[2*n+t])——免费额度不必用完，所以要扫所有层的终点。写的时候三件事容易翻车：层内边权照抄、跨层边权按题意（免费边权 0、付费边权取原权）；dist 数组开 (k+1)×n，堆容量按「(k+1)×m」重新估，别拿原图的 m 去开数组；起点只进第 0 层（初始状态没用过额度），别把起点铺满所有层。

反向的教训也要记：不是所有「带状态的图」都值得分层——k 很大（比如状态是剩余金钱）时层数爆炸，那就该换 DP 或贪心，分层图只是「k 与 n 同量级」时的那把钥匙。判断标准一行：状态空间 = 原图点数 × 状态数，乘积仍在 1e5~1e6 量级才考虑分层。

分层图的亲戚是多源最短路：题目给 k 个起点，问每个点到它们的最近距离。别跑 k 遍 Dijkstra——加一个虚拟超源 s*，从 s* 向每个真起点连一条权 0 的边，然后从 s* 跑一遍单源，「多源」就折叠成了「单源」。这个虚拟点技巧和分层图一样，都属于「改图不改算法」：最短路算法一行不动，建模多想一步。反过来，全源问题（k = n 时）才轮到 15.9 的 Floyd 出场。

小结这一节的要点
  • Dijkstra 的合法性来自一条不变式：「已定型集合里的 dist 是真实最短路」，归纳证明里「路径后半段非负」不可删——负权边一进来，vis 版三个点的图就出错，堆版也只是侥幸；
  • 懒删除堆：改进入新账、旧账不删，弹出时 d > dist[u] 核对跳过；堆容量按 m+2 开；输出路径靠 pre[v] = u 回溯到起点再翻转，pre 必须初始化为 -1；
  • INF 用 LLONG_MAX/4（或 int 的 0x3f3f3f3f），一次「INF+INF」不溢出；但 Floyd/BF 里相加前必须判 INF，三次相加任何一种 INF 都会爆；
  • Bellman-Ford 第 r 轮 = 「最多 r 条边」的最短路，第 n 轮仍能松弛 = 可达负环；SPFA 用队列只松弛被更新的点，负环征兆是单点入队次数到 n；
  • SPFA 可被构造性反例钉死：枢纽点被拉低 k 次、每次全图重冲，实测出队 8000202 次（104 ms），同图 Dijkstra 40401 次（1–2 ms）——非负权一律 Dijkstra；
  • Floyd 的 dp[k][i][j] 是「中转点编号 < k」的最短路，两项必须都来自 k-1 层，所以 k 必须在最外层；本机 n=500 要 75 ms，天花板 n≈1500；
  • 0-1 BFS：权 0 头进同层、权 1 尾进下层，双端队列里最多两个价位；分层图把状态编进点号，原图算法原封不动地跑。

  4. 0x3f3f3f3f × 2 = 2122219134，距 INT_MAX = 2147483647 只剩约 2500 万——一次相加安全，第二次就爆。LLONG_MAX/4 让「INF+INF+w」仍有约 4.6e18 的余量；取 LLONG_MAX/2 时一次相加就贴上界，加任何正边权都溢出。
  5. 任何真最短路至多 n-1 条边（更多必有重复点，重复点成环，非负环可删）。第 n 轮检测到松弛说明存在「绕一圈更便宜」的可达负环，此时负环可达点的最短路是 -∞，dist 数组的有限值全部作废——先判负环，再谈距离。
  6. 递减报价保证 g00 的 dist 被严格拉低 k 次、每次都触发整张网格重冲（k 次改进 = k 遍全图松弛）。报价递增时 SPFA 一开始就拿到最差价、之后的报价没有一次是「改进」（后面的都比前面差），g00 只出队一次——卡不动了。这正是构造的机关：利用 SPFA「按队列顺序、改进即重排」的纪律。
  7. k 内层时读到的 mat[i][k] 是本层半成品，可能已混入「中转点 ≥ 当前 k」的路径，递推式「两项都来自 k-1 层」的前提被破坏；不变式没了，答案只能靠运气。j 递增时修正链恰好「先算的格子被后算的用到」，很多图碰对；j 递减时链方向反过来，同样的图就错——碰对与否取决于遍历方向，这正是没有定义保证的证据。
  8. 入队只发生在「严格变松」时：同价第二份需要 dist[v] 已等于该值还能再「变松」到它，矛盾。第三份意味着出现了三档同存，说明「弹出距离不降」的分层纪律已破——通常是容量推法写错（比如无脑 push 不判改进），本例的容量护栏（qcnt > cap 返回 -2）就是为这种 bug 预留的报警器。
