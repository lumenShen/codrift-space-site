11.1 先看工程长什么样

这一单元的东西看着散：整除、逆元、筛法、组合数、容斥、快速幂。但它们共用同一套工程骨架——每个例子都是「正解 + 暴力 + 对拍驱动」三个文件，而且每个结论都要被随机数据复核。所以照本书的规矩，先别背公式，先看文件。

大白话先把这一单元想成一台「整除计算器」

你手上有一把只能做整数除法、取余数和乘法的计算器。你想用它回答四件事：两数的最大公约数是多少；一个数在模意义下的倒数是多少；一百万以内有多少个质数；从 n 个东西里挑 k 个有多少种挑法。

这四件事看起来毫无关系，其实全都靠同一条线索串起来：整除关系可以被改写成等式，等式可以被放进循环里算。比如「a 是 b 的逆元」这句话改写成 a*x ≡ 1 (mod m)，就变成一个可以暴力验算的方程；「C(n,k)」改写成阶乘的乘除，就把除法换成逆元的乘法；「斐波那契第 n 项」改写成矩阵乘法，就把 n 步递推换成 log n 次平方。

这一单元要教的就是这套改写手艺。你不是在背模板，而是在学怎么把一句话翻译机器能算的式子。

第 1 帧是故事里的起点：ch11 这个目录本身已经有了别的例子，但属于本单元的一个都还没有。第 2 帧是最小的完整工程：numtheory.h 只放声明，exgcd_inverse.c 是正解，exgcd_inverse_brute.c 是故意写得笨但一眼能看出对的暴力版，main.c 负责造随机数据、跑两版、逐组比对。第 3 帧把同一套骨架复制到另外三个主题；第 4 帧补的是这本书的加码——两个性能工程各带一份真实终端会话，以及一个用 C++ STL 重写的应用层。

工程惯例工程惯例：为什么每个例子都要拆成三个文件

标准不管你把一个程序写成几个文件。这里固定拆三份，理由跟并查集那一单元一样：接口、实现、实验各占一处。头文件放函数声明与类型，读者看它就知道「这个例子能做什么」；正解源文件放算法本身，抄模板时只抄它；暴力源文件放在旁边，随时能拿来复核；main.c 是你可以随便改的实验台。

代价是要多写一个 #include，还要保证声明和定义不写拧。收益是：当你改了对拍驱动里的一行随机数种子，不会不小心碰到算法；当你怀疑正解有 bug，可以把 main.c 里的失败轮次原样拿出来单独复现。

11.2 模运算下的负数：先学会跟负数相处

这是最先要讲的小事，因为它会在后面每一个例子里冒出来。

大白话用大白话说取模

把取模想成一块钟面。模 12 的钟面上，15 点和 3 点是同一个位置，所以 15 % 12 是 3。负数也一样：往回拨 1 小时是 11 点，但 C 语言算 -1 % 12 给出的是 -1 而不是 11。

钟面告诉你「-1 和 11 是同一个位置」，C 的运算符只告诉你「我除完还剩 -1」。两者都对，只是口径不同。 ours 要的是钟面口径，也就是 0 到 m-1 之间的那个代表元。

语法规则语法规则：同余与规范化
  1. 同余：a ≡ b (mod m) 读作「a 与 b 模 m 同余」，意思是 m | (a-b)，也就是两者除以 m 余数相同。
  2. C 的 % 保留被除数的符号：-7 % 3 = -1，7 % -3 = 1。想拿到 [0,m) 的代表元，一律写 (a % m + m) % m。
  3. 模运算的四则：(a+b) % m = ((a%m)+(b%m)) % m；减法同理但要先规范；乘法 (a*b) % m = ((a%m)*(b%m)) % m。除法不是这样算的——模意义下的「除以 a」要用 a 的逆元，这正是 11.4 的内容。

模运算最容易被忽略的一点是：它是一套封闭的算术系统。两个 [0,m) 里的数相加、相乘，再取模，结果还在 [0,m) 里。你不需要大整数，也不需要分数，只需要会算余数和乘法。这就是为什么竞赛里几乎所有「答案很大」的题都要求取模——把无穷的整数压进一个有限的环里，机器才装得下。

不过「封闭」不等于「什么运算都能做」。加减乘都好办，除法就麻烦了：在普通算术里 a/b 是「乘 b 的倒数」，但模 m 的世界里没有分数这个东西。于是我们换一个定义：找一个 x 让 b*x ≡ 1 (mod m)，把 a/b 定义成 a*x。这个 x 就是逆元。注意这个定义本身就要求 x 存在，而它存在的条件（互质）在 11.4 才讲。

还有一个实操细节：每次乘法之后立刻取模，而不是攒到最后再取。因为两个小于 m 的数相乘最多是 (m-1)²，m 到 1e9 时就是 1e18，正好卡在 long long 的上限附近；如果连乘好几项不取模，中间量会爆掉。本单元的快速幂和矩阵乘法都在每一次乘法后取模，这不是保守，是必需。

看两个具体的取模例子，把口径钉死。第一个：模 7 下算 15 + 26。先各自取模得 1 和 5，相加得 6，所以结果是 6；直接算 41 再取模也是 6。第二个：模 7 下算 (-15) * 4。-15 % 7 = -1（C 的口径），直接乘得 -4，再规范化 (-4 % 7 + 7) % 7 = 3；如果先把 -15 规范成 6，6*4 % 7 = 24 % 7 = 3，结果一致。先规范再运算和先运算再规范都对，前提是别把 C 的负余数当成最终代表元。

为什么竞赛里几乎不用「减法逆元」？因为 a - b (mod m) 直接写成 (a - b + m) % m 就行，一次加法一次取模就够了；只有除法才必须找逆元。这个不对称值得记住：加减法是「免费的」，乘法便宜，除法最贵。写模板时如果发现自己在循环里反复求逆元，先想想能不能改成预处理。

陷阱你怎么会被坑到：一个负号让逆元验证全错

你会看到什么？写完 exgcd 求逆元，随手拿 a = -3, m = 11 去验，程序说 -3 的逆元是 -4，可暴力版在 [1,10] 里找出来的是 7。你会怎么误判？第一反应是「exgcd 写错了，回去改递归公式」。

真相是：exgcd 给出的 x = -4 和暴力给出的 7 在模 11 下是同一个数，因为 -4 + 11 = 7。错的不是算法，是你没把结果规范到 [0,m)。更隐蔽的一种是底数为负：(-3) % 11 在 C 里是 -3，直接拿去算快速幂，第一层乘出来就是负数，后面虽不会因为溢出出错，但打印出来跟暴力对不上。

修法只有一行：a = (a % m + m) % m;，返回值也照做。本单元的 nt_inv_exgcd 和 nt_inv_fermat 都写了这一行，你抄模板时别省。

11.3 gcd、exgcd 与丢番图方程

先解决最基础的一对函数。

大白话最大公约数与「一把尺子」

gcd(a,b) 是能同时整除 a 和 b 的最大正整数。把它想成一把能同时量尽两段绳子的最长尺子。欧几里得算法的核心观察只有一句：gcd(a,b) = gcd(b, a % b)。因为 a 除以 b 的余数 r 等于 a - q*b，能同时整除 a、b 的数必然整除 r；反过来能整除 b、r 的数也必然整除 a。两边能整除的东西一模一样，最大那个自然也一样。

于是每做一次除法，两个数就变小一轮，直到余数为 0。递归深度是 O(log min(a,b))——几十次就到底，比二叉树还浅。

上面这段是迭代写法。三个赋值语句的顺序不能换：t 先存住旧的 b，否则 a = b 之后 b % a 就无从算起。开头的两行 if (a < 0) a = -a; 是为了让负数也得到正的 gcd——这跟 11.2 的规范是两回事，别混。

先把 gcd 的正确性说清楚，因为后面所有证明都借它的结构。算法每一轮把 (a,b) 换成 (b, a%b)。第一，这个过程一定会停：a%b < b，所以第二个数严格递减，而它始终是非负整数，递减有限次必然到 0。第二，停下来的那个数就是最大公约数：由 gcd(a,b)=gcd(b,a%b)，每一轮的最大公约数都没变，而 b=0 时 gcd(a,0)=a。两条合起来，循环结束时的 a 就是答案。

很多人把欧几里得算法当模板背，却说不出「为什么余数替换不改变最大公约数」。这句话的验证只要一行：a = q*b + r，所以 r = a - q*b。任何整除 a 和 b 的数 d 都整除 a - q*b = r；反过来任何整除 b 和 r 的数 d 都整除 q*b + r = a。两边的公约数集合完全相同，最大者自然相同。

把 1071 和 462 代进去走一遍：1071 = 2*462 + 147，462 = 3*147 + 21，147 = 7*21 + 0。三轮就到底，最大公约数是 21。注意每轮的商分别是 2、3、7——这三个数正是 exgcd 回溯时要用的 a/b，别把它们和余数 147、21、0 搞混。

现在把 gcd 升级成 exgcd。它不只返回最大公约数 g，还给出一组整数 x,y 满足 a*x + b*y = g。这个等式叫贝祖等式，它把「最大公约数」从一个描述变成了一个可以拿去做题的方程。

还是用 1071 和 462 这组数，把递归一层层摊开看，你会对「回溯」两个字有实感。最底层是 (21, 0)：按 b==0 的分支，x=1, y=0，因为 21*1 + 0*0 = 21。上一层是 (147, 21)，商 q=7，下层给出 x1=1, y1=0，于是 x = y1 = 0，y = x1 - 7*y1 = 1；验算 147*0 + 21*1 = 21。再上一层 (462, 147)，q=3，得到 x=1, y=0-3*1=-3；验算 462*1 + 147*(-3) = 21。顶层 (1071, 462)，q=2，x=-3, y=1-2*(-3)=7；验算 1071*(-3) + 462*7 = 21。

每一层只做两件事：把下层的 y1 搬上来当新的 x，再用商 q 算出新的 y。递归负责「钻到底」，回溯负责「把真等式搬回来」，没有第三步。

深度也不用担心：每轮把第二个数从 b 降到 a%b，而 a%b < b 意味着它至少减半（最坏是斐波那契相邻项那种黄金比例），所以深度是 O(log min(a,b))。a、b 到 1e18 时也不过几十层，离本机 2MB 栈的极限远得很——这跟并查集那种深度等于 n 的递归完全是两种风险。

大白话为什么回溯能算出 x 和 y

递归到 b == 0 时，等式 a*1 + b*0 = a 显然成立，所以底层直接令 x=1, y=0。回溯时假设下一层已经算出 x1,y1，满足 b*x1 + (a%b)*y1 = g。

把 a%b 改写成 a - q*b（q 就是 a/b），代入得到 b*x1 + (a - q*b)*y1 = a*y1 + b*(x1 - q*y1) = g。这正好是 a*x + b*y = g 的形状，其中 x = y1、y = x1 - q*y1。代码第 24、25 行就是这两条式子。

一句话：每一层只做一次代入，底层的真等式就被一路搬回顶层。这就是「辗转相除回溯」的全部内容。

陷阱你怎么会被坑到：把 q 写成 a%b 或者把两行顺序颠倒

你会看到什么？程序跑样例时对，对拍跑到某组随机的 a,b 突然FAIL。你会怎么误判？多半会怀疑「是不是 a、b 传反了」。

真相往往在这一行：*y = x1 - (a / b) * y1;。q 必须是整除的商 a/b，不是余数 a%b；而且第 24 行必须先用旧的 y1 算出 *x，第 25 行才能用 y1——因为再往下没有第三条式子能修正它。把两行顺序颠倒不会改变量的值（这里 y1 没被改写），但如果你顺手写成 *y = x1 - (a/b) * (*x)，那就把已经改过的 *x 用了进去，答案会静默错掉。对拍的 200 组随机数据就是专门抓这种「样例过、随机炸」的。

丢番图方程指的是系数和未知数都要求为整数的方程，a*x + b*y = c 是最简单的一类。由贝祖等式立刻得到结论：它有整数解当且仅当 gcd(a,b) | c。理由很简单——左边 a*x + b*y 一定能被 g=gcd(a,b) 整除，所以 c 必须被 g 整除；反过来若 c = g*t，把贝祖解乘 t 就得到一组解。

贝祖等式拿来解 a*x + b*y = c 的完整流程是这样的。先算 g = gcd(a,b)，若 c % g != 0 直接判无解；否则用 exgcd 得到 x0,y0 使 a*x0+b*y0=g，把两边同乘 t=c/g 得到一组特解 x=x0*t, y=y0*t。要得到其它解，用 x + (b/g)*k, y - (a/g)*k（k 任意整数）。想把所有解都列出来，就靠这两条参数式；想把 x 调到最小正数，对 b/g 取模即可。

举个例子：6x + 15y = 9。gcd(6,15)=3，9 能被 3 整除，有解。exgcd 给出 6*(-2) + 15*1 = 3，乘 t=3 得特解 x=-6, y=3；验算 6*(-6)+15*3 = -36+45 = 9。b/g = 5，把 x 规范到 [0,5)：-6 mod 5 = 4，所以最小正解 x=4，对应 y = (9-6*4)/15 = -1。整组解是 x=4+5k, y=-1-2k。

这套流程在「线性同余方程 a*x ≡ c (mod m)」里直接复用：把它改写成 a*x + m*y = c，就是上面这道题。所以 exgcd 不只用来求逆元，它是所有线性同余问题的入口。逆元只是 c=1 这个特例——你看，同一个工具换个参数就换了一种题型，这正是把「整除关系写成等式」的价值。

语法规则语法规则：从贝祖解到全部解

若 a*x0 + b*y0 = g，则 a*x + b*y = g 的全部整数解是 x = x0 + (b/g)*t，y = y0 - (a/g)*t（t 为任意整数）。把 t 换一换，就能把 x 调到 [0, b/g) 里——这正是求最小正逆元时要做的事。

11.4 逆元两法：费马与 exgcd

大白话逆元就是「模意义下的倒数」

普通算术里 3 * (1/3) = 1。模 7 的世界里没有分数，但有个好东西：3 * 5 = 15 ≡ 1 (mod 7)，所以 5 就是 3 在模 7 下的逆元，记作 3⁻¹ ≡ 5。有了它，模意义下的除法 a / b 就变成 a * b⁻¹。

但要注意：逆元不是总存在。模 12 时，2、3、4、6、8、9、10都没有逆元——它们跟 12 有公共因子，乘出来永远是偶数或 3 的倍数，不可能余 1。

语法规则语法规则：逆元存在的条件

a 在模 m 下有逆元，当且仅当 gcd(a,m) = 1（a、m 互质）。这是判断能不能做除法的第一道关，先判再算，比算完发现不对比省事。

求逆元有两种常用办法，前提完全不同，选错前提就会得到错答案。

费马小定理：若 p 是质数且 gcd(a,p)=1，则 a^(p-1) ≡ 1 (mod p)，于是 a^(p-2) ≡ a⁻¹ (mod p)。求逆元变成一次快速幂。

快速幂的指数为 0 这一支必须存在：r = 1 % mod 是循环一轮都不进时的默认值，也就是 a^0 = 1。忘了它，费马法碰到 p=2 这种边界就会返回 0。

exgcd 法：解 a*x + m*y = 1，只要 gcd(a,m)=1 就有解，x 就是逆元。它对模数是不是质数没有任何要求——这是它比费马法通用的地方。

费马小定理本身有一个漂亮的证明轮廓，知道它你就不会把前提记混。考虑模质数 p 下 1,2,...,p-1 这 p-1 个数。若 gcd(a,p)=1，把它们各乘 a 再取模，得到的还是这 p-1 个数的一个排列：不会有两个撞到一起，因为若 a*i ≡ a*j，消去 a 就得到 i ≡ j。于是两组数的乘积相同，a^(p-1) * (p-1)! ≡ (p-1)! (mod p)；由于 (p-1)! 与 p 互质，可以约掉，得 a^(p-1) ≡ 1，移项就是 a^(p-2) ≡ a⁻¹。

证明里用了两次「p 是质数」：一次保证 1..p-1 里没有数与 p 有公因子，一次保证 (p-1)! 可约。p 是合数时两步都塌，公式自然不成立。

逆元的用处远不止「做除法」。组合数里它把 n! / k! 变成 n! * (k!)⁻¹；概率题里它把分数概率变成可取模的整数；多项式题里它是单位根倒数的来源。竞赛里绝大多数「除以一个数再取模」的写法，底下都是这一步。

陷阱你怎么会被坑到：把费马小定理用在合数模数上

你会看到什么？模 12 下想求 5 的逆元。5 和 12 互质，逆元确实存在（是 5，因为 5*5=25≡1）。你套费马公式算 5^(12-2) = 5^10 mod 12，结果得到 1，不是 5。你会怎么误判？多半会怀疑「快速幂写错了」，反复检查循环边界。

真相是：费马小定理要求模数是质数。12 是合数，a^(p-2) 这个公式根本不成立；算出来的 1 在模 12 下不是 5 的逆元。同一组数据交给 exgcd 法，老老实实解 5x + 12y = 1，得到 x=5，正确。

所以选法的规矩是：模数确定是质数（竞赛里 1e9+7、998244353 这类）就用费马，快；模数任意、或者你不确定，就用 exgcd，普适。两法都别忘了 gcd(a,m)=1 这个前提——出口处第 51 行那句 if (g != 1) return 0; 就是干这个的。

暴力版只做一件事：在 [1,m-1] 里把每个 x 代进去试。

对拍驱动就是拿这三版互相验证：随机数种子写死在函数里，模数从一个固定的质数表里取，a 在 [1,p-1] 里取（跟质数 p 必然互质），三版结果必须两两相等，且 a*x % p == 1。

11.5 线性筛：最小质因子唯一性

大白话筛法就是在划掉合数

要找 [2,n] 的质数，最笨的办法是每个数都试除一遍到 √n。埃氏筛换个思路：从 2 开始，遇到一个质数就把它的倍数划掉。剩下的就是质数。问题是它会重复划——6 先被 2 划掉，又被 3 划掉一次。

线性筛的改进只有一句：每个合数只被划一次，而且被划它的那个质数正好是它的最小质因子。要做到这一点，内层循环不能一口气跑到 n，得在恰当的时候刹车。

第 12 行是整段代码的灵魂：if (i % prime[j] == 0) break;。它说的是「一旦当前枚举的质数 prime[j] 能整除 i，就不再往后枚举更大的质数」。为什么这一刹车就能保证线性？下面真写证明。

大白话正确性论证：每个合数恰好被最小质因子筛一次

设合数 c 的最小质因子是 p，写成 c = p * m。因为 p 是 c 的最小质因子，m 的所有质因子都不小于 p，也就是 spf(m) ≥ p。

第一，c 确实会被筛到。 看外层循环走到 i = m 的那一轮。此时质数表按升序枚举，所有小于 p 的质数 q 都不整除 m（否则 q 也整除 c，且 q < p，与 p 是最小质因子矛盾）。于是内层一路走到 prime[j] = p 都不会触发第 12 行的 break，计算 v = m * p = c，把它标记掉。

第二，c 只会被筛这一次。 算法里任何一次标记都是 i * prime[j] 的形式，其中 prime[j] 是 c 的一个质因子，所以 prime[j] ≥ p。质数表是升序的，prime[j] < p 的那些轮次根本轮不到 c；而一旦 prime[j] = p 标记了 c，第 12 行在 p | m 时会立刻 break，在 p ∤ m 时虽然不 break，但下一个质数 > p，乘上 m 会超过 c，不可能再得到 c。换个 i 也不行：若 i 更大，乘任何质数 ≥ p 都超过 c；若 i 更小，则需要一个比 p 大的质数才能凑出 c，而那个质数比 i 的最小质因子还大，升序枚举时到第 12 行早就被 break 拦住了。

两条合起来：c 被筛一次且仅一次，每次标记 O(1)，总共 O(n)。这就是「线性」二字的全部含义。

为什么线性筛比埃氏筛快？把两种写法并排看就清楚了。埃氏筛的思路是「每个质数 p 把 p, 2p, 3p, ... 全划掉」，一个合数如果同时被 2 和 3 整除，就会被划两次——12 会被 2、3 各划一次。线性筛的 break 保证每个合数只由它的最小质因子划掉，所以标记次数恰好等于合数个数，是 O(n) 而不是埃氏筛的 O(n log log n)。

这个「最小质因子」不只是证明里的道具，它本身就能拿来用。从 2 开始反复除 spf(n)，就能把一个数分解成质因数，复杂度 O(log n)；筛的时候顺手把 is_comp[v]=1 换成 spf[v]=i，同一段循环立刻升级成质因数分解器，分解时不需要试除到 √n。

再看内存。n=1e7 时 unsigned char 的标记数组是 10MB，素数数组按 70 万预留是 2.8MB，加起来十几兆，远低于常见 256MB 限制。n 提到 1e8 时标记数组变成 100MB，还在边缘；再往上就要换分段筛。复杂度表里的「能过的 n」就是这么算出来的——不是看渐近符号，是看这台机器装不装得下。

再看 break 条件为什么偏偏是 i % prime[j] == 0，而不是 i % prime[j] != 0 或者 j == k-1。它表达的是「prime[j] 已经是 i 的最小质因子（或更大）时停止」。当 prime[j] | i，由于质数表升序、前面的质数都不整除 i，prime[j] 正好是 i 的最小质因子；此时 i*prime[j] 已经被正确标记，再往后用更大的质数去乘 i，乘出来的数的最小质因子其实是 i 的某个更小的因子，本该由更早的某一轮负责，所以可以停。

如果改成 != 0，循环会在 prime[j] 不整除 i 时提前 break，导致更大的质因子还没枚举就退出——合数被漏筛。这种错误不会让素数表变短，反而会把合数当素数（因为 if (!is_comp[i]) 看见的是没被标记的合数），所以素数个数会明显偏多，逐点比对立刻抓住。

还有一个等价写法：显式存一个 spf[i] 数组，把标记条件写成 if (prime[j] > spf[i]) break;。本质相同，只是把「最小质因子」从隐含变成了明面。本单元选了最紧凑的版本，代价是可读性稍差——第一次读时盯住第 12 行多看两遍就习惯了。

陷阱你怎么会被坑到：把第 12 行删掉，程序照样给对答案

你会看到什么？删掉 if (i % prime[j] == 0) break;，跑样例，素数一个不少，全对。你会怎么误判？「这行是多余的吧，删了还能少一次判断」。

真相是：删掉之后它退化成埃氏筛的「每个质数扫一遍倍数」版本，每个合数会被它的每一个不同质因子各筛一次。n 小的时候看不出差别，n 到 1e7 时重复标记次数会翻好几倍。更阴险的一种改法是把 break 条件写成 if (i % prime[j] != 0) break;，结果合数被漏筛，is_comp 里混进假质数。

怎么验证？本单元的对拍除了比素数个数，还逐个比 is_comp[x] 与暴力试除的结果，再把 prime 数组里每个数都回代暴力判一遍。任何漏筛、重筛导致的逻辑错误都逃不过这三道检查。

暴力版写得越笨越安全：从 2 试除到 √x，第一个整除的就是最小质因子。

固定样例 n=30 给出 10 个质数、19 个合数；spf(12)=2、spf(25)=5、spf(27)=3 三个数正好是「最小质因子」的直观例子。后面那行 OK 200 是 200 组随机 n 的结论。

11.6 组合数取模：阶乘逆元预处理与 Lucas 入门

大白话组合数是什么

C(n,k) 读作「从 n 个不同东西里挑 k 个」，等于 n! / (k! * (n-k)!)。比如 5 个人里挑 2 个人组队，是 C(5,2)=10 种。

问题在竞赛里出现了：n 到 1e6、模数是 1e9+7 时，n! 大得没边，直接算会溢出；而且模意义下不能做除法。解法就是上一单元的逆元——除以 k! 等价于乘上 k! 的逆元。

组合数在竞赛里出现得比想象中频繁。计数题里它直接数方案；概率题里它算「恰好 k 次成功」的二项分布系数；DP 里「从 i 个位置里选 j 个放某种元素」的转移也常写成组合数。一旦 n 上到 1e5、模数是 1e9+7，试错法（递推杨辉三角）要 O(n²) 的时间和内存，必然爆掉；阶乘逆元预处理把查询压到 O(1)，这才是能过的写法。

要注意「模数是质数」这条前提在组合数题里出现得极其频繁，因为几乎所有做法都用到了费马小定理求逆元。如果题目给的模数是合数（比如 1e9 或某个偶数），阶乘逆元法整条链都失效，得改用质因数分解后 CRT 合并之类的办法——那已经超出本单元范围，但至少要能认出「这个模数不能用当前模板」。

语法规则语法规则：阶乘逆元预处理

选一个质数 mod，预处理 fact[i] = i! mod mod 和 invfact[i] = (i!)⁻¹ mod mod。则

C(n,k) = fact[n] * invfact[k] % mod * invfact[n-k] % mod。

关键技巧是倒着算 invfact：先用快速幂求 invfact[n] = (fact[n])^(mod-2)，然后从 n 往 1 递推 invfact[i-1] = invfact[i] * i % mod。因为 (i!)⁻¹ * i = ((i-1)!)⁻¹，一步就是一次乘法，总共只花一次快速幂。

正确性很好验：fact[i] = fact[i-1] * i，所以 fact[i]⁻¹ = fact[i-1]⁻¹ / i，移项得 fact[i-1]⁻¹ = fact[i]⁻¹ * i，正是第 28 行。递推的每一项都只依赖后一项，归纳就齐了。

Lucas 定理解决的是 n 大到没法预处理的情况：若 p 是质数，把 n、k 写成 p 进制，则

C(n,k) ≡ ∏ C(n_i, k_i) (mod p)，

其中 n_i、k_i 是第 i 位上的数字。上面代码第 41、46 行就在做「取当前位、右移一位」的拆位动作，而每一位的小组合数 C(n_i,k_i) 用刚才预处理好的表查。

组合数还有一条最基础的递推：C(n,k) = C(n-1,k-1) + C(n-1,k)。它的意思是「挑不挑第 n 个东西」：不挑就从剩下的 n-1 个里挑 k 个，挑就从 n-1 个里挑 k-1 个。杨辉三角的每一格都是这么来的，暴力版正是照这条式子写的。

阶乘逆元法为什么能 O(1) 给出答案？因为它把所有「分子分母的公共因子」预先约掉了。n! / (k!(n-k)!) 里有大量可约的因子，直接算阶乘再除会爆整数；写成 fact[n] * invfact[k] * invfact[n-k]，三项都是预处理好、已取过模的数，乘两次就完事。唯一的一次除法藏在 invfact[n] = fact[n]^(mod-2) 里——又回到费马小定理，又要求 mod 是质数。

Lucas 定理的证明轮廓也值得记一笔：C(p, k) 对 1≤k≤p-1 都被 p 整除（分子有因子 p，分母没有），所以在模 p 下 (1+x)^p ≡ 1 + x^p。把 n 写成 n = n0 + p*n'，比较 (1+x)^n 两边 x^k 的系数，就得到 C(n,k) ≡ C(n0,k0) * C(n',k')，反复套用即成定理。这里 p 是质数的前提又出现了一次——它保证了那条整除性质成立。

陷阱你怎么会被坑到：Lucas 里的 p 不是质数

你会看到什么？拿 p=12 去拆位，算 C(n,k) mod 12，跟暴力杨辉三角对不上。你会怎么误判？以为是拆位顺序写反了，或者某一行的 C(n_i,k_i) 查错了。

真相是：Lucas 定理的前提是 p 必须是质数。第 27 行那个快速幂 fact[n]^(mod-2) 用的是费马小定理，合数模数下根本不成立；整条链子从根上就断了。本单元的例子把 p 限定在 7 和 11 两个质数上，就是为了把这条前提钉死。

还有一个独立的前提：n_i >= k_i 才有的乘，一旦某一位 k_i > n_i，直接返回 0（第 43 行）。这不是优化，是定理的一部分。

暴力版用杨辉三角，从 tri[i][j] = tri[i-1][j-1] + tri[i-1][j] 一行行推出来，明显正确。

C(200,100) mod 1000000007 是阶乘逆元法的结果；C(100,50) mod 7 = 4 可以手算验证：100=(202)₇、50=(101)₇，于是 C(2,1)*C(0,0)*C(2,1) = 2*1*2 = 4。手算跟程序对上了，Lucas 的拆位就算真懂了。

对拍每轮做两件事：先用 n≤200 的杨辉三角验阶乘逆元法，再用小质数 p 的杨辉三角验 Lucas。

11.7 容斥原理：把「至少一个」拆成加减

大白话容斥就是「多算了就减回来」

数「至少满足一个条件的东西有多少个」时，直接把每个条件的集合大小加起来会重复：同时满足两个条件的被数了两次。容斥的修法很朴素——加单集合，减两两交，加三三交，减四四交……符号交替，直到没有新的交。

两个集合的式子是 |A∪B| = |A| + |B| - |A∩B|。三个集合是 |A∪B∪C| = |A|+|B|+|C| - |A∩B|-|A∩C|-|B∩C| + |A∩B∩C|。一般形式是「奇加偶减」，对 m 个条件求和 Σ(-1)^(k+1) * (所有 k 个条件同时满足的个数)。

容斥在数论里最常见的舞台是计数互质对：要数 [1,n] 中有多少个数与 m 互质，先把 m 的唯一质因子 p1..pr 列出来。「与 m 不互质」就是「至少被某个 pi 整除」。于是

与 m 互质的个数 = n - Σ⌊n/pi⌋ + Σ⌊n/(pi*pj)⌋ - ...

这正好是容斥的奇加偶减。r 最多十来个（23571113171923 就已经超过 1e8），所以 2^r 个子集枚举完全跑得动。

举个能手算的例子，把容斥的加减过程看一遍。数 [1,100] 里能被 2 或 3 或 5 整除的数有多少个。记 A、B、C 分别为能被 2、3、5 整除的集合：|A|=⌊100/2⌋=50，|B|=⌊100/3⌋=33，|C|=⌊100/5⌋=20；|A∩B|=⌊100/6⌋=16，|A∩C|=⌊100/10⌋=10，|B∩C|=⌊100/15⌋=6；|A∩B∩C|=⌊100/30⌋=3。代入奇加偶减：50+33+20-16-10-6+3 = 74，所以答案是 74 个，剩下 26 个与 30 互质。

这个例子同时说明容斥的代价：条件数 r 增加时，要算的交集数量是 2^r - 1。r 到 20 就已经是百万级，得配合别的手法（比如莫比乌斯反演）才跑得动。所以竞赛里用容斥之前先看 r 有多大，别一上来就枚举子集。

陷阱你怎么会被坑到：把容斥用在「至少有一个」之外的问法

你会看到什么？题目问「恰好满足一个条件」，你套上奇加偶减的公式，答案偏大。你会怎么误判？以为是交集算错了。

真相是：容斥的标准形式数的是并集（至少一个满足）。「恰好一个」「恰好两个」要用二项反演或者 deeper 的变形：恰好 k 个满足的个数，等于 Σ_{j≥k} (-1)^(j-k) * C(j,k) * (所有 j 个条件同时满足的个数)。看到「恰好」两个字就停下来，别直接抄并集公式。

工程惯例工程惯例：容斥为什么常跟枚举子集一起写

容斥的每一「项」对应「选出 k 个条件」，这天然就是子集枚举。竞赛里的标准写法是用位掩码从 0 枚举到 2^r - 1，按掩码里 1 的个数定符号，按这些位的乘积定除数。这是惯例而非标准：你也可以写递归逐个选，结果一样，代价是代码长一点、更容易漏掉某一层。

容斥和欧拉函数之间的关系值得再挖一层，因为它能把抽象公式落到一个具体函数上。欧拉函数 φ(n) 数的是 [1,n] 中与 n 互质的数的个数。把 n 的唯一质因子记作 p1..pr，「与 n 不互质」等于「至少被某个 pi 整除」，于是 φ(n) = n - Σn/pi + Σn/(pi*pj) - ... = n * ∏(1 - 1/pi)。这条乘积公式正是容斥展开后逐项提取公因子 n 的结果——不是新定理，只是同一式子的另一种写法。例如 n=12 的质因子是 2 和 3，φ(12)=12*(1-1/2)*(1-1/3)=4，对应 1、5、7、11 四个数。

再往前一步就是莫比乌斯函数 μ：把容斥的「奇加偶减」编码成 μ(d)，则 Σ_{d|n} μ(d) 在 n=1 时为 1、否则为 0。于是「gcd(i,j)=1」可以写成 Σ_{d|gcd(i,j)} μ(d)，交换求和顺序就得到常见的莫比乌斯反演式子。这条线本单元不展开，但它的起点就是容斥——你现在已经握住了入口。

大白话容斥为什么是对的

拿一个具体元素 x 来看。假设它恰好满足 t 个条件。在「加单集合」那一步，它被数了 C(t,1) 次；在「减两两交」那一步被减了 C(t,2) 次；依此类推，总贡献是 C(t,1) - C(t,2) + C(t,3) - ... + (-1)^(t+1) C(t,t)。

由二项式定理，(1-1)^t = C(t,0) - C(t,1) + C(t,2) - ... = 0（t≥1），所以上面这个和等于 C(t,0) = 1。也就是说每个至少满足一个条件的元素恰好被数了 1 次，一个不满足任何条件的元素贡献 0。加起来就是并集的大小。这就是整个证明，不需要画图。

11.8 快速幂与矩阵快速幂：结合律与二分本质

大白话快速幂就是把指数拆成二进制

算 a^13，朴素做法乘 13 次。快速幂的做法是把 13 写成二进制 1101，也就是 8+4+1，于是 a^13 = a^8 * a^4 * a^1。只要能依次算出 a, a^2, a^4, a^8（每次把前一个平方），再挑出需要的那几项乘起来就行。乘法次数从 13 降到约 log₂13 = 4 轮。

第 1 帧到第 4 帧就是 while (exp) 循环的四个回合。每一帧都把三样东西重写了一遍——当前的答案 res、当前的底数 base、剩下的指数 exp——因为屏幕版只画这一帧写出来的东西，不替你带上上一帧。关键恒等式是 exp 每右移一位，base 就平方一次，两者始终对齐。

矩阵乘法的结合律值得把求和式写全，因为很多人只是「听说过」它。设 C = A*B、D = B*E，比较 (A*B)*E 与 A*(B*E) 的第 (i,j) 元：前者是 Σ_k C[i][k]*E[k][j] = Σ_k (Σ_l A[i][l]*B[l][k]) * E[k][j]，交换求和号后是 Σ_l A[i][l] * (Σ_k B[l][k]*E[k][j])，正好是后者的第 (i,j) 元。交换求和顺序对有限和总是合法的，所以结合律成立。

有了结合律，M^a * M^b = M^(a+b) 才是一句合法的话——你可以随意换括号，把 60 个 M 的乘积按任意方式分组。快速幂正是把 M^n 拆成若干个 M^(2^k) 的乘积，再用平方依次造出这些 M^(2^k)。没有结合律，整个算法无从谈起。

转移矩阵的构造有一条通用套路：先看递推式依赖前几项，就取几维状态向量；再把「下一状态的第一分量」写成旧状态的线性组合，作为矩阵第一行；其余各行通常是「把旧分量往上挪一格」的移位。斐波那契依赖两项，所以是 2x2，第一行 [1,1]、第二行 [1,0]。换成 F(n)=F(n-1)+2F(n-2) 就是 [[1,2],[1,0]]；带常数项的 F(n)=F(n-1)+F(n-2)+1 要把常数塞进状态，变成三维 [F(n),F(n-1),1]，最后一行 [0,0,1] 让常数自我保持。这叫「齐次化」，是矩阵建模最常卡人的一步。

陷阱你怎么会被坑到：忘记指数为 0 的那一支

你会看到什么？mp_pow(base, 0, mod) 返回了一个全 0 矩阵，后面拿它去乘别的矩阵，结果全变 0。你会怎么误判？以为是平方函数写错了。

真相是：快速幂里 res 必须初始化成单位矩阵（对角线上是 1，其余是 0），对应 M^0 = I。上面内存图的第 1 帧里 res = 1（标量的单位元）就是这件事。少这一行，指数为 0 时循环一次都不进，直接把没初始化的值返回了。

本单元在固定样例里专门验了这一条：M^0 = [[1,0],[0,1]]，而且 M^10 * M^20 == M^30。后一条同时验证了结合律——换一种括号怎么乘，结果都一样。

现在把「数」升级成「矩阵」。矩阵乘法的结合律 (A*B)*C = A*(B*C) 成立，因为两边第 (i,j) 元都是 Σ_k Σ_l A[i][k] B[k][l] C[l][j]，只是求和顺序不同。正因为结合律成立，才能谈 M^n 而不必关心括号怎么加，也才能用平方把 n 拆成 2 的幂。

快速幂还有两个细节值得单独说。第一，指数 exp 用无符号类型（unsigned long long）才装得下 1e18；如果用 long long，虽然 1e18 还没溢出，但右移时符号位的行为容易让人犯迷糊，而且题目常给到接近 2^63-1 的边界。第二，循环里 if (exp & 1ULL) 检查的是当前最低位，处理完必须 exp >>= 1；忘了右移就是死循环，本机跑起来会直接超时。

矩阵幂和标量幂共用同一个 mp_pow 骨架，区别只在「乘法」和「单位元」换成了矩阵的版本。这种「换掉乘法和单位元就能复用」的结构在代数里叫幺半群，但你不需记这个词——只要记住：凡是有结合律、有单位元的运算，都能套这套二分快速幂。日后遇到多项式乘法、置换复合、甚至字符串拼接，都会再见到它。

再看 2x2 乘法的常数。教科书写法是三重循环、8 次乘法 4 次加法，小规模下完全可以接受；本单元的实现还在内层加了 if (x->a[i][k] == 0) continue;，对稀疏的转移矩阵能省掉一些乘法。代价是多一次分支判断，在本机 2 万次调用总共 27ms 的量级上看不出差别，所以这个优化可有可无——写模板时别为了这种小聪明牺牲可读性。

陷阱你怎么会被坑到：把矩阵元素存成 int

你会看到什么？n 不大时斐波那契数全对，n 到四五十突然蹦出一个负数。你会怎么误判？以为是取模的时机不对。

真相是溢出。模数取 1e9+7 时，两个矩阵元素的乘积可达 (1e9)² = 1e18，而 int 最大只有约 2.1e9——差了九个数量级。更隐蔽的是 r.a[i][j] + x*a[i][k]*y*a[k][j] 先把乘法算完再加，整个中间量都在 int 的领域里爆掉。

修法只有一条：矩阵元素、乘积、累加一律用 long long。本单元的结构体里 ll a[2][2] 就是这么定的。另外加法那一步 (r + 乘积) % mod 里，r < mod、乘积 < mod²，相加 < 2*1e18，还在 ll 的 9.2e18 范围内，安全。

大白话二分本质：为什么 O(log n)

把 n 写成二进制需要 log₂n + 1 位。循环每轮处理一位：低位是 1 就多一次矩阵乘（把当前幂乘进答案），不管低位是什么都要平方一次。所以矩阵乘的总次数不超过 2*log₂n，是个常数倍的对数。

n = 1e18 时 log₂n ≈ 60，也就是不到 120 次 2x2 乘法就能算出第 1e18 项。对比递推版要做 1e18 次加法——后者在宇宙寿命内跑不完。这就是「二分本质」：不是矩阵魔法，是把线性步数压成对数的位运算。

转移矩阵怎么构造？斐波那契的递推 F(n+2) = F(n+1) + F(n) 涉及前两项，所以状态向量取两维 [F(n+1), F(n)]ᵀ。要让它走到 [F(n+2), F(n+1)]ᵀ，只需要

M = [[1,1],[1,0]]，因为 M * [F(n+1), F(n)]ᵀ = [F(n+1)+F(n), F(n+1)]ᵀ。

于是 M^n * [F(1), F(0)]ᵀ = [F(n+1), F(n)]ᵀ，答案就藏在结果的第二行第一列。

第 2 帧里的那条边就是一次矩阵乘法；第 3 帧把它压缩成 M^n，也就是 11.8 那个内存图里二进制分解要做的事。两幅图连起来看：转移矩阵定义了「一步怎么走」，快速幂定义了「怎么一步跨 n 格」。

第 28 行那句 if (n == 0) return 0; 不能省：M^0 是单位矩阵，右下角是 1，而 F(0)=0，两者对不上，必须特判。

固定样例里 M^10 * M^20 == M^30 打出了 1，这是结合律的一次实测；F(50) 打出的是取模后的值，跟你在别处看到的十进制斐波那契数不同，别以为算错了——本例子模数固定是 1e9+7。

暴力版就是老老实实滚两个变量，n 到 60 完全承受得住，正好拿来当对拍的裁判。

对拍 200 组，n 在 0..60 之间随机取，两版结果必须逐组相等。n 只到 60 是因为暴力版是 O(n)，取太大就失去「找反例」的意义了——对拍要小数据高密度，压测另有机权。

为什么每个耗时都取三次？因为单次计时会抖：进程启动、系统调度、缓存冷热都会带来几毫秒的波动。本单元的做法是同一份程序连跑三次，把三次的值写进实验记录——线性筛 22/22/21 ms，矩阵快速幂三次都是 27ms，区间一旦稳定就说明数字可信。如果三次值差了一个数量级，那多半不是计时波动，而是程序里有什么东西没初始化，得回去查。

矩阵那个例子里单次耗时只有 0.0014ms，远低于 clock() 的 1ms 分辨率，直接测一次会得到 0 或 1。所以程序里重复调用 20000 次，测总时间再除——这是测小耗时的标准手法。别把「重复多次取平均」当成小技巧，它是本机事实里写明的纪律：分辨率不够时就得靠放大样本量。

实验记录本机实测：为什么分开放 stdout 和 stderr

perf 程序把可复现的结论（素数个数、最后一个素数、F(10^18) 的取模值）打到 stdout，让闸门逐字对账；把会抖的耗时打到 stderr，让会话文件去记录。这样同一份程序既有「机器验过的结论」，又有「人读的计时」，两边互不干扰。这也是全书对「耗时不进 output 块」这条纪律的落地方式。

读这张表时有个常见误区：只盯着时间复杂度那一列。O(log n) 的矩阵快速幂看起来完胜所有 O(n) 算法，但当 n 只有 60 时，暴力递推（几十次加法）比矩阵快速幂（上百次矩阵乘法）快得多——常数差了两个数量级。复杂度描述的是 n 变大时的趋势，不是小数据下的快慢。所以表里专门留了「暴力递推 n≤60」这一行，提醒你小数据用暴力，大数据才换高级算法。

另一个误区是把「能过的 n」当成硬件常数。它其实由三样东西共同决定：渐近复杂度、常数因子、内存占用。线性筛的 1e7 是这三样在本机取交集的结果；换一台内存 128MB 的机器，1e7 的标记数组还放得下，1e8 就不行了。

C 与 C++ 的取舍也回到同一条链。原理层用 C 裸数组，好处是常数小、内存布局看得见；代价是每换一个模数就要改全局变量，复用性差。应用层用 C++ 类封装，把模数和表绑在一起，可以同时造 CombMod(1000000007, 2000) 和 CombMod(11, 10) 两个实例互不干扰——本单元的 C++ 驱动正是这么干的。代价是构造时分配内存、边界检查可能生效，实测 200 组对拍 0.043–0.048 秒，比 C 版慢了约三成。三成换来的可复用性值不值，看你在赛时写的是一次性题解还是长期模板。

大白话双层写法：原理层用 C，应用层用 C++ STL

同一件事写两遍不是浪费。C 版让你看见每一步——数组怎么开、逆元怎么倒推、break 在哪里；C++ 版让你看见「换成标准库以后，哪些样板代码消失了、哪些代价冒出来了」。本单元的原理层是 comb_mod.c：静态数组、手写快速幂、全局变量记当前模数。应用层是 comb_stl.cpp：两个 std::vector 装阶乘表，用一个类把模数和表封装起来，调用方只看到 C(n,k) 和 lucas(n,k)。

工程惯例工程惯例：什么时候直接用 STL，代价是什么

这是惯例，不是标准。std::vector 替你管内存和长度，std::int64_t 把「至少 64 位」写进类型名，类比全局变量更好复用——这些都是明确的收益。代价有三条：vector 会做边界检查（在开启断言的构建里），比裸数组慢一点；类多一层间接，读代码时得先跳到定义；构造对象时会分配内存，不能在极热的循环里反复 new。

赛时怎么选？写模板用 C 风格裸数组，写题解外壳用 C++ 封装。本单元两份代码都参与对拍：C 版和 C++ 版各自跑 200 组，都打出 OK 200，说明两种写法结论一致。

回到 11.1 的第 4 帧，逐个点名：

容斥原理这一节没有配例子，因为它不是独立算法，而是一条计数恒等式；它的验证方式就是 11.7 里那个「每个元素恰好被数 1 次」的二项式证明。下一单元讲计算几何：从整除关系走到叉积与凸包，你会看到「把几何判断变成整数符号判断」的同一套改写手艺。

写到这里，给你一份能立刻用的自检清单。第一，先看取模：底数、返回值有没有规范化到 [0,m)；第二，先看前提：费马法的模数是不是质数、Lucas 的 p 是不是质数、逆元的 gcd 是不是 1；第三，先看类型：矩阵元素、乘积、指数是不是够宽；第四，先看边界：指数 0、n=0、k>n 有没有单列分支；第五，跑一遍对拍：五份 OK 200 是不是都出现了。这五条按顺序列，是因为前四条错了第五条也救不了——对拍只能证明「两版一致」，不能证明「两版都满足题意」。

小结这一节的要点
  • 取模结果规范到 [0,m) 一律写 (a%m+m)%m；C 的 % 保留被除数符号；
  • gcd(a,b)=gcd(b,a%b)；exgcd 靠回溯代换 x=y1, y=x1-(a/b)*y1 得到贝祖系数，有解当且仅当 gcd(a,b) | c；
  • 逆元存在的条件是 gcd(a,m)=1；费马法 a^(p-2) 只对质数 p 成立，exgcd 法对任意模数成立；
  • 线性筛靠 if (i % prime[j] == 0) break; 让每个合数恰好被最小质因子筛一次，复杂度 O(n)；
  • C(n,k)=fact[n]*invfact[k]*invfact[n-k]，invfact 倒推一次快速幂即可；Lucas 把 n、k 拆成 p 进制位，p 必须是质数；
  • 容斥是奇加偶减的并集计数，每个满足至少一个条件的元素恰好被数 1 次；
  • 矩阵乘法满足结合律，所以 M^n 可用二进制快速幂；转移矩阵把递推编码成「一步怎么走」；矩阵乘法中间量必须 long long；
  • 指数为 0 时快速幂必须返回单位元；矩阵幂的 n=0 还要特判 F(0)=0；
  • 所有结论都被 200 组固定种子对拍验证，耗时只进会话与实验记录。

注自测题答案
  1. -13 % 5 = -3（C 的 % 保留被除数符号）。要得到 [0,5) 的代表元写 (a % m + m) % m，这里得 2。只写 a % m 会得到负数，跟暴力版和手算的钟面结果对不上，后面的乘法与验证都会错。
  2. 回溯时先算出下一层的解 (x1,y1) 满足 b*x1 + (a%b)*y1 = g；再把 a%b 换成 a-(a/b)*b，得到 a*y1 + b*(x1-(a/b)*y1) = g。所以 x=y1，y=x1-(a/b)*y1。最终 1071*(-3)+462*7=21=gcd(1071,462)。
  3. 因为费马小定理要求模数是质数，12 是合数，a^(p-2) 这个公式不成立，算出的 1 不是 5 的逆元。应该用 exgcd 法：解 5x+12y=1，得到 x=5。两者前提不同——费马要「p 是质数且 gcd(a,p)=1」，exgcd 只要「gcd(a,m)=1」。
  4. 素数表仍然对（因为合数照样会被某个质因子划掉），但复杂度退化：每个合数会被它的每个不同质因子各筛一次，常数变大。本单元对拍不只比素数个数，还逐点比 is_comp[x]、回代验每个素数；删掉 break 主要影响耗时而不影响正确性，所以真正抓常数退化靠的是 n=1e7 的性能会话，而把 break 条件写反（!= 0）导致的漏筛会被逐点比对当场抓住。
  5. 100 = 2*49 + 0*7 + 2 = (202)₇，50 = 1*49 + 0*7 + 1 = (101)₇。逐位组合数：C(2,1)*C(0,0)*C(2,1) = 2*1*2 = 4，所以 C(100,50) mod 7 = 4，与程序输出一致。
  6. 模数取 1e9+7 时两个元素乘积可达 (1e9)² = 1e18，远超 int 上限约 2.1e9，所以元素类型、乘积、累加都要 long long。指数为 0 时循环一次都不进，必须把 res 初始化成单位元（标量是 1，矩阵是单位矩阵）；另外矩阵幂算 F(0) 时 M^0 右下角是 1 而 F(0)=0，必须单独特判。
  7. 设元素 x 满足 t 个条件，其总贡献是 C(t,1)-C(t,2)+...+(-1)^(t+1)C(t,t)。由二项式定理 (1-1)^t = C(t,0)-C(t,1)+C(t,2)-... = 0（t≥1），移项得那个和等于 C(t,0)=1。t=0 时贡献为 0，所以并集里每个元素恰好被数 1 次。
