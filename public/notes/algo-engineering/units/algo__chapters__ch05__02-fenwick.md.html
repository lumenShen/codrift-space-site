12.1 先看工程长什么样

树状数组（Fenwick Tree）只维护「前缀和」，但围绕它长出了四种赛场上反复出现的子问题：单点改+区间查、区间改+单点查、区间改+区间查、离散化之后数逆序对。本单元一个不落，全部配对拍、配本机实测耗时。先看文件，因为四个子问题的坑有一半不在算法里，在下标约定里。

大白话这一节想让你先建立一个画面

把树状数组想成一排管段：数组 t 的第 i 格不管单个元素，管的是一段——从 i 往左延伸 lowbit(i) 格，正好到 i 为止。i 的二进制里最低位的 1 有多大，它就管多长：t[3] 管 [3,3]（lowbit(3)=1），t[4] 管 [1,4]（lowbit(4)=4），t[6] 管 [5,6]（lowbit(6)=2）。

  • 问「前 7 个数的和」＝ 从 7 出发把管段首尾相接地拼起来：[7,7]、[5,6]、[1,4]，三段不多不少铺满 [1,7]；
  • 给「第 5 个数加 v」＝ 从 5 出发把所有包住位置 5 的管段各记一笔：t[5]、t[6]、t[8]。

两个方向都是 lowbit 在导航。整个树状数组就是这两件事，剩下的全是它们的变形。

12.2 lowbit：i & (-i) 为什么取出最低位的 1

整个结构的第一主角是一行位运算。它值得一个完整的证明，因为「负数按位与」是多数人第一次认真面对补码的地方：

推导只有四步，设 i 的二进制是「……x 1 0…0」——最低位的 1 后面跟着 k 个 0，也就是 i = m·2^k 且 m 是奇数：

  1. 按位取反：~i = ……x̄ 0 1…1——比 x 高的位全部变反，那个 1 变成 0，后面的 k 个 0 全部变成 1；
  2. 再加一：末尾 k 个 1 全部翻回 0，进位一路走上去，把中间那个 0 翻成 1，到 x̄ 处停住——-i = ……x̄ 1 0…0；
  3. 按位与：x 与 x̄ 相与得 0，中间整段两边都是 0，最低位的 1 两边都是 1，后面的 k 个 0 两边都是 0；
  4. 结论：i & -i 只在第 k 位剩一个 1，正好是 2^k——最低位的 1 连同它代表的量级。

拿 12 验一遍：12 = 1100（k=2），~12 = ……0011，加一得 -12 = ……0100，1100 & 0100 = 0100 = 4。跑一遍看更多值：

规律一目了然：奇数的 lowbit 是 1，2 的倍数才可能是 2，4 的倍数才可能是 4——管段长度由「自己是 2 的几次幂的倍数」决定，这就是 lowbit 决定管段的全部含义。这份输出是真实运行的 stdout：本机 gcc -std=c17 -O2，命令与清单见 12.4。

把 1..8 的 lowbit 排成一行再看一眼：1,2,1,4,1,2,1,8——形状是分形的。奇数位全是 1，2 的倍数位至少是 2，4 的倍数位至少是 4，以此类推。这条形状规律给出一笔有用的计数：1..n 里 lowbit 恰好等于 2^k 的格子有 ⌊n/2^k⌋ 个——它决定了整棵「管段树」的形状，也决定了后面每个操作的层数（12.3 的引理 1 说上跳每层 lowbit 至少翻倍，翻倍的梯子正是按这个计数搭出来的）。换 k 的视角说同一件事：管段 [j-lowbit(j)+1, j] 的左端点永远是「j 去掉最低位的 1」，所以管段的两端都长在 2 的幂的格点上——这就是 12.3 那张图里「缩进一层 = 管段短一半」的算术根源。

大白话用「取反没动它」来记 i & -i

i & -i 是「把自己和自己取反后的交集」。取反把所有位翻面，加一又把一串低位翻回来——两轮折腾下来，唯一两边都是 1 的位置，就是「加一的进位没有越过的那一位」，也就是最低位的 1。它前面的高位在取反时翻了面（交集为 0），它后面的低位是 0（交集为 0）。记住这个「进位停在哪，lowbit 就在哪」，补码那四步推导就不用背了。

顺手记一个孪生写法：i & (i - 1) 是去掉最低位的 1（p - lowbit(p) 与它恒等——自己推一遍 p = …1 0…0 减一后的形状就明白）。于是 query 的 p -= lowbit(p) 也可以写成 p &= p - 1，赛场上两种写法都常见；本单元统一用减法形式，因为它和 update 的加法形式并排摆着，对偶性一眼可见（12.3）。

先把接口钉下来——整个结构对外只有七个函数，前面证过的约定全写进了注释：

bit_range 与 bit_point 是派生品（12.5 会给实现），真正的地基只有 bit_add 与 bit_prefix 两个循环。

lowbit 把 1..n 织成一棵树：每个格子的「父亲」是 i + lowbit(i)——父亲管段完整包住儿子的管段。先看这张图，再看两个循环：

第 1 帧是这张地图：缩进一层就是「管段被包住一层」，8 管 [1,8] 是根。第 2 帧是 update 的走法：从 5 出发沿父亲上跳 5 -> 6 -> 8，路径上三个格子的管段都包含位置 5——它们各记一笔，别的格子（4、7）分文不动。第 3 帧是 query 的走法：从 7 出发每次剥掉自己的 lowbit，7 -> 6 -> 4，三段 [7,7]、[5,6]、[1,4] 首尾相接拼满 [1,7]。两个循环就长这样：

为什么对？这不是「背循环」，是三条可以证死的性质。 update 方向两条，query 方向一条，全部从 lowbit 的定义出发。先立个骨架：

语法规则语法规则：两个循环的三条约定
  1. update 沿父亲上跳：for (p = i + 1; p <= n; p += lowbit(p)) t[p] += v;——入口 i + 1 是外部 0 基换内部 1 基，出口 p > n 是「越过顶」。
  2. query 沿起点链下剥：for (p = i + 1; p > 0; p -= lowbit(p)) s += t[p];——出口 p = 0 是「剥完」；p 必须是有符号的，-1 靠这个判断吸收。
  3. 区间与单点都是减法：[l, r] = prefix(r) - prefix(l-1)，a[i] = prefix(i) - prefix(i-1)；l = 0 时 prefix(-1) 天然为 0，不用特判。

引理 1（上跳一次，管段至少翻倍）：设 q = p + lowbit(p)，则 lowbit(q) ≥ 2·lowbit(p)。证明一句话：写 p = m·2^k（m 奇），则 q = (m+1)·2^k，而 m+1 是偶数，所以 q 至少是 2^(k+1) 的倍数。拿 12.3 第 2 帧的 update(5) 走一遍：lowbit(5)=1，5 跳到 6；lowbit(6)=2 ≥ 2·1 成立；6 跳到 8；lowbit(8)=8 ≥ 2·2 成立。管段 [5,5] ⊂ [5,6] ⊂ [1,8] 一层包一层——「越跳越宽」不是视觉印象，是每次跳完 lowbit 至少翻倍的必然结果。这条引理立刻给出 update 的「不多」：路径 p1 = i, p2, p3, … 的管段一个比一个宽（起点不升、终点递增），而位置 i 在第一段 p1 的管段里，于是按归纳它在每一段里——路径上的格子确实都管着 i，一笔不多；同时它也给出复杂度：包含 i 的管段构成一条 lowbit 逐级翻倍的链，长度不超过 log2(n) + 1。

引理 2（管段包含 ⟹ lowbit 严格变大）：若格子 j 的管段包含 i 且 j > i，则 lowbit(j) > lowbit(i)。证明用余数：写 lowbit(j) = 2^b，则 j ≡ 2^b (mod 2^(b+1))；管段里除 j 外的任何 i = j - s（1 ≤ s < 2^b），代入得 i ≡ 2^b - s (mod 2^(b+1))，而 0 < 2^b - s < 2^b——i 的最低位 1 落在第 b 位以下，所以 lowbit(i) < 2^b。

推论（update「不少」）：任何管段包含 i 的格子 j 都在上跳路径上。反证：设 j 管 i 但不在路径上，取路径上不超过 j 的最后一点 p（由引理 1 的归纳，p 也管 i），于是 p < j < p + lowbit(p)。由引理 2，lowbit(j) ≥ 2·lowbit(p)；而 j 管 i 给出 j - lowbit(j) + 1 ≤ i ≤ p，即 j - p ≥ lowbit(j) - 1 ≥ lowbit(p)；但 j < p + lowbit(p) 给出 j - p < lowbit(p)。矛盾。所以 update 把每一个该记账的格子都记了，一笔不少。

query 方向的论证更干脆：剥皮序列 p1 = p, p2 = p1 - lowbit(p1), … 里，p2 恰好是 p1 管段的左端点减一，所以相邻两段首尾相接、互不重叠；剥到 0 停止，逐段并起来正好是 [1, p]，一段不多一段不少。步数等于 p 的二进制里 1 的个数，不超过 log2(n) + 1——7 = 111 剥三步（第 3 帧走的正是它），8 = 1000 只剥一步。这背后其实是二进制表示定理的几何版：每个前缀都能唯一拆成若干段管段，每段长度恰好是 p 的二进制里那个 1 代表的 2 的幂——「拆分唯一」由二进制表示唯一担保，「能拆」由剥皮构造担保。同一个 lowbit 分割，嵌套方向（谁包含谁）服务 update，拼接方向（谁紧挨谁）服务 query——一张地图，两个视角。

这里有一个值得当场拆掉的想当然：「query 走的是 update 的反路径」——不对。update 边连的是「管段嵌套」关系（i -> i + lowbit(i)），query 边连的是「管段起点链」关系（p -> p - lowbit(p)），两套边共用同一批管段，却是两张不同的图。对照 12.3 的第 3 帧看：query(7) 剥皮走 7 -> 6 -> 4，而真正管着位置 7 的格子是 7 和 8 两个——8（管 [1,8]）不在剥皮路上，因为它的管段越过 7 一路铺到 8，不满足「首尾相接」。query 路径上的格子，是「管段右端点恰好落在剥皮点上」的那批，不是「管段包含 p」的那批。把这两个集合混为一谈的人，写二维 BIT 时一定栽跟头（12.13）。

两个循环是同一张地图的两个方向，这就是对偶性：p += lowbit(p) 沿「管我的更大格子」往上爬（管段嵌套，越爬越宽），p -= lowbit(p) 沿「首尾相接的拼接」往下剥（管段不重叠，恰好铺满）；终止条件也镜像——一个越过 n 停，一个归 0 停。你在 12.9、12.10 里会看到：所有变形（差分、两个 BIT、二维）都只是在这两个循环外面套一层记账。

数组与管段的对照值得盯三帧：

第 1 帧对上 output 里那行 t[1..8]：1 3 3 10 5 11 7 36——每个数都是一段的和，不是单个元素。第 2 帧对上 prefix(6) 那行：三段相加 28，与暴力一致。第 3 帧对上 a[3]+=10 那行：t[4] 从 10 到 20、t[8] 从 36 到 46，t[5]、t[6] 纹丝不动——因为它们的管段不包含内部位置 4。三帧连起来，update 与 query 就不再是「背下来的循环」，而是你在地图上看得见的两条路。

管段的方向也值得问一句「为什么向左延」：t[p] 管 [p-lowbit(p)+1, p]，右端点永远落在自己身上。这不是唯一的设计——向右延的管段 [p, p+lowbit(p)-1] 同样自洽，只是它天然服务后缀和（从 p 到末尾），前缀查询反而找不到「右端对齐」的拆分。前缀和是绝大多数题的问法，所以本书与教材都取左延：query 的剥皮需要「段与段首尾相接铺满 [1, p]」，这个性质只有左延管段给得出。你将来读到「树状数组求后缀和」的写法，会发现它就是把下标翻过来的右延版本。

为什么「两次前缀相减」就够回答区间查？望远镜在这里又转了一圈：prefix(r) 覆盖外部 [0, r]，prefix(l-1) 覆盖 [0, l-1]，两式相减，前 l 项逐项抵消，剩下的正好是 a[l] + … + a[r]——闭区间 [l, r] 本尊，一个下标都不多不少。这行减法没引入任何新结构，只是把 12.3 的「前缀拆分唯一」用了两次。

12.7 离散化求逆序对：把值域压进 1..k

逆序对是树状数组最经典的第二落点：从左往右扫，每个元素问一句「已插入的数里，有几个严格比我大」，问完把自己插进 BIT——BIT 的前缀和正是「有多少个已插入的数 ≤ 我」的计数器。第 7 单元（排序）用归并求过同一个问题：归并在合并时顺手数出横跨中线的逆序对，也是 O(n log n)。两条路线答案必然相同（逆序对个数由定义唯一决定），数据却各自独立对拍——本单元用 BIT 重新数一遍，对拍数据、种子、工程都是新的。

大白话逆序对在数什么

把数组从左往右扫，每走到一个位置就问：「我已经见过的人里，有几个比我大？」每一个这样的「前辈」，跟当前位置都构成一对「前大后小」。把所有位置的答案加起来，就是逆序对总数。树状数组在这里当点名册：插入是把某个 rank 的名字记上，前缀查是「rank 不超过我的已点名人数」——一减，剩下的恰好是「比我大的前辈」。归并版把同一个问题换成了「合并时数横跨中线的人」，点名册换成了分治，数出来的对一对都不会少。

数逆序对其实有两条等价的走法：从左往右问「已插入的严格大于我」（本单元的写法），或者从右往左问「已插入的严格小于我」——把数组整个翻过来，同一个问题。两条路数出来的数必然相等（每一对 (i, j) 在两个方向各被数一次、且只被数一次）。差异只在减号那一侧：从右往左问「严格小于我」时，计数式换成 bit_prefix(t, rank - 1)——比「rank 减一还小」的就是「严格小于我」。两条路都写一遍再互相对拍，是给这个计数式上双保险的老办法；本书只演左往右这条，对拍交给按定义逐对数的暴力。

大白话差分装进 BIT，是「里程表装上导航」

静态差分是里程表：把「区间加」记成两个端点的账，最后沿路加一遍才还原出每一格。树状数组版差分是给里程表装上导航——随时能问「我现在在哪一格」（单点查就是差分的前缀和），而记账方式一格没变（还是两个端点）。代价是每笔记账、每次问路都从 O(1)/O(n) 变成 O(log n)；买到的，正是「加一笔、查一笔随时交错」的自由。

什么时候不需要它？「最后才问、中间不问」照旧用第 9 单元的静态差分——最后还原一次 O(n)，比 BIT 版常数更小。识别信号句没变：「每次操作之后都要报数」用 BIT 版，「最后统一报数」用静态版。第 9 单元的 diff_range_add 与本节的 bit_range_add 摆在一起，就是这道选择题的两个选项——先认题，再动手。

量级账也要预判，别等溢出才想起：q = 1e6 次区间加、每次 |v| ≤ 50 时，任何位置的前缀和（也就是任何 a[i]）的绝对值不超过 2q·max|v| = 1e8——long long 的上界约 9.2e18，余量十万倍。这个余量就是「累计值一律 long long」这条约定的底气：它让你可以放心叠加操作，不用每加一笔就心算一次上限。到 12.10 的两个 BIT，这笔账还要再乘两层，那里接着算。

12.10 区间改区间查：两个 BIT 与那两个系数

区间和不能像区间查那样「两次前缀相减」——你手里没有前缀和。推导从差分出发，一步步来：设内部 1 基位置上的差分为 delta[p]，则 a[i] = Σ_(p≤i) delta[p]（望远镜），于是内部前缀 f(P) = Σ_(i=1..P) a[i] = Σ_(p=1..P) delta[p]·(P - p + 1)——每个 delta[p] 被加了 P - p + 1 遍。把这条式子拆成两半：

f(P) = (P+1)·Σ delta[p] - Σ p·delta[p]

于是两个 BIT：b1 存 delta[p]（第一项），b2 存 p·delta[p]（第二项），各自支持单点改与前缀查，查询时各剥一次皮再组合：

大白话两个 BIT 各管一头

b1 回答「每格被加了多少」（差分本账），b2 回答「这些加法离我多远」（位置加权账）。f(P) 的两项就是「总量 × 远近修正」：(P+1)·Σdelta 假设每笔账都从位置 1 生效，Σp·delta 把「其实是从 p 才生效」的那部分扣回去。一个 BIT 记不了两本账，所以开两个——这也解释了为什么区间查要付两倍的剥皮钱。

先说清为什么不能只开一个 BIT：把 f(P) = Σ delta[p]·(P - p + 1) 交给一个 BIT 现算，剥皮只能给「前缀和」，给不出「前缀 × 加权系数」这种逐项变系数的和——硬算就得逐项扫，O(n) 一次，前面的努力全白费。两个 BIT 的本质是把这个和拆成两个可剥皮的普通前缀和：(P+1)·Σdelta 与 Σp·delta 各自剥一次皮、组装时只做乘减——把「逐项变系数」化成「整体乘一个系数再相减」，这才是这两个 BIT 真正的分工。

陷阱你怎么会被坑到：四个乘数记混

（你会看到什么）单点查全对，区间和的错法千奇百怪：有的数据偏一个 v，有的偏 v 的若干倍——错多少跟 l、r 的具体值纠缠在一起。（你会怎么误判）先怀疑剥皮写错，把两个 BIT 的循环改来改去；其实剥皮没问题，错在账本。（真相）rr_add 里的四个乘数各就各位：b1 记 +v 与 -v（不带位置），b2 记 +v·L 与 -v·(R+1)（带位置，且抵消账乘的是 R+1 不是 R）；查询里的系数是 (P+1) 不是 P。背不下来的后果就是写错——这四个数全部来自上面那行推导，写模板时把推导写在注释里（上面代码就是这么做的），错的时候顺着注释能查出是哪一项。

拿 12.9 自检的同一批数据把公式手算一遍，四个乘数的位置感就落了地。n=8，三次区间加 [1,4]+10、[3,6]-3、[0,7]+1 换到内部 1 基后记的账是：delta[2]+=10、delta[6]-=10、delta[4]-=3、delta[8]+=3、delta[1]+=1、delta[9]-=1。问 rr_sum(0, 7)，外部 [0,7] 换内部 [1,8]，P=8：Σdelta = 1+10+0-3+0-10+0+3 = 1；Σp·delta = 1·1 + 2·10 + 4·(-3) + 6·(-10) + 8·3 = 1 + 20 - 12 - 60 + 24 = -27。代入：f(8) = 9·1 - (-27) = 36——正是 output 里的 区间和 [0,7]=36。注意两处细节：delta[8] 那笔 +3 乘的是 8 而不是 7（b2 的乘数是「记这笔账时的位置」，不管你将来问到哪）；delta[9] 那笔 -1 根本不进 P=8 的前缀——哨兵格的账只对「问到末尾之后」的查询生效。公式里每个下标的位置感，手算一遍比背十遍牢。

两个 BIT 的溢出账接着 12.9 算：b2 的格子里存 p·delta[p]，量级到 1e6 × 1e8 = 1e14；查询时还要乘 (P+1)，|f(P)| 的量级约 1e14——离 long long 上界还有一万多倍余量。若题目给到 |v| = 1e9，这笔账涨到 1e18 级，余量只剩个位数倍——那时先担心的不是 BIT，是这道题在跟你的类型过不去：先看能不能对 v 取模、能不能把问法化成差值，再谈实现。

对拍里这四个乘数被高重复率的随机区间反复捶打（OK 200 见 12.9 的 output 块末行——两个变体与暴力三方同步记账、同步比对）。性能账见 12.11：每次区间加 4 次剥皮/上跳、每次区间查 4 次，常数是普通前缀查的两倍，但量级不变。

12.13 二维树状数组与它不能做什么

两件事收尾，一句一笔。二维：把 12.3 的两个循环各叠一层就行——t[i][j] 管矩形 [i-lowbit(i)+1..i] × [j-lowbit(j)+1..j]，单点改外层沿 i += lowbit(i) 上跳、内层对每个落点的 i 再沿 j += lowbit(j) 上跳；前缀查外层剥 i、内层对每个落点剥 j；区间查容斥四块相减（S(r2,c2) - S(l2-1,c2) - S(r2,c1-1) + S(l2-1,c1-1)，二维前缀和的老朋友，第 9 单元讲过）。单次操作从 O(log n) 变成 O(log² n)——1e3×1e3 的表每次约 100 次格子访问，常数不吓人但也不再「白送」。12.3 拆过的那个误区在二维会加倍咬人：外层剥到的每个 i，内层剥的是「j 方向的管段起点链」，不是「管着 c 的格子」——两层各是各的地图，别拿 update 的边去走 query 的路。内存账先算再开表：n=m=1000 的二维 long long BIT 是 8 MB，2000×2000 是 32 MB——256 MB 的限制下要连同其他数组一起算，别让一张表吃掉半场预算。

不能做什么：区间最值。前缀和能相减是因为加法有逆（S(r) - S(l-1)），max 没有逆——max(l..r) 无法由两个前缀 max 拼出来，中间的元素可能比两端都大却谁也不代表它；「更新」同样没有逆——单点改小之后，旧的大值还赖在管段里出不去。所以区间最值要靠线段树（下一单元的主角：整段信息可合并、懒标记管更新）。特殊构造确实存在，但要认清它的成立条件：只往大改（只增不减）、只查前缀 max 时，把管段里的求和换成取 max，一个 BIT 仍然成立——大值往祖先传不会错，因为没有「撤销」这回事；一旦需要改小、或者要查任意区间（而不是前缀）的 max，嵌套的管段立刻从朋友变成毒药。识别句照旧：见到「区间和、可减」用树状数组，见到「区间最值、可减性没了」想线段树。二维也一样管用：棋盘上「单格改、矩形数和」（扫描线事件的计数、二维偏序的统计）都是第一行加一维的问法——「数多少个点落在左下象限」就是二维前缀和的查询，这也是 12.7 那套「插入 + 前缀计数」在两个维度上的自然延伸。

小结这一节的要点
  • lowbit(i) = i & -i：补码「取反加一」把最低位 1 左边全部清掉，管段长度由「自己是 2 的几次幂的倍数」决定；
  • update 沿 p += lowbit(p) 上跳，正确性两条：路径管段嵌套（不多）+「管段包含 ⟹ lowbit 严格变大」（不少）；query 沿 p -= lowbit(p) 剥皮，管段首尾相接拼满 [1, p]；
  • 内部 1 基、格子 0 是哨兵：lowbit(0) = 0 会让 update 原地打转，p = i + 1 就是防线；循环变量必须是有符号的，否则 -1 变 4294967295；

  1. p++ 每次只前进一格，最终会把所有管段都记上账——答案仍对，但单次操作从 O(log n) 退化成 O(n)，1e6 次操作就是 1e12 量级，评测直接 TLE。p += 2 * lowbit(p) 会跳过管段：比如 p=4 时跳到 12，t[6]、t[8] 这些管着位置 4 的格子没记账——答案从此就错了，对拍会把你领到第一个不一致的组。
  2. l = 0 时 l - 1 = -1，bit_prefix(b, -1) 从 p = 0 进循环，有符号的 p > 0 不成立，循环一步不走、返回 0——负数被循环条件天然吸收。若 p 是 unsigned，-1 回绕成 4294967295，p > 0 永远为真，第一次 p -= lowbit(p) 就在数组外乱跳——崩法是「换个启动方式换一种结果」。
  3. 去重去掉的是「值」到「rank」的一对多：不同值才有不同 rank，相等值共享同一个 rank。忘跑去重表直接二分：rank 会顶到 n，超过按去重个数开的 BIT 格子数，写入越界，症状是时对时错甚至崩溃；lower_bound 换成 upper_bound（或把「严格大于」写成「大于等于」）：重复值自己跟自己成对，答案偏大——正文 [2,1,2] 的自检里正解 1、错版 2。
  4. 最大 n(n-1)/2 ≈ 5e9（完全倒序）；均匀随机期望 n(n-1)/4 ≈ 2.5e9；int 上界 2 147 483 647 ≈ 2.1e9。三个数说明随机数据平均就超了，溢出不是极端数据才有的事——计数器必须 long long；本机实测同一个数喂 int 显示成 -1785592840，-ftrapv 构建下进程以 3221226505 中止。
  5. b1 存差分 delta[p] 本身，b2 存「位置 × 差分」（即 p·delta[p]）。四笔账：b1 在 L 处 +v、在 R+1 处 -v；b2 在 L 处 +v·L、在 R+1 处 -v·(R+1)。查询公式 (P+1)·Σdelta - Σp·delta 里的 (P+1) 少个加一，等于把每段差分的「自己那格」全丢了——区间和每段少一个元素值，对拍会稳定报 FAIL。
  6. 「相减」坏在 max 没有逆：前缀 max 拼不出 max(l..r)，夹在中间的更大值谁也不代表；「更新」坏在改小没有逆：单点改小后旧的大值还留在管段里出不去。所以区间最值交给线段树（信息可合并 + 懒标记管更新）——树状数组守住它擅长的「可减的和」。
