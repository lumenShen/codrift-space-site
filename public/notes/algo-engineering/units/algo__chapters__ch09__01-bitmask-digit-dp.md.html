9.1 先看工程长什么样

这一单元有三个例子工程，都在 examples/ch09/ 下。别急着看状态转移方程，先看文件是怎么分的。第 1 帧是这一章开始时的草稿形态：ch09 连目录都还没建。第 2 帧是三个例子按「正解 + 暴力 + 驱动」落地后的样子。第 3 帧补上性能探针、C++ 应用层、清单和两份真抓的会话，这时候流水线才能逐字对账。

大白话先建立一个画面：把一个整数当成一排开关

一个整数在内存里就是一串二进制位。如果每个位置只代表「某个东西在不在」，那么 8 个开关只需要一个字节，20 个开关只需要四个字节。原来你要用「一个布尔数组」才能记下「哪些点走过、哪些格子铺了骨牌」，现在一个整数就够了。把这个整数当数组下标，就得到一张按「集合」编号的表——所谓状压 DP，本质只有这一句话。

第 2 帧的三个目录正好对应三种「把状态塞进整数」的方式：tsp_bitmask 把「走过哪些城市」塞进一个 n 位整数；digit_count 把「填数填到哪一步、有没有贴着上界、有没有开始写数」三个条件合成搜索参数；digit_sum 换一个问题再走一遍同一套模板。第 3 帧里 session-*.txt 不是装饰：耗时每次都抖，进不了 output 块，只能抓成会话文件再注入正文。注意 digit_sum 里那一组 C++/STL 文件——它是一份完整的应用层程序，也参与 200 组对拍，这是本分册的双层要求。

标准没有规定一个程序分几个文件。这里每个目录都把声明放进 include/*.h、定义放进 src/*.c（或 .cpp），驱动 main.c 只负责造数据、调用和打印。这么分有两个实打实的好处：你抄模板时只抄实现那一份，不会把实验代码带进赛场；头文件就是接缝，读一眼就知道算法能做什么、不能做什么。代价是多一次 #include 和 -Iinclude。本单元三个目录全部遵守，所以每份清单都列出至少两个源文件，并且真的包含了项目内的头文件。

这两类 DP 看起来一个管「集合」一个管「数字」，其实共享同一个动作：把一个原本需要很多变量描述的局面，压成一个或几个能当数组下标的整数。状压 DP 里这个整数是位掩码，数位 DP 里它没有真的压成一个整数，而是拆成 pos / limit / lead 三个小参数，其中 limit 和 lead 都只有真假两值——本质上也是「把局面编码」。学会问「完成这件事到底需要记住多少信息」，比背任何模板都重要：需要记住的信息越多，状态空间越大，能被 n 或位数撑住的程度就越低。

9.2 状压的第一性原理：一位一个元素

先把「一位一个元素」这句话拆开。假设有 4 个城市，编号 0 到 3。我们约定：整数的第 k 位为 1 表示「城市 k 已经访问过」，为 0 表示「还没访问」。那么 0000 是一个点都没去，0101 是去了 0 和 2，1111 是四个点全去完了。这个整数叫位掩码（bitmask），它的第 k 位就是关于第 k 个元素的一个开关。

语法规则状态上界与下标公式
  • 1 << n 是「n 位全为零、更高位为 1」的数，等于 2^n；它正好是集合个数，也是合法掩码的右开上界。掩码取值范围是 0 .. (1<<n)-1。
  • 竞赛里的纪律是 n ≤ 20：2^20 ≈ 1.05e6，配合一个 n 长的终点维还能塞进内存；n=25 时 2^25 ≈ 3.4e7，再乘 25 就是 8 亿个整数，直接越过 256 MB。
  • 二维的 dp[S][i] 实际开成一维：dp[S*n + i]。索引要先转成能装下 2^n * n 的类型（size_t 或 long long），不能拿 int 直接乘。

用一个具体的数把上界钉住：n=10 时 1<<n 是 1024，掩码从 0 数到 1023，一个 10×1024 的表不过一万格；n=20 时 1<<n 是 1048576，配合 20 个终点就是两千万格。从 20 再加一位，集合数翻倍到 2097152，数组直接涨到 160 MB；n=22 是 320 MB，已经摸到常见内存限制的天花板。所以「n≤20」不是谁拍脑袋定的魔法数，而是把 2^n 和每格字节数相乘之后算出来的分界线。顺带提醒：1<<31 在 32 位有符号 int 上越界，哪怕你只是想「试一试 n=31 会怎样」，也要写成 1LL<<31 或 1u<<31，否则测出来的数本身就是错的。

把集合当数组下标之后，表的每一个格子就是一个小问题。下面这张图把「掩码」和「表」两件事摆在一起看。第 1 帧是掩码本身，第 2 帧是它怎么变成下标，第 3 帧是 n 增大时表如何膨胀。

第 2 帧里 dp[1*4+2] 的索引算法值得盯一眼：S=1 的二进制是 0001，表示「只访问了点 0」；i=2 表示「现在停在点 2」。这两件事合起来才是一个完整状态——只说「走过哪些点」不够，还得说「现在人在哪儿」，否则你不知道下一条边从哪个点出发。第 3 帧是内存的真账：2^20 * 20 = 20971520 个格子，每个格子 4 字节，正好 80 MB。这不是纸面估算，性能实验真开了这么大一块数组并跑出了答案。

还要说明「一位一个元素」为什么比布尔数组划算。用 bool visited[20] 记访问状态，20 个元素占 20 字节，看起来也不大；但你要拿整个数组当哈希表键时，得比较 20 次，还要处理它的地址与生命周期。换成 20 位整数，一个寄存器就装得下，比较、拷贝、当数组下标都是一条指令的事。状压带来的不是「省那十几字节」，而是把一整段局面变成可索引的标量——这才是它快的原因。代价是位运算的可读性：S & ((size_t)1 << j) 这种写法第一次看很别扭，所以本单元在关键行都写了注释，第 15 行还专门解释了为什么起点下标是 n 而不是 0。

陷阱你怎么会被坑到：1<<n 用 int 会溢出

你会看到什么？程序在小 n 上一路正常，把 n 调到 31 做「规模测试」，结果要么死循环、要么访问违例、要么得到一个莫名其妙的负数上界。你会怎么误判？以为是数组开小了，或者怀疑循环变量写错。真相是 1 是 int，1 << 31 在 32 位有符号整数里是未定义行为——最高位被当符号位，结果可能是负数。正确写法是 1LL << n 或 1u << n，再赋给 size_t。同样地，第 2 帧里 S * n + i 这个乘法的中间结果也可能越过 int：n=20 时最大值 20971520 还没事，n=24 就到了 4 亿，离 2^31 只剩一步。把索引类型定成 size_t 是省心的做法。

陷阱你怎么会被坑到：dp 开成 long long 直接内存翻倍

你会看到什么？按复杂度表估了 80 MB，觉得 256 MB 限制很宽裕，于是把 dp 顺手写成 long long *，跑 n=20 却收到内存不足。你会怎么误判？以为是编译器多分配了什么隐藏结构。真相是 2^20 * 20 * 8 = 160 MB，再加临时数组和程序本身，离限制就不远了。本例所有花费都是整数距离，一条回路最多 20 条边、每条不超过 100，上界 2000，int 绰绰有余。原理层用 int 不是为了抠门，而是因为「状态规模 × 单格字节数」必须真算一遍。反过来，如果距离本身能到 1e9、边数 20，那 int 就不够，必须先改类型再算内存。

9.3 子集枚举：for (s = mask; s; s = (s-1)&mask) 为什么恰好遍历所有子集

状压 DP 里有一句循环几乎天天出现，它的作用是把 mask 的每一个非空子集都访问一遍：

语法规则子集枚举的标准形式

for (s = mask; s; s = (s - 1) & mask) { ... }

  • 起点是 mask 自己，终点是 0（循环条件 s 为假时结束），所以 0 这个空集不会被访问；
  • s - 1 把 s 的最低位的 1 清成 0、并把更低的全置 1；再 & mask 把不属于 mask 的位抹掉，得到一个仍是 mask 子集的数；
  • 循环次数是 2^popcount(mask) - 1，mask 是全集时就是 2^n - 1。

这句循环太短，短到很多人背下来却讲不出它为什么对。这里把正确性论证完整写一遍，用的是「按最高位归纳」。

命题：对任意掩码 mask，上述循环按数值严格递减的顺序，恰好访问 mask 的每一个非空子集各一次。

证明（一）不会重复且一定终止。 设某一轮的值是 s，下一轮是 s' = (s-1) & mask。因为 s - 1 < s，而按位与只能把某些位从 1 改成 0、绝不会凭空多出 1，所以 s' ≤ s - 1 < s。序列严格递减，因此不可能出现同一个值两次；正整数序列严格递减必然在有限步内到达 0，循环终止。

证明（二）s 始终是 mask 的子集。 初始 s = mask 显然成立。归纳步里 s' = (s-1) & mask，按位与的结果只保留 mask 中为 1 的那些位，所以 s' 的每一位为 1 都意味着 mask 对应位为 1，即 s' ⊆ mask。

证明（三）不漏。 对 mask 的最高置位 b 做归纳。记 m = mask 去掉位 b（于是 m < b）。mask 的非空子集分成两族：不含 b 的（就是 m 的非空子集），含 b 的（形如 U | b，其中 U ⊆ m，U 可以为空）。

循环从 mask = m | b 出发。只要 b 这一位还在，s 就形如 b | u、u ⊆ m。此时若 u > 0，减法 s - 1 不会向 b 借位（低 u 位够减），于是 s' = b | ((u-1) & m)——这正是「对 m 做同一条子集枚举」的一步。由归纳假设，它会把 b | u 中所有 u 非空的情况走遍，也就是所有「含 b 且还含 m 里某些点」的子集。当 u 减到 0 时，s = b，s - 1 = b - 1 的低位全是 1，再 & mask 恰好等于 m——这就访问了 U 为空的那个子集，也就是 {b} 本身。接着 s = m，再按归纳假设走遍 m 的所有非空子集，即所有「不含 b」的子集。两族合起来正好是 mask 的全部非空子集，且由（一）知互不重复。∎

拿 mask = 0b1010（十进制 10，含第 1、3 位）走一遍，全部非空子集依次是 10（1010）、8（1000）、2（0010）。第一步 s=10，s−1=9（1001），& 10（1010）得 8（1000）；第二步 s=8，s−1=7（0111），& 10 得 2（0010）；第三步 s=2，s−1=1（0001），& 10 得 0，循环结束。你看，最低位的 1 每轮都被清掉一次，而「哪些位属于 mask」始终没变。把这个轨迹和第 9.2 节那张图对照，就能体会「清最低位 1」其实是在做「从集合里删掉一个元素，再枚举剩下的」。

还要分清两层循环各自的职责。外层枚举 mask 时，每个 mask 代表一个「正在考虑的集合」；内层枚举子集时，那个子集代表「从这个集合里再挑出一部分」。比如要算「每个集合的所有划分」，就会写出这种双层结构，代价是 3^n。而 TSP 的转移只从 (S,i) 走到 (S∪{j},j)，每个集合只处理一次、每个终点只枚举一次前一个点，根本没有内层子集循环——这正是它能把 n 推到 20 的原因。看到 O(3^n) 别急着认命，先问自己：内层那句「枚举子集」能不能换成「枚举一个元素」？

复杂度。 循环体执行 2^k - 1 次，k 是 mask 里 1 的个数。如果在它外面再套一层「枚举所有 mask」的循环（共 2^n 个 mask），总次数是

sum_{k=0}^{n} C(n,k) (2^k - 1) = (1+2)^n - (1+1)^n = 3^n - 2^n,

也就是 O(3^n)。二项式定理是这一步的关键：sum C(n,k) 2^k 就是把 (1+2)^n 展开。n=20 时 3^20 ≈ 3.4e9，这个量级本机跑不完——所以「外层枚举 mask、内层枚举子集」的双层结构只能用于 n≤15 左右。如果你要的是 TSP 那种「固定终点、只枚举前一个点」的单层转移，复杂度是 O(2^n · n²)，n=20 才能过。

最后提醒一个常见错写：有人图省事把循环写成 for (s = mask; s; s--)，觉得「从 mask 往下数总能数到每个子集」。这会把不属于 mask 的数也数进去——mask=0b1010 时，9（1001）、7（0111）都不是它的子集，却被当成子集处理，答案会凭空多出一堆状态。& mask 那一步不是可省的装饰，它保证每一次迭代后的值仍是 mask 的子集；这正是证明（二）的内容。另一个细节是空集 0 不在循环里：很多题目需要空集（比如「一个点都不选」的方案），那时要么在循环外单独处理 0，要么把循环条件改成能包含 0 的形式并显式终止——别指望这条 for 自动帮你带上它。

陷阱你怎么会被坑到：子集枚举的 s 用了 int

你会看到什么？n 小的时候一切正常，把 n 调上去、让 s 参与下标乘法之后，答案突然变成乱七八糟的数，甚至访问违例。你会怎么误判？以为是 dp 数组开小了，或者 (s-1)&mask 这个式子写错了。真相是 s 的类型太窄：1 << n 里的 1 是 int，n 到 31 就成了未定义行为；即便 n=20 时值本身装得下，s * n + i 这个乘法的中间结果在更大 n 下也会越过 32 位。稳妥写法是把 s 和整个上界都放进 size_t，写成 size_t s 与 (size_t)1 << n。本单元 TSP 里的 size_t S 正是这条纪律的落地。

9.4 TSP 的 dp[S][i]：把「走过哪些城市」塞进一个整数

TSP 是状压 DP 的标本题：n 个城市两两之间有一条路，从 0 号城出发，每个城恰好经过一次，最后回到 0，问最短路多长。按第 20 单元讲的「状态定义三件事」来拆：

  • 阶段：按集合 S 里 1 的个数递增填表；原因是转移只会往 S 里多放一个点，不会少放。
  • 状态：dp[S][i] 表示「从 0 出发，恰好走过集合 S（S 含 0 与 i），最后停在 i 的最小花费」。少说「最后停在 i」这几个字，你就不知道下一条边从哪儿出发。
  • 决策：最后一个到 i 之前，站在哪个 j。于是 dp[S][i] = min{ dp[S\{i}][j] + w[j][i] : j ∈ S\{i} }。等价地从前往后推：从 (S, i) 走到 (S∪{j}, j)，花费加 w[i][j]。

第 15 行最容易被写错：起点是「S 只有第 0 位为 1、停在 0」，所以下标是 1*n+0 = n，不是 0。下标 0 对应的是 S=0、i=0，这个状态根本不合法。初版如果写成 dp[0]=0，所有状态都会保持 INF，对拍第 0 组就报出来——这正是暴力裁判的价值。

（续）第二段是核心转移与答案提取：枚举下一个没去过的城市 j，更新新状态；等 S 变成全集，再加上「从最后一个城回到 0」这条边。

正确性论证（不变式）。处理完集合 S 的所有终点后，dp[S*n+i] 等于「从 0 出发、恰好走过 S、最后停在 i」的最短路；S 里第 0 位必须为 1，i 必须是 S 里的点。初始 S={0}、i=0 时花费 0，成立。归纳步：设 (S,i) 已是最优，任取没去过的 j，新集合 S' = S ∪ {j}、新终点 j 的候选花费是 dp[S*n+i] + w[i][j]。所有到达 (S',j) 的路径，其倒数第二站 i 必然满足 i ∈ S 且 i ≠ j，所以遍历全部这样的 i 与 j 就覆盖了所有可能的最后一刀；取最小即得最优。终止时 S 是全集，每条合法回路都恰好对应某个终点 i，再加回 0 的边取最小，就是答案。n=1 是边界：回路就是站在原地，花费 0，代码里显式处理。∎

复杂度也要真算：集合 S 有 2^n 种，每个 S 里最多 n 个终点 i，每个 (S,i) 再枚举最多 n 个没去过的 j，所以时间是 O(2^n · n²)，空间是 O(2^n · n)。n=20 时 2^20·400 ≈ 4.2e8 次内层判定，本机实测 235–245 ms，说明常数不大。暴力侧是 (n−1)!：n=8 时 5040 条排列，n=10 时 362880 条，n=12 就到了 39916800 条——所以 n≤8 不是随手定的，是让 200 组对拍在十几秒内跑完的上限。把 n 提到 12，光一组就得算四千万条排列，两百组要跑到分钟级；对拍的目的是找反例，不是压测，数据要小而密。

写这类 DP 时最容易在下标上翻车，有个便宜的自检办法：先固定 n=4 手工列出 mask 从 0 到 15 的二进制，再对照程序打印的 S*n+i 索引，看是否一一对应。性能实验的 stdout 里打印的 DP 单元数=20971520 就是这么核对出来的——2^20 乘 20，与源码里 total * n 的分配量逐字相等。另一个信号是答案的合理性：TSP 的最优回路一定不小于最大边长、不大于把所有边加起来；如果程序给出 INF 附近的值，十有八九是起点状态设错了下标，或者某些状态永远没被更新。本单元初版就踩过这个坑：把起点写成 dp[0]=0，而合法起点其实是只有第零位的集合、终点 0、下标 n，结果所有状态都是 INF，暴力第 0 组就报出来。把这类「反向验证」写进对拍的失败分支，比盯着代码看一小时有用。

暴力侧写得明显正确：枚举 1 到 n-1 的所有排列当作访问顺序，逐条算长度取最小。排列数是 (n-1)!，所以只对 n≤8 的对拍数据调用。

9.5 子集枚举的 3^n 与轮廓线入门

上一节证明了「枚举 mask + 枚举子集」是 O(3^n)。这个复杂度有个很鲜明的分界线：n=15 时 3^15 ≈ 1.4e7，本机在秒内；n=20 时 3^20 ≈ 3.4e9，分钟级起步。所以当你看到一道题的朴素做法是「对每个集合、再枚举它的所有子集」，先别急着写，先把 n 代进去算一遍。如果 n≤15，这个三层结构可以直接用；如果 n 到了 20，就必须找只枚举一次集合的 O(2^n) 转移，TSP 正是这种。

轮廓线 DP 是状压的另一个大门类，它把「一位一个元素」用在了另一件事上：棋盘铺砖。给你一块 h×w 的棋盘和 1×2 的骨牌，问铺满有多少种方案。按格子从左到右、从上到下扫描，填到某个格子时，你只关心「哪些已经铺好的骨牌伸到了我这一行」——这些格子的占位情况就是一条切断棋盘的轮廓线，宽度只有 w。于是状态是 dp[mask]，mask 的第 c 位表示「当前行的第 c 列是否已被上一行竖放的骨牌占据」。

处理格子 (r, c) 时只有三种可能：如果 mask 第 c 位已经是 1，说明这个格子被竖骨牌盖住了，直接移向下一格；否则可以横放一块骨牌（占住 (r,c+1)，对应把下一位设 1），也可以竖放一块（占住 (r+1,c)，对应把当前位留给下一行）。每走一格只改变 mask 的少数几位，方案数累加。复杂度 O(h · w · 2^w)——指数上是宽度 w 而不是格子总数 h·w，这正是轮廓线能过题的原因：棋盘可能有 1e5 个格子，但只要宽度 w≤10，2^w 就只有一千多点。

拿一块 2 行 3 列的棋盘、只用横放骨牌铺满来走一遍。轮廓线宽度是 3，mask 的三位对应当前行第 0、1、2 列是否被占。第一格 (0,0) 的 mask 是 000，只能横放，于是 (0,1) 被占，mask 变成 011；走到 (0,1) 发现它已被占，直接跳过；到 (0,2) 又 mask=000，这里不能再横放（右边出界），只能竖放，mask 把第 2 位留给下一行；进入第二行时，第 2 位已经是 1，说明 (1,2) 被上一行的竖骨牌盖住，跳过；(1,0) 和 (1,1) 再横放一块，mask 回到 000，扫描结束，方案数加一。整个过程中 mask 只有 2^3=8 种取值，和棋盘有几个格子无关。

轮廓线和 TSP 的状压是同一套思想的两种用法：TSP 的位记「哪些点去过」，轮廓线的位记「轮廓线上哪些格被占」；前者集合大小是 n，后者是 w。区别在于 TSP 的集合只会增长（每个点去一次），轮廓线的 mask 会随扫描一格一格地变化（旧的占位出线、新的占位入线）。入门时只要抓住「把未来会用到的信息压成一个整数，下标就是状态」这句话，两类题都能自己建模。

陷阱你怎么会被坑到：把宽度和格子总数搞混

你会看到什么？写轮廓线 DP 时顺手把状态开成 dp[1<<(h*w)]，棋盘稍微大一点就直接内存不足或编译不过。你会怎么误判？以为是 2 的幂算错了。真相是轮廓线只覆盖「当前正在处理的一行」，宽度是 w 而不是 h×w。h×w 是格子总数，它出现在阶段数（扫描步数）里，不出现在指数里。判断标准是问自己：「再往下一格走时，我需要记住多久以前的信息？」如果只需要记住当前这一行的占位，那就是 w 位。

9.6 数位 DP：pos / limit / lead 三个参数

现在换一类看起来完全不相关的问题：统计区间 [L, R] 里某个数字出现了几次，或者所有数的数位和是多少。直接扫 0..R 当然可以，但 R 到了 1e18 就是天文数字。数位 DP 的做法是按位填数，像小心翼翼地写一个车牌号：从第最高位开始，每一位能填 0..9 中的哪些，取决于前面填得怎么样。

大白话用大白话说数位 DP

把「数从 0 数到 x」想成在一台只能一位一位拨的号码机上枚举所有不超过 x 的号码。你不需要真的把每个号码拨出来，只要记住三件事：现在拨到第几位了（pos）、前面拨出来的前缀是不是已经顶到了 x 的前缀（limit，顶到了的话这一位就不能随便拨，最多拨到 x 这一位的数字）、以及我是不是还在一路拨零、正经数字还没开始（lead）。这三件事定了，后面怎么拨就是固定的子问题。

形式化地，定义 f(x) = 「0..x 的所有数的十进制写法中，目标事件（某数字出现次数 / 数位和）的总量」，那么区间答案就是 f(R) − f(L−1)。搜索函数写成 dfs(pos, limit, lead)，三个参数的含义是：

  • pos：当前处理第几位（从高位到低位，或从低位到高位，只要全程一致）。它是递归的终止条件与记忆化的键。
  • limit：前面的前缀是否恰好等于 x 的前缀。为真时这一位最多填到 x 在这一位的数字；为假时 0..9 随便填。
  • lead：是否仍处于前导零状态，即到现在还没写出任何非零数字。为真时填 0 不算真的写出一个 0（前导零不进十进制写法）。

第 1 帧里十位填 0 之后，limit 立刻变成假：因为 0 < 1，前缀已经严格小于 x 的前缀，后面再怎么填都不会超过 13。填 1 之后 limit 仍是真，个位被 13 的个位 3 卡住，只能填 0..3。这就是 limit 参数的全部作用——它是一条「还能贴着上界走多久」的绳子。第 2 帧的 lead 还没解除，这一位填 0 不会写出数字，所以数字 0 走的是「全前导零」路径；第 3 帧的 lead 已经解除，填 1 才真的计一次。

实现上有个容易卡住的设计问题：dfs 该返回什么？如果返回「已经累计的出现次数」，那这个累计值就成了第四个参数，记忆化的键也得带上它。这里用一个小技巧——返回一对摘要：num 是后缀能造出多少个数，dig 是这些数里目标数字一共出现几次。当前位 d 的贡献等于「d 是否等于目标」乘以「后缀有多少个数」，所以乘一下就能累加。搜索参数始终只有三个。为什么不让 dfs 返回一个数、把累计值当参数传下去？那样做当然可以，但累计值会变成第四个参数，而且它的取值范围随位数增长（最多 19×9），记忆化表的键就得从 pos 扩成 (pos, 累计值)，表和索引都变复杂。返回一对摘要的好处是：把「已经算出来的部分」留给调用方去加，dfs 自己只描述「从这一位往后还能产生什么」，键就干净得只剩 pos。这个技巧在数位 DP 里很常用，本质是把「前缀贡献」和「后缀能力」分开——凡是你发现状态里混进了「到目前为止的累计量」，都值得问一句能不能改成返回摘要。

9.7 记忆化为什么 limit / lead 为真时不存

记忆化的本质是把一个函数的返回值按参数缓存起来。这里缓存表的键只有 pos（target 在一次 f() 调用里固定，x 的位数也固定，每次调用前都会清空表）。要让这个键合法，缓存的值必须是 pos 的纯函数：同样的 pos，无论从哪条路径走到，结果都必须一样。limit 和 lead 为真时恰好破坏这一点。

limit 为真时不能存。 此时这一位以及后面的位最多填到 x 对应位的值，可选范围被 x 的尾部绑住。同一个 pos，在 x=13 的搜索树里个位最多填 3，在 x=99 的搜索树里个位能填到 9——两者的子问题完全不同。也就是说返回值不仅依赖 pos，还依赖一个没进键的外部参数 x（确切地说是 x 的后缀）。如果把它按 pos 存进表里，下一次遇到相同 pos 但不同边界的调用就会读到错误的值。换一种说法：limit 为真描述的是一条具体路径上的状态，它不是可复用的子问题，而是整棵搜索树中只出现一次的那条贴边上界路径。

举个能当场复现的反例。假设缓存键只有 pos，我们求 f(13)。两次调用开头都会清空 g_vis，所以跨调用没问题；问题出在同一次调用内部。求 f(13) 时，搜索树里有一条贴着上界的路径走到 pos=1、limit=真，此时个位只能填 0..3；如果这时把结果按 pos=1 存进表，那么同一棵搜索树里另一条已经脱离上界的分支走到 pos=1、limit=假时，查表会命中那条「只能填 0..3」的结果，于是 0..9 的自由分支被悄悄限制成 0..3，答案偏小。暴力一比对就会发现 f(13) 不对，而且无论换多少组数据都错在同一个位置。把写表条件加上 !limit 之后，这条贴边路径根本不进表，问题消失。

lead 为真时不能存。 此时「还没写出任何非零数字」是另一种语义状态：这一位填 0 不算写出数字，因此对 target=0 不计数；而 lead 为假时同样的 pos、同样填 0，那是个实打实的 0，要计数。两者在相同 pos 下的结果不同，可缓存的键却只有 pos——如果把 lead 为真的结果写进 memo[pos]，后面一个 lead 为假的调用命中它，答案立刻串掉。所以必须把 lead 为真也排除在写表条件之外。

于是写表的条件就是 !limit && !lead：后缀完全自由（每位 0..9），而且数已经开始写（前导零规则不再生效），这时的结果只由 pos 和固定的 target 决定，是真正的纯函数。第 21 行的查表条件和第 32 行的写表条件用的是同一个判断，这不是巧合——查表和写表必须用同一套条件，否则要么缓存污染，要么命中率归零。

陷阱你怎么会被坑到：limit 为真时错误记忆，答案串到别的组

你会看到什么？对拍在小数据上偶尔报错，报出来的值与暴力差一点点，而且同样的 L、R 单独测又是对的，像是「被前面的计算污染了」。你会怎么误判？以为是全局变量没清零，或者随机数生成器状态串了。真相是记忆化写表的条件漏了 limit：贴着上界的那条路径把结果存进了 memo[pos]，后面一个不贴上界的调用命中它，直接拿到被边界限制过的偏小值。这类 bug 特别阴，因为单组数据重跑时脏缓存不存在，它只在连续多组之间发作。本单元的实现把查表和写表严格写成 if (!limit && !lead)，并且每个 prefix 调用开头都清空 g_vis，就是为了把两条防线都立住。

把 lead 作为记忆化键的一部分（memo[pos][lead]）在数学上是对的，因为 (pos, lead) 确实唯一确定一个自由子问题。但 lead 为真的状态只出现在最高位那短短一段前缀上，缓存它几乎不省事，反而多一倍表和一次索引计算。竞赛模板普遍选择「只缓存 !limit && !lead 的那一类状态」，把复杂度留在 O(位数×10)。这是惯例，不是标准：写清楚为什么排除，比死记条件更重要。

9.8 前导零、数字 0 与 f(L-1) 的边界

三个边界值得单独拎出来，因为它们都不会让程序崩，只会让答案安静地偏一两个。

前导零不计数。 数字 13 的十位填 0 时，我们不是在写「013」，而是进入 0..9 这段。如果 lead 为真又填了 0，这个 0 没被写进十进制表示，所以第 27 行 cur = nlead ? 0 : ... 直接给 0。少了这个判断，统计 target=0 时会把每个数的每一位前导零都数进去，答案偏大得离谱。

数字 0 本身。 全前导零路径走到叶子时，我们得到的是数字 0。按题目「0 写成 "0"」的约定，它包含一个 0，所以第 18 行在 lead && target==0 时给 dig 加 1。这就是 [0,0] 统计数字 0 得到 1 的原因，对拍输出里专门打印了这一行。若你默认「0 没有数字」而漏掉这一步，所有含 0 的区间答案都会少 1。

f(L-1) 的 L=0 边界。 区间公式是 f(R) − f(L−1)，当 L=0 时 L−1 = −1。负数不能直接进 digit_count_prefix 的拆位循环：-1 % 10 在本机得到 −1，会被当成数字位去访问数组，越界。实现里第一句 if (x < 0) return 0 就是为这个边界准备的——0..−1 是空集，统计当然是 0。还有两个边界顺手记下来。一是 R < L：区间为空，答案应该是 0；实现里在 digit_count_range 的参数检查处直接拒绝，返回 −1，比默默算出 f(R)−f(L−1) 这个负数更诚实。二是计数类型：0..1e18 里数字 1 出现 1800000000000000001 次，已经超过 32 位有符号上限，必须用 long long；本单元所有前缀函数都返回 long long，正是为此。位数数组开 20 位也够用——1e18 只有 19 位，留一位余量；如果你把上界推到 1e19，先把数组和类型一起改，别只改常量。

陷阱你怎么会被坑到：把 0 当成「空的数」

你会看到什么？统计 [1, 13] 里数字 1 的出现次数得到 6，和暴力一致，于是以为前导零处理没问题；但统计 [0, 9] 里数字 0 时得到 0，暴力却说 1。你会怎么误判？以为是循环从 1 开始、漏了 0 这个数。真相是循环没漏，漏的是「0 这个数的十进制写法是一个字符 '0'」这个约定。数位 DP 里所有位都填 0 的路径必须单独结算，这正是叶子处 lead && target==0 那一行的作用。把这条约定写进题面理解，比事后调数字可靠。

9.9 数位和：同一套三参数换成另一个摘要

digit_sum 换了个问题：求 0..x 所有数的数位和之和。模板几乎不动，只把返回摘要里的「目标数字出现次数」换成「数位和总和」。当前位 d 对摘要的贡献是 d × 后缀个数——因为每个后缀填法都会配上这个 d。

lead 对数位和其实没有影响——前导零贡献 0，加不加都一样。但代码里仍保留这个参数、并继续用 !limit && !lead 作为记忆化条件，理由有两个：一是维持模板一致，换问题时不用重新推一遍缓存条件；二是这道例子还想示范「同一个状态定义换摘要」的迁移方式。真正需要 lead 的是上一节的「数字 0」统计，那一节已经把坑讲透了。

数位和还有个溢出陷阱值得顺带说清。0..1e18 所有数的数位和之和约为 8.1e19，远超 long long 上限 9.2e18；如果你打算把 digit_sum_prefix 推到 1e18，返回类型必须升级到更宽的整数或者取模。本单元的对拍数据只到 25000 左右，演示值 55，long long 绰绰有余——这也是对拍数据要小而密的另一个理由：它让你可以专心验证逻辑，不必同时和溢出搏斗。C++ 版用 std::int64_t 而不是 long long，是为了把宽度写进类型名；换到别的平台时它仍然保证 64 位，而 long 就不一定。

复杂度表还教了一件事：同一个算法在不同规模下的瓶颈会换。TSP 在 n=20 时瓶颈是内存（80 MB 的数组必须一次性放下），时间还有余量；如果 n 不变但距离改成 64 位，内存立刻翻倍，预算随之变紧。数位 DP 的瓶颈从来不是时间，而是「状态定义是否把边界和前导零都编码进去」——一旦漏了 limit 或 lead，复杂度再低也算错。所以表里那四列不能孤立地读：复杂度决定写法，n 决定能不能开表，耗时决定赛时敢不敢用，证据决定你信不信这个数。

再看三份 OK 200 各自守着什么。tsp-out 守的是「状态定义没写偏」：dp 与全排列两条完全不同的求解路径给出同一个最优值；digit-count-out 守的是「前导零与数字 0 处理对了」：演示里专门打了 [0,0] 统计 0 得 1 这一行；digit-sum-out 与 digit-sum-cpp-out 守的是「换摘要、换语言都不改变结论」。四份对拍共享同一套随机数据生成思路，但求解函数彼此独立——这是防止「两个人一起错还一致」的唯一办法。如果哪天你改了正解却忘了改暴力，让两边共享一个辅助函数，对拍就会失去意义。

9.11 这一节新增了什么

最后留一个带去赛场的判断清单。看到一道题先问三件事：状态要记住多少信息？这个信息能不能压成一个下标？规模 n 代进 2^n 或 3^n 后还在不在预算里？三样都对上了再动笔。状压的答案是「一位一个元素、集合当下标」，数位 DP 的答案是「按位填数、pos/limit/lead 三参数、只缓存自由状态」，轮廓线的答案是「只记当前那一行的占位」。它们不是三套互不相关的模板，而是同一个问题——用尽量少的 bits 描述局面——的三种回答。

回到 9.1 的第 3 帧逐个点名：

  • tsp_bitmask/ —— 状压 DP 与全排列暴力，200 组对称矩阵逐组比对；perf_main.c 真跑 n=20，把 80 MB 数组和 235–245 ms 钉在会话里；
  • digit_count/ —— pos / limit / lead 三参数数位 DP，返回 num 与 dig 一对摘要；limit 或 lead 为真时不写记忆化表；prefix(1e18) 与暴力 1e6 三次取值对照；
  • digit_sum/ —— 同一套模板换摘要求数位和，外加一份完整的 C++/STL 应用层程序参与对拍，构成原理层与应用层的双层证据；
  • session-tsp-perf.txt、session-digit-perf.txt —— 两份真抓终端，放耗时这类会抖的量；六份清单覆盖全部六个 output 块。

回看六个清单的命名也能读出工程层次：algo-tsp-bitmask 与 algo-tsp-perf 一对，algo-digit-count 与 algo-digit-perf 一对，algo-digit-sum 与 algo-digit-sum-cpp 一对。每对里前者证明结论、后者或补性能或补应用层。每个清单都指向本单元正文，正文里每个 output 块都被恰好一个清单认领，这套约定看着繁琐，实则是让「正文里的每个数字都能追溯到一次真实运行」变成机器可检查的事实。

下一单元讲 DP 优化：单调队列、前缀和、斜率优化。这一单元解决的是「状态里塞什么」，下一单元解决的是「转移太慢怎么办」——先看 n 反推该用什么状态，再看转移能不能压缩，顺序反了就会推不出式子还硬套模板。

小结这一节的要点
  • 状压的一位对应一个元素，1<<n 是集合上界；n≤20，dp[S][i] 铺成一维是 dp[S*n+i]，n=20 时数组 80 MB；
  • 子集枚举 for (s=mask; s; s=(s-1)&mask) 按数值严格递减地遍历全部非空子集，s-1 清最低位 1、&mask 去掉多余位；外层再枚举 mask 时总复杂度 O(3^n)；
  • TSP 的 dp[S][i] 是「走过 S、停在 i 的最小花费」，转移枚举下一个没去过的 j，答案补回 0 的边；n≤8 与全排列暴力 200 组一致；
  • 数位 DP 的 pos 是位置、limit 是是否贴着上界、lead 是是否仍在前导零；返回一对摘要让搜索参数保持三个；
  • 记忆化只在 !limit && !lead 时读写：limit 真时结果依赖 x 的后缀、lead 真时「还没开始写数」是另一种语义，两者都不是以 pos 为键的纯函数；
  • 前导零不计数、数字 0 写成 "0" 要单独结算、L=0 时 f(L−1)=0；区间答案统一走 f(R)−f(L−1)；
  • 轮廓线 DP 把「当前行的占位」压成 w 位掩码，复杂度 O(h·w·2^w)，指数上是宽度而不是格子总数。

注自测题答案
  1. 集合个数是 2^n，n=20 时 1048576 个；dp[S][i] 再乘终点维 n，得 2^20×20 = 20971520 个格子，每格 4 字节正好 80 MB。n=25 时数组约 3.4 GB，越过常规内存限制，所以经验上界取 20。
  2. s-1 把 s 的最低位的 1 清成 0，并把更低位全置 1；& mask 把不属于 mask 的位抹掉，保证新值仍是 mask 的子集。因为 s' ≤ s−1 < s，序列严格递减，所以同一个值不可能出现两次。
  3. 终点 i 决定下一条边从哪个城市出发。只记 dp[S] 就不知道这条最优路径最后停在哪，无法继续扩展到没去过的城市；答案处也无从补「回到 0」的那条边。
  4. limit 为真时，这一位及后面能填什么由 x 的尾部决定，同一个 pos 在不同 x 下结果不同，返回值不是以 pos 为键的纯函数。硬写会把贴边路径的偏小结果污染缓存，症状是多组对拍时偶发错误、单组重跑又正确。
  5. lead 为真表示还没写出任何非零数字，此时填的 0 是前导零、不进十进制写法，所以不计数。全前导零路径走到叶子得到的是数字 0，按约定写成 "0"，包含一个 0，必须在叶子处单独加 1。
  6. {0..R} 去掉 {0..L−1} 恰好是 [L,R]，两部分不重不漏，所以用差。L=0 时 L−1=−1，{0..−1} 是空集，f(−1)=0；实现里要在拆位之前判断 x<0 直接返回 0，否则负数取模会得到负的数字位并越界。
  7. 扫描到某个格子时，只需要记住已经铺好、且伸到当前这一行的那些骨牌占了哪些列，这条轮廓线的长度就是列数 w。更早行的信息已经用不到，格子总数 h×w 只是阶段（扫描步数），不进状态的指数。
