21.1 先看工程长什么样

上一单元（alg20）的线性 DP 是一条线：状态 dp[i] 只依赖前面的 dp[i-1]、dp[i-2]。这一单元把「前面的状态」换成两种更立体的形状——一段区间和一棵子树。状态从一维变成二维的那一刻，新手最容易卡住的不是转移方程，而是填充顺序：dp[i][j] 依赖 dp[i][k] 和 dp[k+1][j]，这两个区间都比 [i,j] 短，所以必须按长度从小到大填；树形 DP 的 dp[u] 依赖儿子的 dp，所以必须先儿子后自己。这两句话就是本单元的全部骨架，剩下都是往里面填肉。

照本书的规矩，先看看这骨架落成了哪些文件。

大白话先把两件事说成人话

区间 DP：你手上有一排石子，每次把相邻两堆合成一堆、代价是这两堆的总数。想让总代价最小，你可以先想「最后一刀切在哪」——最后一刀一定把整排切成左右两段，先把两段各自合成一堆，再合起来。于是「大区间的最优」由「小区间的最优」拼出来，小区间要先算好。

树形 DP：树上每个点做决定时只跟儿子有关。「这个点选还是不选」会影响儿子能不能选，所以你得先听完所有儿子的汇报，自己才拍板。这就是「先儿子后自己」——树的后序遍历。

把这两句话记住，本单元每一个公式都是在给它们写实现。

为什么区间和树形是很多人的第二道墙？线性 DP 的状态 dp[i] 只依赖「过去」，顺序是天然给的；一旦状态变成 dp[i][j] 或 dp[u]，依赖就变成「别的区间」「别的点」，填充顺序得自己构造。本单元反复只做一件事：把依赖关系画出来，然后按那个顺序填表。你每写一个新的 DP，先在纸上回答「这个状态依赖谁」，答案就是循环的顺序——这是比背模板可靠得多的习惯。

语法规则语法规则：区间 DP 的三层循环骨架

for (L = 2; L <= n; L++) 定长度 → for (i = 0; i + L <= m; i++) 定起点、算出终点 j → for (k = i; k < j; k++) 枚举断点。三层的含义依次是「先造短的积木」「这一层里从左到右摆」「试所有切法」。L 从 2 起：长度 1 的边界交给初值处理。

工程惯例工程惯例：为什么每个例子都要「正解 + 暴力 + 驱动」三件套

正解（区间 DP、树形 DP、换根）写得再干净，也可能在边界上错；暴力（枚举合并顺序、枚举子集、每根重新 BFS）慢得可笑，但一眼能看出对。两者在同一批随机数据上逐组比对，输出 OK 200——这是 alg02 定下的纪律，本单元四个算法全部过一遍。代价是每个算法多写一份暴力代码（20–40 行）；收益是「我以为对」变成「机器证实对」。更关键的是，本单元三份暴力的结构与正解故意不同：石子合并的暴力是「反复挑相邻对合并」，不是 DP 的「按断点切两段」——两份代码共享同一个错函数是对拍最常见的骗局，这里从源头避开。

这一节对拍的三份工程对应三类典型的「依赖关系图」：interval_stone 的依赖是二维表（每个状态依赖两个更短的区间），tree_independent_set 与 reroot_sum 的依赖是树（每个点依赖儿子，或父亲）。把这两张图看明白，你就不会在考场上把「先算谁」这件事交给运气——本单元所有看似不同的技巧，本质上都在回答这同一个问题。

21.2 区间 DP 三要素：长度递增、断点枚举、区间合并

先把状态定义钉死：f[i][j] = 把第 i..j 堆石子合成一堆的最小代价。注意区间是闭区间，且 i 可以等于 j。有了状态，三要素各回答一个问题：

要素 回答的问题 在代码里长什么样
长度递增 先算谁 外层 for (L = 2; L <= n; L++)，L 是区间长度
断点枚举 大区间怎么由小区间来 中层固定 i、算出 j，内层 for (k = i; k < j; k++)
区间合并 最后加上什么 f[i][j] = min(f[i][k] + f[k+1][j]) + sum(i..j)

三个要素缺一不可。只写断点枚举不控制长度，你算 f[i][j] 时 f[k+1][j] 可能还是 0（没算过）；只按长度不枚举断点，你只能处理「每次合并最左两堆」这一种顺序，丢掉所有别的可能。

状态定义里还有两个自由度值得提前说清。一是目标：同样是石子合并，可以求最小代价（取 min）、也可以求最大得分（取 max）、甚至求方案数（求和、相乘）；三要素的骨架不变，变的只是内层那个运算符。二是边界：f[i][i] = 0 是因为「一堆不用合」，这是问题本身给的，不是模板给的；换一道题，边界可能是 f[i][i] = a[i]（比如「单独这一段也算进得分」）。写新题时先单独把边界填进表，再开 L 循环，能省掉一半的调试时间。

大白话用「搭积木」解释填充顺序

把长度为 1 的区间想成现成的积木（一堆石子，不用合，代价 0）。长度 2 的区间是拿两块积木拼的，长度 3 的区间是拿「1+2」或「2+1」拼的……你不可能在 1 号积木还没造出来时就去拼 3 号。外层循环按长度 L 从小到大走，就是在按「积木的层数」一层一层造。每层里固定起点 i，右端点 j 就定了（j = i + L − 1），剩下的工作只是试所有切法 k。

为什么这样填是对的（最优子结构）：要证 f[i][j] 按转移式算出的就是最小代价，对区间长度 L = j − i + 1 做归纳。奠基 L=1：只有一堆，不需要合并，代价 0，calloc 给的初值正是它。归纳步设所有长度小于 L 的区间都已算对。考虑 [i,j] 的任意一种合并方案：它最后一步一定是把两堆合成一堆，而这两堆各自来自 [i,j] 的一个连续切分 [i,k] 与 [k+1,j]（相邻合并不会把不连续的两段并成一堆，这是「相邻」二字的直接后果），某个 k 唯一确定这一步。这一刀的代价是 sum(i..j)，与 k 无关；两堆各自的合并代价至少是 f[i][k] 与 f[k+1][j]——由归纳假设，表里存的正是各自的最小值，真方案不会比它更小。于是任意方案的代价 ≥ min_k {f[i][k]+f[k+1][j]} + sum(i..j)。反过来，取到最小的那个 k，先把 [i,k] 和 [k+1,j] 各自按最优方案合成（归纳假设保证存在），再付 sum(i..j) 合起来，恰好构造出代价等于右端项的方案。下界可达，f[i][j] 就是最小值。归纳完成。

注意论证里真正起作用的只有两条：最后一次合并必然切成两个连续子区间（相邻性），以及两个子问题互不影响（合并 [i,k] 的内部过程碰不到 [k+1,j]）。以后遇到别的区间 DP，先问自己这两条成不成立——成立了，同样的论证原样搬过去；不成立（比如转移要跨段），这模板就不能用。

用一个四堆的例子把三要素连起来：直线石子 [2,3,4,5]。长度 2：f[0][1]=5、f[1][2]=7、f[2][3]=9。长度 3：f[0][2]=min(f[0][0]+f[1][2], f[0][1]+f[2][2])+9 = min(0+7, 5+0)+9=16；f[1][3]=min(0+9, 7+0)+12=19。长度 4：f[0][3]=min(0+19, 5+9, 16+0)+14=28。三个断点分别对应「先合右边三堆」「先合中间两堆」「先合左边三堆」，min 取 28。你能在纸上把这三行填对，断点枚举就已经掌握了——注意每次的「过路费」分别是 9、12、14，都是本段石子总和，与断点无关。

陷阱你怎么会被坑到：长度从 1 起还是从 2 起

（先说你会看到什么）样例全对，n=2 也对；一到 n=3 以上的环形数据，答案稳定地偏小，偏的量恰好像「少算了一次合并的代价」。 （再说你会怎么误判）你盯着断点循环 k 的范围看了半天，怀疑 k < j 写成了 k <= j——因为「答案偏小」像是某次合并被漏掉了。 （最后说真相）外层循环写成了 for (L = 1; L <= n; L++)。L=1 时 j = i，内层 k 从 i 到 j−1 一个都取不到，best 停在 −1，于是 f[i][i] = −1 + sum(i..i)。如果 calloc 给的 0 被这个循环覆盖了，边界就烂了。正确写法是外层从 L=2 起（如 stone.c 第 14 行），把 L=1 完全交给 calloc 的零初值；或者坚持从 L=1 起，但在 L=1 时 continue 跳过。两种都对，不能又从 1 起又不跳过。顺带一句：best 用 −1 当「还没找到」的哨兵，前提是答案非负（石子数全正，代价必非负）——如果题目允许负权，这个哨兵就要换成 LLONG_MIN/4。

21.3 环形石子：复制一遍，别忘上界

直线上合并是「一排石子」，环形上合并是「一圈石子」——第一堆和最后一堆也相邻。处理办法只有一句话：把数组复制一遍接在后面，在长 2n 的数组上做直线 DP，答案在所有长度为 n 的区间上取最小。第 9 行的 a[i % n] 就是这次复制（不真的开新数组，取值时取模），第 26 行只扫 i = 0..n−1 的起点。

为什么答案只扫 n 个起点，而不是 2n 个？因为从 i 和从 i+n 剪开得到的是同一圈石子的同一个切法（数组复制了一遍，起点平移 n 格回到原位），扫 2n 个只是把每个答案算两遍，最小值不变。真正的坑在另一头：长度 L 的上界要开到 n 而不是 2n。L> n 的区间包含超过一圈的石子，那是假区间；而复制成 2n 长的目的恰恰是让起点 i>0 的长 n 区间 f[i][i+n-1] 有地方存——复制是为了下标够用，不是为了多算长度。

陷阱你怎么会被坑到：环形只复制不处理区间上界

（先说你会看到什么）复制完数组，你把外层循环顺手写成 for (L = 2; L <= m; L++)（m = 2n），心里想「既然复制成 2n 长，就把整张表填满」。样例 n=3 全对，n=8 的随机数据开始和暴力对不上，答案偏小。 （再说你会怎么误判）你怀疑前缀和取模写错、怀疑暴力漏了旋转，因为「偏小」像是少算了代价。 （最后说真相）L 跑到 n+1..2n 时，区间 [i, i+L-1] 里的石子总数超过一圈，前缀和却照算——你把同一批石子重复计了一遍，区间和虚高，而 DP 转而从这些「多算石子」的假区间里挑最小值，结果失真。修法只有一条：复制后，L 的上界仍是 n（stone.c 第 14 行）。记住这条口诀：复制管的是「区间起点能走多远」，长度上界管的是「一个区间最多装几堆」，两件事互不相干。

把上一节那四堆摆成一圈再走一遍：环形 [2,3,4,5] 复制成 [2,3,4,5,2,3,4,5]。起点 0 的长 4 区间就是直线的 [2,3,4,5]，代价 28。起点 1 的区间是 [3,4,5,2]——把剪开的位置挪到 2 与 3 之间：长度 2 得 7、9、7；长度 3 得 min(0+9,7+0)+12=19、min(0+7,9+0)+11=18；长度 4 得 min(0+18,7+7,19+0)+14=28，也是 28。起点 2、3 对称同理。这个手算验证了「n 个起点里取最小」确实在枚举所有剪法：每种剪法对应把圆拉直的一种方式，拉直之后区间 DP 给出的就是该剪法下的最优合并顺序。

21.4 括号匹配与最长回文子序列：同一张表问不同的问题

区间 DP 不只是石子合并。只要「大区间的答案由小区间的答案拼出来」，就能套三要素。**最长回文子序列（LPS）**是最好认的第二个例子：令 f[i][j] = s[i..j] 中最长回文子序列的长度。

  • 长度递增：L 从 1 到 n；
  • 断点：这里不枚举中间断点，而是看两端——s[i] == s[j] 时，这两字符可以配对，f[i][j] = f[i+1][j-1] + 2；不等时，两端不可能同时用，丢掉一个，f[i][j] = max(f[i+1][j], f[i][j-1])；
  • 区间合并：上面两条取 max 就是「合并」。

括号匹配问的是「给一个括号串，最少加几个括号让它合法」。把串扫一遍、用栈数「没被匹配的右括号」和「落单的左括号」，加的数量就是两者之和——这是线性扫描，不是区间 DP。但它的「配对」思想和 LPS 是同一件事：括号合法的本质是「左右括号能一一对上」，而 LPS 找的是「正反读一样」的子序列。真正需要用区间 DP 的括号题是「区间括号匹配」：问 s[l..r] 里有多少对括号互相匹配、或最少改几个字符能合法，这时令 match[i][j] 表示 i 与 j 是否配成一对，转移同样按长度递增、枚举断点 k，把 [i,j] 拆成 [i,k] 与 [k+1,j] 两段分别处理。

把三种「区间上做决策」的题并排看，差别会更清楚。石子合并的转移是 min(左+右) + 区间和，那个「区间和」与断点无关，是一次性付的过路费；LPS 的转移是两端相等时取 中间+2、不等时 max(去左,去右)，没有过路费；矩阵链乘的转移是 min(左+右+最左行×断点列×最右列)，过路费是三个维度的乘积。识别训练只有一句：先把过路费从 min/max 里提到外面，看看它是否真的与断点无关。提得出来，区间 DP 成立；提不出来（比如过路费依赖 k），说明状态切得不对，得换定义。

括号匹配的线性扫描也值得写清边界：扫一遍，遇到左括号压栈、遇到右括号时若栈顶是左括号就弹出、否则记一个「落单右括号」；扫完栈里剩下的都是「落单左括号」。最少要加的括号数 = 落单右括号数 + 落单左括号数。它之所以能线性做，是因为括号的配对是嵌套而非交叉的——后进先出正好描述嵌套。一旦题目问「区间 [l,r] 内有多少对括号互相匹配」，栈就不够用了（任意区间查询），得回到 match[i][j] 的区间 DP：i 与 j 配对时内部 [i+1,j-1] 的方案数加一，不配对时拆成两段分别算。这与 LPS 是同一副骨架，只是配对条件从「字符相等」换成了「左右括号匹配」。

21.5 树形 DP：先儿子后自己

现在换到树上。树形 DP 的状态挂在点上：dp[u] 表示「以 u 为根的子树里，某种条件下 u 的最优值」。「以 u 为根的子树」这个说法提醒我们：树上 DP 先要选一个全局的根（本单元固定 0 号点），子树、父亲、儿子都相对于它定义。

大白话用「开会汇报」解释后序遍历

把每个点想成一个部门经理。树形 DP 的决定是「我要不要在这个点做一件事」，而这个决定取决于下属的汇报。下属的汇报又取决于他们的下属……所以会议只能自底向上开：最底层的小组先总结（dp[叶子]），他们的头儿听完再总结（dp[父]），一层层传到总部（dp[根]）。「先儿子后自己」不是某条语法规定，是信息依赖逼出来的顺序。

发号用的栈里只存点号，每弹出一个点就把它没访问过的儿子压进去；栈是手写在堆上的数组（stk[n]），不是 C 的运行栈。这一点区别在链状树上就是生死之差：递归版活着的帧数 = 链长，本机 2MB 栈下两三万帧就到头；手写栈的格数虽然也等于链长，但它在堆上，4GB 量级的空间随你用。这种「把递归调用的位置显式存进数组」的做法叫手动栈，它的三种形态（帧级、点栈、显式状态机）在 ch05 已展开，这里只借用最省事的发号用法。

第二种写法的正确性只用到一个性质：父一定比儿子先发号。先发号时我们从根出发、只有走到儿子才给它发号，所以父在儿子前是构造出来的、不是碰巧；把发号序列倒过来，每个儿子就都排在父亲前面了。这比递归稳——不用赌评测机的栈。递归深度的账在 21.9 单独算。

21.5.1 顺带一提：树的重心

树的重心是树形 DP 的另一个常见落点，定义只有一句：删掉点 u 后，剩下的每个连通块大小都不超过 n/2，这样的 u 就叫重心（可能有一个或两个）。它为什么重要？以重心为根时，任何子树大小都 ≤ n/2——递归分治的规模每次至少减半，深度变成 O(log n) 而不是 O(n)。点分治、找「最优集合点」的题都靠它。

怎么求？正好用本节已经算出的 sz[]。以 0 为根，对每个点 u，删掉它后剩下的连通块有两类：它的每个儿子子树，大小 sz[v]；以及「父亲那边剩下的全部」，大小 n − sz[u]。取这些数的最大值 mx[u]，若 mx[u] ≤ n/2，u 就是重心。一遍后序算 sz、再扫一遍所有点算 mx，O(n) 完事。链 0−1−2−3 上，点 1 与点 2 都是重心：sz 分别是 3、2、1、1，mx[1] = max(2, 1) = 2 = n/2，mx[2] = max(1, 2) = 2 = n/2——两个重心相邻，这是重心可能成对出现的典型形状。

这与下一节的换根 DP 是同一套装备的两种用法：换根求的是「以每个点为根的距离和」，重心求的是「以每个点为根时最大子树的大小」——都是先把 sz[] 算出来，再把「把根搬走」翻译成一个只依赖 sz 的公式。21.7 的 up[v] 推导看懂之后，重心那句 n − sz[u] 就只是同一张图的另一半。

21.6 最大独立集：「选 / 不选」两行转移

树的最大独立集：选一些点，要求任意两个被选的点之间没有边（互不相邻），最大化被选点的权值之和。这是「先儿子后自己」最经典的落地。

状态拆成两个：dp[u][0] = u 不选时，u 子树内的最大权；dp[u][1] = u 选时，u 子树内的最大权。转移只有两行：

  • u 不选：儿子可选可不选，各取最优——dp[u][0] = Σ max(dp[v][0], dp[v][1])；
  • u 选了：儿子必不能选——dp[u][1] = w[u] + Σ dp[v][0]。

最终答案是 max(dp[root][0], dp[root][1])。

为什么对（归纳于子树大小）：叶子没有儿子，两式里的和都是空和（等于 0），于是 dp[叶][0]=0、dp[叶][1]=w[叶]——这正是「不选得 0、选得自身权」，奠基成立。归纳步设每个儿子的两个 dp 都已正确。考虑 u 子树内的任一独立集：若 u 不在集里，那么它在每个儿子子树里的部分都是一个独立的独立集（否则全局就有相邻两点被选），按归纳假设其权不超过 dp[v][0/1]，取 max 后再求和就是上界；反过来对每个儿子分别取到最优的方案拼起来，彼此互不相邻（u 没选，儿子之间本来就无边），上界可达。若 u 在集里，则任何儿子都不能在集里（独立集定义），u 子树内的选择被锁定为「u + 每个儿子子树里 u 不选的最优」，即 dp[u][1] 的两行式子。两种情况覆盖全部可能，dp[u][0/1] 正确。

「选/不选」这副骨架能迁移到一整类题。最小点覆盖（选最少的点覆盖所有边）和最大独立集是互补的：一个点集是独立集，当且仅当它的补集是点覆盖，所以「最小点覆盖 = n − 最大独立集」。最大权闭合子图则是「选了 u 就必须选它的所有后继」，与树上背包同属依赖约束——区别只在依赖方向由「父亲 → 儿子」换成「自定义的有向边」。至于点权可以是负数的情况，本单元的代码照样成立：dp[叶][1] = w[叶] 可能为负，但 dp[叶][0] = 0 提供「这个叶子我干脆不选」的退路，最终 max(dp0, dp1) 不会强迫你选负权点。对拍数据全用正权，是为了让「最大独立集」的含义直观；负权的正确性正是由这两行转移的结构保证的。

21.7 换根 DP：down / up 两次 DFS

前面的树形 DP 只回答「以 0 为根时的一个问题」。现在问题升级：对每个点 r，求「以 r 为根时，全树所有点到 r 的距离之和」。暴力做法是换一个根就重新 BFS 一遍，O(n²)，n=1e5 直接没戏。换根 DP 用两次遍历把它压到 O(n)。

大白话用「搬运动会会场」解释换根

先固定会场在 0 号点，算出全树到 0 的距离和。现在把会场从父亲 u 搬到它的儿子 v：v 子树里的 sz[v] 个点，离新会场各近了 1 步（总和减去 sz[v]）；其余 n − sz[v] 个点，离新会场各远了 1 步（总和加上 n − sz[v]）。一减一加，新答案立刻从旧答案算出来，根本不用重新 BFS。会场顺着树一层层往下搬，每个点只搬一次——这就是两次遍历的第二次。

符号约定：以 0 为根，sz[u] = u 的子树大小；down[u] = u 子树内所有点到 u 的距离之和（只含子树内部）；up[v] = 以 v 为根时，全树所有点到 v 的距离之和（含全树）。

第一次遍历（down，自底向上）：先看叶子，sz=1、down=0。对任意 u，把每个儿子 v 的子树接到 u 上：v 子树里每个点到 v 的距离是 down[v]，现在到 u 都要多走一条边 (u,v)，所以每个点各加 1、共加 sz[v] 个 1。于是

sz[u] = 1 + Σ_{v 是 u 的儿子} sz[v]，　down[u] = Σ_{v} (down[v] + sz[v])。

归纳于子树大小：叶子是奠基；归纳步里每个儿子子树的距离已经算对，加上跨过 (u,v) 这一条边的影响就得到 u 子树内的距离和。

第二次遍历（up，自顶向下）——这就是要亲手推的 up[v] 公式。设 u 是 v 的父亲，已知 up[u]（以 u 为根的全树距离和），要求 up[v]。把全树按边 (u,v) 切成两半：

  • v 的子树，共 sz[v] 个点。以 u 为根时，它们到 u 的距离 = 到 v 的距离 + 1；把根换成 v，这段「+1」不见了 → 每个点少 1，总距离减去 sz[v]。
  • 剩下的 n − sz[v] 个点（u 自己、u 的其他儿子子树、以及更上面的部分）。以 u 为根时它们到 u 的距离不含边 (u,v)；根换成 v 后，每个点都要多走一条边 (v,u) → 每个点多 1，总距离加上 n − sz[v]。

两笔合起来：

up[v] = up[u] − sz[v] + (n − sz[v]) = up[u] + n − 2·sz[v]。

地基是 up[0] = down[0]（以 0 为根时，全树就是 0 的子树，两个定义重合）。公式里 sz[v] 来自第一次遍历，所以两次遍历缺一不可。

复杂度为什么是 O(n)：第一遍按编号逆序扫一遍所有边，每条边被访问两次（两个方向各一次），O(n)；第二遍按编号正序扫一遍点，每个点只用父亲的 up 和自己的 sz 做一次常数运算，O(n)。两遍加起来仍是 O(n)——这是换根 DP 比「每根重新 BFS 一遍」的 O(n²) 快出 n 倍的根源。注意它不需要任何「按层」「按深度」的循环：编号顺序（父亲 < 儿子）已经把拓扑序免费送给你了。

如果题目问的不是距离和，而是「以每个点为根时，全树所有子树大小之和」，公式会不会一样？不会。根从 u 搬到儿子 v 后，v 的子树大小、v 祖先链上每个点的子树大小全变了，不再只有「近一步/远一步」两笔账。这类变体没有统一模板，必须回到「谁变、变多少」重新推。本节选距离和作代表，正因为它的变化只跨一条边、只影响所有点到新根的距离——两句话说完，公式就是 + n − 2·sz[v]。

还有一个工程细节：up 必须用 long long。n=4e5 时链上距离和约 n²/2 = 8×10¹⁰，远超 int 的 2×10⁹；本单元 perf 程序里 n=4e5 的校验和是 3636925963646（3.6×10¹²），int 存不下。换根 DP 的溢出不像数组越界那样会崩，它安静地给出错误答案——正因如此，逐组对拍才是它最可靠的保险丝。

陷阱你怎么会被坑到：换根公式除以 0 或重复计数

（先说你会看到什么）一种写法是先算「重心候选」再除以子树大小取平均，结果在链上的某些点得到 0 或巨大数；另一种写法是只加了 n − sz[v]、忘了减 sz[v]，答案随深度单调变大，和暴力差出两倍的深度量级。 （再说你会怎么误判）除以 0 的那种，你去查输入是不是有 0 号点没初始化；重复计数的那种，你怀疑 sz[v] 统计错了，反复检查 sz[u] += sz[v]。 （最后说真相）换根公式里没有任何除法。up[v] 是「距离之和」，不是「平均距离」；一旦你写出 / sz[v]，就是把问题偷偷换成了平均数，而某些没被用到的数组位置 sz 还是 0，除零当场发生（整数除零在这台机器上是访问违例，退出码 3221225477）。重复计数的根源是只想到「根搬远了，其他人多走一步」，忘了「子树里的人少走一步」——把同一次搬家同时看成「v 子树近一步」与「其余人远一步」，两笔都要记，公式才是 + n − 2·sz[v]。对拍里「每根重新 BFS」的暴力正是抓这个的：n=120 的随机树上，任何一处漏减都会在第 1 组就暴露。

21.8 依赖背包（树上背包）与 O(n²) 从哪来

还有一种树上 DP 值得单列：依赖背包（俗称树上背包）。题意是给一棵树，选一个包含根的连通点集，点数不超过某个上限，最大化点权和。「依赖」指选了某个点才能选它的儿子——父亲是儿子的前置条件。

状态 f[u][s] = 在 u 的子树里选 s 个点（必须含 u）的最大权。合并儿子 v 时，要从 u 已攒出的每个 s 与 v 的每个 t 组合：f[u][s+t] = max(f[u][s+t], f[u][s] + f[v][t])。这是一个两重嵌套的循环，与 01 背包的「倒序枚举容量」同构，只是容量换成了「子树里选了几个点」。本单元的实现见 tree_independent_set/src/treekp.c 第 18–36 行：

复杂度为什么是 O(n²)：把每次合并的代价记在「配对的点对」上。合并 u 与儿子 v 时，内层两重循环枚举的是「从 u 这边已处理的子树里挑一个点、从 v 子树里挑一个点」的配对；对每个无序点对 (x, y)，它在 x 与 y 的最近公共祖先处被配到，且只被配一次。所以总配对次数不超过 n²/2，加上每个点被访问 O(n) 次，总复杂度 O(n²)。容量上限 cap=n/2 时用 O(n·cap) = O(n²) 的空间。这个「点对只配一次」的论证，是判断一个树上背包有没有被写坏的试金石：如果你写出了 O(n³)，八成是某个儿子的状态在合并时被反复从头枚举。

把它和 01 背包对照，依赖感会更清楚。01 背包里每件物品彼此独立，倒序枚举容量保证「每件只选一次」；树上背包里儿子之间不独立——选了父亲才谈得上选儿子，所以状态必须按子树组织，容量也不能倒序一跑了之，而是「先把父亲自己放进 f[u][1]，再逐个儿子合并」。01 背包的容量是钱，树上背包的容量是点数；前者遍历物品列表，后者遍历儿子列表。把这条对应关系记住，你就不会在树上背包里写出「对每个点跑一遍 01 背包」那种 O(n³) 的代码。

21.9 陷阱集中：递归深度与本机 2MB 栈

前面三份树工程清一色用「发号 + 逆序」的迭代写法，不是风格洁癖。树形 DP 的递归写法 dfs(u){ for v: dfs(v); 算 dp[u]; } 看起来最自然，但同时活着的栈帧数 = 当前递归深度 = 从根到当前点的路径长。随机树上深度约 ln n，n=1e5 时只有二十几层，递归安然无恙；一旦树长成一条链，深度就是 n，1e5 层递归当场死亡。

本机的事实（来自 机器事实-算法篇.md 与 ch05 的 tree_recdepth/ 实测）：可执行文件默认栈保留 2MB（PE 头 SizeOfStackReserve = 0x200000）；那份递归 DFS 程序在 -O2 下撑到约 2.6 万帧、2.601 万被杀，-O0 下撑到约 3.25 万帧、3.26 万被杀。注意边界跟程序走：ch02 的递归并查集 find 在 -O2 下撑到 4.3 万帧，与这里的 2.6 万方向不同——帧大小随函数而变，连 -O0 与 -O2 谁活得多都可能反过来。所以任何具体数字都只能当量级参考，换程序、换优化档、换机器都要自己重测。

陷阱你怎么会被坑到：本地样例全对，评测机上一交就 RE

（先说你会看到什么）树形 DP 的递归写法在几十个点的样例上秒过；交到 n=1e5 的链状数据上，RE，本地重跑却复现不出来（你本地随手造的是随机树）。 （再说你会怎么误判）你怀疑数组开小、怀疑 dp 的下标越界——RE 的第一嫌疑总是它们；把数组加大一圈毫无效果。 （最后说真相）栈溢出。本机 2MB 栈、这类程序 -O2 下两三万帧就是天花板，评测机的栈通常更紧。诊断特征：进程无声死亡，没有段错误横幅；stdout 缓冲区整段丢失（除非开跑前显式 fflush(stdout)）。Git Bash 里 echo $? 报 127，闸门按无符号 32 位读是 3221225725（0xC00000FD，STATUS_STACK_OVERFLOW）。规则写在这里：凡是「深度可能等于输入规模」的递归——DFS、树形 DP、递归 find、递归线段树——一律改成迭代，或者先确认题目对树高有保证（比如明说「随机生成」）。本单元的「发号 + 逆序」就是把后序遍历搬到堆上的手动栈：顺序与递归逐点一致，深度只受堆大小限制（4GB 量级），不再看 2MB 的脸色。

  • 环形石子：复制一遍只为下标够用，长度上界仍是 n、答案只扫 n 个起点；只复制不收上界会把同一批石子重复计入；
  • 括号匹配线性扫描即可，区间括号匹配与 LPS 才用区间 DP；LPS 的转移看两端、没有附加代价项——「转移里有没有只加一次的项」是能否套区间 DP 的试金石；

  4. 不能。先序里父在儿子前，算 dp[u] 时儿子的 dp 还是空的，转移读到的是未定义值。发号 + 逆序的正确性只用到一条构造出的性质：发号时只有走到儿子才给它发号，所以父一定先于儿子进 order；把序列倒过来，每个儿子就都排在父亲前面，恰好是后序。它还是迭代的，不欠递归栈。
  5. 把根从 u 搬到儿子 v 时，全树按边 (u,v) 切成两半：v 子树 sz[v] 个点离新根各近一步（总距离 −sz[v]），其余 n−sz[v] 个点各远一步（总距离 +n−sz[v]），合并即 −sz[v] + (n−sz[v]) = n − 2·sz[v]。只写 +(n−sz[v]) 等于假设 v 子树里的点距离不变，实际上它们明明近了一步——漏减会让答案随深度单调偏大，每下一层多错 sz[v]。公式里没有除法；写 / sz[v] 是把问题换成平均距离且可能除零。
  6. 合并 u 与儿子 v 时，两重循环枚举的是「u 侧已处理子树里的一个点」与「v 子树里的一个点」的配对。每个无序点对 (x,y) 只在它们的最近公共祖先处被配到一次，总配对数 ≤ n²/2，故 O(n²)。若不保留旧的 f[u][s]（即「这个儿子一个都不选」的选项），第一次合并后 f[u][1] 就被覆盖成 −1，之后所有含该点的最优值都被污染，答案整片变负——正是我在 treekp.c 第 25 行修掉的那个 bug。
