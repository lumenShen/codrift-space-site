3.1 先看工程长什么样

排序那一章你已经会把数据排成升序；这一章回答下一个问题：排好了之后，怎么找。二分查找只有十来行，但它是竞赛里「写错率最高的十来行」——边界差一、mid 取整方向、答案位置，每一处都能让你在样例全过的情况下死在大数据上。所以照本书的规矩，先看这一节的工程：三个例子目录，每个都是「正解 + 暴力 + 对拍」或「接口 + 实现 + 驱动」的完整形态。

大白话这一节想让你先建立一个画面

把二分想成在一条已经排好队的长廊里找人：你站在走廊中点问一句「你比我要找的高还是矮」，答案让你直接丢掉半条走廊。四种写法的全部差别，只在两件小事上：

  • 丢半条时敢不敢把中点自己也丢掉——敢，就用 mid + 1 或 mid - 1；不敢，就把 mid 留在边界上；
  • 最后剩下的人是不是答案——有时是（写法一、写法四），有时答案在剩下那截的旁边（写法三的插入点）。

「二分答案」不过是把长廊从数组下标换成答案的取值范围：走廊中点不再是数组中间，而是「假设答案是 x」。

第 1 帧是动笔前的样子：ch03 的两个单元（排序、二分）都还没落盘，本节是这一章第一个成型的目录。第 2、3 帧是三个工程的骨架：每个都带 include/ 头文件与 src/ 实现，算法类例子还带 _brute.c 暴力——这是 alg02 定下的对拍纪律，本节三份对拍全部输出 OK 200。第 4、5 帧把「对照面」补齐：ovf 系列专门演示 mid=(l+r)/2 的溢出（含一份被 -ftrapv 杀死的进程），bsf_stl.cpp 是 STL 应用层，三个 perf_main.c 与四份 session-*.txt 支撑 3.10 的复杂度表。清单按程序一份，共十份，全部 mode: "run"（其中 algo-bsf-ovf-trap 是 runtime_error——它登记的就是那次真死）。

3.2 四种写法的前两种：lower_bound 与 upper_bound

先立参照系。本书所有「二分」话题里最该背下来的两个函数是 lower_bound（第一个大于等于 x 的位置）与 upper_bound（第一个大于 x 的位置）——不只是因为 STL 里就叫这两个名字，而是因为几乎一切二分问题都能翻译成它们：找「第一个满足某单调条件的位置」就是 lower_bound 换个判定；找「最后一个满足」就是 upper_bound 减一。原理层的写法一、写法二：

语法规则写法一 / 写法二的三个约定
  1. 区间是半开的 [l, r)，初值 l=0, r=n：r 从 n 起步，越界答案天然表达为「返回 n」。
  2. mid 取下整 l + (r-l)/2：分支是 l = mid+1 与 r = mid，没有 l = mid，下整不会造成区间不收缩（会出事的写法在 3.3 的写法四）。
  3. 答案是循环结束时的 l——不是 l+1。想找「最后一个 ≤ x」，答案是 upper_bound(x) - 1，先减一再用。

为什么不选闭区间写法来找「第一个」？因为半开区间的越界答案天然落在区间内：r = n 起步，「不存在」就是「返回 n」，不需要任何特判；闭区间版（写法三）找不到时返回 -1，「插入点」要靠另一个变量带出来。两个约定各让一步：半开区间送你「插入点 = 返回值」，闭区间送你「命中即返回」——按题目要哪个选骨架，比背四份模板省力。

还有一层更重要的认识：写法一的本质不是「在数组里找 x」，而是「在一条单调 0/1 链上找第一个 1」。判定条件不必是 a[i] >= x，任何「前缀全假、后缀全真」的谓词都行——「第一个失败的数据点」「第一个装载超限的时刻」「第一个能凑够 k 张的金额」都是它。后两节会反复回到这句话：3.6 的二分答案是把它用在答案的值域上，3.8 的二分求峰是把它用在「已越过峰」这个判定上。认出「这是个单调判定」的那一瞬间，你的手指已经知道该写什么了。

写法三换了骨架：闭区间 [l, r]、循环条件 l <= r、命中即返回——这是「精确查找」的形状，也是最像教科书的那一版：

三个分支把数组切成「小了、相等、大了」三份，每轮砍掉中点一个元素加半条区间。命中即返回是它与写法一的本质差别：返回的是「某个等于 x 的位置」，重复元素时不承诺第一个还是最后一个。对照输出里 x=4 命中下标 3——三个 4 里中间那个，而写法一给的是 2。两份代码都「对」，但对的不是同一个问题：要「第一个」就得用写法一，或者命中后继续向左扫。另一个细节：未命中时循环在 l == r + 1 处结束，这时的 l 恰好是插入点（第一个 ≥ x 的下标）——与写法一的答案完全一致，函数把它带回给调用方。

陷阱你怎么会被坑到：mid 不推进，程序「卡住不输出」

你会看到的现象：程序不输出、不崩溃、不退出，CPU 占着一个核。你会怎么误判：先去查输入循环、查数组边界，半天没结果。真相是：二分自己死了——分支有 l = mid 而 mid 取下整时，区间缩到 r = l + 1 就原地打转：mid = (l + r) / 2 = l，l = mid 什么都没变。修法二选一：mid 取上整（写法四），或改用写法一骨架（upper_bound(x) - 1）。口诀：分支有 l = mid 取上整，有 r = mid 取下整——一句管住两个方向。

错版程序把「永远」变成了可打印的事实（3.2 的 output 块最后一行）：x=9 的区间走到 (5, 6) 后，mid = (5+6)/2 = 5，a[5]=7 ≤ 9 走 l = mid = 5——区间从此一步不动，直到 100 步上限触发（返回 -2）。这份错版刻意留在 bsf.c 里而不是只写在纸面上，理由与 alg02 相同：能复现的 bug 才是教材，描述出来的 bug 只是传说。

顺着「答案差一格」再看一眼全景：四份写法加上一次减法，就能覆盖全部「找边界」类问题。设数组升序、查询 x：

  • 第一个 ≥ x：写法一（或 STL 的 lower_bound）；
  • 第一个 > x：写法二（upper_bound）；
  • 最后一个 < x：lower_bound(x) - 1（写法一的结果减一）；
  • 最后一个 ≤ x：写法四，或 upper_bound(x) - 1；
  • 等于 x 的有几个：upper_bound(x) - lower_bound(x)（3.9 的 equal_range 一次给全）。

这五行的正确性都由「前缀全假、后缀全真」保证，互相之间的换算就是 ±1——但每一行的边界都在换算时错一次：写法四的答案换成 upper_bound(x) 忘了减一，就变成「第一个 > x」，在重复元素上立刻偏一格。所以本节的对拍不只比对「写法四对不对」，还把「写法四 == 写法二 - 1」当成一条独立断言在 1e6 个查询上验过（3.10 的交叉校验行）——换算关系本身也值得进对拍，这是本单元想交给你的工程习惯。

标准原文标准原文：有符号溢出是未定义行为

If an exceptional condition occurs during the evaluation of an expression (that is, if the result is not mathematically defined or not in the range of representable values for its type), the behavior is undefined.

大意：表达式求值中出现「异常状况」——数学上无定义（除以零），或者结果超出该类型的表示范围（int 装不下 35 亿）——行为就是未定义的。语言不承诺回绕、不承诺报错、不承诺任何事情。

出处：ISO/IEC 9899:2018（C17）§6.5 第 5 条。

陷阱你怎么会被坑到：本地小数据全对，一上 1e9 值域就 RE

你会看到的现象：样例（下标几百几千）全过；评测数据值域到 1e9，交上去 RE 或者 WA。你会怎么误判：以为是数组开小了、或者递归爆栈——把 MAXN 改大一倍没用。真相是 mid 的加法在某个区间里回绕成了负数，a[mid] 从此是野读。修法只有两条，任选其一并养成肌肉记忆：int mid = l + (r - l) / 2;（减法先做，两项都不越界）或 long long mid = ((long long)l + r) / 2;（直接把算术升到 64 位）。值域二分（3.6）里 l、r 本身就是 long long，天然躲开；下标二分里请把 l + (r - l) / 2 写进手指。

顺带把「溢出」这件事的边界划清：无符号溢出有定义，有符号溢出没有。C 标准规定无符号运算是模 2^32 的算术（本机 unsigned int 回绕到 0 继续数），所以「计数器回绕」是一个可依赖的行为；而 §6.5 那条只管有符号类型——它连「回绕」都不承诺，编译器有权假设你的加法永不越界，并基于这个假设做优化：删掉你以为的防护（C 分册讲过的 n + 1 < n 判断就是被这样整删的）、或者把常量折叠成不含溢出路径的代码。这就是为什么本节的对照演示里，-O0 的回绕值与 -ftrapv 的中止能在同一份源码上并排出现：源码里的那句 (l + r) / 2 本身就没有语义，你看到的每个数字都来自「本机这一版编译器在这一次的选择」。竞赛代码里正确的反应不是「记下回绕值」，是不写会溢出的加法。

3.5 区间收缩的不变式：四种写法为什么都不会漏

四个函数，四个循环，凭什么敢信它们「不漏答案」？靠的是同一条模板的不变式，只是每种写法各自声明了「l 守什么、r 守什么」。这一节把四个合同逐一写清——赛场上改任何一行，都回来对着合同读一遍。

**写法一 / 写法二（[l, r)，r = mid 型）**的合同：答案永远在闭区间 [l, r] 里；同时 l 左边的下标全部不满足分界条件（太小），r 右边的下标全部满足（够大）。归纳基础显然（l=0, r=n 时两侧为空）。归纳保持：a[mid] < 分界 时 mid 及左侧全出局，l = mid + 1 不撕破合同；否则 mid 自己合格、右边全合格，r = mid 同样不撕破。每轮 r - l 严格变小（下整 mid 落在 [l, r-1] 里，两个分支都会动边界），循环必终止于 l == r，此时 [l, r] 只剩一个位置——它就是答案。

写法三（闭区间三分）的合同：[0, l) 全部小于 x，(r, n-1] 全部大于 x，中间的 [l, r] 是尚未分类的候选。命中分支直接返回（它找到的就是一个 x）；未命中时 a[mid] < x 把 mid 划进左半、a[mid] > x 划进右半，合同保持。循环结束 l = r + 1：左合同说「l 左边全 < x」，右合同说「l 右边（含 l）全 ≥ x」——所以这时的 l 就是插入点，这就是为什么未命中时插入点「白送」。

写法四（l = mid 型）的合同最有意思：r 右边全部大于 x（这条每轮都由 r = mid - 1 维护），以及**「若答案存在，则在 [l, r] 里」**——l 这边不维护「左边全 ≤ x」，只维护「a[l] ≤ x 或者 l 还没验证过」（初始 l = 0 未验证；l = mid 分支刚验证过 a[mid] ≤ x）。结束时 l == r：若 a[l] ≤ x，答案存在且只能是 l；否则数组里没有任何 ≤ x 的元素，返回 -1。这就是为什么写法四出口要再判一次 a[l] > x——它的循环不像写法一那样「顺带」验证了答案存在性。

四份合同的公共骨架值得单独说一句：「区间不变式 + 每轮严格收缩 ⇒ 终止于单点 ⇒ 单点即答案」。三步缺一不可——只背收缩不背不变式，你写得出代码但看不出哪一行撕破了合同；只背不变式不查收缩，死循环（3.3 的错版）就是你的归宿。

把这套论证完整走一遍（以写法一为例，其余三种同构）。命题 P(i)：第 i 轮循环开始时，答案 ∈ [l, r]。基础：P(0) 成立，[0, n] 装着一切可能。保持：设 P(i) 成立。本轮 mid ∈ [l, r - 1]（下整保证 mid 不会取到 r——否则 r = mid 不收缩）。若走 l = mid + 1 分支：数组升序给出「下标 ≤ mid 的全部不满足分界」，而答案若 ≤ mid 就与「mid 不满足」矛盾，故答案 ≥ mid + 1，P(i+1) 成立；若走 r = mid 分支：mid 自己满足分界，答案 ≤ mid 仍然成立（答案原本 ≤ r ≤ …，新的 r = mid 由「mid 满足分界且答案是第一个满足者」保证），P(i+1) 成立。终止：每轮 r - l 严格减小（两个分支都动了边界），所以至多 ⌈log2 n⌉ + 1 轮后 l == r。结论：P 的最终状态说「答案 ∈ [l, l]」，返回 l。

反证可以从另一头验一遍：假设循环正常结束时返回的 l 不是第一个满足分界的下标。那么真正的答案要么在 l 左边——不变式说 l 左边全部不满足分界，矛盾；要么在 l 右边——终态时 l 右边没有元素（l == r），矛盾。两条路都堵死。反证不会给你新信息，但它能检验归纳保持那一步你是否真的读懂了：哪一步说不通，回头补哪一步。

大白话不变式为什么要当合同读

写二分出错，九成不是「想不清算法」，是改代码时不知道哪一行动了合同。比如把写法一的 r = mid 手滑成 r = mid - 1：当 mid 恰好是答案时它被扔掉了，而数组里下一个合格元素可能不存在（查询比所有元素都大时，答案应该是 n）——程序照样跑、样例照样过，只有「查询大于全部元素」这一类数据会错。合同读法是机械的：改动之后，问一句「l 左边还是全不满足吗？r 右边还是全满足吗？区间每轮变小吗？」——三问全过才能存盘。这套读法同样管住 3.6 的值域二分和 3.8 的三分，只是「合同」里装的东西换成判定值和峰。

对拍把这四份合同交给机器抽查：200 组随机升序数组（n ∈ [1, 200]）、每组 40 个随机查询，四种写法与线性扫描逐个比对（3.2 output 块的 OK 200）。线性参照物故意写得笨——从左往右扫出「第一个满足」，从右往左扫出「最后一个满足」——笨到一眼看出对，才能当镜子。特别说明写法三的比对方式：命中时只验证「指向的值等于 x」（它本来就不承诺第一个），未命中时验证「插入点 == lower_bound」——对拍要按每份代码自己的语义比对，不能按你希望它的语义比对。

3.6 二分答案：把「求最优」变成「判可行」

现在把二分从数组里搬出来，搬到答案的取值范围上。题目：把一个正数序列分成恰好 m 段（每段至少一个元素），使「最大段和」尽量小。这就是经典的「最大值最小」—— maximize 的反面，赛场上以划分数组、砍树、复制文章等各种皮出现。

大白话「二分答案」在大白话里是什么

你不知道最优答案是多少，但你能回答另一个更简单的问题：「如果规定每段和不能超过 x，能做到吗？」——这个问题叫判定，它比求最优容易得多（贪心一遍就出结果）。于是把答案的取值范围想成一条长廊，从最小可能值走到最大可能值：判定在某个位置之前全是「做不到」，之后全是「做得到」——这条分界线就是最优答案。在长廊上二分，等于把「找最优」变成「找第一个做得到的 x」。你已经在 3.2 学过「找第一个满足」——写法一，把数组换成判定函数，骨架原样搬过来。

判定为什么单调？这不是显然的，值得写清：若 x 可行（存在一种分法每段 ≤ x），则任何 y > x 也可行——同一种分法直接照用，每段和没变，自然不超过 y。所以可行集合是「上闭」的：F…F T…T 的阶梯，存在唯一分界。二分答案的全部合法性都压在这一条上；反过来，若你写出的判定不单调（x 可行、x+1 反而不可行），二分就是错的——见到的每道「能不能二分答案」的题，第一件事都是论证这一条。

陷阱你怎么会被坑到：把 check 写成「求最优」而不是「判可行」

你会怎么误判：题目读多了，下笔就往 DP 上想——「把前 i 个分成 j 段的最小最大段和」，转移写得出来，n=1e6、m=1e5 时状态数 1e11，直接 MLE/TLE 双杀。真相是：「最大值最小」这四个字就是二分答案的招牌——判定的可行集合天然是上闭的（可行性随放宽条件单调上升），不需要构造任何额外结构。判据记两条：问「最大值最小 / 最小值最大」先试二分答案；判定的单轮代价必须是多项式的（这里是 O(n) 贪心），否则「总代价 = 单轮 × log 域宽」的账算不平。二分答案不是「高级技巧」，它是把写法一用在判定函数上——你的手指已经会了，缺的只是认出「这里的 l、r 不是下标，是答案」。

同一个题目还有第二张脸：把判定换方向，就能解「最小值最大」。比如问「分成 m 段，每段和的下限最大能到多少」——判定变成「每段和 ≥ x 时最多能切出几段」，x 越小段数越多，可行集合变成下闭的 T…T F…F，要找的是最后一个可行——写法四的骨架（或 upper_bound 语义）。两版骨架的差别只剩三处：初始区间（这次 l 要取「每段至少一个元素的最大下限」，即每个元素都 ≤ x 才切得出 m 段的方向）、收缩方向（可行就抬底 lo = mid，不可行压顶 hi = mid - 1）、mid 取整（有 lo = mid 分支就要上整——3.3 的口诀原样生效）。骨架不换脑，换的是判定与方向：这一节真正要背的不是「划分数组的代码」，是「判定 → 可行集形状 → 选骨架」这条推理链。

下界与上界的选取也有一套可复制的问法，别死记「max 与 sum」：问自己两个问题——「答案最小能小到哪？找到一个肯定可行的值（这里 sum 全装下），从它往右收缩没错；再找一个肯定不可行的最大值（这里 max - 1 之下全不可行），从它右边起步。」两问答完，[lo, hi] 就闭区间地装住答案，二分才有起点。常见错法是把 lo 直接取 0：多烧几轮判定不至于错，但若 check 在 x=0 处没写防护（cur + a[i] > 0 恒真、segs 一路涨到 n），返回的段数逻辑就靠 segs <= m 兜底——能过，但把「答案域」与「判定域」混为一谈的习惯，会在别的题（比如答案可以为负的题）上让你把可行域整个划出去。3.7 的实数域是同一问法的浮点版，那里 lo 从 0 起步是刻意的——浮点域没有「max - 1」这种整数邻居。

3.7 实数域：切木头、迭代次数与 eps

整数域的答案一个一个数得出来；实数域的答案在两个相邻 double 之间还有无穷多个，「第一个可行」没有意义，二分的写法与终止条件都要换。题目：n 根木头，切成至少 k 段等长木段（每段只能从同一根切出，不能拼接），段长最长能是多少。判定很直接：段长为 x 时，第 i 根能切出 floor(len_i / x) 段，总数 ≥ k 就可行。注意方向反了过来：x 越小段数越多，可行集合是 [0, x*]——这回要找的是最后一个可行，骨架从写法一换成写法四的实数版：

陷阱你怎么会被坑到：eps 选大错判，选小不收敛

这个坑的两个方向都真实存在于 3.7 的实测里。选大：eps=0.1 时程序 7 轮就「正常结束」、答案看起来有模有样（2.54 对 2.58）——你会以为算完了，错误悄悄混进答案；判断依据是题目精度要求（「保留 6 位小数」就把 eps 取到 1e-8 上下，留两位余量）。选小：eps=1e-16 时循环不退出，程序「卡住不输出」——和 3.3 的 mid 不推进死循环症状一模一样，你会误判成算法错。真相是 double 的表示精度有限：答案附近的最小间隔约 答案 × 2^-52，eps 低于它时区间冻结。修法三选一：eps 取「精度要求的 1/100」但别小于 ULP；把循环条件改成固定轮数（100 轮就是 2^-100 的收缩，对 1e9 域宽绰绰有余）；或者两者都用（本单元的 limit 上限就是保险丝）。赛场上最稳的一句口诀：实数二分先想轮数，再看 eps。

把「轮数公式」推导一遍，它以后可以口算。区间初始宽度 W（这里 8.79），每轮宽度减半，t 轮后宽度 W / 2^t；停在「宽度 ≤ eps」，即 2^t ≥ W / eps，t ≥ log2(W / eps)。代入验证：W=8.79、eps=1e-9 → log2(8.79e9) ≈ 33.0，实测 34 轮（多出的一轮是取整与「宽度正好压线」的边界效应）；eps=1e-4 → log2(8.79e4) ≈ 16.4，实测 17。轮数只跟 W 与 eps 的比值有关——n 根木头还是 1e6 根木头，每轮判定的代价变了，轮数一个字没变。这跟 3.6 的整数域形成一组对照：整数域轮数 = log2(域宽)，实数域轮数 = log2(域宽 / eps)，多出来的那一截就是你买的精度。

double 的表示能力也值得交个底：64 位浮点数有 52 位尾数，同一个量级的两个相邻 double 之间最小间隔约 该值 × 2^-52（2^-52 ≈ 2.22e-16）——换算成十进制大约 15–16 位有效数字。所以「保留 6 位小数」的题目，答案 1e6 量级时绝对精度要求 1e-6，ULP 约 1e-10，eps 取 1e-8 有两个数量级余量；「保留 9 位小数」时 eps 取 1e-11 也远没碰到 ULP。真正会被 ULP 咬到的只有两种人：eps 直接抄了「1e-15 更精确」的（3.7 实测的 1e-16 就是这种），或者答案本身带加减法把误差攒大了的（那是数值计算的另一门课，竞赛里少见）。一句话总结：eps = 题目精度 × 1/100，下限盯住 ULP，轮数上限当保险丝。

3.8 三分：严格单峰才配用

二分吃单调，那「先增后减」的单峰数组怎么办？峰值两侧各自单调，但整体不单调——a[mid] < x 这样的单一判定不存在。三分的答案是每轮取两个探针：在中点两侧各放一个 m1、m2，比它们的大小就能判断峰在哪一侧：

两个分支的「为什么敢砍」都要落在严格单峰上。a[m1] < a[m2] 时砍左边：若峰在 m1 或它左边，则 m1、m2 都在下降段（或 m1 就是峰），严格下降给出 a[m1] > a[m2]，与前提矛盾——所以峰必在 m1 右侧。a[m1] >= a[m2] 时砍右边：若峰在 m2 或它右边，则两点都在上升段，严格上升给出 a[m1] < a[m2]，同样矛盾——峰必在 m2 - 1 及左侧。相等的情形单独看一眼：a[m1] == a[m2] 时两点不可能同在一段（同段严格升降必不等），只能分居峰两侧，峰被夹在 (m1, m2) 之间——砍到 m2 - 1 仍然安全。这三次论证里每一次都用了「严格」二字：允许相等元素的单峰数组（平台）会让「同段必不等」失效，这就是为什么三分的前提必须写成严格单峰，以及为什么大纲说它「不该用在整数上，除非严格单峰」。

第 1 帧是上坡判定：m1 处 5、m2 处 7，右边更高，峰不可能在 m1 左边，l 跳过它。第 2 帧是下坡判定：7 对 4，左边更高，r 收到 m2 - 1。第 3 帧区间只剩两个元素，交给线性扫描收尾——整数三分必须留这一段线性收尾，因为「区间长度 ≤ 2」时两个探针会重合，再比就失去方向。

对照面是二分求峰：严格单峰数组上，「a[mid] 已越过峰（a[mid] > a[mid+1]）」这个判定本身单调——峰左侧全假、右侧全真，写法一换个判定函数直接用：

工程惯例工程惯例：整数上三分其实不划算

这是惯例判断，不是语法问题。严格单峰的整数数组上，判定「a[i] > a[i+1]（i 已越过峰）」是单调的——峰左侧全假、峰右侧全真，写法一换个判定函数就是二分求峰，本单元 tpeak_binary 就是这六行。账面对比（3.10 实测）：三分 31 轮 62 次比较，二分 20 轮 20 次比较；单次调用 40 ns 对 10 ns。三分的真正领地在实数域与黑箱函数：定义域连续、函数表达式可求值但不写导数（凸函数、单峰函数）时，三分是标准解法——那时「线性收尾」由 eps 接管（3.7 的规矩原样适用）。整数上拿到严格单峰数组，请直接二分；只有「单峰」没有「严格」，先想办法消平台（去重、扰动），再谈二分三分。

「为什么三分轮数更多」也值得算一遍账：二分每轮把区间砍到一半，t 轮后剩 W / 2^t；三分的两个探针把区间砍到三分之二，t 轮后剩 W × (2/3)^t——要同样缩到 1，三分需要 log_{2/3} W = log2 W / log2(3/2) ≈ 1.71 × log2 W 轮，每轮却花两次取值比较。总比较次数 2 × 1.71 ≈ 3.4 倍于二分的 1 倍，n=1e6 时的实测（62 对 20）与这个 3 倍出头的理论值咬合。实数域上写三分时，终止条件照抄 3.7：while (m2 - m1 > eps) 或固定轮数，limit 上限照留——浮点的两个探针同样会在 ULP 之内撞车，同样的死法，同样的药方。

还有一类「看起来能三分」的情形要拦一下：多峰函数与多段数组。反例已经演示了双峰数组的错法；实数域同理——函数先降后升再降（中间有个谷）时，两个探针比出的「上坡/下坡」不再指向全局极值。判定方法跟二分答案一样朴素：动手前问一句「这个函数（数组）在整个定义域上是不是严格单峰（凸）」，答不出就先画图、先造反例，或者改用别的方法（枚举峰的候选、先找谷再分段处理）。三分错起来不报错——它只是把「某个」局部极值给你，而你需要的是「那个」全局极值。

三个使用要点把 STL 二分用到底。其一，二分的对象不必是排好序的数组，可以是「排好序的谓词」：C++20 起的 std::partition_point(first, last, pred) 直接回答「谓词前缀真、后缀假的分界在哪」——它就是 3.2 那句「在单调 0/1 链上找第一个 1」的 STL 正名，本机 -std=c++23 可用。其二，排序一次、查询多次是这类函数的正确姿势：n 次查询各 O(log n)，总共 n log n，比「每次线性扫」的 n² 少两个数量级；但若查询只有两三次，排序本身 O(n log n) 反而贵——先估查询次数再决定排不排。其三，自定义比较器的版本 lower_bound(first, last, x, cmp) 里，cmp 必须与排序时用的比较器严格一致（同样的严格弱序），排序用 a < b、查询却传 a <= b 之类的错配，结果不是报错而是静默错位——与 alg07 讲比较器时的教训同源：比较器的一致性是约定，不是编译器能替你检查的。

什么时候直接用 STL？写对优先：它与手写版语义逐字对应、边界经过千锤百炼，赛场上第一遍先交它；什么时候手写？卡常数（3.10 的表给出量级）或者要在二分里夹私货（比如同时维护别的统计量）时。代价两边都摆清楚：STL 版多一层迭代器抽象，本机实测与手写版同在几十纳秒量级；手写版多你自己的一个 bug 面——用 3.5 的合同读法兜住。

小结这一节的要点
  • 四种写法的分界行各差一处：写法一/二只差一个等号；写法三换闭区间三分支；写法四分支走 l = mid，mid 必须上整——分支有 l = mid 取上整、有 r = mid 取下整，记反就死循环；

  1. 当 mid 恰好是答案（第一个 ≥ x 的位置）且再往右没有更合格的元素时出错——典型是「查询大于等于全部元素」这一类。r = mid - 1 把真正的答案扔出候选区，循环结束时 l 停在答案左边一格，返回值比正确答案小 1（偏小）；而正确语义下「全都比 x 小」应返回 n，错误版本会返回 n-1。
  2. 因为分支是 l = mid（mid 不能被扔掉）。卡死状态：r = l + 1 且 a[l] <= x——下整 mid = (l + l + 1) / 2 = l，走 l = mid 后 l 不动、r 不动，区间永远 (l, l+1)。本单元错版在 x=9 的真实轨迹：走到 (5, 6)，mid = 5，a[5]=7 ≤ 9，100 步上限触发（返回 -2）。上整 mid = l + (r - l + 1) / 2 把 mid 推到偏右，两个分支都保证区间严格缩小。
  3. 若 x 可行则任何更大的 y 也可行（同一种分法照用，每段和没变）——可行集合是上闭的 F…F T…T，存在唯一分界。二分维护的不变式「第一个可行点 ∈ [l, r]」才有意义：mid 可行压右界（答案 ≤ mid），mid 不可行推左界（答案 > mid）。本单元 check 的单调性来自「每段和的上限放宽只会让同样贪心切出的段数不变或更少」——段数随 x 单调不增。
  4. 区间宽度要求降到 1e-16，但 double 在答案 2.58 附近的最小间隔（ULP）约 5.7e-16：lo + (hi - lo) / 2 因舍入停回端点，mid 不再是区间内部的新点，hi - lo 冻结在 4.44e-16，循环永不退出（实测 200 步上限触发）。修法：eps 取「题目精度 × 1/100」且不小于 ULP；或改成固定轮数（100 轮即 2^-100 收缩）；或两者都用——轮数上限当保险丝。
  5. 三分给出下标 1（值 2），而线性扫描的真峰在下标 4（值 3）。它不崩溃的原因：三分的每一步都在做合法的比较与收缩，只是「相等 ⇒ 峰被夹在中间」的解读依赖严格单峰前提——双峰数组第一轮 a[1] == a[2] 时这个解读失效，真峰被整个砍出区间。整数严格单峰数组改用二分求峰：判定 a[i] > a[i+1]（峰右侧全真、左侧全假），写法一骨架 while (l < r) 收缩，六行（本单元 tpeak_binary），20 轮 20 次比较。
