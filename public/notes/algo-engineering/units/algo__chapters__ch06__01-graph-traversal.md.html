6.1 先看工程长什么样

图论的题千变万化，但它只做两件事：把图装进内存，再把它走一遍。装法决定了你能做多大的题——n=1e5、m=5e5 用邻接矩阵装，需要的内存是 40GB，竞赛机器直接判死刑；换邻接表，4MB 出头。走法决定了你能不能算对——BFS 与 DFS 的代码骨架一样，差在「用什么装待访问的点」，而这一点差别恰好就是「无权最短路」与「找连通结构」的分工。本单元不需要新的语言知识：C 结构体与指针数组（C 分册第 3、6 章）、malloc/calloc 的区别（第 6 章）就够了；C++ 层用到 vector 与 queue，对应 C++ 分册第 5 章。本单元三个例子各管一摊，先看文件。

第 2 帧是三个例子的分工：graph_storage 把同一张图装进三种存法、逐行对照（它不带暴力，因为它的「暴力」就是另外两种存法）；bfs_shortest 用 BFS 求无权最短路，对拍朴素松弛；bipartite_check 用染色法判二分图，对拍暴力枚举。第 3 帧把后两个补成标准的「正解 + 暴力 + 对拍」三件套，给 graph_storage 加上性能件（M12 的表全靠它）。第 4 帧是 C++ 应用层（M14）与一份真实抓取的耗时会话——正文里的每个数字都能追到这里。

6.2 把图装进内存：三种存法

大白话用大白话说三种存法

把图想成一个班级的「谁和谁认识」名单。邻接矩阵是一张 n×n 的大表格：第 u 行第 v 格写着「u 认识 v 几次」——查任何两个人要不要三步，但表格有 n² 格，班级一万人就是一亿格。邻接表是每人手里一张便签，只写自己认识的人——总字数正比于认识关系数，但想知道「谁认识我」得借全班的便签。链式前向星是把便签压扁进几条数组的账本：每条认识关系占一格，用链把同一个人的关系串起来——总内存一样小，还能顺手记下「这条关系的反向条目在哪」。

三种存法从同一个接口族开始。看帧的方式：第 1 帧先固定「图」本身——后面三帧都是这同一张图，换的只是装它的容器。第 2 帧的矩阵里请注意两个格子：mat[4][5] = 2 是重边并成的计数，mat[3][3] = 2 是自环（对角线）——矩阵用「数数」保住了重边信息，代价是 n² 的空间都为可能不存在的边付着。第 3 帧的邻接表里，同样的信息变成了「一行里写两遍」：4:[5, 5, 1]——不数数了，直接重复。第 4 帧的前向星则把这些序列藏进链里：第 0 行的链是 2 → 1，正好是加边顺序的反过来。三帧读下来应得一个结论：三种存法是同一份信息的三种编码，谁也不丢信息，差别只在空间常数与访问方式。看头文件里的三个结构体：

三个结构体摆在一起，就有了一个值得停一停的问题：C 里明明没有 vector，邻接表的「每行一条变长序列」是怎么落地的？答案是两遍计数：第一遍只数每个点有几条出边，做一个前缀和，得到每行在 adj 里的起点 row[u]；第二遍按加边顺序往各行里填邻居。这就是 C++ vector<vector<int>> 被「压平」之后的形态——教科书管它叫 CSR（Compressed Sparse Row），你只需要记住：每行的邻居是 adj 里连续的一段，row 数组是这段的起止。它值得单独看一眼，因为 6.10 里「邻接表遍历更快」的全部秘密都藏在这句「连续一段」里：

注意自环在这一版的处理：(3,3) 在第一遍给 row[4] 加了 2（两个方向各数一次），第二遍往第 3 行里写了两个 3——三种存法的账由同一条约定撑住：一条无向边 = 两条反向有向边，自环也不豁免。这条约定贯穿本单元全部三个例子与两个语言层，谁改了它，对照程序第 3 行的 3:[2 3 3] 就会当场对不上。

注补充：考场上 30 秒的三选一

读题时按这个顺序问，问完即停。**第一问：n 有多大？**n ≤ 5000 且题目要反复查「两点间有没有边」——矩阵，O(1) 查边的便宜才值得付；n 上万——矩阵出局（内存账在 6.10），直接在邻接表与前向星里选。**第二问：图是边读边建，还是先读完再建？**边读边建（多数题）——前向星，加边 O(1) 不需要预知 m；先把整个图读进边表再建（要排序边、要去重的题）——CSR 的两遍计数顺手。**第三问：要不要边下标当句柄？**要找反向边（桥、割边、网络流退流）、要按边存附加信息（边的编号、 belongsTo）——前向星的 e ^ 1 与槽位号就是为这些准备的。三问全否——两者皆可，选你抄模板最快的那份。这道流程不神秘，就是把 6.2 的选型表按「问」重排了一遍。

陷阱你怎么会被坑到：矩阵存重边，0/1 还是计数？

把边装进矩阵时最顺手的一行是 mat[u][v] = 1——赋值，不是累加。样例全对（小图碰不到重边），直到某个用例给了两条 (4,5)，你的矩阵里它还是 1：重边被静默吞掉一条。你以为只是「少记一条边」，后果却沿着算法走：边数 m 对不上、度数错、按 mat 数边数出的题直接错。误判方向也有讲究：有人改成 mat[u][v]++ 之后，又在「检查 u→v 是否有边」的代码里写 if (mat[u][v] == 1)——累加过的重边点变成 2，检查反而漏判。真相是：矩阵的格子语义要么是「0/1 有没有边」，要么是「计几条边」，全程序必须统一；本单元选「计数」（与列表、前向星的「逐条记录」对得上），所以判存在写 > 0、展开写循环。自环同理：赋值写法会把自环记成 1，累加写法（按本单元约定拆两次）记成 2——哪个对，取决于你的约定，而不取决于手感。

三行邻接序列值得逐字读：内容一样，顺序不一样。矩阵天然升序；CSR 按加边顺序（第 4 行是 5 5 1，先加的两条 4-5、后加的 1-4）；前向星是加边序的倒序（第 0 行 2 1，因为新边总插到链头）。这个差别不是瑕疵，是三种存法的天性，它直接决定了一件赛场上的事：BFS/DFS 的访问顺序跟着存法走。所以拿到一道题先问一句：答案依赖访问顺序吗？不依赖（距离、连通块数、染色、可达性）——存法随便挑，怎么方便怎么来；依赖（DFS 序、割点桥的编号约定、欧拉序）——存法与访问顺序必须一起写进模板、一起带上考场。6.2 输出的第 9 行把这句话演示得一目了然：同一个图、同一个起点，两种存法的先序是两个不同的序列，但点集分毫不差。

选型的结论先给出，6.10 用真实数字兑现：

存法 内存（无向 n 点 m 边） 查边「u→v 存在吗」 加一条边 适用
邻接矩阵 n²×4B O(1)，读格子 O(1) 改格子 稠密图、n ≤ 8000（256MB 口径）、Floyd/传递闭包
邻接表 CSR (n+1+2m)×4B O(deg(u)) 扫行 建图两遍计数，中途加边要重扫 静态图、遍历密集、缓存敏感

矩阵的 O(1) 查边听起来诱人，但内存的 n² 是硬上限：n 一到 8000 就撞 256MB 的竞赛上限，1e5 的图要 40GB——6.10 会真摸一遍给你看。邻接表内存 O(n+m)、邻居连续、遍历缓存友好，是「不知道什么时候该用什么」时的默认答案，但它建图前要知道 m（或者像 C++ 那样让 vector 自增长）。前向星与邻接表同阶，可加边 O(1)、无需预扫、边下标即句柄（6.3 的异或配对）——边读边建的题（输入一边给一边建图）几乎只有它能顺手做，所以赛场上最常见的模板是它。

还有一条边界现在就说死：n=1、m=0 的图——矩阵只有一个对角格、CSR 的 row 全 0、前向星 head[0]=0，三种存法都退化成「什么都没有」，BFS 返回层 0、连通块 1、无环二分图。它不是抬杠：数组开 n 还是 n+1、循环从 0 还是 1，这类「差一格」的错全在 n=1 上现形。边界不是空话，6.6 的生成器会把 n 压到 4，把 m 压到 0，专撒这种组。

6.3 链式前向星：to / w / next 与 head

大白话用大白话说前向星

每个点手里攥着自己那条链的链头号（head），链上每一节是一张「边卡」：正面写终点（to），背面写边权（w），卡片角落写着「我这张的下一张是几号卡」（next）。加新边不用找位置——领一张新卡，把它的「下一张」写成原来的链头，再把链头改成新卡号：四行，永远 O(1)。

边卡怎么落位，看内存图：

第 2 帧藏着本单元最值钱的一个设计：边编号从 2 起。0 号格永远空着，当「链尾」的哨兵（所以 for (e = head[u]; e != 0; e = nxt[e]) 自然终止）；1 号格也空着，让每条无向边占一对相邻槽位——于是 e ^ 1 恰好翻出它的反向边。为什么执意头插、不做尾插？尾插要么给每个点配一个「链尾号」（又一条 n 的数组），要么每次加边扫到链尾（一个度数 5e4 的点会把建图拖进 O(m·deg)）。头插只动两个格子，代价是「边的顺序与加入顺序相反」——而这个代价几乎永远无关紧要，因为遍历结果不依赖顺序（6.2 说过）。第 3 帧解释了遍历顺序为什么是倒序：链是头插的，最后加的边排最前。第 4 帧是自环与重边的处理：各占一对槽位，三种存法的账完全一致——「无向边 = 两条反向有向边」这条约定，自环也不豁免。

内存账顺手在这里算清。n 个点、m 条无向边的前向星要四个数组：head 是 n 个 int，to、nxt、w 各 2m 个 int——合计 (n + 6m) 个 int，n=1e5、m=5e5 时约 12.4MB。不存边权的无向图可以砍掉 w，降到 (n + 4m) 个 int 约 8.4MB；但本书建议永远带上 w：下一单元的 Dijkstra 建在同一个结构上，w[e] 一读就有，省得重建图。CSR 对应的账是 (n+1) + 2m 个 int 约 4.4MB——比前向星小三分之一，因为它不存反向指针（row 的前缀和把「下一条在哪」变成了算术）。这份账在 6.2 输出的第 11 行逐字打过，两处口径一致。

语法规则语法规则：前向星的四条约定
  1. head 一律 calloc 清零，0 是「没有边」的哨兵；遍历写 for (e = head[u]; e; e = nxt[e])。
  2. 边编号从 2 起：0、1 号格空着，第一条无向边占 2、3；e ^ 1 就是反向边（需要找反向边的单元：桥、网络流的退流）。
  3. 加边四行顺序固定：to、w、nxt、head——head 必须最后改，改早了 nxt 拿到的是垃圾。
  4. 数组开 2m（有向边 2m 条、每条一个槽位），m 是无向边数；有向图开 m 就够。
陷阱你怎么会被坑到：head 忘了清零

你把 head 写成 int head[N]; 放在函数里面（局部数组），建图、加边、遍历一路跑下来——输出完全乱掉，或者干脆访问违例退出码 3221225477。你误判成「前向星写错了」，回去检查 star_add 四行；真相是：局部数组不会自动清零，head 里是栈上的垃圾值，第一条加边的 nxt[ec] = head[u] 就把垃圾串进了链。全局数组侥幸对（全局静态区默认清零）——于是「在 main 里跑对的代码，搬进函数就崩」，这是初学者最困惑的一类症状。修法只有一句：head 用 calloc（或 memset），放在建图的第一行，别依赖任何隐式清零。本单元三个例子的 *_init / *_build 都把它当第一行。

陷阱你怎么会被坑到：从 2 起与从 0 起的两套习惯混用

前向星有两套同样流行的习惯。从 2 起（本单元）：head 清 0，0 当哨兵，e ^ 1 配对。从 0 起：head 全初始化成 −1，for (e = head[u]; e != -1; e = nxt[e]) 终止，配对同样是 e ^ 1（0^1=1、2^1=3……）。两套各自都对，混起来必炸：从 0 起的边号配上「head 清 0」——0 号边存在，head[u]=0 却被当成「没有边」，第一批边静默丢失，样例可能照样过（小图碰不到那条边），大数据悄悄错。查法：看三处——head 的初始值、遍历的终止条件、第一条边的槽位号，三处必须出自同一套习惯。从网上抄模板时最容易踩：抄了「从 0 起」的加边，配了自己「从 2 起」的 head 初始化。

6.4 BFS 分层：无权最短路为什么首达即最短

大白话用大白话说 BFS 分层

BFS 像水波纹：把起点按进水里，离起点近的先湿。队列里装的是「刚刚湿掉的点」，处理一个点，就把它的干邻居也弄湿、记上「比发现者晚一层」。于是队列天然按层排布：先全是一层的，再全是二层的——每个点被弄湿时记下的层号，就是它到起点的最短步数。这也正是「无权最短路」的答案：每条边代价一样时，步数就是距离。

跑在第 1 帧那张图上，队列与层的推进是这样的（图就是 6.2 第 1 帧那张，起点换成 0）：

逐帧读一遍：第 2 帧里 2 先入队、1 后入队，那是前向星头插的直接后果（0 的链是 2 → 1）——层内顺序跟着存法走，层号不跟着走：无论谁先谁后，两者 dist 都是 1。第 3 帧是「层与层交界」的样子：队列里 [3, 4] 两个都是层 2，3 是 2 发现的、4 是 1 发现的——同一层的点可以有不同的发现者。第 4 帧的两个细节值得圈出来：自环 3 → 3 被访问检查天然弹掉（3 已有 dist）；6 全程没人认领，最后仍是 -1——不可达不是「无穷大」，是「没人给过它值」，这正是用 -1 当「未访问」的语义。

为什么首次到达就是最短。两条不变式，一起撑起归纳：①队列里所有点的 dist 值单调不减，且最大与最小相差不超过 1（每次入队的值恰好是队头值或队头值 +1）；②任何时刻，dist 已赋值的点的集合，恰好是「起点加全部已出队点加全部在队点」。现在归纳地证主命题——每个点被赋 dist 的那一刻，dist 值等于它到起点的真实最短距离。d=0：起点赋 0，真值也是 0。假设所有真实距离小于 d 的点都已正确赋值并出队；考虑一个真实距离恰为 d 的点 v：它必与某个距离 d−1 的点 u 相邻（最短路的第一步），u 出队时扫描 v；若那时 v 尚未赋值，赋的正是 d（u 的 dist 正确加 1），成立；若 v 已被赋值，由不变式①②，赋值只可能发生在某个 dist 为 d−1 的点出队时，赋的值还是 d——不管谁先发现 v，写进 dist[v] 的都是同一个数 d。而队列的先进先出保证所有 d−1 层的点先于 d 层出队，扫描机会总在「更晚的层」能污染它之前。这就是首达即最短的完整论证：层单调性让它成立，队列纪律让它不出岔。

同一个问题反过来看 DFS 就知道为什么它不行：DFS 走的是「一条道走到黑」，第一个到达 v 的路径完全取决于遍历顺序，与距离无关。反例只要一个三角加一条尾巴：点 0-1-2 组成三角形，0 另有边连到 3。DFS（前向星序）从 0 出发先扎进 2、再 1、才轮到 3——到达 1 走了两步，而 1 与 0 直接相邻，最短路是一步。DFS 到达≠最短，因为它的「第一次」没有层单调性兜底。这一句话同时解释了两件事：无权最短路必须 BFS；而 BFS 的 dist 数组在 6.7 还能再利用一次——染色时把层号换成层号 mod 2。

两条工程备注，都是赛场手会问的。路径怎么还原：BFS 时顺手记 pre[v] = u（在赋 dist 的同一行），要输出路径就从终点沿着 pre 往起点倒爬、再反转——多花一个数组，不花任何时间。多源起点：把若干个「源」同时压进初始队列、dist 全置 0，之后的推导一字不改（归纳的 d=0 层换成「全部源」）——「多个起点同时扩散」这类题就是这么一行初始化的事。队列本身永远开 n 个格子就够：每个点至多入队一次，这是不变式②的直接推论，不需要环形队列也不需要扩容。

复杂度：每个点至多入队一次（入队即标记），每条有向边至多被扫一次，全图扫一遍 O(n+m)。这也解释了为什么连通块计数用同样的骨架——换个起点继续扫就是了：

正文输出第 7 行的「层0[0] 层1[2 1] 层2[3 4] 层3[5]」不是队列的直接读数——队列里层与层是混着流过的（交界处 [3, 4] 同层相邻，但队列从头到尾并不按层分块）。按层输出的两种写法：一是跑完 BFS 后按 dist 值分桶（开 n 个桶，dist 当桶号，一次线性归堆）；二是在队列里插「层界哨兵」——每层结束时压一个 −1，遇到哨兵就换行。两种都对，第一种不用改 BFS 本体，推荐。这也顺手解释了「出队序」这个词：6.2 输出第 7 行括号里写的「前向星出队序」就是队列真正的弹出顺序，它与「按 dist 分桶后的层内顺序」在层内可能不同——层号是数学，出队序是实现。

陷阱你怎么会被坑到：标记的时机——入队标，不是出队标

你会看到的现象：图里有环时，程序跑得极慢或者干脆超时；n=1e5、m=5e5 的图直接内存爆掉。误判：以为 BFS 本身慢。真相：你把「标记」写在了出队的位置（弹出时才置 dist 或 visited）。一个点在被弹出前，可能被多个已出队的邻居各扫到一次、各入队一次——二分图的两半互相指着，同一层的一半点全被重复入队，队列长度从 O(n) 涨到 O(m)，n=1e5 时就是几十万次重复扫描与内存浪费。更糟的变体是忘了标记：visited 永远不更新，环上的两个点互相指，弹出 v 发现 u「没访问」又入队，无限循环——BFS 变成永动机。规矩一句话：入队与标记写在同两行里，谁也不许搬走。本单元所有 BFS 的 dist[v] = dist[u] + 1 与 queue[qt++] = v 就是这一对。

6.5 DFS 与回溯、先序为什么随存法变

大白话用大白话说 DFS 与回溯

DFS 像走迷宫时顺着一条道走到黑：每到岔口挑一条没走过的钻进去，钻到头（或发现此路全是走过的格子）原路退回一格，再试下一个岔口。「退回」这个动作就是回溯——它在代码里就是一次函数返回（递归版）或一次出栈（迭代版）。BFS 用队列（先发现先处理），DFS 用栈（最后发现先处理），骨架一模一样，就换了这一个容器。

逐帧看这棵调用树。第 1 帧是「下潜」：dfs(0) 先递归 2、再递归 3，三层栈帧同时活着——此刻每一层都记着「我进来时的那条链还没走完」。第 2 帧是「回溯」：3 的链上全是访问过的点（两条自环加一条回边），函数返回，=> 箭头就是返回；2 同理。第 3 帧是「分叉」：0 的链走到 1，1 又带出 4、5——注意这是新的下潜，不是回到之前的路径。第 4 帧是「收尾」：5 返回触发一串连续回溯，一层层弹出；然后主循环发现 6 还没访问，另起一个 dfs(6)——新调用从栈底重新开始，这正是「6 属于第二个连通块」的代码形状。

递归版的 DFS 就三行核心，但它把「深度」这个变量押给了系统栈。赛场上更稳的是显式栈迭代版——把「当前点」和「当前链走到哪」一起压栈：

栈里两列并行：sn 是点号、si 是这个点的边链「迭代到哪张卡了」。第 2 帧的回溯在代码里就是 top--；第 3、4 帧的分叉与连续回溯对应「压栈」与连续「出栈」。访问顺序随存法变：对照程序打出的先序——前向星 0 2 3 1 4 5、邻接表 0 1 2 3 4 5（见 6.2 输出第 9 行）——两条路径不同，但访问的都是同一分量里的同一个点集。所以竞赛里凡是「结果与顺序无关」的题（连通块数、可达性、染色），存法随便换；结果依赖顺序的题（构造 DFS 序、找割点桥的具体编号顺序），先序约定要跟模板绑死。

两个常被追问的边界，顺手交代。**迭代版与递归版的先序一致吗？**一致——只要迭代版也「发现即标记」（本节代码第 186 行 mark[v] = 1 在压栈前），两者的访问顺序逐点相同：递归版的隐式栈里存的正是「这个点还没走完的邻居表」，显式栈只是把它搬进了自己的数组。**连通块计数还有别的口径吗？**有——第 2 章的并查集：把每条边 union 一次，剩下的根就是块数。两者的分工按「有没有全部边」分：边全部在手（离线），并查集一次扫完，不用第二次遍历；边要边走边知道（在线/交互），只能遍历。6.6 的对拍就是两边各做一遍再比对——同一条性质被两种机制算出来还相等，这比任何论证都硬。

陷阱你怎么会被坑到：递归 DFS 的深度等于 n，本机 2MB 栈撑不住

递归 DFS 写起来只要三行，深度却等于最长链的长度：一条 1e5 个点的链就是 1e5 层递归。本机的实测口径（第 2 章并查集单元探过、第 5 章线段树单元复测过）：可执行文件的栈保留量是 2MB，-O2 下递归 find 每帧几十字节，4.4 万帧就被系统杀死（退出码折算 127，闸门读 3221225725）；-O0 更早，3.3 万帧就死。帧大小随你的局部变量多少而变，边界数字必须换程序重测，但量级结论不变：n=1e5 的链状图，递归 DFS 在本机必死。判据随身带：看你的递归每层把「剩下的规模」除了几——每次减半（线段树、二分，深度 O(log n)）放心用；每次减一（链上 DFS、递归 find）改显式栈。6.5 的迭代版就是那条退路，跑 1e5 规模只用一个 n 大小的数组。

6.6 对拍一：BFS 对朴素松弛

BFS 的正确性论证在 6.4，但论证是人写的，人也会写错论证。对拍换个思路：找一个慢到不可能写错的暴力——朴素松弛（Bellman-Ford 的雏形）。它的全部逻辑是：反复扫全表，只要还能把某个距离变短就更新，直到一整轮没有任何更新。单位权下最短路不超过 n−1 条边，它必然停；停下来的就是答案，因为没有任何松弛还能改进。它不依赖队列、不依赖分层，只依赖「松弛」这个定义本身。

「不可达」的表示有一处值得较真：暴力里用的 0x3f3f3f3f（约 1.09e9）。它不是随手抄的魔法数——int 上界约 2.1e9，INF + 1 距离溢出还有一半余量，本单元的距离又只有 0..n−1 量级，所以松弛式 dist[a] + 1 < dist[b] 永远安全；要是用了 INT_MAX，第一次对不可达点做松弛加法就是有符号溢出，未定义行为。第 5 章线段树单元的 0x3f 抄法与这里是同一族纪律：INF 要选「加几次也不溢出」的值，并保证「INF 起点的边不松」（第 19 行的 dist[a] != BR_INF 就是这道闸）。

6.7 二分图判定：染色与奇环，两个方向都要证

大白话用大白话说二分图与染色

二分图就是「能分进两个小组、组内谁也不认识谁」的图。染色法是检验它的土办法：随便挑一个人进红组，他的熟人全进蓝组，蓝组的人的熟人全进红组……一路传下去。中途撞见两个熟人被分进同一组，图就不是二分图；全部传完没撞上，就是。BFS 染色的过程和 6.4 分层一模一样，只是把「层号」换成了「层号 mod 2」——同层同色、隔层异色。

前三帧是 6.2 那张演示图被染色一遍的过程——对照 6.4 的分层帧看，色号恰是层号 mod 2：层 0 与层 2 的点全是色 0，层 1 的全是色 1，这就是「颜色 = 到根路径长 mod 2」在实例上的样子。第 4 帧换了张图专门演示失败：三角形三个点两两相邻，染到第三个人必然撞上同色邻居——判定返回 0 的那一刻，第 43 行 color[v] == color[u] 抓住的边，就是充分性论证里「横边 + 两条到根路径」的那个原料。

二分图 ⟺ 无奇环，两个方向分开证。

必要性（二分图 ⇒ 无奇环）：设二分图按红蓝两色分好组，任取一个环沿着走。每走一条边就从一组跳进另一组，颜色交替——红蓝红蓝……走回出发点时必须回到出发时的组，于是步数是偶数。环长为奇时最后一步落不回原组，矛盾。所以二分图里环长全是偶数，奇环不存在。

充分性（无奇环 ⇒ 染色成功）：对染色算法做归纳。每个连通块从起点染 0。关键断言：算法给每个点 v 的颜色，等于「v 到本块起点的任何一条路径长度 mod 2」——归纳地看，树上的点由父亲推得（父子必异色），而任何一条到达 v 的路径最后一步都来自某个已染色的邻居，算法已验证「邻居与 v 异色」，于是 v 的颜色被约束得与起点路径奇偶一致；若存在两条奇偶不同的路径到达 v，把它们在最近的公共点处拼起来，得到一个奇环，与前提矛盾，所以奇偶性唯一，染色自洽推进、不撞同色。反过来，若算法真的报了「相邻同色」的边 (u,v)：u、v 在同一棵 BFS 树里，颜色等于树深度 mod 2（同色 ⇒ 深度奇偶相同 ⇒ 树上两条到根的路径长度和为偶），把这两条路径在最近的公共祖先处拼起来，再加上横边 (u,v)，恰构成一个奇环——判负时抓到的就是它。两个方向合起来：染色法报「是」当且仅当无奇环，报「否」当且仅当有奇环。

三句补充把边角钉牢。不连通的图：每个连通块独立染色（第 31 行的外层循环就是干这个的），块与块之间颜色分配互不干扰，任何一块撞同色即整体判负。为什么不能「数一数有没有环」了事：环的奇偶性不能靠「找到一个环看长度」——图里可能同时有奇环与偶环，只要有一个奇环就不是二分图；反过来「只找到偶环」也不代表没有奇环藏在没扫到的角落。染色法把判定变成一次 O(n+m) 的全图扫描，奇环的存在性在撞同色的那一瞬间自动证毕，不需要真的把环走出来。用 DFS 染行不行：行——把队列换成栈，逐层染换成递归回溯时染，判定结果一字不差（染色的合法性只依赖「相邻异色」这个约束，不依赖访问顺序）；本单元选 BFS 是为了让「颜色 = 层号 mod 2」的论证与 6.4 的层单调性共用一套语言。它为什么重要：二分图是第 7 章二分图匹配（匈牙利算法）的入场券——图不是二分图，那一章的全部机器都不适用；棋盘类的「黑白染色」也是它的直接应用。

陷阱你怎么会被坑到：自环让「显然是二分图」的图当场判负

你会看到的现象：测试数据里混进一个自环 (u,u)，你心算「一个点自己认自己，不算环吧」——输出却是非二分图，你以为染色写错了。真相：自环就是一个长度为 1 的奇环。按定义检验：u 的颜色必须与 u 不同——不可能；代码里 color[v] == color[u] 在 v==u 时永远成立，第 43 行当场判负，这正是定义的要求。同理 n=1 的单点图（无自环）是二分图：染色一次就成功、没有边可以撞。你若「顺手」在加边时跳过 u==v，判二分图反而会在真数据上翻车。对拍的枚举暴力对自环的行为与染色完全一致——bip_brute.c 里任何 mask 都过不了 cu==cv 的检查（自环两端永远同色）。重边则相反：不影响判定，两种颜色怎么摆都对。

复杂度顺手算清：H×W 的网格有 V=H×W 个点，4 方向最多 2V 条无向边（每条相邻关系一条），BFS 全图 O(V)——网格的「边」根本不占内存，它是按需算出来的，这正是网格题往往能开到 1000×1000 以上的原因：没有邻接表，只有 dist 数组（V 个 int，1000×1000 是 4MB）。变体也只有两处小改：八方向（斜着走）把 DR/DC 扩成 8 个偏移量，越界检查一字不改；走斜角要防「挤缝」（两个斜对角的墙之间斜穿过去算不算合法，题面说了算）——这类题的争议全在「能不能斜穿」，不在 BFS 本身。

大白话用一句话收拢这一节

网格不是新的算法，是同一个 BFS 换了个「邻居生成器」——从查链表换成查方向数组，把遍历纪律换成边界纪律。你在 6.4 学的层单调性在这里原样生效：网格最短路同样是「首次到达即最短」。

陷阱你怎么会被坑到：网格越界——三道检查一道都不能省

你会看到的现象：本地小地图全对，换个 1×N 或 N×1 的窄地图、或起点贴着地图边缘的用例，程序访问违例退出码 3221225477，或者（堆上越界更隐蔽）答案时对时错。误判：以为 BFS 队列写错了。真相是越界的经典组合拳：只判了下界没判上界（if (nr < H && nc < W) 漏了 >= 0 的检查，负下标读到数组前面去）、或者先读墙再判边界（walls[nr][nc] == '#' 写在越界判断前面，判断本身已经踩了别人的内存）、或者把行数列数用反（H 处用了 W）。规矩一句话：越界判断、墙判断、访问判断，三道依次排开，一道不省——顺序是「先算邻居坐标，判越界，判墙，判访问过，才落笔」。本单元对拍专门撒 4×5 到 7×9 的窄长网格，专抓这一手。

6.9 应用层：C++ 怎么写这一套

C++ 标准库给了你 vector 与 queue，邻接表就不必再手压 CSR、队列也不必手写下标——这就是应用层的分工：原理层讲清每一步为什么在，应用层换掉其中可以被标准库替代的零件。

收益：不用预估边数（push_back 自增长，不会像前向星那样开小 2m）、不用手写队头队尾、头文件一行声明完接口。代价有两条要说清：内存——vector<vector<int>> 是 n 个 vector 对象（每个 24 字节头）加各自的小块堆内存，同样的图比 CSR 多出几 MB 的零头（6.10 有实测账）；常数——std::queue 默认底下是 deque，比「一个数组两个下标」的队列慢一个可测的小尾巴，赛场上很多人还是用数组队列。

还有一个更隐蔽的差别：迭代器的失效规则。C 层前向星加边不搬动任何已有数据（头插只改两个格子），而 vector 扩容会整体搬家——如果你在遍历 adj[u] 的同时往图里加边（某些搜索题会这么干），C 层安然无恙，STL 层的 for (int v : adj[u]) 就悬在已释放的内存上。规矩：遍历时只读图；要边遍历边建图，先把本轮要入队的邻居收进自己的数组。所以现实中的分工是：懂原理的人用 STL 换生产效率，懂常数与失效规则的人在赛场上换回手写——两套你都得会读。

会话读出三层意思。其一，malloc 成功不等于装得下：40GB 的请求当场拿到指针——页文件给了「承诺」，而本机可用物理内存只有 19.65GB；只摸 1e5 个页就吃掉约 394MB 真内存、花 78ms，把 400 亿格全摸一遍要填满全部物理内存再往页文件倒腾，程序实际等于死。其二，真实开得到的规模：256MB（恰好 8192×8192×4）逐字节摸一遍只要 31ms，1GB 要 109–156ms——竞赛 256MB 上限下矩阵的极限 n≈8000，与本节算术严丝合缝。其三，遍历耗时：同样的 1e6 条有向边，CSR 的 BFS 3–4ms、前向星 15–17ms——CSR 的邻居在内存里连续一段，前向星的链在 to/nxt 两个数组间来回跳，缓存友谊差了一大截；DFS 同理（CSR 7–9ms、前向星 10–12ms）。前向星赢在加边 O(1) 与边下标句柄，遍历常数输给 CSR——选型时两头都要称。

第三层的「缓存友谊」值得把账算细一点，它正是 alg01 讲过的原理在图上的现身。CSR 扫一个点的邻居，读的是 adj[row[u]]..adj[row[u+1]-1]——一段连续内存，硬件预取器一次就搬进缓存行；BFS 的主循环里 90% 的访存都落在这种连续段上。前向星扫一个点，读 to[e] 与 nxt[e] 两个分散的数组、还要跳着改 e；更亏的是 dist[v] 的随机写——两种存法都要付这笔钱，但 CSR 把其余的钱都省了。5–6 倍的差距不是算法复杂度的差距（都是 O(n+m)），是访存模式的差距；它也顺带解释了 6.2 选型表里那句「静态图、遍历密集 → CSR」。竞赛图论题多半「边读边建」，所以前向星仍是默认模板——读入完成后再顺手把图转压成 CSR（一次两遍计数，4ms 的活），遍历密集的大题就能两头都占。

表中「同图 CSR BFS 0.0 ms」那半句也要交代：n=8000 的 CSR 全图 BFS 只要不到 1ms，落进了 clock() 的 1ms 分辨率之下，打出来就是 0.0——不是真的零耗时，是量不到。要量它得把同一操作重复几百次取平均（机器事实篇的规矩），这里不必：结论「矩阵 65–82ms 对 CSR <1ms」已经足够悬殊，再精确两位小数不改变任何判断。

6.11 这一节新增了什么

回到 6.1 的第 2–4 帧逐个点名：

  • graph_storage/ —— 同一张图三种存法：include/storage.h 一份接口三个结构体，src/storage.c 里矩阵、CSR（两遍计数）、前向星（异或配对）三套实现，外加迭代 DFS；main.c 逐行对照邻接序列、打 BFS 分层与 DFS 先序；perf_main.c 量建图与遍历耗时、真演示矩阵 40GB 装不下（malloc 承诺 + 摸页实测）；session-perf.txt 是三次运行的真实会话，M12 表中所有时间区间的出处；
  • bfs_shortest/ —— BFS 分层对朴素松弛 200 组（外加连通块对并查集），网格方向数组对「拆边表暴力」200 组；src/ggraph.c 的 BFS 与 6.4 的证明逐行对应，src/bfs_brute.c 的暴力只依赖松弛定义；

下一单元把边权请回来：同样建在链式前向星上的 Dijkstra 与 Bellman-Ford——本单元的 dist 层号会变成「到起点的最短边权和」，朴素松弛这个对拍暴力会直接升级成算法本体，而「入队即标记」也要让位给「出队才算定型」。把本单元的三个骨架（前向星、BFS 主循环、朴素松弛）写熟，下一单元就只剩「什么时候敢弹队头」一个新问题。

小结这一节的要点
  • 三种存法一本账：矩阵 n²×4B（n≤8000，256MB 口径）、CSR (n+1+2m)×4B、前向星 (n+6m)×4B（带权无向图）；矩阵查边 O(1) 但装不下大图，CSR 遍历缓存最友好，前向星加边 O(1) 且 e^1 即反向边；
  • 前向星四件套：head calloc 清零、边号从 2 起（0 哨兵、1 让配对落位）、加边四行顺序固定（to、w、nxt、head）、数组开 2m；从 2 起与从 0 起两套习惯不许混；
  • BFS 首达即最短，靠两条不变式：队列 dist 单调不减（首尾差 ≤1）与「已赋值集合」的刻画，归纳对每个 d 收口；连通块计数、染色都是同一骨架换赋值内容；
  • DFS 的回溯 = 出栈/返回；显式栈版把「点 + 链迭代器」一起压栈，先序随存法变而访问集合不变；递归版深度 = n，本机 2MB 栈 4.4 万帧被杀（ch02 口径），链上遍历一律迭代；
  • 二分图 ⟺ 无奇环：必要方向走「颜色交替、回到起点必偶数步」；充分方向靠「颜色 = 到根路径长 mod 2」与「同色横边 + 两条到根路径拼出奇环」；自环是长度 1 的奇环，当场判负；
  • 网格图三道检查依次排开：越界、墙、访问过；方向数组只是常量表，纪律在顺序；
  • 实测（n=1e5、m=5e5）：建图 CSR 4–5 ms / 前向星 2–3 ms；BFS CSR 3–4 ms / 前向星 15–17 ms；矩阵 n=8000 的 BFS 65–82 ms 对 CSR 同图 <1 ms；malloc 40GB 会「成功」，摸 1e5 页耗 78ms 与约 394MB 真内存——承诺不是内存；
  • 本单元三个 OK 200（BFS、二分图、C++ 层）全部出自固定种子 LCG / mt19937，重跑逐字一致。

注自测题答案
  1. nxt[e] 写的是「加这条边之前 u 的链头」——把新边挂上旧链；head[u] 写的是新边的槽位号——链头换成它。head 必须最后改：前一行 nxt[ec] = head[u] 要读旧的 head，先改就丢了旧链。顺序倒了，整条链断头。
  2. 0 号格当「链尾」哨兵（遍历终止条件 e != 0），1 号格让第一条无向边落到 2、3 号槽位、保住 e ^ 1 的配对。改从 0 号起存，「0 当哨兵」与「0 号有边」打架——第一批边被当成「没有边」静默丢掉；要修就得把哨兵换成 −1（从 0 起那套的 head 初始化），三处（初始化、终止条件、起始边号）必须一起换。
  3. 不变式①：队列里 dist 单调不减且首尾差 ≤1；不变式②：已赋值的点恰是「已出队 + 在队」。归纳：真实距离 d 的点必邻接某个已正确赋值 d−1 的点，后者出队扫描到它；若它已被赋值，由①②只能是被另一个 d−1 层点赋的同一个值 d。所以无论谁先发现，写入的都是真实最短距离。
  4. 设同色边为 (u,v)。染色时颜色 = BFS 树深度 mod 2，同色 ⇒ u、v 深度奇偶相同 ⇒ 各自到根的树上路径长度和为偶。取两条路径在最近公共祖先处分岔：从 u 上行到 LCA、再下行到 v，加上横边 (u,v)，闭合成环，长度 = 两条路径长之和 + 1，为奇数。
  5. 矩阵 40000000000 字节（37.25 GiB）；CSR 4400004 字节；前向星 12400000 字节。malloc 不失败——本机实测它当场返回非空指针，那是页文件给的「承诺」；可用物理内存只有约 19.65GB，只摸每行第一个格子（1e5 页）就实测消耗 78ms 与约 394MB 真内存，全表摸完要填满物理内存再倒进页文件——所以竞赛按 256MB 口径只给 n≈8000， malloc 不报错不算数，摸得到才算数。
