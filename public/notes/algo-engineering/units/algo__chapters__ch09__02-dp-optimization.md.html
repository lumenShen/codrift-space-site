23.1 先看工程长什么样

这一单元有三个例子工程，都在 examples/ch09/ 下：窗口最小值转移、前缀和转移、任务安排的斜率优化。每个目录仍然是「正解 + 暴力 + 对拍驱动」三件套，斜率那一组还多一份 C++/STL 应用层程序。第 1 帧是这一章开始时的草稿形态，第 2 帧是三个工程落地，第 3 帧是补上清单与真抓会话后的最终形态。

大白话先建立一个画面，再谈优化

把 DP 想成填一张表。每填一格，你都要回头翻一堆旧格子，把它们的值合并一下。普通写法是「翻一遍、算一遍」，填 n 格就翻 O(n²) 次。优化的窍门只有一句话：旧格子被反复翻的时候，翻的那部分如果只跟旧格子自己有关，就提前算好、排好队，用的时候直接拿走。三种优化的区别，只是「提前算好的那部分」长什么样——一个最大值、一个前缀和、还是一条直线。

第 2 帧三个目录正好对应三种「提前算好」的东西：opt_mono_queue 提前算的是 dp[j]+b[j] 的最大值，opt_prefix 提前算的是 dp 的前缀和，opt_slope 提前算的是一条直线。第 3 帧的 session-*.txt 不是装饰：耗时每次都抖，进不了 output 块，只能抓成会话文件再用 file= 注入正文。三份 perf 清单负责把三次取值与 O(n²) 的外推点留在 stdout 的可复现结论旁边。

工程惯例工程惯例：优化的例子为什么必须留暴力

标准没规定优化例子要配暴力版，这是本书的惯例。理由很实在：优化版建立在「我推导的等价式子」上，如果式子推错了，它自己不会报错，只会安静地给出偏小或偏大的答案；暴力版直接按题目原话枚举，不共享这个前提。三个目录的驱动都在程序内跑 200 组固定种子随机数据，逐格比对正解与暴力，最后打 OK 200。代价是要多写一个明显正确的慢版本，并且要保证它真的慢而正确——第 8 单元踩过「基准和选手共享同一个错函数」的坑，这里不会重犯：正解与暴力共享数据生成方式，绝不共享求解函数。

23.2 什么时候能优化：先看重复的那一段依赖谁

先别背模板。拿到一条转移，先把它写成「固定的部分 + 随 j 变化的部分」，再看变化的那部分落在哪种结构上。

最典型的转移长这样：dp[i] = min 或 max over j of { A(i) + B(i) × f(j) + g(j) }，其中 A(i)、B(i) 只跟当前格 i 有关，f(j)、g(j) 只跟旧格 j 有关。三种优化的分界线就在这里：

  • 如果 j 的取值范围是一个滑动窗口 [L(i), R(i)]，而 B(i) 恒为常数，那么 A(i) 是加在所有候选上的同一个数，候选之间只比 g(j) 的大小——用单调队列维护窗口里的最优 j。
  • 如果 B(i) 也恒为常数、但合并方式不是取最值而是求和 sum g(j)，那么用前缀和把区间和变成两个前缀值之差。
  • 如果 B(i) 随 i 变化，但 B(i) 与 f(j) 的乘积能拆开，转移就变成「在一堆直线里，找一条在横坐标 B(i) 处取值最小的」——用凸包（斜率优化）。
大白话用大白话说三种优化的共同点

你在食堂打饭，每次都要问「现在哪一队最短」。笨办法是每次把所有队伍都看一遍。聪明办法是：队伍长度变化时顺手记一下，谁最短永远写在门口牌子上——这就是单调队列。如果问题不是「哪队最短」而是「这几队一共多少人」，你就记一张累加表，要用哪段就做一次减法——这是前缀和。如果每次问的「最短」标准会变（比如按不同的身高权重算），你得把每队画成一条线，按当前标准找最低的那条——这是凸包。三件事的共同点都是把重复翻旧账的工作提前摊到每次更新里。

语法规则三种可优化形状的判定式
  1. 单调队列：dp[i] = A(i) + max/min_{j in [L(i),R(i)]} g(j)，且 L(i)、R(i) 随 i 单调。装进队列的是 g(j) 和它的下标 j。
  2. 前缀和：dp[i] = A(i) + sum_{j=L(i)}^{R(i)} g(j)，且 g(j) 只依赖已算好的旧格。维护 pre[t] = sum_{s<t} g(s)，区间和是 pre[R+1]-pre[L]。
  3. 斜率优化：dp[i] = A(i) + B(i)·f(j) + g(j)，且 f(j) 单调、B(i) 单调。令直线 j 为 y = -f(j)·x + g(j)，在点 x = B(i) 取最小值。

把一条转移真的拆成这三种形状，需要一点手感。拿一道常见的平方代价题练手：

dp[i] = min{ dp[j] + (sum[i] - sum[j])² : j < i }，其中 sum[i] 是前缀和。

括号里的平方一展开就露出原形：sum[i]² + sum[j]² - 2·sum[i]·sum[j]。第一项只跟 i 有关，提到 A(i) 里；剩下的 dp[j] + sum[j]² - 2·sum[i]·sum[j] 可以写成 Y[j] - m·X[j]，其中 X[j] = 2·sum[j]、Y[j] = dp[j] + sum[j]²、m = sum[i]。于是它也是斜率优化——斜率来自那个同时黏着 i 和 j 的乘积项，不是来自题目里显式出现的「斜率」二字。这正是很多人卡住的地方：他们以为斜率优化的标志是题面写着一条直线，其实标志是转移展开后出现了 -m·X[j] 这种可分离的乘积。

再看一个反面：若代价换成 w(i,j) = (i-j)² + a[i]·a[j]，展开后多出一个 a[i]·a[j]，它同样是「i 的量 × j 的量」，可以并进 m = a[i]、X[j] = -a[j]；但前提是 a[i] 与 a[j] 都有序。如果 a 是任意顺序的输入，m 就不单调，凸包模板不能直接套，得换成二分凸包或李超线段树。拆分的手感来自多做几次「展开平方、按 i/j 分组」的练习，而不是背三种模板的名字。

三条判定式里最关键的是「只依赖旧格」这五个字。如果 g(j) 里混进了 dp[i] 或别的还没算出来的量，上面三种结构全都不成立。还有一个常被忽略的前提：单调队列要求窗口两端随 i 单调移动，凸包要求插入的斜率与查询的横坐标都有序；这两个前提一旦不满足，优化版会比暴力版还慢，甚至直接算错。

也别以为「能写出式子」就等于「能优化」。有些转移看着像窗口最值，其实 w(i,j) 同时黏着 i 和 j，拆不开；有些转移看着像求和，其实求和的项要等 i 定了才能算。这一类症状放在 23.7 统一讲，先看三个能优化的正面例子。

动手前可以把下面四问当清单过一遍，每问都要求你写出具体式子，不许只在心里点头：

  1. 固定项是什么？ 把转移里所有只依赖 i 的量提到括号外，写出来记作 A(i)。提不干净说明状态定义可能有问题。
  2. 变化项是什么？ 括号里剩下的部分，是否只含 j 与已算好的前缀量？含 dp[i] 就立刻停手。
  3. 合并方式是什么？ 取最值走单调队列或凸包，求和走前缀和。写成「次大值」「前 k 大」的，三种都不适用。
  4. 有序性成立吗？ 窗口两端是否随 i 单调？凸包斜率与查询点是否都单调？把输入里可能出现的最小、最大值代进去试一遍，别只看样例。

这四问的答案能连成一句话，就可以动手写正解；写不出那句话，先别碰模板。本单元三个例子的源码注释都把这四个答案写在了函数开头——不是给编译器看的，是给三天后回来看自己代码的你看的。

23.3 单调队列优化：把 dp[j] 和它的奖励装进队列

题目是这样一串格子的 DP：dp[0] = a[0]；对 i >= 1，

dp[i] = a[i] + min{ dp[j] + b[j] : max(0, i-k) <= j <= i-1 }。

a[i] 是本站的收益，b[j] 是从 j 跳过来时拿到的一笔奖励，可以是负数。暴力版对每个 i 把窗口里的 j 全扫一遍，是 O(n·k)；k 开到 n 就是 O(n²)。注意 a[i] 只跟 i 有关，对所有候选一视同仁——它就是判定式里的 A(i)；括号里的 dp[j]+b[j] 只跟 j 有关，这就是要装进队列的 g(j)。

大白话用大白话说这一步在干什么

每算完一格，你就把「从这一格出发能给出的最好开价」写在纸条上，按开价从低到高排成一队。窗口往右滑时，过期的纸条从队头抽走；新纸条进来前，把队尾那些「开价比它还高、而且比它更早过期」的全扔掉。队头那张永远是当前窗口里最便宜的，所以每次只要看一眼队头，不用把整队翻一遍。

OK 200 的每一组比的是整条 dp 序列，不只是最后一个答案——一处错就当场定位到组和格子。随机数来自固定种子 LCG，重跑逐字一致。

正确性论证：为什么队首一定最优。 先列不变式。处理到下标 i 时（算完 dp[i]、把它入队之后）：

  1. 队列里的下标严格递增；
  2. 对应的 qval = dp[j]+b[j] 严格递增；
  3. 队首下标不小于 i-k，也就是没过期。

初始化：i=0 时只有下标 0，qval = a[0]+b[0]，三条都成立。归纳步分三段看。

第一步，过期出队不会漏掉最优决策。 第 16 行弹出的下标 j 满足 j < i-k，它对当前 i 以及以后任何 i' 都不可能再进窗口（因为窗口左端 i'-k 只会更大）。所以弹出它不影响当前或未来的最优值。

第二步，出队尾不会漏掉最优决策。 第 19 行弹出的队尾 j，是因为新来的 i 满足 qval[j] >= val[i]，而且 j < i。对所有未来的 i' > i：只要 j 还在窗口里，i 也一定还在窗口里（i 比 j 大、过期更晚），而 i 的开价不大于 j。于是 j 永远不可能成为「最优决策」——它被一个同样合法、开价更低、活得更久的 i 完全支配。丢掉它不影响任何后续答案。这一步是整段证明的核心：支配关系里的两个候选，后来者必须活得更久。

第三步，队首就是窗口最小值。 由不变式 2，队列按开价递增，队首是队列里开价最小的；由不变式 1 与第 16 行，队首下标在窗口内。那么窗口里那些「不在队列中」的 j 会不会更小？不会：任何一个被弹掉的 j 都已在第二步或第一步里被证明被一个更优、更年轻的候选支配，而那个候选要么还在队列里，要么又被更年轻的支配——沿着支配链走到队内，开价只会更低。因此队首的开价等于整个窗口的最小值，dp[i] = a[i] + qval[head] 与暴力式逐字相等。∎

第 1 帧到第 3 帧是同一条队列的三次快照，每帧都把「这一帧要看的盒子」重写了一遍：队列内容、刚算出的两个 dp、当前窗口。请按「第 2 帧」那一行读——开价 -5 的新下标 3 进来之前，队尾的开价是 10 和 1，都比 -5 大，而且它们都比 3 更早过期，所以两支一起被弹掉。这就是支配关系的物理图像。

为什么是 O(n) 而不是 O(n·k)。 摊还分析一行就够：每个下标 j 在算完 dp[j] 之后入队一次；它要么被第 16 行的过期判定弹出，要么被第 19 行的支配判定弹出，一旦弹出永不回来。所以整个 for 循环里 head++ 与 tail-- 的总次数都不超过 n，加上 n 次入队，总共 O(n) 次队列操作。你可能会担心第 19 行的 while 在最坏情况下把同一个元素反复比较——不会，因为每弹一次就少一个元素，tail 只减不增。这种「单次可能很贵、总量有界」的论证叫摊还分析，和动态数组扩容的均摊是同一套思路。写模板时若把队列换成 std::deque，复杂度不变，常数略增；若换成 std::set 每次取最小值，复杂度就从 O(n) 涨到 O(n log n)——n=1e5 时本例 0.40–0.60 ms 会变成几毫秒，虽然还能过，但那是白交的税。

和单调栈的分工。 第 4 单元讲过单调栈：它只在一端进出，弹栈是为了给当前元素找「左边第一个更大/更小」。单调队列是多端结构，弹队首是为了过期、弹队尾是为了支配。一句话记住区别：栈里留的是「还没找到答案的元素」，队列里留的是「未来还可能当最优决策的候选」。本例两个动作同时出现，是因为既要限制 j 的范围、又要在范围内取最值。

边界也别放过。n = 0 时三个函数都直接返回 0，dp 数组一个都不写；n = 1 时循环体一次都不进，dp[0] = a[0] 就是答案。这两个分支在源码里显式写着，不是靠循环条件碰巧绕过去。最容易出事的是 k = 0：题目若允许「不能跳」，窗口 [i, i-1] 是空的，最小值无定义；本例在参数检查里直接拒绝 k < 1，把脏数据挡在入口。还有一种隐蔽的错是把 1 基题面直接喂给 0 基数组：题面 k 表示「最多后退 k 格」，0 基实现里窗口就是 [i-k, i-1]，不需要再加一；若读入时已经把编号减一，又顺手写了 i-k-1，就会在 i=k 那一格读到并不存在的 j=-1。一个程序只能选一套下标口径，本单元三个例子全部 0 基，只有打印给读者看的数据保持原样。

陷阱你怎么会被坑到：队列里存下标还是值

你会看到什么？写了个只存开价的队列，小数据全过，窗口一滑动答案就偏大。你会怎么误判？以为是取最值那行写反了，或者怀疑开价公式。真相是：只存值就无法判断过期。第 16 行需要 qidx[head] < i-k，没有下标就只能靠计数猜，一旦被弹过队尾就错位。反过来，只存下标也不行——第 17 行要直接的开价，每次重算 dp[j]+b[j] 又退化成 O(1) 也还行，但第 19 行比较时反复读 dp 数组，常数变大。正解是两个数组并存：qidx 管生死，qval 管大小。

陷阱你怎么会被坑到：窗口的左右边界差一

你会看到什么？k=3 时，你写的版本在 i=4 用了 j=0 的开价，暴力版却没用。你会怎么误判？以为 i-k 写成了 i-k+1，改了之后第 i=3 组又错。真相是这条转移的窗口是 [i-k, i-1]，左右都闭，长度正好 k。弹出条件必须是 j < i-k 而不是 j <= i-k；差一格，最优决策就会被提前踢掉。另一个常见错误是把 j=i 也放进窗口——那时 dp[i] 还没算出来，读到的是旧值或垃圾值。本例在算完 dp[i] 之后才把 i 入队，顺序就是为这堵墙服务的。

23.4 前缀和优化：把一段和换成两次取值

第二种重复是「求和」。题目：从 0 号格出发，第 i 步能用的步数是 stair[i]，于是

dp[0] = 1，dp[i] = sum{ dp[j] : i-stair[i] <= j <= i-1 } (mod 1e9+7)。

暴力版对每个 i 把那一段 dp 加起来，步数开到 i 时就是 O(n²)。注意被加的每一项 dp[j] 都是旧格，且合并方式是求和——这正是前缀和的适用形状。

大白话用大白话说前缀和在这里干了什么

你有一本流水账，每一页记着当天进账。老板问「最近七天一共进了多少」，你不会把七页重新加一遍，而是翻出「到昨天为止的总账」和「七天前的总账」，一减就完事。前缀和数组 pre 就是这本总账：pre[t] 是前 t 格的和。任何一段连续区间的和，都是两个总账的差。

第 17 行那一次减法，把 O(stair[i]) 的循环变成了 O(1)。暴力版留在旁边做裁判：

正确性论证：差分恒等式。 定义 pre[0] = 0，pre[t+1] = (pre[t] + dp[t]) mod M。展开定义就有

pre[R+1] - pre[L] = (dp[L] + dp[L+1] + ... + dp[R]) mod M,

这就是差分恒等式，对任意 0 <= L <= R 成立。证明用归纳：L=0 时左边是 pre[R+1]-pre[0]，按定义正是前 R+1 项之和；L>0 时把 pre[L] 的展开式代入，抵消掉前 L 项，剩下第 L 项到第 R 项。模 M 意义下减法需要先加一个 M 再取模（第 17 行的 + PREFIX_MOD），否则 C 的负数取模会得到负值。

把 L = max(0, i-stair[i])、R = i-1 代进去，得到 dp[i] = pre[i] - pre[L]，与暴力式逐字相同。这里最关键的对照关系是：pre 的下标比 dp 多一个偏移量。pre[t] 管的是 dp[0..t-1]，所以窗口右端 i-1 对应的是 pre[i]，不是 pre[i-1]。把这件事写成一句口诀就是「右开左闭」，写进注释比每次现推便宜。

第 1 帧里 pre[3]=4 装的是 dp[0]+dp[1]+dp[2]=4，所以 dp[3] 直接取 pre[3]-pre[0]；第 2 帧窗口右端挪到 5，对应的是 pre[6] 而不是 pre[5]。两帧一起把「右开左闭」钉住了。

这套手法能推广到多少题。 被求和的项不一定非得是 dp[j] 本身，只要它在算 dp[i] 之前已经确定就行。若转移是 dp[i] = sum{ dp[j] + c[j] : j in window }，你维护 pre[t] = sum_{s<t} (dp[s]+c[s])，差分照样成立。更一般地，任何形如「一段已算好的量之和」的项都能这么压。第 9 单元的一维前缀和讲的是对输入数组求区间和，这里是对正在生成的 dp 数组求区间和——数学完全一样，区别在于 pre 要随着 dp 一格一格往后长，不能一次性预处理完。这也是为什么第 17 行之后紧跟着第 19 行：先把当前格的钱记进账，下一格才能用。

再补两个工程细节。第一，pre 与 dp 一样要选够宽的类型：本例模数是 1e9+7，pre[i]+dp[i] 最大约 2e9+14，仍在 32 位有符号范围内，所以 int 够用；一旦模数换成 1e18 或者不取模，pre 就必须上 long long，否则第 19 行会静默溢出。第二，本例只做一维前缀和；二维前缀和的容斥公式（四个角加减）也能用来优化二维 DP 的矩形和转移，但那是第 9 单元的内容，这里不重复。记住核心就行：前缀和压的是「连续一段的加法」，压不掉最值，也压不掉带权乘积。

陷阱你怎么会被坑到：pre 的下标错位与取模负号

你会看到什么？小规模上前缀和版和暴力版一致，遇到 stair[i] = i 时突然偏一格；或者改成减法后答案偶发变成负数。你会怎么误判？以为是窗口左端的 max(0, ...) 写错。真相有两个：一是 pre[t] 是前 t 格而非第 t 格，[L, R] 的和是 pre[R+1]-pre[L]，少加那个 1 就会把 dp[R] 丢掉；二是 pre[i]-pre[L] 在模意义下可能为负，C 的 % 保留负号，必须先加一个 M 再取模（本例第 17 行）。另外 pre[0]=0 与 dp[0]=1 要同时设，只设一个会让 i=1 那一格就错。

23.5 斜率优化：把转移看成直线在一点的值

第三种重复最难，但套路一旦认出来就很机械。题目是经典的「任务安排」：有 n 个任务按顺序做，第 i 个任务的耗时是 t[i]、费用系数是 c[i]。你可以把连续若干任务打成一批，每开一批先付启动费 S，批内所有任务统一按批末时刻计费。于是

dp[i] = min{ dp[j] + (T[i] + S) × (C[i] - C[j]) : 0 <= j < i },

其中 T[i] = sum(t[0..i-1])，C[i] = sum(c[0..i-1])，dp[0] = 0。暴力是双重循环，O(n²)。

大白话用大白话说斜率优化在干什么

假设你手里有一堆直线，每条直线代表「如果上一批切在 j，接下来要付多少钱」。当前任务的不同之处在于，问的那个人（横坐标）在变。你不可能每次把所有直线都画出来看一遍，所以事先把肯定不会被问到的直线扔掉，只留下一段可能的下边界；问的时候从最前面那条开始试，一条比一条更划算就往前走一步。因为问的横坐标只会越来越大，往前走过的位置再也不会回头。

怎么把转移拆成直线。 先把跟 i 有关的项提出来：

dp[i] = (T[i]+S)×C[i] + min_j { dp[j] - (T[i]+S)×C[j] } = (T[i]+S)×C[i] + min_j { (dp[j] - S×C[j]) - T[i]×C[j] }。

令 X[j] = C[j]，Y[j] = dp[j] - S×C[j]，m = T[i]。括号里就是 Y[j] - m×X[j]——把 j 看成一条斜率为 -X[j]、截距为 Y[j] 的直线，在横坐标 m 处的取值。前面那一项 (T[i]+S)×C[i] 跟 j 无关，算完最小值再加回去。

前提从哪里来。 两个单调性缺一不可：

  1. 斜率有序：X[j] = C[j]，只要所有 c[i] > 0，X 就严格递增，新直线可以按斜率递增的顺序插入凸壳；
  2. 查询有序：m = T[i]，只要所有 t[i] > 0，m 就严格递增，于是最优决策点只会向右移动——这就是决策单调。

这两条同时成立时，队头指针 q 只前进不后退，队尾插入时只需要弹掉被夹在中间的直线，整个算法是 O(n)。如果输入里允许 c[i] = 0，两条直线斜率相同，交点公式会除零；如果允许 t[i] < 0，查询点会左右横跳，队头指针不能单调前进，凸包退化成要二分查找的一般 CHT——那就不是这个模板了。本例的数据保证 t[i]、c[i] 都在 1..20。

拿演示数据把式子走一遍。 取 i=3（前缀 T[3]=6、C[3]=8，S=5）。暴力括号里要试三项：

  • j=0：dp[0] + 11×(8-0) = 0 + 88 = 88；
  • j=1：21 + 11×(8-3) = 21 + 55 = 76；
  • j=2：31 + 11×(8-4) = 31 + 44 = 75。

最优是 j=2。按拆出来的直线算同一件事：固定项 (T[3]+S)×C[3] = 88；三条直线的 X[j]=C[j] 分别是 0、3、4，Y[j]=dp[j]-5×C[j] 分别是 0、6、11；查询点 m=T[3]=6。于是 Y[j]-m×X[j] 分别是 0、6-18=-12、11-24=-13，加回 88 得 88、76、75——和暴力逐项相等。这一步只是加减乘法的重排，没有近似，所以它同时就是代数等价性的具体验证。你若在自己题上不确定拆得对不对，就照这个办法挑一个 i 手算两遍，比对着代码猜快得多。

还要注意 Y[j] 可能是负数（本例里虽然都是正，但 S 一大就会出现）。dp[j]-S×C[j] 是「已付启动费之后还剩多少」，负数完全合理；评价直线值时也照常做有符号运算，别因为看到负数就去取绝对值。溢出讨论见下面的 trap。

整数版怎么写。 判断「中间那条直线 b 是否没用」时，常规写法是比较两个交点 (Y[b]-Y[a])/(X[b]-X[a]) 与 (Y[c]-Y[b])/(X[c]-X[b])。整数版不除，改成交叉相乘：

(Y[c]-Y[b])×(X[b]-X[a]) <= (Y[b]-Y[a])×(X[c]-X[b]) 时弹掉 b。

因为 X 递增，两个分母都是正数，交叉相乘不改变不等号方向。乘积可能爆 64 位，所以用 __int128 装中间量。

__int128 是本机 gcc 的扩展，基础参数里的 -Wpedantic 会报一条「ISO C 不支持 __int128」的提示。这不是错误：编译退出码仍是 0，程序照跑。本书不许用 -w 压掉它，所以你会在编译日志里看到那四行提示——它们恰好提醒你「这里用了非标准整数，换平台要重查」。完整求解循环把上面两个动作拼起来：

凸包和单调队列不是一回事。 单调队列里每个候选只是一个数，比较的是「谁更小」；凸包里每个候选是一条直线，比较的是「在当前横坐标谁更低」。单调队列的队首一旦出队就永远作废，是因为窗口左端右移；凸包的队首一旦出队也永远作废，是因为查询横坐标右移。两条队列都靠「有序」续命，但有序的来源不同：前者靠窗口边界单调，后者靠斜率与查询点单调。把这两件事混起来，就会出现「在凸包里也去判断下标过期」这类无意义的分支。本例的 hull 只存直线编号，没有任何过期判断——每条直线从插进来到被弹出，寿命由交点决定，不由窗口决定。

再强调一次四边形不等式与斜率优化的分工。两者都导出「决策点单调」，但斜率优化要求你能把转移拆成直线求值，拆出来的是一维 DP；四边形不等式用在区间 DP 上，w(l,r) 只要满足那四个点的不等式，不必拆成直线。所以当你看到状态是 dp[l][r] 时，别往斜率优化上想；看到状态是 dp[i] 且转移里有 i×j 乘积时，别往四边形不等式上想。认错了工具，后面所有推导都会别扭。

正确性论证：凸壳上的决策点为什么单调。 分三步。

第一步，代数等价。 从 (T[i]+S)×C[i] 里把 S 那一份移到括号里，得 dp[j] - (T[i]+S)×C[j] = Y[j] - T[i]×X[j]。这只是加减法重排，没有引入近似，所以对任意 j 两边相等。最小化左边等价于最小化右边，故新式与暴力式逐字等价。

第二步，下凸壳的最优性。 把每条直线画在 (m, 值) 平面上，斜率 -X[j] 严格递减（因为 X 递增、取负变递减）。任意两条直线最多交一次；被第三条直线压在下面的那条永远不会是最低点，可以删掉。剩下的折线就是下凸壳，任意横坐标上的最低点一定在壳上。第 42 行的判定正是「b 与 c 的交点不在 a 与 b 的交点右边」，此时 b 整段都被 a 或 c 压住，删除不改变任意 m 上的最小值。用交叉相乘避免了除零与浮点误差，X 递增保证分母同号，因此不等号方向不会翻。

第三步，决策点单调。 设最优决策从 j 变成 j'，即直线 j' 在 m1 处首次不差于 j，则 m1 = (Y[j']-Y[j])/(X[j]-X[j'])（注意 X 递增时这个交点是确定的）。当查询横坐标 m 继续增大时，由于 j' 的斜率更负（X 更大），Y[j']-m×X[j'] 下降得更快，j' 会一直优于 j，j 再也不会翻盘。于是随着 i 增大、m 增大，最优决策的下标单调不减——第 38 行的 q++ 可以放心只进不退。∀ i 成立，故整段 O(n)，答案与暴力一致。∎

陷阱你怎么会被坑到：交叉相乘溢出与除零

23.6 四边形不等式：只求认得出、知道什么时候查表

有一种 DP 也能从 O(n³) 降到 O(n²)，靠的是「最优决策点单调」这条性质，但它不需要你把转移拆成直线。这类转移通常长成区间 DP：dp[l][r] = min{ dp[l][k] + dp[k][r] + w(l,r) }，并且代价函数满足四边形不等式

w(a,c) + w(b,d) <= w(a,d) + w(b,c) 对 a <= b <= c <= d 成立（叫凸的四边形不等式；取反就是凹的，对应 max）。

大白话用大白话说四边形不等式

把四个点 a、b、c、d 按顺序排在一条线上，交叉的两段代价之和不大于嵌套的两段之和。翻译成人话：「先切里面两小段」不会比「先切外面一大段」更贵。这个性质一成立，最优断点就会随着区间变大而单调右移，于是你不用在区间里从头枚举 k，只要从上一次的最优断点附近找。

拿石子合并的 w(l,r) = sum(a[l..r]) 试一眼：任取 a <= b <= c <= d，w(a,c)+w(b,d) 与 w(a,d)+w(b,c) 相减，区间 [a,b-1] 和 [c+1,d] 两边各出现一次、[b,c] 两边各出现两次，结果恰好相等。相等也算满足「不大于」，所以它是凸的四边形不等式，且 w 单调，于是区间 DP 的最优断点单调，可以套优化。反过来，若 w(l,r) = (sum(l..r))²，同样取四个点就能算出 w(a,c)+w(b,d) <= w(a,d)+w(b,c) 成立——平方让「合起来再算」比「分开算」更贵，方向仍然对。你只需要会做这种「展开、抵消、看符号」的粗判，就能决定要不要去查表；严格证明留给专题资料。

这一单元只到这里为止。理由是：判断一个具体 w(l,r) 满不满足四边形不等式，往往要分情况讨论、甚至构造反例；赛场里碰到「区间 DP + 最优断点单调」的题，正确做法是先确认 w 的形状，再直接套「四边形不等式优化」的标准结论与代码模板，而不是在考场上现推。你需要练的是认出信号：

  • 状态是区间 [l,r]，转移枚举一个断点 k，代价 w(l,r) 与 k 无关或只通过两段区间出现；
  • 题目要求最小值，且直觉上「切得越碎越便宜」或「越整块越便宜」有稳定的方向；
  • 数据规模卡在 O(n³) 过不了、O(n²) 刚好能过（n 在几百到几千）。

满足这三条，就该去查表而不是硬推。查表时只核对两件事：w 的四边形不等式方向（决定是优化 min 还是 max）、以及 w 是否单调（有些写法还要求 w(b,c) <= w(a,d)）。核对完直接抄模板，再用 200 组小数据对拍——和本单元三个例子用的是同一套纪律。如果你想把这一步补成自己的能力，下一站是区间 DP 的专题资料；这里不展开，避免把「能认出」误当成「会证明」。

23.7 优化失败的典型症状：推不出式子就别硬套

三种优化都有清晰的适用边界。边界之外硬套，症状都很像：样例全过、大数据悄悄错，或者复杂度反而更差。按症状反查原因，比对着代码瞎改有效。

症状一：式子里的 j 项拆不开。 比如转移里出现 w(i,j) = (i-j)²，展开后有 -2ij，这个乘积同时黏着 i 和 j。它不是「只依赖窗口/前缀/斜率」里的任何一种，单调队列和前缀和都失效；只有斜率优化能把 -2ij 收进 m=-2i 与 f(j)=j，但前提是别的项也能凑成直线。如果拆到最后 g(j) 里还残留 i，立刻停手，回到 O(n²) 写法。

症状二：队列/凸包的「有序」前提没验证。 单调队列要求窗口两端随 i 单调；凸包要求斜率与查询点都单调。输入里一个负数、一个 0，就能让单调性悄悄 broken。本单元三个例子的随机数据都刻意避开脏值（t、c 保证正数，b 允许负数但只影响开价大小、不影响窗口单调）——你在自己的题里也要先写清楚「哪两个数必须为正」，再选模板。

症状三：合并方式不对。 取最值才能用单调队列和凸包；求和才能用前缀和。有一类题把「最大值」换成「次大值」或「前 k 大之和」，队列里只留一个最优决策就不够了——需要 k 个候选，复杂度变成 O(nk)，优化收益缩水。认准合并方式再动手，别看到「min」就套凸包。

症状四：为了优化而优化。 n 只有 500 时 O(n²) 是 25 万次操作，本机毫秒级；写一个带凸包的 O(n) 版本，多花二十分钟、多出四个溢出陷阱，省下的时间还不够调试。复杂度表要连着 n 一起看——这正是下一节的表格存在的理由。

陷阱推不出式子就别硬套：怎么判断自己卡在哪

你会看到什么？对着模板改了半小时，队首队尾的判定越改越复杂，最后连自己都解释不清队里存的是什么。你会怎么误判？以为是自己细节没写好，继续加 if。真相通常是前提不成立：转移项拆不开、合并方式不是最值/求和、或者有序性不存在。这时候最有效的一步是退回 O(n²) 暴力版，拿小数据对拍确认状态定义本身没问题，再重新做「固定项 / 变化项」的拆分。如果拆不出来，就承认这题不该用这三种优化——能写出正确的 O(n²) 比写出错误的 O(n) 强得多。

再强调一次测量纪律：耗时永远不进 output 块。stdout 放逐字可复现的结论（校验和、OK 数、最优值），stderr 放每次都会抖的毫秒数，正文引用时写三次取值构成的区间。把毫秒数塞进 output 块，明天重跑闸门就会报 stale_output；把输出编造出来而不从真跑的程序回写，同样过不了对账。本单元所有数字都按这个纪律处理，换一台机器要重测，不能直接照抄。

为什么是三次取值而不是一次？因为本机 clock() 的分辨率是 1 ms，单次测量一会儿是 0.40 ms、一会儿是 0.60 ms，只报一个数就像在掷骰子。每次重复 5 遍取平均压掉抖动，再独立跑三次写成一个区间，读者一眼就能看出「这个量级稳定、具体小数别信」。平方版那一列只跑到 n=8000，再往上就要秒级，对拍和实测都吃不消；表里的「外推」是用 8000 点的耗时乘以 (1e5/8000)² 得到的粗略上界，只是用来说明量级差距，不是实测值，所以特意和真测数分开写。你要是在自己的机器上复现，先按同样规模跑四档平方版，确认增长确实是平方，再外推——别把常数项大的算法也当平方看。

还有一个容易忽略的口径：三个 perf 程序用同一固定种子前缀生成数据，所以 n=2000 的那 2000 个数就是 n=1e5 那批数的前 2000 个。这样「同一数据的 O(n²) 与优化版对比」才成立；如果两边各用不同种子，比出来的差异里就掺了数据分布的影响。数据在程序里按固定种子重生成，不写进文件，省掉了 IO 与文件格式带来的额外变量。

下一单元讲字符串哈希与 KMP：这一单元优化的是「同一条状态线上重复翻旧格」，下一单元换到「子串比较」——用前缀哈希把任意子串的比较压成两个前缀值之差，你会看到和 23.4 完全同构的差分思想，只不过减的对象从 dp 变成了多项式哈希值。

临场用这一单元，按下面的顺序做，能省掉大部分返工：先把转移写成「固定项 + 变化项」，确认变化项只依赖旧格；再看合并方式，决定走队列、前缀和还是凸包；然后逐条检查有序性前提（窗口边界、斜率、查询点），把输入的最小最大值代进去试；最后写暴力版，用固定种子小数据跑 200 组对拍。四步里任何一步卡住，就退回 O(n²)，先把正确版本交上去。一个能过 80% 数据的平方解，比一个调了一小时仍偶发 WA 的 O(n) 解值钱得多。

回看七份清单的命名也能读出工程层次：algo-opt-mono / algo-opt-mono-perf、algo-opt-prefix / algo-opt-prefix-perf、algo-opt-slope / algo-opt-slope-perf / algo-opt-slope-cpp。每个 id 全局唯一，每份清单都指向本单元正文，正文里每个 output 块都被恰好一份清单认领。这套约定看着繁琐，实则是让「正文里的每个数字都能追溯到一次真实运行」变成机器可检查的事实——这正是本书比「能过样例」多走的那一步。

小结这一节的要点
  • 能不能优化，看转移里重复的那段依赖谁：滑动窗口最值用单调队列，区间求和用前缀和，能拆成直线求值的用凸包；
  • 单调队列的正确性靠两条：过期下标出队首不影响未来，被更年轻且更优的候选支配的队尾可以永久删除；存下标与存值必须两数组并存；
  • 前缀和的差分恒等式是 sum dp[L..R] = pre[R+1]-pre[L]，pre[t] 管前 t 格，右端要 +1，模减先加 M；
  • 斜率优化的前提是斜率与查询点都单调，据此得到决策点单调，队头只前进；交点比较用整数交叉相乘，别用浮点除法；
  • 四边形不等式只要求认出「区间 DP + 最优断点单调」的信号并知道去查表，不在赛场现推证明；
  • 推不出式子就退回 O(n²) 暴力：拆不开的 i·j 项、被破坏的有序性、不是最值/求和的合并方式，都是硬套优化的典型失败症状；
  • 三份 OK 200 与三份真抓会话构成对拍与实测证据，耗时只进会话不进输出块。

注自测题答案
  1. 开价 dp[j]+b[j] 用来比较大小、取队首最优；下标 j 用来判断 j < i-k 是否过期。只存开价，窗口滑动时无法知道队首是否已过期，只能靠猜；只存下标，比较时要反复回查 dp[j]+b[j]，虽然仍 O(1) 但常数变大，且出队尾的支配判定写起来别扭。本例两个数组并存，qidx 管生死、qval 管大小。
  2. 弹出队尾 j 的原因是把新来的 i 开价不高于 j，且 j<i。对未来任意 i'>i：只要 j 在窗口内，i 也一定在窗口内（i 更年轻、过期更晚），而 i 的开价不大于 j，所以 j 永远不可能成为最优。支配链走到队内，开价只会更低，故删除不改变任何后续答案。「更久」体现在 i > j 使得 i 的过期时刻 i+k 也晚于 j 的 j+k。
  3. 定义 pre[t]=dp[0]+...+dp[t-1]，所以 dp[i-1] 是第 pre[i]-pre[i-1] 这一格，窗口右端 i-1 对应的是 pre[i]。写成 pre[i-1] 会把 dp[i-1] 整格丢掉。C 的 % 对负数保留负号，pre[i]-pre[L] 可能为负，先加一个模数再取模才是模意义下的正确差值。
  4. 令 X[j]=C[j]、Y[j]=dp[j]-S*C[j]、m=T[i]，括号里的目标就是 Y[j]-m*X[j]，即直线在 m 处的取值，外面再加回 (T[i]+S)*C[i]。X 递增由 c[i]>0 保证（斜率有序），m 递增由 t[i]>0 保证（查询有序、决策单调）。
  5. 两个交点的分母 X[b]-X[a] 与 X[c]-X[b] 都是正数，交叉相乘保持不等号方向，且完全不做除法：既避免斜率相等时除零，也避免两个交点极近时浮点判等把直线弹错。__int128 装的是两个差相乘的中间量——X、Y 都能到 1e9 量级，乘积会越过 64 位有符号上限，用 long long 会静默溢出给出偏大或偏小的答案。
  6. 信号是「区间 DP + 枚举断点 + w(l,r) 满足凸的四边形不等式 + n 卡在 O(n³) 过不了」。看到这三条就该确认 w 的方向与单调性，然后直接套标准结论与模板，再用小数据对拍。四边形不等式的证明要分情况讨论甚至构造反例，赛场现推性价比极低，所以本单元只要求认出与知道何时查表。
  7. 依次检查：一，所有 t[i] 是否为正，否则查询点 m 不单调，队头指针不能只进不退；二，所有 c[i] 是否严格为正，否则斜率不再严格递增，凸壳插入顺序失效；三，代价模型是否真的是「批末统一计费」，否则拆不出 Y[j]-m*X[j] 这个直线形状。这三条都属于前提问题，改弹队判定式只是在错的前提下调参数，不会修好根因。正确做法是退回 O(n²) 暴力确认状态定义，再重新做固定项与变化项的拆分。
