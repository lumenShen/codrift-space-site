7.2 二分图匹配：先把「配对」这件事说清

大白话用大白话说二分图匹配

把一群人分成男生和女生两排，只允许异性之间牵手，而且每个人最多牵一只手。你要尽量多地配成对——这就是二分图最大匹配。「二分」说的是点被分成两边，边只跨边不走边内；「匹配」说的是选出的边两两不共端点。想成宿舍分配、想成工人的岗位分配都行：关键不是「谁喜欢谁」，而是「一个人只能占一个位置」。

形式化地说：无向图 G = (V, E) 是二分图，如果 V 能分成两个不相交的集合 L 与 R，使每条边都一端在 L、一端在 R。匹配 M ⊆ E 是两两不共端点的边集；最大匹配是边数最多的那个。点号统一从 0 开始：左侧 0..n1−1，右侧 0..n2−1。

本单元选 matchR 这一种存法：只记录右侧的匹配情况，matchR[j] = u 表示右侧 j 已经和左侧 u 配对了，−1 表示 j 还闲着。为什么不两边都记？因为一个左侧点是否已被匹配，可以在需要时扫一遍 matchR 得到；而每次增广真正要改的，都是「某个右侧点现在归谁」这一件事。一个数组，一份真相。

7.3 匈牙利算法：增广路与 DFS

大白话用大白话说增广路

想象配对已经做了一部分。现在找一个没配上对的人 A，让他沿着一条边走到对面某个已被占用的人 B；B 不甘心，沿着自己匹配的那条边走回来，再找另一个空闲的人……如果这条「你占我的、我再去占别人的」的交替路线最终走到一个空闲位置，那就把所有人大挪一次：原本 k 对，挪完变成 k+1 对。这条路线叫增广路（augmenting path）。匈牙利算法就是：对每个没配对的左侧点找一次增广路，找到就翻盘子，找不到就认命。

形式化定义：相对于匹配 M，交错路是边在 M 中与不在 M 中交替出现的路径；增广路是一条两端都是未匹配点、且以非匹配边开始和结束的交错路。它比别的交错路多一条非匹配边，所以翻转之后匹配数 +1。

陷阱你怎么会被坑到：`vis` 忘了每轮重置

你会看到的现象：程序在小图上偶尔少配一两条边，而且「少配多少」随着左边点的处理顺序变化；加一行打印之后结果居然变了。误判：你会去数边的数量、怀疑邻接矩阵建错，甚至怀疑递归写反。真相：vis 是本轮的访问记录，它 guarantee 的是「这一次找增广路别绕回原来的点」。如果你把它开在函数外面、只在开头 memset 一次，那么第二轮开始，上一轮访问过的右侧点全被当成「不许走」，本可以走的路被自己的旧标记堵死。修法就一行：每处理一个左侧点，重新清零（上面 hm_max_match 第 23 行）。性能版可以换成时间戳写法——用 vis[v] == stamp 判访问、stamp = u+1 每轮递增，效果一样但省掉清零。

陷阱你怎么会被坑到：`matchR` 没初始化成 −1

你会看到的现象：随机小图对拍里偶尔报 FAIL，失败那组的 matchR 里冒出一个很大的正数或 0，程序却以为「右侧点被某个左侧点占着」，于是递归进一个根本不存在的左侧点。误判：你会怀疑递归边界，或者以为 −1 这个哨兵写错了。真相：matchR 是 malloc 出来的裸内存，初值是什么全看运气；只有显式全写 −1，「未匹配」这个语义才成立。注意还不能用 memset(matchR, 0, …) 偷懒——0 是合法的左侧点编号，把空闲点伪装成「被 0 号占了」比留着垃圾值还隐蔽。

7.4 Berge 引理：为什么增广路一定能增大匹配

这一节是本单元第一个真正的「为什么」。我们不背定理名字办事，但要把结论钉死：

定理（Berge 引理，直观版）：匹配 M 是最大匹配，当且仅当相对于 M 不存在增广路。

分两半证，都只需要「对称差」这一个工具。两个集合 A、B 的对称差 A ⊕ B，是「属于其中一个、但不同时属于两个」的元素集合；对匹配来说，就是把两边都有的边抵消掉、剩下的边构成若干条互不相交的路径或环。为什么只能是路径或环？因为 M 和 M′ 都是匹配，每个点最多被一条 M 边和一条 M′ 边碰到，于是剩余图里每个点的度数最多 2——度数 ≤2 的图只能是路径和环。

第一半：有增广路 ⇒ 不是最大匹配。设 P 是相对于 M 的增广路。按定义，P 的两端都是未匹配点，且边在「不在 M / 在 M」之间交替，第一条和最后一条都不在 M，所以 P 上不在 M 的边比在 M 的边恰好多一条。把 P 上的边全部翻转——原来在 M 里的移出，原来不在的加入——得到的 M′ = M ⊕ P 仍然是匹配：路径内部每个点原本恰好碰到一条 P 上的边，翻转后还是恰好一条；两个端点原本一条都没碰到，翻转后各碰到一条。而 |M′| = |M| + 1。既然存在更大的匹配，M 当然不是最大的。这就是 7.3 那段代码里 ans++ 的底气。

**第二半：没有增广路 ⇒ 是最大匹配。**反证。设 M 不是最大匹配，取一个更大的匹配 M′，考虑 D = M ⊕ M′。D 是若干条路径和环的并。因为 |M′| > |M|，D 里必然存在一条路径，其中属于 M′ 的边比属于 M 的边多（否则把所有分支的差值加起来不可能为正；环里两种边数量相等，因为环上交替）。取这样一条路径 P：它的两端只能是 M 未覆盖的点（否则两端各有一条 M 边没被抵消，矛盾），且首尾两条边都属于 M′——于是 P 正是一条相对于 M 的增广路。与「没有增广路」矛盾。∎

把两半合起来，匈牙利算法的结构就一目了然：从空匹配开始，每次找一条增广路翻转它，匹配数严格加一；找不到时就由第二半保证已经最优。算法的停止条件就是正确性的证明本身——这句话值得记住，它能帮你判断很多图论算法的「为什么停在这里」。

拿演示图把对称差过一遍，你会发现它一点都不抽象。初始空匹配 M₀ 上，左侧 0 到右侧 0 就是一条增广路（首尾都未匹配、只有一条非匹配边），翻转后 M₁ = {0-0}。轮到左侧 1 时，真正的增广路是「左1 → 右0（非匹配）→ 左0（沿匹配边回溯）→ 右1（非匹配）」：它交替地走非匹配边与匹配边，两端左1、右1 都未匹配。翻转后 M₂ = {左1-右0, 左0-右1}，边数从 1 变 2。注意这里 M₂ ⊕ M₁ 包含三条边，其中两条属于 M₂、一条属于 M₁——正是「非匹配边多一条」的具象。继续到左侧 2、3，各自找到增广路，最后 M₄ 有四条边。每一轮的 dfs 递归就是在显式枚举这个交错可达区域：从当前未匹配的左侧点走非匹配边到右侧，若右侧已被占就沿匹配边回到它的旧主人，继续扩展；一旦抵达空闲右侧，递归回溯时逐条翻转，整条增广路一次性改完。第二半保证「扫完所有左侧点都没有增广路」等价于「不存在更大的匹配」，所以答案可以放心交。

还有一句实践上的话：dfs 里的递归深度等于交替路径长度，最长不超过 2·min(n1, n2)。本单元小图两侧 ≤8 完全安全；如果哪天把这套代码搬到 n=1e5 的二分图上，请先改成迭代版——第 2 章实测过本机 2MB 栈在 4.4 万帧处杀死递归 find，交替路径 DFS 是同样的死法。

7.5 König 定理：最大匹配 = 最小点覆盖

大白话用大白话说点覆盖

匹配是「挑边」，点覆盖是「挑点」：挑出一批点，让每条边至少有一个端点被挑中。想成监控摄像头：每条路至少要有一头装了摄像头，问最少装几个。奇怪的事情发生了：在二分图里，「最多能挑多少条互不相邻的边」和「最少挑多少个点盖住所有边」，答案是同一个数。一般图上这不成立（三角形最大匹配 1、最小点覆盖 2），二分图上却严丝合缝——这就是 König 定理。

定理（König）：二分图的最大匹配数 = 最小点覆盖数。

先证容易的一半，叫弱对偶：任取一个匹配 M 和一个点覆盖 C。M 的每条边都必须被 C 盖住，而 M 的边两两不共端点，所以一条 M 边至少消耗 C 中一个互不相同的点——给 M 的每条边分配一个盖住它的覆盖点，不同边分到的点不可能相同（否则那个点同时盖住两条匹配边，与匹配不共端点矛盾）。于是 |M| ≤ |C|。这一半对所有图都成立：匹配数永远不超过点覆盖数。

难的是反过来：要造出一个大小恰好等于最大匹配的点覆盖。设 M 是最大匹配，构造如下：

  1. 把所有左侧未匹配点放进集合 Z，从它们出发做交错 DFS：走「不在 M 的边」从左到右，走「在 M 的边」从右到左，把到达的点都记进 Z（右侧也记）。
  2. 令覆盖 C = (L ∖ Z_L) ∪ (Z_R)：左侧没走到过的点，加上右侧走到过的点。

C = (L ∖ Z_L) ∪ (Z_R) 的大小为什么正好是 |M|？按每条匹配边分情况数：

  • 若一条匹配边的左端点不在 Z_L：那么左端点进了 C；它的右端点不可能在 Z_R——否则从右侧走匹配边就会到达这个左端点，把它拉进 Z_L。所以这条边正好贡献 C 中 1 个点。
  • 若左端点在 Z_L：那么从它出发沿非匹配边可以到达右端点（交错 DFS 一定会试这条边），所以右端点在 Z_R，进了 C；同时左端点不在 C。这条边也正好贡献 1 个点。

每条匹配边恰好贡献 1 个覆盖点，未匹配边一个都不贡献（下面证明它们也被盖住），于是 |C| = |M|。

再证 C 真的盖住每条边。取任意边 (u, v)，u ∈ L、v ∈ R：

  • 若 u 不在 Z_L，那 u 就在 C 里，盖住了；
  • 若 u 在 Z_L，交错 DFS 从 u 一定要试 (u, v)。如果 v 不在 Z_R，只可能是「v 已经被访问过」——而 v 一旦被访问，它就在 Z_R；所以 v 必在 Z_R，盖住了。

这里用到了一个关键事实：从 Z_L 的点出发，沿非匹配边能到的右侧点全被标记了（DFS 扫完了所有邻边）。唯一能挡住它的，是这条边本身属于 M——但那正是「走匹配边回左侧」的分支，右端点照样在 Z_R。两条路都通向 Z_R，边一定被盖住。∎

剩下还要说明 |C| 不会「少算」：因为弱对偶告诉我们 |C| ≥ |M|，而上面数出 |C| = |M|（逐匹配边数），所以 C 恰好是最小的。

König 定理不只是个漂亮的等式，它还是最小路径覆盖的钥匙。给一张 DAG，问「最少用几条点不相交的路径覆盖所有点」。做法是先把每个点 v 拆成 v_out 和 v_in，原图的每条边 u→v 连成 u_out → v_in；对这张新二分图求最大匹配 M，答案就是 n − |M|。直觉是：一开始每个点自成一个长度为 0 的路径，共 n 条；每把一条匹配边接进路径，就把两条路径并成一条，路径总数减一；而 König 定理保证「能接多少条」恰好受限于「最少要删多少点」，从而这个贪心式的计数是最优的。这里你能第一次看到「拆点」的威力——它将在 7.10 的建模段里反复出现。

注为什么一般图上 König 不成立

三角形（三个点两两相连）的最大匹配是 1（只能挑一条边），最小点覆盖是 2（任意两点盖住三条边）。上面证明的哪一步在一般图上塌了？是「每个点至少被一条 M 边和一条 M′ 边碰到，度数 ≤2」——这依赖「边只跨两侧」：左侧点只接 M 边或 M′ 边中各自的一条，右侧点同理。一般图上同一个点可能同时被多条 M′ 边用到吗？不会，M′ 也是匹配；真正塌掉的是交错路径的结构不再保证两端都是 M 未覆盖点。所以别把「匹配数 = 覆盖数」当成图的普遍性质，它是二分图专属的礼物。

7.6 Dinic：分层图 + 当前弧

大白话用大白话说 Dinic

先别管「分层」这个词。把网络想成水管网：每一轮你先做一次 BFS，量出「从水源出发，每个节点最少要跳几步才能到」，这就是层数。然后你只允许水沿着「层数恰好 +1」的管子往前流，不许横着流、更不许往回流。这样一轮能把当前所有最短的路径全部灌满（叫阻塞流），灌完再 BFS 量一次，层数变长了就再来一轮。当前弧是说：某个节点往外的管子试到哪根了，记个指针，退回来的管子本轮别再试第二遍。

三条概念必须先立住：

  • 残余网络：每条有向边 u→v 容量 c，流过 f 之后，正向剩余 c−f，同时多出一条反向边 v→u 容量 f。反向边是「后悔药」：后面发现这股水流错了，可以沿反向边把它撤回来。
  • 分层图：在当前残余网络上从 s 做 BFS，得到 level[v] = s 到 v 的最短边数；只保留 level[v] = level[u] + 1 且剩余容量 > 0 的边，就是这一轮的分层图。
  • 阻塞流：把分层图里的 s-t 路径全部灌到不能再灌，这一轮的 DFS 就结束了。

容量必须用 long long。这是硬要求，理由很实在：单个容量到 1e9 时，一条路径上若干条边相加、或者网络里总流量累加，很容易越过 int 的上界。把类型写进结构体，比在每个累加处打补丁靠谱：

7.7 为什么一轮阻塞流之后没有漏掉的增广路

这是 Dinic 正确性的关键，也是它比朴素 Ford-Fulkerson 快的原因。很多人会问：DFS 是贪心地一条路一条路灌的，凭什么保证这一轮把「所有最短路」都灌完了？两件事分开说：当前弧保证不重复劳动，分层图保证不漏路。

先固定记号。设本轮 BFS 得到的 level 数组，是在本轮开始时的残余网络 G_f 上算的，level[v] 就是 s 到 v 的最短距离（BFS 的性质）。由此得到一个基本事实：

对 G_f 中任意剩余容量 > 0 的边 u→v，都有 level[v] ≤ level[u] + 1。

理由：如果 level[v] > level[u] + 1，那就存在一条 s→u 的最短路径再接边 u→v，长度 level[u]+1，比 level[v] 更短，与 level[v] 是最短距离矛盾。

现在看阻塞流结束后的残余网络 G_f′。我们把剩下的边分三类：

  1. 原来就在分层图里的正向边（level[v] = level[u]+1 且剩余 > 0）：它们已被阻塞流全部灌饱和，在 G_f′ 里剩余为 0，不存在了。
  2. 原来就不在分层图里的边：由上面的基本事实，它们满足 level[v] ≤ level[u]，走一步不会让层数增加。
  3. 新长出来的反向边：它们来自本轮流过的分层图边 v→u，方向是 u→v 的反向，即 level 从 level[old_u]+1 退回 level[old_u]，层数只会减少。

三类边没有一种能让 level 增加 1。于是从 s（level 0）出发，无论怎么走，level 最多保持不变或下降；而汇点 t 的 level 至少是 1（否则一开始 BFS 就已经分不到 t，循环根本不会进入）。所以 G_f′ 里不存在任何 s→t 的路径，本轮确实没有漏掉增广路，必须重新 BFS。

当前弧的作用则是把「一轮之内」的复杂度压住。没有它，同一个点在第 k 次 DFS 里可能从头扫描同一批已经证明走不通的出边；有了它，cur[u] 单调地沿着 nxt 前进，每个点的出边在本轮至多被有效考察一次。加上「退回来的边本轮不再看第二遍」，一轮阻塞流在分层图上就是 O(VE)（V 个点、E 条边各被扫一遍），整个 Dinic 是 O(V²E)；在单位网络等常见情形下有更好的界。

「单位网络」指每条边的容量都是 1——二分图匹配建出来的网络正是这种。此时每一轮阻塞流推进的距离至少增加 1，而距离最多 V−1；再配合单位容量下「每层能过的流量有限」的论证，总复杂度降到 O(E·√V)。这就是 M12 表里「Dinic 能过 V≤5000、E≤1e5」的底气：复杂度不是纸上 O(V²E) 那种吓人的数，具体数据长什么样决定了它跑得多快。别把最坏界当成实际运行时间：本单元稠密图 n=500、E=249500 实测只有 6.7–6.9 ms，离 O(V²E) 的悲观估计差着好几个数量级；但反过来，如果容量随意放大、图又接近最坏构造，这个乐观差距就不再有保障。

陷阱你怎么会被坑到：漏掉反向边，增广路就找不全

你会看到的现象：一张很小的图上 Dinic 报出的流量比暴力最小割小 1 或 2，而且「少多少」跟边的加入顺序有关——换个加边顺序，答案居然变了。误判：你会去查 BFS 的层数、怀疑 DFS 的当前弧推进太快。真相：你只加了正向边，或者反向边的容量在增广之后没加回去。构造一张五点图就现形：s→u、s→v、u→v、v→t、u→t 容量全是 1。先送 1 单位走 s→u→v→t，v→t 饱和了；此时 s→v 这条路若不借助反向边 v→u（容量 1）就到不了 u，第二单位永远送不出去，答案是 1 而不是 2。反向边就是「后悔药」：它允许后一股流把先前的流从 v 上挪回 u，再走 u→t。所以 cap[e] -= d; cap[e^1] += d; 这两行必须成对出现，少一行就等着 WA。

陷阱你怎么会被坑到：把 cur 和 head 混用

你会看到的现象：第一组数据全对，第二组开始最大流偏小；或者更诡异——单跑一次正确，连跑两次第二次数值变了。误判：你会怀疑 BFS 的 level 没更新、怀疑反向边写反。真相：你在 DFS 里直接推进了 head[u]。第一轮结束后 head 已经被改得面目全非，第二轮 BFS 虽然重算了 level，却沿着残缺的邻接表遍历，很多边永远扫不到。修法：把 cur[i] = head[i] 放在每轮 BFS 之后（见 fg_dinic 第 77 行），DFS 里只写 cur，head 从头到尾只读。判别口诀：head 是地图，cur 是脚印——你不能因为走过一条路就把地图擦掉。

7.8 最大流最小割定理：弱对偶 + 存在性

大白话用大白话说割

把网络的点刀切成两半：水源 s 所在的叫 S，汇点 t 所在的叫 T。所有从 S 跨到 T 的管子加起来，就是这个割的容量——相当于「把所有水从 S 运到 T 的总闸门口径」。任何水流想从 s 到 t，迟早得穿过这个闸口，所以流量绝不可能超过闸口容量。最大流最小割定理说：你能找到的最大流量，恰好等于最紧的那个闸口的容量。

定义：s-t 割是把 V 分成 S、T 两半，满足 s ∈ S、t ∈ T；割容量 c(S,T) = Σ c(u,v)，其中 u ∈ S、v ∈ T、边 u→v 存在。

第一半（弱对偶）：任意可行流 f 的值 |f| ≤ 任意割容量 c(S,T)。证明只需要对 S 里所有点把流量守恒式加起来：

Σ_{u∈S} (流出 u 的流量 − 流入 u 的流量) = |f|

因为除 s 外 S 中每点的净流入为 0，s 的净流出正是总流量。把左边的每一条边按端点归类：S 内部的边一出一入互相抵消；从 T 进入 S 的边贡献一个负项；从 S 到 T 的边贡献一个正项。于是

|f| = Σ_{u∈S,v∈T} f(u,v) − Σ_{v∈T,u∈S} f(v,u) ≤ Σ_{u∈S,v∈T} f(u,v) ≤ Σ_{u∈S,v∈T} c(u,v) = c(S,T)。

两个不等号分别用了「流量非负」和「流量不超过容量」。这一半对所有网络都成立，和 König 定理里的 |M| ≤ |C| 是同一种论证。

第二半（存在性）：当 Dinic 停止时，令 S = 最后一次 BFS 中从 s 可达的点集，T = V∖S。因为 BFS 分不到 t，所以 t ∈ T，这是一个合法的 s-t 割。看跨割的边：

  • 对 u ∈ S、v ∈ T 的正向边：若它还有剩余容量，BFS 就能从 u 走到 v，v 就该在 S 里——矛盾。所以这类边全部饱和，f(u,v) = c(u,v)。
  • 对 u ∈ T、v ∈ S 的反向跨越边：若它上面有正流量 f(u,v) > 0，那么残余网络里有反向边 v→u 且容量 > 0，BFS 就能从 v 走到 u，u 就该在 S 里——矛盾。所以这类边流量为 0。

把弱对偶证明里的等式搬过来，两个Σ项分别被「饱和」和「零流量」钉死：第一项恰好等于割容量，第二项为 0，于是 |f| = c(S,T)。结合第一半「所有流 ≤ 所有割」，得到

max |f| = min c(S,T)，而且算法终止时手里的流和这个割就达到了这对极值。∎

这个证明顺手送了两个副产品：

  • 整数性：如果所有容量是整数，Dinic 每次增减的都是整数，long long 存下来的最大流一定是整数；最小割也是整数。这就是「整数容量网络里最大流必可取整数」的构造性证明。
  • 对拍的合法性：dinic_maxflow 的暴力枚举割，靠的正是这个定理——它算的是 min cut，我们比的是 max flow，两者必须相等。如果定理不成立，这个对拍从根上就站不住。

拿演示网络验一遍弱对偶，定理就落地了。取割 S = {0,1,2,3,4}、T = {5}，跨割的边只有 3→5（容量 2）与 4→5（容量 2），割容量 4，正好等于最大流。再取割 S = {0}、T = {1,2,3,4,5}，跨割的是 0→1（3）与 0→2（2），割容量 5——比最大流大。所有 2^4 = 16 个割里最小的是 4，这正是暴力程序打印出来的那个数。顺便注意「割容量只算 S→T 的边，不算 T→S 的边」：这个方向性是最大流问题的定义决定的——我们只关心水能不能从 s 送到 t，从 T 倒灌回 S 的管子帮不上忙。最后，对 S 中除 s 外的每个点，「流入 = 流出」是守恒的，把它们全加起来，内部边一进一出抵消干净，只剩 s 的净流出——这就是弱对偶证明里那行等式的全部内容，没有更神秘的机制。

7.9 最小费用最大流：SPFA 与负权反边

大白话用大白话说费用流

普通最大流只问「最多能送多少水」，费用流多问一句：「送这些水，过路费最少多少？」做法很自然：每一轮还是找增广路，但不再随便找一条，而是找单位费用最便宜的那条，能送多少送多少。问题在于「反边」——撤回流的时候，费用得倒贴回去，所以反边的费用是负数；有负边，裸 Dijkstra 就不敢用了，得请 SPFA 出山。

工程惯例工程惯例：SPFA 还是 Dijkstra + 势能

SPFA 好写、能处理负边，但最坏复杂度没有好看的界，赛场上被构造数据卡住是常事。更稳的做法是势能法：先跑一次最短路算出每个点的势能 h[v]，以后每次用 c'(u,v) = c(u,v) + h[u] − h[v] 把费用改成非负，再用 Dijkstra；每轮更新势能。这样单次 Dijkstra 的复杂度有保证。惯例不是标准：本单元容量 1、费用非负、流量最多 8 的小图上，SPFA 完全够用，写势能反而更可能写错。什么时候升级？当你看到 F·V·E 的乘积逼近 1e8，或者题目明确卡 SPFA 时。

还有一处必须说清：连续最短路增广为什么给出「最大流量里的最省费用」。它依赖一个不变式——每一轮开始时，当前流是「流量为 k 的所有可行流里费用最小的一个」。k=0 时显然成立（没有流，费用 0）。归纳步：若当前流不是同流量里最省的，它与那个更省的流之差会形成一个总费用为负的环；而按最短路增广后的残余网络里恰恰不该存在负环（否则 SPFA 会沿着它继续压低费用），矛盾。增广沿的是最便宜的 s-t 路，所以得到 k+1 流量里最省的流。这里的前提是初始网络没有负费用边：本单元只有反边带负费用，而反边初始容量是 0，所以第一轮不存在负环。要是题目直接给了负费用边，先运行一次 Bellman-Ford 消负环，或者老老实实用带势能的版本，不能把 SPFA 往负环网络上硬丢——那会无限松弛，程序跑到超时。

7.10 建模：拆点、源汇与上下界入门

算法会写了，真正的难点才刚开始：把题目翻译成图。这一节给三把常用的钥匙，不展开到竞赛压轴题，但足够你认出「这题能往流上套」。

**第一把钥匙：源点与汇点。**凡是「从若干起点到若干终点、每个对象有容量上限」的问题，先造一个超级源 S 连所有起点、一个超级汇 T 接所有终点，边容量就是各自的限额。二分图匹配就是这么建模的：S → 左点（容量 1，表示每个左点只能用一次）、左点 → 右点（有边才连，容量 1）、右点 → T（容量 1）。此时最大流 = 最大匹配，König 定理给出了它的另一面。

第二把钥匙：拆点。题目说「每个点最多通过 k 次」「经过这个点要付一笔费」「这个点有容量」——图论原生只有边容量，不会直接约束点。办法是把点 v 拆成 v_in 和 v_out，中间连一条 v_in → v_out 的边，容量填 k、费用填过路费；原来所有进入 v 的边接到 v_in，所有离开 v 的边从 v_out 出发。于是「点限制」变成了「边限制」。

第 2 帧是核心动作：原来经过 v 的每一条路径，现在都必须穿过 v_in → v_out 这条边，所以限制自动生效。第 3 帧说明拆点可以和源汇叠加——这是「最小路径覆盖」「 points 不相交路径」这类题的标配建图。

**第三把钥匙：上下界入门。**前面的边容量默认下界是 0；题目若说「这条边至少要流 l、最多流 c」，把它改成上下界网络。标准变换是：先按下界 l 强行流一遍，记每个点的盈亏 d[u] = 流入下界 − 流出下界；原边容量改成 c − l（表示还能加多少）；再加一个超级源 SS 和超级汇 TT：若 d[u] > 0，连 SS → u 容量 d[u]；若 d[u] < 0，连 u → TT 容量 −d[u]。最后从 SS 到 TT 跑一次最大流，跑满说明存在满足上下界的流。这一招的思想是「先用掉强制部分，再补齐盈亏」，本单元只要求认得它，不要求现场推。

三把钥匙经常叠加。举一个网格上的例子：m×n 的格子里有些是障碍，问「从左上走到右下，每个可走格子最多经过一次，最多能走几条点不相交的路」。先把每个可走格子 (i,j) 拆成 (i,j)_in 与 (i,j)_out，中间连容量 1 的边（表示这个格子只能过一次）；四方向相邻的两个格子之间连 (i,j)_out → (i′,j′)_in 容量 1；起点接超级源、终点接超级汇。跑一次最大流就是答案。你看，这里没有新算法，只有「拆点 + 源汇」两把钥匙的组合。上下界那段也一样：做完强制下界的流量记账后，如果 SS 出发的边没能全部流满，说明盈亏补不齐，原问题无解——这个「跑不满即无解」的判据，比逐条检查约束省事得多。

注什么时候不该用网络流

网络流不是万能胶。三条硬边界：规模——V=2e4、E=2e5 时 Dinic 还能跑，V=1e5 且稠密就别想了，2^V 的割枚举更是只能在 V≤20 的玩具图上当裁判；常数——同样一张二分图，匈牙利 O(n·m) 的直接实现通常比「建网络 + Dinic」快一个数量级，能用简单算法就别绕；问题形状——带三个及以上约束（比如「每人最多 k 个且总费用有预算且互斥」）往往已经不是流能表达的，硬套会建出指数级大图，该转向 DP、2-SAT 或搜索。判断顺序永远是：先看能不能用并查集/贪心/DP，不能再看是不是二分图匹配，最后才是网络流。

7.11 对拍、平局与 C++ 应用层

三份对拍的共同结构你已经见过：固定种子 LCG、每组数据正解和暴力各算一次、不一致就打印轮次和两边的值。OK 200 不是「程序没崩」，而是「200 组独立随机数据都验证了结论」。三份校验和（504 / 645 / 680）各自来自不同的生成逻辑，重跑必然逐字一致——这是 alg02 立下的老规矩。

平局问题在这里比 MST 单元更温和：最大匹配数、最大流值、最小费用都是唯一的数，不像 MST 有「树形可不唯一」的烦恼。所以直接比数值即可，不用担心「正确实现被误判」。需要注意的是版本一致性：Dinic 的暴力枚举割依靠最大流最小割定理，费用流的暴力用「最大基数匹配里的最小费用」，两个定义都必须和正解的优化目标完全对齐，否则对拍自身就是错的。

M14 的 C++ 应用层把匈牙利换成 STL 零件：std::vector<std::vector<int>> 存邻接表，vector<int> 存 matchR 与 vis，每轮新建一个 vis 向量就等于每轮重置。生成器和 C 版用同一个 LCG、同一个种子、同样的调用顺序，所以两版看到的是同一批 200 组图，校验和应当逐字相等。

两处 504 与 C 版 hm-out 里的 504 逐字相同。这不是配置出来的巧合：三份实现共享同一个 LCG 种子与调用序列，看到的是同一批图；再加上「最大匹配数唯一」，校验和必然咬合。任何一版生成逻辑漂移、任何一版算法写错，这个数立刻散架。

工程惯例工程惯例：C 手写层与 C++ 应用层各留一份

C 手写层用 matchR + 邻接矩阵，你能看清每个格子什么时候被改写、每轮 vis 什么时候清零；C++ 层换成 vector，两行完成初始化与遍历，代价是内存布局交给标准库、出问题时 gdb 里看到的是模板展开后的长符号。赛场分工是：原理层手写一遍，应用层才敢放心用 STL。不知道负权反边为什么必须初始化的人，用 priority_queue 版 Dijkstra 写费用流时连「为什么不能直接用」都说不清。

小结这一节的要点
  • 匈牙利用 matchR[j] = u 记录右侧 j 的归属；−1 才是未匹配，初始化不能用 0；vis 每轮重置（或改时间戳写法），否则本该走的路被旧标记堵死；
  • Berge 引理：M 最大 ⟺ 无增广路。有增广路就翻转它使匹配 +1；若 M 非最大，取 M ⊕ M′ 中含 M′ 边更多的那条路径，它必是增广路；
  • König 定理：二分图最大匹配 = 最小点覆盖。弱对偶给出 |M| ≤ |C|；从未匹配左点交错 DFS，取 C = (L∖Z_L) ∪ Z_R，每条匹配边恰好贡献一个覆盖点，且每条边都被盖住；
  • Dinic 的 head 只读、cur 可写；BFS 在残余网络上分层，DFS 只走层数 +1 的边；阻塞流后所有分层图正向边饱和，反向边只会让层数下降，故不存在漏掉的增广路；
  • 容量与 INF 一律 long long；cap[e^1] += d 长出反向边，是「反悔」的通道；
  • 最大流最小割：弱对偶用 S 点集上的流量守恒求和；存在性取最后 BFS 的可达集 S，跨割正向边饱和、反向边零流，故 |f| = c(S,T)；
  • 费用流反边初始就该带负费用；SPFA 队列必须环形（n+1 槽 + 取模），线性队列会因反复入队而越界；势能法可换成 Dijkstra，但小图上 SPFA 更省心；
  • 建模三钥匙：超级源汇、拆点（点容量变边容量）、上下界（强制下界 + 盈亏补流）；规模、常数、约束个数是「不该用网络流」的三个信号；

注自测题答案
  1. matchR 来自裸内存，只有显式写 −1 才有「未匹配」这个语义。用 memset(…, 0, …) 会把所有右侧点伪装成「被 0 号左侧点占了」，DFS 一上来就递归到 0 号点的旧主人，结果静默错乱；0 是合法的左侧点编号，不能当哨兵。
  2. 增广路相对于 M 是一条两端都未匹配、边在「不在 M / 在 M」间交替、首尾都不在 M 的交错路，所以非匹配边比匹配边多一条。翻转后路径内部每个点仍恰好接一条匹配边，两个端点从 0 条变成 1 条，匹配数 +1。
  3. 取 Z_L ∪ Z_R 会把「从左侧未匹配点出发能走到的左侧点」也选进覆盖，但它们接出去的边另一端常常也在 Z_R，白白多算；更关键的是，若某条匹配边两端都在 Z_L 与 Z_R 里，它贡献 2 个点，覆盖大小会大于 |M|。正确的 (L∖Z_L) ∪ Z_R 让每条匹配边恰好贡献 1 个点，从而 |C| = |M|。
  4. head[u] 是邻接表的起点，是全局地图；cur[u] 才是本轮扫描的游标。若直接推进 head，第一轮结束后邻接表就被破坏了，第二轮 BFS 虽然重算 level，却沿残缺的边表遍历，大量边永远扫不到，最大流偏小。
  5. 用到「对残余网络中任意剩余容量 > 0 的边 u→v，都有 level[v] ≤ level[u]+1」——否则 s→u 最短路接这条边会给出更短的 v 路，与 level[v] 是最短距离矛盾。阻塞流后，分层图正向边全部饱和，新反向边让 level 下降，其余边满足 level[v] ≤ level[u]，于是没有任何边能让 level 增加，从 0 出发到不了 level ≥ 1 的 t。
  6. 反向边表示「把这股流撤回去」，费用必须与正向相反，所以初始化就是 −c；漏写负号会让 SPFA 以为反悔还要再付一次费，得到的最小费用偏大。SPFA 里同一个点会被多次松弛、反复入队，入队下标 r 单调增长；线性数组 q[n] 会在 r ≥ n 时越界写（实测崩在 free(q)，伴随 HEAP 警告），所以队列开 n+1 槽并对 n+1 取模，循环条件用 h != r。
