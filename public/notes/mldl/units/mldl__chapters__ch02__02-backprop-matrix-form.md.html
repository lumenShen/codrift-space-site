2.1 先看工程长什么样

上一单元那个 2-2-1 网络只有 9 个参数，反向写了十来行，你还能用纸面跟着走。真正的网络有几十万到几百亿个参数，每行代码背后是一整张矩阵；如果只会在标量层面推链式法则，形式一旦换成 batch 就会把 1/m 放错位置、把转置漏掉，而程序照样跑出「看起来还行」的 loss。这一单元要做的，就是把上一单元那几条标量直觉升级成矩阵模板，并证明升级后的结果和框架算出来的一模一样。

例子的目录是 books/mldl/examples/ch02/backprop_matrix/。它延续了两条写作纪律：入口 main.py 必须 import 本地的 backprop.py；手算梯度、中心差分、框架 autograd 三条路径彼此独立，谁也不许抄谁的答案。清单仍是 mode=numerical，expect.numbers 里钉住九个真跑读数，容差 atol=1e-6 只写在清单里。程序自己不打 PASS——判定权在闸门，它从 stdout 自己解析数值行并重算差值。

有人会问：既然框架能做 autograd，为什么还要手写一遍？两个理由。第一，框架自动化了「记账与沿图倒走」，却没有替你检查前向是否正确、损失是否按 batch 取了均值；这些恰好是本单元最容易错的三个地方。第二，autograd 不是独立证据：如果前向写错，它照样给出错得很精确的梯度。保留一条从链式法则直接写出的手算路径、再加一条从导数定义出发的中心差分，才能把「梯度正确」从自称变成可验证的事实。三条路在六位小数上重合，是这一节真正的结论；它们恰好重合这件事本身，比任何一行自报的判定字样都有分量。

第 2 帧的树是自包含的：上一节的四个文件都重画了一遍，只把本单元新增的四个标成 +。读多帧图时这是硬规矩，渲染器不会把上一帧的节点自动带过来。backprop.py 里只有 NumPy：前向、解析梯度、中心差分三条路都在里面，它不 import torch；main.py 才建 autograd 图，并把三条路径的结果压成可对账的标量。

工程惯例为什么手算模块里连 torch 都不能出现

如果中心差分和解析梯度都只调用框架的 .backward()，那两个「独立路径」其实同源，对齐得再漂亮也只是同一段代码和自己对账。本例把 backprop.py 限定为纯 NumPy，并在正文里公开约定：它的 manual_grads 完全依据链式法则写出，numeric_grads 完全依据导数定义写出，两者都不读任何计算图。这样 autograd 结果一进来，就是三条来源不同的证据摆在桌上。代价是代码多几十行，换来的是「梯度正确」这句话真的有支撑。

2.2 从单样本到 batch：多出来的不只是循环

单样本反向时，损失是一个标量，梯度是一组数。batch 之后，输入从 x 变成 X（形状 m×d），激活从 h 变成 H（形状 m×h），损失变成每条样本损失的均值。两件事随之改变。第一，梯度要跨样本求和：每个参数被 batch 里每一条样本共同影响，总敏感度是各条样本贡献的累加。第二，求完和要除以 batch 大小：因为损失是均值而不是总和，这个 1/m 必须恰好出现一次，不能漏也不能重复。

本例用五个样本、三维输入、四隐单元、二维输出：输入 X 是 (5,3)，第一层分数 Z1 与激活 H 是 (5,4)，输出 Y 是 (5,2)，目标 T 同形。这些形状不是随便写的，它们决定了每一次矩阵乘和每一次转置的方向。把形状写在纸上，再看代码里的 @ 与 .T，反向就不再是背公式，而是「让维度对得上」的填空。

第 3 帧里 X -> gw1 这条边值得停一下：gw1 = Xᵀ @ d1，Xᵀ 是 (3,5)，d1 是 (5,4)，乘出来正好 (3,4)，和 w1 同形。权重梯度是输入与敏感度的外积（按 batch 求和），不是内积；如果把 X @ d1 写出来，形状是 (5,4)，立刻就不对。偏置梯度 gb1 = sum(d1) 沿着 batch 维求和，得到 (1,4)，它不接输入，所以没有转置也没有外积。

陷阱把 batch 均值写成总和，忘了除以 m

你会看到 loss 随训练下降，方向也对，于是以为「只是数值大一点」；你会误判成学习率的问题，试着把它调小。真相是梯度被整体放大了 m 倍——本例 m=5，相当于把学习率偷偷乘了 5。更隐蔽的是：如果每步训练换一个 batch 大小，梯度尺度也会跟着变，训练曲线忽快忽慢。查法是在代码里找那个 m，看它是不是既出现在 loss 的分母、又出现在输出侧敏感度 d2 的分母，而且只出现一次。本例 m = x.shape[0] * z2.shape[1] 同时把样本数和输出维度算进去，因为 np.mean 是对所有元素取均值，不是只按行取。

单样本与 batch 的差别还可以从计算图角度看清楚。单样本是一条链，backward 就是沿链倒走；batch 是同一条链被复制 m 份，但参数节点是共享的。共享意味着反向时不能只回传最后一条样本的梯度，而要把 m 条副本在参数节点处相加——矩阵形式的 @ 与 sum 正是这件事的紧凑写法。理解了这一点，你就明白为什么框架要把梯度存进 .grad 而不是当返回值传出去：多次前向可能对应同一个参数，必须先累加再更新。

拿一条具体连接算一遍。W2[1,0] 是第二个隐单元连到第一个输出的权重，梯度是 Σ_t δ⁽²⁾_{t,0} · H_{t,1}，也就是五条样本贡献之和。矩阵形式的 gw2 = Hᵀ @ d2 里，第 (1,0) 格恰好就是这个和：转置后的第 1 行是五个 H_{t,1}，d2 的第 0 列是五个 δ⁽²⁾_{t,0}。手写循环要五步、矩阵只要一次乘；样本数从 5 变成 5000 时，代码一个字不改。矩阵形式省下的不只是键盘输入，它把「跨样本求和」这件事编码进形状约定，让漏乘一项变成形状错误而非沉默的数值偏差。

2.3 δ 的定义与三条反向规则

现在把反向写成模板。设第 l 层的线性分数是 z⁽ˡ⁾ = a⁽ˡ⁻¹⁾ W⁽ˡ⁾ + b⁽ˡ⁾，激活 a⁽ˡ⁾ = φ(z⁽ˡ⁾)。定义

δ⁽ˡ⁾ = ∂L/∂z⁽ˡ⁾

读作「这一层每个线性分数对最终损失有多敏感」。它与 z⁽ˡ⁾ 同形，batch 下就是 m×宽度。有了 δ，整条反向只剩三句话：

  • 输出层：δ⁽ᴸ⁾ = ∂L/∂z⁽ᴸ⁾，由损失函数直接给出。本例是线性输出配平方误差，所以 δ⁽²⁾ = 2(Y-T)/(m·n_out)；
  • 往回一层：δ⁽ˡ⁾ = (δ⁽ˡ⁺¹⁾ @ (W⁽ˡ⁺¹⁾)ᵀ) ⊙ φ′(z⁽ˡ⁾)；
  • 参数梯度：∇_{W⁽ˡ⁾} L = (a⁽ˡ⁻¹⁾)ᵀ @ δ⁽ˡ⁾，∇_{b⁽ˡ⁾} L = sum_batch(δ⁽ˡ⁾)。

三条规则里，第二条最值得盯住。δ⁽ˡ⁺¹⁾ 的形状是 (m, n_{l+1})，下一层的权重 W⁽ˡ⁺¹⁾ 形状是 (n_l, n_{l+1})；要让结果落回 (m, n_l)，必须把它转置成 (n_{l+1}, n_l) 再乘。转置不是风格，是形状对齐的唯一方式。 后面的逐元素乘 ⊙ φ′(z⁽ˡ⁾) 则是激活函数那条边的局部导数：它不混合不同神经元，只把每个位置的敏感度乘上该位置的斜率。

第 3 帧里 w2 被重画了一遍，尽管它已经在第 1 帧的「H -> z2」这条边里出现过——这正是帧自包含的要求：读者看这一帧时，必须能同时看到敏感度和那张被转置的权重，否则「为什么转置」就讲不清。图中没有把 W1 的梯度画出来，因为它属于「参数梯度」那条规则，下一节的代码里会直接落在 gw1 = x.T @ d1 这一行。

还要分清 δ 与参数梯度的角色。δ 是关于中间量的敏感度，它的形状跟着激活走；参数梯度是关于参数的敏感度，形状跟着权重与偏置走。它们不是同一个对象：δ 在层与层之间流动，参数梯度则从每一层被「摘下来」交给更新器。一条边同时产出两样东西——往上游继续传的 δ，以及留给本层参数的梯度——这正是反向函数既返回输入梯度又更新参数缓冲的结构来源。只盯着参数梯度看，你会觉得反向是「算出四个矩阵」；盯着 δ 看，才会发现它其实是一条从输出流向输入的连续信号。

从 Jacobian 的角度看，激活那一步的局部导数是对角矩阵：a⁽ˡ⁾ = φ(z⁽ˡ⁾) 是逐元素运算，第 i 个输出只依赖第 i 个输入，所以 ∂a/∂z 对角线上是 φ′(z_i)、其余全零。乘一个对角矩阵等价于逐元素乘，这就是公式里 ⊙ φ′(z⁽ˡ⁾) 的由来。理解这一点之后，看到 LayerNorm、BatchNorm 这类「会把不同分量混在一起」的层，你就知道它们的局部导数不再是对角矩阵，反向不能只写逐元素乘——那是后面单元的一处重要区别。

大白话把 δ 想成「每个旋钮的紧急程度」

前向是工厂流水线：原料从输入进来，经过两道加工变成成品，最后有一个质检分数。反向不是重新生产一遍，而是质检员往回走：先标出成品哪几个位置最需要改，再按「这道工序把上一站送到哪几个位置」把责任往回摊。每往回一站，都要按该工位把责任分摊到上一站的各个旋钮上——分摊用的是工序矩阵的转置，乘完还要看这个位置的激活是不是迟钝（导数小），迟钝的位置分到的责任自然少。严谨说法就是上面三条规则；类比只是为了记住「敏感度、分摊、局部斜率」这三件事的顺序。

2.4 转置从哪里来：Jacobian 布局与 Hessian 的呼应

线性代数分册在讲矩阵微分时定过一个约定：Jacobian 的行对应输出分量、列对应输入分量。若 y = Ax，y 是 m 维、x 是 n 维，则分子布局下 ∂y/∂x = A，形状 m×n；而框架里的梯度必须与变量同形，是 n 维，于是要把那一行翻过来，得到 Aᵀ。这一册用的都是分母布局（梯度与自变量同形），所有转置都是这次「行列翻译」留下的痕迹。

拿本例的第二层验一次。z2 = H W2 + b2，其中 H 是 (m,4)、W2 是 (4,2)。固定 H 看 W2 的一个元素 W2_ij：它只影响第 i 列的输出分数（对每条样本都是），所以 ∂L/∂W2_ij = Σ_t δ⁽²⁾_{t,i} · H_{t,j}。写成矩阵就是 Hᵀ @ δ⁽²⁾，形状 (4,m) @ (m,2) = (4,2)，恰好与 W2 同形。如果你写成 H @ δ⁽²⁾，(m,4) 乘 (m,2) 根本不成立；如果写成 δ⁽²⁾ᵀ @ H，得到 (2,4)，形状合法但每个格子装的是「转置后的那张表」，更新时会写错权重——这正是方形权重矩阵里最阴险的那类 bug：转置前后都是方阵，形状检查毫无反应。

再看 δ 回传那一步的转置。δ⁽¹⁾_j = Σ_i δ⁽²⁾_i W2_ij，求和指标 i 是下一层的神经元编号。要让 W2 的列跟着 i 走，就得用 W2ᵀ；否则你算的是按行求和，数值完全不同。把两处转置连起来读：∇_{W} L = aᵀ δ 是外积，δ_prev = δ_next Wᵀ 是矩阵乘转置——一个把敏感度摊回输入侧，一个把敏感度摊回参数侧，方向不同但来源相同。

Hessian 分册把这条线推到了二阶。Hessian 是「梯度的梯度」，即 H = ∂²L/∂x²；因为混合偏导可交换，光滑函数的 Hessian 是对称矩阵。一阶梯度之所以要和变量同形，是为了让优化器写 W -= lr·gradW 时逐元素对应；二阶矩阵之所以是方阵，是因为它描述「每个参数的变化如何影响另一个参数的梯度」。链式法则在二阶时要多出一项由 Jacobian 与 Hessian 夹出来的交叉项，这就是为什么高阶优化昂贵。你在这里练的转置纪律，到了 Hessian 那里会原样出现：把「行是输出、列是输入」翻译成「与变量同形」的动作，仍然是转置。

把本例的数字代进去验一个格子，能把这个转置钉死。真跑打印的第一层梯度向量里第十二个分量是 -0.309007，它对应 W1[2,3]（第 3 个输入连到第 4 个隐单元的权重）。按模板，它应等于 Σ_t x_{t,2} · d1_{t,3}，也就是五条样本的输入第 3 维与隐层敏感度第 4 列的乘积之和。手写循环求和与 x.T @ d1 给出的第 (2,3) 格必须是同一个数；你不必在心算里完成五步乘法，但要能指出这五步分别是什么。能定位到下标，才叫真的理解转置，而不是记住了「反向要加 .T」这句口诀。

陷阱方形权重让漏转置隐形

你会觉得 W2 是 4×4 时转不转置形状一样，于是跳过检查；你会误以为「形状对就没问题」。真相是形状检查只能抓维度不匹配，抓不住「维度合法但下标错位」。δ @ W 与 δ @ Wᵀ 都是 (m,4)，后者对、前者错，程序没有任何提示；本例的输出层是 4×2，形状不同的情况反而更友好。训练深层网络时，很多层都是同形方阵，所以必须靠显式对拍而不是形状直觉——这就是下一节三方对账存在的理由。

2.5 手写 batch 梯度：把模板落成代码

backprop.py 里的 manual_grads 就是上一节三条规则的逐行翻译。它先调 forward 拿到缓存，再按「输出侧 → 参数梯度 → 隐层侧 → 参数梯度」的顺序走；所有运算都按 batch 矩阵写，没有一条 Python 循环遍历样本。1/m 被收进 d2，后面每一层都继承这个归一化，不必重复除。

逐行对一下模板。d2 = 2*(z2-t)/m 是输出层 δ，这里的 m 是 batch 大小乘输出维度，因为 np.mean 对 (5,2) 的所有十个元素取均值。gw2 = h.T @ d2 是 (4,5) @ (5,2) = (4,2)，与 w2 同形。gb2 沿 batch 维求和，keepdims=True 保住 (1,2) 的形状，避免以后广播出奇怪结果。d1 = (d2 @ w2.T) * (1-h²) 同时完成「乘权重转置」和「乘 tanh 导数」；(1-h²) 用的是前向缓存里的 h，不重算激活。最后 gw1 = x.T @ d1 是 (3,5) @ (5,4) = (3,4)，gb1 是 (1,4)。四处矩阵乘，两处 .T，四个梯度形状与四个参数一一对应——模板落地就是这么朴素。

缓存的纪律也值得单独说。forward 返回 z1, h, z2, sq 四个量，其中真正被反向用到的是 h 和 z2；z1 与 sq 留着是为了让调用方在需要查看中间量时不必重跑。sq 其实只是 (z2-t)²，反向里没用它——留它是为了让「损失由什么构成」在数据结构里可见，而不是藏在函数内部。这种「宁可多传一个量」的写法在小程序里显得啰嗦，在真实框架里正是所谓「保存供反向使用的张量」：框架的显存开销大头就在这里，所以才需要 no_grad、梯度检查点与重计算这些手段来换空间。

工程惯例keepdims 不是风格问题

sum(axis=0, keepdims=True) 与 sum(axis=0) 数值相同、形状不同：前者给出 (1,4)，后者给出 (4,)。在这个小例子里两者都能广播回正确形状，所以看不出差别；一旦后面接上需要严格维度的运算（比如与外部梯度拼接、或把梯度写进同形的缓冲区），少这个维度就会报广播错误，或者在更糟的情况下被静默扩展到每一列。本书统一保留 batch 维，就是为了让「梯度与参数同形」在程序里也成立，而不是只在数学推导里成立。

2.6 autograd 的 grad_fn 图：框架也在走同一条路

框架并没有什么魔法。你写下 y = torch.tanh(tx @ tp[0] + tp[1]) @ tp[2] + tp[3] 时，每一步运算都会产生一个新的张量，并在这个张量上挂一个 grad_fn，记下「我是由哪两个张量、通过什么运算得到的」。这些 grad_fn 串起来就是一张有向图；backward() 从标量损失出发沿图倒走，每条边乘上该运算的局部导数。它不会替你推导公式，却也不会漏掉链式因子——因为局部导数是跟着运算记录一起存下来的。

四个参数张量都开了 requires_grad=True，所以它们是叶节点，反向后 .grad 会被填成与参数同形的张量。中间量 y、auto_loss 是非叶节点，它们持有 grad_fn 但默认不保留 .grad——框架只在叶节点上存梯度，省内存。用 dtype=torch.float64 是为了和 NumPy 手算使用同样的精度；如果这里用默认的 float32，最后几位小数必然不同，三条路径就失去了严格对拍的资格。

第 2 帧的星号连着三条记录，正是前向那一行代码拆开的三步；第 3 帧只画了通往部分叶节点的边，因为一张图塞满四个参数的梯度会超出「单帧节点不超过十八个」的约束，读图时心里记住还有 db2、dw1、db1 三条并行分支即可。把这张图和 2.3 的 graph 对照看，你会发现框架走的边、乘的因子与手写模板一一对应：框架自动化的是记账与局部导数，不是数学本身。

动态图的另一个后果是「图用完即弃」。每次执行前向那一行代码，框架都现搭一张新图；backward() 走完之后，这张图连同它保存的中间量就被丢弃。下一次循环必须用新的 y 和新的 auto_loss，不能把上一次的 grad_fn 留到这一步。本例只跑一次前向与反向，看不出这个约束；一旦写成训练循环，就会看到每轮都重新建图、重新计算、重新反向。好处是前向代码里可以写普通的 Python 分支和打印，图会照着本次实际走的那条路径搭出来；代价是每轮都有建图开销，这是后面用编译工具优化训练的动机。

陷阱在非叶节点上读 .grad 期待拿到梯度

你会写 print(y.grad) 想看看输出层的敏感度，结果得到 None；你会误以为图断了、backward() 没生效。真相是框架默认只为叶节点保留 .grad，中间节点的梯度算完就传下去、用完即弃。真想看某个中间量的梯度，必须先调 y.retain_grad()。这不是苛刻：上亿个中间量全存下来会撑爆显存。本例只打印四个叶节点的梯度范数，正合框架的接口设计——该更新的只有参数，不该更新的看完就该丢。

2.7 真跑：手写、autograd、中心差分三方对账

入口把三条路径的结果压成可比较的标量，再按数值行规则打印。dw_manual 与 dw_auto 是第一层权重梯度的范数——把一个 3×4 矩阵压成一个数，才能享受 atol=1e-6 的数值对账；grad1:[...] 用冒号保留十二个分量的结构，走逐字比较。db_diff、dw2_diff、db2_diff 是另外三个参数的最大绝对误差，cd_diff 是手写梯度与中心差分的最大绝对误差。

清单里九个黄金值并不是九次重复劳动，而是一张分工表。loss 与 auto_loss_diff 管前向；dw_manual、dw_auto、diff 管第一层权重；另外三个 *_diff 管其余参数；最后 cd_diff 管「手写公式是不是真对」。如果某次改动让 dw_manual 与 dw_auto 一起变大但差仍为零，说明前向或数据变了，而不是梯度实现坏了；如果只有 cd_diff 变大，问题多半出在手写公式里漏了一个链式因子或转置。读输出时先按这张分工表定位，再去看代码，能省掉大量瞎猜。

九行读数各管一件事。loss 是前向的黄金值，它保证「损失真的由这组数据算出」；auto_loss_diff 是两条前向路径的交叉验证；dw_manual 与 dw_auto 是两条梯度路径的范数，diff 是它们的差；db_diff、dw2_diff、db2_diff 把检查扩大到另外三个参数；cd_diff 则把完全不懂链式法则的中心差分请进来当裁判。任意一行出问题，定位方向都不一样：只有 cd_diff 大，说明手写公式错了；只有 dw_auto 一侧异常，说明建图方式（dtype、requires_grad、是否误进 no_grad）有问题。

工程惯例为什么用范数与最大误差，而不是整张矩阵

清单的 expect.numbers 只能声明标量黄金值。3×4 的权重矩阵有十二个数，逐项写成 gw1_0=... 当然也能对账，但读者就看不出「这是一个矩阵梯度」的结构。本例的做法是：把矩阵压成范数走数值通道享受容差，把十二个数排成 grad1:[...] 走文字通道逐字比较。前者查「差一点」的漂移，后者查方向与分量，两种证据互补。最大误差同理——它比平均值更严格，任何一个分量出错都会立刻暴露。

2.8 梯度检查：中心差分为什么是「明显正确的暴力版」

中心差分的实现极其朴素：把第 k 个参数加 eps 算一次损失，减 eps 再算一次，斜率 (f₊-f₋)/(2eps) 就是偏导的近似。它完全不知道链式法则、不知道 δ、也不知道转置，所以不可能犯手写公式那类错。eps 取 1e-5：太小会被浮点舍入淹没，太大又会引入截断误差；双精度下这是常用折中。

这里有个容易忽视的纪律：扰动必须落在副本上，或者像本例这样改完立刻还原。p 是四个参数数组的元组，直接改 p[idx] 会污染原参数；如果忘记 p[idx] = old，后面的参数检查将在被改过的参数上进行，结果全乱。本例每次循环都保存 old、扰动两次、精确还原，所以 numeric_grads 返回后原参数仍然完好。这是「暴力但明显正确」的代价——慢，而且必须自己管好现场。

把误差账算细一点，就知道为什么 eps=1e-5 不是随手挑的。截断误差来自泰勒展开里被丢掉的三次项，量级约 eps²·f'''/6，随 eps 变小而变小；舍入误差来自 f₊ 与 f₋ 各自的浮点噪声，除以 2eps 后被放大，量级约 2u|f|/eps，其中双精度机器精度 u≈2e-16，随 eps 变小反而变大。两者平衡点落在 eps≈u^(1/3)，也就是几微这个量级。本例的平方损失三阶导数为零，截断项理论上消失，剩下的只有舍入，所以六个分量能精确到小数第六位并全部显示为零。若把 eps 压到 1e-15，f₊ 与 f₋ 几乎相同，相减后有效位数被吃光，cd_diff 反而会跳起来——这不是梯度写错，是差分步长选坏了。

参数总数是 3×4+4 + 4×2+2 = 26，每个参数两次前向，一次梯度检查要跑 52 次前向。本例规模小，眨眼就算完；换成一亿参数的网络，同样的检查要跑两亿次前向，完全不可行。中心差分是裁判，不是运动员：它慢，但它明显正确，正适合在离线时给解析梯度背书。训练时用的是 autograd，因为一次前向加一次反向就能拿到全部梯度，成本与一次前向同阶。

陷阱拿中心差分去查 ReLU 在零点附近的梯度

你会觉得「差分这么可靠，哪里都能查」；你会误以为结果不对就是反向写错了。真相是 ReLU 在 0 处不可导，中心差分跨过拐点算出的斜率是某个平均值，而 autograd 在 0 点取的子梯度可能是 0 或 1，两者天然可能不一致。类似情况还有 abs 在 0、norm 在 0、以及一切带 if 分支的前向。正确做法是把检查点稍微挪开拐点，或者只对光滑区域做检查。本例全程用 tanh 与平方误差，处处光滑，所以四条差值才能整齐地归零。

2.9 三类高频错误：漏 1/m、漏转置、广播污染

第一类错误已经说过：batch 均值漏除 m，梯度整体放大。它的症状很规律——loss 曲线形状正常但下降过快，换 batch 大小后行为改变。查法是打印一次 d2 的量级，确认它包含 1/(m·n_out)。本例把 m 写成 x.shape[0] * z2.shape[1]，正是因为 np.mean 把样本和输出两个维度一起平均了；用平方损失配多输出时，这个细节比想象中常见。

第二类错误是漏转置或转错方向。症状更隐蔽：形状合法、loss 照降、只是效果略差。查法只有对拍——把 d2 @ w2.T 临时改成 d2 @ w2，本例输出层形状不匹配会当场报错；但换成同形方阵就不会报，此时 cd_diff 会从 0 跳到非零。凡是维度合法的错误，最终都得靠一条独立路径来抓，这是这一单元最重要的证据纪律。

第三类是广播污染。假设偏置梯度写成 d2.mean(axis=0) 而参数形状是 (1,2)，形状是 (2,)，眼前还看不出问题；一旦在反向链里把它与 (5,2) 的量相加，NumPy 会把 (2,) 广播到每一行，得到形状正确的垃圾。keepdims=True 就是对付它的：(1,2) 与 (5,2) 相加语义明确，与 (2,) 相加则容易误入广播。养成在每个 sum / mean 后打印形状的习惯，比事后追数值异常省时得多。

这三类错误的共同点是：程序都不会崩。漏 1/m 只是尺度变了，漏转置在方阵上只是下标换了，广播污染则直接产出合法形状。能把它们揪出来的只有独立路径与形状纪律，而不是编译通过或 loss 下降。写代码时多打两行调试输出，成本和追一整下午的数值异常完全不在一个量级；这也是本书每个例子都把中间量打到 stdout 的根本原因。

工程惯例把三方对拍写进 CI 的想法

工程里的常规做法是：写一个小的固定数据用例，跑一次前向与反向，把解析梯度和数值梯度逐项比较，容差按精度选（双精度 1e-5 上下，float32 要放宽到 1e-2 左右）。这个检查跑得很快，可以挂在每次提交前。它抓的是「改代码时把转置或 1/m 改没了」这类回归，抓不住「模型结构本身不适合任务」——后者要靠验证集。两种检查不互相替代：一个管实现正确性，一个管任务有效性。本单元的三方对拍就是这套做法的最小实物。

2.10 从这节走向框架：哪些事交给它，哪些事留给你

学完这一节，你应该能把责任分清楚。框架负责：记录前向运算、为每条边提供局部导数、沿图倒走并把梯度累加到叶节点。你负责：把前向写对、确认 dtype 与 requires_grad、确认损失是标量、确认 batch 均值的归一化只出现一次、以及设计一条独立路径去验证结果。框架不会告诉你「这个转置该不该在」——那是布局约定与分量推导的职责；它也不会告诉你「loss 不降是因为结构不够还是初值不好」——那是实验设计的职责。

PyTorch 的 torch.autograd.gradcheck 就是 2.8 那套流程的工业版：对双精度张量做有限差分，与 autograd 结果逐项比较，量级也在 1e-5 附近。自定义算子接入框架时通常要过这一关；手写 CUDA 反向核的人尤其重视，因为最容易漏的仍然是一个转置或一个链式因子。你今天手写的二十六行梯度检查，和它在方法上是同一件事，只是规模小到可以完全手算。

大白话反向传播没有创造新数学

它只是把链式法则按计算图的边排好顺序，再用矩阵乘把「对每条样本分别求导再求和」压成一次运算。前向把输入变成输出，反向把输出的敏感度变成参数的敏感度；中间每一步乘的因子，都是前向那一步的局部导数。所谓「误差反传」，传的不是误差本身，而是「最终结果对中间量有多敏感」这个数。把这句话记住，以后看到任何新层的反向实现，你都能自己推出来：它不过是该层前向运算的局部导数，乘以从上游传来的敏感度。

  • δ⁽ˡ⁾=∂L/∂z⁽ˡ⁾ 与分数同形；回传规则是 δ⁽ˡ⁾=(δ⁽ˡ⁺¹⁾Wᵀ)⊙φ′(z⁽ˡ⁾)，权重梯度是 (a⁽ˡ⁻¹⁾)ᵀδ⁽ˡ⁾；

注自测题答案
  1. np.mean((y-t)**2) 对 (5,2) 的所有十个元素取均值，分母是样本数乘输出维度。若只除以 5，梯度会放大 2 倍；一般地放大「输出维度」倍，多输出任务里这个错误很常见。
  2. 输出层 δ⁽ᴸ⁾=∂L/∂z⁽ᴸ⁾；回传 δ⁽ˡ⁾=(δ⁽ˡ⁺¹⁾(W⁽ˡ⁺¹⁾)ᵀ)⊙φ′(z⁽ˡ⁾)；参数梯度 ∇_{W⁽ˡ⁾}=(a⁽ˡ⁻¹⁾)ᵀδ⁽ˡ⁾，∇_{b⁽ˡ⁾}=Σ_batch δ⁽ˡ⁾。δ⁽ˡ⁺¹⁾ 是 (m,n_{l+1})，W⁽ˡ⁺¹⁾ 是 (n_l,n_{l+1})，只有转置成 (n_{l+1},n_l) 才能乘出 (m,n_l)；不转置则维度不匹配（同形方阵时数值错但形状合法）。
  3. 分子布局下 ∂y/∂x = A，形状 m×n（行对应输出、列对应输入）；分母布局下梯度与 x 同形，是 n 维列向量，等于 Aᵀ 乘上游梯度。两者相差一次转置，这正是反向代码里 .T 的来源。
  4. 框架默认只为叶节点保留 .grad，中间节点的梯度传下去后即丢弃，以免上亿个中间量占满显存。想查看要先 y.retain_grad()，再在反向后读它的 .grad。
  5. 错。中心差分每个参数要两次前向，一亿参数就是两亿次前向，训练中完全不可行。它是离线裁判，用于验证解析梯度或自定义算子；训练靠 autograd，因为一次前向加一次反向就能取得全部梯度。
  6. 形状检查只能抓维度不匹配；方阵转置前后维度相同，值却不同，程序没有任何异常。本例若把权重改成同形方阵并注入该错误，cd_diff（手写与中心差分的差）会首先变成非零；在当前 4×2 形状下，d2 @ w2 会直接报维度错误。autograd 路径不受影响，因此 dw_auto 仍正确，这也正是三方对拍的价值。
