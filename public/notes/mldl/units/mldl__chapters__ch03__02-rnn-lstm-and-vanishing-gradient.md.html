大白话循环一句话在说什么

把同一组权重在每个时刻用一遍，当前时刻的输出连同上一步的隐状态一起，算出这一步的隐状态。隐状态像一条不断被改写的纸条，前面读过的内容留在上面，后面的计算从纸条上取用。因为每一时刻用的是同一组权重，参数不会随序列变长而增加——这是循环网络与卷积网络共有的共享思想，只不过一个沿时间共享，一个沿空间共享。

8.2 循环与展开：一条链上的参数共享

循环网络最难懂的地方不是公式，而是「同一个模块被调用很多次」这件事。把 h_t = f(W x_t + U h_{t-1} + b) 这条式子按时间画出来，就得到一条链：每个时刻一个圆圈，圆圈之间由隐状态连接，每个圆圈都用同一组 W、U、b。这条链叫展开（unrolling）。展开只是画图上的复制，参数并没有跟着复制——24 个时刻共享同一张 W、同一张 U，这是它与「堆 24 层全连接」的根本区别。

第 1 帧只有一步，W,U 画成一组。第 2 帧展开到两步，注意 W,U 仍只有一份，只是被用了两次；x1 是零，说明后续没有新信息进来，隐状态全靠上一步传下来。第 3 帧把中间二十步压成一条省略的链，h23 是终点——本例真跑给出 rnn_h_last=0.000005，标记从第 0 步走到第 23 步几乎消失了。三帧里所有节点都写在当帧里，因为渲染器只画这一帧写出来的东西，上一帧的节点不会自动带过来。

展开带来的训练算法叫 BPTT（沿时间的反向传播）。它其实就是反向传播，只不过计算图是那条展开链：损失在最右端，梯度沿 h23 → h22 → … → h0 一路往回走，每走过一个时刻都要乘一次循环权重与激活函数的导数。这条回程是理解梯度消失的钥匙，后面第 8.6 节专门拆开看。

8.3 手写 RNN：一步前向与固定权重

例子用一个「只在第 0 步放标记、其余全零」的序列当探针。这是检验长期依赖的经典设计：如果模型能记住开头，第 23 步的隐状态就该与零输入时的状态明显不同；如果记不住，隐状态会衰减到接近零。权重写死而不随机初始化，是为了让对照不被初始化噪声污染——任何差异都只能来自循环结构本身。

第 18、19 行造出长度 24 的序列，只有 x[0,0] 是 1，其余 23 步全是 0。第 25 行的 wx 把一维输入投到二维隐状态，第 26 行的 wh 是对角矩阵，两个对角元都是 0.6，所以每一步的循环部分都是「把旧隐状态乘 0.6」——衰减速度一眼能看出来，谱半径 0.6 小于 1，梯度必然逐步骤缩小。

第 35 行是全部算术：x[t] @ wx.T 得到二维输入投影，h @ wh.T 得到上一步的循环贡献，相加后过 tanh 压到 (−1, 1)。第 33 行把隐状态初始化为零向量，这是序列模型的默认起点。第 37 行把所有步的隐状态堆成 (24, 2) 的表，方便打印整条轨迹。这段代码没有调用 nn.RNN 或 nn.RNNCell，所以你能指着任何一步说清它怎么算出来。

按这个公式手算前两步。第 0 步输入是 1、旧状态是零，所以 h0 = tanh([0.8, 0.6]) = [0.664037, 0.537050]。第 1 步输入是 0，只剩循环项：0.6 × h0 = [0.398422, 0.322230]，再过 tanh 得 [0.378598, 0.311522]。第 2 步继续乘 0.6 再过 tanh，数值继续缩小。24 步之后是 [0.000005, 0.000004]，正是 stdout 的 rnn_h:[0.000005, 0.000004]。衰减不是某一步突然发生的，而是每步都乘一个小于 1 的因子，累积起来的指数效应。

陷阱忘了把旧隐状态从头传下去

你会看到：第 0 步输出合理，后面所有步都变成同一个值甚至全零，损失不降。你会怀疑权重太小、学习率不对，或者数据标签错位。真相常常是：你在循环里写了 h = torch.zeros(2)，每一步都把纸条换成新纸，上一步的结果从未进入下一步。判断方法：打印前四步的隐状态，若第 1、2 步与第 0 步完全相同，就是状态没传下去。本例第 33 行的零初始化只在循环之前执行一次，循环体内只更新 h、不重置它，这是最容易被改写坏的一行。

8.4 LSTM：三门与细胞状态

LSTM 解决的就是上一节看到的衰减问题。它把隐状态拆成两份：对外仍输出 h_t，对内多保留一条细胞状态 c_t。细胞状态的更新是 c_t = f_t ⊙ c_{t-1} + i_t ⊙ ĉ_t：遗忘门 f_t 决定旧记忆留多少，输入门 i_t 决定新内容写多少。当 f_t ≈ 1 且 i_t ≈ 0 时，c_t ≈ c_{t-1}，信息沿着一条近乎恒等的通道穿过时间——梯度也能沿这条通道传回去，不再每步都被压缩。

第 46 行让四个门共用一次投影 z，这是为了教学清晰做的简化：真实 LSTM 给每个门配独立的权重矩阵，但那只会把数字变得难手算，不改变门控的机制。第 48 行给遗忘门加一个正 3.0 的偏置，z ≈ [0.8, 0.6] 时 f ≈ [0.978, 0.973]，非常接近 1——这就是「记住」的工程实现。第 51 行是细胞状态的加法更新，第 52 行才把 c 过 tanh 并乘输出门得到对外的 h。注意 c 不像 h 那样被 tanh 反复压缩，它可以用加法一路累积。

第 1 帧里第 0 步的标记通过输入门写进 c0，遗忘门虽然接近 1 但旧状态是零，所以没有可忘的东西。第 2 帧里输入变成零、输入门几乎不再写新内容，细胞状态靠 f ≈ 0.978 把旧记忆保留下来并略微增长。第 3 帧到达第 23 步，c23 仍是 2.862650，经 tanh 与输出门后 h23 是 0.582533——与 RNN 的 0.000005 形成鲜明对照。三帧都把当帧要看的闸门与状态写全，切帧时不会缺上下文。

本例的细胞状态一路涨到 2.86 而不是停在某个小常数，原因恰是三门共享投影：i 与 f 都接近 0.978，每步写入量略大于遗忘量，于是 c 缓慢累积。这是一个为展示通路而设计的玩具配置，不是真实训练出来的 LSTM。它足以说明要点：信息在细胞状态里被保留并累积，而不是被 tanh 反复压缩到零。真实模型里三门各有独立权重，门值由数据决定，c 通常不会这样单调增长。

8.5 真跑对账：24 步之后两条路差多少

入口把两条路径都跑一遍，再用 autograd 反查「第 0 步输入对最终输出还有多大影响」。做法是把最终隐状态的平方和当损失，对输入序列求梯度，取第 0 步那一格的绝对值。这个量就是长期依赖的直接度量：它若接近零，说明早期输入已经被网络忘干净。

第 24、25 行克隆两份输入并打开 requires_grad：原序列 x 保持干净，两份副本分别给两条路径求导，互不污染。第 26、27 行把最终隐状态平方和当损失——这只是一个标量代理，不对应真实任务，但足以让梯度沿整条链回来。第 28、29 行用 torch.autograd.grad 取出对输入的梯度，不需要手动清零 .grad。注意两条路径各自构建计算图，不能把 no_grad() 包在这里，否则图根本不存在，梯度全是 None。

真实 stdout 有 11 行，前八行是标量，后三行是张量文本。

rnn_h_last=0.000005 说明标记走完 24 步几乎消失；lstm_h_last=0.582533 说明 LSTM 还握着它；两者之差 long_dep_diff=0.582528 就是本例最直白的证据。梯度侧更悬殊：rnn_grad0=0.000000 在六位小数上为零，rnn_grad0_log10=-10.297742 告诉你它的真实量级约是 5×10⁻¹¹；LSTM 同一位置的梯度是 lstm_grad0=0.029265，比前者大九个数量级。这不是精度问题，而是结构差异的直接后果。

8.6 梯度消失从哪来

现在拆开 BPTT 的回程。设损失是 L = (h23)²，想求它对第 0 步输入 x0 的梯度。链式法则要求沿链把所有局部导数乘起来：∂L/∂x0 = (∂L/∂h23) · (∂h23/∂h22) · … · (∂h1/∂h0) · (∂h0/∂x0)。每一步的因子都含两块：循环权重 U 的转置，以及激活函数的导数 diag(1 − h²)。本例 U = 0.6 I，h 很小，所以 1 − h² ≈ 1，每步因子约 0.6。24 步连乘就是 0.6 的 23 次方，约 8×10⁻⁶，再乘上首尾两项，落到 10⁻¹¹ 量级——与 rnn_grad0_log10=-10.297742 一致。

第 1 帧从终点损失出发。第 2 帧往回走一步：L -> dh22 是反向，h22 -> h23 是同一段链的前向方向，两者并列画出来，方便对照。第 3 帧跨过整条链，dx0 是终点——它的数值已经小到六位小数打不出来。三帧各自把参与的节点写全，不需要靠上一帧补上下文。

关键不在「0.6 这个数特殊」，而在「连乘的因子模长小于 1」。只要循环权重的谱半径小于 1，或激活函数导数普遍小于 1（tanh 与 sigmoid 在饱和区都如此），梯度就会指数衰减；反过来谱半径大于 1 则指数爆炸。这正是 ml06 讲初始化时遇到过的同一现象，只是那里沿层数累积，这里沿时间步累积。梯度消失的直接后果是：早期输入几乎无法影响后期输出，模型学不到「句首那个词决定了句尾该填什么」这类长依赖。

陷阱把梯度消失当成「训练步数不够」

你会看到：loss 降到一个平台就不动了，延长训练几百步也没改善。你会怀疑学习率太小、数据太少，甚至想换优化器。真相常常是：早期输入的梯度已经小到被优化器的数值精度吃掉，再多步数也不会让它变大——问题出在路径，不在迭代次数。判断方法：像本例一样直接打一条早期输入梯度的量级；若 log10 已经在 −10 以下，就该改结构（LSTM、GRU、残差连接、注意力），而不是继续调学习率。相邻陷阱是把权重初始化得很大想「放大梯度」，那多半先撞上梯度爆炸，loss 直接变 NaN。

8.7 手算核对：两条路径的隐状态

把 stdout 的关键数字再手算一遍，能确认框架没有在背后偷偷改公式。RNN 第 0 步：h0 = tanh(x0·wxᵀ + 0·whᵀ) = tanh([0.8, 0.6]) = [0.664037, 0.537050]。第 1 步输入为零：h0·whᵀ = [0.398422, 0.322230]，tanh 后是 [0.378598, 0.311522]。每步都把上一状态乘 0.6 再压一次，23 步后到 [0.000005, 0.000004]，与 rnn_h 那一行逐格吻合。

LSTM 第 0 步的四个门都由同一个 z = [0.8, 0.6] 生成：输入门 i0 = sigmoid(z) = [0.689971, 0.645656]，遗忘门 f0 = sigmoid(z + 3) = [0.978119, 0.973403]——第一个分量正是 stdout 的 forget=0.978119。候选 g0 = tanh(z) = [0.664037, 0.537050]。旧细胞状态是零，于是 c0 = f0·0 + i0·g0 = [0.458168, 0.346749]，与中间探针读数一致。对外输出 h0 = o0·tanh(c0) = [0.295716, 0.215320]，其中 o0 = i0。

第 1 步输入为零，z1 = h0·whᵀ = [0.177430, 0.129192]，门值随状态变小而接近 0.5，但遗忘门仍因 +3 偏置而接近 0.96。细胞状态更新为 c1 = f1·c0 + i1·g1 ≈ [0.535395, 0.400597]，比 c0 还大——这印证了上一节的说明：三门共享投影时，写入量略大于遗忘量，细胞状态会缓慢累积。到第 23 步 c23 = 2.862650，h23 = 0.582533，正是 lstm_c_last 与 lstm_h_last。整条手算链闭合，没有一步靠「看起来差不多」糊过去。

陷阱手算 LSTM 时最容易在门的方向上翻车

第一种错：把 f 当成「要忘掉的比例」而不是「要保留的比例」。本例 f ≈ 0.978 表示保留 97.8%，忘掉 2.2%；若当成忘掉 97.8%，你会得出细胞状态迅速归零的错误结论。第二种错：把 h 当成细胞状态。真正穿过时间是 c，h 是对外的、经过 tanh 与输出门的视图；两者形状相同但数值不同，本例 c23=2.862650 而 h23=0.582533，差了近五倍。第三种错：以为 tanh 也作用在细胞状态的递推上。递推式 c_t = f·c_{t-1} + i·ĉ 里没有 tanh 包住 c_{t-1}，这正是近恒等通道成立的前提；若你手写时写成 c = tanh(f*c + i*g)，梯度又会开始消失。

8.8 GRU 与注意力的互补

GRU 是 LSTM 的简化版：把输入门和遗忘门合并成「更新门」，把细胞状态与隐状态合并成一份，再用一个「重置门」控制旧状态对新候选的影响。参数更少、计算更快，在很多任务上与 LSTM 表现相近；代价是少了独立的细胞状态，长期通路的显式性弱一点。选用哪个没有定论，通常靠实验定——本例不实现 GRU，是因为它的两条门与 LSTM 的两条门在机制上同构，再写一遍不会带来新理解。

注意力提供了另一条思路。RNN 要让第 0 步影响第 23 步，信息得沿链走 23 次，每次都可能被乘小因子；注意力让任意两个位置直接算一次匹配分，路径长度是 1。这一差别在长序列上被放大：序列越长，循环路径越长、衰减越重，注意力的一次交互却不变。代价是注意力本身有 n² 的分数表，长序列的算力与显存开销大；而 RNN 每步成本与序列长度无关，只是串行难以并行。

工程惯例三种结构的归纳偏置怎么选

循环假设「时间上有因果顺序，信息逐步传递」，适合流式与在线场景；卷积假设「局部与平移等变」，适合网格数据；注意力几乎不假设结构，但付出二次复杂度。真实系统常把它们叠用：卷积或 RNN 抽局部特征，注意力负责远距离交互。判断标准不是哪个更流行，而是你的任务里信息主要靠相邻传递还是远距离直连。代价是混合结构更难调参与部署——这是工程取舍，不是数学上的优劣。

8.9 打印纪律：梯度也要落到标量上

这一单元的 stdout 有 11 行，其中八行是 key=0.123456 形状的标量，三行是张量文本。分界规则与上一单元相同：闸门把形如 key=value 且 value 是有限十进制数的行当数值行，拿清单里的 atol=1e-6 重算差值；其它行逐字对账。rnn_h:[...] 这类冒号文本带逗号，若写成 rnn_h=0.000005, 0.000004 会被判成 numeric_value_invalid。

第 33、34 行各打印两条路径终点状态的第一个分量，第 35 行打印两者之差——long_dep_diff 是对账量，横跨两种实现。第 40 行值得单独说：rnn_grad0 真实值约 5×10⁻¹¹，用 %.6f 打成 0.000000 会把量级信息全部丢掉；再打一行 log10 得到 −10.297742，既保持了六位小数语法，又把「小到什么程度」写成了可对账的数。第 41 至 43 行把两条轨迹与细胞状态按冒号文本打印，逐字参与对账。

标量里也分三类。rnn_h_last、lstm_h_last、lstm_c_last、forget 是前向路径的中间量与终值；rnn_grad0、lstm_grad0、rnn_grad0_log10 是反向路径的证据；long_dep_diff 横跨两条路径。清单为每一行都写了黄金值，所以改任何一步实现，闸门都能指出是哪一类量先变了。正文里写「梯度几乎为零」不算证据，只有 log10 那一行的数才是机器可执行的证据。

语法规则极小数值的打印方法

六位小数语法 key=%.6f 会把 5×10⁻¹¹ 打成 0.000000，丢失量级信息。补一行 key_log10=%.6f 打印 torch.log10 的结果，本例得 rnn_grad0_log10=-10.297742。两行都在清单里声明黄金值：前者负责「确实小」，后者负责「小到哪一档」。注意 log10 的输入必须为正，梯度取绝对值后再取对数。

8.10 变体实验：让闸门变红的四种改法

真正让实验可信的是「一改就失败」。这里列出四个马上能做的变体。

第一个变体：把第 26 行的 wh 对角元从 0.6 改成 1.0。循环项不再衰减，rnn_h_last 会从 0.000005 涨到接近 tanh 的不动点，黄金值失配，闸门报 numeric_value_mismatch。这个变体专门抓「你以为衰减来自数据，其实来自权重」的误判。

第二个变体：把第 48 行的 forget_bias 改成 0。遗忘门降到约 0.69，c 每步丢掉三成，lstm_h_last 明显下降，long_dep_diff 随之改变。若你顺手只改正文 output 去迁就，闸门还会报 stale_output，因为正文必须与真实 stdout 逐字一致。

第三个变体：把第 35 行改成 h = torch.tanh((x[t] @ wx.T + h @ wh.T) * 0)，等于把输入投影乘零。两条路径的终点都归零，rnn_grad0 仍为零，但 lstm_grad0 不再是 0.029265——黄金值会指向「输入根本没进计算图」这个责任侧。

第四个变体：把第 52 行改成 h = torch.tanh(f * c + i * g)，让输出绕过输出门。程序照跑，但 lstm_h_last 改变而 lstm_c_last 不变——这类「一个动一个不动」的组合最能帮你定位错在哪一行。若同时改两处让数值碰巧回到原位，那属于自欺，不算通过。

实验记录变体实验怎么做才有证据
  • 一次只改一处；每次把改动前的 stdout 留一份，别靠记忆对比；
  • 用 node build/run.js --unit ml08-rnn 看失败码：黄金值超差是 numeric_value_mismatch，行数变了是 numeric_line_mismatch，手改正文是 stale_output；
  • 若某个变体竟然全部通过，先怀疑黄金值选得不够敏感，再怀疑自己改错了地方；
  • 决定保留新行为时，先重跑程序拿真实 stdout，再更新清单黄金值，最后重跑 render 与 run 两条闸门。

8.11 把这一单元与前后接起来

往回看，上一单元的卷积沿空间位置共享权重，这一单元的循环沿时间步共享权重——同一思想的两次出现，只是共享的维度换了。两者的参数量都与输入尺寸或序列长度无关，这正是它们能处理变长输入的根本原因。往前看，注意力几乎不做结构假设，用一次交互换取任意两位置的直连；代价是二次复杂度。理解这条取舍线，比记住哪个模型在某张榜单上赢更重要。

再补一层对账纪律上的呼应。卷积例子把 diff 当作手写与框架是否同义的证据，本例把 long_dep_diff 当作两种结构是否分道扬镳的证据：前者希望差接近零，后者希望差明显大于零。同一个「差」，在不同问题里方向相反，判断标准必须来自你要验证的命题，而不是「差越小越好」这句口头禅。黄金值把命题写成了机器能判定的数，这是两个单元共同的方法论。

回到这一单元开头的问题：序列模型怎么记住前文？答案分三层。机制上，靠隐状态这条被反复改写的纸条；训练上，靠 BPTT 让梯度沿纸条回来；结构上，靠 LSTM 的细胞状态给梯度开一条近乎恒等的通道。三层里任何一层断了，长期依赖就学不到。本例用 24 步的固定序列把三层都量成了数：long_dep_diff=0.582528 说机制还在，rnn_grad0_log10=-10.297742 说普通 RNN 的训练路径断了，lstm_grad0=0.029265 说门控把路径接了回来。

8.12 从一步到一批：形状账本与并行性

本例的张量都很小：输入 x 是 (24, 1)，隐状态是 (2,)，投影 wx 是 (2, 1)、循环权重 wh 是 (2, 2)。真实训练要加 batch 维，输入变成 (N, T, D)，隐状态是 (N, H)。每一步的矩阵乘从「向量乘矩阵」变成「矩阵乘矩阵」，但公式一个字都不用改——这正是矩阵写法比逐个循环值钱的地方。参数量仍然固定：wx 是 (H, D)、wh 是 (H, H)，与序列长度 T 和批量 N 都无关。把 T 从 24 加到 2400，参数一个不增；代价是前向必须串行走 2400 步，无法像卷积那样把位置并行算完。

串行是循环网络最大的工程短板。卷积的九个窗口位置可以同时算，注意力的 n² 个分数可以一次矩阵乘出来，而 RNN 的第 t 步必须等第 t−1 步的 h 出来才能开始。GPU 擅长大规模并行，却被这条依赖链卡住，利用率往往很低。工程上用两种办法缓解：一是截断 BPTT，只回传最近 K 步的梯度，把长链切成短段；二是用融合算子，至少让单步内部的矩阵乘更高效。前者改变了训练信号，让模型更偏向短依赖；后者不改变数学，只减少每步的调度开销。两者都不能让第 0 步的梯度重新变大——那需要结构改造。

批量的另一个影响在梯度上。BPTT 的梯度是沿时间连乘出来的，批量只提供多个样本的平均，不会改变每个样本内部的连乘因子。所以「加大 batch」救不了梯度消失，这是本例最该带走的一条判断。若你把 batch 从 1 加到 256 仍学不到长依赖，原因几乎肯定在回传路径上，而不在统计噪声上。反过来，若小批量就能学到，那说明路径通畅，此时再考虑用大批量稳住训练。

陷阱把截断长度当成模型的记忆长度

你会看到：把截断长度 K 从 20 调到 50，验证指标略有改善，于是宣布模型记住了 50 步。你会误以为 K 就是记忆容量。真相是：K 只决定梯度能回传多远，超过 K 的依赖关系在训练时根本没有监督信号，模型不可能凭空学会。判断方法：像本例一样直接测第 0 步输入的梯度；若把 K 设成 5，rnn_grad0_log10 会比 K=24 时更小，说明更远的路径被人为切断了。截断是算力与显存的妥协，不是记忆的度量；把这两件事混为一谈，调参就会变成盲猜。

8.13 门控偏置：一个数字决定爱记还是爱忘

第 48 行的 +3.0 是本例最不起眼、也最要紧的一处设计。sigmoid(3) ≈ 0.953，加上 z 里的 0.8 后是 0.978。若把偏置设成 −3，遗忘门会降到约 0.12，细胞状态每步只剩一成，LSTM 退化得比普通 RNN 还快。偏置不随输入变化，却直接决定网络在初始阶段的行为：正偏置让网络默认「先记着，需要时再学忘」，负偏置让它默认「先忘掉，需要时再学记」。经验上遗忘门偏置常设成正数，道理就在这里。

这个偏置在真实模型里是可学习参数，训练中会被梯度调整。本例把它写死，是为了让对照只反映结构差异，不被训练动态搅乱。要注意它与输入门的分工：输入门决定写多少新内容，遗忘门决定留多少旧内容。两者都接近 1 时，细胞状态会像本例一样缓慢累积；若输入门很小而遗忘门接近 1，细胞状态会长期保持一个常数——那才是教科书里「恒定误差轮转」的典型图景。本例选了前一种，因为两个门共用同一次投影，无法把输入门单独压小；这个简化让数字可手算，也让累积行为更显眼。

工程惯例门控初始化是工程惯例，不是理论结论

把遗忘门偏置初始化成正数，是长期实践中总结出的默认选择，并没有哪条定理规定必须是 3.0。不同任务会调到 1、2 或 5，也有人让模型自己学。代价是正偏置会削弱初期对新信息的吸收，因为遗忘门太守旧；收益是长期通路一开始就通着，训练不至于从「全忘」状态艰难爬出来。写实验记录时应当把偏置值与初始化方式一起记下，否则别人复现不出你的曲线——这类看似不起眼的超参数，往往是两次实验结果不同的真正原因。

8.14 BPTT 的两笔账：显存与梯度

展开 24 步意味着前向要保存每一步的 h、c 与门值，反向时逐个取用。显存随 T 线性增长，这是循环网络处理长序列时的第二道坎：即使梯度没有消失，先撑不住的也可能是显存。工程上用梯度检查点：只保存每隔 K 步的状态，反向时重新计算中间那一小段，用算力换显存。这与卷积里 im2col 用显存换速度的方向相反，但思路一致——都是把有限资源在不同维度之间重新分配。

梯度检查点不改变数学结果，只改变哪些中间量被暂存在显存里。本例没有用它，因为 24 步的图小到可以直接全存；但你要知道，当序列长到几千步时，这条工程手段与 LSTM 的结构改造是互补的：一个让梯度能传回来，一个让图能装进显存。只做后者不解前者，只做前者也可能先遇到显存不足。把两者分开记账，才不会在调参时把不同原因混在一起。

把三件事放在一起看：参数共享让参数量与序列长度无关，BPTT 让梯度沿时间回传，门控让回传路径不衰减。再加上检查点解决显存，你就有了一张完整的循环网络工程图。本例的小实验把前两条之外的关键量都量化成了真数——rnn_grad0_log10=-10.297742 说普通 RNN 的回传几乎断掉，lstm_grad0=0.029265 说门控把路接了回来，long_dep_diff=0.582528 说这条接回来的路确实把早期信息带到了终点。三个数分工不同，合起来才构成完整证据。

8.15 长依赖要靠探针测，不能只看总损失

如果只盯训练损失，本例的普通 RNN 看起来也「学到了」什么：序列里绝大多数位置是零，模型只要学会输出接近零，损失就能降得很漂亮。真正重要的第 0 步标记只占 24 步里的一步，它对总损失的贡献被二十三个零步稀释，优化器完全可以忽略它而照样把指标做好看。这是序列模型评估里最常见的假象：聚合指标把稀有但关键的事件平均掉了。

为此研究者设计了专门的长依赖任务。加法问题给一串数字和两个标记位置，要求模型只把标记处两个数相加；复制任务先念一串符号，隔很长一段空白后再原样吐出来。两类任务的共同点是：关键信息只出现在少数位置，其余位置都是干扰或空白，模型想得分就必须把远处的信息一路带过来。本例那个「第 0 步放标记、后面全零」的序列，就是这两类任务的最小版本——小到能在纸上算完，又保留了「关键信号稀疏且远离终点」这个本质。

把探针思路用在自己的实验上，有一条简单纪律：不要只钉最终 loss，还要钉一个直接衡量目标能力的量。本例钉的是 rnn_grad0_log10 与 lstm_grad0——它们不是任务指标，而是「早期输入还能不能影响终点」的直接测量。换成真实任务，这个位置可以是标记位置的准确率、远距离配对的正确率，或者按位置分层的误差表。聚合指标告诉你模型整体好不好，探针告诉你它究竟会不会你要它会的那件事。两者缺一不可。

工程惯例探针设计的代价

专门探针能暴露聚合指标藏住的问题，但它只覆盖你设计的那一种依赖。模型可能在你的加法任务上表现完美，却在真实文本里仍抓不住指代关系。代价是探针要花时间设计，还得防止模型用捷径记住固定模式——本例序列固定不变，所以只适合讲机制，不能当泛化能力的证据。做严谨实验时，应当把探针与真实任务一起报，并固定随机种子让结果可复现。

小结这一节的要点
  • 展开后的循环链上，W/U/b 在所有时刻共享；BPTT 就是沿这条链把梯度从末端传回起点；
  • 手写 RNN 一步是 tanh(xWᵀ + hUᵀ)；本例 24 步后 rnn_h_last=0.000005，早期标记几乎衰减干净；
  • LSTM 用遗忘门、输入门、输出门与细胞状态，c_t = f_t⊙c_{t-1} + i_t⊙ĉ_t 在 f≈1 时提供近恒等通道；本例 forget=0.978119、lstm_h_last=0.582533；
  • 梯度消失来自连乘因子：每步乘小于 1 的循环权重与 tanh 导数，24 步后 RNN 早期输入梯度约 5×10⁻¹¹，log10 读数是 −10.297742；

  • 极小量级补打 log10 行，标量走等号、张量走冒号，黄金值与容差只写在清单。

  5. 不是。六位小数把约 5×10⁻¹¹ 打成 0.000000；log10 行给出 −10.297742，说明量级是 10⁻¹¹，小到优化器实际上无法利用，但并非数学上的零。补打对数行正是为了不丢这个信息。

  7. GRU 把输入门与遗忘门合成更新门、把细胞状态与隐状态合成一份，参数更少、计算更快；代价是少了独立细胞状态，长期通路更隐式。注意力的任意两位置交互路径长度是 1，不受序列长度拉长影响，但分数表是 n×n、成本二次；循环每步成本固定却串行。两者适合不同约束，常叠用而非互相取代。
