6.1 先看工程长什么样

上一单元的链式法则把梯度算出来了，这一单元回答下一个问题：梯度拿到手之后怎么用？答案朴素得近乎无聊——往反方向走一小步，重复做。但「一小步」里的「小」字藏着整个优化理论的半壁江山：步子多大才合适，取决于损失曲面在那个点附近有多弯。这一节把这件事放进一个能完全手算的二次碗里，让每一步的数值都摊在 stdout 上。

清单这一节走 mode=train，和前几节的 numerical / gradient 又不一样。它不查单个黄金数值，也不查梯度表，而是查一条 loss 轨迹是否满足「起点够高、终点够低、总降幅够大、前若干步非增」；此外还要把同一个程序跑三遍：固定种子两遍必须逐值一致，对照种子必须让输出变化。这三遍合起来，才能证明轨迹是真算出来的，而不是一张写死的表。

第 1 帧是空目录，第 2 帧长出四个文件。gd.h 声明问题（二次碗的参数、固定步数、学习率）与四个函数；gd.c 实现种子读取、LCG 起点生成、损失与一步更新；main.c 把起点与 12 行 loss 打到屏幕上；mc06-gd.json 声明训练模式与种子条件。共用库仍然来自 examples/common/：mc_print_vec 负责把起点打成 start:[...]，mc_vec 负责把两个 double 装进定长向量。

大白话把训练想成「蒙眼下山」

你站在山坡上，看不见整座山，只能感觉到脚下地面的倾斜方向。最稳妥的策略是：每走一步之前，先朝最陡的下坡方向迈一小步，然后再感受一次。梯度就是脚下地面的倾斜方向（严格说是上坡方向），负梯度就是下坡。学习率决定你一步迈多大：迈太小，天黑了还没到谷底；迈太大，一步跨过谷底冲到对面坡上，来回震荡甚至越跳越高。这一节的全部内容，都是这句直觉的精确版本。

6.2 更新式：从「下降方向」到「下降一步」

多元函数在点 x 附近的一阶近似是 L(x + Δ) ≈ L(x) + ∇L(x)ᵀΔ。如果要让 L 变小，就要让内积 ∇LᵀΔ 为负。在所有长度相同的 Δ 里，让这个内积最负的方向是 −∇L/‖∇L‖——这就是「负梯度是最陡下降方向」的来历，也是第 2 单元讲过的内容。

但方向只决定往哪走，不决定走多远。把 Δ 取成 −lr·∇L，就得到梯度下降的更新式：

x_{t+1} = x_t − lr · ∇L(x_t)

其中 lr > 0 是学习率。一阶近似只在足够小的邻域里成立，所以 lr 不能太大；可也不能太小，否则每步的收益被浮点精度吃掉，训练时间无法接受。这两条约束之间的窗口，就是学习率调参的全部空间。

本节用的损失是 L(x₀, x₁) = x₀² + 0.5 x₁²，最小值在 (0,0)，最小损失为 0。梯度是 ∇L = (2x₀, x₁)，Hessian 是常数矩阵 diag(2, 1)。取 lr = 0.2，更新式展开就是：

  • x₀ ← x₀ − 0.2×2x₀ = 0.6x₀
  • x₁ ← x₁ − 0.2×x₁ = 0.8x₁

两个坐标各自按比例缩小，互不干扰。这是一个理想到失真的例子：每一步都严格下降，没有任何震荡，12 步之后基本收敛。它的价值正在于「理想」——你能把每一步的衰减倍数算出来，再拿它去理解真实问题里那些不理想的曲线。

工程惯例为什么平方前有 0.5

如果把损失写成 L = x₀² + x₁²，梯度是 (2x₀, 2x₁)；写成 0.5 x₁²，梯度才是 (2x₀, x₁)。平方前面的系数直接影响梯度的数值，进而影响同样的 lr 下走多远。真实网络里损失常常带 1/N（batch 平均）或 1/2（为了求导时消掉 2），这些系数不是装饰：调学习率时必须连它们一起看。很多「同样配置在别人机器上不收敛」的故事，最后查出来是 batch 大小或损失缩放不同，等效学习率变了。

6.3 收敛几何：曲率决定步长，条件数决定难度

把二次碗画成等高线，是一组同心椭圆：x₀² + 0.5x₁² = c。椭圆在 x₀ 方向更窄（曲率 2），在 x₁ 方向更宽（曲率 1）。梯度下降沿法线方向走，而椭圆的法线并不指向圆心，所以除了正对着轴走的特殊起点，路径会呈锯齿形向中心逼近。两个方向的衰减倍数分别是 0.6 与 0.8——x₁ 方向下降得慢，因为它更平坦。

第 1 帧的起点是种子决定的，不是写死的；第 2 帧的三步之后，x₀ 乘了 0.6³ = 0.216，x₁ 乘了 0.8³ = 0.512，路径明显向 x₀ 轴方向压缩；第 3 帧的 12 步之后，0.6¹² ≈ 0.0022、0.8¹² ≈ 0.0687，两个方向都贴近 0。注意每帧都把前面仍在讨论的节点重写一遍——渲染器不会自动把上一帧的节点带过来，这就是「帧自包含」的意思。

现在看一个不理想的对照。若把损失改成 L = x₀² + 25 x₁²，等高线变成细长的峡谷：x₁ 方向曲率 25，稳定步长上限约为 2/25 = 0.08；x₀ 方向曲率只有 1，用这么小的步长就会慢得像爬行。为了在峡谷里稳定，你被迫选小学习率；选了小学习率，平坦方向又进展缓慢。这种「最弯方向与最平方向曲率相差很大」的情形，用条件数 κ = λ_max/λ_min 度量。本例 κ = 2，很温和；峡谷例子 κ = 25，已经明显难训；真实网络里 κ 可以是几千，这正是动量、AdaGrad、Adam 等优化器要解决的核心困难。

陷阱「梯度下降」不等于「沿损失下降最快的离散路径」

负梯度是连续意义下的最陡方向，但一旦乘以有限步长，走完之后损失未必下降。步长超过某个阈值，你会越过极小点，损失反而上升；在峡谷里，即使每一步都朝负梯度，路径也会来回横跳。可以证明，对二次函数 L = 0.5 xᵀHx，梯度下降稳定（每步损失不增）的步长上限是 2/λ_max，最优步长是 2/(λ_max+λ_min)。本节 H = diag(2,1)，上限 1、最优约 0.667，取 0.2 既安全又不过分慢。换一个 H，这些数就要重算——这就是为什么「学习率 0.1 万能」是幻觉。

6.4 固定种子：为什么不用 rand()

本节的起点不是写死的，而是从种子算出来的。程序读环境变量 MC_SEED，用它初始化一个 32 位 LCG（线性同余发生器），取前两个随机数把起点落在 (1,3)×(0.5,2.5) 的矩形里。MC_SEED=12345 时起点是 (2.310308, 1.109629)；换成 67890，起点变成 (1.498678, 1.147762)。固定种子，起点就固定；换种子，整条轨迹跟着变。

为什么不用 rand()？因为 rand() 的具体序列由 C 运行库实现决定，换台机器、换个编译器就可能不同。「同一颗种子复现同样输出」这条闸门判定会立刻失败，而且失败原因跟你的算法没有半点关系。LCG 的公式只有一行乘法加取模，任何平台上整数溢出按 unsigned long 的规则定义，结果完全一致——这就是可复现性的来源。

第 5–8 行读环境变量：没设置时退回 12345，所以手工运行程序也能得到默认结果。第 11–14 行是 LCG 本体，乘数 1103515245、增量 12345、模 2³¹，是很多 C 库的历史选择；这里不追求统计质量，只追求跨平台一致。第 16–22 行把两个 [0,1) 区间的随机数映射到起点矩形。注意种子是 unsigned long，& 0x7fffffff 先把高位截掉，保证乘法不会在 64 位平台上走出另一条路径。

第 2 帧里两个 u 值是把 31 位整数除以 2³¹ 得到的，永远落在 [0,1)。第 3 帧把它们线性映射到指定矩形，这样不同种子给出的起点分布在碗壁四周，而不是偶尔刚好落在极小点附近——否则「起点够高」这条判定就没意义了。

工程惯例种子写在清单里叫「实验条件」

种子写在源码里叫硬编码：读者看不出起点从哪来，也没法改变它。种子写在清单里叫实验条件：一眼可见，而且能被对照实验改变。mc06-gd.json 里同时写了 seed_env: "MC_SEED"、seed: 12345 和 seed_contrast: 67890。闸门把种子当环境变量注入，程序只管读——这种分工让「这次实验用了什么随机来源」成为清单的一部分，而不是埋在代码深处的常量。

6.5 12 行 loss 轨迹：把数字读成故事

main.c 先打印起点，再打印 12 行 loss，每打一行就更新一步。真实 stdout 如下。

第一行 start:[...] 用冒号，是共用库打印向量的格式；它不是数值行，闸门按普通文字逐字比较。下面 12 行 loss=... 才是数值行。读这张表要抓四个特征：起点 5.953161 明显不是最优；终点 0.004613 已经很小；首尾降幅约 5.948548；12 行严格递减，前 8 步尤其陡。这四条正好对应清单里的四项阈值。

把衰减倍数代进去验算第一步：起点 x₀=2.310308、x₁=1.109629，更新后 x₀=1.386185、x₁=0.887703，新损失 1.386185² + 0.5×0.887703² ≈ 1.9215 + 0.3940 = 2.3155，和 stdout 第二行 2.315517 一致。第 7 行 0.053925 对应第 7 步（从第 0 行开始数），此时 x₀ 已经乘了七次 0.6、x₁ 乘了七次 0.8，损失主要来自 x₁ 方向——这印证了「平坦方向拖后腿」的几何直觉。

这四行代码就是全部「训练逻辑」。它没有循环、没有反向传播、没有自动微分，因为梯度的解析形式太简单了。它的价值在于把上一节的梯度变成了一个可观察的过程：梯度不再是一张静态表，而是推动点沿曲面移动的动力。真实网络里的优化器代码比这复杂得多，但骨架一样——取梯度、乘步长、更新参数、记录损失。

实验记录把学习率改成 0.55 会发生什么

gd.h 里 GD_LR 现在是 0.2。改成 0.55，x₀ 的衰减因子变成 1-0.55×2 = -0.1，x₁ 变成 0.45。负的衰减因子意味着 x₀ 每步越过原点并换边，虽然绝对值在缩小，损失仍可能逐行下降，但轨迹会在两个象限之间来回跳。改成 1.1，x₀ 的因子变成 -1.2，绝对值逐 step 放大，loss 会反弹并很快爆掉，train_loss_not_decreasing 当场报出来。改完记得同步更新 output 块和阈值，否则先报的是 stale_output。

6.6 train 闸门：三遍运行，四项目标

清单里 expect.train 有七个字段，我们把它们和作用一一对上。loss_key: "loss" 告诉闸门哪一行是损失；min_points: 12 要求至少 12 个点，防止程序只打两步就宣称收敛；first_min: 5.0 要求起点损失不低于 5，防止「起点已经在谷底」的假演示；last_max: 0.01 要求终点不高于 0.01；decline_min: 5.0 要求首尾降幅至少 5；monotone_window: 8 与 slack: 1e-4 要求前 8 步非增（允许 1e-4 的数值噪声）。

这些阈值都有余量：真实起点 5.953161 高于 5.0，终点 0.004613 低于 0.01，降幅 5.948548 高于 5.0。留余量是必要的——换一台机器，最后一两位小数可能不同；阈值贴着真值写，闸门会变成一台「随机失败机」。但余量也不能大到失去判别力：把 last_max 改成 100，任何终点都能过，这项检查就废了。

判定流程跑三遍。第一遍带 MC_SEED=12345，检查轨迹四项指标。第二遍还是 12345，要求每一行与第一次逐值一致，否则报 train_nondeterministic——这抓的是隐藏的随机来源，比如忘了初始化就用的局部变量或偷用 rand()。第三遍换成 MC_SEED=67890，要求至少一个数值变化，否则报 seed_has_no_effect——这抓的是把 12 行 loss 硬编码进数组的程序。

陷阱复现性不等于正确性

三遍检查合起来很强，但仍有一件事它证明不了：你算的梯度是不是正确的梯度。一个程序完全可以把梯度乘错两倍，照样得到一个平滑下降的 loss 轨迹，三遍检查全绿。所以本册把「梯度对拍」和「训练收敛」分成两道独立的闸门：第 5 单元查导数对不对，这一单元查训练过程是不是真的在跑。少任何一道，都会留下能骗过闸门的写法。

工程惯例程序自报的收敛不算证据

和 gradient 模式一样，闸门从 stdout 自己解析 loss= 行并重算判定；程序就算在末尾打印 CONVERGED，闸门也不会看。而且容差与阈值只写在清单里，正文写「大概收敛了」不算证据。这套纪律在真实训练平台里同样成立：监控系统要从日志里独立读指标，不能信任训练脚本自己上报的「成功」标记。

6.7 动量与自适应学习率：引子

本节用的是最朴素的固定学习率梯度下降。它在二次碗上表现完美，因为两个方向的曲率只差两倍。真实损失曲面往往像一条狭长谷：某些方向很弯，步长被它们卡住；另一些方向很平，同样的步长下进展慢得让人绝望。优化器的发展史，几乎就是一部「如何让不同方向各走各的合适步长」的历史。

动量（momentum） 的想法来自物理：把更新量看成一个带惯性的速度，每步先衰减旧速度，再把当前梯度加进去，v ← βv + ∇L，x ← x − lr·v。在狭长谷里，横向的梯度每步变号，旧速度与新梯度互相抵消；纵向的梯度方向一致，速度逐 step 累积变大。结果是横向震荡被压住、纵向前进被加速。β 通常取 0.9，意味着速度能记住大约十步的方向。

AdaGrad / RMSProp / Adam 走另一条路：它们给每个坐标维护一份梯度平方的滑动平均，再用它去除梯度。梯度大的坐标（弯方向）得到有效步长变小，梯度小的坐标（平方向）有效步长变大。Adam 还叠加了动量，并做偏差修正，使训练初期的估计不被零初值带偏。今天训练大模型时 AdamW 几乎是默认选择——这里的 W 指权重衰减与自适应步长解耦，细节属于深度学习分册，但它的根基就是本节这条更新式。

大白话优化器不改「往哪走」，只改「走多远」

无论是动量还是自适应学习率，梯度本身还是那个梯度，负方向还是那个负方向。优化器改的是步长的形状：动量让步长带上历史方向，自适应方法让不同坐标有不同步长。记住这一点，你就不会把「换 Adam 就一定能收敛」当成咒语——如果梯度本身算错了（比如上一节漏乘内层导数），再好的优化器也只是更高效地走向错误的地方。

6.8 鞍点、局部极小与非单峰：loss 下降不等于找到最优

二次碗是凸函数，只有一个极小点，梯度为零的地方就是全局最优。真实网络的损失几乎从不这么乖。它可能有大量局部极小：梯度为零但不是全局最低；可能有鞍点：某个方向是极小、另一个方向是极大，梯度同样为零；还可能有大片平坦区域：梯度很小但不是零，训练看起来「卡住」了。

鞍点尤其值得说，因为在高维空间里它比局部极小更常见。考虑 L = x₀² - x₁²，原点梯度为零，沿 x₀ 方向是碗底，沿 x₁ 方向是山顶。朴素梯度下降如果恰好从 x₁=0 的直线上出发，会直奔原点停下；只要有一点数值扰动，就会沿 x₁ 方向滑走。动量在这里反而有帮助：惯性可能把点推过鞍点附近的平坦区。实践中完全精确的鞍点很少遇到，真正拖慢训练的是鞍点周围那一大片梯度很小的区域。

陷阱「loss 一直在降」不等于「模型在变好」

训练日志只告诉你目标函数在下降，不告诉你在参数空间里走到了哪里。过拟合时训练 loss 持续下降，验证 loss 却在上升；非凸问题里，你可能掉进一个浅的局部极小，再也出不来。所以训练时要同时看训练损失、验证指标和参数范数，不能只盯一条曲线。本节的二次碗没有这些麻烦，正是因为它太干净——把它当作「理想基准」，而不是真实训练的全貌。

本节的 12 步轨迹之所以能逐行下降，还有一个前提：起点在碗壁上，而且学习率落在稳定区间内。把这两条拿掉，同样的更新式也会给出震荡甚至发散的曲线。闸门只检查前 8 步单调，留 slack 1e-4，就是为了容忍真实的数值噪声；它并不要求整条轨迹完美。理解每条检查「为什么这么写」，比背下阈值更重要——阈值是这套几何的数字化身。

6.9 常见坑与调参直觉

第一，学习率与损失缩放脱节。把 batch 大小翻倍却忘了调学习率，等效步长变了；把损失从求和改成平均，梯度的尺度变了。第二，忘了检查起点。随机起点如果恰好接近最优，起点阈值会拦下这种「假收敛」。第三，用 rand() 导致复现失败。第四，在更新之前就记录 loss，结果轨迹整体错一步——本例先打印再更新，打印的是更新前的位置，这是明确的约定。第五，把 loss 打印成 loss: 5.9 这类格式；闸门只认 key=value 数值行，冒号格式会被当普通文字，数值检查全部落空。

实验记录对照种子到底在防什么

把清单里的 seed_contrast: 67890 暂时删掉，再把 main.c 改成直接打印一个写死的 12 行 loss 表（数值抄自本单元 output 块）。同种子两遍仍然一致，轨迹四项判定也照样通过——闸门全绿。现在把 seed_contrast 加回来，闸门立刻报 seed_has_no_effect，因为换种子后输出纹丝不动。这个实验说明：复现性检查只证明确定，对照种子才证明数值真被随机来源驱动。改回原程序后再跑一次，确认三遍全绿。

6.10 学习率的量纲直觉与搜索方法

初学者常把学习率当成一个「越小越安全」的魔法数字，其实它有清楚的量纲直觉。更新量是 lr × ∇L，所以真正决定一步走多远的，是梯度尺度与学习率的乘积，而不是学习率单独的值。把损失整体放大 10 倍，梯度也放大 10 倍，等效步长就放大 10 倍；此时若学习率不动，原本温和的训练会突然震荡。反过来，把参数从「米」改成「毫米」，梯度数值也跟着变，合适的学习率同样要变。脱离损失缩放和参数尺度谈学习率，是没有意义的。

选学习率的实用办法是指数扫描。从一个小值开始，比如 1e-5，每个数量级试一次，看前几百步的 loss 曲线：太小，曲线几乎是平的；合适，曲线稳定下降；太大，曲线震荡、反弹，甚至出现 nan。找到能稳定下降的最大量级后，再在附近做细调。这个办法之所以有效，是因为损失尺度和曲率通常跨几个数量级，先用指数定位量级比线性网格高效得多。

工程惯例warmup 与学习率衰减为什么有用

训练刚开始时参数是随机初始化的，损失曲面在起点附近可能非常弯曲，一步迈太大容易直接把模型推到坏区域。warmup 让学习率从前几步的小值线性升到目标值，相当于「先试探再加速」。训练后期则相反：参数已经接近较好的区域，需要小步微调，于是用余弦衰减或阶梯衰减把学习率降下来。两者合起来，本质是承认「合适步长」在整个训练过程中不是常数。本节用固定 lr=0.2，是因为二次碗的曲率处处相同——真实网络没有这个 luxury。

梯度裁剪是另一道保险。当梯度范数超过阈值时，把它整体缩放到阈值以内，相当于在异常步上临时降低学习率。训练 Transformer 时几乎必配梯度裁剪，因为个别 batch 会产生异常大的梯度，不裁掉的话一步就能把训练带偏。注意裁剪改变的是更新量的长度，不改变方向；所以它和本节讲的「负梯度是最陡下降方向」并不冲突。

6.11 早停、日志与阈值之间的关系

本节让程序固定跑 12 步，因为这是一个能讲清楚的最小实验。真实训练不会事先知道该跑多少步：跑太少欠拟合，跑太多过拟合。常用做法是划一块验证集，每隔若干步评估一次，验证指标连续若干轮不再改善就停——这叫早停。早停保存的是验证表现最好的那一步的参数，而不是最后一步的参数。

把这件事和闸门阈值对照着看，会更有体会。清单要求 min_points: 12，本例如果只跑 8 步，第 8 个 loss 是 0.018834：终点高于 0.01，last_max 这条就会拦下。如果只跑 6 步，终点 0.053925，连降幅都可能不够。换句话说，阈值不只是「验收标准」，它同时 encodes 了「至少要走这么多步才够接近谷底」这个实验判断。写阈值时心里要有这条物理图像，否则很容易写出一个要么太松、要么太紧的条件。

实验记录自己做一个早停实验

把 gd.h 里的 GD_STEPS 改成 20，重新编译运行，观察第 12 步之后的 loss 是否还在明显下降。你会发现第 12 步的 0.004613 到第 19 步大约只剩 1e-5 量级，继续训练的收益微乎其微，这就是这个二次碗上的「收益递减点」。再把学习率改成 0.05 跑 20 步，收敛会慢得多，说明步长和步数可以互相补偿——但补偿不是免费的，小步长意味着更多次前向反向计算。改完记得把输出块和清单的 min_points 一起更新，否则 stale_output 和阈值检查会先后报错。

日志的粒度也值得设计。本节每一步都打一行，因为总共只有 12 步；真实训练动辄几十万步，通常每几十或几百步打一次，并记录时间戳、学习率、梯度范数、训练与验证指标。光看 loss 一行不够：loss 在降但梯度范数突然飙升，往往意味着即将进入不稳定区；验证 loss 与训练 loss 的差距在扩大，则是过拟合信号。本节的 stdout 是这些工业日志的最小原型——它只记录一个数字，但这个数字的轨迹已经足够判断收敛。

陷阱打印格式决定闸门能不能看见数字

本例用 printf("loss=%.6f\n", ...)，等号左边是纯字母 key，右边是有限十进制数，正好符合数值行语法。若改成 printf("loss: %.6f\n", ...)，这一行会被当成普通文字，闸门找不到 loss= 键，直接报 numeric_key_missing；若改成 printf("loss=%.6g\n", ...)，极小值可能打印成科学计数法 4.613e-03，同样不是合法的有限十进制数，报 numeric_value_invalid。看起来只是格式的小差别，却决定了整条证据链断在哪里。写数值实验程序时，先确认打印格式符合闸门的解析约定，再谈数值对不对。

还有一个细节：本例先打印 loss 再更新参数，所以第一行对应初始点、最后一行对应第 11 步更新后的位置。如果把两行调换顺序，轨迹整体平移一步，起点变成 2.315517，first_min: 5.0 这条立刻不满足。这种「差一步」的错误不会引起任何编译警告，也不会让曲线变得难看——曲线照样漂亮下降——只有把判定条件写清楚才能抓住。实验代码里凡是涉及「先记录还是先更新」的地方，都要在注释和正文里写明约定。

6.12 从二次碗到深度网络：同一骨架，不同规模

把本节的四个函数换成深度网络里的对应物，骨架一点没变：gd_start 是权重初始化，gd_loss 是前向加损失，gd_step 里那两行梯度换成了 autograd 算出的上亿个梯度，main.c 的循环换成了遍历训练数据的 epoch 循环。变的只是规模和噪声，不是逻辑。

真实训练用的是随机梯度下降：每一步只用一小批样本估计梯度，而不是对全量数据求精确梯度。这让每步的计算成本从「与数据集大小成正比」降到「与 batch 大小成正比」，代价是梯度带噪声。噪声并不意味着坏事——它帮助模型跳出浅的局部极小和鞍点附近的平坦区，这也是 SGD 泛化表现往往不差的原因之一。本节用精确梯度、固定起点，得到一条完美光滑的曲线；把 batch 噪声加进来，曲线会毛刺丛生，但整体趋势仍然向下。

大白话确定性实验的价值

看到这里你可能会问：既然真实训练充满随机性，为什么要花这么大力气做一个完全确定、没有任何噪声的二次碗？答案是分层验证。先在一个能完全手算、完全复现的环境里把「梯度→更新→收敛」这条链跑通，确定每一步的机制正确；再往里加随机性、加 batch、加复杂曲面。本节的 LCG 和对照种子不是为了模拟深度学习的噪声，而是为了让「随机来源」这件事本身变得可观察、可注入、可对照。机制清楚之后，再引入真实噪声才不会把 bug 误当成随机性。

最后提醒一个容易被忽略的点：train 闸门检查的是轨迹的形状，不是参数是否真的收敛到最优。一个程序完全可以让参数按错误公式更新、却把 loss 打印成一条漂亮的下降曲线——只要它真的去算了损失，轨迹就会下降。要证明「梯度算对了」，还得靠第 5 单元的梯度对拍和第 8 单元的矩阵微分对拍。把这几道闸门叠起来，才构成对训练实验的完整证据链。

6.13 与闭式解对照：梯度下降是在做什么近似

二次碗的好处是它有闭式解，可以把梯度下降的行为算到一步不差。对本节的 L = 0.5 xᵀHx、H = diag(2,1)，最小值在 x*=0。从第 t 步到第 t+1 步：x_{t+1} = (I - lr·H)x_t；迭代 t 次就是 x_t = (I - lr·H)^t x₀。代入 lr=0.2、H=diag(2,1)，得到 x₀(t) = 0.6^t × 2.310308、x₁(t) = 0.8^t × 1.109629。拿这个公式直接算第 12 步：0.6¹²×2.310308 ≈ 0.00511、0.8¹²×1.109629 ≈ 0.0762，代回损失得到约 0.0046，与 stdout 最后一行 0.004613 对得上。

这个闭式表达式还告诉你一个工程事实：收敛速度由 |1-lr·λᵢ| 中最大的那个决定，也就是由条件数决定。想一步到位，就得让 I-lr·H = 0——但一个标量 lr 不可能同时让 lr·2=1 和 lr·1=1。牛顿法用 H⁻¹ 给每个方向配一个步长，x_{t+1} = x_t - H⁻¹∇L = x_t - x_t = 0，在二次函数上一步到谷底。代价是要算并存储 Hessian 的逆，n 个参数就是 n×n 矩阵，深度网络里根本负担不起——这正是第 4 单元说「深度网络一般不用完整 Hessian」的原因。

工程惯例预条件子就是「给每个方向配一个学习率」

牛顿法的 H⁻¹ 可以理解成一个完美的预条件子：它把弯曲方向的小步长和平坦方向的大步长一次性安排好。实际优化器做的是它的廉价近似。AdaGrad / RMSProp 用梯度平方的对角矩阵近似 H 的尺度，Adam 再加上动量；它们都只存一个与参数同形的向量，而不是 n×n 的矩阵。从这个角度看，第 6.7 节的「自适应学习率」不是一堆经验 trick，而是「用对角近似代替完整曲率」这条思路的具体实现。本节的二次碗条件数只有 2，固定学习率已经够用；换成条件数几千的曲面，近似曲率就变成了必需品。

小结这一节的要点
  • 更新式 x ← x − lr·∇L：负梯度给方向，学习率给步长；二次碗 x₀²+0.5x₁² 在 lr=0.2 下的衰减因子是 0.6 与 0.8；
  • 收敛几何由曲率决定：稳定步长上限约 2/λ_max，条件数大（狭长谷）会让朴素梯度下降反复震荡；
  • 起点由 LCG 从 MC_SEED 生成，不用 rand()：种子写在清单里是实验条件，写在源码里是硬编码；
  • 12 行真实轨迹从 5.953161 降到 0.004613，起点、终点、降幅、单调窗口四项都由清单阈值判定；
  • train 闸门跑三遍：同种子复现、对照种子必须改变输出，防止把 loss 曲线写死；
  • 动量与自适应学习率只改变步长的形状，不改变梯度方向；鞍点与局部极小说明 loss 下降不等于找到全局最优。

  4. 为什么不用 rand()？若换成它，闸门的哪一项最先失败？
  5. train 模式为什么跑三遍？只跑固定种子两遍会漏掉哪种作弊？
  6. 清单里的 slack: 1e-4 是干什么用的？把它设成 0 会有什么风险？
  7. 动量与 AdaGrad 分别解决什么问题？它们会改变梯度方向吗？
  8. 鞍点和局部极小有什么区别？为什么说高维空间里鞍点附近的平坦区更常见？
注自测题答案
  1. 一阶近似里 L(x+Δ)-L(x) ≈ ∇LᵀΔ。在 ‖Δ‖ 固定时，由柯西不等式 |∇LᵀΔ| ≤ ‖∇L‖‖Δ‖，当 Δ 与 ∇L 反向时取到最小值 −‖∇L‖‖Δ‖，所以 −∇L 是下降最快的方向。
  2. x₀ 的衰减因子 1-0.2×2 = 0.6，x₁ 是 1-0.2×1 = 0.8。改成 0.55 后 x₀ 的因子是 −0.1，每步越过原点换边，轨迹在两个象限间来回跳；改成 1.1 则因子为 −1.2，绝对值放大，loss 反弹并触发闸门失败。
  3. 沿最大曲率特征方向，更新后该坐标的因子是 1-lr·λ_max；当它落在 (-1,1) 内才不会逐 step 放大，因此 lr < 2/λ_max。条件数大时，λ_max 逼你用小步长，而 λ_min 方向的收敛速度又正比于 lr·λ_min，于是小步长让平坦方向慢得无法忍受。
  4. rand() 的序列依运行库实现而定，换机器或编译器就可能变。最先失败的是同种子复现检查 train_nondeterministic。
  5. 两遍同种子只能证明确定性；把 12 行 loss 硬编码进数组也能过。第三遍对照种子要求输出变化，才能证明数值真由种子驱动的起点算出来。
  6. slack 是单调判定的容差，允许前若干步有微小回升（浮点噪声）。设成 0 会让不同平台上最后几位的差异被当成「不单调」，闸门变成随机失败机。
  7. 动量用历史速度的惯性压住狭长谷里的横向震荡、加速纵向前进；AdaGrad 用梯度平方累积给每个坐标不同步长，弯方向步长变小、平方向变大。两者都只改步长，不改梯度的方向。
  8. 局部极小在所有方向上都是极小；鞍点在某些方向极小、另一些方向极大，梯度同样为零。高维空间里要让所有方向都向上非常困难，所以驻点更可能是鞍点；而鞍点周围梯度普遍很小，形成的平坦区比一个孤立的点更常见，也更拖慢训练。
