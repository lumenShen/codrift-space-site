7.1 先看工程长什么样

前面几节优化的都是「自由变量」：参数可以往任何方向动，只要损失下降就行。这一单元加一条规矩：变量必须待在某个曲面上。最经典的例子是在单位圆上找一个线性函数最大的点。这个问题简单到能徒手算完，却把约束优化最关键的那张图——两组等高线相切——讲得清清楚楚。

清单这一节回到 mode=numerical：程序打印 lambda、x0、x1、check 四个数值行，清单给四个黄金值和统一的 atol=1e-6。没有阴性对照，因为这里没有解析梯度与数值梯度的对拍；取而代之的是「残差必须接近零」这一独立验证：就算解是从闭式公式算出来的，check 也要用数值梯度重新验一遍驻点条件与约束条件。

第 1 帧里 ch03 已有 gd_train/，第 2 帧新增 lagrange/。头文件把问题写死为「二维、单位圆、线性目标」，源文件给出闭式求解与残差验证，main.c 打印四行数值，清单声明黄金值与容差。共用库继续提供 mc_vec、mc_zero、mc_grad、mc_norm 与冒号打印——这一节会真正用到数值梯度和范数，是前几节积累的工具的一次集中亮相。

大白话一句话讲完约束优化

自由优化时，最优点的梯度必须是零；有约束时，最优点可以在约束曲面上「顶着走不动」。此时梯度不必为零，但它必须垂直于约束曲面——否则你还能沿曲面切线方向挪一点，让目标继续变大。梯度垂直于曲面，等价于它和约束函数的梯度平行，那个比例系数就是拉格朗日乘子 λ。

7.2 问题：在圆上最大化一个线性函数

取目标 f(x₀, x₁) = 3x₀ + 4x₁，约束 g(x₀, x₁) = x₀² + x₁² − 1 = 0，也就是点必须落在单位圆上。没有约束时，f 是一个斜平面，沿着 (3,4) 方向一直增大，根本没有有限的最大值。加上圆这个约束后，问题变成：圆周上哪个点让 3x₀+4x₁ 最大？

凭直觉也能猜到答案：f 的等值线是斜率为 −3/4 的平行直线，把这样一条直线沿 (3,4) 方向往外推，最后离开圆的位置一定是与圆相切的那条直线。切点处圆的半径方向是 (x₀,x₁)，而 f 的梯度方向是 (3,4)，两者平行。单位圆上和 (3,4) 同向的点就是 (3,4)/5 = (0.6, 0.8)，此时 f 的值是 3×0.6+4×0.8 = 5。反方向 (-0.6,-0.8) 给出最小值 −5。

工程惯例为什么线性目标 + 圆形约束是理想教具

它同时满足三个条件：第一，几何图像能画出来，等高线是直线、约束是圆，相切一眼可见；第二，闭式解能徒手算，‖(3,4)‖=5 是勾股数，切点坐标干净；第三，λ 有明确数值 2.5，符号还能区分最大与最小。初学约束优化时，最怕一上来就遇到十个约束、非线性目标的例子——那样只能背公式，没法验证每一步。把这个玩具例子吃透，再去看一般形式就有了锚点。

7.3 为什么极值处有 ∇f = λ∇g

先看几何。设 x* 是约束曲面上的一个点，沿曲面的任意一条光滑曲线 γ(t) 都满足 g(γ(t))=0，且 γ(0)=x*。把约束对 t 求导：

d/dt g(γ(t)) |_{t=0} = ∇g(x*)·γ′(0) = 0

这说明 ∇g(x*) 垂直于曲面在 x* 处的所有切线方向，也就是曲面的法向。现在假设 x* 是 f 在约束上的极值点。沿同一条曲线考察 f：

d/dt f(γ(t)) |_{t=0} = ∇f(x*)·γ′(0) = 0

极值点处沿任何切线方向的一阶变化都必须为零，否则往某个方向走一点还能让 f 变大或变小。于是 ∇f(x*) 也垂直于所有切线方向。在二维里，垂直于同一条切线的向量必然共线，所以存在 λ 使 ∇f = λ∇g。在更高维里，只要约束的梯度张成法空间，结论同样成立。

第 1 帧的 normal 是圆在切点的半径方向。第 2 帧把目标等值线推进到与圆相切——再往外推就与圆没有交点，再往里推目标值更小。第 3 帧的关键数字是 ∇g = 2x = (1.2, 1.6)，而 ∇f = (3,4)，两者确实相差 2.5 倍。这就是 λ 的几何意义：把约束曲面的法向量拉伸到与目标梯度重合所需的倍数。

陷阱梯度为零不是有约束问题的驻点条件

自由优化时我们习惯找 ∇f = 0；有约束时这个条件完全不对。本例在最优点 (0.6,0.8) 处 ∇f=(3,4)，根本不是零。如果你用无约束的思路去解，会去找 (3,4)=0 的点，永远找不到。正确的驻点条件是 ∇f = λ∇g，再加上约束 g=0 本身——两个方程一起才把解钉住。λ 是新引入的未知数，数量与约束个数相同。

7.4 代数推导与 λ 的符号

把条件写成方程组：

  • 驻点：3 = 2λx₀，4 = 2λx₁
  • 可行：x₀² + x₁² = 1

由前两式得 x₀ = 3/(2λ)、x₁ = 4/(2λ)。代入约束：(9+16)/(4λ²) = 1，即 25 = 4λ²，所以 λ = ±2.5。正号给出 x = (0.6, 0.8)，这是最大值点；负号给出 x = (-0.6, -0.8)，最小值点。同一个驻点条件会给出多个候选，必须逐个比较目标值才能确定最大还是最小。

λ 的符号还回答一个实用问题：如果目标变大一点，最优值会怎么变？把约束改成 x₀²+x₁² = c，同样的推导给出 λ = 5/(2√c)，最优值 f* = 5√c 的倒数关系对应 ∂f*/∂c = λ（在这里因为约束写成 =c 而出现符号约定差异，规范写法下 λ 正是对约束右端的敏感度）。这种「λ 告诉你约束松动一点值多少」的解读，就是下一节要讲的影子价格。

大白话多一个约束就多一个 λ

如果同时有 g₁=0 和 g₂=0，驻点条件变成 ∇f = λ₁∇g₁ + λ₂∇g₂。几何上，两个约束曲面的法向量张成一个法空间，目标梯度必须落在这个空间里。每个约束自带一个乘子，乘子的个数永远与约束个数相同。这个结构在带约束的深度学习问题里也一样：每个等式约束对应一个对偶变量，优化时一起更新。

7.5 KKT 直觉：把不等式约束也装进来

现实里的约束常常是不等式，比如「概率必须非负」「资源用量不能超过预算」。把 g(x)=0 推广成 g(x) ≤ 0，最优点分两种情况：约束没被顶住（g(x) < 0），此时它根本不起作用，相当于无约束问题，乘子 λ=0；约束正好顶住（g(x) = 0），此时它像等式约束一样提供法向，λ 非零。把两种情况合在一起，就是互补松弛条件：

λ ≥ 0，g(x) ≤ 0，λ·g(x) = 0

最后一条的意思是「两者至少有一个为零」：约束松着则乘子为零，乘子非零则约束必须紧。这四条——驻点、原始可行、对偶可行、互补松弛——合起来叫 Karush-Kuhn-Tucker（KKT）条件。它是约束优化的一阶必要条件，凸问题下还是充分条件。

第 1 帧的两条管「点在哪、梯度怎么摆」；第 2 帧的两条管「乘子取什么值、什么时候该为零」。反过来从乘子看原问题，就得到对偶问题：原问题在最小化（或最大化）f，对偶问题在优化 λ，两边的最优值在凸情形下相等。这个对偶视角不只是理论装饰——它直接给出了分布式优化和很多机器学习算法的构造方式。

工程惯例互补松弛的想法到处都是

SVM 里每个训练样本带一个 αᵢ，只有支持向量的 αᵢ 非零，其余样本「约束松着、乘子为零」——这正是互补松弛。带不等式约束的强化学习里，策略更新要满足安全约束，对应的对偶变量只在约束快被违反时才变大。甚至经济学里的供需均衡也可用同一套语言描述。你不必记住 KKT 的完整证明，但要认得这个模式：每个约束配一个乘子，松弛时乘子归零，顶住时乘子为正。

7.6 本例手算：把四个数算到小数点后六位

现在按程序的实现走一遍。程序的做法是：先用共用库的 mc_grad 对线性目标求数值梯度，得到 ∇f = (3,4)（线性函数的中心差分没有截断误差）；再用 mc_norm 算出范数 5，于是 λ = 5/2 = 2.5；最后 x = ∇f/(2λ) = (3,4)/5 = (0.6, 0.8)。

第 14 行在零点求 f 的梯度。为什么在零点求也行？因为 f 是线性的，梯度处处相同，mc_grad 的中心差分把 f(p)-f(m) 里的常数项抵消掉，只留下 2eps×3 与 2eps×4，除以 2eps 正好是 (3,4)。第 18 行的注释是整段推导的压缩版：∇g = 2x，在单位圆上 ‖x‖=1，所以 ‖∇f‖ = λ‖∇g‖ = 2λ。

验证代码走的是完全独立的另一条路：它把解代入数值梯度，检查驻点残差与约束残差。

第 26、27 行分别数值求出两个梯度；第 28、29 行检查 ∇f − λ∇g 的两个分量；第 30 行检查 g(x)=0；最后取三者中的最大值作为总体残差。为什么取最大值而不是和？因为我们要的是「最坏的一条有没有超标」，和会把三个小误差加起来，掩盖某一条明显不合格的情况。这种「取最坏」的写法在数值验证里很常见。

真跑的 stdout 如下，四个数值行对应四个黄金值：

x:[...] 还是冒号格式，闸门按普通文字逐字比较；lambda、x0、x1、check 四行是数值行，各按 atol=1e-6 对账。check=0.000000 说明最大残差小于 5e-7，实际上数值梯度在这里精确到 1e-11 量级，打印成六位小数就是零。

实验记录把 λ 改错一位会怎样

把 lg_solve 里的 sol->lambda = norm / 2.0 改成 norm / 2.1，重新编译运行。此时 x 会变成约 (0.5714, 0.7619)，x0、x1 两行不再匹配黄金值；更重要的是 check 会从 0.000000 变成约 0.038，因为驻点条件不再成立。注意程序依然打印 PASS 吗？不，程序根本没打印 PASS——它只打印数字，闸门自己判断。这正是数值模式的纪律：证据由闸门从 stdout 重算，不由被测程序自报。

7.7 numerical 闸门：四个黄金值与一个容差

清单里 expect.numbers 写了四项：lambda=2.5、x0=0.6、x1=0.8、check=0.0，每项 atol=1e-6。闸门做三件事：从真实 stdout 里解析出这四个 key；逐项与黄金值比较，判定式 |actual − expected| ≤ atol + rtol×|expected|（这里没写 rtol，用默认的 1e-4，但 atol=1e-6 主导）；同时把正文 output 块的四行与实际输出逐行对账，防止正文被改成好看的假数字。

为什么黄金值要写四个而不是只写 x0、x1？因为「切点对了」和「整套推导对了」不是一回事。一个程序可以硬编码 x=(0.6,0.8) 却把 λ 算错；加上 lambda 这一行就能抓住。再加 check 是第三道保险：即使三个输出都蒙对了，残差验证还能独立确认它们满足数学条件。黄金值越多，作弊或出错后还能全部蒙对的可能性越小。

陷阱check 不能由被检查的量直接算出来

如果把 lg_check 写成「用 sol->x 和 sol->lambda 再算一遍闭式公式，然后返回 0」，残差就永远为零，这道验证形同虚设。本节的 lg_check 刻意走另一条路：调用 mc_grad 从函数值重新求梯度，完全不使用 lg_solve 里的推导。两条路径越独立，验证越有价值。这和梯度对拍里「解析梯度 vs 中心差分」是同一条原则：裁判不能和运动员共用同一套公式。

7.8 影子价格：λ 在 SVM 与 RLHF 里的样子

拉格朗日乘子最实用的解读是「约束松一点的代价」。假设你在分配有限预算，约束是总花费不超过 B，最优解对应的 λ 告诉你：预算 B 每增加一元，最优目标大约能改善多少。λ 大说明这条约束卡得紧、放宽它很值钱；λ 为零说明预算根本没用完，再多加也没用。这就是影子价格这个名字的由来。

支持向量机是教科书级的例子。软间隔 SVM 的目标是在分类间隔与违规惩罚之间折中，每个训练样本带一个不等式约束和对应的乘子 αᵢ。KKT 的互补松弛保证：只有那些正好卡在间隔边界上或越界的样本才有非零 αᵢ——它们就是支持向量。其余样本即使删掉，训练结果也不变。今天看大规模 SVM 的训练算法，核心就是如何高效找出这批非零乘子。

RLHF（基于人类反馈的强化学习）里也能看到同一个模式。给策略加一条 KL 约束，限制它不要偏离参考模型太远，对应的拉格朗日乘子控制「偏离」与「奖励」之间的兑换率。实际系统常把这个乘子做成自适应控制器：奖励上升太快就加大惩罚，约束太松就减小乘子。你看到的是一堆工程调节，本质仍是本节那条 ∇f = λ∇g 和对偶变量的更新。

大白话对偶变量是「谈判代表」

把约束看成一条硬性规定，原问题在规定的框框里尽量优化目标。对偶问题则派出一个「谈判代表」λ，负责给这条规定定价：定得太高，原问题会过度保守；定得太低，规定会被无视。两边的最优值在凸问题下汇合，谈判结束。这个视角让很多算法变得自然：交替更新原变量和对偶变量，让定价与实际松紧互相适应。本节那个小小的 λ=2.5，就是这条思路的最小样本。

7.9 常见错误清单

第一，把驻点条件写成 ∇f = 0。前面说过，那是无约束问题的条件。第二，忽略 λ 的符号，把最大与最小的候选混在一起；算出 λ=±2.5 后必须代回比较目标值。第三，约束函数写成 1 − x₀² − x₁² = 0 而不是 x₀²+x₁²−1=0，∇g 整体变号，λ 的符号跟着翻转——数值解没错，但影子价格的解读反了。写约束时先固定一个约定，并在正文里写明。

第四，只验证驻点条件，不验证可行性。一个点可以让 ∇f = λ∇g 成立却不在圆上，此时 λ 再漂亮也没有意义。本节的 check 特意把约束残差也包进去。第五，用单侧差分求梯度：mc_grad 用中心差分不是巧合，线性函数下两种都精确，但换成非线性约束，单侧差分的 O(eps) 误差会直接污染 check。

工程惯例从二维推广到 n 维

本例只有两个变量、一个约束，维数低到可以画图。推广到 n 维时，几何图像仍然存在，只是画不出来：∇g 变成一个 n 维法向量，∇f 必须落在由所有约束梯度张成的法空间里。KKT 条件的代码形式也不变——仍然是「算梯度、检查共线、检查可行」。真正变麻烦的是求解：二维可以徒手解方程，n 维需要数值方法（对偶上升、增广拉格朗日、内点法）。但无论用什么方法，检验解好坏的还是本节这几条残差。

7.10 为什么这样的玩具例子值得真跑

有人会问：既然答案徒手就能算到 (0.6,0.8)，为什么还要写 C 程序、建清单、跑闸门？理由和前几节一样：手算是推导，真跑是证据。手算可能把 λ 的符号搞反、把 ∇g=2x 的 2 漏掉，自己还浑然不觉；程序把闭式解与数值梯度两条路并排放在一起，残差一旦不为零就当场暴露。更重要的是，程序把「求解」和「验证」分成了两个函数，这种分工在更大规模的问题里会救命——当你解不出闭式解、只能靠优化器迭代时，验证代码依然可以原封不动地用。

7.11 拉格朗日量：把方程组装进一个函数

把驻点条件和可行性塞进同一个函数，就得到拉格朗日量 ℒ(x,λ) = f(x) − λ·g(x)（符号约定可正可负，不影响解）。对它分别求偏导：

  • ∂ℒ/∂x = ∇f − λ∇g = 0，这就是驻点条件；
  • ∂ℒ/∂λ = −g(x) = 0，这就是约束本身。

于是「在约束下优化 f」变成了「在无约束的 (x,λ) 联合空间里找 ℒ 的驻点」。这个改写不只是记号游戏：它让同一套无约束优化工具（梯度下降、牛顿法）可以用于带约束问题，只要把 λ 也当作一个变量来更新。实践中常见的增广拉格朗日法还在 ℒ 上加一项 ρ·g(x)²/2，把约束违反变成实实在在的惩罚，让迭代更稳。

ℒ 的驻点一般是鞍点而不是极小点：对 x 是极小、对 λ 是极大（或相反，取决于符号约定）。这也解释了为什么约束优化不能简单套用「沿负梯度走」：对 λ 那一维要往上走，对 x 那一维要往下走。对偶算法就是这种「分方向走」的系统化版本。

第 2 帧是求解路径：用 mc_grad 与 mc_norm 得到梯度和范数，按闭式公式给出解。第 3 帧是验证路径：lg_check() 自己的 mc_grad 调用从头再算一遍，完全不看求解路径用过的中间量。两帧的调用结构画在一起，就能一眼看出「裁判与运动员分离」这件事在代码层面是怎么落实的。

7.12 对偶问题：从乘子那一侧看同一个优化

把 ℒ 对 x 最小化后得到的函数称为对偶函数 d(λ) = min_x ℒ(x,λ)。原问题是在约束下优化 f，对偶问题则是在 λ 上最大化 d(λ)。对任意 λ，d(λ) 都是原问题最优值的下界（对最小化问题而言），所以最大化这个下界是在从下方逼近真实最优值——这叫弱对偶。凸问题加上合适的约束资格条件时，两边最优值相等，叫强对偶。

大白话下界是怎么来的

对任意满足约束的可行点 x 与任意对偶变量 λ，因为 g(x)=0，有 ℒ(x,λ)=f(x)。于是 d(λ)=min_x ℒ(x,λ) ≤ ℒ(x_feasible,λ)=f(x_feasible)。也就是说，无论 λ 取什么值，d(λ) 都不会超过任何可行点的目标值，当然也不会超过最优值。把 d(λ) 最大化，就是把这条下界抬得尽可能高。这个证明只用到了「最小值不大于任一取值」，不需要任何凸性假设——所以弱对偶永远成立。

强对偶不是免费的。非凸问题里常常出现对偶间隙：对偶最优值严格低于原问题最优值。深度学习里大量问题是非凸的，所以当你看到某个算法「通过对偶求解」时，要问一句它在什么条件下与原本问题等价。不过即便有间隙，对偶变量仍常常是有用的正则化旋钮——比如 RLHF 里那个 KL 乘子，工程师未必在意强对偶，只在意它能不能把策略约束在合理范围内。

7.13 残差的误差预算：为什么 1e-6 是合适的容差

check 用数值梯度，而数值梯度带误差。中心差分求 ∇g 时，g 是二次函数，g(p)-g(m) 里的二次项精确抵消，分子只剩 4eps·x_i，除以 2eps 得到 2x_i，误差只来自浮点舍入，量级在 1e-11 附近。求 ∇f 时 f 是线性函数，同样只有舍入误差。因此 check 的理论残差应该在 1e-11 量级，远小于清单的 atol=1e-6。

工程惯例容差要按误差来源定，不是拍脑袋

如果目标换成 f = exp(x₀) + sin(x₁)，中心差分的截断误差是 O(eps²)，在 eps=1e-5 下约 1e-10，仍在 1e-6 之内；若换成不光滑的函数（比如带 abs 或 max），中心差分在折点附近会给出完全错误的梯度，残差可能跳到 1e-2。此时该改的是验证方法（用解析梯度或自动微分），而不是把容差放宽到 0.1——放宽容差等于取消检查。容差是误差预算的数字化，必须先弄清误差从哪里来。

还有一个容易忽略的点：容差写在清单，但黄金值本身也要可信。本节的四个黄金值来自手算的闭式解：勾股数 (3,4,5) 保证 λ=2.5 与切点 (0.6,0.8) 没有舍入问题；check=0 是因为残差在打印精度下为零。如果黄金值来自「第一次跑出来的输出」，就有循环论证的风险——程序算错了，黄金值也跟着错。正确做法是先手算或用独立方法算出期望值，再用真跑确认。

7.14 换个约束再算一遍：推广的直觉

把约束从单位圆改成椭圆 x₀²/4 + x₁² = 1，目标仍是 3x₀+4x₁。方法可以照搬：等值线沿 (3,4) 方向外推，最后与椭圆相切。∇g = (x₀/2, 2x₁)，驻点条件是 (3,4)=λ(x₀/2,2x₁)，解出 x₀=6/λ、x₁=2/λ，代入椭圆得 9/λ² + 4/λ² = 1，于是 λ=√13≈3.6056，切点约 (1.664, 0.555)。可见 λ 的数值随约束形状改变，但「梯度共线 + 约束可行」这两条永不变。

多个约束时，驻点条件变成梯度线性组合：∇f = Σⱼ λⱼ∇gⱼ。几何上，目标梯度必须落在所有约束法向量张成的空间里；如果某个约束的法向量与其余共线，对应的乘子就不唯一——这叫约束资格条件不满足，数值求解会变得病态。不等式约束再叠加互补松弛，就组成完整的 KKT 体系。把这些推广记在心里，本节这个圆上的玩具例子就成了一把通用钥匙。

7.15 从几何到算法：大问题上怎么求 λ

本例能徒手解出 λ，是因为约束是圆、目标是线性函数。一般问题不能这么幸运，需要一套迭代办法。最朴素的是对偶上升：固定当前 λ，对 x 做一步（或若干步）无约束下降，最小化 ℒ(x,λ)=f(x)−λg(x)；然后用当前的约束违反量更新乘子，λ ← λ + α·g(x)（符号取决于 ℒ 的写法）。如果约束被违反得多，乘子就变大，下一轮对 x 的惩罚更强，逼它回到可行域。两个变量交替更新，直到约束满足且 x 不再变化。

陷阱对偶上升的步长不好调

对 λ 的更新步长 α 与对 x 的学习率不是一回事：α 太大，乘子会在正负之间剧烈震荡；α 太小，约束违反量收敛得极慢。更麻烦的是，当 ℒ 对 x 不是严格凸时，min_x ℒ 这一步可能根本没唯一解，对偶函数不光滑，朴素梯度更新会卡住。增广拉格朗日法在 ℒ 里再加 ρ·g(x)²/2，让 x 子问题更良态，乘子更新也稳得多；代价是引入一个惩罚系数 ρ 要调。现代约束优化库大多以增广拉格朗日为核心，不是偶然。

在深度学习里，约束往往不是几何曲面，而是「概率非负且和为 1」「策略与参考模型的 KL 小于 δ」这类条件。处理办法分两派。一派把约束做成硬投影：每步更新后把参数或输出投影回可行域，比如把负值截断为 0 再重新归一化；简单，但投影会引入偏差。另一派把约束做成软惩罚：把 ρ·g(x)² 加进损失，让训练自己学会满足约束；灵活，但永远不能保证严格可行。拉格朗日乘子法介于两者之间——它保留硬约束的目标，同时用可学习的乘子代替固定的大惩罚系数，因此在 RLHF、安全强化学习和带约束的生成控制里越用越多。

工程惯例从本节到「用 PyTorch 写约束优化」

如果将来你在框架里实现类似算法，会发现代码结构和本节很像：主网络输出 x，另有一个标量参数 λ 通过 λ = λ + α·g(x).item() 更新；训练循环里既记录任务损失，也记录约束残差。本节教你的是「为什么这两个量要一起更新」，框架只负责自动求导。不要因为看不到显式的 ∇f = λ∇g 就以为公式没用——它藏在优化器的更新规则里。

7.16 数值实验的复现清单

把这一节的实验搬到别处时，最好把条件写全，否则别人（包括未来的你）无法复现。至少要记录：目标函数的系数 (3,4)；约束函数 x₀²+x₁²−1=0 的写法；中心差分步长 1e-5；黄金值的来源（勾股数手算，不是第一次运行的输出）；容差 1e-6 的依据（残差理论量级 1e-11 远小于容差）。清单保存了容差和「程序该打印什么」，源码保存了实验怎么做，两者合起来才是一份可复现记录。

再列一遍常见失败模式，方便对照排查：

把 lg_g 改成 1.0 - x.v[0]*x.v[0] - x.v[1]*x.v[1]，其余不动，重新编译运行。你会看到 lambda=-2.500000，而 x 仍是 (0.6,0.8)，check 仍是零。四个黄金值里只有一个不匹配，闸门报 numeric_value_mismatch。这个实验说明：约束的写法是一种约定，它决定 λ 的符号；解本身不变，但「影子价格」的解读会跟着翻转。所以写约束时一定把约定写进注释和正文，不要留给读者猜。

最后强调一句贯穿本册的纪律：黄金值必须来自独立的推导，不能来自程序输出。本节之所以敢把 lambda=2.5 写进清单，是因为 3²+4²=5² 这个勾股数让人一眼就能验算；check=0 则来自误差量级分析。要是把「第一次运行的输出」直接抄成黄金值，程序里一个稳定的错误就会被固化成标准答案，之后每次对拍都会 green——但 green 的是错误。这与第 5、8 单元的阴性对照是同一条原则的不同侧面。

7.17 从二维图到高维代数：法空间与秩

二维图很好用，但别让它把你限制住。在 n 维空间里，单个等式约束 g(x)=0 定义的是一张 n−1 维曲面；∇g(x) 是这张曲面的法向量，所有切线方向都与它垂直。∇f=λ∇g 的意思是目标梯度只能沿法向，没有任何切向分量——否则沿那个切向走一点，f 还会变化，当前点就不是极值。

多个约束时，每个 ∇gⱼ 贡献一个法向，它们的线性组合张成法空间。驻点条件 ∇f = Σⱼλⱼ∇gⱼ 说的是目标梯度落在这个法空间里。用线性代数的语言：∇f 必须在 span{∇gⱼ} 中。如果这些法向量线性相关——比如两个约束其实是同一个圆写了两遍——那么法空间的维数小于约束个数，乘子不唯一。数值求解器遇到这种情况会报「约束资格条件不满足」或者给出巨大的乘子，工程上要先删掉冗余约束。

工程惯例用投影的视角看同一件事

把约束想成一张曲面，优化过程可以分成两步：先按 unconstrained 的方式走一步，再把落点投影回曲面。投影方向就是法向，而投影量正好与 λ∇g 成正比——乘子在这里变成了「需要往法向拉回多远」的度量。这个视角把拉格朗日乘子与数值线性代数里的投影矩阵联系了起来：法空间投影矩阵是 N(NᵀN)⁻¹Nᵀ，其中 N 的列是各个约束梯度。你不必在代码里真的构造它，但知道它的存在，就能理解为什么约束越多、法向越接近共线，求解越不稳定。

最后回到本例。圆在 (0.6,0.8) 处的法向是 (0.6,0.8)，目标梯度 (3,4) 正好是它的 5 倍；而 ∇g=2x=(1.2,1.6)，所以 λ=2.5。三个数字之间的倍数关系一目了然。把这张图记牢：以后不管约束变成椭圆、超平面还是复杂的神经网络输出流形，你脑海里都应该浮现同一幅画面——两组等高线相切，法向对齐，乘子就是对齐的比例系数。

7.18 收敛判据：残差比目标值更值得盯

数值求解约束优化时，很多人习惯盯目标值是否还在变化。但目标值停滞不一定意味着收敛：算法可能卡在一个约束严重不可行的点上，此时目标值当然不再改善。可靠的判据是同时看三类残差：驻点残差 ‖∇f − λ∇g‖、约束违反量 ‖g(x)‖、以及互补残差 ‖λ·g(x)‖。三者都降到阈值以下，才能说找到了一个近似 KKT 点。本节的 check 把前两类合并成一个数，正是这个思想的最小版本。

工程惯例为什么互补残差也不能漏

只看驻点与可行性，会漏掉「乘子取了不该取的值」的情形。举例说，一个不等式约束明明松着（g<0），却配了一个很大的正乘子，驻点方程可能被这个乘子强行满足，点也确实可行，但互补条件被破坏。此时影子价格的解读完全错误：预算根本没花完，报告却说放宽预算很值钱。把互补残差加进监控列表，几行代码就能挡住这种误导。

小结这一节的要点
  • 有约束极值处 ∇f = λ∇g：目标梯度与约束梯度共线，几何上是两组等高线相切；
  • 本例 ∇f=(3,4)、∇g=2x，解得 λ=2.5、x=(0.6,0.8)，λ 取负号给出最小值点；
  • KKT 四条件：驻点、原始可行、对偶可行、互补松弛；每个不等式约束配一个非负乘子；
  • check 用数值梯度独立重验 ∇f−λ∇g=0 与 g=0，取最坏残差，不能由被验证的量直接算出；
  • mode=numerical 给四个黄金值与 atol=1e-6，程序自报不算证据；
  • λ 是影子价格：SVM 的支持向量、RLHF 的 KL 约束乘子都是同一个对偶变量的实例。

注自测题答案
  1. 沿约束曲线 γ(t) 有 g(γ(t))=0，求导得 ∇g(x*)·γ′(0)=0，所以 ∇g 垂直于切线。极值处同理 d f(γ(t))/dt|₀ = ∇f(x*)·γ′(0)=0，∇f 也垂直切线；二维里垂直同一方向的向量必共线，于是 ∇f=λ∇g。
  2. 3=2λx₀、4=2λx₁ 给出 x=(3,4)/(2λ)；代入 x₀²+x₁²=1 得 25/(4λ²)=1，λ=±2.5。λ=2.5 给出 (0.6,0.8)，最大值 5；λ=-2.5 给出 (-0.6,-0.8)，最小值 −5。
  3. 新约束的梯度是 −2x，与原 ∇g 反号，所以 λ 也反号。点 x 仍满足驻点比例关系，数值解不变；但影子价格的符号解读跟着约定翻转，必须固定一种写法。
  4. 驻点 ∇f=λ∇g、原始可行 g≤0、对偶可行 λ≥0、互补松弛 λg=0。约束没顶住时 g<0，互补条件逼出 λ=0，说明这条约束在该解处不起作用。
  5. 取最大值检验的是最坏一条是否超标，求和会让三个小误差互相掩盖。走不同路径是为了让验证独立于推导：若 check 复用闭式公式，残差恒为零，等于没有验证。
  6. 报 numeric_value_mismatch：真实 stdout 的 lambda=2.500000 与清单黄金值 2.6 相差 0.1，远超 atol=1e-6。说明容差与黄金值只由清单决定，正文写「约等于」或程序打印什么都无效。
  7. 影子价格是约束右端变化时最优值的变化率，衡量「放宽约束值多少」。软间隔 SVM 里只有卡在间隔边界或越界的样本约束是紧的，由互补松弛它们的 αᵢ 非零；其余样本 αᵢ=0，对决策没有贡献，因此得以和支持向量区分开。
