8.1 先看工程长什么样

这一单元是整册的收官。前七节把偏导、梯度、Jacobian、Hessian、链式法则、梯度下降、拉格朗日乘子逐个讲过，现在把它们汇到同一个问题上：损失函数是一个标量，参数是一个矩阵，梯度该怎么算？ 深度学习里这件事无处不在——每一层的权重 W 都是矩阵，反向传播返回的梯度也必须是同形矩阵；少一个转置，维度检查还照样通过，训练却悄悄走错。

本节仍然走 mode=gradient，和 mc05 一样要求阴性对照。不同的是，注入的错误从「漏乘内层导数」换成了「漏掉转置那一半」。这个选择很有讲究：2×2 矩阵转置前后形状一样，编译器抓不住，程序照常跑，只有对拍能发现。

第 1 帧是已有工程，第 2 帧新增 mat_deriv/。头文件声明 2×2 问题与三个函数；matderiv.c 里解析梯度走 (A+Aᵀ)X，数值梯度把 X 摊平成 4 维向量后借用共用库的 mc_grad；main.c 打印 A、X 两个矩阵与四行梯度表；清单声明 atol=1e-5、min_params=4、min_nonzero=2，以及 negative_flags: ["-DGRAD_BUG=1"]。

大白话矩阵微分不是新数学，是换了记号的标量微分

把矩阵的每个元素看成独立变量，把目标函数看成这些变量的多变量函数，那么前面七节学的一切都还成立。矩阵微分唯一新增的东西是记号：用矩阵乘法、trace、内积把一大堆分量求和压成一个简洁表达式。好处是公式短、能看出结构；坏处是转置和下标很容易悄悄错位。所以对拍在这里比在别处更重要。

8.2 形状先定死：梯度长什么样

先立约定。输出是标量 f，输入是 m×n 矩阵 X，那么 Jacobian 严格来说是 1×(mn) 的一行；我们习惯把梯度存成与 X 同形的 m×n，第 i 行第 j 列的数是 ∂f/∂X_ij——「X 的这个位置拧一下，f 变多少」。这个「把一行折成同形矩阵」的动作，是很多转置的源头。

一一对应的工具是 Frobenius 内积：

<A, B> = tr(AᵀB) = Σᵢⱼ A_ij B_ij

它就是把两个矩阵按元素相乘再求和，和向量的点积一模一样。有了它，标量函数的一阶近似可以写成：

f(X + dX) ≈ f(X) + <∇f(X), dX>

这条式子定义了矩阵梯度：哪个矩阵 G 能让任意微小改动 dX 引起的变化等于 <G, dX>，那个 G 就是 ∇f。记住这条定义，推导任何矩阵导数都只需要做代数整理，不用背公式表。

第 2 帧的四个数就是本节要证明的结果。注意 g[0][1] 是负的：把 X01 增大一点，损失会下降。梯度矩阵与 X 同形这件事，让反向传播可以写出漂亮的更新式 W ← W − lr·∇W——两个矩阵逐格相减，不需要任何 reshape。

工程惯例为什么不用「Jacobian 是一行」的严格形式

严格按 Jacobian 约定，标量对 m×n 矩阵的导数是 1×mn，写起来是一长行。这当然没错，但反向传播里每层的参数都是矩阵，把梯度存成同形矩阵才能直接做逐元素更新。于是全行业都采用「同形梯度」约定，代价是每次推导都要小心转置——你看到的每一个 .T，多半就是在把严格 Jacobian 翻译成同形梯度。分母布局与分子布局的术语之争也源于此，本节统一采用「梯度与变量同形」的约定。

8.3 第一个恒等式：∇_X tr(AX) = Aᵀ

从 Frobenius 内积的定义出发。设 f(X) = tr(AX)，其中 A 是 n×m、X 是 m×n，乘积 AX 是 n×n，trace 有定义。把 trace 展开：

tr(AX) = Σᵢ (AX)_ii = Σᵢ Σⱼ A_ij X_ji

分母布局下梯度与 X 同形，所以 ∂f/∂X_ji = A_ij。要把这个关系写成矩阵形式：第 j 行第 i 列是 A 的第 i 行第 j 列——正好是 A 的转置。所以 ∇_X tr(AX) = Aᵀ。

用微分形式推更短。df = tr(A dX)。为了套进 <G, dX> = tr(Gᵀ dX) 的形式，只要令 Gᵀ = A，即 G = Aᵀ。一步到位。

陷阱形状检查在这里能帮你

tr(AX) 要求 A 的列数等于 X 的行数；梯度必须与 X 同形，也就是 m×n。A 本身是 n×m，直接拿 A 当梯度形状是 n×m——当 m≠n 时立刻不合法，转置一下才对。长方形矩阵里，漏转置会被形状检查抓住；方形矩阵里不会。 本例的 A 恰好是 2×2，所以阴性对照必须靠对拍来判别，不能指望编译器。这是矩阵微分最危险的一类陷阱。

再来一个常见变体：f(X) = tr(X)，那么 df = tr(dX)，对照 <G,dX>=tr(GᵀdX) 得 Gᵀ=I，即 ∇_X tr(X)=I。同理 ∇_X tr(BXC) = BᵀCᵀ：先用 trace 的循环性质把 tr(BXC) 写成 tr(CBX)，再套上一条恒等式。循环性质 tr(ABC)=tr(BCA)=tr(CAB) 是 trace 微分的瑞士军刀，几乎所有公式都能靠它化简。注意循环不等于随意交换：只有整体轮换可以，任意两两交换一般不行。

8.4 第二个恒等式：∇_X tr(XᵀAX) = (A+Aᵀ)X

这是本节的核心公式，也是阴性对照针对的那一条。先用分量展开，最稳妥：

tr(XᵀAX) = Σⱼ Σᵢ Σₖ X_ij A_ik X_kj

对 X_ab 求偏导。X 出现在两处：第一处是 X_ij，当 i=a, j=b 时贡献 Σₖ A_ak X_kb；第二处是 X_kj，当 k=a, j=b 时贡献 Σᵢ X_ia A_ia——注意这里利用 A 的下标 A_i k 中 k=a。把第二项的下标 i 改名为 k，得到 Σₖ X_ka A_ka。两项合起来：

∂f/∂X_ab = Σₖ (A_ak + A_ka) X_kb

写成矩阵就是 (A + Aᵀ) X 的第 a 行第 b 列。如果 A 是对称矩阵，A+Aᵀ=2A，公式退化成 2AX；但一般情形下漏掉 Aᵀ 那一半就是错的。 本例刻意选了非对称的 A，正是为了让错误暴露出来。

用微分法也能得到同一结果，而且更能看出对称化的来源：

df = tr(dXᵀ A X) + tr(Xᵀ A dX) = tr((AX)ᵀ dX) + tr((AᵀX)ᵀ dX) = < (A+Aᵀ)X, dX >

第一步用了乘积微分法则，第二步把第一项转置一下写成 Frobenius 内积的标准形式（tr(dXᵀ M) = tr(Mᵀ dX)），第三步合并同类项。整个推导没有一句「显然」，全靠 trace 与内积的定义。

第 2、3 帧说明了一个重要事实：A 出现两次，所以梯度里出现两份贡献。一份来自 A 的左乘，贡献 AX；一份来自 A 的右乘（转置后），贡献 AᵀX。漏掉后一份，就等于假装 A 是对称的。第 3 帧的 grad 节点与第 1 帧的 X 同形，这正是反向传播要求的输出。

8.5 本例：四个梯度逐项手算

取 A = [[2, 1], [−0.5, 3]]、X = [[0.5, −1], [1.5, 0.8]]。A 非对称（A01=1、A10=−0.5），这是关键。先算对称部分：

A + Aᵀ = [[4, 0.5], [0.5, 6]]

再算梯度矩阵 (A+Aᵀ)X：

  • g00 = 4×0.5 + 0.5×1.5 = 2 + 0.75 = 2.75
  • g01 = 4×(−1) + 0.5×0.8 = −4 + 0.4 = −3.6
  • g10 = 0.5×0.5 + 6×1.5 = 0.25 + 9 = 9.25
  • g11 = 0.5×(−1) + 6×0.8 = −0.5 + 4.8 = 4.3

四个数全部非零，清单的 min_nonzero: 2 稳稳满足。为了确认，再用分量式验算一个：∂f/∂X01 = Σₖ (A_0k + A_k0) X_k1 = (A00+A00)X01 + (A01+A10)X11 = 4×(−1) + 0.5×0.8 = −3.6，一致。

实验记录把 A 改成对称矩阵会怎样

把 main.c 里的 av 改成 {2.0, 0.5, 0.5, 3.0}，A 变成对称矩阵。此时正解 A+Aᵀ=2A，阴性对照的 2AX 与它完全相同，两列梯度仍然逐项对齐；但闸门会报 gradient_harness_not_discriminating，因为错梯度也通过了。这不是程序写错了，而是实验设计失去了判别力。 这个实验把「阴性对照为什么必须用非对称矩阵」讲得清清楚楚：检查器的能力取决于你喂给它的例子。

8.6 阴性对照：漏转置为什么最隐蔽

打开 -DGRAD_BUG=1 再编译一份，四行解析梯度变成 (5.0, −2.4, 8.5, 5.8)，数值梯度仍是 (2.75, −3.6, 9.25, 4.3)。四个差值分别是 2.25、1.2、−0.75、1.5，全部远超 atol=1e-5，阴性对照被判失败——闸门由此证明这套对拍能抓住「漏转置」。

为什么这类错误最隐蔽？因为它不改变形状。A 是 2×2，A 与 Aᵀ 都是 2×2，2AX 与 (A+Aᵀ)X 都是 2×2；编译器不报错，运行时不越界，打印出来的数字也「看着像梯度」——有正有负、数量级合理。如果只做形状检查，这类错误 100% 漏网。矩形矩阵里还有一线希望：AᵀB 与 AB 形状不同，编译器可能拦一下；方形矩阵里连这线希望都没有。

陷阱只跑正例会给你虚假的安全感

正例四行完美对齐，很容易让人收工。但你无法区分两种可能：梯度真的算对了，或者「对拍机制失灵」。把 md_analytic_grad 改成直接调用 md_numerical_grad，正例照样满分；把 A 改成对称矩阵，阴性对照也会满分。只有同时看到「正例通过、阴性对照失败」，才能说检查有效。阴性对照验证的是检查器，不是被测程序——这句话在本节和第 5 单元各出现一次，值得重复到变成肌肉记忆。

再补一个工程视角。深度网络里权重矩阵往往是方阵（比如 hidden size 相同的两层之间），所以手写反向时漏一个 .T 是高频事故。框架虽然帮你记了转置，但自定义算子、手写 CUDA 核、量化后的低精度反向里，转置仍然要自己写。对拍的成本只是几行代码和几秒钟运行，漏掉它的代价可能是几周训练白跑。

8.7 闸门怎么判定：三条缺一不可

expect.gradient 给了 atol=1e-5、min_params=4、min_nonzero=2。闸门从 stdout 里解析出 x00、x01、x10、x11 四行，依次检查：行数≥4；解析梯度绝对值大于 atol×10=1e-4 的行数≥2；每行 |a−n| ≤ 1e-5。三条都过，再跑阴性对照，要求它至少有一条不过。

四条数字里最小的是 x01 = −3.6，绝对值远大于 1e-4，所以非零组数毫无争议。为什么还要单独设这一条？设想一个程序把四个解析梯度全输出 0，而数值梯度因为某些原因也接近 0（比如把 eps 误设为 0 导致差分商异常），逐项差值可能落在容差里；非零组数这条会立刻拦下它。反过来只查非零组数也不行：乱写四个非零数一样能通过。两条互相补足。

工程惯例容差 1e-5 从哪里来

被微分的 tr(XᵀAX) 是 X 的二次函数，中心差分对二次函数没有截断误差，剩下的只有双精度舍入。eps=1e-5 时，分子 f₊−f₋ 的量级约 eps×梯度，除以 2eps 后舍入噪声被放大约 1/eps ≈ 1e5 倍，绝对误差仍在 1e-10 量级。取 atol=1e-5 留了五个数量级的余量，既不会被噪声误伤，又能抓住 0.75 这种量级的错误。容差不是拍脑袋——它来自对误差来源的估计。

8.8 接回老朋友：Wᵀ(Wx−y) 里的转置从哪来

现在把本节的规则用到最熟悉的式子上。取 r = Wx − y、L = rᵀr。对 x 求导时，把 L 看成 r 的函数、r 看成 x 的函数。先看残差对 x 的 Jacobian：∂r/∂x = W，形状 m×n。外层对 r 的梯度是 2r，形状 m 维。按链式法则要乘 Jacobian 的转置：∇_x L = Wᵀ(2r) = 2Wᵀr。

为什么必须是转置？用 Frobenius 内积看更清楚。df = 2rᵀ dr = 2rᵀ (W dx) = (2Wᵀr)ᵀ dx = <2Wᵀr, dx>。对照 df = <∇f, dx> 的定义，梯度就是 2Wᵀr。转置来自把 2rᵀW dx 改写成「某个向量与 dx 的内积」这一步——和 8.3 把 tr(A dX) 改写成 <Aᵀ, dX> 是同一个动作。

对 W 求导则用本节的规则。W 的元素记作 w_ij，r_i = Σⱼ w_ij x_j − y_i，于是 ∂r_i/∂w_ij = x_j，∂L/∂w_ij = 2r_i x_j。排成矩阵是 2 r xᵀ——一个外积，行对应残差下标、列对应输入下标。注意这里出现的是 xᵀ 而不是 x：因为外层梯度是列向量，要写成矩阵形状必须把 x 转置后做外积。本节的「同形梯度」约定与链式法则的「Jacobian 行列」约定，在每一层都要翻译一次；翻译的动作就是转置。

第 1、2 帧是「同一公式的两种写法」，第 3 帧的裁判完全不用 trace 也不用转置。三条路径给出同一个数，才让本节那张梯度表有说服力。

8.9 布局之争：为什么转置总是成对出现

查矩阵微分资料时，你一定会遇到「分母布局」和「分子布局」两个术语。它们不是两套数学，而是同一事实的两种记号。分母布局把梯度存成与分母（自变量）同形：分子布局把导数存成与分子（因变量）同形。当因变量是标量、自变量是矩阵时，分母布局给 m×n 的同形梯度，分子布局给 1×(mn) 的一行——两者互为转置。

向量情形也一样。y = Wx，y 是 m 维、x 是 n 维：分子布局下 ∂y/∂x = W（m×n，行对应输出、列对应输入）；分母布局下同一个导数写成 Wᵀ（n×m）。本册从 mc01 起一直采用「Jacobian 行是输出、列是输入」的约定，那是分子布局；而反向传播里用的梯度是分母布局。从一种布局切换到另一种，就是把 Jacobian 转置一次。 你看到的每一个 .T，几乎都是这次切换的痕迹。

陷阱读公式前先确认布局约定

同一本教材里如果混用两种布局，公式会看起来自相矛盾：一处写 ∇f = Wᵀr，另一处写 ∂f/∂x = rᵀW。它们其实说的是同一件事，只是前者是分母布局的列向量，后者是分子布局的行向量。真正危险的不是记住哪个公式，而是没确认约定就照抄。本节的判据很简单：梯度是否与自变量同形？是，就是分母布局；不是，就看看它是不是 Jacobian 的转置。

框架则基本统一用同形梯度：参数的梯度与参数同形，激活的梯度与激活同形。这让更新式写成逐元素相减，非常顺手。代价是每次手写反向都要自己做一次「Jacobian → 同形梯度」的翻译，也就是转置。理解这一点之后，第 5 单元末尾那句话就完整了：反向传播不是一堆凭空冒出的转置，而是布局约定在每个局部映射上的反复落实。

8.10 推导套路与常用恒等式小抄

矩阵微分不需要死记几十条公式，掌握一条套路和四条基本规则就够。套路是：写出微分 df，利用 trace 的循环性质把它整理成 tr(M dX)，则梯度 G 满足 Gᵀ = M，即 G = Mᵀ。

四条基本规则：d tr(X) = tr(dX)；乘积法则 d(XY) = (dX)Y + X(dY)；逆矩阵微分 d(X⁻¹) = −X⁻¹(dX)X⁻¹；行列式微分 d det(X) = det(X) tr(X⁻¹ dX)。再加上循环性质 tr(ABC) = tr(BCA) = tr(CAB)，足以推出绝大多数常见公式。

举两个例子。第一，f(X) = tr(X⁻¹A)：df = tr(d(X⁻¹)A) = −tr(X⁻¹ dX X⁻¹ A)；循环一步得 tr((AX⁻¹) X⁻¹ dX)，也就是 tr(M dX) 且 M = X⁻¹ A X⁻¹（利用循环性整理顺序），于是 ∇f = −(X⁻¹ A X⁻¹)ᵀ。第二，f(X) = ‖AX − B‖_F² = tr((AX−B)ᵀ(AX−B))：记 R = AX−B，df = 2 tr(Rᵀ A dX) = 2 tr((AᵀR)ᵀ dX)，于是 ∇f = 2Aᵀ(AX−B)。把 X 换成 W、A 换成输入矩阵，这条就是全连接层权重梯度的通用形式。

陷阱循环性质只能轮换，不能任意交换

tr(ABC) = tr(BCA) = tr(CAB) 成立；但 tr(ABC) = tr(ACB) 一般不成立，因为那交换了 B 与 C。推导时只做「把末尾因子挪到最前面」这种整体轮换，不做的中间交换就不会出错。另一个常见错误是把 tr(dXᵀM) 直接读成梯度 M——正确的读法是先转成 tr(Mᵀ dX)，梯度才是 M。本节 8.4 的微分推导里专门做了这一步转置，就是在演示这个规矩。

8.11 二阶微分：为什么这里不展开成四阶张量

一阶微分 df = <∇f, dX> 我们已经很熟。再微分一次得到二阶项 d²f，它描述「梯度本身怎么随 X 变」。对矩阵变量，二阶导数是「矩阵的矩阵」——一个四阶张量，n×n 个一阶梯度，每个又是 n×n。深度网络里一层权重可能有上百万个元素，完整二阶导数的存储量是这个数字的平方，完全不可行。

但二阶信息有时只需要「沿某个方向」的值。对标量变量 x，Hv 给出 Hessian 在方向 v 上的作用；对矩阵变量也一样，可以定义 d²f[X, dX]，它是 dX 的线性函数，不需要显式构造四阶张量。对本节的例子，若 A 对称，f = tr(XᵀAX) 的二阶微分是 d²f = 2 tr(dXᵀ A dX)——一个关于 dX 的二次型，和 mc04 里的 Hessian 二次型是同一个东西。

大白话Hessian-vector product 为什么便宜

计算 Hv 不需要构造 H：先算 g(x)=∇f(x)，再沿方向 v 取方向导数 lim (g(x+εv)−g(x))/ε，或者用自动微分的前向模式直接算 g 的 Jacobian 与 v 的乘积。成本与一次梯度同阶。这正是 mc04 说「深度网络不用完整 Hessian，但可以用 Hessian-vector product」的原因。矩阵微分提供的是记号层面的统一：无论变量是向量还是矩阵，「一阶微分定义梯度、二阶微分定义曲率算子」这两句话都不变。

8.12 手写一层的反向：把转置逐个点名

把本节的规则用到最常见的一层网络：s = Wx + b，y = σ(s)（逐元素 sigmoid），L = ½‖y − t‖²。记 dy = y−t，逐层往回：

dL = <dy, dy_actual> → 对 y 的梯度 g_y = y−t； 过 sigmoid：g_s = g_y ⊙ y⊙(1−y)，逐元素相乘，没有转置，因为 s 与 y 同形； 过线性层：ds = (dW)x + W(dx) + db，于是 g_W = g_s xᵀ（外积），g_b = g_s，g_x = Wᵀ g_s。

三个结果里两个带转置。g_W = g_s xᵀ 的转置来自「把 Σᵢ g_s,i x_j 排成矩阵时，行是输出下标、列是输入下标」——正是外积的形状。g_x = Wᵀ g_s 的转置来自「W 把 x 映射到 s，反向要乘它的转置」。这与 8.8 的 2Wᵀr、2rxᵀ 完全同构，只是外层多了 sigmoid 的逐元素链式因子。

工程惯例形状表是最好的草稿纸

手写反向之前，先列出每个量的形状：W 是 m×n，x 是 n，b 与 s 与 y 都是 m。于是 g_s xᵀ 是 m×1 乘 1×n 得 m×n，与 W 同形；Wᵀ g_s 是 n×m 乘 m×1 得 n，与 x 同形。形状对不上的写法一定错，形状对上的写法未必对——本节的阴性对照就是形状对上但数值错的样板。先用形状筛掉一半错误，再用对拍抓住剩下那一半。

写到这里，整册的线索就闭合了：mc01–mc04 给出导数的形状与局部意义，mc05 把局部导数串成反向传播，mc06 用梯度做优化，mc07 处理带约束的优化，mc08 把这一切推广到矩阵参数。每一步都坚持同一条纪律——公式可以简写，数字必须对拍；程序可以自报成功，闸门必须独立重算。

8.13 实验纪律复盘

最后把这一节的实验条件盘点一遍，供以后照抄。输入 A 取非对称矩阵，这是阴性对照有判别力的前提；X 取四个数都能产生非零梯度，这是 min_nonzero 有意义的前提；数值微分步长取 1e-5，二次函数下截断误差为零、舍入误差可忽略；容差取 1e-5，比预期误差大约高五个数量级；黄金值来自手算的 (A+Aᵀ)X，不是第一次运行的输出。

实验记录自己设计一次「检查器失灵」实验

试着把 md_numerical_grad 改成直接返回解析梯度的拷贝。正例四行仍然完美对齐；阴性对照也会「通过」，因为错梯度被抄成了同样的值。闸门应报 gradient_harness_not_discriminating。这个实验和第 5 单元那次一样，说明检查器守的是自己。做完把文件改回原样，再跑一次 node build/run.js --unit mc08-matderiv，确认恢复全绿。

8.14 五个常见场景，一套统一规则

把本节规则套到深度学习里最常见的五种梯度上，你会发现它们其实是同一件事的五次变体。

场景一，线性层对输入： f=‖Wx−y‖²，∇_x f = 2Wᵀ(Wx−y)。转置来自「W 的列数等于 x 的维数，反向要把残差投影回输入空间」。 场景二，线性层对权重： ∇_W f = 2rxᵀ，r 是残差。外积的行对应输出、列对应输入，形状 m×n 与 W 同形。 场景三，权重衰减： f=λ‖W‖_F² = λ tr(WᵀW)，∇_W f = 2λW。梯度与 W 同形，更新时逐格缩小，这就是 L2 正则化的矩阵写法。 场景四，softmax 加交叉熵： 若 p = softmax(Wx+b)、L = −Σ y_i log p_i，则 ∂L/∂(Wx+b) = p − y，于是 ∇_W L = (p−y)xᵀ。形式与场景二几乎一样，只是残差换成了「预测概率减去标签」。 场景五，批量数据： batch 里 B 个样本，每个贡献一个外积 g_s^{(b)} x^{(b)ᵀ}，总梯度是它们求和。框架把这个求和写成矩阵乘法 G_sᵀ X，本质仍是外积的批量版。

工程惯例从这五个场景里能看出什么规律

第一，标量输出的梯度总是与参数同形——这是分母布局的承诺。第二，凡是「参数左乘变量」的地方，对变量的梯度里就出现参数的转置；凡是「变量被参数映射」的地方，对参数的梯度里就出现变量的外积。第三，非线性激活只带来逐元素的链式因子，不引入新的转置。把这三条记住，手写任何一层的反向都只需要查形状表，不必每次从零推导。

8.15 对拍的边界：中心差分什么时候不够用

本节的中心差分之所以精确，是因为 tr(XᵀAX) 是光滑的二次函数。换成不光滑的目标，情况会变糟。比如 f(x)=|x| 在 0 点不可导，中心差分给出 (|eps|−|−eps|)/(2eps)=0，而数学上 0 点的次梯度是一个区间；再比如 max、ReLU、排序、离散采样这些操作，差分步长跨过折点时结果会完全失真。此时不能把对拍失败简单归咎于解析梯度——可能是裁判本身不适用。

陷阱低精度下的对拍会系统性失灵

如果用 float16 做前向，f₊ 与 f₋ 的差可能小到被量化为同一个数，差分商恒为零；此时梯度对拍毫无意义。工程上的做法是梯度检查一律用双精度，训练时才用低精度。另一个边界是随机计算：如果目标函数内部含 dropout 或采样，同一参数两次求值本身就不一样，中心差分测到的是噪声而不是导数。此时要么固定随机种子并关掉随机性，要么用专门设计的似然比梯度估计器。

需要高精度时还有一个漂亮的办法：复数步。对实解析函数 f，取 f(x + i·h) 的虚部除以 h，可以在 h 极小时仍不受减法抵消影响，精度接近机器精度。限制是函数必须对复数有定义——abs、max、比较运算都不行。自动微分则是更通用的裁判：它按链式法则机械记录每一步，既不受步长困扰，也不要求函数光滑到能写解析式；本书手写中心差分，是为了让你看清「导数从定义上是什么」，不是因为它在工业里最好用。

8.16 全书收束：一份可复制的检查清单

到此八个单元走完。把它们共同的实验纪律抽出来，就是下面这份清单。以后写任何数值实验，照着过一遍即可：

  1. 先定形状：输入、输出、梯度的形状各是什么？形状对不上一定错，形状对上还要继续查。
  2. 先手算一例：选能整除或能心算的数字，算出期望值，作为黄金值的独立来源。
  3. 写解析路径和数值路径，两条路径不共用中间公式。
  4. 打印格式符合闸门约定：向量矩阵用冒号，数值行用 key=value 加有限十进制数。
  5. 容差来自误差预算：中心差分的截断与舍入、函数光滑性、数值精度，逐项估一遍。
  6. 梯度模式必须给阴性对照，并确认注入的错误确实让对拍失败。
  7. 训练模式必须固定种子、复现两次、换种子对照，三遍缺一不可。
  8. 程序自报的 PASS 不算证据；正文里的数字与真实 stdout 由闸门独立对账。
大白话这门课真正想教的东西

八节下来，公式会忘，数字会更早忘。留下来的应该是三种习惯：先看形状，再算数值；先造独立参照，再信自己的推导；先让检查器失败一次，再信它通过的结果。 深度学习框架会替你做大部分计算，但它不会替你形成这三种习惯。下次看到反向实现里一个孤零零的 .T，你能说出它从哪来、漏了会怎样、怎么验证——这一册的目的就达到了。

8.17 从 2×2 到 n×n：复杂度与实现取舍

本节只算 2×2 的四个梯度，手算和程序跑起来都只需一瞬。真实网络里一层权重可能是 4096×4096，约一千六百万个元素，梯度同样大小。好消息是，矩阵微分公式本身不随规模变坏：(A+Aᵀ)X 的计算量是 O(n³)（或 n×n 乘 n×m 的一般形式），与一次前向同阶；自动微分也正是以这个成本给出梯度。坏消息是存储：前向要保存的中间量与反向要保存的梯度都是矩阵级别，参数量乘以几倍就是显存开销的主要来源。

结构信息在大规模下变得重要。如果 A 已知对称，(A+Aᵀ)X 可以直接算 2AX，省掉一次加法；如果 A 低秩或稀疏，就可以利用分解避免显式构造 A+Aᵀ；如果 X 是稀疏的梯度（比如某些结构化剪枝场景），外积结果也可以用稀疏格式存储。这些优化不改变数学结论，只改变「怎么算更快」——本节的小例子把它们都藏起来了，但思路是一脉相承的。

陷阱中心差分最怕「原地修改」

md_numerical_grad 里每次扰动都作用在副本上，原始 X 保持不变。如果图省事，直接在 p->x[i][j] 上加减 eps 而忘了复原，算完第一个元素后 X 已经被改动，后面三个差分都在错误的基准点上计算，四行梯度会连锁出错。更隐蔽的情况是扰动量没有精确复原：x = x + eps; x = x - eps 在浮点里未必严格回到原值，多次循环后会累积漂移。正确做法就是本节这样——先复制问题结构，在副本上扰动，或者显式保存原值再写回。

框架之所以用自动微分而不是「公式表 + 人工代入」，原因也在这里：n 个矩阵、m 种运算，公式表的组合数会爆炸，而且每次结构改动都要人工重新推导。自动微分把局部求导规则绑定在操作上，组合由框架完成。本节手写这些公式，是为了让你理解框架在替你做什么，而不是为了将来手写它们。 当你能独立推出 2Wᵀr、(A+Aᵀ)X 和 g_s xᵀ，再去看框架的源码，那些 transpose 与 matmul 的组合就不再是黑魔法。

8.18 再算一例：从公式到数字的完整闭环

为了把套路练熟，再走一个与本节结构相同但系数不同的例子。取 A = [[1, 2], [3, 4]]、X = [[1, 0], [0, 1]]，也就是 X 为单位矩阵。此时 f = tr(XᵀAX) = tr(A) = 5。梯度按公式是 (A+Aᵀ)X = A+Aᵀ = [[2, 5], [5, 8]]，因为单位矩阵乘什么都等于原矩阵。四个分量是 (2, 5, 5, 8)。

用分量式抽查 g01：∂f/∂X01 = Σₖ (A_0k+A_k0) X_k1 = (A00+A00)X01 + (A01+A10)X11 = 2×0 + (2+3)×1 = 5。注意这里 X01 本身是零，但梯度不是零——因为 X11 那一格也参与了求和。「某格为零」不等于「对该格的敏感度为零」，这个误会常见于刚学矩阵微分的人，尤其在稀疏矩阵里，零元素的梯度完全可以非零，优化时它就会被更新成非零值。

再用单位矩阵这个特例反查公式的一致性：当 X=I 时，f=tr(A)，而 tr(A) 对 A 的梯度是 I。若把 A 也当作变量，f = tr(XᵀAX) 对 A 的梯度是 XXᵀ = I，与直接结论一致。两条独立路线给出同一个数，正是矩阵微分公式可靠性的体现。

实验记录把 X 换成非单位矩阵再验证一次

取 X = [[1, 2], [3, 4]]，A 仍为 [[1,2],[3,4]]。先算 A+Aᵀ = [[2,5],[5,8]]，再算 (A+Aᵀ)X = [[32,46],[47,70]]。把这四个数填进 xv 数组重新编译运行，正例四行应与手算一致；打开 GRAD_BUG 后，2AX 给出 [[38,48],[42,72]]，四个分量全部偏离。这个练习把「先算对称部分、再做矩阵乘」的流程走了一遍，也再次展示了漏掉 Aᵀ 后每一格都会被污染。

8.19 把矩阵微分当成一门「翻译课」

回头看这一单元，真正要练的能力不是记住 (A+Aᵀ)X，而是三种表示之间的来回翻译：分量下标写法 (a_ik+a_ki)x_kj、矩阵公式 (A+Aᵀ)X、以及微分形式 df = <(A+Aᵀ)X, dX>。分量写法最不容易出错，适合验证；矩阵公式最紧凑，适合写在论文里；微分形式最适合推导，因为它直接连着梯度的定义。遇到一个新公式时，先用微分形式推，再用分量式抽查一格，最后把矩阵形式写进笔记——三步走完，基本不会翻车。

工程惯例给自己的三个检查问题

以后每看到一个矩阵梯度公式，问三句：第一，梯度与自变量同形吗？第二，d f 能不能整理成 <G, dX> 的标准形式？第三，挑一格用手写分量式验算过吗？三句都点头，公式就可以放心用。本节的阴性对照正好卡在第二句上：2AX 也能写成某个内积，但那是另一个函数的微分——它对应的是 tr(Xᵀ A_sym X) 中把 A 强行对称化后的版本，而不是原题。微分形式对不上，就是最本质的「不对」。

8.20 留给下一册的伏笔

矩阵微分是深度学习分册的直接入口：那里第一章就会把本节的全连接层梯度推广到任意维度的张量，用 autograd 把 g_s xᵀ 与 Wᵀ g_s 这类式子机械化。你现在手推过一遍，将来看到框架在反向图里插入的转置节点，就能立刻判断它属于哪一种翻译。若将来要读优化器源码，本节关于步长与梯度的分工也会派上用场——自适应优化器改变的只是更新量的尺度，不改变这里算出的梯度方向。

小结这一节的要点
  • Frobenius 内积 <A,B>=tr(AᵀB) 定义矩阵梯度：f(X+dX) ≈ f(X)+<∇f,dX>，梯度与 X 同形；
  • ∇_X tr(AX)=Aᵀ：把 tr(A dX) 改写成 <Aᵀ,dX>；
  • ∇_X tr(XᵀAX)=(A+Aᵀ)X：A 出现两次，贡献 AX 与 AᵀX，非对称时必须保留两份；
  • 本例四个梯度是 (2.75, −3.6, 9.25, 4.3)，中心差分逐项相符；
  • GRAD_BUG 把 (A+Aᵀ)X 换成 2AX，四个解析值变成 (5.0, −2.4, 8.5, 5.8)，对拍失败；
  • 方形矩阵上漏转置不改变形状，编译器抓不住；阴性对照验证的是检查器本身；
  • ∇_x ‖Wx−y‖² = 2Wᵀ(Wx−y)、∇_W = 2rxᵀ 里的转置来自「把微分改写成内积」的翻译步骤。

注自测题答案
  1. 定义是 f(X+dX) ≈ f(X)+<∇f,dX>，其中 <G,dX>=tr(GᵀdX)=Σᵢⱼ G_ij dX_ij。要让这个式子对任意 dX 成立，G 的第 i 行第 j 列必须等于 ∂f/∂X_ij，所以 G 与 X 同形。
  2. <G,dX>=tr(GᵀdX)，与 df=tr(A dX) 对照得 Gᵀ=A，故 G=Aᵀ。分量式：tr(AX)=ΣᵢΣⱼ A_ij X_ji，对 X_ji 的偏导是 A_ij，即第 j 行第 i 列等于 A 的第 i 行第 j 列，正是 A 的转置。
  3. A+Aᵀ=[[4,0.5],[0.5,6]]，乘以 X 得 (2.75, −3.6, 9.25, 4.3)。若 A 对称，则 A+Aᵀ=2A，阴性对照的 2AX 与正解相同，错梯度也通过对拍，检查器失去判别力。
  4. 变成 (5.0, −2.4, 8.5, 5.8)。A 是方阵，A 与 Aᵀ 形状相同，正解与错解都是 2×2，编译器和运行时都没有任何维度提示；只能靠与中心差分对拍发现。
  5. 2rᵀ(W dx) = (2Wᵀr)ᵀ dx = <2Wᵀr, dx>。转置出现在「把 rᵀW 改写成某个向量转置」这一步：要让内积的第二项是 dx，第一项必须是 2Wᵀr 的转置。
  6. 三条分别防三种漏网：行数不够是演示不完整；全零梯度可能让逐项差值 trivially 落在容差内；只查非零组数又会放过乱写数值的程序。三条合起来才证明梯度真被正确算过。
  7. 说明阴性对照的有效性取决于实验条件。对称矩阵让「漏转置」变得无差别，检查器看不出错；这与把解析梯度抄成数值梯度属于同一类「零证据通过」，闸门用 gradient_harness_not_discriminating 拦下。
