5.1 先看工程长什么样

这一单元进入 ch02 的最后一节。前四节分别把偏导、梯度、Jacobian、Hessian 的形状钉死了，现在要回答的问题是：当函数是一层套一层拼起来的时候，这些导数怎么拼起来？答案就是链式法则，而它在深度学习里的名字叫反向传播。两者不是两件事——反向传播就是把链式法则按计算图的拓扑序倒着执行一遍，顺便把每一层的 Jacobian 转置乘到上游梯度上。

本节的工程落在 ch02 下，和前面的数值例子并列。它仍然坚持同一套纪律：一个头文件声明问题与四个函数，一个源文件实现解析梯度与中心差分，main.c 只负责把数字打到屏幕上，清单负责真编译真跑并对账。共用库 common/ 不改动，打印向量继续走 mc_print_vec，所以 stdout 里会出现 p:[...] 这样的冒号行。

第 1 帧列出 ch02 里已有的两个例子：Jacobian 与 Hessian 的数值探针。第 2 帧新增 chain_rule/，四份文件各司其职：chain.h 把问题写死为「两个参数构成内层、两个参数构成外层」的标量复合；chain.c 给出解析梯度与中心差分两条独立路线；main.c 打印四个参数的梯度表；mc05-chain.json 声明 mode=gradient，并给了一份故意写错的阴性对照开关。注意共用库没有出现在新增列表里——它从第 1 单元起就一直待在 examples/common/，这一节只是通过 -I../../common/include 和源文件列表继续用它。

大白话先用一句话把这一节讲完

复合函数的导数是「逐层敏感度相乘」。输入动一点点，先被内层放大或缩小若干倍，再被外层放大或缩小若干倍；总的放大倍数就是这些倍数的乘积。反向传播做的事情，是从最外面的损失开始，一层一层把这个「放大倍数」乘回去，乘到每个参数头上。所谓「梯度」，就是每个参数对最终损失的放大倍数。

5.2 单变量链式法则：两个导数为什么要相乘

先看最简单的情形。设 z = g(x)、L = f(z)，于是 L = f(g(x))。把 x 轻轻推动 Δx，内层先把 z 推动 Δz ≈ g′(x)Δx，外层再把 z 的这点变化变成损失变化 ΔL ≈ f′(z)Δz。把两式接起来：

ΔL ≈ f′(z) · g′(x) · Δx

两边除以 Δx 再令它趋于零，得到 dL/dx = f′(z)·g′(x)。这就是链式法则的全部来源：两个一阶近似的复合，斜率乘起来。它不是谁规定的运算法则，而是「微小变化按倍数传递」这件事的直接后果。

这个视角马上解释了一个常见疑问：为什么复合函数求导不是「分别求导再相加」？因为加法对应的是两条并列路径的贡献，而这里是一条串联路径。串联路径上放大倍数相乘，并联路径上才相加。计算图里一个节点被多条路径到达时，梯度确实要相加——那是并联；一条路径穿过许多层时，梯度要连乘——那是串联。反向传播同时用到这两条规则。

用一个纯数字例子感受「敏感度相乘」。取 g(x) = 0.5x²，在 x = 3 处 g′(3) = 3，意思是 x 增加 0.001，z 大约增加 0.003。再取 f(z) = 2z + 1，f′(z) = 2 处处成立，意思是 z 增加 0.003，L 大约增加 0.006。于是 dL/dx = 2×3 = 6。直接把复合函数写出来验证：L(x) = 2(0.5x²)+1 = x²+1，导数是 2x，在 x=3 处正好是 6。两条路给出同一个数，但它们的信息量不同：直接展开能给出答案，链式法则还告诉你中间那一层把信号放大了三倍、外层又放大了两倍——这个信息在深层网络里是诊断梯度消失/爆炸的关键。

工程惯例为什么「先展开再求导」在深度学习里行不通

上面这个两层例子手算展开很容易，但真实网络有几十上百层，每层还有矩阵乘法和非线性激活。把整个网络展开成一个关于全部参数的巨大多项式再去求导，表达式长度会爆炸，根本写不出来。链式法则允许我们只保存每层的局部导数，反向时再把它们乘起来。自动微分框架正是在做这件事：前向时记下每一层的局部 Jacobian（或者足够重算它的中间量），反向时按拓扑逆序逐层乘上去。「展开再求导」在数学上等价，在计算上不可行。

链式法则还有一层误差传播的含义。如果 x 的测量本身带噪声 δx，经过 g 后噪声约变成 g′(x)δx，再经过 f 变成 f′(z)g′(x)δx。也就是说，导数绝对值大的地方，输入误差被放大得厉害。数值微分里选择扰动量 eps 时要考虑舍入误差被 1/(2eps) 放大，本质上也是同一件事：除法是一个放大倍数为 1/(2eps) 的层。

5.3 多变量链式法则：转置从形状对齐而来

当输入和输出都不再是标量，链式法则要写成矩阵形式。设内层是 y = g(x) ∈ Rᵐ，外层是 L = f(y) ∈ R，那么内层的 Jacobian J = ∂y/∂x 是 m×n（行对应 y 的分量，列对应 x 的分量），外层对 y 的梯度 ∂L/∂y 是 m 维。按链式法则：

∂L/∂x_j = Σ_i (∂L/∂y_i) · (∂y_i/∂x_j)

这个求和式里的 i 是输出下标。把它写成矩阵乘法，就是 Jᵀ · (∂L/∂y)：Jᵀ 是 n×m，乘 m 维向量得 n 维，正好和 x 同形。转置不是为了好看，而是因为 Jacobian 的行是输出、梯度却是列向量，只有转置之后才能把「对输出求和」这件事写成标准矩阵乘向量。

第 1 帧是前向：四个参数通过两条内层路径合成 z，再被外层压成标量 L。第 2 帧里，梯度从标量变成了一个数 dz——因为这里内层输出也是标量。第 3 帧才真正体现转置：dz 要分别乘上 ∂z/∂p_k 才能得到四个参数的梯度，这一组敏感度排成向量就是内层 Jacobian 的转置乘上游梯度。如果内层输出是 m 维，第 3 帧里的 Jᵀ 就是 n×m 矩阵，转置的必要性会更直观。

陷阱标量内层输出会让转置「看起来没必要」

本例的内层输出 z 是一个数，它的 Jacobian 是一行（或一列，取约定），转置前后形状很像，初学者容易以为「直接乘就行」。但请盯住分量式：第 k 个参数的梯度是 dz × ∂z/∂p_k，这里的 ∂z/∂p_k 必须放在和 p_k 对应的位置。一旦内层输出变成向量、参数变成矩阵，不转置就会把「对哪个输出求和」和「对哪个参数求偏导」两个下标对调，数值全错而形状完全合法。第 8 单元里那个「漏掉 Aᵀ 一半」的阴性对照，正是这一类错误在矩阵上的版本。

把这条规则记成一句可操作的话：反向传播时，每经过一个局部映射，都把它 Jacobian 的转置乘到上游梯度上；遇到分叉就把几条路径的梯度加起来。 这句话覆盖了从两层标量网络到 Transformer 的全部反向实现，区别只在 Jacobian 的具体内容和稀疏程度。

5.4 计算图、拓扑序与梯度累积

计算图是把一次前向计算拆成节点和边的有向无环图。节点是中间量（标量、向量、矩阵都算），边是「这个节点的计算用了那个节点」。前向计算必须按拓扑序进行：一个节点的所有输入都算完了，才能算它。反向传播则按拓扑序的逆序进行：一个节点的所有消费者都把梯度送回来了，才能继续往它的输入传。

为什么必须逆序？因为一个节点的梯度等于「所有消费者传回的梯度之和」。如果某个消费者还没算完，你手里的梯度就不完整。这个「先汇总再传播」的要求，正是逆拓扑序的另一种说法。

第 1 帧里 main() 只是发起请求，第 2 帧显示解析梯度必须先调用 cr_inner() 拿到 z，第 3 帧才把四个梯度槽填满。这个调用顺序就是前向拓扑序在函数层面的投影。注意第 3 帧把 z=0.525 写在返回边上——这是前向计算出的中间量，反向时每一步都要用到它。自动微分框架不会真的「重算」 z 的正确值，它只是把前向保存的 z 取出来用。

第 2 帧是真正写入后的样子。请注意 grad[0] 与 grad[1] 虽然共用同一个上游因子 dz = 1.76，但乘的内层敏感度不同：一个是 x = 1.5，一个是 x² = 2.25。「忘记乘内层导数」这个错误，恰好就是把这两行都写成 dz。 它不会让程序崩溃，也不会让维度报错，只会让两个数字从 2.64、3.96 变成 1.76、1.76——这正是下一节阴性对照要抓的东西。

工程惯例梯度累积与「覆盖」的区别

如果计算图里同一条支路被用了两次，比如 L = z² + z，那么 z 的梯度来自两股：2z 和 1。实现时必须写成 g_z += 2z; g_z += 1，不能写 g_z = ... 覆盖。本例里四个参数各只被用一次，所以代码里直接赋值没问题；但一旦模型里出现权重共享（比如 Transformer 里同一个 embedding 矩阵既做输入映射又做输出映射），梯度累积就是必须的。漏掉累加的表现是「梯度比正确值小」，而且模型照常训练、loss 照常下降，只是学得不对——这类静默错误只能靠对拍发现。

5.5 本例的两层复合：四个梯度逐项手算

现在把本例的问题写清楚。输入 x = 1.5 固定，四个参数 p = (0.8, -0.3, 1.2, 0.5)：

  • 内层：z = p₀x + p₁x² = 0.8×1.5 + (-0.3)×2.25 = 1.2 - 0.675 = 0.525
  • 外层：L = p₂z² + p₃z = 1.2×0.275625 + 0.5×0.525 = 0.59325

要求的是 ∂L/∂p₀ … ∂L/∂p₃。按链式法则，前两个参数通过 z 影响 L，后两个参数直接出现在 L 里，所以分两组算。

外层对 z 的敏感度：dz = ∂L/∂z = 2p₂z + p₃ = 2×1.2×0.525 + 0.5 = 1.76。这是整条反向路径上的「上游梯度」。

内层对 p₀ 的敏感度：∂z/∂p₀ = x = 1.5，于是 ∂L/∂p₀ = 1.76×1.5 = 2.64。 内层对 p₁ 的敏感度：∂z/∂p₁ = x² = 2.25，于是 ∂L/∂p₁ = 1.76×2.25 = 3.96。 外层直接给出：∂L/∂p₂ = z² = 0.275625，∂L/∂p₃ = z = 0.525。

四个数合起来是 (2.64, 3.96, 0.275625, 0.525)，全部非零。清单要求 min_nonzero: 2，这里远超门槛；稍后你会看到，正是这些非零分量让阴性对照无处藏身。

下面是解析梯度的源码。dz 就是上游因子，第 16、17 行把它分别乘上 x 与 x²；第 18、19 行是外层直接给出的两项。第 20–24 行的 #ifdef 是阴性对照开关，正常编译时这几行不存在。

把源码里的表达式对照上面的手算：dz * q->x 是 1.76×1.5，dz * q->x * q->x 是 1.76×2.25。注意这里写的是连乘而不是 x*x 先算，浮点上两者相同，因为都是精确的二进制小数或乘法可交换；换成更一般的小数时，求和顺序可能影响最后一位，这正是容差存在的原因。

实验记录换一个 x 会怎样

把 main.c 里的 q.x = 1.5 改成 2.0，其它不动。此时 z = 0.8×2 - 0.3×4 = 1.6-1.2 = 0.4，dz = 2×1.2×0.4+0.5 = 1.46，四个梯度变成 (2.92, 5.84, 0.16, 0.4)。注意 p₀ 与 p₁ 的梯度比例始终是 1 : x——因为它们的区别只在内层敏感度 x 与 x²。这个比例关系是检查链式法则有没有写对的快速方法：如果你改动 x 后发现这个比例不再是 1 : x，十有八九是内层导数漏了或写错了。改完记得同步改正文与输出块，否则闸门会报 stale_output。

5.6 中心差分：明显正确的暴力版

现在走另一条完全独立的路。中心差分不懂什么是链式法则，也不关心 z 和 dz；它只把第 k 个参数加 eps 算一次损失、减 eps 再算一次，斜率 (L₊-L₋)/(2eps) 就是导数的近似。这段实现里没有任何复合函数求导的公式，所以它「明显正确」，正适合当裁判。

第 30 行复制了整个问题结构，后面所有拧旋钮的动作都落在副本 t 上，原始问题 q 一点不被污染。这一点很关键：如果直接在 q 上改，算完 p₀ 的梯度后 p₀ 没被复原，后面 p₁ 的梯度就会在错误的基准点上计算，整张表连锁出错。第 36、38 行分别往正方向和负方向拧，第 41 行取中心差分公式。

为什么用中心差分而不是单侧差分？因为单侧差分 (L₊-L)/eps 的一阶截断误差是 O(eps)，中心差分是 O(eps²)。取 eps = 1e-5 时，前者误差约 1e-5 量级，已经和我们的对拍容差 atol=1e-5 同一数量级；后者误差约 1e-10，被舍入误差盖住之前基本可以忽略。反过来，eps 也不能无限小——两个几乎相等的浮点数相减会发生灾难性抵消，(L₊-L₋) 的有效位数随 eps 变小而急剧减少，除以 2eps 后又把这点噪声放大。双精度下的甜点区间在 1e-5 到 1e-6 附近。

实验记录把中心差分的 eps 改成 1e-15 试试

5.7 阴性对照：为什么这套检查必须有

清单里有一行 negative_flags: ["-DGRAD_BUG=1"]。闸门拿这组参数再编译一份程序，跑出第二张梯度表；如果这张错表也通过对拍，闸门报 gradient_harness_not_discriminating——意思是这套检查不判别，等于零证据。

先打开开关看看错在哪。第 20–24 行的 #ifdef GRAD_BUG 把 grad[0] 和 grad[1] 改写成了 dz，也就是漏乘了内层导数 x 与 x²。正数版本这两行是 2.64 与 3.96，阴性对照变成 1.76 与 1.76；数值梯度那一路完全不受影响，还是 2.64 与 3.96。于是两个差值分别是 0.88 与 2.2，远大于 atol=1e-5，阴性对照被判失败——这正是我们要的结果。

为什么必须主动制造一次失败？因为「对拍通过」这件事本身太容易被骗。设想三种偷懒的实现：第一种，把 cr_analytic_grad 整个换成「直接调用 cr_numerical_grad」，两列当然逐项相等；第二种，把四行都打成 0，如果数值梯度恰好也接近 0 就可能蒙混过关；第三种最隐蔽——就是本节这种漏乘一个链式因子的错，维度对、符号对、数量级看着也合理。如果没有阴性对照，你根本不知道闸门有没有能力抓住这些错。阴性对照验证的不是被测程序，而是检查器本身。

这和深度学习里做 gradcheck 的纪律完全一致。自定义算子接入框架时要过 gradcheck，手写反向 CUDA 核的人尤其重视，因为最容易漏的就是一个链式因子或一个转置。写个单元测试很容易，写个「真的能抓住 bug」的单元测试才难。下面的对照表把三种情形放在一起看：

有人喜欢在 main.c 里自己比对两列数字，然后打印一句 PASS。闸门完全不看这句话——它从 stdout 里重新解析梯度表，自己重算差值。原因很简单：如果写梯度的人能顺便写一句 PASS，他也能让程序在错误时照样打印 PASS。证据必须由独立于被测代码的一方产生，这是所有闸门设计的基本原则。本节的阴性对照把这条原则又推进了一步：不仅证据要独立产生，检查器本身还要接受一次「故意出错必须被抓」的演练。

工程惯例把阴性对照做成一种工作习惯

任何「自动检查」都该问一句：如果我故意把被检查的东西弄坏，检查器会不会报警？编译器的 -Werror 可以拿一个真警告试；单元测试可以临时改一个断言的期望值；训练收敛判定可以喂一张硬编码的 loss 表。能报警的说明检查有效，不能报警的就是零证据通过。这条纪律比任何具体工具都值钱，因为工具会换，而「检查器也要被检查」这件事永远成立。

5.8 梯度消失、爆炸与 Jacobian 谱半径

把链式法则用到深层网络，反向传播的梯度大致是 J₁ᵀ J₂ᵀ … J_Lᵀ · ∇f 这样一串矩阵连乘。矩阵的连乘和标量连乘有一个共同点：每一层的增益如果大于 1，连乘几十次就会指数级放大；如果小于 1，就会指数级衰减。这就是梯度爆炸与梯度消失。

在标量情形下，增益就是导数本身。在矩阵情形下，决定「一个向量被拉长还是压短」的是矩阵的奇异值，谱半径（最大奇异值的模）给出最坏情况下的增益。如果每层的权重矩阵谱半径明显大于 1，梯度反向传播时会被一次次拉长，几十层后变成天文数字，参数更新一步就把模型炸掉；如果明显小于 1，梯度衰减到几乎为零，靠近输入的层几乎学不到东西。

大白话这正是为什么初始化要除以根号 n

权重初始化不是玄学。假设一层有 n 个输入，权重元素取自方差为 σ² 的分布，那么这一层输出的方差大约是 nσ²。要让前向信号的方差保持在 1 附近，就要取 σ² = 1/n——这就是 Xavier 初始化。若激活函数换成 ReLU，大约一半神经元输出为零，方差再减半，于是 He 初始化取 σ² = 2/n。从本节的角度看，这些做法的目标是让每层 Jacobian 的典型增益落在 1 附近，不让本节推导出的那一串转置 Jacobian 把信号捏死或撑爆。

除了初始化，还有三种常见对策。第一，梯度裁剪：发现梯度范数超过阈值就整体缩放，直接压住爆炸，训练大模型时几乎必备。第二，归一化层：BatchNorm / LayerNorm 把中间激活的尺度拉回可控范围，间接稳定了每层的 Jacobian。第三，残差连接：把 y = F(x) 改成 y = x + F(x)，于是 Jacobian 变成 I + ∂F/∂x，即使 ∂F/∂x 很小，恒等项 I 也保证梯度有一条直达通路。Transformer 里残差连接无处不在，理由正在于此。

反过来说，梯度消失也不总是坏事。在强化学习的时间差分里，折扣因子 γ < 1 本质上就是故意让远处的奖励梯度按 γ^t 衰减——这里的「消失」是建模选择，不是 bug。关键是你得知道增益从哪来、是不是你想要的。学完这一节，再看到某个层的反向实现里冒出一个 .T，别把它当样板代码跳过：它多半正在履行本节推导的职责，把 Jacobian 的行列约定翻译回同形梯度。

5.9 常见错误清单

第一，把「链式相乘」写成「链式相加」。判断方法：一条串联路径用乘，分叉汇合用加。写反了数值会差出几个数量级，而且形状通常不报错。

第二，漏乘内层导数。本节的 GRAD_BUG 就是这个错误的样板。它在内层是线性函数时尤其危险，因为「乘常数」看起来像多余的步骤，有人会顺手省掉。

第三，该累积梯度时用了覆盖。权重共享、循环网络的时间展开都会遇到。症状是梯度偏小、训练缓慢，很难从 loss 曲线上直接看出来。

第四，把 Jacobian 的行列约定搞混。记住一行话：Jacobian 行是输出、列是输入；梯度要同形，所以反向时乘的是转置。第 8 单元会用矩阵微分把这件事再讲一遍。

第五，中心差分步长选得极端。太小被舍入淹没，太大截断误差冒头。平方函数下中心差分几乎精确，换成含 exp、tanh 的复合函数，误差会明显变大，此时容差要适当放宽。

第六，只跑正例不跑阴性对照。这等于只做了一半体检，具体风险已经在 5.7 讲透。

5.10 自动微分的两种模式：为什么深度学习选反向

链式法则既可以顺着算，也可以倒着算，这对应自动微分的两种模式。前向模式沿着输入方向累积导数：给每个变量附带一个「对某个输入变量的导数」，每做一步运算就同步更新这个导数。它算的是 Jacobian 与一个向量的乘积 Jv，成本大约是前向计算的一到三倍。反向模式则先跑一遍完整前向，把中间量记下来，再从标量输出倒着累积敏感度；它算的是向量与 Jacobian 的乘积 vᵀJ，成本大约是前向计算的两到四倍，与输入维度几乎无关。

这个成本差异决定了深度学习的取舍。设输入是上亿个参数、输出是一个标量损失：前向模式要对每个参数单独跑一遍，成本随参数个数线性增长；反向模式只需要一次前向加一次反向，成本与一次前向同阶。训练之所以可行，靠的就是反向模式把「对上亿个参数求导」的成本压到了「做一次前向」的量级。 本节那个只有四个参数的小例子看不出这个差别，但机制完全一样：cr_analytic_grad 先算一次 z（前向），再从 dz 倒着把四个梯度填出来（反向）。

大白话tape 就是计算图的流水账

主流框架的自动微分实现常被叫作「记录磁带」（tape）。前向时，每做一次运算就往磁带上写一条：「这个结果由那两个输入经这个操作得到」。反向时从磁带尾部往前读，每读一条就调用该操作对应的局部求导规则，把上游梯度乘上去并累加到输入上。这条磁带就是本节 calltree 图元的工业化版本：节点是中间量，边是运算，反向遍历就是逆拓扑序。理解了磁带，你就知道为什么框架的反向实现里到处是 transpose——每一条运算记录的求导规则都在履行链式法则，而涉及矩阵的规则几乎都带转置。

反向模式也不是没有代价。它必须保存前向的中间量，内存占用随层数增长，这就是为什么训练大模型时显存比算力更早成为瓶颈。梯度检查点（checkpointing）技术用「存少数几个锚点、其余反向时重算」的办法，用时间换空间：把 O(L) 的内存降到 O(√L)，代价是多做大约一次前向。这个折中能在大模型训练里成立，前提仍然是链式法则保证「重算出来的中间量与原来一致」。

工程惯例什么时候前向模式反而更合适

如果输出维度远大于输入维度，前向模式更省。比如求一批向量对少数参数的 Jacobian，或者计算 Hessian-vector product 时嵌套一层前向模式，都会用到前向模式。实际框架里两种模式常常混用：先反向求外层梯度，再在前向模式里对这个梯度求导，得到 Hessian-vector product。本册第 4 单元讲 Hessian 时提到「深度网络一般不用完整 Hessian」，理由就是 n 个参数的 Hessian 有 n² 个元素；但 Hessian-vector product 只要两次反向或反向加前向，成本与一次梯度同阶——这正是链式法则可以嵌套使用的直接后果。

5.11 从梯度到更新：这一节和下一节的接缝

算出梯度之后干什么？最朴素的用法是往负梯度方向走一小步：p ← p - lr · ∇L。这里 lr 是学习率，控制步长。把它和本节的数字接起来看：p₀ 的梯度是 2.64，若取 lr = 0.1，一步就减去 0.264，相当于参数 0.8 的三分之一；p₁ 的梯度 3.96 更大，一步减去 0.396，比参数本身 -0.3 还大。这个步长明显过猛，一步就可能越过极小点，让损失反弹。下一单元会在一个二次碗上把这件事讲透：学习率多大算合适，取决于损失曲面的曲率，而不只是「感觉」。

本节的 dz = 1.76 还说明另一件事：同一个上游因子对不同参数的影响可以差很多，因为它乘的内层敏感度不同。优化器里的自适应学习率方法（AdaGrad、RMSProp、Adam）正是在利用这个差异：梯度历史大的参数把步长调小，梯度历史小的调大，让不同尺度的参数都能稳定前进。这些方法不改梯度本身，只改每个坐标的有效步长；所以本节把梯度算对，是它们能发挥作用的前提。

实验记录手算一步更新，看看损失会怎样

拿本节的数字试一步：更新前 p = (0.8, -0.3, 1.2, 0.5)，损失 L = 0.59325。取 lr = 0.01，按 p_k ← p_k - lr·grad_k 更新：p₀ 变成 0.8-0.0264=0.7736，p₁ 变成 -0.3-0.0396=-0.3396，p₂ 变成 1.2-0.00275625=1.19724375，p₃ 变成 0.5-0.00525=0.49475。代回原来的公式重算 z 与 L，你会发现损失确实变小了。再把 lr 改成 0.5 试一次，损失大概率反弹甚至变成更大的数。这个手算实验把「梯度给出方向、学习率决定走多远」这件事从口号变成了可验证的数字，下一单元会把它变成一条可闸门对账的 loss 轨迹。

5.12 手算、公式与代码：三种语言要对上

这一节反复在三种语言之间切换：数学符号写 ∂L/∂p₁ = (∂L/∂z)(∂z/∂p₁)，分量计算写 1.76×2.25 = 3.96，C 代码写 grad[1] = dz * q->x * q->x。学习数值方法的一个重要能力，就是随时能把这三句话互相翻译，并发现它们之间的不一致。初学者最容易卡在「公式看懂了，代码也能编译，但不知道对不对」；对拍提供的正是把三件事钉在一起的钉子。

翻译时要特别留意下标。公式里的 p₁ 和代码数组里的 p[1] 是同一个东西，但 C 数组从 0 开始，所以 p₀ 对应 p[0]。本例的内层用了 p[0] 与 p[1]，外层用了 p[2] 与 p[3]；如果把外层的下标顺手写成 p[1] 与 p[2]，程序照样编译运行，梯度表会出现一组错位的值，而对拍立刻失败。下标错位是手写反向实现里最常见的一类错误，它的隐蔽程度和「漏转置」不相上下。

再看打印精度。代码用 %.7f 输出梯度，七位小数足以让 1e-5 的容差判定稳定：解析值与数值值如果只差在第八位以后，打印出来两列完全相同；如果真的算错了，差值通常会大到小数点后第三四位，atol=1e-5 一眼就能抓住。打印位数不是越多越好——打印到十几位小数只会暴露浮点实现的最后几位噪声，反而让人误以为结果不可靠。容差决定你需要看几位有效数字，打印格式应该服务于这个目的。
