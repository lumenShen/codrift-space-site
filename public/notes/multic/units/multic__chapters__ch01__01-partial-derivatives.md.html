1.1 先看工程长什么样

多元微积分分册不装科学计算库，先用 C 把最小的一套数值微分原语写出来。理由和线性代数分册一样：这一册要证明的不是「会不会调自动微分框架」，而是每个导数从哪来、对不对。共用库 common/ 已经把中心差分、数值梯度、Hessian 这些原语写好了，每个新例子只要提供「目标函数 + 解析导数」，再让两者对拍。

大白话先建立一个画面

一元函数 f(x) 的图像是一条曲线，导数是曲线在某点的切线斜率。二元函数 f(x,y) 的图像是一张曲面，这时候「斜率」不再只有一个数——你得先说清沿哪个方向走。偏导数把问题拆开：固定 y 不动，只让 x 变，得到的是沿 x 方向的斜率；固定 x 不动，只让 y 变，得到的是沿 y 方向的斜率。两个斜率合起来，就是这张曲面在该点最基础的「坡度信息」。

第 1 帧是动笔前的形态：examples/ 下只有 common/ 共用库，chapters/ch01/ 还是空目录。第 2 帧长出 partial_probe/：三个源文件加一个清单。共用库一个字都不改——这是整册的纪律，所有单元都从它取数值微分原语。头文件 partial.h 声明目标函数与两个解析偏导，partial.c 是它们的值现，main.c 驱动打印，mc01-partial.json 声明用 mode=gradient 做对拍。

工程惯例为什么把声明放进头文件

partial.h 只放函数声明，partial.c 只放实现，main.c 只管选点、打印。三者分开的代价是要多写几行 #include，换来的是「接缝可见」：读头文件就知道这个例子会什么——能算 f、能算两个解析偏导；实现换了算法不影响驱动。下一单元换 steepest/ 时，也是同一套结构，只是目标函数换了。这种分家从第二个工程起就是硬要求，不是风格偏好。

1.2 偏导的定义：固定一个变量切一刀

一元导数 f'(a) = lim (f(a+h)−f(a))/h 的核心是「让自变量动一点点，看函数值变多少」。二元函数多了一个变量，偏导数把这个「一点点」限制在单个坐标轴上。

定义写清楚：在 (x₀,y₀) 处，对 x 的偏导是

∂f/∂x (x₀,y₀) = lim_{h→0} (f(x₀+h, y₀) − f(x₀, y₀)) / h

注意第二项里 y 始终是 y₀，一点没动。对 y 的偏导完全对称：把 x 钉死在 x₀，只让 y 动。这两个式子就是「固定其他变量」的全部含义——它不是偷懒，而是把一个二维的变化问题拆成两个一维问题，每个都能套用你已经会的一元导数。

拿本节的目标函数练手：f(x,y) = x²y + sin(x) + y³。

  • 对 x 求偏导时把 y 当常数：x²y 的导数是 2xy，sin(x) 的导数是 cos(x)，y³ 与 x 无关，导数是 0。所以 ∂f/∂x = 2xy + cos(x)。
  • 对 y 求偏导时把 x 当常数：x²y 的导数是 x²，sin(x) 与 y 无关，导数是 0，y³ 的导数是 3y²。所以 ∂f/∂y = x² + 3y²。
大白话把「常数」这两个字读对

「把 y 当常数」不是把 y 变成数字 2 或 3，而是在求导这一刻，把 y 看作不会随 x 变化的量。所以 x²y 对 x 求导得像 2y·x，而不是 2xy + x²。你可以想象成：你正拿一支笔沿 x 方向在曲面上画一条线，y 坐标锁死，这条线的高度只由 x 决定，于是你用的还是一元求导那套。锁死的 y 取多少，决定了你画的是哪一条线，也决定了斜率数值——所以偏导是「点」的函数，不只是一个公式。

第 1 帧先把观察点钉在 (1,2)：这里 f=1·2+sin(1)+8≈9.841471。第 2 帧把 y 锁在 2，曲面被平面 y=2 截成一条曲线 f(x,2)=2x²+sin(x)+8——它已经是一元函数了。第 3 帧在这条曲线上找切线斜率：4x+cos(x) 在 x=1 处是 4+cos(1)≈4.540302，正是 ∂f/∂x 在 (1,2) 的值。换一个 y 锁，就换一条截面曲线、换一个斜率——这就是偏导依赖位置的原因。

陷阱把「偏导存在」和「函数连续」混为一谈

你会觉得：两个方向的偏导都算出来了，函数在这点应该挺平滑。你会据此推断「偏导存在 ⇒ 函数连续」。真相不是这样。一元里「可导 ⇒ 连续」成立，但二元里「两个偏导存在」只保证沿坐标轴两个方向变化良好，完全不管斜着靠近时会发生什么。经典反例是 f(x,y)=xy/(x²+y²)（原点补 0）：沿 x 轴和 y 轴偏导都是 0，可沿直线 y=x 靠近时函数恒等于 1/2，极限都不是 0。所以偏导存在推不出连续。反过来，若偏导在点附近连续（即 C¹），就能推出可微、推出连续。这一节点到为止，你只要记住「偏导是可微的必要不充分条件」这句结论，别把单向蕴含用反了。

1.3 等高线：把地形图压成平面图

曲面不好画，工程上更常用等高线（level set）：把所有满足 f(x,y)=c 的点连成一条线，就像地图上的海拔线。等高线把二维输入、一维输出的函数压进一张平面图，x、y 是平面坐标，f 的大小用线的标注表示。

对 f(x,y)=x²+2y²，等高线 x²+2y²=c 是一族椭圆；c 越大椭圆越大，代表函数值越高。偏导与等高线的关系非常干净：梯度（下一单元主角，分量就是两个偏导）垂直于等高线，指向函数增长最快的方向。这一节先埋个伏笔：偏导告诉你「沿轴走多快」，等高线告诉你「往哪走不变」，两者是同一张地形图的两种读法。

第 2 帧的两个点都在 f=8 这条线上，2²+2·0²=4？等等——这里要小心：x=2,y=0 时 f=4，不在 f=8 上；正确的点是 (2√2,0) 与 (0,2)，因为 2·2²=8。这个细节正好说明别凭直觉写等高线上的点，代回函数验一下。第 3 帧的箭头横穿等高线，指向函数减小的方向（朝原点），也就是负梯度方向——下一单元会把它严格化。

实验记录心算验算等高线

取 f(x,y)=x²+2y²。f=8 的椭圆上，x=2√2≈2.828, y=0 满足 8+0=8；x=0, y=2 满足 0+8=8。沿这条椭圆从一点走到另一点，函数值始终是 8，所以「沿等高线的方向导数 = 0」。若从 (2√2,0) 朝原点走到 (2,0)，函数值从 8 降到 4+0=4，变化量 −4，走过的距离约 0.828，平均下降率约 −4.83，接近该点梯度 (2x,4y)=(5.657,0) 的长度 5.657——离散步长的偏差留给你用更小的步验证。

1.4 可微：比偏导更强的一个词

偏导只回答「沿坐标轴方向的变化率」，可微回答的是「能不能用一张切平面在局部把曲面替换掉，误差是比距离更高阶的小量」。定义写作：若存在向量 g=(g₁,g₂) 使得

f(x₀+h₁, y₀+h₂) − f(x₀,y₀) = g₁h₁ + g₂h₂ + o(√(h₁²+h₂²))

就说 f 在 (x₀,y₀) 可微，g 就是梯度。这个 o(·) 是关键：它要求误差比「走的距离」缩得更快，于是切平面是曲面的良好局部近似。可微一定推出两个偏导存在，且偏导就是 g 的两个分量；但反过来不成立，原因上一节的 trap 已经给了反例。

对深度学习来说，可微是「反向传播能不能用」的门槛。我们训练时默认 loss 对参数几乎处处可微，链式法则才敢一层层乘下去。遇到 ReLU 这种在 0 点不可导的函数，工程上取次梯度（在 0 点随便选个 0 到 1 之间的值），实践能跑，但严格说那里没有唯一的切平面。本节不展开，你只要分清「偏导存在」与「可微」的强弱关系，别在推导里把必要条件当充分条件用。

陷阱分段函数的尖角处偏导可能「算出来但没用」

考虑 f(x,y)=|x|+|y|，在原点沿 x 方向的偏导涉及 |h|/h，h 从正侧和负侧靠近给出 +1 与 −1，极限不存在，所以偏导根本不存在。你会以为「绝对值处处有导数」，真相是只在 x≠0 处成立。更隐蔽的是某些函数偏导存在但不可微：沿轴导数有，斜着靠近却对不上切平面。判断办法不是死记定义，而是把 f(x₀+h₁,y₀+h₂)−f(x₀,y₀)−g₁h₁−g₂h₂ 除以距离，看它是否趋于 0。这一节不要求你证明，只要求你看到「偏导存在 ≠ 可微」时别愣住。

1.5 数值偏导：中心差分与它的两块误差

解析偏导靠代数推导，快但可能推错。数值偏导不依赖任何公式，只依赖导数定义：把第 i 个坐标加 ε 算一次函数，减 ε 再算一次，斜率取

(f(x+εeᵢ) − f(x−εeᵢ)) / (2ε)

这叫中心差分。共用库的 mc_partial 就是它：plus = x; minus = x; plus.v[i] += eps; minus.v[i] -= eps; return (f(plus)−f(minus))/(2eps);。它没有任何链式法则、乘积法则的影子，所以「明显正确」——正因为它慢而可靠，才配当裁判。

为什么用中心而不是单侧？单侧差分 (f(x+ε)−f(x))/ε 的截断误差是 O(ε)，中心差分是 O(ε²)。泰勒展开一看便知：f(x+ε)=f(x)+εf'+ε²f''/2+ε³f'''/6+…，f(x−ε)=f(x)−εf'+ε²f''/2−ε³f'''/6+…，两式相减时偶数阶项抵消，剩下 2εf' + 2ε³f'''/6 + …，除以 2ε 得 f' + ε²f'''/6 + …。误差主项是 ε² 量级，比单侧的 εf''/2 小一个数量级。

但 ε 不是越小越好。截断误差随 ε 减小而减小，舍入误差却相反：f(x+ε) 与 f(x−ε) 各自带约 u·|f| 的双精度噪声（u≈2×10⁻¹⁶），相减后除以 2ε 放大成约 u|f|/ε。ε 越小，这个放大越狠。两类误差一个随 ε 增、一个随 ε 减，最优 ε 在 (u)^{1/3} 附近，约 6×10⁻⁶，所以取 1e-5 正合适。

陷阱把 ε 取成 1e-15 会得到锯齿状乱码

你会想「ε 越小越接近导数定义」，于是把它改成 1e-15。结果梯度表全是些毫无规律的数字，你会怀疑解析公式写错了。真相是：两个几乎相同的浮点数相减，有效位数被 catastrophic cancellation 吃光，剩下的全是噪声。双精度下别把 ε 压到 1e-8 以下。想要更高精度请换复数步或自动微分，而不是硬拧 ε。这也是为什么容差 atol=1e-5 不能写成零——它是给浮点实现留的合理空间，不是「允许算错」。

工程惯例裁判不是运动员

中心差分每算一个偏导就要重新算两次函数。这一节 2 个变量，看不出成本；换成一亿个参数的网络，一次梯度就要两亿次前向，完全不可行。解析梯度（自动微分在做的事）只用一次前向加一次反向，成本与一次前向同阶。所以工程里训练绝不用数值差分，但验证反向实现是否正确时又离不开它——慢而明显正确的裁判，正是它不可替代的地方。PyTorch 的 gradcheck 就是这套流程的工业版。

1.7 阴性对照：为什么闸门必须会「抓错」

清单 mc01-partial.json 里有 negative_flags: ["-DGRAD_BUG=1"]。闸门拿这组参数再编译一份，跑出第二张偏导表；如果这张错表也通过了对拍，闸门就报 gradient_harness_not_discriminating——意思是这套检查根本不判别，等于零证据。

为什么非要这么麻烦？因为「对拍通过」太容易被骗。一个程序可以把数值偏导直接抄给解析列，于是每对都相等；也可以把四行全打成 0，在容差内也可能混过去。更隐蔽的是本节这种「忘乘一个 y」：公式看着挺合理，维度也不报错，程序照常跑。如果没有阴性对照，你根本不知道检查器有没有能力区分对与错。**阴性对照验证的是检查器本身，不只是被检查的程序。**这和深度学习里做 gradcheck 的纪律一模一样。

看阴性对照那张表错在哪：正例 d0=4.5403023，打开开关后变成 2.5403023，恰好差一个 2x=2——因为忘乘的 y=2 被丢掉了。d2 从 −0.1224174 变成 1.8775826，差了 2x·y=2·0.5·(−1)=−1 的相反数，也就是把本该减去的 1 加回来了。错误是「局部且可解释」的：只影响 ∂f/∂x 两行，∂f/∂y 两行没被碰。闸门重算每对差值，|2.5403023−4.5403023|=2，远大于 atol=1e-5，于是阴性对照被判失败——正是我们要的结果。

陷阱只跑正例会给你虚假的安全感

你会看到四行完美对齐，于是收工，心里想着「对拍通过 = 偏导正确」。真相是：正例只能证明「程序给出的两列数碰巧相等」。把 pc_dx_analytic 改成直接返回数值偏导的假实现，正例照样满分。只有把错误主动注入一次、并看到闸门把它拦下来，你才知道这台机器真的能判别。程序自报的 PASS 不算证据，阴性对照才是。

实验记录闸门到底查了几件事

清单的 expect.gradient 写了三条：atol=1e-5、min_params=4、min_nonzero=2。闸门做三件事：数对数至少 4 组；数非零解析偏导至少 2 组；每组 |analytic−numerical| ≤ 1e-5。三条缺一不可——只查「每组接近」，一个把四行全输出 0 的程序会 trivially 通过；所以还要单独数非零组。本节四个解析偏导全非零，min_nonzero=2 轻松满足。容差只写在清单里，正文写「约等于 4.54」不算证据。

1.8 把偏导接到梯度：下一单元的入口

这一节的四个偏导还不是「梯度」。梯度是把它们按顺序装进一个向量：∇f=(∂f/∂x, ∂f/∂y)。在 (1,2) 处 ∇f=(4.5403023, 13)。这个向量不只是四个数字的重新排列——它的方向有明确几何意义（等高线的法向），它的长度有明确物理意义（函数增长最快有多快）。下一单元会证明：任意单位方向 u 上的变化率等于 ∇f·u，于是 u 取 ∇f/|∇f| 时变化率最大，最大值就是 |∇f|。那正是「梯度指向最陡上升」这句话的全部内容。

第 1 帧把两个偏导分别画成两张截面图的斜率；第 2 帧把它们装进同一个向量；第 3 帧点出梯度与等高线的垂直关系。三帧各自自包含，哪怕单独打印第 3 帧也能读懂。

工程惯例为什么工程里先算偏导再谈梯度

手写反向传播时，你几乎不会显式构造 Jacobian 矩阵，而是对每个参数算出「它变一点 loss 变多少」——那就是偏导。把它们按参数顺序排好，框架里叫 gradient，数学上就是梯度向量。所以偏导是「原子操作」，梯度是「打包结果」。先把原子算对（这一节），才谈得上打包（下一节）与链式相乘（mc05）。这条路线是整册的骨架：偏导 → 梯度 → Jacobian → Hessian → 链式法则 → 矩阵微分。

1.9 这一节新增了什么

回到 1.1 的第 2 帧：partial_probe/ 多了三个源文件和一个清单。共用库没有改动，mc_partial 被直接复用。这一节真正产出的是一套可复现的对拍流程：解析偏导从公式来，数值偏导从定义来，两者在四个点上逐项比较；再用 negative_flags 注入一个具体错误，确认闸门真的会拒绝它。这套流程会在 mc05（链式法则）与 mc08（矩阵微分）里原样复用，只是解析侧换成更复杂的链式推导，注入的错误换成「漏乘内层导数」「漏转置」。

1.10 高阶偏导与混合偏导的对称性

偏导本身还是 (x,y) 的函数，所以可以再求一次导，得到二阶偏导。对 f(x,y)=x²y+sin(x)+y³，先对 x 再对 x 得到 ∂²f/∂x²=2y；先对 y 再对 y 得到 ∂²f/∂y²=6y。更有意思的是混合偏导：先对 x 后对 y 写作 ∂²f/∂y∂x，先对 y 后对 x 写作 ∂²f/∂x∂y。本例中 ∂f/∂x=2xy+cos(x)，再对 y 求导得 2x；∂f/∂y=x²+3y²，再对 x 求导也得 2x。两条路给出同一个数，这不是巧合。

大白话混偏相等其实是「换序不改变结果」

只要两个偏导在点附近连续（还是那个 C¹ 条件），先沿 x 再沿 y 与先沿 y 再沿 x 的斜率就一样。直观说法：你在一个小矩形上从一角走到对角，走「先横后竖」和「先竖后横」的总高度差相同——因为都是同一个函数的两个角点高度之差，与路径无关。把高度差除以面积，再让矩形缩到一点，得到的就是混合偏导。路径可以换序，极限值自然相同。抓住这层直觉，你就能记住结论而不是死背符号。

这条性质叫 Schwarz 定理（或克莱罗定理），它直接决定了下一章 Hessian 矩阵的对称性：H_ij = ∂²f/∂x_i∂x_j 与 H_ji 相等，于是 Hessian 是对称矩阵。深度学习里能从二阶信息省一半存储，就靠这个对称性。但要注意前提：偏导必须连续。教科书里能造出混合偏导不相等的反例，通常带分段定义和振荡项，在原点附近不连续。我们训练用的函数大多由多项式、指数、平滑激活拼成，几乎处处满足对称性，所以工程上默认 Hessian 对称是安全的。

陷阱别把「二阶偏导存在」和「混偏相等」当成一回事

你会觉得：既然 ∂²f/∂x∂y 和 ∂²f/∂y∂x 都算出来了，它们自然相等。真相是：各自存在并不保证相等，还需要偏导连续这个额外条件。经典反例 f(x,y)=xy(x²−y²)/(x²+y²)（原点补 0）在原点两个混合偏导分别是 1 与 −1。这个反例不影响你日常用多项式做练习，但它提醒一件事：定理的前提不是装饰。下次看到「Hessian 对称」这句话，记得它背后站着 Schwarz 定理和它的连续性条件，不是凭空规定。

第 1、2 帧把矩形四个角摆出来；第 3 帧点出两条路径的总高度差都是 f(x+h,y+k)−f(x,y)，除以面积 hk 后取极限，两条路给出同一个混合偏导。这个图元不依赖具体函数，说的是「换序不变」的几何原因。

1.11 把误差拆成两块：一次定量的扫 ε 实验

中心差分的误差来自两个方向，值得单独算一算，这样你以后选 ε 就不是背数字而是有依据。截断误差的主项是 ε²f'''(ξ)/6，对本节 f(x,y)=x²y+sin(x)+y³ 的对 x 偏导来说，三阶导涉及 −cos(x)，量级不超过 1，所以截断误差约 ε²/6。舍入误差约 u|f|/ε，u 取 2.2×10⁻¹⁶，本例 f 在 10 左右，所以约 2×10⁻¹⁵/ε。

把两式相等求最优 ε：ε²/6 = 2×10⁻¹⁵/ε，得 ε³≈1.2×10⁻¹⁴，ε≈2.3×10⁻⁵。这和理论值 u^{1/3}≈6×10⁻⁶ 同一数量级，解释了为什么 1e-5 是合适选择。

实验记录心算三个 ε 的误差量级

取 ε=1e-3：截断误差约 1e-6/6≈1.7×10⁻⁷，舍入误差约 2×10⁻¹²，截断占主导，会得到偏小的斜率。取 ε=1e-5：截断约 1.7×10⁻¹¹，舍入约 2×10⁻¹⁰，两者都小于打印精度，四行完美对齐（这就是真跑看到的）。取 ε=1e-12：截断几乎为零，舍入约 2×10⁻³，梯度表开始乱跳。这三个点把「U 形误差曲线」画得很清楚：中间有最小值，两头都差。

工程惯例什么时候该换更聪明的差分

若目标函数本身噪声很大（比如来自蒙特卡洛模拟），中心差分会把噪声除以 2ε 放大，这时再怎么调 ε 都救不回来。工程上的做法是改用「复数步」：把 x 换成复数 x+iε，利用解析函数的泰勒展开 f(x+iε)=f(x)+iεf'(x)−ε²f''/2+…，取虚部除以 ε 得到 f' 且没有相减，精度接近机器极限。代价是要求函数支持复数运算、且是解析的。Python 的 jax 里这类技巧叫 complex-step differentiation，和本节的有限差分是同一个目标的不同实现。知道有这条路，就不至于在 ε 上钻牛角尖。

1.12 偏导在训练循环里的真实位置

把镜头拉远一点。神经网络训练时有一个损失函数 L(w)，w 是成千上万个参数。每次迭代做一件事：w ← w − η∇L(w)。这里的 ∇L(w) 是一个向量，它的第 i 个分量正是 ∂L/∂w_i——一个偏导。所以本节算的每一个数，都是那个巨大梯度向量里的一个元素。框架的自动微分在后台做的事，本质上就是把本节「解析偏导」那套推导规则（乘积法则、链式法则）程序化，一个参数一个参数地算出来。

为什么不用数值差分训练？回到成本：一亿个参数，每个偏导要两次前向，一次梯度要两亿次前向，训练一步就跑到天亮。自动微分只用一次前向加一次反向，成本与一次前向同阶。于是形成分工：自动微分当运动员，有限差分当裁判。你在自定义算子时写的反向实现如果漏了一个因子，训练 loss 照样下降，只是下降得不对；这时 gradcheck（本节流程的工业版）用中心差分把每个偏导核对一遍，才能把错误揪出来。

陷阱「loss 在下降」不等于「梯度算对了」

你会盯着训练曲线，看到 loss 一路走低，于是认定反向实现没问题。真相是：一个漏乘了 0.5、漏转置、或者链式因子写反的梯度，往往仍然指向「大致向下」的方向，loss 照样下降，只是收敛慢一点或停在奇怪的地方。这类 bug 最隐蔽，因为它不报错、不崩溃。唯一可靠的判别手段就是拿一个明显正确的参照物（中心差分）逐个偏导对拍，就像本节四行表做的那样。把这条纪律带进你的项目：任何手写反向的代码，提交前过一遍 gradcheck。

1.13 再多算几个：偏导的手感是靠例子磨出来的

光看一个函数容易把「求偏导」记成背模板。下面多摆几个例子，每个都先说「固定谁」，再给结果，你可以拿笔算完再对照。

第一例 g(x,y)=e^{xy}。对 x 求偏导时把 y 当常数，指数 xy 对 x 的导数是 y，所以 ∂g/∂x = y·e^{xy}；对 y 求偏导同理得 x·e^{xy}。注意这里指数函数链式法则带来一个因子，漏掉它就和本节 GRAD_BUG 忘乘 y 是同一类错误。

第二例 h(x,y)=ln(x²+y²)（在原点外）。对 x：(1/(x²+y²))·2x = 2x/(x²+y²)；对 y：2y/(x²+y²)。这类「分母里有两个变量」的函数在最大似然里很常见，偏导的分母相同、分子各带自己的变量，是很典型的模式。

第三例 k(x,y)=max(x,y)。在 x>y 的区域 k=x，偏导是 (1,0)；在 y>x 的区域是 (0,1)；在 x=y 这条线上，沿两个轴的单侧导数不一致，偏导不存在。这是 ReLU 类函数在「折痕」处的缩影——主区域里偏导干净利落，折痕上要额外约定。

第四例 s(x,y)=x^y（x>0）。对 x：y·x^{y−1}（幂函数规则，y 是指数当常数）；对 y：x^y·ln(x)（指数函数规则，x 是底数当常数）。同一个表达式里两个变量扮演不同角色，正好检验你有没有真的做到「固定另一个」。

工程惯例一个五步手算流程

拿到一个多元函数要偏导时，按这个顺序走不容易错：一，圈出要对的那个变量， 其余变量全部在心里贴「常数」标签；二，把函数重写成只显含该变量的形式，例如 x²y 写成 (y)·x²；三，套一元求导规则，常数因子原样带着；四，代回数值前先检查量纲或符号是否合理；五，若时间允许，用中心差分在一点验一下。第五步是本节对拍流程的迷你版，考试里随手一算就能抓住大部分低级错误。

陷阱常数标签贴错位置的两种典型

第一种是把「对 x 求导」误做成「把 x 代入一个数」。偏导是函数，不是某个点的斜率数字；先写出含 x、y 的表达式，最后才代点。第二种是链式法则里外层求导后忘了乘内层导数，比如 sin(xy) 对 x 写成 cos(xy) 而漏了 y。正确是 y·cos(xy)。你会在神经网络反向里遇到完全同型的错误：外层 loss 对激活求导后，忘了乘激活对预激活的导数。本节 GRAD_BUG 的「忘乘 y」就是给这类错误做的一次彩排。

第 1 帧强调「先贴标签」；第 2 帧是真正的求导动作；第 3 帧把数值验算接上，呼应本节核心纪律。三帧自包含，单独打印任何一帧都读得通。

1.14 从偏导到梯度：为什么需要把数字排成向量

这一节最后再回到「打包」这件事。四个偏导 d0 到 d3 是两个点上的两个方向导数。若只做「某个参数变一点 loss 变多少」这种局部敏感度，四个标量已经够用。但一旦问「沿任意方向 (u₁,u₂) 走，函数变多快」，就需要把它们组合起来：变化率等于 u₁·∂f/∂x + u₂·∂f/∂y，正是偏导向量与方向向量的点积。这个点积形式逼着我们把偏导排成一个向量，否则每次都得临时把四个数抄出来相乘。

排成向量还有第二个好处：形状对齐。后文 Jacobian 是「输出行、输入列」的矩阵，梯度是「与输入同形」的列向量，两者之间差一个转置。倘若这一节你习惯把偏导写成散落的标量，到 mc05 推导 ∂L/∂x = Jᵀ(∂L/∂y) 时就会觉得转置凭空冒出来。现在就把 ∇f=(∂f/∂x,∂f/∂y) 当成一个正式对象来对待，后面所有转置都有出处。

大白话标量、向量、矩阵是同一件事的不同打包层级

一个偏导是一个数；把同一个点的所有偏导排起来是梯度向量；把一个向量值函数的所有输出的偏导排成表是 Jacobian 矩阵。层级不同，但底层全是「一个输入变一点，一个输出变多少」这同一句话。你在这一节算的 4.5403023 和 13，既可以是两个独立的敏感度，也可以是梯度向量的两个分量——取决于你要回答的问题有多大。 工程上常见的困惑，往往不是不会求导，而是没分清自己手里该拿标量、向量还是矩阵。

1.15 符号读法与常见写法陷阱

最后统一一下符号，免得你以后在教材和框架文档之间切换时被同一堆记号绕晕。大写弯曲的 ∂（读作「偏」）专门用于多元函数的偏导，普通 d 用于一元导数或全微分。∂f/∂x 里的分母不是分式，而是一个不可拆的整体记号；你不能把 ∂x 当成一个可以约掉的因子——尽管链式法则里它看起来很像能约。这种「像分数但不是分数」的性质，正是初学者在链式法则里反复出错的根源。

梯度记号 ∇（读作「nabla」或「梯度」）作用在标量函数上给出一个向量，本例中 ∇f=(∂f/∂x,∂f/∂y)。它作用在不同对象上含义会变：作用在向量场上给出散度或旋度，那属于矢量分析，本册不涉及。你只要在深度学习语境里记住「∇ 后面跟标量 loss，结果是与参数同形的梯度」就够了。

陷阱把 `∂L/∂W` 的行列顺序想反

损失函数 L 对矩阵参数 W 的偏导，形状与 W 相同——这是框架的约定。但数学上严格的 Jacobian 是「输出行、输入列」，标量输出对应一行。要把一行变成与 W 同形的矩阵，必须转置。这个转置在方形矩阵上不改变维度，所以编译器抓不住，只有对拍能发现。mc08 会专门讲这件事。现在先建立一个习惯：看到梯度就问「它和谁同形」，答案通常是「和它被求的那个参数同形」。

工程惯例一套自洽的记账法

手写推导时给每个量标上形状：标量是 ()，二元向量是 (2)，梯度是 (2)，Jacobian 是 (m,2)。每写一步乘法，先检查左边形状能不能和右边对上。这套习惯在偏导阶段看起来多余，到了 mc05 链式法则与 mc08 矩阵微分就会救命——那里绝大多数错误不是算术错，而是形状没对上还硬乘。把形状当第一道检查，比事后调试快得多。

小结这一节的要点
  • 偏导是「固定其他变量、沿单个坐标轴切一刀」的斜率，∂f/∂x=2xy+cos(x)、∂f/∂y=x²+3y²；
  • 中心差分 (f(x+εeᵢ)−f(x−εeᵢ))/(2ε) 是二阶精度，ε 取 1e-5 平衡截断误差与舍入误差；
  • 解析偏导与数值偏导必须逐项对拍；闸门查对数、非零组数、逐对差值三条，容差只写在清单；
  • negative_flags 注入的错误若也通过对拍，报 gradient_harness_not_discriminating，说明检查器不判别；
  • 偏导存在推不出连续，连续偏导才推出可微；梯度由偏导打包而成，垂直于等高线。

  3. f(x+ε)=f+εf'+ε²f''/2+ε³f'''/6+…，f(x−ε)=f−εf'+ε²f''/2−ε³f'''/6+…。相减时 f、ε²f''/2 这些偶次项抵消，剩 2εf'+2ε³f'''/6+…，除以 2ε 后主误差是 ε²f'''/6，故为二阶。
  4. 截断误差随 ε 减小而变小，但舍入误差约 u|f|/ε 随 ε 减小而变大；1e-14 时相减几乎全是噪声，梯度表变成锯齿状乱码，与真实导数无关。
  5. 会漏掉把全部解析偏导输出 0 的程序：此时每对差值可能都小于容差，逐对检查全绿。要求足够多组非零，才能证明梯度真的被算过，而不是被抄成零。
  6. 报 gradient_harness_not_discriminating。说明这套对拍不判别——错偏导和对偏导都放过，等于零证据。它守的不是程序，是闸门自己。
  7. 可微 ⇒ 偏导存在且连续偏导 ⇒ 可微 ⇒ 连续；但偏导存在 ⇏ 连续。反例 f(x,y)=xy/(x²+y²)（原点补 0）两个偏导都是 0 却不连续；C¹（偏导连续）的函数如多项式则处处可微且连续。
