3.1 先看工程长什么样

前两个单元的输出都是标量：一个函数值，一个 loss。这一单元第一次让输出变成多个数。F(x,y)=(x²+y, xy) 吃进两个输入，吐出两个输出。导数不再是一个向量，而是一张表——每个输出对每个输入的偏导各占一格。这张表就是 Jacobian 矩阵。

大白话一个函数突然变成两个输出，会发生什么

之前的 f(x,y) 像一台机器：两个旋钮进去，一个读数出来。梯度告诉我们每个旋钮对读数的灵敏度。现在换成 F(x,y)：还是两个旋钮，但有两个读数。每个旋钮都会同时影响两个读数，于是灵敏度从「两个数」变成「四个数」。把这四个数按「哪一行是哪个读数、哪一列是哪个旋钮」排好，得到 2×2 的 Jacobian。它不是一个全新的概念，只是把上一单元的偏导按输出再多排一维。

第 1 帧画的是动笔前的形态：examples/ch01/ 里有前两个单元的例子，examples/ch02/ 还没有内容。第 2 帧在 ch02/ 下长出 jac_probe/。注意这是第二个项目，所以按照规矩必须多文件：jac.h 声明接口、jac.c 实现解析与数值两套 Jacobian、main.c 驱动打印、清单声明 numerical 模式。共用库依旧不动，mc_partial 与 mc_print_mat 直接拿来用。

工程惯例为什么解析版与数值版同时留在代码里

和 mc01 同样的理由：解析版快但可能推错，数值版慢但明显正确。jac_analytic 写公式，jac_numerical 对每个输出、每个输入做功差分。真跑把两张矩阵并排打印，一眼就能看出是否逐格相等。这一节没有用 gradient 模式加阴性对照，是因为公式简单到几乎不会错；真正的看点是「形状对不对」——行列的约定一旦反了，数值可能对不上，也可能碰巧对上（本例恰好对称时才看不出来，3.8 节专门讲这个坑）。

3.2 向量值函数：输出从标量变成向量

标量值函数 f: Rⁿ→R 把一个向量映射成一个数。向量值函数 F: Rⁿ→Rᵐ 把一个向量映射成另一个向量，可以拆成 m 个标量分量函数：F(x)=(F₁(x), F₂(x), …, Fₘ(x))。本例 F(x,y)=(u,v)，其中 u(x,y)=x²+y，v(x,y)=xy。两个分量都是二元标量函数，求偏导的办法你已经会了。

大白话拆成标量分量，事情就简单了

遇到向量值函数别慌，它不是新物种。把它拆开看，F 的输出有两个数，每个数都是一个普通的二元函数。你上一单元会对 f(x,y) 求偏导，现在对 u 和 v 各求一遍就行了。唯一的新问题是「结果怎么摆」：两个函数各有两个偏导，一共四个数，必须约定谁放哪格。这个约定就是 Jacobian 的行列规则，也是这一节最需要记住的东西。

第 1 帧是输入 (2,3)；第 2 帧把函数拆成两支，各自算出 7 与 6；第 3 帧把结果合回向量 (7,6)。三帧各自自包含，第 3 帧仍写出两支通道作为来源。

3.3 Jacobian 的形状：行是输出，列是输入

定义：若 F: Rⁿ→Rᵐ，则其 Jacobian J 是一个 m 行 n 列的矩阵，第 i 行第 j 列的元素是 ∂Fᵢ/∂xⱼ——第 i 个输出对第 j 个输入的偏导。口诀是「行=输出，列=输入」。本例 m=2、n=2，所以 J 是 2×2：

J = [[∂u/∂x, ∂u/∂y], [∂v/∂x, ∂v/∂y]]

在 (2,3) 处：∂u/∂x=2x=4，∂u/∂y=1，∂v/∂x=y=3，∂v/∂y=x=2，于是 J=[[4,1],[3,2]]。这就是解析版要写出的四格。

陷阱把行列记反，方形矩阵上看不出来

你会觉得「反正都是 2×2，行先列后有什么区别」。真相是：本例 J=[[4,1],[3,2]]，转置后是 [[4,3],[1,2]]，两个都是合法的 2×2 矩阵，程序不会报维度错。只有当输出与输入维度不同时（比如 n=3, m=2），J 是 2×3，转置是 3×2，形状才暴露问题。所以方形情形是最危险的——你必须靠「行=输出、列=输入」这条约定主动检查，不能指望编译器。mc08 里「漏转置」在方形矩阵上隐形，是同一类陷阱。

第 1 帧把四格连同来源写出来。第 2 帧点出两种读法：按行读，得到某个输出的梯度；按列读，得到某个输入对所有输出的影响。这是理解 Jacobian 的关键——它同时编码了「每个输出对输入的敏感度」和「每个输入对输出的影响」两组信息。

大白话为什么行是输出而不是输入

这是约定，不是定理，但约定得很聪明。线性近似写成 F(x+Δx) ≈ F(x) + J·Δx。F 是 m 维向量，Δx 是 n 维向量，矩阵乘向量要得到 m 维结果，J 必须是 m×n——也就是行对应输出。若反过来定义成 n×m，每次写线性近似都得转置，反而累赘。所以「行=输出」是让公式最省事的约定，记住这个理由比死背口诀牢。

3.4 线性近似：Jacobian 是最佳的局部线性映射

一元函数可导意味着「局部像直线」，多元函数可微意味着「局部像一张平面（线性映射）」。Jacobian 就是这张平面的系数矩阵。具体地，在 p 附近：

F(p+Δx) ≈ F(p) + J(p)·Δx

误差是 o(‖Δx‖)。这意味着：如果你在 p 附近挪动一小步 Δx，输出的变化可以先用矩阵乘法 J·Δx 算出来，剩下的误差比步长更小。Jacobian 是「在 p 处最贴合 F 的线性映射」。

拿本例验一下。在 p=(2,3) 处 F(p)=(7,6)，J=[[4,1],[3,2]]。往 x 正方向挪 0.01，Δx=(0.01,0)，线性近似预测 ΔF≈J·Δx=(0.04,0.03)，于是 F≈(7.04,6.03)。真值：u=2.01²+3=4.0401+3=7.0401，v=2.01×3=6.03，即 (7.0401,6.03)。误差 (0.0001,0)，确实是步长 0.01 的平方量级——这正是 o(‖Δx‖) 的味道。

实验记录自己再算一个斜向的步

取 Δx=(0.01,0.02)，线性预测 ΔF=(4×0.01+1×0.02, 3×0.01+2×0.02)=(0.06,0.07)，预测点 (7.06,6.07)。真值 u=2.01²+3.02=4.0401+3.02=7.0601，v=2.01×3.02=6.0702。真值 (7.0601,6.0702)，误差 (0.0001,0.0002)，仍是步长的平方量级。两个例子都说明 Jacobian 给出的线性项抓住了一阶变化，剩下的是二阶小量。把步长减半，误差会变成四分之一——这就是「一阶近似」的含义。

第 2 帧展示线性项怎么算；第 3 帧把近似点与真值并列，误差是 0.0001，相对步长 0.01 是高阶小量。三帧自包含。

3.6 梯度是 Jacobian 的特例

现在把 Jacobian 和前两单元的梯度连起来。标量输出 f: Rⁿ→R 是 m=1 的特例，它的 Jacobian 是 1×n 的一行：[∂f/∂x₁, …, ∂f/∂xₙ]。我们习惯把梯度写成与输入同形的 n 维列向量，也就是把这一行转置过来。所以梯度不是与 Jacobian 无关的新东西，它就是标量输出时的那一行，只是被转置成了列的形状。

大白话转置来自「同形」偏好，不是数学必然

数学上，f 的 Jacobian 严格是一行；工程上，框架把梯度存成和参数同形的张量。要让一行变成同形的一列，只能转置。你看到的每一个「梯度转置」，几乎都在履行这个翻译职责。本例是 2×2 的方形 Jacobian，转不转置形状都一样，所以看不出来；等遇到 m≠n 的情形，转置的必要性就一目了然。

陷阱把 Jacobian 当成「一堆梯度」而忽略行结构

你会说：Jacobian 不就是每个输出各有一个梯度，堆起来吗？对，但「怎么堆」正是关键。若把每个输出的梯度都写成列向量再左右并排，得到的是 n×m，与标准的 m×n 差一个转置。这个错误在反向传播里会直接导致形状不匹配：上游梯度是 m 维，要乘 n×m 的矩阵根本乘不了。养成习惯：写 Jacobian 时先问「输出维数 m 是多少」，把它作为行数定下来，再填列。

3.7 batch Jacobian：神经网络里的直觉

训练时输入往往是一整个 batch：B 个样本，每个 n 维。把 F 作用在每个样本上，得到 B 个 m 维输出。如果对每个样本都算一份 Jacobian，就得到 B 份 m×n 矩阵，堆起来是一个 B×m×n 的三阶张量。框架里做 batch 的 gradcheck 时，就是在跟这个张量打交道。

工程惯例batch 维度不要和 Jacobian 的行列混在一起

你会觉得 B×m×n 里的 B 只是一层包装，没什么讲究。真相是：框架在 batch 维上通常做向量化，Jacobian 的 m×n 计算对每个样本独立，但内存布局必须明确「哪一维是 batch」。把 batch 维和输入维搞混，会出现「矩阵乘法把不同样本混在一起」的 bug，而且往往不报错。工程上的做法是把 batch 当作最外层维度固定下来，里面才是每个样本的 m×n。代价是多了内存开销，换来的是逻辑清晰。

第 1 帧强调每个样本有自己的 Jacobian；第 2 帧把它们堆成三阶张量，batch 维在最外层。节点文字都短，打印出来也是两张完整的图。

3.8 Jacobian 的行列式：导数在多维里的推广

一元导数是一个数，可以比较大小。多元 Jacobian 是矩阵，不能直接比大小，但它的行列式有类似「局部放大率」的意义：线性映射 Δx ↦ J·Δx 把单位体积缩放 |det J| 倍。本例 det J = 4×2 − 1×3 = 5，说明 F 在 (2,3) 附近把面积放大约 5 倍。行列式为 0 意味着映射在这个点把某个方向压扁，局部不可逆——这是多元版「导数为零」的对应现象。

陷阱行列式为零不等于函数不单调

你会把 det J=0 当成「这里出问题了」。真相是：它只说明线性近似不可逆，F 本身可能在其他方面表现良好。比如 F(x,y)=(x²,y) 在 x=0 处 J=[[0,0],[0,1]]，行列式为零，但函数仍然把不同的输入映到不同的输出（除了 x 与 −x 重合），并不是全局不可逆。可逆性定理（反函数定理）说的是 det J≠0 保证局部可逆，逆命题不成立。把充分条件当充要条件用，是这一节最容易犯的逻辑错误。

工程惯例行列式在生成模型里的影子

归一化流（normalizing flow）用一系列可逆变换把简单分布变成复杂分布，训练时需要计算每步变换的 log|det J| 来修正概率密度。那里的 Jacobian 往往设计成三角矩阵，行列式就是对角线乘积，计算才可行。你在本节手算的 det J=5，就是那个量在最小维度的样子。理解「行列式=局部体积缩放」，以后看到流模型里的对数行列式项就不会觉得那是凭空冒出来的。

3.9 链式法则中的 Jacobian：反向为什么需要转置

若 y=F(x)（Jacobian 为 J_F，形状 m×n），L=g(y)（梯度 ∇_y L 是 m 维列向量），则 ∂L/∂x = J_Fᵀ · ∇_y L。这是多元链式法则的核心式子。形状对账：J_Fᵀ 是 n×m，乘 m 维向量得到 n 维，正好与 x 同形。若不转置，m×n 乘 m 维向量在维度上就不合法。

大白话转置是「把影响送回原空间」

前向传播把 n 维输入变成 m 维输出，Jacobian 记录了这个过程。反向传播要反过来问「输出的变化对输入意味着什么」，自然要用同一个映射的「反向版本」。在线性代数里，把 m 维的量送回 n 维空间的正确操作就是乘 Jᵀ（更严格地说是伴随映射）。所以转置不是人为加的步骤，而是「反方向」这件事在矩阵语言里的写法。mc05 会把这套推导完整走一遍。

陷阱用「转置」这个词掩盖维度思考

你会养成习惯：看到链式法则就写 .T，不再检查维度。真相是：转置只在「输出行、输入列」这套约定下才对；若某处把 Jacobian 定义反了，机械地转置反而错。稳妥做法永远是先把 J 的形状写出来，再问「要得到与谁同形的梯度，该乘什么」。本节 2×2 的方形 Jacobian 看不出差别，但你已经知道 mc08 里「漏转置」在方形矩阵上隐形——那正是机械习惯翻车的地方。

3.10 从标量到向量：导数的概念地图

把前三个单元放在一起看，导数的概念地图是这样的：输入输出都是标量时，导数是数；输出标量、输入向量时，导数是梯度向量；输出向量、输入向量时，导数是 Jacobian 矩阵；输出向量、输入标量时，导数是速度向量。Jacobian 是其中最一般的形式，其他几种都是它的特例或转置。

大白话一张表装下所有情况

R→R 导数是数；Rⁿ→R 梯度是 n 维向量（严格说是 1×n 的一行转置）；Rⁿ→Rᵐ Jacobian 是 m×n；R→Rᵐ 是 m 维列向量。统一写法是「输出维数作行、输入维数作列」。你以后在任何框架文档里看到梯度形状，都可以用这张表反推它为什么是那个形状。把形状想清楚，反向传播里绝大多数疑惑都会消失。

3.11 可微与 Jacobian 的存在

Jacobian 存在要求每个偏导都存在，但仅此还不够——可微要求整张 Jacobian 能作为线性近似，误差是 o(‖Δx‖)。和 mc01 里「偏导存在推不出可微」一样，这里「Jacobian 的每个格子都能算」也推不出「Jacobian 就是好的线性近似」。反例同样是带分段和振荡的函数：偏导处处存在却不连续，线性近似在局部失效。我们训练用的函数由平滑模块拼成，几乎处处可微，所以工程上默认 Jacobian 好用；但遇到绝对值、max 这类折痕，仍要意识到那里可能没有合格的线性近似。

陷阱用数值 Jacobian 判断可微会得到假阳性

你会想：数值差分算出来的 Jacobian 挺正常，函数应该可微。真相是：中心差分在某些不可微点也会给出一个数——比如 |x| 在 0 处，中心差分恰好给出 0（左右斜率对称抵消）。这个数既不是左导数也不是右导数，更不对应任何线性近似。所以「差分能算出值」不等于「导数存在」。判断可微要看定义里的误差阶，而不是看差分有没有输出。这也是为什么gradcheck 只能验证「解析梯度与差分一致」，不能证明「函数可微」。

3.12 把整节串成一条数值叙事

真跑的六行输出讲的是同一件事。前两行 J_analytic 与 J_numerical 逐格相同，证明四条公式与行列约定一致。后四行 j00=4, j01=1, j10=3, j11=2 是四个黄金值，分别对应 ∂u/∂x, ∂u/∂y, ∂v/∂x, ∂v/∂y。把这四格按「行=输出」排好得到 [[4,1],[3,2]]；行列式是 5，线性近似在 (2,3) 附近把面积放大 5 倍；转置后是 [[4,3],[1,2]]，这正是反向传播要用的那个矩阵。一个 2×2 的小例子，把 Jacobian 的形状、数值、线性近似、行列式、转置五个方面全串起来了。

这六行还演示了一种通用的阅读顺序：先看矩阵的整体形状，确认行列约定；再看逐格数值，确认公式；最后看派生量（行列式、转置、线性近似），确认几何意义。以后你在论文或框架文档里遇到任何一个 Jacobian，都可以按这三步读，不必被一堆下标吓住。数值对账只是第一步——它告诉你「算得对」，而形状与几何才告诉你「用得对」。两者缺一不可：一个形状错但数值碰巧对的实现，在方形矩阵上能骗过所有简单的测试，只有在维度不对称的真实层上才会原形毕露。把这套阅读顺序练成习惯，是这一节最值得带走的技能。

3.13 再用三个例子磨手感

只看一个函数容易把 Jacobian 记成套公式。下面三个例子各有侧重，你可以先自己填四格再对答案。

第一例 F(x,y)=(eˣcos y, eˣsin y)。第一行是 ∂/∂x (eˣcos y)=eˣcos y，∂/∂y (eˣcos y)=−eˣsin y；第二行是 eˣsin y 与 eˣcos y。这个 Jacobian 每行都是对应输出的梯度，行与行互相旋转 90°，它是二维极坐标到直角坐标映射的局部线性化。行列式是 e²ˣ(cos²y+sin²y)=e²ˣ，永远为正，说明映射处处保持定向且局部可逆。

第二例 F(x,y)=(x+y, x−y)。Jacobian 是 [[1,1],[1,−1]]，处处相同——因为 F 本身就是线性映射，它的线性近似就是它自己。这是理解「Jacobian 是最佳线性近似」的干净例子：对线性函数，近似是精确的，没有二阶误差。行列式是 −2，负号说明映射翻转了定向。

第三例 F(x,y)=(x², y²)。Jacobian 是 [[2x,0],[0,2y]]，对角矩阵。在 x=0 或 y=0 的轴上，某个对角元为零，行列式为零，线性近似在那条线上把对应方向压扁。但函数本身 x² 在整个实轴上并不是一一对应——它把 x 与 −x 映到同一个值。这个例子提醒你，Jacobian 行列式为零的点往往正是映射「折叠」的地方。

实验记录手算与真跑互相印证

把第一例在 (0,0) 处算一遍：J=[[1,0],[0,1]]，是单位矩阵，说明映射在原点附近近似恒等，行列式为 1。把第二例在任何点算都是 [[1,1],[1,−1]]。把第三例在 (1,2) 处算得 [[2,0],[0,4]]。三例分别给出「旋转缩放」「纯线性」「对角伸缩」三种典型 Jacobian。建议你照本节的清单元理写一版程序，把这三个例子的解析与数值 Jacobian 都打印出来——数值版不需要改结构，只要换掉 jc_u 与 jc_v 两个函数即可，这正体现了共用原语的可复用性。

3.14 方向导数与 Jacobian 的行

mc02 讲过方向导数 D_u f=∇f·u。对向量值函数，沿方向 u 走会有 m 个方向导数，每个对应一个输出分量。把它们排成一个向量，恰好是 J·u——Jacobian 乘方向向量。这一句把前两个单元和本单元完全打通：J 的第 i 行是第 i 个输出的梯度，所以 J·u 的第 i 个分量就是第 i 个输出沿 u 的方向导数。

本例 J=[[4,1],[3,2]]，沿 u=(1/√2,1/√2) 的方向导数向量是 (4/√2+1/√2, 3/√2+2/√2)=(5/√2, 5/√2)≈(3.535534,3.535534)。两个分量都是正数，说明两个输出沿 45° 方向都在增长。若沿 u=(1,0)（x 轴正向），得到 (4,3)，正是 Jacobian 的第一列——印证了「第 j 列是输入 xⱼ 对所有输出的影响」。

大白话行与列的两种读法再强调一次

J·u 是「行视角」：每个输出拿自己的那一行与方向做内积，得到该输出的变化率。J 的第 j 列是「列视角」：第 j 个输入变化时，所有输出各自怎么变。两种读法说的是同一个矩阵，只是你关心「哪个输出」还是「哪个输入」不同。线性代数里这叫「矩阵乘向量是行的线性组合」，你把这句话和 Jacobian 的行列约定对上，就再也不会搞混。

陷阱把 `J·u` 与 `Jᵀ·u` 的作用搞反

你会想：既然方向导数是 J·u，那反向传播应该也用 J·u。真相是：方向导数是「输入方向 → 输出变化」，用 J；反向传播是「输出梯度 → 输入梯度」，用 Jᵀ。两者作用的向量生活在不同空间：u 在输入空间（n 维），上游梯度在输出空间（m 维）。J 把输入向量送到输出空间，Jᵀ 把输出向量送回输入空间。本例两个空间都是 2 维，形状上看不出区别，但概念上方向完全相反。记住「输入空间 vs 输出空间」这两个词，比记「正向用 J、反向用转置」更不容易混。

3.15 Jacobian 的秩：输出真的独立吗

Jacobian 的秩告诉你 m 个输出里有多少是「真正独立变化」的。若 rank(J)<m，说明输出之间存在局部依赖——某些输出组合无法独立改变。本例 det J=5≠0，所以满秩 2，两个输出独立。若某个点 det J=0，秩降到 1，两个输出在该点附近被压到一条曲线上。

工程惯例秩 deficient 在实践里的含义

自编码器里，编码器把高维输入压到低维隐变量，其 Jacobian 必然秩亏——因为输出维度本就小于输入。生成模型里，若生成器的 Jacobian 秩亏，意味着它只能生成数据空间里的一个低维流形，覆盖不到全部可能输出。训练坍塌（mode collapse）的一种表现就是生成器 Jacobian 的秩越来越小。你在本节手算的 det J=5，就是这些高级话题在最小尺度上的影子：行列式不为零，映射才局部「铺开」，才有能力覆盖周围空间。

大白话用线性近似理解秩

Jacobian 是线性映射，线性映射把整个空间压成的维度就是秩。rank=2 表示平面映到平面，面积不塌；rank=1 表示平面被压成一条线，面积变零；rank=0 表示所有方向都被压到一个点。你在 (2,3) 处算出的 J 满秩，所以 F 在那附近把小圆映成小椭圆，而不是一条线或一点。把「秩」想成「线性近似保留了多少维」，比背定义直观得多。

3.16 数值实现里的三个细节

第一，差分步长 eps 取 1e-5，理由和 mc01 完全一样：截断误差 O(eps²) 与舍入误差 O(u/eps) 的平衡点。第二，mc_partial 接收函数指针，所以同一个原语能作用于不同输出；要把 u 与 v 分别包成函数传进去。第三，数值版总是先 *j = mc_zero_mat(2,2) 把矩阵清零，再逐格填入——避免结构体里残留上一次调用的旧值。

陷阱共用库的 mc_mat_t 是定长的，维度不会自动检查

共用库用 MC_MAX=8 的固定数组存矩阵，rows 与 cols 只是记录有效尺寸。mc_partial 也不检查输入向量的 n 是否足够。若你手滑把 j->a[1][1] 写成 j->a[1][2]，在 2×2 的矩阵里这是越界写，但数组实际开到 8×8，程序不会崩，只会悄悄改了不该改的格子。更隐蔽的是打印时 mc_print_mat 只按 rows/cols 循环，越界那格根本不显示，你看到的是一张「看起来对」的矩阵。真实项目里要用断言或带边界检查的容器，教材里为了代码短才省略。

工程惯例从 jac_probe 到更大的网络

框架里的自动微分不需要你手写这四个偏导——它把每个算子（加、乘、指数）的局部 Jacobian 记下来，反向时按链式法则连乘。本例手写的 jc_analytic 就是那个「局部 Jacobian」的人工版。等到了 mc05，你会看到 J₁ᵀ J₂ᵀ … J_Lᵀ 这样的连乘链，每一环都是本节这种小矩阵。先在 2×2 上手算清楚，后面面对上百层的链条时才有抓手。

3.17 把 Jacobian 与后面几节的关系摆清楚

本单元是整册的枢纽之一。前面的梯度只处理标量输出，一旦输出变成向量，你就必须面对「导数该长什么形状」这个问题，而答案正是 Jacobian。它把偏导按输出与输入两个维度排开，让「一个输入影响多个输出」这件事第一次有了紧凑的表达。往前看，它是 mc01 偏导与 mc02 梯度的推广——把「一个输出」放宽到「多个输出」。往后看，它是 mc04 Hessian 的近亲——Hessian 是「梯度的 Jacobian」，也就是对一个向量值函数（梯度场）再求一次 Jacobian。mc05 的链式法则用 Jᵀ 把梯度传回输入空间。mc08 的矩阵微分则回答「当输入本身是矩阵时，Jacobian 的形状约定怎么演化成 Frobenius 内积与 trace 形式」。一句话：你在本节建立的「行=输出、列=输入」约定，会在后面每一节反复出现。

大白话一条线索贯穿整册

偏导是标量，梯度是偏导的向量打包，Jacobian 是梯度的矩阵打包，Hessian 是 Jacobian 的再求导，反向传播是 Jacobian 转置的连乘。这些名词看似各成一章，其实是同一个「导数」概念在不同输出维度、不同输出类型下的化身。你每往前学一节，回头看这张清单都会更清楚一层。把本节的 J=[[4,1],[3,2]] 记牢，它后面会以各种形式回来。

具体到下一单元：Hessian 是对梯度场再求一次 Jacobian。梯度场把输入向量映射到梯度向量，是 Rⁿ→Rⁿ 的向量值函数，它的 Jacobian 就是 n×n 的 Hessian。本节强调的「行=输出、列=输入」在那里变成「行=梯度分量、列=输入坐标」，两条约定完全一致。你在本节练熟的按行读梯度、按列读影响，下一单元会原样复用，只是多出一个对称性——那是混合偏导相等的礼物。

3.18 坐标变换下的 Jacobian：链式法则的几何

前面 3.13 节第二例 F(x,y)=(x+y,x−y) 是线性映射，Jacobian 处处相同。若再把 F 接到另一个函数 G 上，复合函数 G∘F 的 Jacobian 等于两者 Jacobian 的乘积——这就是链式法则的矩阵形式：J_{G∘F}(x) = J_G(F(x)) · J_F(x)。注意乘法顺序：先作用的 F 的 Jacobian 在右边，后作用的 G 的在左边。矩阵乘法不满足交换律，所以顺序错了结果就错。哪怕两个 Jacobian 恰好都是方阵，乘出来仍然合法，数值却完全不同，这是最容易被忽略的一类错误。写出形状再决定左右顺序，比凭语感写要可靠得多。

大白话顺序为什么是「后乘前」

把 Δx 想成一个小位移。先经 F 变成 J_F·Δx，再经 G 变成 J_G·(J_F·Δx)，括号去掉就是 (J_G·J_F)·Δx。所以复合映射的线性近似是 J_G·J_F，后作用的矩阵在左边。这个顺序和「先脱鞋再脱袜」是同一类问题——日常语言常说「先 F 后 G」，写成矩阵却是 G 在左。以后看到 J₂J₁ 的连乘，记得从右往左读，那才是作用顺序。

实验记录用本例验一次链式法则

取 F(x,y)=(x+y,x−y)，J_F=[[1,1],[1,−1]]。取 G(u,v)=(u²,v)，J_G=[[2u,0],[0,1]]。在 x=(2,3) 处，F(x)=(5,−1)，J_G 在该点是 [[10,0],[0,1]]。复合 G∘F=( (x+y)², x−y )，直接求导得 J=[[2(x+y),2(x+y)],[1,−1]]，在 (2,3) 处是 [[10,10],[1,−1]]。用链式公式：J_G·J_F=[[10,0],[0,1]]·[[1,1],[1,−1]]=[[10,10],[1,−1]]，完全一致。这个手算例子把「后乘前」的顺序钉死了。

陷阱把链式法则写成 `J_F·J_G` 会怎样

你会觉得「先 F 后 G，那就 J_F 乘 J_G」。真相是：在非方阵或不可交换的情形下这直接给出错误形状和错误数值。本例因为两个 Jacobian 恰好都是 2×2，乘出来仍是 2×2，不报错但数值全错：[[1,1],[1,−1]]·[[10,0],[0,1]]=[[10,1],[10,−1]]，与正确结果天差地别。这就是方形矩阵的危险之处——形状检查完全失效，只有对拍或手算能发现。mc05 会把这套顺序问题放在多层网络里再讲一遍。

3.19 常见误解速查与第一人称踩坑记录

我自己在写第一版 jc_numerical 时犯过一个错：把第一行写成了 mc_partial(jc_v, x, 0, eps) 与 mc_partial(jc_v, x, 1, eps)，也就是用第二个输出的函数填了第一行。程序照常跑，打印出来的矩阵转置过来恰好还是 [[4,1],[3,2]]？不，本例 jc_u 与 jc_v 的偏导分别是 (4,1) 与 (3,2)，交换后第二行变成 (4,1)、第一行变成 (3,2)，矩阵变成 [[3,2],[4,1]]，与解析版明显不同。闸门报了 numeric_value_mismatch，我才知道自己把函数指针传反了。这个坑不深，但很典型：数值版最容易错的不是差分公式，而是把「哪个函数填哪一行」搞混。

工程惯例给数值版加一道自检

写完 jc_numerical 后，先别急着跑大程序，打印一行中间结果看看：printf("%.6f %.6f\n", mc_partial(jc_u,x,0,eps), mc_partial(jc_u,x,1,eps)) 应该输出 4.000000 1.000000。若看到别的数，先怀疑函数指针传错了，而不是怀疑差分公式。这种「先验证零件再装整机」的习惯，在写复杂反向传播时能省下大量时间。代价只是多打几行临时输出，换来的是错误定位从「整张梯度表都不对」缩小到「第一个函数指针就错了」。调试完记得把临时输出删掉，否则它会混进正文对账的 stdout，让清单里的黄金值对不上——这也是一年手工对拍里最常见的意外之一。

3.20 为什么这一节值得单独占一个单元

你可能会觉得 Jacobian 不过是「偏导排成矩阵」，何必单独讲一整节。等真正写反向传播就会被说服：那里每一个线性算子都有一个 Jacobian，网络有多少层，链式链条里就有多少个 Jacobian 在相乘。若对「行=输出、列=输入」这条约定只是模棱两可地记住，写出来的 .T 会在某个维度不对称的层上翻车，而且这种 bug 在方形层上完全隐形。本节用一个 2×2 的小例子把约定、数值、几何、转置一次性钉死，正是为了后面少踩坑。

大白话小例子是高级概念的最佳载体

F(x,y)=(x²+y,xy) 简单到能完全手算，却又包含了 Jacobian 的全部要点：两行两列能演示行列约定；四个偏导都不为零能做对拍；行列式非零能讲线性近似；转置后仍是 2×2 能演示「方形上错误隐形」。换成真实网络里几百维的层，你无法手算、无法一眼看出错，只能依赖本节建立的直觉。花时间把小例子吃透，是最省时间的投资。

工程惯例给下一单元留一个问题

Jacobian 描述的是一阶导数。如果继续对梯度 ∇f 求 Jacobian，就得到二阶导数的矩阵——Hessian。它对称（在偏导连续时），它的特征值告诉我们驻点是极小、极大还是鞍点，它的逆矩阵出现在牛顿法里。本节的 det J=5 是一阶体积缩放，下一单元的 det H 将告诉我们曲率信息。你把「行=输出、列=输入」的约定带过去，会发现 Hessian 不过是「梯度这个向量值函数的 Jacobian」，概念上毫无违和。

小结这一节的要点
  • 向量值函数 F: Rⁿ→Rᵐ 的 Jacobian 是 m×n 矩阵，第 i 行第 j 列是 ∂Fᵢ/∂xⱼ——行=输出，列=输入；
  • 本例 F(x,y)=(x²+y,xy) 在 (2,3) 处 J=[[4,1],[3,2]]，四个黄金值由解析与数值两条路共同确认；
  • Jacobian 是最佳局部线性近似：F(p+Δx)≈F(p)+J(p)·Δx，误差是 o(‖Δx‖)；
  • 梯度是标量输出时 Jacobian 那一行转置成同形向量的特例；反向传播用 Jᵀ 把影响送回输入空间；
  • det J 是局部体积放大率，为零只说明线性近似不可逆，不等于函数全局不可逆。

  1. F(x,y)=(x²+y, xy)，在 (1,−2) 处手算 Jacobian 的四格，并写出 det J。
  2. 为什么 Jacobian 的行对应输出、列对应输入？从线性近似 F(p+Δx)≈F(p)+JΔx 的形状推导。
  3. 本例 J=[[4,1],[3,2]]，写出它的转置，并说明转置后每个元素表示什么。
  4. 数值 Jacobian 里，为什么 jc_numerical 要对 jc_u 和 jc_v 各调用两次 mc_partial？
  5. 梯度与 Jacobian 是什么关系？为什么梯度要转置？
  6. det J=0 是否意味着 F 在该点附近不可逆？反函数定理的条件是充分还是必要？
注自测题答案
  1. ∂u/∂x=2x=2，∂u/∂y=1，∂v/∂x=y=−2，∂v/∂y=x=1，故 J=[[2,1],[−2,1]]，det J=2×1−1×(−2)=4。
  2. F 是 m 维，Δx 是 n 维，矩阵乘 J·Δx 要得到 m 维结果，J 必须是 m×n，所以行对应输出、列对应输入。
  3. Jᵀ=[[4,3],[1,2]]。它把「输出的变化」映射回「输入应有的变化」，第 i 行第 j 列变成 ∂Fⱼ/∂xᵢ，是反向传播要用的形状。
  4. 因为有两个输出，每个输出都要对两个输入各做一次中心差分，共 2×2=4 次。mc_partial 的函数指针参数让同一原语能作用于 jc_u 与 jc_v。
  5. 梯度是标量输出（m=1）时 Jacobian 的那一行，转置成与输入同形的列向量。转置是为了满足框架「梯度与参数同形」的约定。
  6. 不意味着全局不可逆，只说明该点的线性近似不可逆、反函数定理不适用。定理条件是充分的：det J≠0 保证局部可逆，但 det J=0 时函数也可能仍然可逆（如 x³ 在 0 处导数为零却严格单调）。
