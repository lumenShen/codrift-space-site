8.1 先看工程长什么样

线性代数分册里已经把注意力拆成过矩阵：输入 X 分别乘 Wq、Wk、Wv 得到 Q、K、V，再算 QKᵀ、做 softmax、乘回 V。那时我们只关心「这些矩阵乘出来是什么」。这一单元要做的是同一件事的工程版：把每一步用 PyTorch 写出来，再让框架自己的 nn.MultiheadAttention 从旁边跑一遍，看两条路给出的数字是否一致。

例子仍然只有两个源文件。attn.py 装手写实现与固定的投影矩阵，main.py 负责调框架、打印数值。两个 token、四维嵌入——小到能逐格手算，又足够撑起所有形状关系。

第 1 帧是讲故事用的起点。第 2 帧里多了 torch_attention/，结构与上一单元刻意保持一致：入口编排流程，本地模块提供可复用的函数，清单声明证据。第 3 帧把目录外壳去掉，只看 from attn import ... 这条边——本地模块放在 src/ 下，靠 python src/main.py 时自动加入的模块搜索路径找到它。

大白话注意力一句话在说什么

给序列里每个位置发一张问询卡（Q）、一张身份证（K）和一份可提取的内容（V）。某个位置拿着自己的问询卡去和所有位置的身份证做匹配，匹配分数越高，就从那个位置的内容里取越多。所谓「注意力权重」就是这份取用的比例，加起来等于 1。softmax 负责把它们变成合法比例，√d 负责让分数别太夸张。

8.2 先有 Wq/Wk/Wv：输入被复制成三个角色

注意力的输入 X 是一张 n×d 的表：n 行是 token，d 列是嵌入维度。同一份 X 要扮演三种角色，所以要乘三张不同的矩阵。本例把三张矩阵写死成常量，避免随机初始化把对账弄脏。

第 19 行的注释「行是输出维、列是输入维」是理解整套约定的钥匙：矩阵 wq[i, j] 说的是「第 j 个输入分量对第 i 个输出分量的贡献」。线性代数分册习惯写 Q = XWq，那是把 Wq 存成「列是输出维」的形状；PyTorch 的 nn.Linear 存的是「行是输出维」的形状，于是前向写成 XWᵀ。两者是同一张矩阵的不同摆放方式，不是两套数学。

第 43 行的 @ 是矩阵乘法，x @ wq.T 把 2×4 的 X 变成 2×4 的 Q。三张矩阵都用 torch.tensor([...]) 直接给出，没有随机性；种子照样固定，是为了让整个工程保持可复现的纪律，而不是因为这里真的用到了随机数。

第 1 帧强调投影矩阵是 4×4：输入四维、输出也四维，所以形状不变。第 2 帧强调 Q、K、V 都从同一个 X 来——它们不是三份独立数据，而是同一份数据的三种看法。若你把 d_q 与 d_k 设成不同维度，前三步的矩阵形状仍能对上，只是那时要为每个 head 单独记维度；本例为了手算方便让它们相等。

陷阱把 Wq/Wk/Wv 存反了，数字全变但程序不报错

你会看到：程序正常退出，输出也是漂亮的六位小数，只是与线性代数分册手算的结果对不上。你会怀疑 softmax 写错了，或者怀疑浮点精度。真相是：把 Wq 当成「列是输出维」直接写 x @ wq，等于用了 Wqᵀ，投影结果整体转置了一项。框架里 nn.MultiheadAttention.in_proj_weight 按 [Wq; Wk; Wv] 纵向拼接，每一块都是「行是输出维」。本例把矩阵写死并在注释里钉死这个约定，就是为了让这种错位一眼能查出来：拿第 0 行的 Q 手算一遍，看是否等于 q00=0.750000。

8.3 手写五步：从分数到输出

投影做完，剩下的就是注意力的核心。代码把「算分数」和「分数变输出」拆成两个函数，好处是掩码可以单独插进第一步，而 softmax 与乘 V 的逻辑不需要改。

第 49 行的 k.transpose(-2, -1) 把 K 从 2×4 变成 4×2，于是 Q(2×4) 乘 Kᵀ(4×2) 得到 2×2 的分数表——第 i 行第 j 列就是「第 i 个 token 对第 j 个 token 的匹配分」。除以 math.sqrt(d) 就是 √d 缩放，本例 d = 4，所以除以 2。第 51 行把掩码位置填成负无穷，softmax(-∞) = 0，这些位置从此不参与取用。第 57 行的 dim=-1 指定沿最后一维做 softmax：每一行独立归一化，行的和等于 1。第 58 行用权重乘 V，2×2 乘 2×4 得 2×4 的输出。

为什么非要除以 √d？假设 q 和 k 的每个分量是独立同分布、均值为 0 方差为 1 的随机数，那么点积 q·k = Σᵢ qᵢkᵢ 的方差随 d 线性增长。d 大时，分数的量级会很大，softmax 进入饱和区：最大值几乎吃掉全部概率，其余位置接近 0。饱和的 softmax 梯度极小，反向传播几乎传不回去，训练就卡住了。除以 √d 把分数的方差拉回 1 附近，既保留区分度，又让梯度活着。这不是为了好看，是为了反向传播能工作。

第 1 帧的节点名 scores(2,4→2) 是在说形状从 2×4 与 4×2 的乘法收缩成 2×2；第 2 帧只换了一样东西——分数变成权重；第 3 帧把 V 拉进来，输出才出现。三帧合起来读，你就得到了那句熟悉的公式：softmax(QKᵀ/√d)V。

大白话负无穷不是「一个很大的负数」

掩码的实现写的是 float("-inf")，这不只是偷懒。softmax 的分母要算 e 的幂次，任何有限的负数都会给出一个虽然很小但非零的概率；只有负无穷的指数严格为 0。换句话说，用 −1e9 当掩码在数学上只是「几乎屏蔽」，用 −∞ 才是「完全屏蔽」。本例输出 mask01=0.000000，六位小数上两者看不出差别，但语义差了一层。

8.4 掩码：让某些位置「不可见」

掩码是一张布尔表，形状通常和分数表一样是 n×n。本例的 mask = [[False, True], [False, False]] 表示：第 0 个 token 不许看第 1 个，第 1 个 token 两个都能看。这是因果掩码的最小版本——预测第 t 个词时只能看到它自己与之前的词。

第 45 行的布尔值含义要记牢：在 PyTorch 的 attn_mask 里，True 表示这个位置不允许被注意。这与某些库里「1 表示保留」的约定正好相反，是新手最常踩的反直觉点。第 46 行把同一张表交给手写实现，masked_fill 对 True 的位置填负无穷，语义一致。第 48 行交给框架，第 49 行取最大绝对差当证据。

真跑给出 mask00=1.000000、mask01=0.000000：第 0 个 token 只能看自己，于是它的全部权重都落在第 0 列。mask_diff=0.000000 说明手写与框架在掩码情形下也一致。注意这只覆盖了布尔掩码；浮点掩码（在分数上加一个偏置）语义不同，别混着用。

陷阱把掩码当成「给分数乘零」

你会想当然地以为「屏蔽就是把这个位置的分数乘 0」，于是写出 scores = scores * (~mask)。你会看到输出确实变了，但权重不再满足每行和为 1，而且被屏蔽位置得到一个等于 e⁰ = 1 的未归一化贡献——它在 softmax 分母里照样占一份。真相是：屏蔽必须发生在 softmax 之前，且要让该位置的指数严格为 0，所以填负无穷而不是乘零。另一个相邻陷阱是掩码形状写反：[[True, False], [False, False]] 屏蔽的是第 0 行第 1 列以外的位置，语义完全变了。

8.5 框架版：把同一组 Wq/Wk/Wv 塞进 MultiheadAttention

nn.MultiheadAttention 默认自己随机初始化投影矩阵。如果我们直接调用它，输出当然和手写版对不上——那样的比较毫无信息量。正确做法是把本例写死的 Wq/Wk/Wv 拷贝进框架，再把输出投影设成单位阵，让两条路唯一可能的差别只剩实现细节。

第 20 行把头数设成 1，这样框架的注意力权重就是一张 2×2 的表，和手写版形状一致；batch_first=True 让输入形状写成 (batch, 序列长度, 嵌入维)。第 22 行的 torch.cat([wq, wk, wv], dim=0) 按行把三张 4×4 拼成 12×4，这正是框架内部的存法。第 24 行把输出投影设为单位阵：如果留着随机初始化，框架输出会再乘一张随机矩阵，差自然很大，但你根本分不清差来自输入投影还是输出投影。

调用部分也很短。

第 31 行是两行四列的输入；第 34 行手写版直接吃二维张量，第 36 行框架版要一个 batch 维，所以第 39 行 unsqueeze(0) 把它变成 (1, 2, 4)，算完再 squeeze(0) 收回二维。第 41 行的三个 xb 分别是 query、key、value——本例是自注意力，三者同源；换成编码器—解码器注意力，query 来自目标序列、key 与 value 来自源序列。第 43 行的 diff 取所有输出元素里最大的绝对差，比只看某一个元素更严格。

fw00=0.631421 与 out00=0.631421 相同，manual:[...] 与 fw:[...] 四格逐位一致，diff=0.000000。这不是因为框架调用了我们的手写函数——两条路径是独立实现的，只是化简到同一串浮点运算，结果恰好逐位相同。换成多头、不同硬件或不同精度，你可能会看到 1e-7 量级的小差；所以清单给 atol=1e-6，而不是要求二进制逐位相等。

实验记录本机实测：两条独立路径对上了
  • 工具链：本机 Python {{python}}，PyTorch 与 NumPy 的版本记在 build/toolchain.json 的 runners.python；
  • 命令（在 books/pybridge/examples/ch03/torch_attention/ 里）：python src/main.py；清单 pb08-attention.json 通过 PY_SEED=2024 注入种子；
  • 结果：退出码 0，stdout 就是上面 15 行；手写与框架的输出四格全同，diff=0.000000；加掩码后的最大差 mask_diff=0.000000；
  • 对照：若把第 22 行那次 copy_ 注释掉，框架会用随机初始化的投影矩阵，diff 立刻变大——这正是清单黄金值要抓住的错误。

8.6 复杂度：为什么长序列贵在 n²

注意力的成本可以数乘法次数。设序列长 n、嵌入维 d：

  • QKᵀ：矩阵 (n×d) 乘 (d×n)，每个输出元素要做 d 次乘加，共 n² 个元素，所以约 n²d 次运算；
  • softmax：对每个分数做指数与归一化，约 n² 次，不含大矩阵乘法；
  • 权重乘 V：(n×n) 乘 (n×d)，同样是 n²d 次运算。

合计是 O(n²d)。本例 n = 2、d = 4，前一步 2×2×4 = 16 次乘加，后一步也是 2×2×4 = 16 次，总共 32 次——小到你能在纸上数完。把序列长度从 2 加到 2000，其他不变，成本不是涨 1000 倍，而是涨约一百万倍；这就是长上下文模型的注意力层成为瓶颈的原因。

第 2 帧是本单元最该记住的一张图：QKᵀ 产生一张 n×n 的表，序列里任意两个位置都有一格，这就是「二次」的来源。第 3 帧把信息压回 n×d，形状回到输入的样子，所以注意力层能一层层堆起来。

工程惯例为什么生产环境不直接物化这张 n×n 表

n = 4096 时，一张 float32 的分数表约 64 MB，仅一层的一个 head 就占这么多；几十层、几十个 head 会把显存吃光。工程惯例是用 FlashAttention 这类「分块计算、不落盘整张表」的实现：数学上还是 softmax(QKᵀ/√d)V，但只在片上算一小块就立刻累积结果，省掉显存往返。这是惯例而非标准，代价是实现复杂、对硬件依赖强；收益是长序列能跑得动。本例故意把整张表算出来，因为它只有 2×2，正好能看清每一步。

8.7 手算核对：从 q00 到 out00 的完整链路

这一节把 stdout 里的每个数字用手算对一遍，证明框架没有在背后偷偷改公式。

x₀ = [1.0, 0.5, −0.5, 1.0]。按第 43 行的 x @ wq.T，q₀ 的第 0 个分量是 x₀ 与 Wq 第 0 行的点积：1.0×1.0 + 0.5×0 + (−0.5)×0.5 + 1.0×0 = 0.75，正是 q00=0.750000。同法可得 q₀ = [0.75, 1.0, 0, 1.25]；再从 Wk 得 k₀ = [0.75, 0.25, 0, 1.5]，所以 k00=0.750000。

点积 q₀·k₀ = 0.75×0.75 + 1.0×0.25 + 0×0 + 1.25×1.5 = 2.6875。第 49 行除以 √4 = 2，得 score00=1.343750。这一除不是装饰：不除的话分数是 2.6875，softmax 会更尖锐，权重会从 0.737 推向更接近 1 的位置，小梯度的风险随之上升。

再算第 0 行第二个分数：q₀·k₁ = 0.75×0.5 + 1.0×1.5 + 0×0.5 + 1.25×(−1.0) = 0.625，除以 2 得 0.3125。于是第 0 行的两个分数是 [1.343750, 0.3125]，指数后归一化给出 attn00=0.737158、attn01=0.262842，两者相加为 1（六位小数上恰好 1.000000）。

V 的第 0 行是 [0.5, 1.0, 0, 0.75]，第 1 行是 [1.0, 0, 0.5, −0.5]。按第 58 行加权求和：out₀₀ = 0.737158×0.5 + 0.262842×1.0 = 0.631421，正是 out00=0.631421；out₀₁ = 0.737158×1.0 + 0.262842×0 = 0.737158，正是 out01=0.737158。两格都对上，再加上 manual:[...] 与 fw:[...] 四格全同，这条从输入到输出的链就闭合了。

陷阱手算时最容易在转置和归一化上翻车

第一种错：算 q₀·k₀ 时用 Wk 的列而不是行，得到的不是身份证匹配分，而是另一组投影的组合。记住第 43 行投影完的 Q、K 已经是 2×4，分数是这两张表的行向量点积，不需要再回头碰 Wq/Wk。第二种错：softmax 沿错了维度。dim=-1 是让每一行独立地归一化；若写成 dim=0，归一化发生在列上，第 0 行的两个数不再和为 1，attn00 + attn01 = 1 这条手算核对立刻失败。第三种错：忘了缩放，直接拿 2.6875 和 0.625 去 softmax；程序照样跑，但 score00 对不上，闸门会报 numeric_value_mismatch。

8.8 多头、批量与形状：框架多做了什么

本例把头数设成 1，是为了让手写与框架的权重表能一一对齐。多头注意力做的事情并不神秘：把 d 维切成 h 份，每份用自己的一组 Wq/Wk/Wv 独立算注意力，最后把 h 份输出拼起来再乘一张输出投影矩阵。h = 1 时这套机制退化成我们手写的版本——这就是为什么本例能把 diff 做到 0。

框架的输入输出形状也值得钉死。batch_first=True 时输入是 (N, L, E)，N 是批量、L 是序列长度、E 是嵌入维；输出同形状。need_weights=True 才会返回注意力权重，形状是 (N, h, L, L)。本例 unsqueeze(0) 造出 N = 1，squeeze(0) 又去掉它，所以你看到的 attn:[...] 只是第 0 个 batch、第 0 个 head 的那一行。若把 average_attn_weights 打开（默认行为之一），多头的权重会被平均成 (N, L, L)，这在多头情形下只是一张摘要表，不再是某个 head 的真实权重。

大白话为什么输出还要再乘一张 W_o

注意力输出是多头结果的拼接，每个头学到的「取什么信息」未必在同一个坐标系里。乘一张输出投影 W_o 相当于给它们换到统一的坐标，让下一层能统一处理。本例把它设成单位阵，等于宣布「这一步不重要，别让它干扰对账」。真实模型里 W_o 是学出来的，不能随便丢。

8.9 打印纪律：张量走冒号，标量走等号

这一单元的 stdout 有 15 行，其中十行是 key=0.123456 形状的标量，三行是 attn:[...] 这类冒号文本。分界不是审美问题，而是闸门的解析规则：它把形如 key=value 且 value 是有限十进制数的行当数值行，拿清单里的 atol=1e-6 重算差值；其它行按文本逐字对账。张量里带逗号，若写成 out=0.631421, 0.737158, ... 会被判成 numeric_value_invalid。

标量里也分两类。q00、score00、attn00、out00 是手写路径的中间量与输出；fw00 是框架路径的输出；diff 与 mask_diff 是两条路径的差距；mask00、mask01 是掩码后的权重。清单为每一行都写了黄金值，所以改任何一步实现，闸门都能指出是哪一类量先变了。正文里写「大约相等」没有精度承诺，只有清单里的 atol 才是机器可执行的证据。

选这些量还有一层考虑：它们分布在计算链的不同位置。q00 在最上游，score00 在缩放前后之间，attn00 在 softmax 之后，out00 在最下游，diff 横跨两种实现。中间的某一步写错时，下游数字当然也会错，但上游黄金值先失败能帮你少走很多弯路。设计自己的实验时，也别只钉最终 loss——沿链路每隔几步钉一个量，排查成本会低得多。

8.10 softmax 的数值稳定：框架替你减了最大值

第 57 行调用的 F.softmax 看着只是「指数、求和、相除」，但框架在里面多做了一步保命的操作。朴素写法是 exp(xᵢ)/Σⱼ exp(xⱼ)：当某个分数大到几百，exp(500) 会溢出成正无穷，分子分母都是无穷，结果变成 NaN；当所有分数都很负，exp(−1000) 全部下溢成 0，分母为零，同样得到 NaN。注意力分数经过 √d 缩放后一般落在几到几十的量级，离溢出很远，但你也见过那些因为一行坏数据就把 loss 打成 NaN 的训练——softmax 往往是第一个倒下的地方。

稳定写法先减去这一行的最大值：m = maxⱼ xⱼ，然后算 exp(xᵢ − m)/Σⱼ exp(xⱼ − m)。数学上分子分母同乘 exp(−m)，结果完全不变；数值上最大的那个指数变成 exp(0) = 1，其余都是小于等于 1 的数，永远不会溢出，至少有一项不为零，分母也不会下溢成 0。F.softmax 内部正是这么做的。

拿本例第 0 行核对一遍：分数是 [1.343750, 0.3125]，最大值 m = 1.343750。减去最大值后变成 [0, −1.03125]，指数约是 [1, 0.3568]，归一化得 1/1.3568 ≈ 0.737 与 0.3568/1.3568 ≈ 0.263，正是 attn00=0.737158、attn01=0.262842。减与不减在数学上是同一件事，但只有减了之后这套计算对大数也是安全的。

陷阱手写 softmax 时漏掉减最大值

你会看到：小输入的测试全过，一旦换成量级大一点的分数，输出突然全是 NaN，你可能怀疑是 learning rate 爆炸或者数据里有 inf。真相常常是自己写的 softmax 直接对原始分数取指数，溢出之后 0/0 变成 NaN，再传到损失里一路污染。判断方法是把这行的最大分数打印出来：如果它已经到了几百的量级，先给 softmax 减最大值。本例直接调用 F.softmax，这层保护已经替你做了——这也是为什么我们说「框架收走了样板代码」有时还包括你根本想不到的数值防御。

8.11 三种掩码：同一个位置，三种「不许看」

掩码不是一个单一概念。按用途分，最常见的有三类，它们的形状和取值约定各有讲究。

第一类是因果掩码，本例用的就是它。第 t 个位置只能看 0 到 t 位置，不能看未来。n×n 的布尔表里，上三角（不含对角线）为 True，本例 n = 2 时就是 [[False, True], [False, False]]。它让自回归生成成为可能：预测第 t 个词时，模型看不到后面的答案。

第二类是填充掩码。一个 batch 里句子长短不一，短句尾部要补占位符，这些位置不该被注意。常见写法是生成一个长度为 n 的布尔表，占位位置为 True，再广播成 n×n——每个 query 都不能看占位位置。它与因果掩码可以叠加：逻辑或起来就是「既不能看未来，也不能看占位」。广播这一步很容易写错形状，尤其当框架要求掩码形状是 (N, h, L, L) 时，少一个维度就会报形状错或悄悄按错误方向广播。

第三类是自定义块掩码。比如图结构数据里只让相连节点互相注意，或者文档里只让同一段落的 token 互看。这类掩码不再是简单的三角形状，而是一张由业务规则算出来的 n×n 表；本例的 masked_fill 照样适用，只要布尔语义一致。

还要区分布尔掩码与浮点掩码。本例传的是布尔表，True 表示屏蔽；有些接口接受浮点表，直接把它加到分数上，此时 0 表示不屏蔽，一个很大的负数表示屏蔽。两者语义相反，混用会让「加掩码」变成「只注意被屏蔽的位置」，而且不一定报错。本例在两个路径里都使用布尔语义，并用 mask_diff=0.000000 把这条约定钉死。

大白话掩码为什么要作用在分数上，而不是输出上

输出是「从 V 里按权重取内容」，权重由 softmax 决定。想让某个位置完全不被取用，就要让它的权重严格为 0；权重是 softmax 算出来的，所以必须在 softmax 之前动手。填负无穷正是让指数严格为 0 的办法。若等输出出来再把那一格乘 0，权重本身仍然不对，你只是把错误的取用结果抹掉了——训练时的梯度依然会告诉模型「去看那个位置」，下一次它还会犯错。

8.12 从单头到多头：形状账本再推一遍

本例用 num_heads=1，是为了让手写与框架的权重能一一对齐。多头做了什么？把嵌入维 d 切成 h 份，每份 d_k = d/h，每个头用自己那一份 Wq/Wk/Wv 独立算注意力，最后把 h 份输出拼起来再乘输出投影。

形状账是这样的：输入 X 是 (N, L, d)；in_proj_weight 形状 (3d, d)，一次乘出 Q、K、V 各 (N, L, d)。接着把最后一维拆成 (N, L, h, d_k) 并转置成 (N, h, L, d_k)，让每个头单独算。分数是 (N, h, L, L)；权重同形状；每个头的输出是 (N, h, L, d_k)。最后转置回 (N, L, h, d_k)、摊平 h 与 d_k 两维得到 (N, L, d)，再乘 out_proj 的 (d, d) 矩阵。

算一笔复杂度账：每个头的 QKᵀ 约 L²d_k 次乘加，h 个头合起来是 h·L²d_k = L²d，与单头同阶；权重乘 V 同理。多头并没有省掉二次项，它省的是「所有信息只能挤在一个 d 维空间里做匹配」的限制：不同头可以关注不同关系，比如一个头盯句法相邻，另一个头盯指代回指。本例的 d = 4、h = 1 只有一个头，所以手写版与框架版的权重表都是 2×2，能直接相减。

框架还有一处细节值得知道：batch_first=True 决定输入的最前面一维是 batch；老代码里常见 batch_first=False，形状变成 (L, N, E)。本例手写版吃二维 (L, E)，框架版吃三维 (1, L, E)，靠 unsqueeze(0) / squeeze(0) 来回切换。这两个函数不复制数据，只改视图的 shape，所以没有额外成本；但形状写错时错误信息往往指向矩阵乘法而不是入口，调试时要从输入形状查起。

工程惯例为什么教学例子要把头数设成 1

因为多头会把权重表变成 (N, h, L, L)，手写版只实现单头，两者没法逐格相减。设成 1 之后，in_proj_weight 的三块与我们的 Wq/Wk/Wv 一一对应，out_proj 设成单位阵后输出也不再被二次混合，diff 才真的在衡量「手写数学对不对」。代价是你学不到多头 reshape 的细节——所以我们在正文里把形状账写清楚，而不是假装它不存在。做真实项目时，头数、隐藏维、层数都要通过实验定，不能照抄本例。

8.13 变体实验：哪些改动会让闸门变红

和上一单元一样，真正让实验可信的是「一改就失败」。这里列出四个你马上能做的变体，以及闸门会给出的具体码。

第一个变体：把第 43 行的 x @ wq.T 改成 x @ wq。q₀ 的第 0 个分量不再是 0.75，q00 与清单黄金值不符，闸门报 numeric_value_mismatch。这个变体专门抓「转置写反」，也是连接线性代数分册写法时最容易犯的错。

第二个变体：把第 57 行的 dim=-1 改成 dim=0。程序照跑，权重表不再是每行和为 1，attn00 与 attn01 同时偏离黄金值；若你顺手只改正文 output 去迁就，闸门还会报 stale_output，因为正文必须与真实 stdout 逐字一致。

第三个变体：注释掉第 22 行的 copy_。框架用自己的随机初始化投影，fw00 与 out00 分道扬镳，diff 不再为零。注意这时 attn00、out00 这些手写路径的量仍然正确——失败只发生在框架路径，黄金值帮你把责任定位到具体那一侧。

第四个变体：把掩码的 False 与 True 对调。mask00 与 mask01 互换，mask_diff 仍可能为零（两条路径都改了），但黄金值会抓住语义反转。这说明多钉几个量有好处：如果只钉 mask_diff，掩码语义整体反了反而看不出来。

实验记录变体实验怎么做才有证据
  • 一次只改一处；每次把改动前的 stdout 留一份，别靠记忆对比；
  • 用 node build/run.js --unit pb08-attention 看失败码：黄金值超差是 numeric_value_mismatch，行数变了是 numeric_line_mismatch，手改正文是 stale_output；
  • 若某个变体竟然全部通过，先怀疑黄金值选得不够敏感，再怀疑自己改错了地方；
  • 决定保留新行为时，先重跑程序拿真实 stdout，再更新清单黄金值，最后重跑 render 与 run 两条闸门。

8.14 反向也能走通：注意力不是只能前向

本例在调用手写与框架注意力时都包了 torch.no_grad()，因为我们在做数值对账，不需要梯度，也就没必要为计算图付内存。可一旦把注意力放进真正的训练，这些包围圈就得去掉：Q、K、V 来自可学习的 Wq/Wk/Wv，softmax 的权重也是由它们算出来的，损失对投影矩阵的梯度必须沿着「输出 → 权重 → 分数 → Q/K → Wq/Wk」这条链一路传回去。

这条链上的每一步都是可微的。矩阵乘法 QKᵀ 对 Q 的导数是 K，对 K 的导数是 Qᵀ；除以 √d 只是乘常数；softmax 有自己的雅可比矩阵，PyTorch 已经实现好；乘 V 对 V 的导数就是权重表。你不需要手推这些导数，上一册手推的链式法则在这里由 autograd 自动完成——但要知道它们确实存在，否则「为什么 attention 层的参数能被训练」就成了一个黑箱。

陷阱为了让数字稳定，把 no_grad 包在了整个训练前向

你会看到：loss 打出来很正常，跑几百步也不降，检查参数发现 .grad 全是 None。你会怀疑数据标签错位、怀疑学习率。真相是前向被 no_grad() 包住，计算图根本没建，反向时无图可走。本例包 no_grad 只在「比较两个固定权重的实现」这个场景成立；写训练代码时，正确做法是先正常前向拿 loss、反向、更新，只在评估或计算指标时包 no_grad。判断方法很简单：在 loss 后打印 loss.requires_grad，训练路径应该是 True，推理路径才是 False。

工程惯例什么时候手写，什么时候调框架

手写一遍的价值在于你能指着 score00=1.343750 说清它从哪来，能在结果异常时定位到「是缩放漏了还是转置反了」。框架的价值在于它把多头 reshape、数值稳定、不同后端的高效算子都收走了，生产环境自己重写一遍既慢又容易错。本例的策略是「教学时手写一遍、对账时用框架复核」：两条路给出同一个 diff=0.000000，你既拿到了理解，也拿到了可以放心调用框架的证据。代价是要多写一个本地模块和多做一次对账，换来的是以后看到注意力变体时知道该改哪一步。

8.15 注意力在 Transformer 层里只占一块

学会了注意力，你可能以为它就是 Transformer 的全部。其实一层标准的 Transformer 编码器通常由几块拼成：先是多头自注意力，然后残差连接与层归一化，再过一个逐位置的前馈网络（通常是两层线性加激活），最后再来一次残差与归一化。注意力负责「让不同位置交换信息」，前馈网络负责「对每个位置单独加工」，残差负责让梯度有直达通道，层归一化负责稳住数值尺度。

本例只实现了第一块，原因很实际：其余部件不涉及新的数学思想，而且会把对账链条拉长。你可以把注意力输出 manual:[0.631421, ...] 想成第一块交出的结果；下游的残差会把它与原来的 X 相加，前馈网络再对每个四维向量单独处理。所有后续操作的形状仍然是 (n, d)，所以本单元建立的形状账本能一直用下去。

这也解释了为什么复杂度讨论要盯住 n²：前馈网络的成本是 O(nd²)，与序列长度线性相关；注意力的 O(n²d) 才会随着上下文变长反超。短序列时前馈甚至可能是大头，长序列时注意力必然成为瓶颈。任何「优化 Transformer」的说法都要先说明优化的是哪一块、在什么长度下成立，否则就是空话。

判断一个性能改进是否真的有效，也要落到数字上：固定批量、序列长度与头数，记录前向耗时与显存峰值，再改一处重测。只看「感觉更快了」很容易被测量噪声误导；把配置与结果写进实验记录，别人才复现得出你的结论。本单元的小例子跑不出有意义的性能数字，它的任务是把形状与数值链讲清，为以后读懂那些优化留出抓手。

大白话为什么要残差与归一化

深层网络里，梯度从最后一层往回传时要连乘很多 Jacobian，容易越乘越小（消失）或越乘越大（爆炸）。残差连接给梯度开了一条「绕过这一层」的直路，像给山路修了一条平缓的辅路。层归一化则把每一层的输出拉回相近的量级，让后面的层不必反复适应新的尺度。两者都不是注意力的一部分，但缺了它们，几十层注意力很难训得动。

把这一单元与线性代数分册接起来：那边教的是「注意力就是三组投影加两次矩阵乘加一次 softmax」，这边教的是「同一套数学写成 PyTorch 会长什么样，以及框架替你做了哪些形状搬运」。真正的新东西只有 √d 缩放、掩码语义和 O(n²d) 的成本意识；矩阵乘法与 softmax 还是你早就认识的那两个操作。

小结这一节的要点
  • X 乘 Wq/Wk/Wv 的转置得到 Q、K、V；三张表形状都是 n×d，PyTorch 的存法是「行是输出维」，与线性代数分册的写法差一次转置；
  • 手写五步是点积、除以 √d、掩码、softmax、乘 V；缩放把分数方差拉回 1 附近，避免 softmax 饱和吞掉梯度；
  • 布尔掩码里 True 表示禁止注意，靠 masked_fill(-inf) 让 softmax 给出严格的 0；本例 mask00=1.000000、mask01=0.000000；
  • 把同一组投影矩阵拷进 nn.MultiheadAttention 并把输出投影设为单位阵后，两条独立路径给出相同结果：out00=fw00=0.631421、diff=0.000000；
  • 分数表是 n×n，所以注意力复杂度是 O(n²d)；本例 n = 2、d = 4，共约 32 次乘加；
  • 标量用 key=0.123456、张量用冒号文本，黄金值与容差只写在清单，diff 这类比较量必须来自真跑。

  1. 为什么 PyTorch 里投影写成 x @ wq.T，而线性代数分册习惯写 XWq？两种写法差的是什么？
  2. 手算 q₀ 的第 0 个分量，核对 q00=0.750000；再算 q₀·k₀ 与缩放后的 score00=1.343750。
  3. √d 缩放解决的是什么问题？如果不除，softmax 和反向传播会怎样？
  4. 布尔掩码里 True 表示什么？为什么屏蔽要填负无穷而不是把分数乘零？本例掩码后的权重是多少？
  5. 为什么把 Wq/Wk/Wv 拷进框架、并把输出投影设成单位阵之后，diff 才有意义？
  6. 注意力的复杂度为什么是 O(n²d)？把序列长度扩大 10 倍，成本大约涨多少？
  7. 张量为什么打印成 attn:[...] 而不是 attn=0.737158, 0.262842？后一种写法闸门会报什么码？
注自测题答案
  1. PyTorch 的 nn.Linear 把矩阵存成「行是输出维、列是输入维」，所以前向是 xWᵀ；线性代数分册把 Wq 存成「列是输出维」，写法是 XWq。两者是同一张矩阵转置后的两种摆放，投影结果相同，但把矩阵元素抄错位置会让结果整体转置。
  2. x₀ = [1.0, 0.5, −0.5, 1.0]，Wq 第 0 行是 [1.0, 0, 0.5, 0]，点积为 1.0 − 0.25 = 0.75，即 q00=0.750000。k₀ = [0.75, 0.25, 0, 1.5]，q₀·k₀ = 0.5625 + 0.25 + 1.875 = 2.6875；除以 √4 = 2 得 1.343750，与 score00 一致。
  3. q 与 k 的点积方差随 d 增长，d 大时分数很极端，softmax 进入饱和区，几乎把所有概率给一个位置，其余位置的梯度趋近于零，训练就传不回梯度。除以 √d 把方差拉回 1 附近，保留区分度也让梯度存活。
  4. True 表示这个位置禁止被注意。softmax(-∞) = 0 是严格为零；乘零只会让分数变成 0，指数 e⁰ = 1 仍在分母里占份额，权重不再和为 1。本例掩码后第 0 行权重是 [1.000000, 0.000000]。
  5. 框架默认随机初始化投影与输出投影。若只调用而不拷贝，输出会经过另一组随机矩阵，差来自初始化而非实现，对照没有信息量；拷贝同一组 Wq/Wk/Wv、把输出投影设成单位阵后，两条路的唯一差别才是实现细节，diff 才是对账证据。
  6. QKᵀ 是 (n×d)(d×n) → n×n，约 n²d 次乘加；权重乘 V 是 (n×n)(n×d) → n×d，也约 n²d 次；softmax 是 n² 量级。总成本 O(n²d)，序列长扩大 10 倍、d 不变时成本约涨 100 倍。
  7. 闸门把 key=value 当数值行解析，张量那一串逗号不是有限十进制数，会报 numeric_value_invalid。冒号文本按字面量逐字对账；真正参与容差比较的标量单独打成六位小数，例如 attn00=0.737158。
