vector 用下标访问；map 用键访问。你给一个键，它找回对应的值，不需要自己遍历。map / set 保持有序（按比较器），查找是对数时间；unordered_map / unordered_set 用哈希分桶，平均常数时间，但遍历顺序不保证。两者都能去重、都能按“键”找“值”，差别在“有序”与“哈希”这两条底层路线。

这一单元有六个小实验：map 的插入与查找、operator[] 的副作用、自定义比较器、自定义哈希、set 去重、multimap 的重复键。每个实验只改一个变量，让你看清“键怎么比较、怎么哈希、什么时候会插入”。

学习目标看完这一单元，你应该能
  • 用 map / set 插入、查找、遍历，并解释为什么遍历顺序是按键排序的；
  • 说清 operator[] 与 find / contains / at 的区别，指出哪一行会悄悄插入；
  • 给自定义类型提供比较器（有序容器）或哈希 + operator==（无序容器）；
  • 说出 unordered_* 的遍历顺序为什么不可依赖，以及桶/负载因子只作观察；
  • 用 set 去重、用 multimap / multiset 保存重复键，并用 equal_range 取一组值。

12.1 先看工程长什么样

这一单元在 examples/ch05/ 下再加六个多文件例子。每个例子仍然 include/ + 两个 .cpp + 清单；容器类型、比较器、哈希放在头文件里，main.cpp 只做插入/查找/打印。

第 1 帧的 map_basic/ 用 map<string,int> 存分数，遍历输出按名字排序；map_insert_side_effect/ 专门展示 operator[] 插入。第 2 帧的 custom_compare/ 用 std::greater<int> 让键降序；unordered_hash/ 给自定义 Point 写哈希与 ==。第 3 帧的 set_unique/ 去重，multimap_demo/ 用 equal_range 取重复键。

12.2 map：键唯一、按比较器排序

std::map<std::string,int> 的键是 std::string，值 int；遍历输出按字符串升序（alice、bob、carol、dave），因为 map 用 std::less<Key> 维持有序。scores["dave"] = 60; 插入一个新键；scores.find("bob") 返回指向 bob 的迭代器，it->second 读值。map 的“有序”不是按插入顺序，而是按比较器；插入顺序不同，遍历顺序仍按比较器。

map 的键是唯一的：重复插入同一个键，insert 不会覆盖已有值（返回 pair<iterator,bool>，bool 为假）；要覆盖，用 operator[] 或 insert_or_assign。map 的查找、插入、删除都是对数时间；set 是只有键没有值的 map，multimap / multiset 允许重复键。map 的迭代器在插入/删除时通常保持稳定（节点树结构，除被删元素外），但不要把“通常”当保证；需要长期保存迭代器时，查标准对该操作的失效规则。

map 的元素类型是 std::pair<const Key, T>，键是 const，不能通过迭代器改键（改了会破坏排序）。it->second 可以改值，it->first 只能读。“键不可变”是有序容器的基本不变量；要“改键”，只能删除旧节点再插入新键，或者用 C++17 的节点句柄 extract 把节点取出来（节点的键仍不可变，通常用于转移到另一个容器）。

插入接口要分清：insert({key, value}) 拷贝/移动构造一个 pair，键已存在就丢弃；emplace(args...) 就地构造 pair，但参数会被转发给 pair 的构造函数，容易在隐式转换上踩坑；try_emplace(key, args...) 把 key 与“值的构造参数”分开，键已存在时不构造值，是插入新键的首选；insert_or_assign(key, value) 键存在就赋值、不存在就插入。C++17 之后，新代码优先 try_emplace 与 insert_or_assign，它们把意图写得更清楚，也避免不必要的构造。

map::at(key) 在键不存在时抛 std::out_of_range；find 返回 end()；contains 返回 bool；count 返回 0 或 1（multimap 可能更多）。只读查找不要用 operator[]：它的语义是“取或插入”，会改变容器。需要“查不到就用默认值”时，用 find + 条件，或 at + try / catch，把“缺失”显式处理；不要用一个会偷偷插入的接口表达“只读”。

12.3 operator[] 会插入：find 不会

names[2] 在键 2 不存在时插入一个 {2, ""}，返回值的引用；所以 before=1、after=2，value=empty。names.find(3) 不插入，返回 end()，size 仍然是 2。读操作也可能改容器：operator[] 的语义是“取或插入”，不是“只读查找”。如果只想读，用 at(key)（不存在抛 out_of_range）或 find；只想判断存在，用 contains（C++20）。

operator[] 的插入行为在标准里的写法是 return try_emplace(x).first->second;：键不存在就插入一个值初始化的 mapped_type，再返回它的引用。对 int 来说值初始化为 0；对 std::string 是空串。不要把 operator[] 用在 const map 上：它需要修改容器，const map 没有这个重载；只读时用 at 或 find。

标准原文标准原文：`operator[]` 等价于 try_emplace

Effects: Equivalent to: return try_emplace(x).first->second;

大意：map::operator[] 在键不存在时插入一个值初始化的映射值，并返回它的引用；因此它可能改变容器大小。

出处：N4950 §24.4.4.3「Element access」（[map.access]）。

陷阱用 `operator[]` 做只读查找

你会看到：代码里写 if (m[key] == 0) ... 判断“键不存在”，结果 m.size() 越跑越大，后面遍历多出一堆空值。你会误判成“map 有 bug”或“遍历写错了”。真相是：operator[] 在键不存在时插入了默认值；你每判断一次，就多一个元素。只读用 find / at / contains；要“没有就插入”才用 operator[] 或 try_emplace。

try_emplace 与 operator[] 的差别不只在性能：operator[] 要求 mapped_type 可默认构造，try_emplace 不要求——它把值的构造参数只在“键不存在”时使用。如果值类型没有默认构造函数，operator[] 直接编译失败；这时必须用 try_emplace / insert / insert_or_assign。插入失败时，try_emplace 返回 {iterator, false}，迭代器指向已存在的元素，且不会构造新值；需要“插入或读取”时，它比 operator[] 更精确。

at 与 operator[] 的 const 差异也值得注意：const map 只能调用 at / find / contains，不能调用 operator[]，因为后者可能插入。把只读接口写成 const map&，编译器就会阻止你误用 operator[]；这是用类型系统守住“只读”的简单办法。需要“没有就插入”的接口，明确写成非 const，让调用者知道它会改容器。

12.4 自定义比较器：键的顺序由你定

std::map<int, std::string, std::greater<int>> 把比较器从默认的 std::less<int> 换成 std::greater<int>，遍历顺序变成降序（3、2、1）。比较器必须是严格弱序：对任意 a、b，comp(a,b) 与 comp(b,a) 不能同时为真；相等时两者都为假。写自定义比较器时，返回 a < b 或 a > b，不要写 <= / >=；否则 map 会把相等键当成不同键，或出现未定义行为。

比较器也可以是比较函数对象/ lambda（需要作为类型参数传入，或 C++20 的透明比较器）。比较器决定“键相等”的定义：map 认为 !(comp(a,b) || comp(b,a)) 的两个键等价；如果你的比较器忽略大小写，"Apple" 与 "apple" 就是同一个键。这既是灵活性，也是坑：比较器写错，查找/去重都会跟着错。

严格弱序有两条容易忽略的要求：不可自反（comp(a,a) 必须为假）与传递性（comp(a,b) 且 comp(b,c) 则 comp(a,c)）。写 comp(a,b) { return a <= b; } 违反不可自反，a == b 时两个方向都为真，map 的等价判断失效；写一个依赖外部可变状态的比较器，可能在不同时刻给出不同顺序，破坏容器不变量。比较器应当是纯函数、稳定、无副作用；需要“按多个字段排序”时，按优先级依次比较，不要用减法（可能溢出）。

C++14 起可以用透明比较器 std::less<> 做异质查找：std::map<std::string, int, std::less<>> 可以直接用 const char* 查找，不必先构造 std::string。透明比较器的类型是 std::less<>，不是 std::less<std::string>；后者要求实参类型一致，异质查找不会启用。自定义比较器也可以提供 is_transparent 标记与多个重载，让查找省掉临时对象；这是性能优化，不是正确性要求。

比较器写错时，map 可能“看起来能跑”：小数据量下顺序碰巧对，数据一多就出现查找失败、遍历乱序、甚至死循环。测试比较器时，用相等键、边界键、乱序插入三种情况；不要只用一组升序数据验证。std::map 的正确性依赖比较器，容器自己无法发现“你的 < 不满足严格弱序”。

第 1 帧的 map / set 只依赖比较器；第 2 帧的 unordered_* 依赖哈希函数与相等比较。两条路线对键的要求不同：自定义类型要么提供 <（或用比较器），要么提供 std::hash 特化/哈希对象与 ==；只提供其中一个，另一种容器就用不了。

12.5 unordered_*：哈希与桶

unordered_map 用哈希把键分到桶里，查找时先算哈希、定位桶，再在桶内比较相等。自定义 Point 必须提供两样东西：哈希函数（PointHash）与相等比较（operator==）。哈希相同不代表键相等：不同键可能落进同一个桶（哈希冲突），容器用 == 区分；如果 == 与哈希不一致，查找会失败或行为异常。

unordered_map 的遍历顺序不保证，不要依赖它输出确定的顺序；需要有序输出时，把键取出来排序，或直接用 map。bucket_count()、load_factor() 是可观察的读数，但具体桶数与 rehash 时机由实现决定；reserve 可以给个预期元素数，减少 rehash。哈希容器的“平均 O(1)”是平均情况；哈希函数很差或冲突很多时，最坏会退化到线性。

自定义类型的哈希要满足两条：相等的键必须得到相同的哈希值；不相等的键尽量分散。只满足第一条、哈希值全相同，程序仍然正确，但所有元素挤在一个桶里，查找退化成线性。“正确”和“高效”是两件事：std::hash 的默认实现对整数通常是恒等映射，对字符串有专门算法；自定义类型应把参与 == 的字段都纳入哈希，否则相等对象可能哈希不同，容器直接失效。

rehash 会改变桶的数量，通常使所有迭代器失效，但指向元素的引用/指针仍有效（节点没有搬）。reserve(n) 请求“至少能放 n 个元素而不 rehash”；max_load_factor 控制“平均每个桶多少元素时扩容”。不要把 bucket_count() 当成元素个数；它是桶数，元素数用 size()。需要稳定迭代器时，不要依赖 unordered_* 的 rehash 行为；需要稳定顺序时，直接用 map / set。

unordered_map 的键需要 std::hash<Key> 或显式传入哈希对象，值需要 operator==。标准库没有为“任意自定义类型”自动生成哈希；要么特化 std::hash（放在 namespace std，遵循特化规则），要么在容器模板参数里传自定义哈希。前者让类型“开箱即用”，后者更局部、更容易测试；库代码里通常选后者，避免污染 std。

unordered_map::operator[] 与 map::operator[] 一样会插入默认值；只读查找用 find / at / contains。无序容器没有 lower_bound / upper_bound / equal_range，因为它不维护顺序；需要这些操作就换 map / set。“查找快”不等于“什么都能做”：无序容器牺牲了顺序与范围查询，换来了平均常数时间的单键查找；选型时先看需不需要按顺序遍历或范围查询。

unordered_* 的内存开销通常比 map / set 更大：每个元素除了键值还要存节点指针/哈希缓存，桶数组本身也占空间。“哈希表一定更省”是误解；元素少、键简单时，map 的节点开销与 unordered_map 的桶开销可能差不多，甚至 map 更省。先测量，再选型；不要因为“O(1)”三个字就默认哈希容器更快。

12.6 set 去重与 multimap 重复键

make_set() 返回 {3, 1, 2, 1, 3}，但 std::set<int> 去重并按升序排列，输出 1 2 3、size=3。set 的键就是值，插入重复键不会改变容器；multiset 则保留重复。set 的“去重”依赖于比较器：如果比较器认为两个值等价，它们就是重复的，哪怕字节不同。

std::multimap<std::string,int> 允许同一个键出现多次；equal_range("apple") 返回一对迭代器 [first,last)，覆盖所有键为 apple 的元素。输出 apple_total=4（1+3）、size=3（三个元素，两个键）。multimap 没有 operator[]：同一个键可能对应多个值，取一个值的语义不明确；要访问重复键，用 equal_range 或 find + 循环。

equal_range 在 map / set 上同样可用，返回的区间长度为 0 或 1；在 multimap / multiset 上可能更长。它比“find 再循环 ++it 直到键变”更直接，也避免手写边界条件。lower_bound / upper_bound 分别给出“第一个不小于键”和“第一个大于键”的位置，对有序容器是二分查找，对无序容器没有这两个接口；需要范围查询时，这是 map / set 相对 unordered_* 的独特优势。

set 只存键，适合“去重 + 有序遍历 + 快速成员检查”；multiset 允许重复键，适合“统计每个值的出现次数”或“保留重复记录”。用 set 做去重时，插入返回值告诉你是否真的插入了：auto [it, inserted] = s.insert(value);，inserted 为假说明已存在。需要计数时，map<Value, int> 通常比 multiset 更直接；需要保留全部重复记录时，才用 multiset。

set / map 的迭代器是双向的，不是随机的：不能 it + 3，只能 ++ / --。std::next(it, 3) 可以前进 3 步，但那是线性时间；不要用 std::next 在 set 上做“随机访问”，需要下标就换 vector。有序容器的优势是“按顺序查找/遍历”，不是“按位置访问”；把两者混在一起，选型就会错。

count 在有序容器上并不是“一次二分就结束”：它先二分找到起点，再逐个统计等价的重复元素，重复很多时耗时随重复个数增长。只关心“有没有”时，用 contains（C++20）或 find，不要用 count(...) != 0 再数一遍。

插入时给一个“提示位置”可以降低查找成本：m.emplace_hint(hint, key, value) 告诉容器“新元素大概插在这里”。如果提示正确，插入可以接近常数时间；提示错了，容器会退回到正常查找。提示是优化，不是正确性要求；批量插入已知有序的数据时，用 end() 作为提示很常见，但不要为了“优化”牺牲代码可读性。先写正确版本，测量后再决定要不要加提示。

最后，map / set 的键一旦插入就不能原地修改；需要“改键”时，用 extract 取出节点、改值（键仍不可变）、再插入，或者删除旧键插入新键。不要用 const_cast 去改键，那会破坏排序不变量，后续查找与遍历都可能出错；容器的正确性依赖“键在生命周期内不变”，这条约束不能绕过。

C++17 的节点句柄让“在容器之间搬元素而不复制”成为可能：auto node = m.extract(key); 取出节点，m2.insert(std::move(node)); 插入另一个容器；节点的键仍不可变，但值可以改。extract 不使其他元素的迭代器失效，适合“改键”或“合并容器”的场景；merge 则把另一个容器的节点直接搬过来，遇到重复键就留下源节点。这些接口的语义比 erase + insert 更精确，但用之前要确认两个容器的键类型与比较器兼容。

12.8 下一单元从哪继续

下一单元 11.3 迭代器、算法与 ranges 会把“用下标/键访问”换成“用迭代器访问”：sort / find_if / transform / accumulate，lambda 作为谓词，views 作为惰性管线。map 的迭代器是双向的，vector 的是随机的；算法对迭代器类别有要求，这就是为什么 std::sort 不能直接排 list。先确保你能说清 map::operator[] 与 find 的差别，再去看算法。

小结这一节要带走的五件事
  • map / set 按键有序、键唯一；unordered_* 按哈希分桶，遍历顺序不保证。
  • map::operator[] 在键不存在时插入默认值；只读用 find / at / contains。
  • 有序容器要严格弱序比较器；无序容器要哈希 + operator==。
  • set 去重依赖比较器；multimap / multiset 用 equal_range 访问重复键。
  • 哈希容器的平均常数时间不等于最坏常数时间；不要依赖遍历顺序。

  1. 由比较器（默认 std::less<Key>）决定；插入顺序不影响遍历顺序，只影响插入成本与节点结构。
  2. names[2] 会插入一个值初始化的映射值并返回引用；names.find(2) 返回 end()，不插入。只读用 find / at，需要“没有就插入”才用 operator[]。
  3. 放进 map 需要严格弱序比较器（默认 <）；放进 unordered_map 需要哈希函数与 operator==。
  4. 因为桶的数量、rehash 时机、桶内顺序都由实现决定；哈希冲突时容器用 operator== 区分同一个桶里的不同键。
  5. set / map 键唯一，multiset / multimap 允许重复键；multimap 同一个键可能对应多个值，operator[] 没有明确的“取哪一个值”的语义，所以标准不提供。
