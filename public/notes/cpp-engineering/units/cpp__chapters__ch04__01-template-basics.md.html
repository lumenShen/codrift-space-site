上一章的虚函数在运行期选实现；模板在编译期生成实现。max_of(3, 9) 与 max_of(3.5, 1.5) 看起来是同一个函数，编译器却为它们生成了两份代码，一份收 int，一份收 double。这叫实例化：模板本身不是函数，是一张“怎么生成函数”的图纸；具体类型填进去，才得到一个真正的函数。

模板是 C++ 标准库的基础：std::vector<T>、std::string、std::sort 都是模板。这一单元只讲入门：函数模板怎么推导、类模板怎么用、为什么定义必须放在头文件、显式实例化是什么、非类型参数怎么用、模板与普通函数重载时谁优先。

学习目标看完这一单元，你应该能

  • 解释模板定义为什么通常放在头文件，并读懂“定义在 .cpp 里”导致的链接错误；
  • 用显式实例化与 extern template 控制实例化发生在哪个翻译单元；
  • 说出非类型模板参数的用途，以及模板与普通函数重载时非模板版本为什么优先。

8.1 先看工程长什么样

这一单元在 examples/ch04/ 下建六个多文件例子。模板的定义放在头文件里（原因见 8.4），所以 include/ 会比前几章更“重”；src/<例名>.cpp 仍然承担非模板函数或显式实例化，main.cpp 只做驱动。

第 1 帧的 max_template/ 把函数模板定义放进头文件，main.cpp 用 int、double、string 三种类型调用；box_template/ 是类模板。第 2 帧的 template_in_cpp/ 故意把模板定义藏在 .cpp 里，让链接失败；explicit_instantiation/ 用 extern template + 显式实例化把定义留在 .cpp 里还能链接。第 3 帧的 non_type_param/ 用 FixedArray<T, N> 展示非类型参数；template_overload/ 对照普通函数、函数模板与显式特化。

8.2 函数模板：从实参推导 T

max_of(3, 9) 的两个实参都是 int，编译器推导 T = int，生成一份 int max_of(const int&, const int&)；max_of(3.5, 1.5) 推导 T = double；std::string 版本同理。模板不是“一个函数接受任意类型”，而是“为每种用到的类型各生成一个函数”；生成发生在编译期，运行期没有“类型判断”这回事。

推导规则不总是“看第一个实参”：如果两个实参推导出不同的 T（例如 max_of(3, 4.5)），推导失败，编译器报 no matching function。这时可以显式指定 max_of<double>(3, 4.5)，把 3 转成 double；也可以把两个实参改成同类型。显式模板实参的作用是“不让编译器猜”，不是“强制转换”；它仍然要满足参数类型的匹配规则。

模板参数 T 也可以出现在返回类型、多个参数、默认实参里；typename 与 class 在模板参数列表里等价，本书统一用 typename。模板可以有多个类型参数（template <typename Key, typename Value>），也可以有非类型参数（8.6 节）。模板参数的名字只在模板定义内有效，实例化后不再存在。

推导规则和函数参数的写法强相关。T max_of(T a, T b) 按值传参，数组会退化成指针、函数会退化成函数指针、顶层 const 会被丢掉；T max_of(T& a, T& b) 只接左值，T 保留实参类型；本单元的 const T& 能接左值也能接临时对象，T 仍按实参推导为 int / double / std::string。想保留数组或函数类型，必须用引用；按值传参一定会退化。

显式模板实参可以打破推导僵局，但它不是“任意转换”。max_of<double>(3, 4.5) 把 3 转成 double，因为形参是 const double&；如果模板参数出现在无法转换的位置（例如要求 T*），显式指定也救不了。先让两个实参推导出同一个 T，再考虑显式实参；显式实参更多用于“指定返回类型”或“指定无法从实参推导的参数”。

模板实例化是按需的：一个类模板里如果有十个成员函数，你只调用其中一个，编译器通常只实例化用到的那个（虚函数与某些场景例外）。这让模板库可以暴露大量接口而不付出全部代码体积；也意味着“模板里某段代码从没被实例化”时，它的错误可能一直不出现。模板的编译错误往往延迟到“第一次真正使用”那一刻，读错误时要先找到实例化链。

8.3 类模板：Box<T> 是一张图纸

Box<int> 与 Box<std::string> 是两个不同的类型：它们的成员函数各有一份实例化，sizeof 也可能不同。Box 本身不是类型，不能声明 Box box;；必须写 Box<int> box;。

语法规则类模板成员在类外定义时的写法
  • 每个成员定义前都要写 template <typename T>；
  • 成员名要写成 Box<T>::get，不能只写 get；
  • 定义仍然要放在头文件里，保证使用点可见。

本书的例子把成员函数定义在类内，省掉重复的模板头。类模板的静态成员、嵌套类型、成员模板也都要在头文件里可见，否则使用它们的翻译单元无法实例化。

类模板也可以有默认实参：template <typename T = int> class Box; 让 Box<> 等价于 Box<int>。默认实参可以省掉重复写类型的麻烦，但也让“这里到底用了哪个类型”变得不显眼；接口里用默认实参时，要在文档或别名里写清楚默认是什么。

C++17 起有类模板实参推导（CTAD）：如果构造函数能推导出模板参数，写 Box number(7); 就能得到 Box<int>，不必写 Box<int> number(7);。CTAD 只从构造函数推导，不读取你心里的意图；Box text("hi") 会推导成 Box<const char*>，而不是 Box<std::string>，因为字符串字面量的类型是 const char[N]，按值传参后退化成 const char*。CTAD 方便，但遇到字符串、数组、花括号初始化时要特别小心；不确定就写全 Box<std::string>。

using IntBox = Box<int>; 是别名模板/别名声明，它不创建新类型，只是给 Box<int> 起个短名字。别名不会改变类型系统：IntBox 与 Box<int> 在重载、特化、is_same_v 里完全等价。需要“真正的新类型”时，要用继承或包装类，而不是别名。

8.4 为什么模板定义必须可见

twice 的定义在 src/template_in_cpp.cpp 里，但那个文件没有用到 twice<int>，所以编译器不会为它生成 int twice<int>(int) 的机器码；main.cpp 只看见声明，也无法生成定义。链接器于是找不到 int twice<int>(int)，报 undefined reference。这不是“模板不能放 .cpp”，而是“模板的实例化需要定义在调用点可见”：编译器在调用点才知道 T = int，而它手里只有声明，没法生成代码。

解决办法有三种：

  1. 把定义放进头文件（最常见）：每个包含头文件的翻译单元都能在调用点实例化；链接器用弱符号/COMDAT 合并重复实例。
  2. 显式实例化：在一个 .cpp 里写 template int twice<int>(int);，强制生成这份实例；头文件里用 extern template 告诉其他翻译单元“别自己生成，去链接”。
  3. 把模板限制在单个 .cpp 内使用：不对外暴露，只在定义它的文件里调用；这适合内部实现细节，不适合库接口。

头文件里的模板定义会被多个翻译单元各实例化一份，链接器靠 COMDAT/弱符号把它们合并成一份。这要求每份实例化的“记号序列”一致：同一个模板在不同翻译单元里必须来自同一份定义；如果两个 .cpp 各写了一个同名模板、函数体不同，链接器可能随便挑一份，程序行为就没有保证。ODR 对模板同样适用，只是它允许“重复定义”而不是“不同定义”。

显式实例化有两种写法：template int twice<int>(int); 是实例化定义，强制编译器在这里生成代码；extern template int twice<int>(int); 是实例化声明，告诉编译器“别在这里生成，去别处链接”。前者一个程序里只能有一处，后者可以出现在多个头文件里。extern template 不是“保证有定义”；如果没有任何一个 .cpp 提供显式实例化，链接仍然会失败。

类模板的显式实例化 template class Box<int>; 会实例化它的所有非模板成员；如果某个成员对 int 不合法，即使你从没调用它，也会在这里报错。显式实例化类模板前，先确认所有成员对该类型都成立；否则就只显式实例化需要的成员函数，或者把不满足条件的成员用 if constexpr / 约束隔开。

第 1 帧的 main.cpp 只看见声明，第 2 帧的调用点要求实例化 int twice<int>(int)，但两个翻译单元都没有生成它——链接器只能报 undefined reference。模板的“声明与定义分家”与普通函数相反：普通函数可以把定义藏进 .cpp，模板不行，除非你显式实例化。

第 1 帧的 max_of<T> 只是图纸；第 2 帧的 max_of<int> 与 max_of<double> 才是编译器生成的两份具体函数。实例化由“用到了哪种类型”决定，而不是由模板定义本身决定。

陷阱模板编译通过、链接失败，以为是编译器 bug

你会看到：模板函数在 .cpp 里写得好好的，main.cpp 也 include 了头文件，编译每个文件都过，链接却报 undefined reference to 'int twice<int>(int)'。你会误判成“模板写错了”或“链接器有问题”。真相是：编译器在每个翻译单元独立工作；main.cpp 只有声明，生成不了 int 版本的机器码；template_in_cpp.cpp 没有用到 int 版本，也不会主动生成。模板不是“声明一次、到处链接”的普通函数；它需要定义在实例化点可见，或者被显式实例化。

8.5 显式实例化与 extern template

explicit_instantiation.cpp 里既有定义，又有 template int triple<int>(int);：这行强制编译器在这个翻译单元生成 int 版本。头文件里的 extern template int triple<int>(int); 告诉其他翻译单元“这个实例已经在别处生成了，不要重复生成，链接时去找它”。于是 main.cpp 只看见声明也能链接成功。

显式实例化的收益是减少重复实例化、缩短编译时间，代价是你要手动维护“哪些类型在哪个 .cpp 里实例化”。如果漏写 extern template，每个翻译单元都会生成一份，链接器通常会合并（弱符号），但编译时间与目标文件会变大；如果漏写显式实例化定义，就会回到 undefined reference。这是工程取舍，不是语法必需。

8.6 非类型模板参数：把值写进类型

FixedArray<int, 3> 与 FixedArray<int, 4> 是不同类型；N 在编译期就是常量，所以 T data_[N] 可以直接作为数组成员，不需要 new。非类型参数可以是整型、枚举、指针、引用、nullptr_t 等；C++20 起还允许某些类类型作为非类型参数，但本书不展开。非类型参数的用途是“把配置写进类型”：数组长度、维度、策略开关都可以这样做，代价是每种取值生成一份代码。

FixedArray 的 operator[] 没有边界检查；如果 index >= N，是未定义行为。模板不会自动帮你检查运行期下标，除非你用 std::array::at 或自己加判断。模板保证的是“类型与编译期常量正确”，不是“运行期输入安全”。

非类型参数必须是编译期常量：FixedArray<int, 4> 可以，FixedArray<int, n>（n 是运行期变量）不行。整型非类型参数还允许从常量表达式转换，例如 FixedArray<int, 4u> 可能被转成 int；但转换必须保留值，不能溢出。非类型参数让“配置”成为类型的一部分，因此每种配置都是不同类型、各生成一份代码；配置值很多时，代码体积会明显增加；选非类型参数前，先确认这个配置真的需要在类型里，而不是运行期传一个普通参数就够了。

8.7 模板与重载：非模板优先

show(7) 同时匹配普通函数 show(int) 与模板 show<int>；重载决议优先选择非模板的精确匹配，所以输出 non-template int 7。show(2.5) 只能匹配模板（普通函数要 double → int 转换），输出 template value 2.5。show<std::string>("pear") 显式指定模板实参，匹配 std::string 的显式特化，输出 template string pear。

模板特化不是重载：显式特化 template <> void show(std::string) 是“为特定类型提供另一份实现”，它仍然属于模板家族；重载决议先选主模板/普通函数，再决定是否用特化。写特化时要保证主模板声明在特化之前，否则编译器可能报“特化在实例化之后”。本书不深入模板元编程，只要求你读懂“非模板优先、特化是例外”这两条。

如果没有普通函数，只有两个模板，重载决议会选“更特殊”的那个：template <typename T> void show(T) 与 template <typename T> void show(T*)，传指针时后者更特殊。偏序（partial ordering）比较的是“哪个模板能接受更少的类型”，不是“哪个写得晚”。普通函数比模板更特殊，是因为它不需要推导；显式特化又比主模板更特殊，因为它指定了具体类型。

函数模板的显式特化容易踩坑：特化必须在使用之前声明，否则编译器可能先用主模板实例化，再看到特化就报“特化在实例化之后”。更推荐用重载代替函数模板特化：写一个普通函数 void show(std::string)，让重载决议自然选它，比 template <> 更直观，也不会遇到声明顺序问题。类模板的特化则常用，因为类没有“重载”这条路。类模板还可以写偏特化，只固定一部分模板参数；函数模板不支持偏特化，只能全特化，这是两者最容易被混淆的差别。

8.9 下一单元从哪继续

下一单元 8.2 concepts 与约束 会给模板参数加“门槛”：不是什么类型都能传给 max_of，也不是所有类型都该走同一份实现。requires 表达式与标准 concepts 把“这个类型必须支持 < / 必须可打印”写成编译期约束，让错误在调用点就说清楚，而不是在模板体深处炸出一堆实例化栈。

小结这一节要带走的五件事
  • 函数模板按实参推导类型，为每种用到的类型生成一份实例；推导不出时可以显式写 <T>。
  • 类模板不是类型，Box<int> 才是；成员函数与静态成员的定义通常要放在头文件。
  • 模板定义必须对实例化点可见；放 .cpp 会导致链接期 undefined reference，除非显式实例化。
  • extern template 抑制其他翻译单元的隐式实例化，显式实例化定义负责生成唯一一份。
  • 非类型模板参数把编译期常量写进类型；重载时非模板函数优先于模板。

注自测答案
  1. 不是同一个函数；编译器为 int 与 double 各生成一份实例。运行期没有类型判断，调用的是两份不同的机器码。
  2. Box 是类模板（图纸），Box<int> 是具体类型（实例化结果）；不能声明 Box box;，因为没有指定 T，编译器无法生成完整类型。
