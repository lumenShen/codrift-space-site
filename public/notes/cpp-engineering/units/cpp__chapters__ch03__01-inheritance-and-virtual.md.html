C 的“复用”主要靠组合：一个结构体里放另一个结构体。C++ 多了继承：class Derived : public Base 表示“派生类是一种基类”，派生对象里包含一个基类子对象。继承本身不产生多态；只有虚函数 + 通过基类引用/指针调用，才会在运行期选到派生类的实现。这一单元把这两件事分开：先看继承的对象布局，再看虚函数怎样把“调用哪份实现”推迟到运行期。

多态不是免费的：对象里多一个虚表指针，调用要经过一次间接跳转，析构函数如果不是虚的，通过基类指针删除派生对象就是未定义行为。这一单元先用六个例子把“怎么用”讲清，下一单元再算“值不值得用”。

学习目标看完这一单元，你应该能
  • 写出一个基类 + 两个派生类，用 override 标注重写，并通过 unique_ptr<Base> 容器调用虚函数；
  • 解释对象切片：按值传递基类为什么丢掉派生部分，sizeof 的读数说明什么；
  • 说出虚析构函数解决什么问题，并解释“非虚析构 + 基类指针删除”为什么是未定义行为；
  • 读懂 marked 'override', but does not override 的诊断，知道签名差一个 const 会怎样；
  • 说出构造与析构的顺序：基类 → 成员 → 派生类，销毁时反过来。

6.1 先看工程长什么样

这一单元在 examples/ch03/ 下建六个多文件例子。每个例子仍然是 include/<例名>.h 放类声明、src/<例名>.cpp 放成员函数实现、src/main.cpp 只做驱动与打印；第 2 章起的硬规定③继续生效。

第 1 帧的 virtual_basic/ 定义抽象基类 Shape 与两个派生类 Circle / Rect，用 vector<unique_ptr<Shape>> 装起来，循环调用虚函数。第 2 帧的 slicing/ 按值传基类，观察派生部分被切掉；virtual_dtor/ 对照“非虚析构”与“虚析构”两种基类。第 3 帧的 override_typo/ 故意把 draw() const 写成 draw()，让 override 报错；abstract_shape/ 用纯虚接口 + 工厂；ctor_dtor_order/ 打印基类、成员、派生类的构造/析构顺序。

6.2 继承与虚函数：同一句调用，不同的实现

shapes 的元素类型是 unique_ptr<Shape>，但循环里 shape->name() 与 shape->area() 分别调到了 Circle 与 Rect 的实现，输出 circle=12.56、rect=12。这就是动态绑定：编译器在调用点只知道“这是一个 Shape”，具体调用哪份函数由对象的动态类型决定。

virtual 只写在基类；派生类的 override 不是必须的（不写也能重写），但它是让编译器帮你检查签名的开关。override 的意思是“我声称这个函数重写基类的虚函数”；如果签名对不上（参数、const、返回类型不兼容），编译器直接报错，而不是悄悄生成一个同名的新函数。final 则相反：它告诉编译器“这个虚函数到此为止，派生类不能再重写”；写在类名后面表示“这个类不能被继承”。

标准原文标准原文：虚函数与重写

A non-static member function is a virtual function if it is first declared with the keyword virtual or if it overrides a virtual member function declared in a base class. … Virtual functions support dynamic binding and object-oriented programming.

If a virtual member function F is declared in a class B, and, in a class D derived (directly or indirectly) from B, a declaration of a member function G corresponds to a declaration of F, … then G overrides F.

大意：虚函数可以用 virtual 首次声明，也可以重写基类的虚函数；虚函数支持动态绑定。派生类中“对应”的函数声明会重写基类的虚函数，对应关系包含参数列表与 cv 限定符。

出处：N4950 §11.7.3「Virtual functions」（[class.virtual]）。

= 0 是纯虚函数：基类只声明接口，不提供实现，派生类必须重写，否则派生类也是抽象的。含纯虚函数的类叫抽象类，不能直接创建对象。Shape 的析构函数写成 virtual ~Shape() = default;，原因在 6.5 节；现在只要记住：只要一个类准备被继承并通过基类指针删除，析构函数就该是虚的。

第 1 帧的调用点写的是 Shape::area()，编译期只能确认“Shape 有这个名字”；第 2 帧由对象的虚表指针找到 Circle::area()，返回 12.56。虚函数不是“运行时查字符串”，而是通过对象里的虚表指针做一次间接调用；具体布局由 ABI 决定，C++ 标准只规定行为，不规定虚表长什么样。

带虚函数的类，对象里通常多一个“虚表指针”，所以 sizeof 会比同字段的非多态类大；多继承时可能有多份虚表指针，布局更复杂。这些是实现细节，不是标准保证；但选型时值得知道：多态不是零成本，每个对象都可能多一次间接寻址与一个指针的空间。下一单元会把成本展开。

final 有两个用法：写在虚函数后面表示“派生类不能再重写”，写在类名后面表示“不能被继承”。它不仅是文档，也能让编译器在确定动态类型时做去虚化（devirtualization）；但不要把 final 当成性能开关，它的主要价值是表达设计意图：这个接口到此为止。滥用 final 会让本来可扩展的类变得封闭。

构造/析构期间调用虚函数不会派发到派生类：基类构造时派生部分还没构造，基类析构时派生部分已经销毁，虚调用只能落到当前构造/析构的类。在构造函数里调用纯虚函数是未定义行为（通常会终止）；需要“构造后初始化”，用两阶段构造或工厂函数，而不是在构造函数里调用虚函数。这条规则与 6.7 的构造顺序一起记，能解释很多“为什么多态对象在构造阶段不听话”的疑问。

6.3 对象切片：按值传基类会切掉派生部分

d.name() 直接调用，输出 direct=derived；show_by_value(d) 按值接收 Shape，编译器只复制 d 的基类子对象，派生类的 extra_ 与派生类的虚表指针都没有被复制过来，函数里的 shape 是一个真正的 Shape 对象，所以输出 copy=base。sizeof_base=8 sizeof_derived=16 进一步说明：基类对象只有一个虚表指针（8 字节），派生类对象在它后面还有 double（8 字节），但按值传参只复制了前 8 字节。

对象切片不是“类型转换失败”，而是“派生部分被静默丢弃”。 编译器不会为此报警（有些编译器会对“按值传多态对象”给出提示，但不是标准要求）。避免切片的方法：传 const Shape& 或 Shape*，让函数通过引用/指针看动态类型；容器用 unique_ptr<Shape> 或 Shape&，不要用 vector<Shape> 装派生对象。

第 1 帧的派生对象由“基类子对象 + 派生成员”拼成；第 2 帧的 Shape 副本 只包含基类子对象，extra_ 没有位置可放，虚表指针也换成了 Shape 的。切片是“按基类的大小复制”，不是“把派生对象转成基类引用”；引用/指针不会创建新对象，所以不会切。

切片还有更隐蔽的版本：把派生对象赋给基类变量、把派生对象放进 vector<Base>、从函数按值返回 Base。它们的共同点是“新对象是基类类型”，派生部分没有容身之处。判断标准：这个位置会不会创建一个 Base 类型的独立对象？会，就切片；只是绑定一个名字/指针，就不会。

6.4 override 与签名：差一个 const 就不是重写

Base::draw() const 带 const，Derived::draw() 不带，两个函数的签名不同，所以前者没有被重写。override 的作用在这里体现：编译器直接报 marked 'override', but does not override，而不是让你得到一个“看起来能调用、实际上没有多态”的派生函数。旁边的 -Woverloaded-virtual 警告还指出：派生类的 draw() 隐藏了基类的 draw() const，通过基类指针调用时不会走到它。

签名包含参数列表与 cv 限定符；返回类型要兼容（协变返回类型除外）。 常见错误有：漏 const、参数类型写成引用/值不一致、把 noexcept 当成签名一部分（C++17 起 noexcept 是函数类型的一部分，重写时也要匹配）、把 virtual 写在派生类却漏了 override。写 override 的成本很低，收益是让编译器替你抓这些错误；本书建议所有重写都写 override，不重写就不写 virtual。

陷阱以为“同名函数就是重写”

你会看到：派生类写了一个和基类同名、参数略有不同的函数，编译通过，调用却走到基类版本。你会误判成“虚函数失效了”或“编译器没看见派生类”。真相是：参数列表/const 不同就不是重写，而是隐藏——派生类的新函数把基类的同名函数挡住了，基类指针调用仍然按基类的虚表走。override 会让这种“假重写”直接编译失败；不写 override 时，编译器可能只给一条 -Woverloaded-virtual 警告，甚至什么都不说。

6.5 虚析构：通过基类指针删除派生对象

下面是同一份头文件里的第二组：类的形状不变，只把基类析构改成 virtual。

bad 的静态类型是 BadBase*，动态类型是 BadDerived；delete bad; 只调用了 ~BadBase，~BadDerived 没有执行，所以 bad_destroyed=0。good 的基类析构是 virtual，delete good; 先调用 ~GoodDerived，再自动调用 ~GoodBase，所以 good_destroyed=1。

通过基类指针删除派生对象，而基类析构不是虚的，是未定义行为。 本机可观察到的结果是“派生析构没执行、派生类的资源泄漏”，但这只是这一套 ABI/运行库下的表现；标准不保证你一定看到这个结果，也不保证不会崩溃。规则很简单：如果一个类准备被继承，并且可能通过基类指针删除，就把析构函数写成 virtual。 如果一个类不准备被继承，可以用 final 明确禁止继承，避免别人误用。

虚析构的代价是对象里多一个虚表指针（如果还没有其他虚函数），以及一次间接调用；对“多态基类”来说，这是必须付的成本。Shape 的 virtual ~Shape() = default; 就是这条规则的落地：它没有资源要释放，但它是多态基类，必须有虚析构，否则 unique_ptr<Shape> 删除派生对象时只走基类析构。

6.6 抽象类与接口：只规定“能做什么”

Shape 只有纯虚函数与虚析构，没有任何数据成员；这种类常被叫作接口类。它不能直接实例化（Shape s; 编译失败），但可以定义 Shape& / Shape* / unique_ptr<Shape>，让调用者只依赖“能算面积”这个能力。make_square 返回 unique_ptr<Shape>，调用者不需要知道具体是 Square；total_area(const Shape&) 只读地使用接口，不拥有对象。“面向接口编程”在 C++ 里就是“依赖抽象基类的引用/指针，不依赖具体派生类”。

接口类的析构函数必须是虚的（virtual ~Shape() = default;）。原因与上一节相同：调用者可能通过 unique_ptr<Shape> 删除对象，析构链必须走到派生类。纯虚析构在语法上允许，但必须提供定义（否则派生类析构时链接不到），本书统一用 virtual ~Shape() = default;。

抽象类也可以有数据成员与普通成员函数；纯虚函数只表示“这个操作必须由派生类提供”。不要把“抽象类”理解成“不能有实现”：它可以有构造函数、普通函数、甚至纯虚函数的定义（派生类可以显式调用 Base::f()）。抽象的是“能否实例化”，不是“有没有代码”。

6.7 构造与析构的顺序

构造一个 Derived 的顺序是：基类子对象 → 成员子对象（按声明顺序）→ 派生类构造函数体；析构顺序完全相反：派生类析构函数体 → 成员析构（按声明逆序）→ 基类析构。输出正是 Base() → Member() → Derived()，然后 ~Derived() → ~Member() → ~Base()。

这个顺序有一个实际后果：在基类构造函数里调用虚函数，不会调用到派生类的重写版本。因为构造基类时，派生类部分还没构造，对象的动态类型还是基类；虚表指针指向基类的虚表。析构时同理：进入基类析构后，派生类部分已经销毁，虚调用也不会再回到派生类。标准把这条规则写在构造/析构期间的动态类型里；实际写代码时记住一句话：构造/析构期间不要依赖派生类的虚函数行为。

成员析构按声明逆序，与成员初始化顺序相反；这与 3.3 节的“按声明顺序初始化”是一对。初始化顺序与销毁顺序互为逆序，这是 C++ 对象生命周期的一条基本对称性。

6.9 把继承变成工程习惯

  1. 先问“是不是 is-a”：派生类必须能替换基类使用（Liskov 替换原则的朴素版本）；只是“想复用代码”不该用继承，用组合。
  2. 多态基类必须有虚析构：只要可能通过基类指针删除，就写 virtual ~Base() = default;；不准备被继承就写 final。
  3. 所有重写都写 override：让编译器检查签名；不要依赖“同名就是重写”。
  4. 按引用/指针传递多态对象：不要按值传基类，也不要把派生对象放进 vector<Base>；容器用 unique_ptr<Base>。
  5. 构造/析构期间不调用虚函数：基类构造时派生部分还没好，基类析构时派生部分已经没了。

继承层次越深，构造与析构链越长，追踪一次行为要跨过的文件也越多；超过两层的具体继承通常应改成组合。继承是“类型关系”的声明，不是省代码的工具，每加一层都要能说清它表达了什么 is-a 关系。

6.10 下一单元从哪继续

小结这一节要带走的五件事
  • 继承表达 is-a；虚函数 + 基类引用/指针才产生动态绑定，override 让编译器检查签名。
  • 按值传基类会切片：派生部分被静默丢弃，容器要用 unique_ptr<Base> 或引用。
  • 多态基类的析构必须是虚的；通过非虚析构基类指针删除派生对象是未定义行为。
  • 抽象类用纯虚函数规定接口，不能实例化；接口类的析构同样必须是虚的。
  • 构造顺序是基类 → 成员 → 派生类，析构顺序相反；构造/析构期间不要依赖派生类虚函数。
自测题自测题（先自己做，再对答案）
  1. Shape 的 area() 是纯虚函数，为什么 Shape s; 不能编译，而 Shape* p 可以声明？
  2. show_by_value(Shape shape) 收到一个 Derived 对象时，为什么 shape.name() 返回 base？
  3. 非虚析构的基类指针删除派生对象，本机看到 bad_destroyed=0；这说明了什么？标准上这属于什么行为？
  4. override 与 virtual 各解决什么问题？为什么本书建议“重写都写 override，不重写不写 virtual”？
  5. 构造 Derived 时，输出顺序为什么是 Base() → Member() → Derived()？析构为什么反过来？
注自测答案
  1. Shape 含纯虚函数，是抽象类，不能创建对象；但可以声明指向它的指针/引用，用来绑定派生对象。
  2. 按值传参创建了一个独立的 Shape 对象，只复制了 d 的基类子对象；派生部分与派生虚表都没被复制，所以虚调用只能到 Shape::name()。
  3. 本机可观察到派生析构没有执行、派生资源没有释放；这属于未定义行为，标准不保证具体结果，不能把 bad_destroyed=0 当成可移植的规律。
  4. virtual 声明“这个函数可以动态绑定”；override 声明“我在重写基类虚函数，请检查签名”。重写写 override 能让签名错误编译失败；不重写就不写 virtual，避免制造新的虚函数。
  5. 构造顺序是基类子对象、成员子对象（按声明顺序）、派生类构造函数体；析构按完全相反的顺序执行，所以先派生、再成员、最后基类。
