lambda 看起来像“临时写一个函数”，其实是编译器在你写下方括号的位置生成一个类，再创建一个该类的对象。捕获列表决定这个类有哪些数据成员，函数体变成它的 operator()。理解这一点，捕获的“按值还是按引用”、mutable 为什么能改副本、泛型 lambda 为什么能收不同类型，全都能顺下来。

这一单元用六个多文件例子拆开闭包：先看捕获的值何时复制，再看引用捕获的生命周期风险，然后用 mutable 改副本，用泛型 lambda 生成多个 operator()，最后把不同可调用对象装进 std::function，并和老的 std::bind 对照。

学习目标看完这一单元，你应该能
  • 说出 lambda 表达式生成的是什么样的对象，为什么两个写法相同的 lambda 类型也不同；
  • 区分按值捕获与按引用捕获，指出复制发生在什么时候；
  • 解释引用捕获为什么会悬垂，以及“在本作用域内调用”为什么暂时安全；
  • 用 mutable 修改按值捕获的副本，并说明它不会改到外面的变量；
  • 写泛型 lambda，理解每个实参类型会实例化一份 operator()；
  • 用 std::function 统一存放 lambda 与函数对象，并说出它的代价；
  • 读懂 std::bind，并在新代码里优先选择 lambda。

15.1 先看工程长什么样

这一单元在 examples/ch06/ 下新增六个例子。每个例子的头文件只放声明，辅助函数放在 .cpp，main.cpp 负责构造 lambda 并打印读数。这样每个例子仍是两个以上源文件、至少一个头文件，和后面的大作业保持同一种组织方式。

第 1 帧的三个例子都在 main.cpp 里就地写 lambda：lambda_capture/ 对照按值与按引用，capture_ref_dangle/ 把引用捕获限制在对象存活期内，mutable_counter/ 修改按值捕获的副本。第 2 帧把 lambda 放进函数：generic_lambda/ 用 auto 参数写两个调用点，function_wrapper/ 用 std::function 接收 lambda 和函数对象。第 3 帧的 bind_old/ 用 std::bind 完成与 lambda 相同的绑定，方便对照。

15.2 lambda 生成的是闭包对象，不是函数

写下一个 lambda 表达式，标准规定它产生一个独有的、没有名字的类类型，叫闭包类型；表达式本身创建一个该类型的对象，叫闭包对象。函数体成为这个类的 operator()。“独有的、没有名字”有两层意思：第一，两个写法完全相同的 lambda，类型也不一样；第二，你没法直接写出这个类型，只能用 auto、模板参数或 std::function 接住它。

by_value 的方括号里写 value，闭包对象里就多一个 int 成员，初始化时复制当时的 10；之后 value = 20 改的是外面的变量，闭包里的副本仍是 10，所以输出 value_capture=10。by_ref 写 &value，闭包里存的是引用（实现上通常是一个指针），调用时读的是 value 当前的值，所以输出 ref_capture=20。按值捕获的复制发生在 lambda 创建时，不是调用时；这是理解后面所有捕获行为的时间点。

标准原文标准原文：闭包类型与按值捕获的成员

The type of a lambda-expression (which is also the type of the closure object) is a unique, unnamed non-union class type, called the closure type …

For each entity captured by copy, an unnamed non-static data member is declared in the closure type. The declaration order of these members is unspecified.

大意：lambda 表达式产生一个独有的、无名的类类型；每个按值捕获的实体，都会在闭包类型里声明一个无名的非静态数据成员。

出处：N4950 §7.5.5.2「Closure types」（[expr.prim.lambda.closure]）与 §7.5.5.3「Lambda capture」（[expr.prim.lambda.capture]）。

按值捕获的成员类型还有细节：如果被捕获的是一个引用，成员类型是“被引用对象的类型”，不是引用；如果捕获的是函数，成员是函数引用。这些规则保证了闭包对象可以复制、可以移动。闭包对象本身是一个普通对象：可以按值传给函数、可以放进容器、可以返回；它的“函数”身份只体现在 operator() 上。

一个不捕获任何东西的 lambda 还可以转换成函数指针，因为它的 operator() 不依赖任何成员。捕获了东西的 lambda 不能这样转换，因为函数指针没有地方存那些成员。这也是为什么回调接口如果只收函数指针，就没法直接传一个有状态的 lambda；要么改成模板/std::function，要么把状态放到别处。

捕获默认值 [=] / [&] 是“让编译器按使用情况自动捕获”：[=] 默认按值，[&] 默认按引用。默认捕获看起来省事，但会把“到底捕获了什么”藏起来；读到 lambda 时，你必须扫一遍函数体才知道它依赖哪些变量。工程代码更推荐显式列出捕获，尤其是跨作用域保存的 lambda；默认引用捕获 [&] 在异步/回调场景最容易悬垂。

类成员函数里的 lambda 捕获 this 时，捕获的是对象指针，不是对象副本；[this] 后访问成员等价于通过 this-> 访问。如果对象在 lambda 调用前销毁，this 悬垂；C++17 起可以用 [*this] 按值捕获整个对象（要求可复制），避免悬垂。[=] 在成员函数里默认捕获的是 this 指针，不是成员的副本；这是另一个容易误判的点。

初始化捕获（[owner = std::move(ptr)]）解决了两件事：把资源移进闭包，以及让捕获的名字与外部不同。需要 lambda 拥有资源时，用初始化捕获把所有权移进去；这比捕获裸引用安全，也比 std::function 包装更直接。捕获列表是闭包的“成员声明”，写法越明确，闭包的寿命与所有权越清楚，读代码的人也越容易发现潜在的悬垂。

15.3 引用捕获：闭包不延长对象寿命

引用捕获省掉了复制，也让闭包能改到外面的变量。代价是闭包不拥有那个对象，对象的寿命必须比闭包长。标准在引用捕获的条文里明确提醒：这种捕获是否有效，取决于被引用对象的寿命，而不是引用本身的寿命。

这个例子里 borrowed 在 local 还活着时调用，所以输出 7，没有任何问题。但把同一个 lambda 返回出去，情况就变了：local 在函数返回时销毁，闭包里的引用指向一块已经结束生命周期的存储；再调用 borrowed() 就是未定义行为。它可能打印出旧值 7，可能打印垃圾，也可能直接崩溃——三种结果都不算“正确”，因为标准没有规定。

陷阱引用捕获逃出作用域就是悬垂

设想一个函数 make_bad()：它声明局部变量 int local = 7;，然后 return [&local]() { return local; };。返回的闭包对象里存着一个指向 local 的引用；local 是栈上的自动变量，函数一返回就销毁。调用这个闭包是未定义行为。本机某次运行可能仍然打印 7，那只是那块栈内存还没被覆盖，不能当成“这样写也行”的证据。

正确做法只有两种：按值捕获（[local]，闭包自己存一份），或者让被引用对象的寿命确实长于闭包（例如捕获堆上的对象、捕获 shared_ptr、或让闭包在对象销毁前用完）。[&] 默认引用捕获在“马上调用”的场景很方便，但只要 lambda 会被存起来、返回、传给异步任务，就要逐个检查它引用的东西还活着没有。

C++14 起可以用初始化捕获把“搬进闭包”写得更明确：[owner = std::move(ptr)] 创建一个新成员，用 std::move(ptr) 初始化；[&ref = obj] 创建一个引用成员。初始化捕获让捕获的名字和外面的名字可以不同，也让移动捕获成为可能。例如把 std::unique_ptr 移进闭包，闭包就拥有了对象，寿命问题自然消失；这比捕获裸引用安全得多。

第 1 帧的闭包可以安全地活过 local；第 2 帧的闭包只是“借看”local，local 一销毁，借用就失效。按值捕获买的是寿命，按引用捕获买的是“能看到最新值、能改原对象”；两者不能同时免费得到。

15.4 mutable：改的是闭包里的副本

默认情况下，lambda 的 operator() 是 const 成员函数；按值捕获的成员在函数体里是只读的。想修改这份副本，要在参数列表后写 mutable，它去掉 operator() 的 const。注意：mutable 改的是闭包对象里的成员，不是外面的原变量。

next 创建时复制 start 的 0；第一次调用把成员从 0 加到 1 并返回 1，第二次从 1 加到 2 并返回 2；外面的 start 一直是 0，所以 outer=0。闭包对象有状态，状态在多次调用之间保留；这也是 lambda 能当计数器、累加器的原因。

如果把 mutable 去掉，return ++start; 会编译失败，因为 operator() 是 const，不能改成员。标准的规定是：operator() 声明为 const 当且仅当 lambda 没有写 mutable（也没有显式对象参数）。mutable 不是“让捕获变成引用”，它只解除 operator() 的 const；按值捕获仍然是副本，外面的变量仍然不受影响。

第 1 帧的两块存储互不相干；第 2 帧只改了闭包成员。看到“lambda 里的计数器每次都从零开始”，先检查闭包对象是不是每次都被重新创建：临时写一个 [count = 0]() mutable { return ++count; } 并马上调用，闭包用完就销毁，下一次又建一个新的，状态自然不保留。

15.5 泛型 lambda：一个写法，多份 operator()

C++14 允许 lambda 的参数写 auto。这不是“运行期看类型”，而是编译器把闭包类型的 operator() 做成一个函数模板；每个不同的实参类型，实例化一份具体的 operator()。所以一个泛型 lambda 可以同时处理 int 和 std::string，但每一份实例仍是强类型的。

两个函数里各写了一个 describe，函数体都只有一句返回。describe_int 用 int 调用，实例化出 operator()(const int&)；describe_text 用 std::string 调用，实例化出 operator()(const std::string&)。它们是同一个 lambda 写法的两个实例，不是同一个函数；如果某个类型不支持函数体里的操作（例如 std::to_string 不接受的类型），编译在实例化时才报错。

const auto& 在这里让实参按只读引用传入，避免复制字符串。泛型 lambda 也可以写 auto&、auto&&，规则与函数模板的参数推导一致：auto 按值、auto& 只接左值、auto&& 是转发引用。泛型 lambda 本质上是“少写一个模板头”的简写，理解函数模板的推导，就理解它。

泛型 lambda 还有一个常见用途：给标准算法提供比较器。std::sort(v.begin(), v.end(), [](const auto& a, const auto& b) { return a.key < b.key; }) 对元素类型不敏感，算法内部也不用为每种元素写一个新函数。代价是每换一种元素类型就多一份实例代码，编译时间和二进制体积都会增加；这是模板化的常规取舍，不是 lambda 特有的问题。

15.6 std::function：把不同可调用对象装进同一个类型

lambda 的类型各不相同，函数指针、函数对象也各有各的类型。如果接口需要“存一个可调用对象，稍后调用”，就需要类型擦除。std::function<R(Args...)> 就是这样一种容器：它可以装函数指针、lambda、函数对象，只要调用签名匹配。

apply_twice 把传入的函数调用两次：add_one 先算 3+1=4，再算 4+1=5；Doubler 先算 3×2=6，再算 6×2=12。std::function 不关心你传的是 lambda 还是类，它只检查“能不能用 int 调用、返回能不能转成 int”。这正是类型擦除的价值：接口只需要写一次签名，调用方可以用任何满足签名的东西。

function(function(value)) 先调一次得到中间值，再用中间值调一次。std::function 的 operator() 会转去调用它内部保存的目标；如果 std::function 是空的，调用会抛 std::bad_function_call。这个例子里传的都是有目标的对象，所以不会走到那条路径。

代价也要说清楚：std::function 通常要做间接调用，可能还要堆分配（小对象可能放在内部缓冲区，是否放、放多大由实现决定）；拷贝 std::function 可能拷贝它保存的闭包。作为对比，模板参数 template<class F> int apply_twice(F f, int) 可以完全内联，没有类型擦除的开销，但会让每个 F 生成一份 apply_twice，而且 F 的类型必须写在头文件里。要“统一类型、运行期替换”用 std::function；要“零开销、编译期确定”用模板，这是工程上最常见的分界。

15.7 std::bind：老办法，仍能读懂

在 lambda 普及之前，绑定参数常用 std::bind。它接收一个可调用对象和一串参数，返回一个新的可调用对象；参数里的 std::placeholders::_1、_2 表示“调用时再填”。

std::bind(add, 10, _1) 把 add 的第一个参数固定为 10，第二个参数留到调用时填；add_ten(5) 等价于 add(10, 5)，结果是 15。lambda 版本直接写 value + 10，读起来更直白。

std::bind 的规则比 lambda 多：它默认按值保存绑定参数，要传引用得用 std::ref / std::cref；嵌套 bind、成员函数指针、重载函数都要额外处理；占位符的编号也容易写错。C++14 之后，绝大多数 std::bind 都能用 lambda 更清楚地表达，尤其是初始化捕获出现以后。读旧代码要认识 std::bind，写新代码优先 lambda；C++20 还提供了 std::bind_front 处理“只固定前几个参数”的常见情形。

编译器视角编译器视角：`std::bind` 的返回类型很长

std::bind 的返回类型是一个由实现定义的类型，通常带有 _Bind、_Placeholder 之类的模板细节。它不能直接写成变量类型，所以老代码里常见 auto 或 std::function 接住。lambda 的闭包类型同样没有名字，但它的“接口”就是函数体，读代码时不需要穿过 bind 的模板去看参数怎么绑定。这也是“可读性”在类型层面的体现：同样的 15，lambda 版本一眼能看懂，bind 版本要先在脑子里展开参数映射。

  • lambda_capture 的 stdout 是 value_capture=10 ref_capture=20：按值捕获停在 10，按引用捕获看到改后的 20；

15.9 下一单元从哪继续

下一单元进入异常处理：函数怎么把“失败”报告给调用者，try / catch 怎么接，栈展开时局部对象怎么按 RAII 销毁，noexcept 又承诺了什么。这一单元的 lambda 会继续出现——标准库的谓词、回调、错误处理回调都常写成 lambda；而 std::function 的拷贝与调用开销，也会在异常安全的讨论里再次遇到。

小结这一节要带走的四件事
  • lambda 生成独有的无名闭包类；按值捕获在创建时复制，按引用捕获只是借看，闭包活过对象就悬垂。
  • mutable 去掉 operator() 的 const，改的是按值捕获的成员；泛型 lambda 的 operator() 是函数模板，每个实参类型实例化一份。
  • std::function 用类型擦除统一签名，灵活但有间接调用/可能的堆分配；能编译期确定时优先模板。
  • std::bind 能读懂即可；新代码用 lambda（尤其初始化捕获）表达更清楚。
自测题自测题（先自己做，再对答案）
  1. int x = 1; auto f = [x]() { return x; }; x = 2; 调用 f() 返回几？如果把 [x] 改成 [&x] 呢？
  2. 为什么返回 [&local] 的 lambda 是危险的？按值捕获为什么能避免？
  3. mutable 的作用是什么？它会让按值捕获变成按引用捕获吗？
  4. 泛型 lambda [](const auto& v) { ... } 对 int 和 std::string 各生成什么？
  5. std::function<int(int)> 能装下哪些东西？它相比模板参数有什么代价？
注自测答案
  1. 返回 1：按值捕获复制的是创建时的 1；改成 [&x] 后返回 2，因为引用读到的是改后的值。
  2. local 在函数返回时销毁，闭包里的引用指向已结束生命周期的存储，再调用是未定义行为；按值捕获让闭包自己存一份副本，寿命随闭包。
  3. mutable 去掉闭包 operator() 的 const，允许修改按值捕获的成员；它不会把副本变成引用，外面的变量仍然不变。
  4. 对 int 实例化 operator()(const int&)，对 std::string 实例化 operator()(const std::string&)；函数体里的操作必须对每个类型都合法。
  5. 能装函数指针、lambda、函数对象等所有满足 int(int) 调用的目标；代价是类型擦除后的间接调用、可能的堆分配，以及拷贝时可能复制闭包。
