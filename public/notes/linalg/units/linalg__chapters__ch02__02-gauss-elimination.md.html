2.1 先看工程长什么样

上一单元把矩阵当成一个「层」：输入向量进去，输出向量出来。这一单元反过来问一个问题——已知输出 b 和这一层 A，能不能把输入 x 找回来？写成式子就是 Ax=b。求解它不需要先算出逆矩阵，只需要一套规规矩矩的消元流程。

这一节先看清工程骨架。从第二个项目起，分册不允许单文件工程，所以这里把声明和实现分开：include/ 放头文件，src/ 放两个源文件，再用一个清单把它们和共用库串成一条编译命令。

第 1 帧是故事里的起点：chapters/ch02/ 和 examples/ch02/ 都还是空目录。第 2 帧标出这一节新增的东西——那个 +消元单元正文 节点在磁盘上就是 chapters/ch02/02-gauss-elimination.md，图里只留短名，是为了让节点文字足够短；真正的工程落在 examples/ch02/gauss_solve/，它有一个头文件 gauss.h、一个算法实现 gauss.c、一个驱动 main.c 和一个清单。共用库 common/ 不是这一节新增的，所以两帧里都没有把它画成新增项，但编译命令里照样要带上它。

大白话为什么头文件非要单独放一个目录

你可以把 main.c 和 gauss.c 拼成一个文件，把函数都堆在 main 上面，程序照样跑。分开的理由是接缝可见：gauss.h 只有几行声明，看一眼就知道这个例子对外提供什么能力、需要什么类型；gauss.c 里装着怎么做的细节，改它的时候不用碰驱动。代价是你要多学一条 include 规则：源文件写 #include "gauss.h"（不带路径），编译命令用 -Iinclude 告诉编译器去哪找它。头文件有 #ifndef 保护，所以两个源文件同时包含它也不会重复定义。

2.2 解方程不等于求逆：先把这件事说清楚

新手最容易冒出来的念头是：既然要解 Ax=b，那就先算 A 的逆矩阵 A⁻¹，再算 x=A⁻¹b。数学上没错，工程上却多半不这么做，原因有三层。

第一层是活儿更多。求逆相当于解 n 个右端向量（分别取单位向量的每一列），而解方程只需要解一个。你为了拿一个答案，顺手多算了 n-1 个用不上的答案。

第二层是精度更差。逆矩阵的元素会放大舍入误差，尤其当 A 接近奇异时，A⁻¹ 里的数会变得很大；再拿这个很大的矩阵去乘 b，误差被二次放大。直接消元只走一遍，少了一次「先放大再相乘」的机会。

第三层是结构会丢。现实里的矩阵常常是稀疏的——神经网络一层里绝大多数权重可能接近零，或者来自图结构的邻接关系只有少量连边。求逆会把稀疏矩阵变成稠密矩阵，内存和计算量都爆掉；消元至少还能在每一步跳过已经为零的位置。

所以这一单元只做一件事：给定 A 和 b，求出 x，但不显式构造 A⁻¹。流程分三段：选主元、向下消元、向上回代。每一段都只动矩阵的一行或一列，最后再算一个残差 ‖Ax-b‖ 自查。

把 Ax=b 换个看法会更有意思。按行读，每一行是一个方程，三个方程联立才定出三个未知数；按列读，A 的三列是三个向量，b 是它们的线性组合，未知数 x0,x1,x2 就是组合系数。第 2 单元讲过线性组合与张成，这里正好接上：解方程其实是在问「要用多少倍的列向量，才能拼出 b」。如果三列张成整个三维空间，这个组合唯一；如果三列共面，b 落在平面外就无解，落在平面内就有无穷多组系数。消元做的是同一件事的机械版本——它不关心几何图像，只老老实实把系数一个个算出来。这个双重视角在后面讲行列式、秩和逆时都会回来。

陷阱把「有解」当成「解唯一」

你会看到方程组有三个方程三个未知数，第一反应是「肯定有唯一解」。你会按这个预期去回代，结果主元位置出现 0，除零之后屏幕上跳出一串 inf 或 nan。你会怀疑是 printf 的格式写错了，或者怀疑编译器抽风。真相是：方程的个数和未知数的个数相等，既不保证有解，也不保证解唯一。三行里如果有一行是另外两行的线性组合，实际约束就只剩两个，解会形成一条直线；如果还互相矛盾，就一个解都没有。主元变成 0 正是这件事在算法里的信号，不是程序的 bug。

2.3 消元三步：挑主元、往下消、往回代

我们用这个方程组做贯穿全单元的例子，它的答案刚好是整数，方便你手算核对：

  • 第 0 行：0·x0 + 2·x1 + 1·x2 = 1
  • 第 1 行：1·x0 - 2·x1 - 3·x2 = -5
  • 第 2 行：3·x0 - 1·x1 + 2·x2 = 13

注意第 0 行第 0 列是 0。如果老老实实拿它当除数，第一步就崩了。这就是「部分选主元」要解决的问题：在当前列的未处理行里，挑绝对值最大的那一个，把它换到主元位置。下面四帧把整个过程走一遍。

第 2 帧是部分选主元的全部动作：只换行，不换列。只看当前列 k 以下的部分，找 |a[i][k]| 最大的行 piv；如果最大的恰好是 0，说明这一列从 k 往下全是 0，矩阵奇异。换行时同时交换右端向量 b 的对应两项——很多人只交换矩阵的行、忘了交换 b，结果方程组被悄悄改了。第 3 帧是消元：对每个 i>k，算倍数 f=a[i][k]/a[k][k]，令第 i 行减去 f 倍主元行，并把 a[i][k] 直接写成 0。第 4 帧的回代从下往上：最后一个方程只含 x2，解出 3；倒数第二个方程含 x1 和 x2，解出 -1；最上面那个方程含三个未知数，但后两个已知，解出 2。

把第 3 帧的分数摊开看，你会更清楚每一步在算什么。第 0 行换上来之后是 3x0-x1+2x2=13；消第 1 行时倍数是 1/3，于是 -2-(-1)/3=-5/3、-3-2/3=-11/3、右端 -5-13/3=-28/3。再处理第 1 列，主元是换上来的 2，把第二个方程减去 -5/6 倍主元行，最后一行第 2 列变成 -11/3+5/6=-17/6，右端变成 -28/3+5/6=-17/2。回代时 x2=(-17/2)/(-17/6)=3，x1=(1-3)/2=-1，x0=(13-1-6)/3=2。这些分数在屏幕上会被打印成小数，但手算时保留成分数反而更容易检查。

下面是头文件里的接口和算法里选主元那一段。读代码时把 k 想成「当前正在处理第几列」，piv 想成「这一列最该站到主元位上的是第几行」。

第 18 行那个 1e-12 是奇异阈值，不是数学上的「等于 0」。浮点数几乎不会精确等于零：一次除法、一次乘法就可能留下 1e-17 这样的尾巴。如果不设阈值，程序会拿一个极小的数当除数，得到一个极大的倍数，把本来有用的行彻底污染。返回 0 表示「消元失败，矩阵奇异」，调用者据此判断方程组没有唯一解。这个阈值是工程惯例，不是标准规定的常数；矩阵尺度很大或很小时，还要按规模缩放它。

2.4 回代与残差：怎么知道答案没算错

消元把矩阵变成上三角，回代就是把上三角「拆回去」。代码里 i 从 n-1 递减到 0，先算 x[i]，再用已经算出来的 x[i+1..n-1] 把它修正。注意第 30–38 行消元时把 a[i][k] 写成了 0，所以回代的内层循环从 j=i+1 起就够了。

解出来之后，程序做一件很多人会跳过的事：把解代回原方程，看残差。残差定义为 r = Ax - b，它的范数 ‖r‖ 越接近 0，说明解越可信。这一步用的还是第 1 单元的向量工具：mat_vec 算 Ax，vec_sub 算 Ax-b，vec_norm 取长度。共用库在这里第一次跨单元发挥作用——你不用重写点积和范数。

驱动 main.c 把矩阵和右端向量装进共用库的结构，调用算法，然后按固定格式打印。打印格式刻意只让纯数值行出现在 x0= 这一类键后面，solved 和 swaps 也是数值，所以整段 stdout 都是可解析的——闸门会逐行拿清单里的黄金值做容差对账。

这个方程组是刻意挑的：解是整数，矩阵元素也是整数，消元过程中出现的分数刚好能整除到底，所以残差精确为 0。别把这个 0 当成「浮点计算永远不会错」的证据。把 bv 改成 1.0000001，再跑一次，你会看到解变成一长串小数、残差变成 1.000000e-07 附近——残差不是零，但它正确反映了你改动了多少。真正判断解可不可信，要看残差相对于 ‖b‖ 和 ‖A‖ 的大小，而不是只看它是不是字面意义上的 0。

残差还有一个容易忽略的用法：定位哪一行出了问题。把 r=Ax-b 的三个分量分别打出来，哪个分量明显偏大，就回头看对应的那个方程和它在消元时被哪一行消过。本例的残差是零向量，说明三行都对上了。真实数据里残差往往不会精确为零，这时要看它相对于 ‖b‖ 的比例；比例在 1e-12 量级通常可以接受，到了 1e-3 就该怀疑数据或算法。另外，残差小并不总是等于解准——当矩阵病态时，一个错误的解也可能给出很小的残差，这需要条件数来判断，本册不展开这条线。

工程惯例为什么打印用等号而不是冒号

第 1 单元里向量打印用的是 a:[...]，因为方括号里的东西不是数值，闸门会把它当普通文字逐字比较。这里反过来：x0=2.000000 是标准的 key=value 数值行，闸门会解析它并和清单的黄金值做容差对账。格式选哪种，取决于你想让闸门怎么验：要验「一字不差」就用冒号或非数值形式，要验「数值在容差内」就用等号加有限小数。清单 la04-gauss.json 里 expect.numbers 写了六个键，各给 atol=1e-6，所以你没法靠改正文里的数字蒙混过关。

2.5 奇异矩阵：主元消失时长什么样

现在换一组系数，看看算法「失败」的样子。考虑方程组 x0+x1+x2=1、x1+x2=2、2x1+2x2=4。第三个方程正好是第二个的两倍，所以真正独立的约束只有两个。

第 2 帧里 r2 变成 0=0，这不是矛盾，而是「这一行没提供新信息」。算法在第 1 列之后找不到非零主元，于是返回 0。第 3 帧说明后果：x2 可以任取， x1=2-x2、x0=-1 跟着变，解是一整条直线上的无穷多个点。你把 x2 取 0 得 (x0,x1,x2)=(-1,2,0)，取 1 得 (-1,1,1)，两组都满足原来的三个方程——这就是「解不唯一」的具体含义。

如果第三行改成 2x1+2x2=5，消元后会出现 0=1 这样的矛盾式，这时连解都没有。从算法角度看，两种情况都会在主元位上遇到零；要区分「无解」和「无穷多解」，得继续检查右端是否也同时归零。本单元的例子只负责把「没有唯一解」这件事报告出来，不做更进一步分类。

陷阱用 `if (pivot == 0.0)` 判断奇异

你会觉得「数学书上写主元为 0 就奇异，那我就写 == 0.0」。你会看到程序在绝大多数时候正常工作，于是放心了。直到某天主元是 3.2e-17——它在数学上应该是 0，只是被浮点误差污染了——你的判断放它过关，接着拿它当除数，倍数变成 1e16 量级，后面所有行都被冲垮。屏幕上打印出的解是一串 nan 或大到离谱的数，你却以为算法写错了。真相是：浮点比较要用容差，这就是源码里 fabs(...) < 1e-12 存在的原因。顺带说一句，C 语言里 NaN 有个讨厌的性质：nan != nan 为真，所以 if (x == nan) 永远抓不到它；真要查非有限数得用 isfinite。

2.6 复杂度：三层循环为什么是 O(n³)

看代码里的嵌套：外层 k 走 n 次；对每个 k，消元的内层 i 最多走 n-k-1 次；对每个 (k,i)，更新 j 最多走 n-k-1 次。把三层乘起来大约是 n³/3 次浮点更新，所以叫 O(n³)。回代只有两层，是 O(n²)，在主项面前可以忽略。

把数字放进去感受一下：n=3 时大约几十次更新，手算都行；n=1000 时约三亿多次，现代机器还要几秒；n=10000 时是一万亿量级，普通机器要跑很久。这就是为什么大规模问题要利用稀疏性、分块或迭代法，而不是傻套高斯消元。

顺便区分两个常被混用的词。部分选主元只在当前列下面找最大者，换行不换列，代价小，是工程默认；完全选主元在整个未处理子矩阵里找最大者，行列都换，更稳但要多做比较和列交换，还要记住列的置换才能把解排回原来的顺序。本例用的是部分选主元，所以你看到的 swaps=2 只记了行交换。另一个常见问题是缩放：如果某一行的系数整体比别行大一万倍，按绝对值挑主元会偏向它；工程上会先把每行按最大元素归一化再挑，这叫按行平衡的选主元。

这一节和深度学习的关系在这里：Ax=b 形式的线性系统到处都是。最小二乘的正规方程是 (XᵀX)w=Xᵀy，牛顿法要解 HΔ=-∇f，某些隐式微分方程每步也在解线性系统。框架替你调了库，但库里跑的就是这套「选主元—消元—回代」的流程；当训练报出矩阵奇异、Hesse 矩阵不可逆时，你在这一节学到的主元消失正好就是根因。下一单元从另一个角度看同一个矩阵：行列式。它会告诉我们「主元乘积」在几何上到底是什么。

2.7 为什么非要选主元：误差放大的算术

2.7.1 消去倍数就是误差放大器

消元时，用主元行消去第 i 行，用的倍数是 f = a[i][k] / a[k][k]。这个 f 不只是「要减多少倍」的记账符号，它还是误差放大器。设主元行里的数带有微小舍入误差 ε，那么 f 倍的误差 fε 会被写进第 i 行；若 |f| 很大（比如主元 a[k][k] 很小），fε 就会远大于 ε，原本不起眼的误差被放大成显眼的污染。更糟的是，被污染的行如果成为后续步骤的主元行，误差会继续传递、逐级放大。

举个具体的数：主元是 1e-8，待消元素 a[i][k]=1。那么 f=1e8，主元行里一个 1e-16 量级的舍入误差，乘上 1e8 就变成 1e-8——已经和主元本身同量级。再消几步，误差会盖过真值。反过来，若我们挑绝对值最大的元素当主元（比如同列下面有个 3），则 |f| ≤ 1，误差不会被放大。这就是部分选主元的全部理由：让每个消去倍数的绝对值都不超过 1，从而抑制误差增长。它不是为了「好看」，是数值稳定性的硬性要求。

2.7.2 为什么只换行、不换列

部分选主元只在当前列 k 的下方找最大者，换行不换列。这样做的代价是 |f| 只能保证不超过 1（因为同列最大值作分母，分子不超过分母），不能保证所有元素都理想；好处是简单且够用。完全选主元会在整个未处理子矩阵里找最大者，行列都换，稳定性更好，但代价是：要维护列置换记录，最后把解的分量按原来的变量顺序排回去；比较次数也更多。工程上部分选主元是默认选择——绝大多数实际矩阵它已经足够稳，额外的复杂度不划算。本单元 swaps=2 记录的只有行交换，正说明用的是部分选主元。

还有一个常常被忽略的变量：按行缩放。若某一行整体系数都比别行大一万倍，按绝对值挑主元会偏向它，即使它在真实尺度上并不重要。工程上会先把每行除以该行最大元素（相当于给每行归一化），再挑主元，这样比较的是相对大小。这叫「按行平衡的选主元」。本例的行尺度相近，用不上，但遇到来自不同物理单位的数据（比如一列是米、一列是毫米）就至关重要。

2.7.3 消元其实是在做 LU 分解

把消元过程换个角度记，会得到线性代数里最重要的分解之一。每一步消元「第 i 行减去 f 倍主元行」，等价于左乘一个单位下三角矩阵 L_k（对角线全 1，第 (i,k) 位置是 -f）。把所有消元步骤连起来：L_{n-1}...L_1 A = U，其中 U 是上三角。两边左乘逆矩阵得 A = (L_1⁻¹...L_{n-1}⁻¹) U = LU，其中 L 是单位下三角矩阵，装着所有的消去倍数 f。选主元则进一步引入置换矩阵 P：PA = LU。

这个视角解释了两件事。第一，Ax=b 的解法可以拆成：先解 Ly=Pb（前代，因为 L 是下三角），再解 Ux=y（回代）——这正是消元的矩阵化描述。第二，求逆为什么多余：一旦有了 LU，解多个右端向量 b 只需复用同一个分解，每次只做前代回代（O(n²)），不必重新消元（O(n³)）。深度学习里求解线性系统、计算行列式（det A = det P · det L · det U = ±∏uᵢᵢ，即主元乘积），底层都是这套分解。你在代码里一步步写的 f，就是 L 的元素；屏幕上 swaps=2 记的，就是 P 的置换次数。

陷阱主元很小不等于矩阵奇异，但确实危险

新手容易走两个极端：要么见到小主元就断定「奇异、无解」，要么觉得「不是零就能除」。真相在中间。主元小可能是因为矩阵接近奇异（真的病态），也可能只是列尺度选得不好；后者通过换行或缩放能解决。但即使不奇异，拿小数做除数仍会放大误差。所以源码用 fabs(pivot) < 1e-12 当报警线：低于它就返回失败，让调用者去判断是尺度问题还是真的奇异。阈值 1e-12 是经验值，矩阵元素普遍很大时（比如 1e20）它太松，普遍很小时太紧——真实工程会按矩阵范数缩放阈值。

2.8 失败模式：从 nan 到「解对了却不可信」

2.8.1 忘了同步交换 b，方程被悄悄改掉

换行时如果只交换 A 的行、忘了交换 b 的对应项，得到的不是原方程组的重排，而是一个全新的方程组。现象很隐匿：程序照样给出一组有限解、residual 也照常计算，但残差是拿「被改过的 A」和「没跟着改的 b」算的，可能对不上原问题——若你再用原始问题验算，会发现解根本不满足。闸门能发现吗？只有在正文黄金值来自「正确交换」时才会报数值不符；若连黄金值都来自错误版本，闸门照样通过。这再次说明：闸门保证的是一致性，不是正确性。防御办法是把换行封装成一个同时操作 A 和 b 的函数，别让调用者有机会只改一个。

2.8.2 病态矩阵：残差很小，解却完全错

这是最危险的一类失败。考虑矩阵 [[1,1],[1,1.0001]]，条件数约 2e4。右端稍作扰动 b=(2,2.0001)，解就从 (1,1) 附近变成 (2,-1) 附近——变化巨大。但在这两个解上，残差 ‖Ax-b‖ 都很小（因为矩阵把某些方向的误差压得很扁）。换句话说，残差小不能证明解准，只能证明「代回去对得上」。判断解的可信度要看相对残差 ‖r‖/(‖A‖‖x‖) 与条件数 κ(A) 的乘积：这个量大约才是解的相对误差上界。条件数很大时，即使残差机器精度级，解也可能错得离谱。这里不展开条件数的计算（那是第 3 章的主题），但你要记住这条结论：病态问题的「小残差」是陷阱，不是安慰。

2.8.3 阈值选错的两个方向

奇异阈值 1e-12 若设得过大（比如 1e-2），会把正常但偏小的主元误判为奇异，程序提前退出，打印 solved=0——明明有解却报无解。若设得过小（比如 1e-300），又放过了 1e-15 这种假小量，拿它做除数得到 1e15 量级的倍数，把后续行全部污染，解变成一串大数或 nan。两种错误在屏幕上都表现为「结果不对」，但根因相反。调试时先看 solved 和 swaps：若 solved=0 却预期有解，怀疑阈值太大；若解是 inf/nan，怀疑阈值太小或数据里本来就有非有限数。

实验记录亲手触发两种失败

把 bv 改成 1.0000001 再跑，观察解变成小数、残差约 1e-7——这是「输入扰动 → 解变化」的正常演示。再把矩阵某个主元位置改成 1e-14（让它数学上不该奇异但数值上接近），看程序是报奇异还是给出大数解。最后，故意把源码里交换 b 的两行注释掉（只改你自己的副本，别动仓库文件），看 residual 会变成多少。做完把文件恢复。这三个实验分别对应「扰动」「阈值」「同步交换」三类失败模式，跑一遍比读十遍描述都管用。

2.9 与深度学习的对应：训练里到处是线性系统

2.9.1 从正规方程到牛顿法

最小二乘的正规方程 (XᵀX)w=Xᵀy 是一个线性系统；牛顿法每步要解 HΔ=-∇f（H 是 Hesse 矩阵）；很多隐式微分方程每步也在解线性系统。框架替你调了库，库里跑的就是「选主元—消元—回代」这套流程。当训练报出「矩阵奇异」「Hesse 矩阵不可逆」时，根因正是本单元讲的主元消失——例如特征共线导致 XᵀX 降秩，或者损失曲面在某处平坦导致 H 奇异。读懂主元，你就能把这类报错翻译成具体的几何事实，而不是束手无策。

2.9.2 正则化为什么能救病态系统

岭回归把正规方程改成 (XᵀX + λI)w = Xᵀy，加上的 λI 把对角线上抬了一截，使矩阵远离奇异、条件数下降——这就是「正则化改善数值稳定性」的算术解释。它还有另一层身份：在牛顿法里给 H 加阻尼（Levenberg–Marquardt），目的同样是让线性系统可解且稳定。你本单元看到的「主元太小要小心」，在这些高级方法里变成了系统性的设计：主动改造矩阵，让它别落到主元消失的境地。从「被动检测奇异」到「主动改善条件」，这是数值线性代数走向工程实践的关键一步。

工程惯例一次解多个右端：为什么分解比重复消元划算

若要对同一个 A 解很多个不同的 b（比如一批样本的共同线性结构），不要每个 b 都从头消元一遍。按 2.7.3 的 PA=LU 视角，消元只做一次（O(n³)），之后每个 b 只需前代+回代（O(n²)）。这正是 2.2 节「求逆不划算」的正面版本：不显式求 A⁻¹，但复用分解。真实框架的线性求解器都提供「分解一次、求解多次」的接口，用的就是这个道理。本单元只解一个 b，看不出优势；一旦问题规模上到训练级别，复用分解就是数量级的节省。

2.10 手算核对：把分数一路算到底

2.10.1 主例的逐步验算

再用分数把贯穿全单元的例子走一遍，确认每一步。原始矩阵三行是 (0,2,1|1)、(1,-2,-3|-5)、(3,-1,2|13)（竖线右边是 b）。第 0 列绝对值最大的是第三行的 3，换行后主元行是 (3,-1,2|13)。

消第 1 行：倍数 f=1/3。新第 1 行 = 原第 1 行 - (1/3)×主元行：第 1 列 -2-(-1/3)=-5/3；第 2 列 -3-2/3=-11/3；右端 -5-13/3=-28/3。消第 2 行：f=0/3=0，第 2 行不变，仍是 (0,2,1|1)（原第 0 行）。

现在处理第 1 列：候选是 -5/3 和 2，按绝对值挑 2（当前最后一行），换行。新主元行 (0,2,1|1)。消新第 1 行（旧的 -5/3 行）：倍数 f=(-5/3)/2=-5/6。第 2 列 -11/3 - (-5/6)×1 = -22/6+5/6=-17/6；右端 -28/3 - (-5/6)×1 = -56/6+5/6=-51/6=-17/2。上三角完成。

回代：x2 = (-17/2)/(-17/6) = 3；x1 = (1 - 1×3)/2 = -1（用 (0,2,1|1) 那行）；x0 = (13 - (-1)×1 - 2×3)/3 = (13+1-6)/3 = 2。得到 x=(2,-1,3)，与屏幕一致。代回原方程验算：第 0 行 2×2+(-1)=3？注意原式是 0·x0+2x1+x2=2×(-1)+3=1，对；第 1 行 2-2×(-1)-3×3=2+2-9=-5，对；第 2 行 3×2-(-1)+2×3=6+1+6=13，对。三行全对，残差为零。

2.10.2 为什么这组数适合手算

主元 3、2、-17/6 都不为零，换行恰好两次，分数分母小、能整除到底。右端和系数都是整数，消元中出现的 -5/3、-17/6 是有理数，纸笔可算。解是整数 (2,-1,3)，便于代回验算。这组数据的设计目的，就是让「选主元—消元—回代」每一步都能被独立核对——你要相信程序，先得能用纸笔复现它。这与第 3 单元「手算锚点」是同一条纪律。

自测题深化自测（先自己答，再对答案）
  1. 消去倍数 f=a[i][k]/a[k][k] 为什么会放大误差？为什么选绝对值最大的主元能把 |f| 压到不超过 1？
  2. 部分选主元与完全选主元各换什么？为什么工程默认前者？
  3. 写出 PA=LU 的含义，并说明「消元等价于 LU 分解」如何解释「一次分解、多次求解」的高效。
  4. 某矩阵解出来的残差只有 1e-14，但解与已知答案差了 10%。可能是什么原因？该看什么量判断？
  5. 用分数手算：2x+y=5、x+3y=10。先写出增广矩阵，指出主元，再消元回代。
注深化自测答案
  1. 主元行的舍入误差 ε 乘上 f 后写进被消行，误差变成 fε；|f| 大时放大明显，若被消行后续又当主元行，误差继续传播。挑同列绝对值最大者作分母，分子 |a[i][k]| ≤ |a[k][k]|，故 |f| ≤ 1。
  2. 部分选主元只在当前列下方找最大者，换行不换列；完全选主元在未处理子矩阵里找，行列都换。前者比较次数少、无需记录列置换，稳定性对多数矩阵已足够，故为默认。
  3. P 是行置换（记录换行），L 是单位下三角（存消去倍数），U 是消元结果上三角。A=P⁻¹LU，解多个 b 时分解只做一次 O(n³)，每个 b 只做前代回代 O(n²)。
  4. 可能是矩阵病态（条件数很大）：小残差对应大的解误差。应看相对残差 ‖r‖/(‖A‖‖x‖) 与条件数的乘积来估计解的相对误差，而不是只看残差绝对值。
  5. 增广矩阵 (2,1|5)、(1,3|10)。第 0 列最大是 2，主元即第一行（无需换行）。倍数 f=1/2，第二行减 1/2 倍第一行：y 系数 3-1/2=5/2，右端 10-5/2=15/2。回代 y=(15/2)/(5/2)=3，x=(5-3)/2=1。验算 2×1+3=5、1+9=10，正确。

2.11 读图指引与「为什么不求逆」的量化

2.11.1 四张图各自该盯哪里

这一单元的 tree 用两帧标出「空目录 → 新增例子」，注意 + 号落在 gauss.h、gauss.c、main.c、清单四样上，共用库不属于本单元新增。graph 是消元过程的分步动画：第 2 帧的换行、第 3 帧的清零、第 4 帧的回代，三件事别混成一团；读图时问自己「这一帧相对上一帧多了什么动作」。memory 那张图把奇异情形摊开：第 2 帧 r2 变成 0=0，第 3 帧给出自由变量——这是「主元消失」的视觉版本。复杂度那张 graph 则用三层嵌套的箭头，把 O(n³) 的三个来源（外层 k、中层 i、内层 j）画出来。把图和代码的行号对照着看，复杂度就不再是背下来的结论，而是数出来的事实。

2.11.2 求逆到底多做了多少活

2.2 节说求逆「活儿更多」，这里把它量化。用高斯—若尔当法求 A⁻¹，相当于把 A 增广成 [A | I]，把左边化成单位矩阵的同时右边就变成 A⁻¹。对 n 阶矩阵，消元阶段大约 n³ 次运算，而回代阶段要对 n 个右端向量各做 O(n²)，合计又是 n³ 量级——总量约为直接解一个 Ax=b（约 n³/3 + n²）的三倍。若只解一个右端，求逆是纯浪费；若解 k 个右端，直接消元的成本仍是 n³/3 + k·n²，而求逆后再乘是 3n³ + k·n²，直到 k 接近 n 两者才相当。这就是 2.2 节「求逆相当于解 n 个右端向量」的精算版本。再叠加上「误差二次放大」和「破坏稀疏性」两条，工程上不显式求逆的理由就完整了。

工程惯例残差、条件数、正则化：一条串起来的线

本单元把三个概念分别讲了：残差衡量「代回去对不对」，条件数衡量「问题本身敏不敏感」，正则化通过改造矩阵改善条件。把它们串起来看：训练里的病态系统（特征共线、Hesse 奇异）会让解对扰动极度敏感，此时即使残差很小也不可信；正则化在矩阵对角线上加一项，抬高最小奇异值、降低条件数，从根上缓解问题。所以下次看到「加个 λI 让矩阵可逆」的说法，你要能翻译成「选主元不再消失、误差不再被巨幅放大」。这正是第 4 单元正定矩阵与第 5 单元 SVD 要展开的内容。

小结这一节的要点
  • 解 Ax=b 不必先求 A⁻¹：求逆是多做 n 倍的工作，还放大误差、破坏稀疏性；
  • 消元三段：在当前列选绝对值最大的主元并换行、向下消去、从下往上回代；换行时右端 b 必须同步交换；
  • 主元接近零用容差判断奇异，不能用 == 0.0；零主元意味着没有唯一解；
  • 残差 ‖Ax-b‖ 是自查手段，本例真跑得到 x=(2,-1,3)、residual=0；
  • 复杂度来自三层嵌套循环，是 O(n³)，这是大规模线性系统必须利用结构的原因。

注自测题答案
  1. 第一次在第 0 列挑到 3（原第 2 行），换上来后主元是 3；消完第 0 列后，第 1 列剩下的两个候选是 -5/3 和 2，按绝对值挑 2，所以还要把当前第 2 行换到第 1 行。
  2. 一次行交换等价于交换方程组里两个方程的书写顺序，方程组本身没变；b 是方程右边的常数，必须跟着它那一行走。只换矩阵不换 b，等于把两个方程的左边互换而右边留在原地，得到的是另一个方程组，解自然错了。
