9.1 先看工程长什么样

这一单元从「特征值」走到「优化」。前面 la07、la08 都在问「一张矩阵把向量拉成什么样」，现在要问一个更实用的问题：给定一张对称矩阵 A，二次函数 q(x) = xᵀAx 长什么样，它的最低点在哪？答案要落到 Cholesky 分解上——它是正定矩阵的专属「平方根」，也是很多优化算法内部真正的计算底座。

老规矩，先用一个 2×2 的例子把每一步打出来。用 C 写的好处是：sqrt 取正根还是负根、A - LLᵀ 是不是真的为零，都在屏幕上，不用靠想象。

第 1 帧是起点：ch04 目录还空着。第 2 帧里新增一个 cholesky/ 工程，包含头文件、算法、驱动和数值清单。共用库照旧从 ../../common/include 引入，矩阵转置和范数都从那里取，不重复造轮子。注意这是第二个章节下的工程，所以清单的 sources 列了三个 .c 文件，并且头文件真的被 #include "chol.h" 引用——这两条是硬规定，缺一条闸门就报 single_file_project_forbidden。

大白话二次型就是「带交叉项的平方和」

把 xᵀAx 展开看看。若 A = [[a,b],[b,c]]，那么 xᵀAx = a·x0² + 2b·x0·x1 + c·x1²。它长得像一个二次多项式，只不过多了个交叉项 2b·x0·x1。矩阵写法的好处是：不管维度多高，都写成同一个 xᵀAx，而「正定」这种性质也能统一成一句判断——对所有非零 x 都有 xᵀAx > 0。用大白话说：无论你往哪个方向走，这个函数都往上翘，原点就是唯一的坑底。

工程惯例为什么对称矩阵的交叉项是 2b

xᵀAx 展开时， off-diagonal 的两个 b 会各贡献一次，合起来是 2b·x0·x1。所以写矩阵时只填一个 b，写多项式时却是 2b。新手常在这里把矩阵填成 [[4,4],[4,5]]，结果算出的交叉项多了一倍。约定俗成的做法是：对称矩阵只存一半，展开时自己补上 2。这一册的 mat_make 没有强制对称检查，责任在你。

你可能会问：一个二次函数的最低点，跟深度学习有什么关系？关系很大。训练一个模型，本质上就是在一个极高维的参数空间里找损失函数的最低点；而在任何一点的局部，损失函数都可以用一个二次函数近似。于是「这个二次近似是不是碗形」直接决定了优化器能不能稳定往下走。上一单元的 SVD 告诉我们数据有哪些方向，这一单元的 Cholesky 告诉我们二次型的碗有多陡、有没有唯一的底。把这两件事看透，后面读 Adam、L-BFGS 的实现才不会只把它们当黑箱。

还有一个容易含糊的点：这里说的「碗」是严格凸的碗，不是马鞍面。马鞍面在一个方向向上、另一个方向向下，沿着某个方向走会一直下降，没有最低点。正定条件 xᵀAx > 0 排除了马鞍面的可能——它要求每一个方向都向上翘。这就是为什么判定必须检查所有特征值，而不是只检查几个。

9.2 碗形等高线：正定到底在说什么

取我们的例子 A = [[4,2],[2,5]]，那么 q(x) = 4x0² + 4x0x1 + 5x1²。沿着任何一条从原点出发的直线看过去，q 都是「距离平方 × 某个正数」——因为没有一次项，也没有常数项，原点必然是驻点；又因为系数为正，离开原点 q 只会变大。把等高线画在纸上，是一圈圈套着原点的椭圆。

第 1 帧里主轴不是坐标轴，而是 A 的特征向量方向；第 2、3 帧说明等高圈为什么是椭圆而不是圆——沿着长轴走，同样的 q 增量要走更远。把这三帧和 la07 的谱分解放一起读，你会看到同一件事的两种说法：A = QΛQᵀ 里的 Λ 决定了椭圆两个半轴的长度，Q 决定了椭圆朝哪个方向摆。

正定 ⇔ 特征值全正

现在给判定准则。把 A 写成谱分解 A = QΛQᵀ，代入二次型：

xᵀAx = xᵀQΛQᵀx = (Qᵀx)ᵀΛ(Qᵀx) = Σ λᵢ · yᵢ²，其中 y = Qᵀx。

因为 Q 正交，y 跑遍所有非零向量；于是 xᵀAx > 0 对所有非零 x 成立，当且仅当每个 λᵢ > 0。这就把「对所有方向都正」这个无限条件，压缩成「数有限个特征值」。本例的 A 迹为 9、行列式为 16，特征值是 (9 ± √17)/2，约 6.561553 与 2.438447，全正，所以正定。

这个换元过程值得多看一眼，因为它以后会反复出现。正交矩阵 Q 的列就是 A 的特征向量，Qᵀx 相当于把 x 的坐标换到特征向量这组基底下。在新坐标里，A 变成对角阵 Λ，二次项之间不再有交叉耦合，于是 yᵀΛy 只是若干个独立的平方加权求和。所谓「换一组坐标看同一件事」，在这里有了最直白的体现：不是矩阵变了，是描述它的基底换了。把这件事记住，下一单元看那些转置从哪来时会更轻松。

2×2 情形还有一个手算友好的判据，叫 Sylvester 准则：a > 0 且 ac − b² > 0（顺序主子式全正）就正定。它和「特征值全正」等价，但不用解二次方程。你会问已经有了特征值判据为什么还要它——答案是手算快，而且在代码里可以直接检查两个标量，不必先做一遍特征分解。代价是它在高维要检查 n 个主子式，不如 Cholesky 那样一次分解顺便给出解。

陷阱对角元全正不等于正定

你会盯着 [[4,2],[2,5]] 的对角元 4 和 5，觉得「对角都是正的，肯定正定」。再试 [[1,2],[2,1]]：对角元都是 1，但特征值是 3 和 −1，沿着 (1,−1) 方向代进去得到 −2 < 0，它是不定矩阵。你会怎么误判？因为只看对角线，忽略了两个对角元夹角方向上的耦合。真相是交叉项 2b 可以大到把某个方向拽成负曲率；2×2 的判据是 a > 0 且 ac − b² > 0（顺序主子式全正），高维就用特征值或 Cholesky 是否成功来判。

工程惯例正定与半正定的分界

如果允许 xᵀAx ≥ 0（可以等于 0），就叫半正定。差别只在有没有「平坦方向」。协方差矩阵就是典型：把一组样本中心化后拼成数据矩阵 X，协方差 Σ = XXᵀ/(m−1)，对任意 v 有 vᵀΣv = ‖Xᵀv‖²/(m−1) ≥ 0，永远非负；但如果样本全都躺在一条直线上，就存在一个方向让这个值为 0，Σ 只是半正定。这也解释了 la08 里为什么可以用 SVD 做 PCA——数据集中在一个低维子空间时，协方差有一批零特征值，对应的奇异值也接近零。

9.3 Cholesky：给正定矩阵开平方

正定矩阵最实用的分解是 A = LLᵀ，其中 L 是下三角、对角元为正。它相当于矩阵的「平方根」，但比 √A 更省事：只用一个三角因子，求解时只要两次回代。对 2×2 情况，三个元素可以直接写出来：

l00 = √a00，l10 = a01/l00，l11 = √(a11 − l10²)。

本例 a00 = 4，所以 l00 = 2；l10 = 2/2 = 1；a11 − l10² = 5 − 1 = 4，所以 l11 = 2。三个数字就把 A 完全装下了。注意 l00、l11 都取正根：这是分解约定，取负根虽然也能让 LLᵀ = A，但会破坏后续回代的唯一性。

第 1 帧里上三角那格永远是零，这正是「下三角」的意思；第 2 帧显示重建怎么把三个数摊回对称阵：A[0][1] = A[1][0] = l00·l10。所以 Cholesky 的存储量只有对称矩阵的一半——高维时能省下近一半内存，这是它在工程里受欢迎的直接原因。

第 15 行那次减法叫做「Schur 补」：把第一个方向已经解释掉的部分扣掉，剩下的才是第二个方向独立的能量。如果 A 只是半正定而非正定，d 可能算出 0（甚至因为舍入算出 −1e−16），程序会直接判失败。这正是我们想要的——宁愿明确报错，也不要悄悄给出一个带 NaN 的因子。

Cholesky 在工程里还有一个常被忽略的优点：数值稳定。求正定矩阵的逆再左乘右乘，会引入更多舍入误差；而 Cholesky 只做开方和除法，每一步都被对角元控制住。高维协方差矩阵求逆时，人们宁可做两次三角回代，也不愿意显式构造逆矩阵——不仅因为快，也因为准。当然它也不是没有代价：A 必须严格正定才可用，半正定就得先加 jitter，这是稳定性的另一面。

9.4 回代：为什么求解不用先求逆

la04 讲过解 Ax = b 不要显式求逆。Cholesky 给出更干净的两步：先解 Ly = b（前代），再解 Lᵀx = y（回代）。因为 L 是三角阵，每一步只有一个未知量，复杂度是 O(n²)，而先求逆再乘要 O(n³)。本例的 b = (6,9)：前代得 y0 = 6/2 = 3、y1 = (9 − 1×3)/2 = 3；回代得 x1 = 3/2 = 1.5、x0 = (3 − 1×1.5)/2 = 0.75，与真跑一致。

注意第 23 行用 l00 做分母、第 26 行又用 l00 做分母——一个在前代、一个在回代，位置不同、含义不同。把它们搞混是初学者最常见的错误：前代用 L 自己，回代用 L 的转置，所以第二遍才轮到 l11 先出场。写成矩阵看就是 L Lᵀ x = b，先消掉 L，再消掉 Lᵀ。

把复杂度摊开算一笔账。高斯消元对一般的 n×n 矩阵是 O(n³/3) 次乘加；Cholesky 利用对称性，只算一半，大约 O(n³/6)，省掉一半；随后两次三角回代各是 O(n²)，在 n 很大时相比分解本身几乎可以忽略。这就是「先分解一次、反复回代」划算的原因：训练时同一个 Hessian 结构可能要解很多次不同右端，分解只做一次，回代每次都很便宜。代价是分解需要矩阵正定，而一般高斯消元不需要——你没有免费的午餐。

陷阱残差为零不等于矩阵正定

你会想：残差 0 说明 LLᵀ = A 成立，那 A 一定正定吧？这里有个坑。只要允许 l11 = 0，半正定矩阵也能写出 LLᵀ；我们的 chol2_factor 在第 16 行用 d <= 0.0 把这种情况直接拒掉，所以程序里不会出现。但如果你把判据改成 d < 0.0，一个秩 1 的半正定矩阵就会通过，随后 chol2_solve 拿 0 当分母，输出 NaN。真相是：残差只验证分解算得对，不验证分解存在；存在性靠对角元为正这条约束保证。

9.5 从碗形到深度学习：Hessian 与协方差

现在把这一单元和深度学习接上。大多数训练目标都是 f(w) = ½‖Wx − y‖² 这类二次函数或它的推广。在一个驻点附近做二阶近似：f(w+δ) ≈ f(w) + gᵀδ + ½δᵀHδ，其中 H 是 Hessian（二阶导数矩阵）。如果 H 正定，那么对任何非零 δ 都有 δᵀHδ > 0，二次项是正的——驻点必然是严格局部极小点，而且因为整个二次近似是凸的，这个极小点唯一。这就是「Hessian 正定 ⇒ 唯一最低点」的全部理由：不是魔法，只是碗形在起作用。

再把「唯一」这件事说透。如果 H 只是半正定，二次项 δᵀHδ 可能为零，那么沿那个平坦方向走多远损失函数都不变——最低点是一整条线而非一个点，优化器会漫无目的地漂。如果 H 不定，就存在让二次项为负的方向，驻点其实是马鞍点，沿那个方向走反而下降。只有 H 正定时，碗底才是一个孤立的点，牛顿步才有明确目标。这三条分别对应「不唯一」「不是极小」「唯一极小」，正好把优化里最常见的三种地形说全了。

牛顿法直接拿 δ = −H⁻¹g 跳到最低点，但前提是 H 正定；H 一旦不定，这一步可能往山顶走。实际网络里 H 通常不是正定的，所以 L-BFGS、Adam 这些方法都在用各种近似维护一个「像正定」的曲率矩阵。你以后看到「把 Hessian 加上阻尼 λI 变成正定」，那就是 H + λI 的所有特征值都平移 λ，把负的抬成正的——和本节的判定准则是同一件事。

另一条联系是协方差。深度学习里做 PCA 白化、做高斯分布的协方差估计，都要处理 Σ = E[(x−μ)(x−μ)ᵀ]。前面 practice 里已经证明它半正定；当数据维度高于样本数时，Σ 必然有零特征值，也就是奇异的。这时候想求 Σ⁻¹ 就会失败，而 Cholesky 也会在 d <= 0 处拒绝。工程上的解法是加一个很小的对角项：Σ + εI，人为把所有特征值抬离零。这个 ε 叫 jitter，是深度学习代码里非常常见的技巧——它和「Hessian 加阻尼」是同一个想法的两次出场。

把这些串起来看，la08 的 SVD、la09 的 Cholesky、la10 的矩阵微分其实是同一条线索的三段：SVD 告诉你数据有哪些方向、每个方向多重要；Cholesky 告诉你一个正定的二次型怎么开方、怎么求最低点；矩阵微分告诉你这些量对参数怎么变。下一单元就把最后一段补齐，重点讲反向传播里那些转置到底从哪来。

9.6 主轴分解：椭圆的半轴长是 1/√λ

9.2 说等高线是椭圆，现在把椭圆的尺寸也算出来。在特征基下写 q(x) = Σ λᵢ yᵢ²，取等高线 q = 1，沿着第 i 根主轴走距离 t，有 λᵢ t² = 1，所以半轴长 t = 1/√λᵢ。特征值越大，碗在那个方向越陡，等高圈在那个方向就越短。本例 λ1 ≈ 6.561553、λ2 ≈ 2.438447，对应半轴约 0.390388 与 0.640388；等价地，最大特征值对应的特征向量 v1 ≈ (0.615412, 0.788205) 是短轴方向，v2 ≈ (0.788205, −0.615412) 是长轴方向。长短轴之比 √(λ1/λ2) ≈ 1.64，而条件数 κ = λ1/λ2 ≈ 2.690873。

这个比值不只是几何趣味，它直接决定优化难度。最速下降在二次碗上的收敛速度由 κ 控制：最坏方向的误差每步约按 (κ−1)/(κ+1) 衰减。κ 越大，椭圆越细长，算法只能在短轴方向来回振荡、沿长轴缓慢爬行。把坐标换到特征基并各轴除以 √λᵢ，椭圆变成圆，κ 变成 1，一步就能走到中心——这就是预条件、牛顿法与 Cholesky 求解在高维问题里受欢迎的原因：不是改变最低点，而是改变碗的形状。Cholesky 的 L 恰好提供了这次换坐标：先解 Ly = b 再解 Lᵀx = y，等价于在 L⁻¹AL⁻ᵀ = I 的新坐标里求解。

大白话读图指引：等高线图的三帧怎么连起来

9.2 的 graph 图第 1 帧只标出「主轴」是特征向量方向，注意它是星号节点：表示这一帧才引入的新概念。第 2 帧画最小的椭圆，标明「长轴伸得远、短轴收得紧」，这时要把 9.6 的结论补进去：伸得远的方向对应小特征值，因为半轴长是 1/√λ。第 3 帧画更大的椭圆，说明 q 从 1 增到 4 时圈按 √4 = 2 倍放大，所以等高线是一族相似椭圆。读这类图时别把「椭圆变大」理解成「矩阵变了」——矩阵没变，只是取的等高值变了。

9.7 Sylvester 准则为什么够

判定正定有两条路：查全部特征值，或查 n 个顺序主子式。后者的理由是它可以和 Cholesky 的对角元一一对应。记 A_i 为 A 的左上角 i×i 子矩阵，Cholesky 分解走到第 i 步时，对角元满足 l_ii² = det(A_i)/det(A_{i−1})（约定 det(A_0)=1）。这是因为第 i 步的 Schur 补正是「去掉前 i−1 个方向后剩下的独立能量」，它的行列式等于 det(A_i)/det(A_{i−1})，而开方后就是 l_ii。于是：所有顺序主子式为正 ⇔ 所有 l_ii² 为正 ⇔ Cholesky 能一路算到底 ⇔ A 正定。Sylvester 准则之所以够，是因为它查的 n 个数正是 Cholesky 途中依次出现的 n 个分母。

这里容易和另一条判据混淆：对称矩阵正定也等价于「全部 2^n−1 个主子式为正」，但它要查的量多得多。顺序主子式只查左上角那 n 个，看起来少得可疑，其实是因为对称性把其余主子式的信息绑定在一起了；没有对称性这个前提，顺序主子式全正并不能推出正定。本例 A = [[4,2],[2,5]] 的两个顺序主子式是 4 与 16，都正；反过来 [[1,2],[2,1]] 的顺序主子式是 1 与 −3，第二个就失败了，和「特征值 3 与 −1」的结论一致。

工程惯例手算核对：把 det、特征值、Cholesky 与椭圆连成一条线

A = [[4,2],[2,5]]：迹 9、行列式 20−4 = 16，所以 λ1,2 = (9±√17)/2 ≈ 6.561553 与 2.438447，乘积恰为 16、和恰为 9。Cholesky 因子 L = [[2,0],[1,2]]，行列式 det L = 4，而 det A = det(L)² = 16，对上。再看对角元与子式：l00² = 4 = det[[4]]，l11² = 4 = det A / det[[4]] = 16/4，正是 9.7 的公式。把 L 乘回去：LLᵀ = [[2², 2×1], [1×2, 1²+2²]] = [[4,2],[2,5]]，逐格对上 A，所以输出块的 residual=0.000000 不是空话。解也逐格验一次：Ax = (4×0.75+2×1.5, 2×0.75+5×1.5) = (3+3, 1.5+7.5) = (6,9)。最后看几何：半轴 1/√6.561553 ≈ 0.390388 与 1/√2.438447 ≈ 0.640388，短轴对应大特征值。行列式、特征值、Cholesky 对角元、椭圆半轴——四个数字从不同角度描述同一只碗。

9.8 数值失败模式：Cholesky 为什么会失败

理论上「正定 ⇔ Cholesky 成功」，但浮点世界里有中间地带。取 Aε = [[1,1],[1,1+δ]]，δ 在 1e-16 量级。它在数学上正定（行列式 δ > 0），可计算 l10 = 1/1 = 1 之后，Schur 补 d = a11 − l10² 只剩下 δ；若 δ 被舍入成 0 甚至 −1e-16，chol2_factor 的 d <= 0.0 就把这个合法矩阵判成失败，打印 not positive definite 并以非零退出码返回。反过来取 δ = 0 的半正定矩阵，数学上确实没有严格正定的 Cholesky，程序拒绝它是正确行为。两种情形在屏幕上长得一样，但一个是数值 limit，一个是数学事实。

如果有人为了「让程序跑通」把判据改成 d < 0.0，d = 0 会放行，于是 l11 = 0，chol2_solve 拿 0 做分母，解里出现 NaN。此时 stdout 的 x0=、x1= 不再是有限小数，闸门解析数值行时先报 numeric_value_invalid；若程序直接非零退出而清单期望 0，则先报 exit_mismatch。若它硬撑着输出几行却少了清单声明的键，报 numeric_key_missing；行还在但数值不对，报 numeric_value_mismatch。这就是为什么 9.4 强调残差要独立算：程序自报的 PASS 或「分解成功」都不可信，只有清单容差下的逐行对账可信。

陷阱失败模式：半正定、近奇异与非对称输入

三类输入会让这套代码失灵。第一类：协方差矩阵在样本数小于维度时必然半正定，d 算出零或负，程序拒绝；工程上先加 jitter，用 Σ + εI 把特征值抬离零，再分解。第二类：严格正定但条件数很大的矩阵，l00 很小导致 l10 巨大，随后 a11 − l10² 是两个相近大数相减，有效位数被吃掉——这是 catastrophic cancellation，不是判定逻辑错。第三类：浮点舍入让理论上对称的矩阵出现 a01 ≠ a10，代码只读上三角，重建的残差按完整 A 计算会有一个 1e-16 量级的差；用 %.6f 打印时它显示为 0.000000，看起来「没问题」，其实是被输出精度掩盖了。要抓它得把残差按科学计数法多打几位，或显式检查对称性。症状相同不等于病因相同：失败时先分清是数学上不正定、数值上太病态，还是输入根本不对称。

9.9 Hessian、协方差与优化的再对接

把 9.5 的牛顿法说透。在驻点 g = 0 附近做二阶近似，牛顿步是 δ = −H⁻¹g。若 H 正定，则 H⁻¹ 也正定，于是 gᵀδ = −gᵀH⁻¹g < 0（只要 g ≠ 0）——下降方向与梯度严格反向，步长不会把你送上山顶。若 H 有一个负特征值，沿对应方向 gᵀH⁻¹g 可能为负，牛顿步变成上升步。所以优化器要么检查 H 的正定性，要么加阻尼 λI：H 的特征值整体平移 λ，把负的抬成正的，这就是 Levenberg–Marquardt 与信赖域方法在做的事。要区分两个层次：某一点的 Hessian 正定只保证局部唯一极小；Hessian 在整个凸集上处处正定（半正定加上严格凸条件）才保证全局唯一极小。二次近似只在驻点邻域可信，走太远就得重算或做线搜索。

协方差那条线也要补一个细节。中心化样本满足 Σᵢ(x_i−μ) = 0，这带来一个线性相关，所以数据矩阵的秩最多是 m−1；协方差 Σ = XcᵀXc/(m−1) 的秩也最多 min(n, m−1)。这就是「样本数小于维度必然奇异」的精确说法。半正定的证明对每个 v 都成立：vᵀΣv = Σᵢ (vᵀ(x_i−μ))²/(m−1) ≥ 0，它是平方和，不可能为负；当所有样本落在 v 的正交补里时这一项为 0，于是有平坦方向。做白化时若直接求 Σ⁻¹/² 会撞上零特征值，工程上要么用 Cholesky 的 L⁻¹（此时 Σ ≈ LLᵀ），要么用 SVD 把接近零的倒数截断。加 εI 是在用一点偏差换稳定：白化后的协方差不再是精确的 I，但矩阵可逆、数值可控。

大白话常见误解速查

误解一：「对角线全正就正定」。9.2 的反例 [[1,2],[2,1]] 已经否掉它，要看的是所有方向。误解二：「半正定也有唯一最低点」。半正定允许平坦方向，最低点可能是一整条线，优化器会沿着它漂。误解三：「Hessian 正定等于函数全局凸」。它只说明这一点的局部碗形；全局凸需要在整个区域上都成立。误解四：「Cholesky 失败一定说明矩阵不定」。近奇异的正定矩阵也会因舍入失败，先检查条件数。误解五：「协方差矩阵一定可逆」。中心化后秩最多 m−1，样本少时必然奇异，必须加 jitter 或降维。

9.10 为什么判正定优先用 Cholesky，而不是先算特征值

给定一张对称矩阵，想知道它是否正定，理论上可以算全部特征值再看符号；工程上更常见的做法是直接尝试 Cholesky。原因有三条。第一，代价：Cholesky 约 n³/6 次乘加，特征分解通常要更多运算和更多中间存储；对高维协方差矩阵，这个差别很实在。第二，附带收益：分解成功后 L 就地可用，立刻能解不同右端的方程，而特征值还要另外重组才能求解。第三，判定与用途一致：你真正关心的是「能不能安全分解回代」，那就直接分解，成功即通过，失败即拒绝，不需要绕一圈问特征值。

代价是 Cholesky 对「差不多正定」的矩阵很敏感：特征值恰好为零时失败，特征值小到舍入级别时也失败。这既是缺点也是优点——它把病态矩阵拦在门外，逼你先决定要不要加 jitter、要不要降维。真正需要区分「半正定」和「不定」的场合，可以用带主元的 LDLᵀ 分解：允许对角元为零或负，但记录主元符号，从而数出正负特征值的个数；这对 Hesse 矩阵是马鞍点还是平坦谷底的判断很有用。本书只用 2×2 的 Cholesky 把直觉钉死，读到二阶优化时再回头看 LDLᵀ，会发现它不过是「允许对角元取负号」的推广。

工程惯例手算反例：Cholesky 在哪一步崩掉

取 B = [[1,2],[2,1]]：对角元都是 1，看着像正定。走一遍 Cholesky：l00 = √1 = 1，l10 = 2/1 = 2，d = a11 − l10² = 1 − 4 = −3 < 0，于是 chol2_factor 在第 16 行直接返回 0。崩点正是 Schur 补：第一个方向解释掉的能量已经超过第二个方向的总能量，剩下的独立能量是负的，开方无从谈起。用 Sylvester 准则更快：顺序主子式 1 与 det B = 1−4 = −3，第二个就失败。用特征值验证：迹 2、行列式 −3，λ² − 2λ − 3 = 0 给出 3 与 −1，有一个负。三条路指向同一个结论。再对比 [[1,2],[2,5]]：l00 = 1，l10 = 2，d = 5−4 = 1 > 0，l11 = 1，分解成功。这说明交叉项大不大不要紧，要紧的是它有没有把 Schur 补吃成负数。

陷阱Cholesky 因子的符号约定与「唯一性」

l00 = √a00 取正根，是为了让分解唯一、回代行为可预测。若取负根，比如对 A = [[4,2],[2,5]] 取 l00 = −2、l10 = −1、l11 = 2，LLᵀ 仍然逐格等于 A——注意 L 和 −L 给出同一个乘积，对角元同时翻号不改变 LLᵀ。但不同符号会让 solve 的中间量 y 变号，最后 x 却相同；若不统一约定，调试时看到中间量对不上就会误判。本书固定「对角全正」，所以屏幕上的 L 只有一个版本。另一个常见误解是以为 Cholesky 对一切对称矩阵都成立：对称但不定或半正定时，分解会在某一步失败；这不是程序 bug，而是正定这条前提没满足。

9.11 与 SVD 的对照：同一只碗的两种开方

上一单元用 SVD 把任意矩阵拆成 UΣVᵀ，这一单元用 Cholesky 把正定矩阵拆成 LLᵀ。两者都在「开平方」，但对象与性质不同。SVD 的 Σ 可以有零和任意谱分布，U、V 都正交，对任意矩阵成立；Cholesky 要求矩阵对称正定，只有一个三角因子，且对角必须为正。若 A 对称正定，它的 SVD 与谱分解重合（U = V = Q，Σ = Λ），于是可以写出另一种平方根 A^{1/2} = QΛ^{1/2}Qᵀ；Cholesky 的 L 则是另一种平方根，因为 LLᵀ = A 而 L 不要求对称。两者都可用，但用途不同：想要「保留主成分、做白化」时用特征基，想要「快速求解、反复回代」时用三角因子。

误差行为也值得对照。SVD 对扰动稳定，奇异值的变化不超过扰动矩阵的谱范数；Cholesky 对正定矩阵同样稳定，但一旦接近半正定，最小特征值附近的相对误差会急剧放大——因为 l_ii² 是 Schur 补，连续相减会累积舍入。所以处理高维协方差时，常见流程是：先做特征值或奇异值分析决定保留多少维，再用 Cholesky 在降维后的子空间里做求解与白化。先用 SVD 看谱，再用 Cholesky 干活，这是 la08 与 la09 在工程里最常见的搭配。

大白话读图指引：下三角-factor 图的两帧怎么看

9.3 的 memory 图第 1 帧画 L 的三个有效格子，上三角恒为零；读的时候注意 L[1][0] = 1 是交叉项 a01 = 2 除以前面的对角元 2 得来的，不是凭空填的。第 2 帧把三个数摊回 A，三行分别对应 A00 = L00²、A01 = L00·L10、A11 = L10²+L11²。把两帧叠起来看，你会意识到 Cholesky 的「存一半」不是省格子那么简单：它把对称约束变成了算法不变量——上三角永远不用存，重建时自动补齐。图上带星号的 A[1][1] = L10²+L11² 提示这是最容易算错的一格，很多人只加 L11² 忘了 L10²，残差就会在右下角露出 1.0 的偏差。

工程惯例三维手算：把 Sylvester 与 Cholesky 对上

试一张 3×3 的矩阵 A = [[2,1,1],[1,2,1],[1,1,2]]。三个顺序主子式分别是 2、4−1 = 3、det A = 4，全正，按 Sylvester 准则它正定。走一遍 Cholesky：l00 = √2，l10 = l20 = 1/√2；l11 = √(2−1/2) = √1.5；l21 = (1−1/2)/√1.5 ≈ 0.408248；l22 = √(2−1/2−0.166667) ≈ 1.154701。三个对角元全为正，分解成功。再核对乘积：l00·l11·l22 = √2×√1.5×√1.333333 = √4 = 2，正是 det L，平方后 det A = 4，与主子式的结论一致。这张矩阵的特征值是 4、1、1，全正；沿 (1,1,1) 方向拉伸最强，对应最陡的碗壁。三维的好处是能看见规律：l_ii² 依次是 det(A1)/det(A0) = 2、det(A2)/det(A1) = 3/2、det(A3)/det(A2) = 4/3，乘起来望远镜式相消，正好是 det A。

陷阱失败模式：细长碗上的梯度下降现象

把对角矩阵 diag(1000, 1) 当作损失曲率，它正定、Cholesky 也容易（L = diag(√1000, 1)），但条件数是 1000。梯度下降在短轴方向步长被 1000 限制，必须取很小的学习率才不发散；沿长轴方向每步却只走一点点，最坏方向的误差每步约按 (κ−1)/(κ+1) ≈ 0.998 衰减，几千步仍看不到明显下降。程序现象是 loss 曲线缓慢下滑、几乎水平，容易被误判成「学习率太小」，于是有人把学习率调大，结果短轴方向立刻爆炸成 NaN。真相是问题出在条件数而不是学习率：预条件把两个方向的尺度拉齐（对二次碗等价于乘 L⁻¹），曲线才会变陡。本例 κ ≈ 2.69，衰减因子约 0.458，十来步就能收敛，所以小例子体会不到这种痛；换成高维协方差或深层网络的 Hessian，它才是常态。

大白话读图回顾：从碗到因子的一条线

把这一单元的图按顺序重看一遍：等高线 graph 告诉你「碗」长什么样，主轴方向由特征向量给出、半轴长由 1/√λ 给出；memory 图告诉你 L 只存三个数，重建时靠对称补齐；代码旁的残差数字告诉你这条链真的闭合。三处出现同一个 det A = 16：等高线里它是 λ1λ2，Cholesky 里它是 l00²l11²，主子式判据里它是最后一个顺序主子式。同一个数字在不同表示里反复出现，正是线性代数最值得训练的直觉——形式换了，不变量没换。

小结这一节的要点
  • 二次型 xᵀAx 在 A 正定时是一张开口向上的碗，xᵀAx > 0 对所有非零 x 成立；
  • 正定 ⇔ 特征值全正 ⇔ Cholesky 分解能成功（对角元全为正）；对角元全正并不够；
  • A = LLᵀ 是正定矩阵的三角平方根，只存一半元素；求解 Ax=b 用前代加回代，复杂度 O(n²)；
  • Hessian 正定让二次近似变成碗形，从而驻点是唯一极小点；协方差矩阵只能保证半正定；
  • 黄金值和容差只写在清单 expect.numbers，正文贴真实 stdout，程序自报的 PASS 不算证据。

  2. 例如 [[1,2],[2,1]]，对角元都是 1，但特征值是 3 和 −1。取 x = (1,−1)，二次型为 1 − 4 + 1 = −2 < 0，所以不定。
  3. 令 y = Qᵀx，因为 Q 正交，y 也跑遍所有非零向量，且 xᵀQΛQᵀx = yᵀΛy = Σ λᵢyᵢ²。若所有 λᵢ > 0，各项非负且至少一个 yᵢ 非零，和必正；若某个 λᵢ < 0，取 y 只在该方向非零，和为负。正交性保证这个换元不丢失任何方向。
  4. 因为半正定允许某个对角元为零，此时 L 奇异，chol2_solve 会除以零得到 NaN。检查 d <= 0.0 让程序明确报「不是正定」，而不是悄悄产出坏结果；残差为零只验证等式成立，不验证分解可用。
  5. vᵀΣv = E[(vᵀ(x−μ))²] ≥ 0，所以只能保证非负；若样本落在低维子空间，存在 v 使它等于 0，Σ 奇异、Cholesky 失败。工程上加一个很小的 εI（jitter）把特征值抬离零，等价于给 Hessian 加阻尼。
  6. 半轴为 1/√6.561553 ≈ 0.390388 与 1/√2.438447 ≈ 0.640388，长短轴比 √(λ1/λ2) ≈ 1.64。大特征值表示那个方向曲率大、走一点点 q 就涨很多，所以等高线在那个方向收得短。条件数 κ = λ1/λ2 ≈ 2.69，最速下降的最坏方向每步按 (κ−1)/(κ+1) 衰减；κ 越大越慢，换到特征基并各轴除以 √λᵢ 就能把椭圆拉圆。
  7. l10 = 1，Schur 补 d = a11 − l10² ≈ 1e-16，落在舍入噪声里，可能算成零或负数，d <= 0.0 于是拒绝分解——这是数值 limit 而非数学不正定。若放宽成 d < 0.0，d=0 会放行，l11=0 使回代除零、解变成 NaN，闸门按解析数值行报 numeric_value_invalid；程序非零退出而清单期望 0 则报 exit_mismatch，缺键报 numeric_key_missing，值超差报 numeric_value_mismatch。
