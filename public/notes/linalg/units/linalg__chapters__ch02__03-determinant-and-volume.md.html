2.1 先看工程长什么样

上一单元里，消元做到某一步主元消失，我们只说「矩阵奇异」。这一单元要给这件事一个几何名字：行列式为零。行列式是一个从方阵到单个数的函数，它同时回答两个问题——这个矩阵把空间拉伸了多少倍？它把空间压扁了没有？

这一节的工程和上一节平行：一个头文件声明两个求 det 的算法，一个源文件实现它们，一个驱动负责把两条路径的结果并排打印，清单负责真编译真跑和数值对账。

第 1 帧同样是故事里的起点：ch02 里此刻只有上一单元刚建起来的 gauss_solve/，行列式例子还不存在。第 2 帧用 + 标出这一节新增的东西：那个 +体积单元正文 节点对应磁盘上的 chapters/ch02/03-determinant-and-volume.md，而新例子 det_lu/ 里有头文件 det.h、LU 实现 det.c、驱动 main.c 和清单。注意共用库 common/ 依然不是新增项——mat_get、mat_set 这些老朋友直接拿来用，这正是分册从第 1 单元起就养成的习惯。

大白话行列式到底是个什么数

先别管公式。把一个矩阵想成「对空间的一次操作」：它把单位正方形拉成斜平行四边形，或者把单位立方体扭成斜平行六面体。行列式就是这个变形前后的体积倍数，还带一个正负号表示有没有把空间翻面。倍数是 2，意思是所有图形面积或体积都变成 2 倍；倍数是 -1，意思是大小不变但里外翻过来了；倍数是 0，意思是整个空间被压成一张纸甚至一条线，体积没了。最后一句话就是「矩阵不可逆」的几何版本。

2.2 二阶行列式：一块有向面积

从二维开始最直观。取矩阵的两列作为两个向量 u=(2,0)、v=(1,3)，把它们首尾相接，就围出一个平行四边形。它的面积可以用「底乘高」算：底是 2，高是 3，面积 6。而二阶行列式的公式 a·d-b·c 在这里给出 2×3-0×1=6，两者相等。

第 2 帧要留意「首尾相接」的含义：v 的坐标没变，只是把它的尾巴挪到 u 的头上。这和向量加减那一单元是同一件事。第 3 帧的 6 叫有向面积：如果把 u 和 v 交换顺序，公式变成 0×1-2×3=-6，大小还是 6，符号却反了。符号记录的是「从 u 转到 v 是逆时针还是顺时针」，也就是有没有翻面。

这个面积公式还能从「线性变换」的角度推出来。单位正方形的两条边是 (1,0) 和 (0,1)，面积是 1。矩阵 [[a,b],[c,d]] 把这两条边分别送到 (a,c) 和 (b,d)，也就是矩阵的两列。正方形被拉成平行四边形，面积从 1 变成 ad-bc。所以 det 不只是「算出来的公式」，它直接度量了这个变换对面积的缩放倍数。顺便得到一个很好用的性质：先做变换 A 再做变换 B，总的缩放倍数应该是两次倍数相乘，于是 det(AB)=det(A)·det(B)。这条性质在推导特征值时还会用到，这里先记住它的几何图像：连续拉伸，倍数相乘。

陷阱把行列式当成「面积」而忘了符号

你会看到书上说行列式是面积，于是算出 -6 时怀疑自己算错，甚至手动取绝对值。你会觉得「面积怎么会是负的」。真相是：行列式是有向体积，符号携带了方向信息。交换两列或两行，图形形状没变，符号却翻转——这正是下一节「行交换变号」那条性质的来源。只有在明确只关心大小时（比如某些几何面积计算）才会取绝对值；判断可逆时只看它是不是零，符号无所谓。

2.3 三阶行列式：有向体积与「降维」

三维时，三列向量围成一个斜的平行六面体，行列式就是它的有向体积。公式比二阶长得多，三阶展开是六项，硬背很容易漏符号；我们将在 2.5 节用「代数余子式展开」把它化成一个递归，让代码去做重复劳动。这里先抓住几何图像。

第 2 帧是这一步的关键：c2 原本指向盒子外的第三个方向，现在被挪进 c0 和 c1 铺成的平面里。三根柱子躺在同一个平面上，盒子没有了「高度」。第 3 帧把这个事实写成 det=0。这解释了上一单元那个未展开的问题：为什么主元会消失？因为矩阵的列已经不独立，消元找不到新的方向，只能得到零行。

几何语言换回方程语言：列向量独立，意味着它们的线性组合能铺满整个空间，任意 b 都能拼出来，而且拼法唯一；列共面，意味着只能拼出平面里的向量，b 在平面外就无解，在平面内就有无穷多组拼法。所以 det≠0 和「Ax=b 对每个 b 都有唯一解」是同一句话的两种说法，det=0 和「矩阵不可逆」也是同一句话的两种说法。

体积倍数这个视角还顺手解释了两个常见事实。第一，单位矩阵的 det 是 1，因为它什么都不做，空间体积不变。第二，把某一行或某一列整体乘一个数 s，det 也跟着乘 s：这一条边被拉长 s 倍，盒子体积自然跟着变。由此可以推出，某一行全为 0 时 det 必为 0——盒子有一条边长度为零，体积塌陷。你还可以通过重复这一操作得到：把一行的倍数加到另一行，det 不变，因为这种「剪切」只把盒子推斜，没有改变底面积和高度。这一条正是消元能够保持 det（除换行造成的符号外）的理论依据，也是为什么我们在 2.4 节只担心换行、不担心消元本身。

2.4 两条能算快的性质：三角与换行

如果每次都按六项展开去算，矩阵一大就完全不可行。两条性质把活儿大幅减少。

第一条：上三角矩阵的行列式等于对角元之积。上三角矩阵主对角线下方全是 0，展开时大量项直接消掉，剩下的刚好是对角元相乘。这意味着只要我们能用消元把矩阵变成上三角，就能顺手得到行列式——而消元我们已经写过了。

第二条：交换两行，行列式变号。上一单元为了确保主元不为零，经常要换行；每换一次，det 的符号就翻一次。如果忘了记换行次数，算出来会差一个负号。代码里那个 count 变量专门记这件事，最后用 if (count % 2) prod = -prod; 把符号补回去。

第 1 帧的对角元之积是 -6；第 2 帧把两行交换之后，对角元变成 -1,2,3，乘积是 -6，但因为发生了一次换行，最终 det 是 6。两条性质合起来就是 LU 求 det 的全部原理：分解得到上三角 U，把 U 的对角元相乘，再按换行次数决定符号。

下面是 LU 分解的前半段：选主元、查奇异、必要时换行。它和上一单元的高斯消元几乎一样，唯一的区别是这里不需要处理右端向量 b——我们只关心矩阵本身。

第 23–26 行是 det 专有的一步：主元一旦接近零，不必继续分解，直接把 det 写成 0 并返回。几何上这就是「空间被压扁」；方程上这就是「没有唯一解」。接着看后半段——把主元乘进 prod，再做消元，最后按换行次数定符号。

注意第 35 行在消元之前就把主元乘进 prod：此时 a[k][k] 还是原值，乘完才去改下面的行。第 38 行把倍数 f 写进 a[i][k]，这是标准 Doolittle 分解里 L 的元素——虽然我们这里只用它来算 det，没有把 L 单独保存下来。count 只加不减，因为它记录的是「换行动作的奇偶性」；换同一行两次等于没换，奇偶性会自己抵消。

2.5 代数余子式展开：一条慢但对拍用的路

LU 那套算法很快，但快的东西也可能有 bug——比如忘了换行符号、比如累乘的时机不对。怎么验证？用一条完全独立的慢路：代数余子式展开。

三阶行列式沿第一行展开的公式是 det = a00·M00 - a01·M01 + a02·M02，其中 M0j 是删掉第 0 行第 j 列剩下的二阶行列式，叫余子式；前面再带上 (-1)^j 的符号，就叫代数余子式。二阶余子式只有两项 ad-bc，代码里写成一个四参数小函数。

三条式子前面的符号是 +、-、+，这就是符号交替。这个算法只适用于三阶（因为余子式函数写死了二阶），但作为对拍足够了：它和 LU 路径除了「都读同一个矩阵」以外没有任何共享代码，一条路径错了，另一条大概率不会跟着错同样的错。这也是交叉验证的朴素形式——用两种独立方法算同一个量，看它们是否一致。

手算一遍本单元的例子。矩阵的三行分别是：

  • 第 0 行：1 -2 -3
  • 第 1 行：0 2 1
  • 第 2 行：3 -1 2

沿第一行展开：1×(2×2-1×(-1)) - (-2)×(0×2-1×3) + (-3)×(0×(-1)-2×3) = 5 + 2×(-3) + (-3)×(-6) = 5-6+18 = 17。这条慢路给出的也是 17，和 LU 那条路一致。

陷阱展开时漏掉交替符号

你会觉得「余子式都算出来，乘上对应元素加起来就行」，于是把 - a01·M01 写成 + a01·M01。你会看到小矩阵（比如对角阵）算得全对，因为非对角元是 0，符号错也看不出来。换到本例，-(-2)×(-3) 被写成 +(-2)×(-3)，结果从 17 变成 5。真相是：符号来自 (-1)^(i+j)，沿第一行时就是 +、-、+、…；只要 i 或 j 变一次，符号就翻一次。代码的 s +=、s -=、s += 把这个规则写死在三个式子里，正是为了避免手算时漏掉。

三个黄金值 det_lu、det_cofactor、diff 都写在清单 la05-det.json 的 expect.numbers 里，容差 atol=1e-6。这里 diff 严格为 0，是因为整数矩阵的两条路都落在可精确表示的小数上。把矩阵元素改成 0.1 这类十进制小数，两条路会有细微的舍入差别，diff 通常落到 1e-15 量级；这时只要它小于容差，就认为对拍通过。对拍比的是差值是否在容差内，不是字面相等。

为什么值得花力气做对拍？因为这两条路径的出错方式互不相关。LU 路径容易错在换行次数的奇偶、主元累乘的时机、或者零主元的阈值；展开路径容易错在余子式的下标和交替符号。如果两条路径共用同一个辅助函数、或者都从同一个中间结果出发，它们可能一起错、还错得一模一样，看起来「对拍通过」其实自欺欺人。这里两条路径唯一的交集是原始矩阵数据，所以差值接近零确实是一条独立证据。这种思路在数值代码里很常见：拿一个慢但简单的参考实现去验一个快但复杂的实现，参考实现只用于测试，不进入生产路径。代价是你得多写一份代码、多花测试时间，换来的是对关键数字的可信度。

2.7 判断可逆，其实不用算行列式

既然 det 这么有用，工程里是不是应该先算它？答案是：几乎不。

先说代价。按定义展开算 det 是 O(n!) 的，完全不能用；LU 分解是 O(n³)，看起来还行，但为了回答「可逆吗」这一个是否问题，你付出了完整的三次方代价。而上一单元的消元本身就会告诉你主元有没有消失——顺手就能知道可逆性，不需要再单独算一遍 det。

再说数值。det 的数值尺度很危险：矩阵整体乘 0.01，三阶 det 就乘 1e-6；矩阵整体乘 100，det 就乘 1e6。同一个「接近奇异」的矩阵，换个单位，det 可能从 1e-12 变成 1e12，你根本没法用一个固定阈值判断谁奇异。相比之下，消元里的主元大小、或者更专业的条件数，尺度意义要明确得多。

那 det 还有什么用？它是理论工具：判断可逆性的充要条件、特征值多项式的定义、换元积分里的雅可比行列式、概率里的协方差矩阵正定判定，背后都有它。它的几何意义（体积倍数）也是理解线性变换的核心语言。只是「拿来当数值判据」这件事，交给分解更合适。

工程惯例一个能落地的判断准则

如果你只是想知道 A 能不能解，最实用的做法是做一次带选主元的消元，看主元是否小于容差——这正是上一单元 gauss_solve 返回 0 的条件。如果还想顺便解多个右端向量，就做一次 LU 分解并复用它：分解一次 O(n³)，每次回代 O(n²)，比每来一个 b 就重新消元便宜得多。行列式在这个流程里不是必需的副产品。这是工程惯例，不是数学上的必须；数学上 det≠0 与可逆完全等价，两个说法没有矛盾。

2.8 多重线性与交错：体积公式是被「逼」出来的

前面我们把 det 当成「算出来的公式」，这一节回答一个更根本的问题：为什么偏偏是这个公式，而不是别的？答案藏在三条性质里，它们像三条公理一样把 det 唯一地钉死。

第一条叫多重线性。把矩阵按列看成 A=[c0,c1,c2]，det 对每一列都是线性的：固定其它列，只把某一列写成 αu+βv，就有 det(...,αu+βv,...)=α·det(...,u,...)+β·det(...,v,...)。用体积去想再自然不过：把盒子的某一条边拉长 α 倍，体积就乘 α；把这条边拆成两段再相加，等于两个盒子的体积相加。我们在 2.3 节说「某列乘 s，det 乘 s」，就是这条性质在单列上的特例。

第二条叫交错性。交换任意两列，det 变号；由此立刻推出，若两列相同，则 det=-det，所以 det=0。用体积想：把两条边换成同一条，盒子被压成一张纸，体积为零；交换两条边，形状没变，但「从第一条边转到第二条边」的旋向反了，所以有向体积变号。

第三条是归一化：单位矩阵的 det 等于 1。单位立方体体积是 1，这是度量体积的尺子。

这三条加在一起，足以推出二阶公式。设 e1=(1,0)、e2=(0,1)，任意两列可写成 a·e1+b·e2 与 c·e1+d·e2。由多重线性展开成四项：ad·det(e1,e2)+bc·det(e2,e1)+bd·det(e1,e1)+ac·det(e2,e2)。后两项因两列相同而为零（交错性），det(e1,e2)=1（归一化），det(e2,e1)=-1（交换变号），于是只剩 ad-bc。你看，公式不是背下来的，而是被「体积该有的样子」逼出来的。

三阶的情形完全同理，只是展开成六项，对应六个排列；每个排列的符号等于它把 (1,2,3) 打乱了多少次——偶数次交换取正，奇数次取负。这正好解释了 2.5 节余子式展开里 +、-、+ 交替的来历：符号不是人为规定，而是排列奇偶性的记账。

大白话三条性质就是体积的三条常识

多重线性 = 拉长一条边，体积跟着成比例变；交错性 = 两条边重合就没体积、交换就翻面；归一化 = 单位立方体体积定为一。把这三句常识写成代数规则，det 的公式就被唯一确定了。所以与其背六项展开，不如记住这三条，忘了公式时现场推一遍。

第 2 帧把第一条边从 1 拉到 3，面积从 1 变成 3，这就是多重线性在图上最直白的样子。第 3 帧两条边交换，图形还是那个正方形，但有向面积从 1 变成 -1——形状没变、符号变了，这正是「有向」两个字的含义，也是 2.4 节「行交换变号」的几何源头。

2.9 浮点程序为什么不该拿 det 判断可逆

2.7 节给了结论，这里把道理讲透。核心矛盾是：det 的大小和矩阵是否病态几乎是两件事。

先看尺度。n 阶矩阵整体乘一个常数 s，det 乘 s^n。同一个「形状」的矩阵，换个计量单位，det 能差出几十个数量级。举个具体的：A 是 3×3 的单位矩阵，det(A)=1；把元素都写成以毫米为单位（数值放大 1000 倍），矩阵变成 1000I，det=1e9。矩阵一点没病态，det 却从 1 变成十亿。反过来，一个良态的旋转矩阵 det=1，整体缩小到 0.01 倍，det=1e-6，看着像「接近奇异」，其实条件数还是 1。可见脱离尺度谈 det 的阈值没有意义。

再看溢出。det 是 n 个量的乘积，n 一大就爆。200×200 的对角矩阵，对角元都是 100，条件数是 1（完美良态），但 det 是 100^200=10^400，远超双精度浮点上限约 1.8×10^308，程序里直接变成 inf；对角元都是 0.01 时 det 是 10^-400，变成 0。一个完美良态的矩阵，det 不是溢出就是下溢，拿它当判据只会得到无效数字。

那该拿什么？两个更靠谱的量。第一是主元：2.4 节我们已经看到，消元过程中主元接近零，就意味着找不到新方向，这是尺度无关的几何事实；det.c 里第 23 行那个 1e-12 阈值判的正是它。第二是条件数 κ(A)=‖A‖·‖A⁻¹‖：它衡量输入扰动被放大多少倍，良态矩阵 κ 接近 1，病态矩阵 κ 很大。经验规则是，当 κ(A) 接近 1/ε_machine（双精度约 4×10^15）时，矩阵在浮点意义下就该当作奇异。条件数通常由 SVD 或数值库里的条件数估计例程算出，比 det 稳定得多。

编译器视角一个阈值判不了所有矩阵

假设你写 if (fabs(det) < 1e-12) 奇异。单位矩阵放大到 1000I（三阶），det 是 1e9，判为可逆，对；把良态旋转矩阵 R 缩到 0.01R，det 是 1e-6，仍大于阈值；再缩到 1e-5R，det 是 1e-15，小于阈值，被误判为奇异——可它的条件数始终是 1。同一个良态矩阵，仅仅因为整体缩放，结论就翻转了。这个反例说明：det 的绝对值不是可逆性的可靠指示器。

工程上的标准做法是：需要解 Ax=b 就直接做带选主元的消元或 LU，顺带看主元；需要定量描述病态程度就算条件数估计。det 留给理论推导——特征值多项式的定义、换元积分的雅可比、协方差正定判定，背后都要它，但「数值判据」这口锅不该它背。一句话：det 回答「体积是不是零」，主元和条件数回答「数值上还能不能信」，后者才是工程真正关心的问题。

2.10 det 的另一个舞台：概率密度变换里的雅可比

det 在深度学习里最活跃的身影，其实不是「判可逆」，而是换元公式里的体积缩放因子。先从一个变量看起。设 X 在 [0,1] 上均匀分布，密度 p_X(x)=1。令 Y=2X。显然 Y 落在 [0,2]，总概率还是 1，所以密度必须变成 p_Y(y)=1/2——区间被拉长 2 倍，密度就被稀释 2 倍。这个「稀释倍数」就是变换导数 2 的倒数：p_Y(y)=p_X(x)·|dx/dy|=p_X(x)·|dy/dx|⁻¹。

多维时，导数的角色由雅可比矩阵担当：J=∂g/∂x，其第 i 行第 j 列是 ∂g_i/∂x_j。换元公式是

p_Y(y)=p_X(x)·|det J|⁻¹，其中 x=g⁻¹(y)

为什么是 det？因为雅可比矩阵描述的是「在 x 附近，变换把无穷小立方体拉成什么样的斜盒子」，而 det 正是这个盒子的体积倍数。概率总量守恒：拉大 3 倍的盒子，密度要除以 3，才能保持积分仍是 1。这和 2.1 节「det 是体积倍数」完全同源，只不过这里作用在无穷小尺度上。

一个经典例子是直角坐标换极坐标：x=r cosθ, y=r sinθ。雅可比行列式算出来是 r，所以面积元 dx dy = r dr dθ，积分里那个多出来的 r 正是它。忘了写 r，高斯积分就积不对——这是初学者最常犯的错，根源就是没把 det 当成体积缩放因子。

第 2 帧里高度从 1 掉到 0.5，不是概率丢了，而是底边从 1 拉到 2，矩形面积保持 1。第 3 帧把这个直观推广到任意维：|det J| 就是「体积被放大几倍」，密度除以它才守恒。

这条公式在深度学习里叫归一化流（normalizing flow）。模型设计一串可逆变换把简单分布（比如标准正态）扭曲成复杂数据分布，训练时要用换元公式算精确似然，于是每一步都要算 log|det J|——取对数把连乘变成连加，数值上更稳。难点恰恰在 det：一般 J 的行列式要 O(n³)，流模型因此刻意把每步设计成三角雅可比（比如耦合层只改一半变量、且改动只依赖另一半），这时 det 就是对角线元素之积——正是 2.4 节「三角矩阵 det 等于对角积」那条性质，在这里成了让模型能训练的关键。你看，一个看似纯理论的知识点，反过来支撑了一大类生成模型。

2.11 失败模式：输入什么会让这条路失灵

把可能翻车的地方集中说清，并指明程序现象与闸门报错。

情形一：零主元与近零主元。 若输入矩阵有一整行（或一列）全为零，LU 在第 23 行直接报 det=0、ok=0，几何上就是盒子塌了——这是正确行为，不是故障。危险的是「接近零」：比如三阶矩阵 [[1,2,3],[4,5,6],[7,8,9]]，三行等差，其实第二行等于第一行与第三行的平均，行线性相关，det 应该是 0；但浮点消元后主元是 ~10⁻¹⁶ 量级而不是精确的 0，程序若只判「小于 1e-12 才算零」，这里恰好在阈值附近摇摆。程序现象：det_lu 打出 -9.5e-15，det_cofactor 打出 0.000000，两者之差约 9.5e-15。容差 atol=1e-6 下差值仍在容差内，对拍通过，但如果你把阈值改成 1e-18，nonsingular 的判定就会翻转。教训：零的判定永远依赖阈值，阈值要按问题尺度选，不能照抄。

情形二：篡改符号。 若有人把 if (count % 2) prod = -prod; 这行删掉，想让 det「看起来正一点」，本例换行一次，正确 det 是 17，篡改后变成 -17。程序现象：det_lu=-17.000000，而 det_cofactor 仍是 17.000000，diff=34.000000。闸门对 expect.numbers 里的 det_lu 黄金值 17 做容差对账，立刻报 numeric_value_mismatch；正文里的数字也按同一容差检查，改不动。这正是 2.6 节强调「对拍比的是差值是否在容差内」的价值——两条独立路径，一处被改，差值立刻暴露。

情形三：溢出。 若把例子换成 200×200 的对角矩阵（当然那需要改代码，这里只作思想实验），det 会变成 inf，stdout 打出 det_lu=inf，numerical 模式解析 inf 与黄金值比较，照样报 numeric_value_mismatch。它提醒我们：det 的数值范围本身就是隐患，2.9 节讲的道理在这里变成可见的故障。

闸门报什么错。 三类故障最后都落到同一个机制：清单 la05-det.json 声明 mode=numerical，闸门真编译真跑、从 stdout 解析 key=value，与 expect.numbers 的黄金值按 atol 对账；任何数字对不上就报 numeric_value_mismatch。它不会告诉你「为什么错」，只会告诉你「哪个 key 错了」——定位原因得靠上面这些几何与数值分析。

情形四：把 det 当成求解器。 有人会想「既然 det≠0 保证唯一解，那就先算 det 再解」。这个顺序既慢又危险：慢是因为算完 det 还要再消元一遍；危险是因为 det 只回答「有没有唯一解」，完全不告诉你解是什么，也不告诉你解对扰动敏不敏感。正确的顺序是 2.7 节讲的：直接消元或 LU，分解过程中主元既给了可逆性又给了求解所需的一切，det 全程不必出场。把理论上的等价关系误当成工程上的操作顺序，是这一段最常见的误解。

调试实录从报错反推故障的自检顺序

看到 numeric_value_mismatch 时，不要先改黄金值。按这个顺序查：第一步看 diff——如果它远大于容差，说明两条独立路径分歧，优先查换行符号和余子式下标；第二步看 nonsingular 与 swaps——若标志对不上，查零主元阈值与换行记账；第三步看数量级——若数字是 inf 或 0.000000 却不该是，查溢出与缩放。黄金值是真跑出来的参考，改它等于把体温计砸了退烧。

2.12 手算核对：换一个矩阵，把两条路再走一遍

光看懂例子的 17 不够，换个矩阵自己算一遍才算真会。取上三角矩阵

B = [[2, 1, 3], [0, -1, 4], [0, 0, 5]]

路一（三角性质）：主对角线下方全为零，det 直接是对角元之积 2×(-1)×5=-10。

路二（余子式展开）：沿第一列展开（第一列只有一项非零），det=2×det([[-1,4],[0,5]]) - 0 + 0 = 2×((-1)×5-4×0)=2×(-5)=-10。两路一致。

再试一个需要换行的：C=[[0,1],[1,0]]。它是单位矩阵交换两行，det 应该是 -1。用公式：0×0-1×1=-1，对。LU 路径会先选主元：第 0 列绝对值是 0 和 1，于是换到第 1 行，swaps=1；换后对角积是 1×1=1，再按一次换行变号得 -1。符号记账的每一步都对得上。

最后做一个「降维」核对：D=[[1,2,3],[2,4,6],[7,8,9]]。第二行是第一行的 2 倍，两行成比例，按交错性 det 必须为 0。展开验证：1×(4×9-6×8) - 2×(2×9-6×7) + 3×(2×8-4×7) = 1×(36-48) - 2×(18-42) + 3×(16-28) = -12 +48 -36 = 0。果然为零。这类「先看出相关、再用展开验证」的练习，比机械算十道题更能建立对 det 的直觉。

工程惯例读图指引：四张图怎么连起来读

本单元的图元其实在讲同一件事的几个侧面。平行四边形图（2.2）说 det 是二维体积倍数；「三列压进同一平面」图（2.3）说 det=0 就是降维；「消成上三角再补符号」图（2.4）说怎么把这个体积算出来；新增的多重线图（2.8）回到源头。读图时盯住两样东西：每帧的 * 标记那一格，是本步新增或改变的关键量；帧与帧之间的箭头，是「从上一步到下一步的操作」。比如 2.4 第 2 帧的 d0 被标成 -1，换到了首位，箭头写着 奇数次换行变号——把这两处连起来读，就看懂了符号记账。2.10 的密度变换图则把同一条体积倍数性质搬到概率里：底边拉长、高度减半，面积不变。四条线索指向同一个观点：det 是体积倍数，翻面变号，塌陷为零。

小结这一节的要点
  • 二阶 det 是有向面积、三阶 det 是有向体积；符号记录有没有翻面，交换两行或两列就变号；
  • 上三角 det 等于对角元之积，所以 LU 分解后累乘主元、按换行次数定符号即可；
  • det=0 表示列向量线性相关、空间被压扁，等价于矩阵不可逆、Ax=b 没有唯一解；
  • 代数余子式展开是独立的慢路，适合给快路做对拍；本例两条路都得到 17，差值 0；
  • 数值上判断可逆不必真算 det：消元的主元或条件数更可靠，det 主要作理论工具。

  1. 面积是 2×3-0×1=6；交换两列后 det 变成 -6，大小不变、符号翻转，因为两向量交换后从 u 转到 v 的旋向反了。
  2. 上三角矩阵主对角线下方全为零，按展开式计算时含这些零元素的项全部消失，只剩沿对角线的那一串乘积；所以用消元把矩阵化成上三角后，对角元的乘积就是 det，再按换行次数补上符号，这正是 LU 求 det 的原理。
  3. M00=2×2-1×(-1)=5，M01=0×2-1×3=-3，M02=0×(-1)-2×3=-6；沿第一行符号是 +、-、+，所以 det=1×5-(-2)×(-3)+(-3)×(-6)=5-6+18=17。
  4. 几何上，三列共面，平行六面体被压成平面、体积为零，空间被降维；方程上，列向量线性相关，它们的线性组合铺不满整个空间，Ax=b 要么无解、要么有无穷多解。两种说法都等价于「不存在逆变换把被压扁的空间恢复回来」，所以等价于不可逆。
  5. 按定义展开是 O(n!)，即使用 LU 也要付 O(n³) 的完整代价，而消元本身就能顺带告知可逆性；此外 det 的尺度随矩阵规模剧烈变化，矩阵整体缩放会让 det 乘上缩放因子的 n 次方，没有固定阈值能区分「接近奇异」和「尺度很小」，主元或条件数在尺度意义上更可靠。det 的主要价值是理论刻画而非数值判据。
