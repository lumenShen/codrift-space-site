10.1 先看工程长什么样

到这一单元，前面积累的三件事汇到一起：la03 的矩阵乘法告诉你 Wx 怎么算，la09 的正定二次型告诉你 ‖Wx−y‖² 为什么是一个碗，现在要补的是这个碗对参数怎么变。也就是：把 W 的四个数字各轻轻拧一下，损失会怎么变？这四个敏感度凑起来，就是反向传播里那个梯度。

这一节的清单走 mode=gradient，和前两节的 mode=numerical 不同。它不写黄金数值，而是检查「解析梯度与中心差分是否逐项相符」，并且额外要求一份故意写错的阴性对照。

第 1 帧里 ch04 只有上一节的 cholesky/；第 2 帧新增 mat_grad/，四个文件各司其职：matgrad.h 声明问题与两个求梯度函数，matgrad.c 实现解析梯度与中心差分，main.c 打印梯度表，la10-matgrad.json 声明 gradient 模式与阴性对照开关。共用库依旧来自 common/，矩阵乘法、向量减法、点积全部复用。

大白话导数就是「拧一下旋钮看读数」

把 W 的四个元素想成四个旋钮，损失函数是仪表盘上的读数。想知道第一个旋钮有多灵敏，就把它往右拧一点点，看读数变多少，再往左拧一点点，两个读数之差除以拧的总量就是导数。这就是中心差分。解析梯度则是把仪表盘的内部线路画出来，直接算出每个旋钮的灵敏度。两条路走出来必须是同一个数——这一节的全部戏剧性都在这句「必须」上。

10.2 形状先定死：梯度到底长什么样

矩阵微分最常被卡住的地方不是算术，而是形状。先立一条约定：如果输出是 m 维向量、输入是 n 维向量，Jacobian 是 m×n——行对应输出分量，列对应输入分量。现在输出是标量 f，m = 1，所以 Jacobian 是 1×n；但我们习惯把梯度存成和变量同形的 n 维向量，也就是把那一行转置过来。这个习惯是很多转置的源头。

具体到本节：W 是 2×2，四个参数，输出是一个标量，所以 ∂f/∂W 必须是 2×2，和 W 完全同形。第 j 行第 k 列的数字表示「W 的这个位置变一点，损失变多少」。x 是 2 维，y 是 2 维，残差 r = Wx − y 也是 2 维。整条链式法则的数据流如下。

第 1 帧是前向，第 2、3 帧是反向。注意第 3 帧那个节点写作 Jᵀ g_r——不是 J g_r。原因下一节细说，这里先把「转置Jacobian」这件事记住。

工程惯例梯度与 Jacobian 的约定差别

深度学习框架里通常把梯度存成和张量同形：W 是 2×2，梯度也是 2×2；x 是 2 维，梯度也是 2 维。但数学上严格的 Jacobian 是「输出行、输入列」的矩阵，对标量输出就是一行。要把一行变成同形向量，只能转置。**所以你看到的每一个转置，先问一句：是不是在把 Jacobian 的行列约定翻译成「同形梯度」？**这个习惯在方形矩阵里尤其危险，因为转置前后形状一样，看不出来。

顺带把这条线索接到一个你会反复听到的问题上：梯度消失与梯度爆炸。链式法则把很多层的 Jacobian 连乘起来，每一层都贡献一个转置后的权重矩阵。如果某层权重整体偏小，连乘几十次之后梯度就衰减到几乎为零；如果偏大，就指数级放大。la08 的奇异值在这里派上用场——一个矩阵把向量拉长还是压短，正是它的最大/最小奇异值说了算。Xavier 初始化把权重方差定成 1/n，He 初始化在 ReLU 后定成 2/n，目的都是让连乘的增益落在 1 附近。所以「初始化为什么要除以 √n」不是玄学，它是为了不让本节推导出的这个 Wᵀ 在深层网络里把信号捏死或撑爆。

10.3 转置从哪来：两条推导路线

路线一：对 x 求导，转置来自 Jacobian

先求最经典的那个式子。令 r = Wx − y，f = rᵀr。按链式法则：

∂f/∂x = (∂r/∂x)ᵀ · (∂f/∂r) = Wᵀ · (2r) = 2Wᵀr

∂r/∂x = W 是 2×2，∂f/∂r = 2r 是 2 维列向量。把它们按 Jacobian 约定接起来，应该是 (1×2) × (2×2) 得到一个行向量；要把它写成和 x 同形的列向量，就得整体转置，于是 Wᵀ 出现了。转置不是谁拍脑袋加的，而是「Jacobian 是行、梯度是列」这件约定逼出来的。

分量写法更能说明问题。第 j 个输入分量 x_j 影响了所有残差 r_i，每个 r_i 对 x_j 的导数是 W_ij。所以

∂f/∂x_j = Σ_i 2r_i · W_ij

注意求和指标是 i（残差的下标），W_ij 的第一个下标跟着 i 变。要写成矩阵乘法，必须让 W 的列对应 x 的下标、行对应 r 的下标——这正是 Wᵀ 的形状。如果写成 2Wr，第 i 个分量变成 Σ_j W_ij r_j，求和的是输入下标而不是残差下标，数值就错了。

再多说一层：真实网络不是一步 Wx，而是很多层串起来。每一层都把自己的 Jacobian 转置之后乘到上游梯度上，于是反向传播里的链条大致是 J₁ᵀ J₂ᵀ … J_Lᵀ · ∇f。所谓「反向传播」，本质上就是从后往前依次乘这些转置过的 Jacobian；自动微分框架帮你把每一步都记下来，但不会替你决定转置该不该在——那仍然来自同一条约定。你手写反向实现时漏掉一个 .T，和本节那个 GRAD_BUG 是同一类错误，只是在深层网络里更难发现。

路线二：对 W 的四个参数求导，转置来自形状对齐

本例的「参数」是 W 的四个元素。把它们摊平成 w = (w00, w01, w10, w11)。残差对 w 的 Jacobian 是 2×4：

J = [[x0, x1, 0, 0], [0, 0, x0, x1]]

第 i 行对应第 i 个残差，第 (2i) 与 (2i+1) 列对应 W_i0 与 W_i1。梯度必须和 w 同形，也就是 4 维列向量。而 J 是 2×4、∂f/∂r = 2r 是 2 维——只有 Jᵀ（4×2）乘 2 维向量才能得到 4 维。这一步的转置纯粹是被形状逼出来的，不转置连矩阵乘法都做不了。

把 Jᵀ(2r) 的分量写出来：(2r0·x0, 2r0·x1, 2r1·x0, 2r1·x1)，排回 2×2 就是 2 r xᵀ——一个外积。注意这里出现的是 xᵀ 而不是 x：因为结果要摆成「行是残差下标 i、列是输入下标 j」的 2×2，正是外积 r xᵀ 的形状。

拿真实数字核对。取 W = [[0.5, 1], [−0.5, 2]]、x = (1, 2)、y = (0.5, −1)，那么 r = (2, 4.5)。四个梯度应为 (4, 8, 9, 18)。手算一个：w01 增加 h 时，r0 增加 2h，f = r0² + r1² 增加约 2r0·2h = 8h，所以导数是 8，与外积给出的 2r0·x1 = 2×2×2 = 8 一致。

陷阱方形矩阵会让「漏转置」隐形

你会觉得 W 是 2×2，转不转置都是 2×2，Wr 和 Wᵀr 形状一样，编译器不报错，程序照常跑。你会误以为形状检查能兜住所有错误。真相是：恰恰在方形矩阵上，少写一个转置是最隐蔽的 bug——它不改变维度，只改变数值。上面的 2Wr 给出的四个数是 (4.5, 9, 4, 8) 之类，和正确的 (4, 8, 9, 18) 完全不同，但程序不会给任何提示。唯一能抓住它的办法就是下面那场对拍。

10.4 对拍：中心差分给解析梯度背书

中心差分完全不懂链式法则。它把第 k 个参数加 ε 算一次损失，减 ε 再算一次，斜率取 (f₊ − f₋)/(2ε)。这里 ε 取 1e-5：太小会被浮点舍入淹没，太大又会让 O(ε²) 的截断误差冒头。

把两类误差摊开看会更清楚。截断误差来自泰勒展开里被丢掉的三次项，量级约 ε²·f'''/6；舍入误差来自 f₊ 与 f₋ 各自携带的双精度噪声，除以 2ε 后放大成约 2·u·|f|/ε，其中 u 是机器精度，约 2e−16。前者随 ε 变小而变小，后者随 ε 变小而变大，平衡点落在 ε ≈ u^(1/3)，也就是几微这个量级——1e-5 正好在附近。对于本节这种二次函数，三阶导数为零，截断项消失，剩下就是舍入，所以四个数字能精确到小数第七位。

工程惯例别把 ε 取得无限小

初学者常想「ε 越小越接近导数定义」，于是取 1e-15，结果梯度表变成一堆锯齿状乱码。你会误以为解析梯度写错了，其实是被减法的 catastrophic cancellation 吃掉：两个几乎相同的数相减，有效位数所剩无几。真相是差分商里的 ε 是一个折中参数，不是越小越好。真正需要高精度时应该用复数步（complex step）或自动微分，而不是硬把 ε 往机器精度上压。

10.5 阴性对照：为什么这套检查必须有

现在讲清单里那行 negative_flags: ["-DGRAD_BUG=1"]。闸门拿这组参数再编译一份，跑出第二张梯度表；如果这张错表也通过对拍，闸门就报 gradient_harness_not_discriminating——意思是这套检查根本不判别，等于零证据。

为什么必须这么做？因为「对拍通过」这件事本身太容易被骗。一个程序可以干脆把数值梯度抄成解析梯度，于是每对都相等；也可以把四行全打成 0，在很小的容差下也可能混过去（所以还要查非零组数）；更隐蔽的是像本节这样少写一个转置——形状不变、维度不报错、代码看着还挺合理。如果没有阴性对照，你根本不知道闸门到底有没有能力区分对与错。**阴性对照是在验证「检查器本身」，不只是验证「被检查的程序」。**这和深度学习里做 gradcheck 的纪律完全一样：写个单元测试很容易，写个能真正抓住 bug 的单元测试才难。

先看阴性对照那张表到底错在哪。正例四行是 (4, 8, 9, 18)，打开 GRAD_BUG 后变成 (4, 9, 8, 18)——只有 w01 和 w10 变了，而且恰好互换。原因就在源码第 24、25 行：错误分支只改写了下标交叉的那两个分量，w00 和 w11 没被碰过。这个细节很有说服力：它证明错误是「局部且可解释」的，不是把整张表洗成随机数。闸门重算差值，w01 的 |9−8| = 1、w10 的 |8−9| = 1，都远大于 atol=1e-5，于是阴性对照被判失败——这正是我们要的结果。

反过来想，如果闸门不判别会怎样？把 mg_analytic_grad 改成直接返回数值梯度的假实现，正例四行依然完美对齐；阴性对照也会因为「假实现照样抄到数值梯度」而通过，闸门就会报 gradient_harness_not_discriminating。所以这一条检查守的不是程序，而是闸门自己。

陷阱只跑正例会给你虚假的安全感

你会看到正例四行完美对齐，于是收工。你会误以为「对拍通过 = 梯度正确」。真相是：正例只能证明「程序给出的两列数碰巧相等」。把 mg_analytic_grad 整个改成 grad[k] = numerical[k] 的假实现，正例照样满分。只有把错误主动注入一次、并看到闸门把它拦下来，你才知道这台机器真的能判别。程序自报的 PASS 不算证据，阴性对照才是。

工程惯例框架里的 gradcheck

PyTorch 的 gradcheck 就是这套流程的工业版：对双精度张量做中心差分，与 autograd 的结果逐项比较，量级同样是 atol=1e-5 加一个相对容差。自定义算子接入框架时通常要过这一关；手写 CUDA 反向核的人尤其重视，因为最容易漏的就是一个转置或一个链式因子。你在本书里手写的四行表，和它在方法上是同一件事，只是规模小到可以完全手算。

把这条纪律放到更大的背景里看：PyTorch 的 torch.autograd.gradcheck 做的就是同一件事——用有限差分去核对反向传播；各种深度学习框架在接入新的自定义算子时都要求过这一关。你在这里手写的四行梯度表，就是那个机制的最小版本。下次看到某个层的反向实现里冒出一个 .transpose() 或 .T，别把它当样板代码跳过：它多半正在履行本节推导的职责——把 Jacobian 的行列约定翻译回同形梯度。

再补一个常见疑问：既然中心差分这么可靠，为什么训练时不用它？因为每算一个参数就要重新前向一次。本节只有 4 个参数，看不出差别；换成一亿个参数的网络，一次梯度就要曝一亿次前向，完全不可行。解析梯度（也就是自动微分在做的事）只用一次前向加一次反向，成本与一次前向同阶。中心差分是裁判，不是运动员——它慢，但它明显正确，正合裁判的角色。

下一节会回到更宏观的视角：把这一册八、九、十三个单元串起来，看 SVD、正定、矩阵微分如何分别对应「有哪些方向」「碗有多陡」「对参数怎么变」，这就是深度学习里线性代数真正的用法。

10.6 两种约定：分母布局与分子布局

矩阵微分最让人头晕的地方，往往不是算术而是「同一个导数该摆成什么形状」。业界有两套约定。分子布局（numerator-layout）把 Jacobian 写成「行对应输出分量、列对应输入分量」：若 y = Ax，y 是 m 维、x 是 n 维，则 ∂y/∂x = A，形状 m×n。分母布局（denominator-layout）把导数写成与分母（自变量）同形：∂y/∂x 变成 n×m，也就是 Aᵀ。两套约定没有对错，混用才会出错；本文的取舍是：写 Jacobian 时用分子布局，因为它忠实反映「第 i 个输出被第 j 个输入影响」；存梯度时用分母布局，因为它与参数张量同形，优化器才能 W -= lr * gradW。两者之间的翻译动作就是转置。

标量输出最能把这件事看清。f 是 1 维、W 是 2×2 有四个参数，分子布局的 Jacobian 是 1×4 的一行，分母布局的梯度是 2×2 的矩阵。这两个对象包含的信息相同，排列不同；从一行变成 2×2 必须先按摊平顺序还原，再排回矩阵， transpose 正是这一步的表现。代码里 grad[0..3] 按 (w00, w01, w10, w11) 的顺序摊平，和 Jacobian 的第 0..3 列一一对应——摊平顺序本身也是约定，换一种顺序就要改梯度表的行顺序，闸门按 w00、w01 这些键逐行配对，顺序错了会报 gradient_pair_mismatch。

陷阱方形矩阵是约定的隐身衣

W 是 2×2 时，分子布局的 Jacobian 与分母布局的梯度在形状上都是 2×2（写成矩阵后），Wr 与 Wᵀr 也都是 2 维。编译器、形状检查、甚至打印出来的行数都不会给你任何提示。这正是本节要专门做对拍的原因：形状检查只能抓住维度不匹配的错误，抓不住「维度合法但下标错了」的错误。养成习惯：每写一个转置，都用分量下标验一次——∂f/∂W_ij = Σ_k (∂f/∂r_k)(∂r_k/∂W_ij)，看求和指标是不是落在正确的那个下标上。

10.7 trace 技巧：把 ∇tr(XᵀAX) 推出来

深度学习的讲义里常出现 trace 技巧，它其实是 10.3 那条分量推导的紧凑写法，不需要死记。先立一条翻译规则：标量 f 的全微分总可以写成 df = ⟨G, dX⟩ = tr(Gᵀ dX)，这个 G 就是分母布局下的梯度 ∇_X f。现在取 f = tr(XᵀAX)，对 X 求微分（A 与 X 无关）：

df = tr(dXᵀ A X) + tr(Xᵀ A dX)

第一项按 Frobenius 内积读：tr(dXᵀ A X) = Σ_ij dX_ij (AX)_ij = ⟨AX, dX⟩，贡献 AX。第二项先用转置把 XᵀA 换成 (AᵀX)ᵀ：tr(Xᵀ A dX) = ⟨AᵀX, dX⟩，贡献 AᵀX。两项相加得 ∇_X tr(XᵀAX) = AX + AᵀX = (A+Aᵀ)X；若 A 对称，就退化成常见的 2AX。注意关键词是「微分」而不是「偏导列表」：写出 df 的线性部分，读出与 dX 配对的那张矩阵，梯度自动落在正确的布局上，转置也不会漏。

用同一套工具重推本节的损失。f = ‖Wx−y‖² = rᵀr，df = 2rᵀ dr = 2rᵀ dW x（x、y 固定）。把标量套进 trace：2rᵀ dW x = tr(2x rᵀ dW) = ⟨2 r xᵀ, dW⟩，于是 ∇_W f = 2 r xᵀ，与 10.3 的外积结论完全一致。对 x 求导同理：df = 2rᵀ W dx = ⟨2 Wᵀ r, dx⟩，得 ∇_x f = 2 Wᵀ r。一次微分，两处梯度，不需要分别写两套下标；trace 循环移位 tr(AB) = tr(BA) 是把矩阵挪到正确位置的唯一工具。

工程惯例读图指引：链式法则图的三帧怎么配公式

10.2 的 graph 图第 1 帧是前向：W → r → f，公式是 r = Wx−y、f = rᵀr。第 2 帧星号落在 g_r 上，表示反向第一站：f 对 r 的梯度 2r，对应 ∂f/∂r = 2r。第 3 帧星号落在 g_w 上，写作 Jᵀg_r，对应 ∇_W f = Jᵀ(2r) = 2rxᵀ。读图时把每帧的星号节点和上面的一条公式绑定，不要整张图一起背：第 2、3 帧各只做一次「乘 Jacobian 的转置」，深层网络只是把这一步重复 L 次。10.4 的 memory 图则专门看形状：J 是 2×4，Jᵀ 是 4×2，只有转置后才乘得动 2 维的 g_r。

10.8 与反向传播逐元素对应

把本节的两个结果放进一层网络里，就能看懂反向传播的模板。设第 l 层 z⁽ˡ⁾ = W⁽ˡ⁾ a⁽ˡ⁻¹⁾ + b⁽ˡ⁾、a⁽ˡ⁾ = φ(z⁽ˡ⁾)，末层损失 f。定义 δ⁽ˡ⁾ = ∂f/∂z⁽ˡ⁾（分母布局，与 z 同形）。从后往前有两条规则：

δ⁽ˡ⁾ = (W⁽ˡ⁺¹⁾)ᵀ δ⁽ˡ⁺¹⁾ ⊙ φ′(z⁽ˡ⁾)，∇_{W⁽ˡ⁾} f = δ⁽ˡ⁾ (a⁽ˡ⁻¹⁾)ᵀ，∇_{b⁽ˡ⁾} f = δ⁽ˡ⁾。

第一条里的转置和 10.3 的 Wᵀr 同源：第 j 个分量的公式是 δ⁽ˡ⁾_j = (Σ_i W⁽ˡ⁺¹⁾_{ij} δ⁽ˡ⁺¹⁾_i) φ′(z⁽ˡ⁾_j)，求和下标 i 是上一层的神经元编号，要让它落到 W 的行上，必须转置。第二条的外积和本例的 2rxᵀ 同源：第 (i,j) 个权重只被第 i 个输出和第 j 个输入影响，所以梯度就是 δ_i a_j。若损失是 mini-batch 的均值，还要把每条样本的贡献除以批量大小 m；漏掉这个 1/m 会让梯度放大 m 倍，等价于学习率被偷偷放大 m 倍。

末层若接平方损失且 φ 是恒等映射，δ⁽ᴸ⁾ = 2r，于是权重的梯度正是 2rxᵀ——本节的程序就是这套模板在 2×2 上的完整实现。把链条展开，∇f 实际上是 J₁ᵀ J₂ᵀ … J_Lᵀ ∇_out，每一层贡献一个转置的 Jacobian 和一个逐元素激活导数。所谓「自动微分」，就是框架替你把这条链记下来并按逆序乘回去；它不会替你决定这些转置该不该在——那是布局约定与分量推导的职责。

10.9 数值梯度检查的精度与边界

10.4 已经算出 1e-5 是个折中，这里把误差账算细。中心差分的截断误差来自泰勒展开的三次项，量级 ε² f'''/6；舍入误差来自 f₊、f₋ 各自的机器噪声，除以 2ε 后放大成约 2u|f|/ε，u 在双精度下约 2e−16。两者平衡点 ε ≈ u^(1/3)，数值约几微；1e-5 正落在附近。本例的 f 是二次函数，三阶导数为零，理论上截断项消失，剩下的只有舍入——所以四行梯度能精确到小数第七位。真跑时 fp = 24.2500400001 这种末位的 1 就是舍入的痕迹，不是程序写错。

换精度要换参数：float32 的 u 约 1e−7，最优 ε 约 5e−3，容差也只能放到 1e−2 左右；拿双精度的 1e−5 去查 float32 梯度，会报一堆假失败。若导数函数解析且没有分支，可以用复数步：f(x + i h) ≈ f(x) + i h f′(x)，取 h = 1e−20，虚部直接给导数，没有相减就没有 cancellation，精度接近机器极限。代价是不适用于 abs、ReLU、max 这类非全纯操作。另一个边界是非光滑点：ReLU 在 0 处不可导，norm 在 0 处也不可导，恰好在这些点做 gradcheck 会失败；正确做法是把检查点稍微平移，或只对光滑区域做检查。

框架里的 gradcheck 还常用相对误差 |a−n| / max(1, |a|, |n|)，避免梯度本身很大时绝对容差过严。本节只查绝对差值 |a−n| ≤ 1e−5，因为四个数都在 4 到 18 之间，绝对容差够用；换到真实网络就得加相对项。

10.10 梯度消失、爆炸与初始化

反向传播是转置 Jacobian 的连乘，这解释了深度学习里两个最著名的病症。若每层 Jacobian 的奇异值普遍小于 1，连乘 L 层后梯度按指数衰减，浅层参数几乎收不到更新——损失曲线平稳、浅层权重不变，这就是梯度消失。若奇异值普遍大于 1，梯度指数放大，权重更新一步跨过极小点，损失变成 NaN 或反复震荡——这就是梯度爆炸。la08 的奇异值正是判断增益的尺子：一个矩阵把向量拉长还是压短，由最大与最小奇异值决定；深层网络里要看的是整条乘积链。

初始化就是在源头控制这条链的增益。对线性层，若激活方差为 v、权重独立同分布且方差 σ²、fan_in 个输入，则输出方差约为 fan_in·σ²·v；要让前向方差不随层数漂移，取 σ² = 1/fan_in，这就是 Xavier 初始化（对称考虑 fan_out 时用 2/(fan_in+fan_out)）。ReLU 把约一半激活置零，方差再折半，于是 He 初始化取 2/fan_in。这些 1/√n 不是玄学，而是让 10.3 里那个 Wᵀ 在统计意义上既不把梯度捏死也不撑爆。工程上还有三条补救：残差连接让雅可比变成 I + J_F，恒等通路保住梯度；梯度裁剪在范数超过阈值时按比例缩放，专治爆炸；归一化层把每层的激活尺度稳住。

陷阱失败模式：初始化太小或太大的程序现象

把 W 全部初始化成 1e−3 量级，前向激活每层缩小，深层输出近乎常数，损失几乎不降；反向梯度比激活更小，浅层的 |grad| 可能只有 1e−12，看起来像「学习率太小」。把 W 放大到 10 的量级，激活逐层放大，前向就出现 inf，损失打印 nan；即使没溢出，梯度也会指数增长，一次更新把权重推到更大的量级。这两类失败都不是损失函数写错，而是连乘增益失控。本节 2×2 的例子只有一层，所以看不出病；把同一段 Wᵀr 复制五十层，再用 la08 的奇异值估一下增益，就能预料会不会出事。

手算核对：用一个参数扰动出四行梯度

拿本节的数字完整核一遍。W = [[0.5,1],[−0.5,2]]、x = (1,2)、y = (0.5,−1)，r = (2,4.5)，f = 2² + 4.5² = 24.25。固定其他参数，只动 w00：加 ε = 1e−5 时 f₊ ≈ 24.2500400001，减 ε 时 f₋ ≈ 24.2499600001，差约 0.00008，除以 2ε 得 4。同样算法给出 w01: (24.2500800004 − 24.2499200004)/2e−5 = 8；w10: 9；w11: 18，与输出块的四行逐项相同。再用 10.7 的公式独立核：∇_W f = 2rxᵀ = [[4,8],[9,18]]，摊平成 (4,8,9,18)；∇_x f = 2Wᵀr = 2(−1.25, 11) = (−2.5, 22)。四条路（分量、Jacobian 转置、trace 微分、中心差分）落在同一组数字上，这才是「梯度正确」的证据。

陷阱失败模式：错误注入后闸门报什么

打开 GRAD_BUG，解析梯度从 (4,8,9,18) 变成 (4,9,8,18)：只有 w01 与 w10 互换，因为错误分支只改写了交叉下标。此时正例的对拍在 w01 上报 |9−8| = 1 > 1e−5，闸门报 gradient_pair_mismatch；阴性对照本就应该失败，若它反而也通过，说明这份检查不判别，报 gradient_harness_not_discriminating。把解析梯度整段改成「直接返回数值梯度」，正例四行照样完美，但阴性对照也会通过，于是同样报 gradient_harness_not_discriminating。若某个实现把四行全输出 0，非零组数不够，报 gradient_trivially_zero；只输出三行则报 gradient_too_few_params。这些错误码不是背的，它们分别对应「数值不对」「检查器无效」「梯度没算」「表格不全」四类失败。

大白话常见误解速查

误解一：「转置是风格问题」。它是布局翻译，方阵上漏掉不改形状只改数值，最难查。误解二：「中心差分 ε 越小越准」。ε 太小会被舍入淹没；二次函数三阶项为零，ε 大一点反而稳。误解三：「对拍通过就说明反向实现正确」。只有错误注入被拦下，才能证明检查器有判别力。误解四：「梯度爆炸靠调小学习率就能解决」。增益来自连乘，根本办法是初始化、归一化与残差通路，学习率只是缓解。误解五：「bias 的梯度也要乘输入」。bias 不接输入，梯度就是 δ 在批量上的平均。

手算核对：一个两层网络把 δ 传到底

把 10.8 的模板套到两层小网络上，所有数字都能手算。取 a⁰ = (1,2)，W¹ = I、b¹ = 0，激活用 ReLU，于是 z¹ = (1,2)、a¹ = (1,2)（都是正数，导数恒为 1）。取 W² = [[1,1],[0,1]]、b² = 0，得 z² = (3,2)；目标 y = (2,2)，残差 r = (1,0)，损失 f = 1。从末层往回：δ² = 2r = (2,0)；∇{W²} = δ²(a¹)ᵀ = [[2,4],[0,0]]；∇{b²} = (2,0)。再到第一层：δ¹ = (W²)ᵀδ² ⊙ φ′(z¹) = (2,2) ⊙ (1,1) = (2,2)；∇{W¹} = δ¹(a⁰)ᵀ = [[2,4],[2,4]]；∇{b¹} = (2,2)。

这里两处关键都能验到下标。第一，δ¹ 的第一个分量是 W²_{00}·δ²_0 + W²_{10}·δ²_1 = 1×2 + 0×0 = 2，第二个是 W²_{01}·δ²_0 + W²_{11}·δ²_1 = 1×2 + 1×0 = 2——求和走的是 W² 的列，这正是转置的来源。第二，∇{W¹}{ij} = δ¹_i a⁰_j，例如 (0,1) 格是 2×2 = 4，是外积而不是内积。若把 ReLU 换成恒等映射，δ¹ 不变；若某一层的激活为负，对应 φ′ = 0，那条通路上的梯度直接归零——这就是 ReLU 网络里「神经元死亡」的微分层面解释。

工程惯例读输出表：四行数字各在证明什么

输出块每行由参数名和 analytic=、numerical= 两列组成。第一列来自链式法则，第二列来自导数的定义；闸门先数行数够不够（至少 4 组），再数非零解析梯度够不够（至少 2 组），最后逐行比较 |a−n| ≤ 1e−5。三项分别防住三种假通过：行数不足是偷懒，全零是 trivially 通过，逐行超差是真算错。阴性对照再编译一次错版本，若错版本也能过这三关，整个检查器就没有判别力。所以读这张表时别只看「四行相等」，要意识到每一行都是两条独立计算路径的交叉验证，而阴性对照是在验证「这个交叉验证本身有效」。

大白话写对导数的五步清单

第一步，先定形状：梯度要和自变量同形，W 是 2×2 就写 2×2，x 是 2 维就写 2 维；形状定错，后面全错。第二步，只写前向表达式，不急着求导：r = Wx−y，f = rᵀr。第三步，对前向式取微分，把变化量写成 df = ⟨G, d变量⟩ 的内积形式；trace 的循环移位是唯一需要记的代数工具。第四步，从内积里读出 G，它就是梯度——这一步自动给出转置，不需要靠感觉补 .T。第五步，用中心差分对拍，并故意注入一个错误（像 GRAD_BUG）确认检查器真的会拦。以 g = Wx 为例：dg = dW x + W dx，单独看 x 的部分是 ⟨Wᵀ(dg), dx⟩，所以分母布局下 ∇_x (向量函数) 对应的导数是 Wᵀ；分子布局写 ∂g/∂x 则是 W。同一个公式在不同布局里长得不一样，五步清单保证你不会在中间悄悄换约定。

陷阱batch 均值的两个常见错法

真实损失是 mini-batch 均值 f = (1/m) Σ_t ‖Wx_t − y_t‖²，本节只做单条样本，相当于 m = 1。常见错误一：照搬单样本梯度，忘了除以 m，于是学习率被隐式放大 m 倍，批量越大越容易爆炸。常见错误二：把 bias 的梯度也乘上输入——bias 不接输入，它只贡献一次加法，所以 ∇_b = (1/m) Σ_t δ_t，形状与 bias 相同；代码里若写成 δ aᵀ 的形状就错了。还有一种隐蔽错误：广播时把形状 (m,1) 的 bias 梯度加到 (m,d) 的权重梯度上，NumPy 不报错却把 bias 梯度复制到每一列。检查方法还是逐元素对拍：拿两条样本手算一次均值梯度，看每个参数是不是恰好等于两条样本贡献之和再除以 2。

工程惯例外积与内积：为什么权重梯度是矩阵而不是向量

对 x 求导得到 2Wᵀr，是一个向量；对 W 求导得到 2rxᵀ，是一张矩阵。差别不在难度而在自由度：x 的 2 个分量各自被所有残差汇总，所以每个分量一个数；W 的 4 个位置彼此独立，每个位置都有自己的敏感度，所以必须有 4 个数。外积 r xᵀ 的第 (i,j) 格是 r_i x_j，正好对应第 i 个输出、第 j 个输入的那根连接。若误写成内积 rᵀx，得到的是一个标量，形状就漏了。再想一层：损失对 Wᵀ 的梯度是 (2rxᵀ)ᵀ = 2xrᵀ，同一根连接的敏感度不变，只是表的行列换了位置——这也提醒你，报告梯度时先说清是对哪个变量。

大白话三节收束：从方向到敏感度

把三个单元连起来读：la08 的 SVD 指出数据和权重里有哪些有效方向，la09 的正定与 Cholesky 说明一个方向上的曲率有多大，la10 的矩阵微分则回答这些量对参数怎么变。反向传播里那个 Wᵀ，就是把「输出侧的敏感度」翻译回「输入侧的参数」的搬运工；低秩近似省的是方向上的自由度，Cholesky 治的是曲率带来的病态，初始化与归一化管的是敏感度在深层的增益。下次看到一段反向代码，先问三个问题：它搬的是哪个方向、经过什么曲率、增益有没有失控。

小结这一节的要点
  • Jacobian 的行对应输出、列对应输入；标量输出的梯度要转置成与变量同形，这是转置的主要来源；
  • 对 x 求导得 2Wᵀr：分量 Σᵢ W_ij r_i 按残差下标求和，逼出 W 的转置；
  • 对 W 的四个参数求导得 2rxᵀ：Jacobian 是 2×4，梯度是 4 维，只有 Jᵀ 能让形状对齐；
  • 中心差分是明显正确的暴力版，逐项对拍解析梯度；闸门还查非零组数，防止全零 trivially 通过；
  • negative_flags 编译出的错梯度若也通过，报 gradient_harness_not_discriminating；阴性对照验证的是检查器本身。

注自测题答案
  1. r=(2,4.5)，Wr=(1×2+2×4.5, −0.5×2+2×4.5)=(10,8)，乘 2 得 (20,16)；Wᵀr=(0.5×2−0.5×4.5, 1×2+2×4.5)=(−1.25,11)，乘 2 得 (−2.5,22)。两者都是 2 维，形状完全合法，但数值天差地别；只有对拍能发现。
  2. J = [[x0,x1,0,0],[0,0,x0,x1]]，是 2×4；Jᵀ 是 4×2，乘 2 维的 2r 得 4 维。展开第 2i 与 2i+1 个分量，分别是 2r_i x0 与 2r_i x1，排回 2×2 正是 2rxᵀ。
  3. 中心差分是二阶精度，截断误差 O(ε²)，单侧差分是一阶 O(ε)；但 ε 太小会让 f₊ 与 f₋ 的舍入误差被 (2ε) 放大。平方函数下中心差分几乎精确，主要受舍入支配，1e-5 是双精度下的常用折中。
  4. 会漏掉把全部解析梯度输出 0 的程序：此时每对差值可能都小于容差，逐项检查全绿。要求足够多组非零，才能证明梯度真的被算过，而不是被抄成零。
  5. 报 gradient_harness_not_discriminating。说明这套对拍不判别——错梯度和对梯度都放过，等于零证据；它和 detect 模式的 detect_not_attributable 属于同一类失败。
  6. 分子布局下 ∂y/∂x = A（m×n，行输出列入）；分母布局下是 Aᵀ（n×m，与 x 同形）。本文用分子布局写 J、分母布局存梯度，链式法则要把「输出行」翻成「变量列」，所以乘 Jᵀ。写 df = tr(dXᵀAX)+tr(XᵀA dX) = ⟨AX,dX⟩+⟨AᵀX,dX⟩，故 ∇ = AX+AᵀX = (A+Aᵀ)X；A 对称时为 2AX。
  7. r = (2,4.5)，f = 24.25。逐项扰动：w00 的 f₊ ≈ 24.2500400001、f₋ ≈ 24.2499600001，差 8e−5 除以 2e−5 得 4；同理 w01 得 8、w10 得 9、w11 得 18。外积 2rxᵀ = 2[2],[4.5] = [[4,8],[9,18]]，摊平一致。反向是转置 Jacobian 的连乘，奇异值普遍小于 1 就指数衰减、大于 1 就指数放大；Xavier 取 1/fan_in、He 取 2/fan_in，正是让每层增益接近 1。
