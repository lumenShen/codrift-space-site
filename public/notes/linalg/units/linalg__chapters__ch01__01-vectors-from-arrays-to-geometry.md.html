1.1 先看工程长什么样

线性代数分册不装科学计算库，先用 C 把最小的一套向量运算写出来。原因是这一册要证明的不是「会不会调 numpy」，而是每一步数值从哪来、对不对。

大白话先建立一个画面

向量有两个身份。写成 (1,2,3) 时它是一组三个数，计算机里就是连续的三格内存；画成从原点出发的箭头时，它有长度、有方向。这两个身份不是两件事——数组是箭头的坐标，箭头是数组的几何解释。

加减法在数组视角是「逐格相加」，在几何视角是「首尾相接」。点积在数组视角是「对应格相乘再求和」，在几何视角是「一个箭头在另一个箭头方向上的投影长度，再乘以对方长度」。两种说法算出来是同一个数。

共用库 common/ 从第 1 单元起就在，之后 9 个单元的矩阵、分解、微分例子都从它取函数。每个例子仍然是「main.c + 共用库 + 一个清单」的多文件工程：清单负责真编译真跑，main.c 负责把要展示的数打出来。

1.2 加法：两种看法，同一个结果

取 a=(1,2,3)、b=(4,-5,6)。数组视角的加法是逐格算：

  • a+b = (1+4, 2+(-5), 3+6) = (5,-3,9)
  • 2a = (2,4,6)，数乘就是把每一格都乘同一个数

几何视角的加法是「把 b 的尾巴挪到 a 的头上，从原点连到 b 的新头」。下面三帧把这件事拆开：

第 2 帧里 b 的位置变了，但它的坐标没变——(4,-5,6) 描述的是「往哪个方向走多远」，跟起点在哪无关。这一点是向量和「点」的根本区别：点有固定位置，向量只有方向和长度。第 3 帧的合向量 a+b 才是我们要的那个箭头。

1.3 点积：一个数字里藏了方向信息

点积的定义是对应分量相乘再求和：a·b = 1×4 + 2×(-5) + 3×6 = 4-10+18 = 12。这个 12 本身不好解释，得配合两个长度一起看。

几何上 a·b = |a||b|cosθ，其中 θ 是两个箭头的夹角。也就是说，点积把三件事揉成了一个数：两个箭头各自多长、它们有多对齐。我们这组数据的长度是 |a|=√14≈3.741657、|b|=√77≈8.774964，于是：

  • cosθ = 12 / (3.741657 × 8.774964) = 0.365487
  • cos 为正 → 夹角小于 90°，两个向量大体同向
  • cos 为 0 → 垂直；cos 为负 → 大体反向
陷阱余弦相似度为什么要除以长度

如果只比点积，同一段文字被重复两遍，embedding 长度翻倍，点积也跟着翻倍——明明语义没变，相似度却变了。除以 |a||b| 之后只剩 cosθ，长度被约掉，比的是纯方向。这就是检索系统里常用余弦而不是点积的原因。反过来，若你本来就想让「更长 = 更重要」，那点积反而更合适。

1.4 内存：向量在机器里长什么样

分册里用定长结构 vec_t：一个 n 记录有效长度，一个数组装最多 LA_MAX=8 个 double。读的时候只看前 n 格，后面的空槽不参与任何计算。

工程惯例为什么要带一个 n，而不是全局定长 3

后面矩阵乘法会换各种维度：2 维输入、3 维隐层、1 维输出。如果写死长度，每换一次形状就得改一份代码。把 n 放进结构，函数就只看 n 格，同一套 vec_dot 能给所有维度用。代价是空槽浪费一点内存——在这个量级完全无所谓。

1.6 减法、距离与单位化：同一个工具的三种用法

1.6.1 减法就是「从哪走到哪」

加法把两个箭头首尾相接，减法回答的是另一个问题：从 a 的终点走到 b 的终点，要往哪个方向走多远。把 b-a 看成「b 加上 -a」，就知道它是逐格相减：a-b=(1-4, 2-(-5), 3-6)=(-3,7,-3)。几何上，它是从 a 指向 b 的那支箭头；把它的尾巴挪回原点，方向和长度都不变。

这个视角在深度学习里到处都是。梯度下降里的更新量 w_new - w_old 是一个向量，loss 下降量是关于这两个点的差；两个 embedding 的差常被当作「语义方向」（经典例子是 king - man + woman ≈ queen）。这些说法能成立，前提正是向量只有方向和长度、与起点无关。

1.6.2 范数把「多远」变成一个数

‖a‖ = √(a·a) 把一支箭头压成一个标量。它满足三件事：非负（长度不可能是负的）、齐次（‖ca‖=|c|‖a‖）、三角不等式（‖a+b‖ ≤ ‖a‖+‖b‖）。第三条不是数学家的洁癖——它正是「走折路不会比直路短」这句话的代数版本；检索系统用余弦相似度和 Euclidean 距离排序时，隐含依赖的就是这套性质。

我们这组数里 ‖a‖=√14≈3.741657，‖b‖=√77≈8.774964。注意 ‖a‖²=a·a=14 是个整数，而 ‖a‖ 是无理数。程序里先算平方和再开方是对的；反过来先对分量开方再组合会得到完全不同的东西。

陷阱别把「范数」和「绝对值」混为一谈

标量 |-3|=3 只有一种长度；向量的范数要看所有分量的联合贡献。a=(1,2,3) 的三个分量都不大，但 ‖a‖≈3.74 已经比最大分量还大——因为三个方向上的长度按勾股定理合成。有人写 ‖a‖ = |a₁|+|a₂|+|a₃|，那叫 L1 范数，是另一种度量，几何形状（菱形而不是圆）和梯度性质都不一样。本册默认说的范数是 L2。

1.6.3 单位化：把长度和方向分开

a/‖a‖ 叫单位向量，长度恰好为 1。它把「指向哪」和「有多长」拆成两件事：单位向量只管方向，范数只管长度，乘回去就得到原向量。余弦相似度的定义 cosθ = (a·b)/(‖a‖‖b‖) 正是先把 a、b 都单位化，再算点积——两个长度被除掉，只剩方向的夹角。

工程惯例什么时候不该单位化

文本检索里，同一段话出现一次和出现十次，语义方向几乎一样，但「重要程度」不一样。这时用余弦会把频次信息抹平。反过来在推荐系统里，如果你把用户行为向量单位化了，一个只点过一次的用户和一个点过一百次的用户会变得无法区分。所以「归一化还是不归一化」不是技术问题，是你想让模型看见什么的问题。

1.7 图形怎么读：三步图元不是装饰

这一节用了三个图元，它们的分工不一样。graph 画的是过程：第 2 帧里 b 的尾巴接到 a 头上，第 3 帧里合向量出现，读者点「下一步」能看到状态怎么变。memory 画的是静态布局：vec_t 里 n=3 和八个 double 槽是什么关系，哪一格有效、哪一格是空的。两者不能互换——用 graph 画内存会丢掉「格子」的直觉，用 memory 画向量加法会丢掉「首尾相接」的动作。

图元还有一条硬规矩：每一帧自包含。第 3 帧里必须把 a、b、a+b 三支箭头都写进去，不能只写新出现的 a+b——渲染器不会自动把上一帧的节点带过来，打印版每一帧是独立的一张图。这也是为什么图里的节点文字要短：重复写三遍，长句子会把一张图撑爆。

1.7.1 实现里的四个小坑

第一，n 和容量必须分清。vec_make(3, values) 只把前三个数拷进数组，后面五格保持未初始化；vec_dot 也只循环 i < a.n。要是某处手滑写成 i < LA_MAX，未初始化的内存就被算进点积，结果每次跑都不一样——而且这种 bug 在 -O0 下经常「看起来还挺对」。

第二，长度不同的两个向量不能点积。vec_dot 默认两个 n 相等；要是传进一个 2 维一个 3 维，它按 a.n 循环，会读到 b 的第三格（里面可能是上次算完留下的旧值）。共用库里没有维度检查，是为了让代码短到能印在书上；真实项目里这一步必须断言，或者在类型系统里把维度编进类型。

第三，浮点求和的顺序会影响最后几位。a·b 的三项 4、-10、18 先加哪个，严格来说结果可能差一个 ulp。这一节的数都选得能精确表示，所以四种顺序都给出 12.000000；换成随机小数就不会这么乖。这就是数值实验里容差不能写零的原因——atol=1e-6 不是「允许算错」，是给浮点实现留的合理空间。

第四，开方前先平方和。vec_norm 先算 vec_dot(a,a) 再 sqrt，而不是对每个分量开方。前者是一次开方，后者是三次开方加三次乘法，结果还不对——勾股定理说的是平方和再开方。把这步写反了，闸门里的 norm_a 黄金值会立刻报 numeric_value_mismatch。

陷阱"看起来一样"的两种写法

‖a‖² 和 a·a 数学上是同一个数，代码里却是两条路：前者要先算 vec_dot 再乘一次，后者直接就是 vec_dot。若你把 norm_a 的黄金值从 3.741657 改成 14，闸门会失败——因为程序打印的是开方后的 ‖a‖，不是平方。这类「平方 vs 开方」的错位是手写数值代码最常见的一类错误，读输出时先确认单位再确认数值。

实验记录把 b 换个数会怎样

建议自己改 bv 试两遍。改成 b=(2,4,6)，点积变成 2+8+18=28，cos 会明显变大——两向量更同向了。改成 b=(-2,-4,-6)，点积变成 -28，cos 变成负的——两支箭头几乎反向。注意 ‖b‖ 在这两次改动里没变，因为 (-2,-4,-6) 只是把 (2,4,6) 转了 180°，长度不变。这正好说明：cos 的变化来自方向，不是来自长度。改完记得把清单里的黄金值也改成真跑读数，否则闸门会报 numeric_value_mismatch。

实验记录为什么这一节选这三个数

a=(1,2,3)、b=(4,-5,6) 不是随手挑的。点积 1×4+2×(-5)+3×6=12 恰好是个整数，手算不容易出错；‖a‖²=14、‖b‖²=77 也都是整数，读者能验证开方前的那一步。b 的第二分量是负数，保证加法里真的出现「一正一负抵消」的情形，不会让人以为向量加法只是正数相加。余弦 0.365487 是个既不正也不负、既不接近 0 也不接近 1 的数，正好说明「大体同向但不是特别同向」。

工程惯例把这一节接到后面的矩阵

下一节的矩阵乘法，本质就是把这一节的 vec_dot 批量做一遍：矩阵每一行都是一个向量，乘上输入向量得到一个分量，所有行合起来就是输出向量。所以这里的点积不是「向量章的小练习」，它是整个深度学习前向传播的基本动作。你现在写的每一层 Wx+b，拆开来看都是若干个 a·b。把点积的两种看法（逐格乘加 / 投影）都记牢，后面看反向传播里的转置时才不会觉得那是个凭空冒出来的符号。

实验记录用改数字的办法检验理解

把 a 改成 (3,0,4)（长度 5）、b 改成 (0,5,0)（长度 5）。这时候点积是 0，两个箭头垂直，cos=0。再看 a+b=(3,5,4)，它的长度是 √50≈7.071，而 ‖a‖+‖b‖=10——三角不等式在这里是严格的。这个例子比正文里的三位数更好手算，适合拿来给人讲「为什么向量加法不是长度相加」。建议你真跑一遍，把 stdout 里的 dot、cos、a+b:[...] 三行读一读，确认自己的手算和程序一致。

1.8 这一节新增了什么

回到 1.1 的第 2 帧：多了共用库 common/（头文件与实现），多了 vec_basics/（驱动与清单）。共用库从这一节起长期陪伴整册，之后每章只往里加函数，不另起炉灶。这一节的四个函数——vec_make 装数据、vec_add/vec_scale 做线性组合、vec_dot 做投影、vec_norm 量长度——后面九节一次都不会丢掉：矩阵乘法是点积的批量版，特征向量要靠范数归一，SVD 的截断误差要用范数度量。先把它们写对，后面的楼才盖得稳。

下一单元问一个更关键的问题：给定几个向量，把它们任意伸缩再相加，到底能铺出多大的空间？那就是线性组合与张成。这一节的 vec_scale 和 vec_add 正好是那件事的两个零件，下一节只是把它们反复用起来而已。

1.9 为什么点积非得这样定义

前面我们直接接受了「对应分量相乘再求和」这个定义。但一个定义值不值得记住，要看它能不能同时做到三件事：算起来便宜（只需乘法和加法）、代数上好用（满足漂亮的运算律）、几何上说得通（能解释角度和投影）。点积三样全占。这一节把「为什么」补完整，顺便把后面所有推导的地基打牢。

1.9.1 双线性不是假设，是从定义推出来的

先证明两条性质。第一条是齐次性：把 a 整体乘一个数 c，有 (ca)·b = Σᵢ(c aᵢ)bᵢ = c Σᵢ aᵢbᵢ = c(a·b)。从定义到结论只用了「有限求和能提出公因子」这一步。同样地 a·(cb) = c(a·b)。第二条是分配性：a·(b+d) = Σᵢ aᵢ(bᵢ+dᵢ) = Σᵢ aᵢbᵢ + Σᵢ aᵢdᵢ = a·b + a·d。把两条合起来说：固定其中一个变量，点积对另一个变量是线性的，术语叫双线性（bilinear）——对每个变量分别线性。

这里有个初学时极容易踩的坑：双线性不等于「对整体线性」。若把 a 和 b 同时乘 c，点积变成 (ca)·(cb) = c²(a·b)，多出一个平方。后面讲二阶导数（Hesse 矩阵）、注意力分数随维度缩放时，这个平方因子会反复出现。记住一条：每乘一次向量，点积就多一次 c。

还要专门强调对称性 a·b = b·a，因为乘法满足 aᵢbᵢ = bᵢaᵢ。别小看这一行，它意味着我们不必区分「谁投影到谁」——a 在 b 上的投影长度乘 |b|，与 b 在 a 上的投影长度乘 |a|，是同一个数。这一性质让余弦相似度天然对称，检索时 sim(a,b) 与 sim(b,a) 永远相等。

1.9.2 用余弦定理把几何公式严格推出来

现在证明 a·b = |a||b|cosθ。很多人把它当定义背，其实它可以从两条更基本的事实推出来：余弦定理与刚证的双线性。

考虑向量 a-b，用两种办法算它的长度平方。代数办法：|a-b|² = (a-b)·(a-b) = a·a - a·b - b·a + b·b = |a|² - 2a·b + |b|²，这一步用到了双线性与对称性。几何办法：把 a、b、a-b 看成三角形的三条边，a-b 对着夹角 θ，余弦定理给出 |a-b|² = |a|² + |b|² - 2|a||b|cosθ。两式左边相等，右边前两项也相同，于是 -2a·b = -2|a||b|cosθ，两边除以 -2 就得到结论。

这个推导的价值不只是记住公式：它告诉你点积里的「长度乘积」和「余弦」不是谁硬塞进去的，而是勾股定理在斜三角形上的修正项。当 θ=90°，余弦为零，公式退化为勾股定理 |a+b|² = |a|²+|b|²。反过来看，正因为 |a|² = a·a，范数和点积是一回事：vec_norm 内部就是 vec_dot(a,a) 再开方。如果你把点积改了定义，范数、距离、余弦会一起变——它们是同一套结构的三张脸。

1.9.3 为什么不用「夹角」直接当定义

有人会问：既然点积能算夹角，为什么不干脆把 |a||b|cosθ 定义成点积，把「对应相乘再求和」当推论？答案是计算代价。cosθ 要算两个开方和一次反余弦，都是超越函数，硬件上要么用迭代逼近，要么查表；而「相乘再求和」只需要乘法器和加法器，是处理器一个周期就能干的事。把便宜的东西定义为基本运算，把贵的东西定义为导出量，这是数值计算的一贯取舍。深度学习的注意力层每做一次要算几百万个点积，如果每个都走反余弦，训练根本跑不动。

陷阱双线性在浮点里只是「近似成立」

数学上 (ca)·b = c(a·b) 精确成立，程序里却不总是。左边先把 aᵢ 乘 c 再求和，右边先求和再乘 c，两步的舍入位置不同，最后几位可能差一个 ulp。我们这一节选的整数都能被 double 精确表示，所以看不到差别；换成随机小数，(2a)·b 与 2(a·b) 的打印值可能不一致。闸门给 atol=1e-6 正是为这种情况留的。若你在调试里看到「明明数学上相等的两个式子在程序里差了 1e-15」，先怀疑浮点结合顺序，别急着怀疑公式。

1.10 失败模式：什么时候向量工具会失灵

这一节专门讲「什么时候不好使」，因为看懂一个工具的最好办法，是看它坏掉的样子。

1.10.1 零向量让余弦没有定义

余弦公式的分母是 ‖a‖‖b‖。只要有一个是零向量，分母为零，vec_dot(a,b)/(vec_norm(a)*vec_norm(b)) 在 C 里会得到 nan（0.0/0.0）或 inf（非零除以零）。屏幕上打出 cos=nan，这不是格式问题，是几何上「零向量没有方向，夹角无从谈起」。工程上的处理通常是在算余弦前检查范数是否为零，返回 0 或抛错，而不是让 nan 流进后续计算。nan 有传染性：一旦它进了 softmax，整个输出全变 nan，而且 nan != nan 让你的断言也失效。

1.10.2 维度不匹配是静默错误

vec_dot 只按 a.n 循环。传进 2 维的 a 和 3 维的 b，它会读 b 的前两格，忽略第三格——不越界、不报错、不崩溃。你以为算的是两个三维向量的点积，实际算的是截断后的二维点积。更糟的是那格空槽里可能残留着上一次计算的旧值，导致同一份输入在不同运行里得到不同结果。这类静默错误比崩溃危险得多：崩溃逼你去看，静默错误让你带着错误答案继续往下走。闸门对这种情况无能为力——它只核对打印出的数在容差内，而程序打印的本来就是错的数。防御办法只有两个：入口断言两个 n 相等，或者把维度编进类型（比如 C++ 的固定长度数组），让不匹配在编译期就被拦下。

1.10.3 大数相消吃掉有效位

点积 (-10) + 4 + 18 = 12 看着没问题。但把量级放大：取 a=(1e16, 1, -1e16)、b=(1, 1, 1)。精确答案是 1e16 + 1 - 1e16 = 1。可 double 只有约 15 位十进制有效数字，1e16 + 1 在 double 里就已经舍入成 1e16（因为 1 相对 1e16 太小，落到了精度之外），减完得到 0，真正的答案 1 被完全吃掉。这叫灾难性相消（catastrophic cancellation）。现象是：你手算明明有个不大的答案，程序却打出 0 或奇怪的小数。防御办法是补偿求和（Kahan 算法）或提高中间精度。本册的例子刻意选小整数，就是为了让读者先看清结构，不被数值问题分心。

实验记录让闸门替你制造一次失败

想亲眼看到闸门报错，最简单的办法是把正文 output 块里 dot=12.000000 改成 dot=13.000000，然后跑单元渲染。闸门会报 numeric_value_mismatch：正文的数与清单黄金值（以及程序真跑的 stdout）对不上。注意这说明什么——正文里的数不是装饰，它受清单约束。反过来，若你把 cos 那行改成 cos=nan，闸门会报数值无法解析。把这两个错误各触发一次，你对「闸门到底在验什么」就有体感了。做完记得改回来，否则整册的其他检查也会受影响。

1.11 与深度学习的对应：点积就是注意力的心跳

1.11.1 从 embedding 到 attention score

Transformer 的第一步把每个 token 映射成一个向量（embedding），于是「一个词」在模型里就是一支箭头，和你手里的 (1,2,3) 没有本质区别。自注意力的核心动作是：为每个 token 算出 query q、key k、value v，再用 q 与所有 k 的点积作为注意力分数（attention score）：score(q,kᵢ) = q·kᵢ / √d。分子 q·kᵢ 正是本单元的点积——它衡量当前 query 和某个 key 的方向有多一致，也就是「这个位置该去注意哪个位置」。除以 √d 是为了抵消维度带来的放大：若 q、k 的分量相互独立，点积的方差随维度 d 线性增长，不除的话分数会很大，softmax 饱和成接近 one-hot，梯度几乎消失。这个 √d 不是魔法，是点积双线性加上方差分析的直接结论。

1.11.2 反向传播里的点积梯度

训练时还要算梯度。由双线性立刻得到 ∂(a·b)/∂a = b 与 ∂(a·b)/∂b = a，因为 a·b = Σ aᵢbᵢ，对 aⱼ 求偏导时只有第 j 项留下 bⱼ。这意味着注意力的反向传播里，dL/dq 是「上游梯度与所有 key 的加权和」——又是一次向量线性组合。你在本节练的加、减、数乘、点积，就是反向传播的全部算术；后面矩阵那一单元只是把它们批量化，本质没有新东西。

工程惯例为什么「余弦 vs 点积」在检索系统里是个开关

向量数据库建索引时要先选相似度：点积，还是余弦。若 embedding 已经单位化，两者只差一个常数，可以互换；若没单位化，点积把「长度」也算进去——长度往往编码了置信度或词频，这时点积更合理。余弦则把长度约掉，只比方向。这个选择会改变召回结果，不是随手调的参数。实现上还有个细节：很多库为了速度，内部仍用点积，只是在入库前把向量归一化，从而在结果上等价于余弦。读懂本节「归一化抹掉什么」，你就知道该选哪个，而不是照抄默认配置。

1.12 手算核对：不用程序也能验的三组数

1.12.1 主例逐步算

取 a=(1,2,3)、b=(4,-5,6)。第一遍算点积，按分量逐项列出再求和：1×4=4，2×(-5)=-10，3×6=18，合计 4-10+18=12。第二遍算长度平方：a·a=1+4+9=14，b·b=16+25+36=77。于是 |a|=√14≈3.741657，|b|=√77≈8.774964。第三遍算余弦：12/(√14·√77)=12/√1078。用近似值验算：3.741657×8.774964≈32.833，12/32.833≈0.3655，与屏幕上的 0.365487 一致。三步都不需要计算器以外的东西，过程清楚，任何人重算都能得到同一串数——这就是「可手算核对」的意义，它让你在程序出错时还有一把独立的尺子。

1.12.2 垂直例子与单位化

再取 a=(3,4,0)、b=(0,0,5)。a·b=3×0+4×0+0×5=0，所以两向量垂直，cosθ=0。|a|=√(9+16)=5，|b|=5。把 a 单位化：a/|a|=(3/5,4/5,0)=(0.6,0.8,0)，它的长度是 √(0.36+0.64)=1。你可以再验 ‖a+b‖=‖(3,4,5)‖=√50≈7.071，而 ‖a‖+‖b‖=10，严格大于前者——三角不等式在这里是严格的，因为两向量不共线。若取共线的 b 为 (6,8,0)（即 2a），‖a+b‖=‖(9,12,0)‖=15 恰好等于 5+10，等号只在同向共线时成立。这组数小到能心算，适合拿来给别人讲清「长度不相加、方向才相加」。

自测题深化自测（先自己答，再对答案）
  1. 用分配律证明 (a+b)·(a+b) = |a|² + 2a·b + |b|²，并说明它和余弦定理的关系。
  2. 为什么点积叫「双线性」而不是「线性」？把 a、b 同时乘 2，点积变几倍？
  3. a=(1,0,0)、b=(0,1,0)，手算 a·b、|a|、|b|、cosθ。这说明点积为零是否要求某个向量为零？
  4. 一个 embedding 向量被整体乘了 3 倍。分别用点积相似度和余弦相似度比较它与原向量，结果各变多少？这对检索意味着什么？
  5. 程序打出 cos=nan，列出两种可能原因，并说明你先该检查哪一步。
注深化自测答案
  1. 展开得 a·a + a·b + b·a + b·b，由对称性 a·b=b·a，得 |a|²+2a·b+|b|²。与余弦定理 |a+b|²=|a|²+|b|²+2|a||b|cosθ 对照，可反推出 a·b=|a||b|cosθ，是同一件事的两种写法。
  2. 因为它对两个变量分别线性：固定 b 时对 a 线性，固定 a 时对 b 线性。同时乘 2 得 (2a)·(2b)=4(a·b)，变 4 倍，不是 2 倍，所以不是对整体的线性。
  3. a·b=0，|a|=|b|=1，cosθ=0（垂直）。这说明点积为零并不要求有零向量，只要两向量垂直即可。
  4. 点积相似度变 3 倍（(3a)·a=3(a·a)）；余弦相似度不变（分子分母同乘 3 约掉）。所以若你关心语义方向，用余弦；若长度本身编码了重要度，用点积。
  5. 两种原因：某个向量是零向量（分母为零，0/0 得 nan）；或者某分量已是 nan/inf 污染了计算。先检查两个向量的范数是否为零，再看输入里有没有非有限数——用 isfinite，不要用 ==nan 判断。

1.13 把「长度」讲透：柯西—施瓦茨与三角不等式

1.13.1 从一个显然的事实推出柯西—施瓦茨

前面说余弦的绝对值不超过 1，理由是「投影不会比原箭头更长」。这是直觉，不是证明。严格证明从一件谁都不会怀疑的事出发：长度平方永远非负，即对任意实数 t 都有 ‖a - t b‖² ≥ 0。把它按点积展开，得到一个关于 t 的二次式：

‖b‖² t² - 2(a·b) t + ‖a‖² ≥ 0

一个开口向上的二次函数对一切 t 都不小于零，唯一可能是它的判别式不大于零：(-2a·b)² - 4‖b‖²‖a‖² ≤ 0。化简并开方，得到 |a·b| ≤ ‖a‖‖b‖，这就是柯西—施瓦茨不等式。把两边除以 ‖a‖‖b‖，正好得到 |cosθ| ≤ 1，余弦的合法性由此而来；等号成立当且仅当 a 与 b 共线（那个二次式有重根，意味着存在某个 t 使 a-tb=0）。

这个推导值得慢慢读，因为它示范了线性代数里最常用的招数：把一个几何命题转成一个关于参数的二次式，再用判别式读出结论。后面证明矩阵范数的次乘性、最小二乘解的存在性，用的都是同一招。

1.13.2 三角不等式其实是柯西—施瓦茨的推论

三角不等式 ‖a+b‖ ≤ ‖a‖+‖b‖ 也可以从柯西—施瓦茨推出来，而不是当成公理接受。展开平方：

‖a+b‖² = ‖a‖² + 2a·b + ‖b‖²

由柯西—施瓦茨，a·b ≤ |a·b| ≤ ‖a‖‖b‖，于是

‖a+b‖² ≤ ‖a‖² + 2‖a‖‖b‖ + ‖b‖² = (‖a‖+‖b‖)²

两边都是非负数，同时开方就得到三角不等式。整条链条没有用到任何关于维度的假设，所以它在二维、三维、一百万维都成立——这也解释了为什么单位化后的向量能直接拿来做相似度排序：所有依靠范数的性质都在任意维度成立。

1.13.3 手算验证：把不等式按在本例的数字上

用我们熟悉的数字验一遍。取 a=(1,2,3)、b=(4,-5,6)：左边 |a·b|=12；右边 ‖a‖‖b‖=√14·√77=√1078≈32.83。12 ≤ 32.83 成立，而且离等号很远，正好对应「两向量大体同向但不共线」的直觉。再取共线的一对 a=(1,2,3)、b=(2,4,6)=2a：a·b=2+8+18=28，‖a‖‖b‖=√14·√56=√784=28，两边相等——等号只在共线时出现，验证了上一节的判据。

三角不等式同样可以验：a+b=(5,-3,9)，‖a+b‖=√(25+9+81)=√115≈10.724；‖a‖+‖b‖≈3.742+8.775=12.517。10.724 ≤ 12.517 成立且不取等，因为两向量不共线。这组手算把「投影不超过全长」「走折路不比直路短」两句大白话，落到了可以逐位核对的整数和根号上。

工程惯例这些不等式在训练里不是摆设

你可能觉得柯西—施瓦茨只是考试题。其实它保证了归一化后的点积（余弦）落在 [-1,1]，softmax 的输入才有合理范围；它也是推导出「梯度下降的更新不会让损失无限下降」这类收敛证明的起点。三角不等式则支撑着向量数据库的近似最近邻索引：很多索引结构（比如树、图）依赖「三角不等式」来剪枝——如果已知查询点到某个中心的距离，加上半径就能排除一整簇候选点。没有这些性质，十亿级向量的检索就没有可行的加速办法。

1.14 读图指引与一个反复出现的误解

1.14.1 三张图分别该盯着哪里

这一单元出现了 tree、graph、memory 三类图元，它们的读法不同。tree 的要点是看带 + 的行，它们标记本单元新增的工程文件；graph 的要点是逐帧比较状态差异——第 2 帧比第 1 帧多了什么，第 3 帧又多了什么，而不是把三帧当成三张互不相干的插图。memory 的要点是看「有效」与「空槽」的边界：n=3 说前三个 double 有效，后面五格只是占着位置。把图当动画的步骤看，而不是当静态照片看，才能读出作者想表达的「变化」。打印版没有动画，所以每帧都自包含、把上一帧的节点重复画一遍——这是约束，不是啰嗦。

1.14.2 最常见的误解：把向量当成「一串数」就完事

初学者最容易停在数组视角，把向量当成「装了几个数的容器」，于是遇到几何说法就觉得是比喻。正确的态度是来回切换：看到 a+b 要能立刻想到首尾相接的箭头，看到点积要能想到投影；反过来，看到两支箭头要能写出它们的分量。两种视角不是「直观 vs 严格」，而是同一对象的两种坐标表示。这个习惯在下一单元会立刻兑现——线性组合既是「伸缩再拼接」的几何动作，也是「解方程组」的代数动作，只会其中一种的人会在张成空间那里卡住。

陷阱别把「归一化」当成无损操作

单位化 a/‖a‖ 丢掉了长度信息，这一点在检索里是特性，在别处可能是 bug。比如做词频统计时，把词频向量单位化后，「出现一次」和「出现一百次」方向相同、余弦相同——模型再也看不出频次差异。再比如梯度更新里，若你偷偷把梯度单位化，更新步伐就固定为 1，再也不会随梯度大小自动调整步长，训练很可能直接发散。归一化永远要问一句：被除掉的那个长度，是不是本来携带了我要的信息？本单元的余弦相似度之所以合理，是因为它明确服务于「只比方向」的任务。

小结这一节的要点
  • 向量既是箭头也是有序数组；加减在数组里是逐格算，在几何里是首尾相接；
  • 点积 a·b = |a||b|cosθ：既含长度也含方向；除以两长度得余弦相似度，只比方向；
  • 范数 ‖a‖ = √(a·a)，单位向量是 a/‖a‖；
  • vec_t 用 n 记录有效长度、用定长数组装数值，空槽不参与计算；
  • 打印向量用冒号而非等号，避免被闸门的数值行解析当成坏行；
  • mode=numerical 的黄金值与容差写在清单，程序自报的 PASS 不算证据。

注自测题答案
  1. a-b=(1-4, 2-(-5), 3-6)=(-3,7,-3)；点积 4-10+18=12；cos 为正，夹角小于 90°。
  2. 向量只有方向和长度，没有固定起点。平移箭头不改它的分量，所以还是同一个向量；点才有固定位置。
  3. 不一定。例如 a=(1,0)、b=(0,1)，两个都不是零向量，但 a·b=0——它们垂直。
  4. 牺牲了长度（模长）信息。若「更长」本身有意义（比如词频、金额、重要度），归一化后这些差别被抹掉，点积反而更合适。
  5. a=[...] 会被解析成 key=a 的数值行，但 [...] 不是合法有限小数，闸门报 numeric_value_invalid。改用冒号后它只是普通文字行，逐字对账即可。
  6. 它只读 b 的前两个分量，把 b 的第三格完全忽略，算出的点积与「正确结果」无关；程序既不会越界也不会报错，所以是静默错误。真正危险的是那格可能残留着上一次计算的旧值，导致同一份输入在不同运行里得到不同点积。工程上要么在入口断言两个 n 相等，要么把维度编进类型，让这类调用编译不过。
  7. (-4,5,-6) 是 (4,-5,6) 整体乘 -1，是同一支箭头转了 180°，所以 ‖b‖ 不变，仍是 8.774964；点积从 12 变成 -12，余弦从 0.365487 变成 -0.365487。几何直觉：方向反了，夹角从锐角变钝角，余弦取相反数，长度完全不参与这件事。
