工程惯例工程惯例：为什么一个例子一个最小工程

标准对「分几个文件」只有一个要求：一个程序有且只有一个 main。其余全是惯例。本书从第二个项目起要求每个例子都摆成 src/ + include/，理由和上一单元一样，但在这里更值钱：

  • 一个例子只演示一件事：loop_offbyone 里只有差一错误，nested_continue 里只有 continue 的范围。出问题时你能立刻知道该看哪里；
  • 声明与定义分家：include/xxx.h 只放声明，src/xxx.c 放定义，src/main.c 只负责把输入喂进去、把结果打出来；
  • 清单把编译参数固定下来：这些例子的编译命令一律是 gcc -std=c17 -Wall -Wextra -Wpedantic -O0 -g -Iinclude src/main.c src/<例名>.c -o app ——-Iinclude 让编译器找到头文件，其余参数与第 1、2 单元完全一样（普通 -I 参数可以进清单，-w / -Wno-* 这类减警告的参数不允许）。

标准原文标准原文：`else` 归谁，真值怎么算

C 语言标准（ISO/IEC 9899，C17）6.8.4.1 节「The if statement」的语义部分：

In both forms, the first substatement is executed if the expression compares unequal to 0. In the else form, the second substatement is executed if the expression compares equal to 0.

An else is associated with the lexically nearest preceding if that is allowed by the syntax.

大意：两种形式下，只要表达式的值不等于 0 就执行第一个子语句；else 形式里，表达式等于 0 时执行第二个子语句。而 else 只跟按语法来说最近的那个还没有 else 的 if 配对——标准说的是「语法上最近」，不是「看起来最近」。

出处：ISO/IEC 9899:2018（C17）§6.8.4.1。

这段话同时回答了本节两个问题。第一，else 归谁：最近的、还没配对的那个 if，缩进不参与判断。第二，真值规则：0 假、非 0 真，跟类型没关系——上面输出里那行真值表就是这条规则的实物：

  • if (0) 假、if (0.0) 假——值为 0 就是假；
  • if (-1) 真——负数也是非 0，所以是真；
  • if (0.1) 真——浮点只要不是 0 就是真；
  • if ('0') 真——这一条最容易看错：'0' 是字符常量，它的值是这个字符在执行字符集里的编码（本机是 48），不是数字 0。
陷阱`if (x = 0.1)`：一次赋值被你当成了比较

看输出最后一行，再回头看源码：if (x = 0.1) 里只有一个等号，它是赋值：先把 0.1 存进 x，再拿 x 的新值（0.1）当条件——非 0，所以进了真分支。而写这段代码的人多半想写的是 if (x == 0.1)。

你会怎么被坑到：这段代码能编译，只是多一条警告（下面的编译会话里就贴着这条警告的原文）。新手看到警告一划而过，程序里那个「永远进真分支」的分支就一直留着，直到某天发现「这个判断根本没起作用」。

怎么防：一是习惯——条件里只要出现单个 = 就停下来数一遍；二是让编译器替你数——本书固定打开的 -Wall 里包含 -Wparentheses，它会说 suggest parentheses around assignment used as truth value（建议给「当条件用的赋值」加括号）。它的意思不是「加个括号就对了」，而是「这里看着像写错了」：真的想一边赋值一边判断，才写 if ((x = 0.1))。

大白话花括号的代价是零，收益是「我读到的就是编译器读到的」

if 后面的花括号不是语法要求（一条语句时可以不写），它是一笔零成本的保险：多打两个字符，换来的是「控制流的边界在纸上看得见」。真的只有一条语句、而且短到不会看错时，不写也没关系；只要有第二个语句、只要有人可能往里加语句，就必须写——因为后加的那一句永远不会被认为在 if 里，而读代码的人恰恰会这么以为。

回到严谨说法：if（表达式）语句 里的「语句」是一条语句；{ … } 是复合语句，在语法上算作一条语句——所以花括号不是「多了一层」，而是「把好几条打包成一条」。

语法规则`switch` 的形式与四条规矩

形式是 switch (整型表达式) { case 常量: 语句 … default: 语句 … }。四条规矩：

  1. 括号里必须是整型表达式（int、char、enum… 都行，浮点与字符串不行）；
  2. 每个 case 后面只能跟整数常量表达式——写变量、写函数调用都不行；
  3. case 的值必须互不相同（同一个 switch 里不许两个 case 撞值）；
  4. default 最多一个，位置由你定：写在最后、写在中间、写在第一个都合法（写法不同只影响「没有匹配时从哪里开始往下执行」）。

为什么不推荐把它放最前面：单个 default 配 5 个 case 时，放最后，读者一眼就知道「其余都走这里」；放最前面，读者要读到最后才发现「哦，没有匹配是回到第一行开始的」——两种写法都对，但一种更好读。代价也说清楚：grade_points 的 default 返回 -1，'E' 因此得到一个看得见的结果；要是删掉 default，'E' 会走出 switch、走到函数末尾那个 }——那是一个没有 return 的终点，调用者一旦用到这个返回值，按 6.9.1 节就是未定义行为（不是「返回一个大概的垃圾值」）。

6.4 三种循环的语义差与循环不变式

三种循环长得像，语法上差得可不少。先看形式：

语法规则三种循环：`for` / `while` / `do-while`
  • while (条件) 语句：每一轮开始前判断条件，为假就一轮都不跑；
  • for (初始化; 条件; 每轮之后) 语句：三段各管一段——第一段只在进入循环前跑一次，第二段在每一轮开始前判断，第三段在每一轮结束之后跑；
  • do 语句 while (条件);：先执行一轮，再看条件——所以循环体至少执行一次，这一条是它和前两者的全部区别。

顺序记牢这一条就不会混：while 与 for 都是「先看后做」，do-while 是「先做后看」。另外 break 能用在三者里，continue 也可以——但 for 的 continue 会照跑第三段（i++ 不会被跳过），这是它和 while 里 continue 最容易搞混的地方。

不用记术语，它就是一个提问方式：「每一轮跑完之后，我能拍胸脯说哪句话是真的？」

陷阱「从 0 开始」和「从 1 开始」是两种不同的生物

差一错误之所以难，是因为同一个 <= 在两个形状里一错一对：

  • 从 0 开始 + < n：跑 n 轮，用到的下标 0…n-1——这是「数组前 n 个」的标准形状；
  • 从 1 开始 + <= n：跑 n 轮，用到 1…n——这是「1 到 n 的和」的标准形状。

你怎么会被坑到：这两个形状长得像、轮数也一样，于是你把「从 1 开始」的终点抄到「从 0 开始」的循环里，程序不报错，只是多算一个（或多读一个）。判据只有一条：先定「我要哪些下标」，再决定起点与比较符，而不是反过来先想起点。写完再补一句「循环退出时 i 是几」——从 0 开始配 < n，退出时 i == n；配 <= n，退出时 i == n + 1。这两句一写，错没错立刻看得见（6.8 的 gdb 会话里 p i 打出 11 就是这个道理）。

标准原文标准原文：`goto` 跳不出函数

C 语言标准（ISO/IEC 9899，C17）6.8.6.1 节「The goto statement」的约束部分：

The identifier in a goto statement shall name a label located somewhere in the enclosing function.

大意：goto 的目标标签必须在同一个函数里。所以 goto 跳不出函数，也就不可能像有些语言那样「跨函数跳转」。

出处：ISO/IEC 9899:2018（C17）§6.8.6.1。

工程惯例工程惯例：`goto` 什么时候用

标准允许 goto 跳到函数里任何地方，但工程上三十年攒下来两条约定（是惯例，不是标准）：

  • 只往前跳，不往回跳。往回跳等于手工造循环，可读性还不如写个 while；往前跳的典型场景就是我们刚看的「多层跳出」。
  • 跳到的地方要么是统一收尾，要么是错误出口。C 代码里 goto 最常见的用法是「一段代码要申请好几个资源，任何一步失败就 goto fail;，在那儿按申请的逆序释放」。这样申请与释放成对出现、只有一个出口。第 12 单元（动态内存）会反复用到这个形状。

代价：每多一个标签，读代码的人就多一处「可能从别处跳到这里」要记住。所以约定是一个函数里的 goto 标签越少越好（一个、最多两个），而且标签名要能读出用途（done、fail、cleanup 比 L1 强得多）。

  • 模式 0（忘自增）：while (i < 5) 的循环体里没有 i++，i 永远是 0，条件永远为真——退出码 124，2 秒后被 timeout 杀掉。这是三种成因里最常见的一种，编译器一个字都不说（它没理由认为你想让 i 变），只能靠「程序不结束」来发现。
  • 模式 1（浮点做终止条件）：d != 1.0 同样退出码 124。0.1 加十次得到的是 0.9999999999999999（不等于 1.0），再加一次是 1.0999999999999999——跳过了 1.0，那个 != 永远不会为假。
  • 模式 2（同一循环换成 d < 1.0）：能停，但 rounds = 11！加了 11 次（0.0 到 1.0999999999999999），不是我们直觉里的 10 次。浮点的差一错误就长这样：终止条件写成 < 之后，轮数由「累加的误差」决定，而不是由数学决定。
  • 模式 3（条件永真）：for (;;) 省掉第二段，循环体里也没有出口——退出码 124，同样 2 秒后被掐掉。它和模式 0 的区别在「条件」这一侧：模式 0 的条件本来会变假，只是循环体忘了让它变；模式 3 的条件根本没有（被一个恒不为 0 的常量顶替了）。

第三种成因「条件永真」就是 6.4 里标准说的那句：for (;;) 里被省掉的第二段等于一个恒不为 0 的常量，循环只能靠 break / return / goto 出来。模式 3 只是故意这么写的结果；真正危险的是不小心写成恒真（比如把 while (i > 0) 敲成 while (i >= 0)）。写 for (;;) 时请自己数一遍有几条出口。

小结小结：分支的配对、真值与贯穿
  • else 归语法上最近的那个 if，缩进不算数；一条语句的花括号可以省，但「看着像在里面」的语句永远是 bug 的温床（-Wdangling-else / -Wmisleading-indentation 会替你数）。
  • 真值就是「非 0 为真」：if (0.0) 是假、if (-1) 是真、if ('0') 是真（'0' 的值是它在本机执行字符集里的编码 48）；if (x = 0.1) 是赋值当条件，-Wparentheses 会给警告。
  • switch 的控制表达式必须是整型（浮点、字符串直接编译失败），case 后面必须是整数常量表达式（写变量直接报错）；default 的位置由你定，但最好别省。
  • 漏 break 会贯穿；-Wimplicit-fallthrough 属于 -Wextra——只加 -Wall 它不吭声，只加 -Werror 它仍然不出现（没有警告可升级）；必须 -Wextra 加 -Werror 才把退出码从 0 变成 1。
小结（续）小结：循环的边界、跳出与类型
  • while / for 先看后做，do-while 先做后看（至少执行一次）；用「每一轮开始时什么为真」当判据检查循环，再用「退出时循环变量是几」检查差一错误（n = 10 时退出值为 11）。
  • 跳出只有最内层：continue 跳过一轮、break 结束一层；多层跳出用 goto（标签只能在自己函数里）或标志位，能靠小函数 + return 解决就不用 goto。
  • 停不下来的三种成因：忘自增（编译器不吭声）、浮点做精确相等（d != 1.0 永远为真）、条件恒真（for (;;) 与写错的不等号）；读输入要用 int c 接 getchar() 并与 EOF（本机是 -1）比。
