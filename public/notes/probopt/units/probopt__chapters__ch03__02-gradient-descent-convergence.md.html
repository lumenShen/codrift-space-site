7.1 先看工程长什么样

上一单元把「最优点长什么样」讲清楚了：凸函数加驻点就是全局最小，强凸再加唯一性。这一单元问下一个问题：从某个起点出发，一步一步走，到底走不走得到。答案是取决于步长。步长太小，走得稳但慢；步长太大，越过谷底来回震荡，甚至越震越大直接发散。这一节把一个二维二次碗作为实验台，把这件事做成可见的 12 行 loss 轨迹。

工程上仍然是一个「驱动 + 本地算法 + 共用库」的三源文件工程。种子来自环境变量 PO_SEED，由清单注入，程序里不硬编码。这是 train 模式的硬要求：同一个种子跑两次必须给出逐值一致的轨迹，换一个对照种子必须改变数值——否则你看到的那条漂亮曲线可能只是一张写死的表。

大白话先建立一个画面

把二次碗想成一张中间低、四周高的橡胶膜。你站在膜上的某一点，脚下的坡度就是梯度；梯度下降让你每次都沿最陡的下坡方向走一小步。步子迈多大由学习率决定。碗在不同方向上陡峭程度不同：陡的方向步子要小，不然会越过谷底；平的方向步子要大，不然挪不动。一个固定的学习率要同时伺候所有方向，这就是条件数的由来。

第 1 帧是这一节开始时的形态：ch03 下只有上一单元留下的 convex_probe/。第 2 帧多了 gd_converge/ 整个项目，四个带 + 的文件就是这一节的全部新增。共用库不在图里，因为它从第 1 单元起就在，不属于本单元新增——这是读这类图的基本功：只盯 + 行。

清单 po07-gd.json 用 mode=train，sources 列 src/main.c、src/gd.c、../../common/src/probopt.c，flags 给 -Iinclude 与 -I../../common/include，libs 给 -lm。和前两个单元不同的是，它多出 seed_env、seed、seed_contrast 三个字段，以及 expect.train 里的收敛判据。下一节先讲数学，再回到这张清单逐项解释。

7.2 更新式：一步往哪走、走多远

梯度下降只有一行公式：

w ← w - lr · ∇f(w)

∇f(w) 是损失在当前位置的梯度，指向函数上升最快的方向；前面加负号，就是往下降最快的方向走。lr 是学习率（步长），它把梯度的量级缩放成实际位移。为什么不能直接用梯度当位移？因为梯度的大小依赖于目标函数的尺度：把损失整体乘 100，最优点不变，梯度却放大 100 倍，直接用会把你甩出定义域。学习率就是那个把「方向」和「步幅」分开的旋钮。

一元情形下这件事最直观：f(x)=(x-2)²，f'(x)=2(x-2)。从 x=0 出发，f'=-4，往正方向走；取 lr=0.1，新位置 0 - 0.1×(-4) = 0.4。梯度变成 -3.2，下一步走到 0.72。每一步都在靠近 2，而且越靠近梯度越小、步子越短——这就是「自动刹车」。要注意 lr=0.1 在这个函数上是安全的，因为它的二阶导是 2，稳定上界是 2/2=1；换成二阶导很大的函数，同样的 0.1 可能就过头了。

陷阱把「梯度小」误读成「离最优点近」

梯度小有两种可能：你确实快到最优点了，或者你落进了一片平坦区域，那里离最优点还远得很。后者在深层网络里很常见，也是「训练卡住」的主因之一。梯度下降的停止准则通常写「梯度范数小于阈值」，它在凸问题上可靠，在非凸问题上就会在鞍点或平坦区误判。你会发现 loss 曲线平了，以为收敛了，其实模型还没学到东西。这个坑要到第 8 单元的动量方法才部分缓解——动量靠累积过去的梯度冲过平坦区。

7.2.1 为什么负梯度是「最陡下降」方向

「沿负梯度走」这句话需要一个理由。考虑从点 w 出发沿单位方向 d 走一小步 ε，损失的一阶近似是 f(w+εd) ≈ f(w) + ε ∇f(w)ᵀd。想让这一步下降最多，就要让内积 ∇f(w)ᵀd 最小。由柯西—施瓦茨不等式，∇fᵀd ≥ -‖∇f‖‖d‖，而 d 是单位向量，所以下界是 -‖∇f‖；取等号当且仅当 d 与梯度反向。于是 d = -∇f/‖∇f‖ 就是最速下降方向。

这个推导顺手解释了两件事。第一，梯度为零时任何方向的一阶变化都是零，一阶信息失效，必须看二阶——这正是鞍点判断的入口。第二，最速下降只是局部最优方向：它保证脚下的瞬间最陡，不保证走一步之后仍然最陡。二次碗上你会看到路径呈折线，每拐一次方向都变；若换成牛顿法，用 Hessian 的逆来校正方向，路径会直得多，代价是每步要算并求逆一个矩阵。梯度下降的取舍就是：每步便宜，但可能要走很多步。

工程惯例数值梯度：不用公式也能验证方向

若你怀疑自己推错了梯度，可以用中心差分独立算：(f(w+εeᵢ)-f(w-εeᵢ))/(2ε) 给出第 i 个偏导，ε 取 1e-5。本例 f(w)=½(0.5w₀²+2w₁²)，在 w=(1,1) 处解析梯度是 (0.5,2)；中心差分会给到小数点后七位相同。这个方法慢，但「明显正确」，适合在写复杂网络时给反向传播背书。 train 模式不管梯度对不对，这项得你自己用数值对拍补上。

7.3 二次碗：把收敛条件做成可核对的数字

本单元的实验台是二元二次函数：

f(w) = ½ (0.5 w₀² + 2 w₁²)

它的 Hessian 是对角矩阵 diag(0.5, 2)，两个特征值分别是 0.5 与 2。矩阵的对角结构让两维完全解耦：第 0 维的梯度是 0.5 w₀，第 1 维是 2 w₁，更新时各走各的。这个「解耦」是关键——我们可以把二维问题拆成两个一维问题，分别检查收敛条件，再把结论合起来。

对一维二次函数 f(x)=½ a x²，梯度是 a x，更新是 x ← (1 - lr·a) x。每走一步，x 乘上因子 ρ = 1 - lr·a。要让 x 趋近零，必须 |ρ| < 1，也就是 -1 < 1 - lr·a < 1，化简得到 0 < lr·a < 2，即 0 < lr < 2/a。本例中 a₀=0.5，允许 lr < 4；a₁=2，允许 lr < 1。两维都要收敛，取交集得到 0 < lr < 1。最大曲率 L = max(0.5, 2) = 2，于是条件写成熟悉的 0 < lr < 2/L。

第 2 帧的因子来自 ρ = 1 - lr·a：方向 0 是 1 - 0.3×0.5 = 0.85，方向 1 是 1 - 0.3×2 = 0.4。每步把对应坐标乘上这个数，12 步之后分别是 0.85¹² ≈ 0.142 与 0.4¹² ≈ 0.0000168。所以程序打出的 end_w 里第一个分量还有零点一几，第二个已经接近零——同一个步长在平的方向慢、在陡的方向快，这正是条件数 κ = 2/0.5 = 4 的可见后果。

第 2 帧的箭头方向不是直指碗底，而是垂直于当地等高线——这是负梯度的几何意义。第 3 帧说明了一个重要现象：当第二维几乎归零后，剩下的路程全在平的长轴上，收敛明显变慢。等高线越扁（条件数越大），这条长轴越长，走的步数越多。

7.3.1 一般二次碗：对角化之后还是同一套公式

真实的二次目标通常写成 f(w) = ½ wᵀ A w - bᵀw + c，其中 A 是对称正定矩阵。对称矩阵一定能正交对角化：A = Q Λ Qᵀ，Λ 的对角元是特征值 λᵢ，Q 的列是对应的正交特征向量。作变量替换 u = Qᵀ w，目标在新坐标里变成 ½ Σ λᵢ uᵢ² 加一个线性项——又是一个各维解耦的碗。所以前面在 diag(0.5,2) 上推的每个结论都通用：第 i 个方向的收缩因子是 1-lr·λᵢ，稳定条件是 lr < 2/λ_max，最优步长是 1/λ_max，收敛速率由 λ_min/λ_max 决定。

这也给出了条件数的严格定义：κ = λ_max/λ_min。本例 λ_max=2、λ_min=0.5，κ=4。正交变换 Q 在几何上只是把碗旋转一个角度，不改变它的扁圆程度；条件数才是旋转不变量，所以它是问题本身的难度，不是坐标系的毛病。实践中改善条件数的办法是预处理：找一个可逆矩阵 P，令 w = P z，使 Pᵀ A P 的条件数接近 1。在 P = A^{-1/2} 的理想情况下，新 Hessian 变成单位矩阵，一步就到最低点——这就是牛顿法的极限形态。真实算法做不起精确的 A^{-1/2}，于是有了各种近似，第 8 单元的 Adam 可以看成一种对角近似。

陷阱特征值全为正才叫「碗」，有一个零就变成「槽」

若 A 半正定但有零特征值，沿那个特征向量方向目标完全平坦，最优点不构成孤立点而是一条线。梯度下降在那个方向上不会移动，收敛到哪个点完全由起点决定。若有负特征值，那个方向是「倒扣的碗」，目标沿它无下界，优化问题本身没有最小值。你会被坑到的场景是拿一个经验协方差矩阵当 Hessian：样本数少于维数时它必然奇异，零特征值一堆，「收敛」只是停在了某个任意点。加一点正则（岭回归的 λI）把零特征值抬起来，是最常见的补救。

7.4 步长的三种命运：收敛、震荡、发散

把 ρ = 1 - lr·a 的正负分三种情况看，就得到学习率选择的全部故事。第一，0 < lr·a < 1，此时 0 < ρ < 1，坐标每步同号缩小，平滑收敛。第二，1 < lr·a < 2，此时 -1 < ρ < 0，坐标每步变号、绝对值缩小——在碗两侧来回跳，但幅度逐次减小，叫震荡收敛。第三，lr·a > 2，此时 ρ < -1，每步变号且绝对值放大，离碗底越来越远，叫发散。边界 lr·a = 1 时 ρ=0，一步到位；lr·a = 2 时 ρ=-1，在两点间永远来回，不收敛。

第 2 帧用 lr=0.7（对 a=2 那一维，lr·a=1.4，ρ=-0.4），确实变号且缩小；第 3 帧用 lr=1.2（lr·a=2.4，ρ=-1.4），确实越跳越大。本单元程序选的 lr=0.3，对最陡的那维 lr·a=0.6，属于第一档——平滑收敛，所以前 8 步 loss 单调下降，能过 monotone_window=8 的闸门。若把它改成 0.7，loss 会上下跳动，闸门立刻报 train_loss_not_decreasing。

陷阱只看 loss 轨迹不一定看得出震荡

震荡有两种：坐标变号但 loss 仍下降（因为 loss 只看平方），和坐标变号且 loss 反弹。前一种在 ρ 为负但绝对值小于 1 时出现：参数在碗两侧来回跳，loss 却一路下降，肉眼看 loss 曲线完全健康。后一种才是发散。本单元的程序把 end_w 也打了出来，就是为了让这条信息可见——若你只看 loss= 行，可能永远发现不了参数在震荡。真实训练里要同时看参数范数或梯度范数，不能只盯 loss。

7.4.1 不知道 L 怎么办：线搜索与步长衰减

0 < lr < 2/L 这个条件很干净，但前提是知道 L。真实目标函数里 L 通常只能估计：你可以用有限差分近似 Hessian 的最大特征值，也可以从一个保守的小步长开始试探。更稳妥的做法是回溯线搜索：先给一个试探步长，走一步算损失；若损失没有按预期下降，就把步长减半再试，直到满足条件。这条规则不要求预先知道 L，实践中比固定步长皮实得多。

步长衰减是另一种常见策略：训练初期用较大的步长快速接近最优区域，后期逐步缩小，让参数在最优附近稳定下来。它与线搜索并不冲突——前者管「整个训练过程的节奏」，后者管「当前这一步该迈多大」。在第 6 单元说过逻辑回归的 L 与数据矩阵的谱范数有关，所以换一批数据、做一次标准化，L 就可能变化；固定步长要跟着重调，而线搜索会自动适应。

陷阱把「loss 变小」当成线搜索的唯一判据

回溯线搜索通常要求的不只是 f(w_new) < f(w)，而是充分下降：f(w_new) ≤ f(w) - c·lr·‖∇f‖²，c 是一个小正数如 1e-4。若只要求变小，步长可能被取得极小，每步只降一丁点，程序一直判定「合格」却几乎不前进。你会被坑到的场景是：训练 loss 缓慢下降，看起来在收敛，实际几百步只走了固定步长几十步的距离。充分下降条件用梯度范数给下降量设了一个门槛，堵住了这种「假装在优化」。

7.5 强凸为什么给的是「线性收敛」

上一单元说过，μ-强凸加 L-光滑时，步长取 1/L 有 (1-μ/L)^k 的线性收敛保证。现在用二次碗把它落实。这里 μ=0.5、L=2，条件数 κ=4，最优步长 1/L=0.5，收敛因子 1-μ/L=0.75，也就是每步把初始 gap 缩到 75%。程序取的是 0.3 而不是最优的 0.5：对最陡那维 ρ=0.4 比最优步长的 ρ=0 慢，但对最平那维 ρ=0.85 比最优步长的 ρ=0.75 快，综合起来 12 步的轨迹依然漂亮。

「线性收敛」这个词容易被听成「loss 随步数呈直线下降」。它真正的意思是误差按几何级数递减：f(w_k) - f* ≤ c·q^k，q<1。取对数后，log gap 对步数 k 才是一条直线。本例第一维的收缩因子是 0.85，12 步后剩 0.85¹²≈0.142，取自然对数 log(0.142)≈-1.95，平均每步约 -0.163——这就是那条直线的斜率。理解这一点，你就能从半对数图上直接读出收敛速率，而不是盯着原始曲线猜。

工程惯例条件数差一点，步数差很多

若把 Hessian 改成 diag(0.02, 2)，条件数从 4 飙到 100。最陡维仍允许 lr<1，但最平维的允许上界是 2/0.02=100， contraction 因子取 lr=0.5 时是 1-0.5×0.02=0.99。要让这一维缩到原来的 1%，需要 0.99^k ≤ 0.01，即 k ≥ log(0.01)/log(0.99) ≈ 459 步；而条件数为 4 时只要十几步。这就是「线性回归先标准化特征」的全部理由：把各维曲率拉到同一量级，条件数变小，步数从几百掉到几十。

7.5.1 线性收敛的证明骨架

把上一单元的下降引理与强凸性接起来，几行就能推出线性收敛。记 g_k = ∇f(w_k)，下降引理给 f(w_{k+1}) ≤ f(w_k) - (1/(2L))‖g_k‖²。强凸性有一个等价推论：‖∇f(w)‖² ≥ 2μ (f(w)-f*)——把「函数值 gap」和「梯度范数」绑在一起，直观上是最优点附近梯度不会异常小。把这个下界代入下降引理，得到 f(w_{k+1})-f* ≤ (1 - μ/L)(f(w_k)-f*)。迭代 k 次就是 (1-μ/L)^k 乘上初始 gap，线性收敛得证。

这条链条里最脆弱的一环是 ‖∇f‖² ≥ 2μ gap，它只在强凸时成立。若只是普通凸函数，梯度可以在离最优点很远的地方非常小（想想一条渐近趋近横轴但永远不到零的曲线），于是下降引理里的下降量也小，算法可能要走极其多步。这就是「凸但不强凸」的问题最难在收敛速度上给出好看结论的原因。本例的平方函数把每个环节都取到等号：‖∇f‖² = 4(f-f*)，μ=2，所以 2μ=4，正好相等。

工程惯例从半对数图读收敛率

把每步的 gap 取自然对数后画出来，线性收敛表现为一条直线，斜率是 log(1-μ/L)。本例 μ/L=0.25，斜率 log(0.75)≈-0.288；若你从程序打的 12 行 loss 里减去真实最优值 0，再取对数拟合，应该看到接近这个斜率的下降。实际数据不会完美，因为最陡那维以 ρ=0.4 收缩、最平那维以 ρ=0.85 收缩，前几步由快的一维主导，后面转为慢的一维主导，曲线会出现一个拐点。能看出这个拐点，你就理解了条件数在轨迹上的真实样子。

7.6 真跑：12 步轨迹与 train 闸门

现在把程序的核心贴出来。损失函数与更新规则都在本地文件 src/gd.c，它从共用库取 LCG 随机源，用 po_uniform() 产生起点。注意 gd_loss 里那个 0.5 系数：它让梯度刚好是 A w，不多一个 2 的因子，收敛条件才写得干净。

驱动 main.c 读环境变量 PO_SEED，用 strtoul 转成无符号长整型，再交给 gd_init_from_seed。种子从环境变量来而不是写死在代码里，是 train 模式的纪律：写死叫硬编码，写在清单里叫实验条件，后者可被对照实验改变。循环跑 12 步，每步打印一行 loss=，最后打一次终点坐标。

真跑（种子 12345）得到的 stdout 如下。12 行 loss 从 0.353410 一路降到 0.005267，首行与末行之间差 0.348143。这些数不是我手填进去的，而是程序按清单注入的种子真跑后抓回来的。

实验记录train 闸门查的四件事

7.6.1 清单字段逐项读一遍

把 po07-gd.json 当成实验记录的表格来读，每个字段都有明确职责。seed_env 写 PO_SEED，告诉闸门把种子放进哪个环境变量；seed=12345 是主实验条件；seed_contrast=67890 是对照条件。expect.train.loss_key 写 loss，闸门就从 stdout 里所有形如 loss=数值 的行取出轨迹；min_points=12 保证程序真的跑了 12 步，少一步就报失败。

四个阈值是为了防止「看起来在收敛」的骗法。first_min=0.35 要求起点不能已经在最优附近——若程序把起点写成 (0,0)，首行 loss 会是零，下降演示就没有意义。last_max=0.006 要求终点足够低，防止程序每步只走微不足道的一小步、12 步都没走出起点附近。decline_min=0.34 要求首尾确实有明显降幅，防止「起点低终点也低」的平凡通过。monotone_window=8 配合 slack=1e-4，要求前 8 步不反弹，容差给浮点比较留一点余地。这四条互相独立，少一条都能构造出骗过闸门的写法。

实验记录真跑的三组数字

主种子 12345：起点 1.020403, 1.016548，首行 loss 0.353410，末行 0.005267，首尾差 0.348143。对照种子 67890：起点 1.547002, 1.157184，首行 0.646527，末行 0.012105。同种子第二次运行的 15 行 stdout 与第一次逐字一致。三组结果合起来说明：程序确定性地读了种子，由种子决定起点，再由起点经 12 步更新算出轨迹；任何一环被硬编码，三次运行里至少有一次会露馅。

7.7 种子复现与对照：为什么要跑三次

train 模式一共跑三次程序。第一次带 seed=12345，用来抓 stdout 并检查收敛；第二次还是 12345，要求逐值一致，否则报 train_nondeterministic；第三次换成 seed_contrast=67890，要求至少一个数值变化，否则报 seed_has_no_effect。真跑对照种子的结果是：起点变成 start_w:[1.547002,1.157184]，首行 loss 0.646527，末行 0.012105——整条轨迹都变了，说明数字确实由种子驱动的起点算出来，而不是一张硬编码的表。

为什么两次同种子还不够？一个把整条 loss 曲线写死进数组的程序也完全确定，同种子两次能一模一样。所以必须加对照种子。反过来为什么还要同种子两次？因为一个用时间或地址当随机源的程序，每次跑出来都不同，看起来「有变化」却无法复现。两次一致证明确定性，换种子变化证明数值真的来自种子——两条缺一不可。

第 2 帧强调两次运行用的是同一个算法与步长，唯一差别是起点；第 3 帧的末态不同正是闸门 seed_has_no_effect 检查的反面证据。图里的节点只写关键数字，完整轨迹在 output 块里。

陷阱可复现不等于正确

同种子两次一致，只能说明程序是确定的；换种子有变化，只能说明程序读了种子。两者都通过，也不能证明梯度算对、损失算对。本单元的正确性来自三条独立证据：手算的收缩因子与 end_w 吻合、12 步 loss 单调下降且首尾差符合预期、换种子后整条轨迹改变。train 闸门查的是后两条，第一条由你手算把关。把「闸门通过」当成「数学正确」是这一册反复要破除的误解。

7.8 非凸问题上，最多保证到驻点

把碗换成深层网络的损失，前面那些漂亮保证还剩什么？几乎只剩「梯度下降是下降方法」这一条：在 L-光滑的前提下，步长足够小，每步至少不增加损失。但「不增加」不等于「能到全局最优」，甚至不等于「能到局部最优」——你可能停在一个鞍点。鞍点是指某些方向是局部最小、另一些方向是局部最大的驻点，梯度同样为零。在高维空间里，随机驻点是鞍点的概率远大于局部最小：要成为局部最小，Hessian 的所有特征值都得为正，维数越高这个条件越苛刻。

这听起来很悲观，但实践中有三个缓冲。第一，过参数化让大量方向的曲率变正，真正的坏鞍点变少。第二，随机梯度下降的噪声会不断扰动参数，有机会把鞍点附近的状态踢走；确定性的全梯度下降反而更容易卡住。第三，很多局部最小的损失值彼此接近，对泛化而言「找到一个够好的局部最小」往往就够了。这些说法都有各自的理论与实验支持，但都不是「梯度下降保证收敛到全局最优」那种强保证。

工程惯例怎么判断训练是卡在鞍点还是真的收敛

一个可操作的检查是：在疑似停滞的参数点上，随机取几个方向算方向导数或直接观察 loss 在扰动后的变化。若所有方向都让 loss 上升，八成是局部最小；若某些方向让 loss 下降而其他方向上升，就是鞍点。另一个便宜的信号是梯度范数：它确实很小，但 loss 仍明显高于你预期的水平，说明停在了平坦区。第 8 单元的动量方法之所以有效，正是因为它保留过去的方向，能沿着「一直往下」的方向积累速度，冲过那些会让纯梯度下降停下的平坦点。

7.8.1 高维驻点为什么大多是鞍点

一个随机驻点是局部最小的概率，取决于 Hessian 的所有特征值是否同号。若假设各特征值的正负近似独立、每边概率各半，d 维空间里这个概率大约是 2^{-d}。d=2 时还有四分之一，d=1000 时已经是天文数字般的小。所以高维非凸问题里，梯度下降真正需要防的往往不是局部最小，而是鞍点。这个统计论证是直觉性的——真实网络的特征值并不独立——但结论方向是对的，而且有实验支持。

鞍点附近的行为很特别：某些方向向上弯、某些向下弯。纯梯度下降在正好落到鞍点时梯度为零，会永远停在那里；但只要有一点数值扰动或随机梯度噪声，就会被向下弯的方向推走。随机梯度下降的噪声在这里反而是件好事：批量越小，噪声越大，越容易逃离鞍点；代价是收敛后参数会持续抖动。学习率衰减的作用之一就是前期靠噪声逃逸、后期压低噪声稳定下来。

工程惯例用一个二维函数亲手看鞍点

取 f(x,y)=x²-y²，在原点梯度为零。沿 x 方向是局部最小，沿 y 方向是局部最大，所以原点是鞍点。让梯度下降从 (0.1, 0) 出发：y 分量为零，梯度在 y 方向也是零，程序会沿 x 方向走到原点然后停住——完美卡在鞍点上。若起点改成 (0.1, 0.1)，y 方向的梯度是 -2y，更新 y ← y + 2lr·y，只要 lr 合适，y 会指数增长，参数被推离原点。这个实验说明：能不能逃离鞍点，全看扰动有没有把那个不稳定方向激活。

7.9 三个最常见的误解

第一，把学习率当成「越大越快」。从本节的三种命运看，超过上界之后越大越糟；就是在安全区间里，过大也会带来震荡，虽然 loss 可能仍下降。学习率是一个有上界的调参量，不是一个「加满就好」的油门。

第二，把 lr < 2/L 当成通用常数。这个条件只对二次函数的精确线搜索分析严格成立；对一般 L-光滑凸函数，保证收敛的充分条件是 lr < 1/L（更保守），对非凸函数还要考虑随机梯度的方差。L 本身也难知道——它就是 Hessian 最大特征值的上界，真实网络里只能估计。所以工程上常做的「学习率衰减」，本质是在训练过程中逐步缩小对 L 的估计，先在大的尺度上快速下降，后期再收细。

第三，以为 loss 单调下降才算正常。小批量训练里每步用的是一批样本的梯度，loss 曲线上下抖动是常态；train 模式之所以能对这条二次碗轨迹要求前 8 步非增，是因为这里用的是全批量确定性梯度、目标又是严格凸的二次碗。换成随机梯度，就该看移动平均的下降趋势，而不是逐点比较。

真正决定学习率的还有一种尺度感：参数本身的数量级。若某维权重的典型取值是 1e-3，而另一维是 1e3，同一个绝对步长对前者是巨步、对后者是微步。这就是标准化输入与合理初始化如此重要的原因——它们让各维参数的可行尺度接近，固定学习率才有机会同时合适。

陷阱别在本例里改步长却忘改闸门阈值

把 GD_LR 改成 0.7，前几步 loss 会明显反弹，monotone_window=8 的检查会报 train_loss_not_decreasing；改成 0.05，轨迹依旧单调，但末行可能高于 last_max=0.006，报同一个码。这两个失败都不是闸门坏了，而是它真的在拦「步长不合适」。若你为了让闸门通过而把 last_max 放宽到 1.0，闸门是过了，但那条「必须真的收敛」的纪律被你自己拆掉了——这正是所有实验清单共同的底线：黄金值来自真跑，不能反过来为了绿字改黄金值。

7.10 与后面单元的接口

这一节把「步长决定走不走得到」讲成了一个可计算的区间，后面两条线都会用到它。第一条是第 8 单元的动量与自适应方法：动量相当于在 update 里引入惯性，把条件数造成的「平方向走得慢」问题部分缓解；Adam 则给每个坐标配一个按梯度平方累积出来的步长缩放，可以粗略理解成对每个方向的曲率做归一化。理解了本单元 ρ = 1 - lr·a 的逐维收缩，再看 Adam 的逐坐标更新就不会觉得那是魔法。

第二条是第 9 单元的对偶。对偶问题里的对偶变量有它自己的步长与收敛条件，但背后的「沿梯度走、步长受曲率限制」是同一套直觉。再往后到第 10 单元的采样，你会看到另一类随机性：那里的随机来自分布，这里的随机只来自初始化。两种随机都要求固定种子才能复现，但前者还要检查统计量是否与真值相符，后者只要检查轨迹确定性就够了。

工程惯例用三个问题复盘这一个实验

拿到任何一份训练轨迹，先问三件事。第一，起点在哪：本例 start_w 约 (1.02,1.02)，离最低点 (0,0) 不远不近，适合演示；若起点恰好是 (0,0)，整条轨迹平坦，什么也证明不了。第二，中间有没有异常：12 行 loss 一直下降，但 end_w 第二个分量已到 0.000017，说明陡的那维早就收敛，剩下的路程全在平的方向上。第三，证据够不够：手算的 0.85¹² 与终点第一分量 0.145144 相符，这是独立于闸门的第三重核对。养成这三个问题的习惯，你读别人的实验报告时就不会只看「loss 降了」四个字。

  1. 对 f(x)=½ a x² 推导收缩因子 ρ=1-lr·a，说明 lr=2/a 时发生什么。
  2. 本例 Hessian 是 diag(0.5,2)。取 lr=0.7，两个方向的收缩因子各是多少？属于收敛、震荡收敛还是发散？
  3. 为什么程序要同时打印 loss= 与 end_w:[...]？只看 loss 会漏掉什么现象？
  4. train 模式为什么跑三次？两次同种子与一次对照种子各自防的是什么？
  5. 条件数 κ=4 与 κ=100 的碗，为什么后者需要多得多的步数？给出收缩因子层面的解释。
注自测题答案
  1. 梯度是 a x，更新得 x - lr·a x = (1-lr·a)x，所以 ρ=1-lr·a。lr=2/a 时 ρ=-1，坐标每步变号但大小不变，在两点之间永远来回，不收敛。
  2. 方向 0：ρ=1-0.7×0.5=0.65，同号收缩；方向 1：ρ=1-0.7×2=-0.4，变号但绝对值缩小。两者都属于收敛，其中第二维是震荡收敛，整体 loss 仍会下降但参数来回跳。
  3. loss 只看平方，参数在碗两侧变号时 loss 仍可能逐点下降。打印 end_w 才能看出坐标是否在震荡、是否沿平的方向缓慢挪动；只看 loss 会把「参数反复横跳」误判成健康的平滑收敛。
  4. 同种子两次逐值一致，防的是程序用时间、地址等不可控随机源，保证可复现；换对照种子必须改变至少一个数值，防的是把整条轨迹硬编码进程序——那样同种子也一致，所以光跑两次不够。
  5. 收缩因子最接近 1 的那个方向决定总步数。κ=4 时取 lr=0.5，最平方向 ρ=0.75；κ=100 时最平方向 ρ=0.99。要把误差缩到 1%，前者约 (0.75)^k≤0.01 需 16 步左右，后者 0.99^k≤0.01 需约 459 步，差了近三十倍。
