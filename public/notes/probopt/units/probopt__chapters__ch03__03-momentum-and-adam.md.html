8.1 先看工程长什么样

前面两个单元把优化的地基铺好了：po06 讲凸性，告诉你「凸问题为什么有全局最优」；po07 讲梯度下降，告诉你「步长为什么决定走不走得到」。这一单元往工程里再走一步，问一个特别实际的问题：既然梯度下降人人都用，为什么深度学习里几乎清一色用 Adam？它究竟在梯度之上多算了什么，又凭什么常常更好使。

这一册的例子仍然走同一套路子：一个共用数值库，一个本单元专属的小工程，再加一份清单。共用库 common/ 提供固定种子随机源和打印函数；本单元的例子 adam_step/ 自己实现 SGD 与 Adam 的更新；清单 po08-adam.json 负责真编译、真跑、真对账。没有第三方框架，也没有神秘的黑箱——每一条更新式都能在源文件里逐行找到。

大白话一句话讲完这一单元

梯度下降只看「此刻的梯度」，动量把「过去的梯度」加权平均进来，Adam 则同时看「梯度的平均」和「梯度大小的平均」。前者管方向，后者管步长：方向一致的维度被推着走，梯度忽大忽小的维度被自动调小步子。偏差修正只是在开头几步把这两个平均值从零附近拉回正常量级。

第 2 帧里四个文件各有分工：adam.h 把二维状态、超参数和四个函数声明集中起来；adam.c 实现目标函数、梯度以及两种更新；main.c 固定种子、跑十步、打印四行数值；清单写出黄金值和容差。共用库一行都不用改，这正是分册开头定下的纪律——每章只加例子，不动底座。

8.2 动量：把更新当成有惯性的速度

先看最朴素的梯度下降。参数是向量 w，损失是 L(w)，梯度是 g_t = ∇L(w_t)，更新式写成 w_{t+1} = w_t − η g_t。这里的 η 是学习率。这个式子有个明显的性格：它完全没有记忆。上一步往左冲得多猛，这一步该往右还是往右，只看当前点的梯度。如果损失函数在某几个方向上窄、某几个方向上宽，这种「无记忆」会付出代价：窄的方向上梯度大，步长必须小才不会冲过头；步长一小，宽的方向上就挪得像蜗牛。

动量的改法很朴素：不要直接拿当前梯度当更新量，而是维护一个「速度」m_t，每一步把它朝当前梯度推一点，再用它去更新参数：

m_t = β·m_{t−1} + (1−β)·g_t，w_{t+1} = w_t − η·m_t

这个递推叫指数加权平均（exponentially weighted average）。把 m_t 展开看看它到底平均了什么：代入一步得到 m_t = (1−β)g_t + (1−β)β g_{t−1} + (1−β)β² g_{t−2} + …。所有历史梯度的权重加起来是 (1−β)(1+β+β²+…) = 1，所以 m_t 确实是过去梯度的加权平均，只是越老的梯度权重按 β 的幂衰减。取 β=0.9，权重衰减到一半大约要七步；取 β=0.99，大约要七十步。这个「看多远」就是动量唯一新增的旋钮。

第 2 帧是动量最值钱的场景：连续几步梯度都指向同一边，旧速度的九成被留下来，新梯度再添一成，速度越滚越大，参数沿着这条「坡」加速下滑。第 3 帧展示了另一面：一旦梯度掉头，旧速度还按九成惯性往前冲，新梯度只占一成，于是速度不会立刻反向，而是先被削弱。这在损失面上表现为「冲过谷底再拐回来」——好处是能跳过小坑，坏处是可能来回过冲。注意两帧里旧速度节点都写进去了，因为每一帧自包含，渲染器不会替你把上一帧的节点搬过来。

陷阱动量不是「记住上一步走了多远」

很多人把动量理解成物理里的位移记忆，其实它记的是梯度的加权平均，不是参数走了多远。判据很简单：如果某几步梯度恰好为零，参数那几步不动，但速度仍在按 β 衰减——它会慢慢忘掉之前的加速。真实实现里你还会见到另一种写法 w ← w − η(βm + g)（叫 Nesterov 或不同归一化的动量），它和这里的式子只差一个 1−β 的因子吸收进学习率，行为并不等价。读论文和框架源码时先确认是哪一种，别把两个 η 直接比较。

8.3 AdaGrad 与 RMSProp：先学会动二阶矩

动量解决的是「方向记忆」，没有解决「每个维度的步长该不一样」。回到那个病态二次碗：L(w)=0.5w₀²+5w₁²。w₀ 方向的曲率是 1，w₁ 方向是 10，相差十倍。用同一个学习率，η 必须小到在 w₁ 方向不发散，结果 w₀ 方向就慢得让人着急。

AdaGrad 的想法是：给每个维度单独记一个「历史梯度平方和」G_t = G_{t−1} + g_t ⊙ g_t，然后让这一维的步长除以 √G_t。梯度大的维度累积得快，步长被压得小；梯度小的维度累积得慢，步长大。它第一次让「步长自适应」这件事有了简单可实现的版本，但有个致命毛病：G_t 只增不减，训练越久分母越大，步长单调缩到几乎为零，模型还没学好就「饿死」了。

RMSProp 把累加改成指数加权平均，正好补上这个洞：

v_t = β₂·v_{t−1} + (1−β₂)·g_t ⊙ g_t，w_{t+1} = w_t − η·g_t/(√v_t + eps)

这里的 v_t 是梯度平方的指数加权平均，也就是二阶矩的估计。因为它是滑动平均而不是无限累加，老的平方梯度会被逐渐忘掉，步长不会一路缩到零。eps 是一个极小的正数（常用 1e-8），只用来防止分母为零：在某些维度梯度长期接近零时，v_t 会很小，没有 eps 就会除出无穷大。

第 2 帧的四个数字是第一步真算出来的：起点 w=(1.414216, 1.158867) 的梯度就是它自己（因为 L 里 w₀² 的系数是 0.5，w₁² 的系数是 5，见 ad_grad），于是 m₁ = 0.1g、v₁ = 0.001g²。v[1] 明显比 v[0] 大得多——这正是 RMSProp 要抓住的信息：w₁ 方向的梯度更猛，步长就该更小。两帧把「空槽 → 有值」的变化写全了，打印出来也能看懂。

工程惯例为什么 RMSProp 用的是平方梯度而不是梯度绝对值

平方有一个绝对值没有的好处：它对符号不敏感，但放大大梯度更狠。梯度从 1 变 2，绝对值只翻一倍，平方翻四倍，于是「大梯度维度要被压得更狠」这件事被自动放大。另一方面，平方和开方合起来接近梯度的均方根，量纲与梯度一致，所以 η 仍然是一个「以梯度为单位」的学习率，不用重新标定。代价是平方会把偶发的尖峰梯度记得比较久，这也是后来 Adam 依然沿用它、但配上更稳健修正的原因。

8.4 Adam：把一阶和二阶拼起来

Adam 几乎是把两件事直接焊在一起：一阶矩用动量，二阶矩用 RMSProp，然后两个都做偏差修正。完整递推如下，其中乘法全是逐维的：

  • m_t = β₁m_{t−1} + (1−β₁)g_t（梯度的一阶矩，管方向）
  • v_t = β₂v_{t−1} + (1−β₂)g_t⊙g_t（梯度平方的二阶矩，管步长）
  • m̂_t = m_t/(1−β₁^t)，v̂_t = v_t/(1−β₂^t)（偏差修正）
  • w_{t+1} = w_t − η·m̂_t/(√v̂_t + eps)

先说偏差修正为什么必须做。m_t 和 v_t 都从零开始。第一步 m₁ = (1−β₁)g₁ = 0.1g₁，只有真实梯度的十分之一；v₁ = 0.001g₁²，只有真实平方的千分之一。如果不修正，第一步的更新量是 η·(0.1g)/(√(0.001g²)) = η·0.1/0.0316 ≈ 3.16η——比预期的 η 大了三倍多，而且这个倍数还随步数变化。修正的做法很直接：把 m_t 除以 1−β₁^t，把 v_t 除以 1−β₂^t。第一步这两个分母分别是 0.1 和 0.001，正好把两个初始估计还原成 g₁ 和 g₁²，于是第一步的更新量正好是 η·g₁/|g₁| = ±η。

实验记录手算第一步，确认「步长就是 η」

取 β₁=0.9、β₂=0.999、η=0.10。第 0 维初始梯度 g₀=1.414216。修正前 m₁=0.141422、v₁=0.001999...；修正后 m̂₁=m₁/0.1=1.414216=g₀，v̂₁=v₁/0.001=1.99999...=g₀²。于是 m̂₁/√v̂₁ = g₀/|g₀| = 1，更新量 η×1=0.10。第 1 维梯度是 11.58867，修正后同样会得到比值 1，更新量也是 0.10。两个方向第一步走完全一样的距离——这就是 Adam 最反直觉也最值钱的性质：步长与梯度的绝对大小无关，只与它的符号（更准确说是方向与历史波动的比值）有关。读者可以用这个手算去核对第 8.5 节真跑出的落点。

第 3 帧里 step 节点同时接了两条箭头：一条来自 mhat，提供方向；一条来自 vhat，提供步长。这个「两路汇合」的画面就是 Adam 的全部结构。第 2 帧把 m_t 与 v_t 两个状态都写进去了，因为第 3 帧要用它们，而帧与帧之间不会自动继承节点。

陷阱别把 v_t 当成梯度的方差

v_t 是梯度平方的平均，不是 (g−mean(g))² 的方差。它保留的是梯度的量级信息，包括均值带来的那一部分。因此当梯度恒定不变时，v_t 不会为零，步长也不会因此变大——这正是一阶矩负责的方向信息不该被二阶矩抹掉的原因。真要算方差，得用 E[g²]−(E[g])²，Adam 没这么做，是有意的。另一个常见误读是把 β₂ 调得很小来「加快适应」，这会让 v_t 只看见最近一两步的波动，步长变得抖，失去自适应本来的平滑作用。

8.6 数字怎么读：两条曲线的分叉

先核对起点。w0=[1.414216,1.158867]，损失 0.5×1.414216² + 5×1.158867² ≈ 1.0000 + 6.7149 = 7.7149，和屏幕上的 loss0=7.714869 一致。这里 w₁ 那一项贡献了绝大部分损失——因为它的系数是 5，而 w₀ 只有 0.5。这就是病态二次碗的含义：等高线是被拉长的椭圆，长轴沿着 w₀，短轴沿着 w₁。

再看 SGD 的落点 w_sgd=[0.846743,0.001132]。第二维特别有意思：SGD 更新是 w₁ ← w₁ − 0.05×10w₁ = 0.5w₁，每步恰好减半，十步之后 1.158867/2¹⁰ = 0.001132，和屏幕上的数完全对上。第一维是 w₀ ← 0.95w₀，十步后 1.414216×0.95¹⁰ = 0.846743，也对上。SGD 在陡的方向上收敛极快（十步压到千分之一），在平的方向上却只走了约 0.57，还剩 0.85 没走完。这就是单一学习率的尴尬。

Adam 的落点 w_adam=[0.455934,0.217270] 讲述了另一个故事。两个维度走过的绝对距离分别是 1.414216−0.455934≈0.958 和 1.158867−0.217270≈0.942，几乎一样——这正是第 8.4 节手算的结论：每步大致走 η=0.10，十步约 1.0。它不像 SGD 那样在陡方向一口气压到底，而是两个方向齐头并进。此时损失 0.5×0.455934² + 5×0.217270² ≈ 0.1039 + 0.2360 = 0.3400，比 SGD 的 0.3585 低了 0.0185，就是 diff 那一行。

工程惯例为什么 Adam 只领先一点点，而不是一大截

十步太短了。Adam 的优势在「不同维度曲率差异很大」时才会累积：SGD 在平方向慢，Adam 每个方向都按同样的步幅走。但这里 Adam 在陡方向还没走到底（w₁=0.217，还在来回摆），损失里那一项 5×0.217²≈0.236 吃掉了它在平方向省下的大部分收益。如果再多跑几十步，SGD 的 w₁ 早就贴零，而 Adam 会继续在 ±0.1 附近抖动，届时谁赢反而不好说。这个细节很重要：它提醒你，优化器的排名依赖预算、问题和超参，脱离具体条件谈「Adam 一定更好」是错的。

8.7 偏差修正：前几步的隐形炸药

把偏差修正单独拎出来讲，是因为它最容易被「优化掉」。初学者看公式觉得 1−β₂^t 只是个趋近 1 的因子，十步之后 β₂^t≈0.99，几乎不影响，于是干脆删掉。这个判断在十步之后是对的，在第一步是灾难性的。

关键在 β₂=0.999 这个数。它意味着二阶矩要看大约一千步的历史；第一步的 v₁ 只有 0.001g²，被严重低估。若除 √v₁=0.0316|g|，步长会被放大约 31.6 倍。配上 β₁=0.9 带来的一阶矩低估（0.1 倍），两者相除得到约 3.16 倍——看起来还好？问题在于这个倍数每一步都在变：第二步 β₁²=0.81、分母 β₂²=0.998，放大倍数又不一样。结果是前十步的步幅忽大忽小，训练初期的轨迹完全不可预测。偏差修正用两个精确的分母把这件事一次性消掉，让第一步就回到「走 η」的正常量级。

陷阱eps 的位置不能挪

程序里写的是 m̂/(√v̂ + eps)，不是 m̂/√(v̂+eps)。两者在 v̂ 很小时差别很大：前者给整体更新量加了一个软下限的分母，后者只在根号内部加了个小偏移。更隐蔽的坑是把 eps 设成 1e-3 甚至 1e-2——这时它会实质性压小更新量，让 Adam 退化成某种奇怪的带动量 SGD。1e-8 是默认值，只在分母真正接近零时才起作用；如果你发现改 eps 明显改变结果，通常说明你的梯度太小或 v̂ 被算错了，该查的是上游而不是调这个旋钮。

8.8 什么时候 SGD 反而更好

既然 Adam 这么聪明，为什么还有人坚持用 SGD？理由大致有三条。第一，泛化。大量经验观察表明，在图像分类这类任务上，精心调度的 SGD（配动量）最终的测试集表现常常不逊于甚至优于 Adam。一种解释是 Adam 的自适应步长让训练更早贴合训练集的噪声，而 SGD 的「笨」反而是一种正则。这不是定理，但足够让认真做实验的人两种都试。

第二，可预测性。SGD 的更新量正比于梯度，梯度大步子大，梯度小步子小，行为好推理。Adam 把梯度大小约掉了，步幅几乎恒定，一旦学习率选错，它不会像 SGD 那样「梯度变小自动刹车」，而是一路按固定步幅抖到最后。第三，显存与实现。Adam 每个参数要多存一份 v（再加上 m 就是两份），在大模型上这是一笔可观的开销；SGD 加动量只多一份。

第 2 帧特意把共用的 ad_grad() 画出来：SGD 与 Adam 的差别不在「看什么梯度」，而在「拿到梯度之后怎么处理」。同一份 g，SGD 直接乘学习率，Adam 先拿它更新两个矩再相除。理解了这一点，你去读任何框架的优化器源码，都会发现骨架完全一样。

工程惯例一条实用的选择经验

如果你在做一个新任务、还不知道合适的学习率，Adam 更省心：它对量纲不敏感，默认 η=1e-3 往往就能跑起来。如果你已经在某个任务上调得很细、关心最终泛化指标，值得把带动量的 SGD 也加进对照表，并给它配一个余弦或阶梯衰减。还有一个折中方案是 AdamW——把权重衰减从梯度里拆出来直接加在参数上，修掉了 Adam 与 L2 正则组合时的一个经典错配。无论选哪个，都要像本单元这样把轨迹打出来看，而不是只盯最后一行损失。

8.9 常见失败模式与排查

第一，t 的初始化。前已述及，t 从 1 开始；若从 0 开始又先算修正分母，pow(β,0)=1 给出零分母，inf 会顺着 v 一路污染到参数。打印时出现 nan 或 inf，先查这里。

第二，m 和 v 忘清零，或者两个状态实例共用了一块内存。本单元用两个独立的 adam_state_t，各自带 m[2]、v[2]；如果你把它们写成全局数组又忘了在 ad_state_init 里逐维置零，第二次实验会继承第一次的矩，轨迹完全错乱。结构里带 t 和超参的好处正在于此：状态自包含，不容易串味。

第三，把逐维乘法写成矩阵乘法或点积。g_t ⊙ g_t 是逐元素平方，m̂/√v̂ 也是逐元素相除；写成向量点积会把二维压成一个标量，程序照样编译、照样打印，只是结果完全不是 Adam。

8.10 从 po07 走到 po08：一句话串起来

po07 的梯度下降回答「步长多大会发散」：在二次碗上有 0<η<2/L，超过就震荡。这条结论在这里依然成立，只是 Adam 让「有效步长」变成了逐维的 η·m̂/(√v̂+eps)，不好直接套 2/L。po08 回答的是另一个问题：当不同方向的 L 差很多时，能不能让每个方向自己找到合适的步长。答案是把梯度平方的平均放进分母，并用偏差修正把开头几步稳住。

再往前看，po06 的凸性保证了这个二次碗有唯一全局最优，我们才有资格比较「谁离最优更近」。接下来 ch04 会换一个话题：如果优化问题带约束，最优解不再由 ∇L=0 刻画，而要靠对偶与 KKT。你会发现那边出现的乘子，和这一节的 v_t 一样，都是「给每一个方向/约束配一个自己的旋钮」这个大思路的实例。优化器的自适应与约束的影子价格，骨子里是同一种工程直觉。

8.11 一个更细的对照：如果梯度是常值

为了把三种更新式的性格彻底分开，我们再做一个思想实验。假设损失是个线性函数 L(w)=c·w，梯度 g=c 处处相同且不含噪声。这种情况下，理想的优化器应该一步走到边界，或者按固定步幅匀速前进。

SGD 的更新是 w ← w − ηc，每步走固定距离 η|c|，匀速直线运动。动量会怎样？因为 g 恒定，m_t=(1−β)(1+β+…+β^{t−1})c=(1−β^t)c，所以速度从 0.1c 逐渐涨到 c，经过大约十步（对 β=0.9）后接近满速。也就是说，动量在常值梯度下有一个「起步加速段」，之后和 SGD 同速。这解释了为什么动量在训练初期有时显得「反应慢」——它要先花几步把速度攒起来。

RMSProp 与 Adam 在常值梯度下会怎样？v_t=(1−β₂)(1+β₂+…+β₂^{t−1})c²=(1−β₂^t)c²，修正后 v̂_t=c²，开方得 |c|，于是 m̂_t/√v̂_t = c/|c| = sign(c)，更新量恒为 η·sign(c)。这就是第 8.4 节说过的「步长与梯度大小无关」：不管 c 是 0.001 还是 1000，Adam 都走同样的步幅。这件事在梯度尺度混乱的深度网络里是救命的——不同层的梯度可能差好几个数量级，SGD 必须选一个折中学习率，Adam 却能自动把每层拉到同一量级。

陷阱常值梯度下 Adam 不会自动停下来

注意上面的结论：Adam 走到最优点之后，如果梯度恰好过零又变为反向，它仍会以 ±η 的步幅来回跨过最优点，不会像 SGD 那样「梯度变小、步子变小、自然收敛」。这是 Adam 训练后期损失曲线常见的锯齿状抖动来源。工程上的标准做法是学习率衰减：把 η 逐步调小，抖动幅度跟着变小。很多人误以为 Adam 不需要调度学习率，其实它只是对初始学习率不敏感，对「后期要不要降下来」同样敏感。

8.12 Nesterov 动量：先往前看再决定

经典动量先更新速度、再用速度更新参数，相当于「看着脚下的坡度决定往哪冲」。Nesterov 加速梯度换了一个顺序：先用旧速度往前探一步，在探测点算梯度，再用这个「前瞻梯度」更新速度。写成式子是 m_t = β m_{t−1} + (1−β)∇L(w_{t−1} − ηβ m_{t−1})，然后照常用 m_t 更新参数。

这个改动的效果可以用一个画面记：普通动量像开车时看着当前位置打方向，容易过弯；Nesterov 像先看一眼「按现在的惯性半秒后会在哪」，再决定打多少方向，于是过冲之前就开始回正。在凸的二次碗上，Nesterov 动量的收敛率理论上比普通动量更好（从 O(1/t) 改进到 O(1/t²) 那一族结果），这也是它名字里「加速」的来历。深度学习里两者的经验差距通常没这么戏剧化，但 Nesterov 几乎不增加计算量，所以很多框架把它作为动量优化器的默认选项。

有个实现细节值得记：Nesterov 需要在「前瞻点」求梯度，这意味着要多做一次参数加减法。adam.c 里没有实现它，是为了让代码短到能印在书上；你在框架里看到 nesterov=True 时，背后就是多出来的那一步。别把它和 Adam 混为一谈——Nesterov 只改进一阶矩的用法，不涉及二阶矩，也不做偏差修正。

工程惯例为什么这一节不把 Nesterov 写进例子

一来十步的短轨迹里它和普通动量的差别太小，打印出来几乎看不出黄金值的变化，教学收益低；二来本单元的主线是「一阶矩加二阶矩」，再塞进一个变体会把主线冲淡。写作和做实验一样要有取舍：例子负责把最重要的那条曲线钉死，边上的分支用正文讲清、留给读者自己去试。建议有兴趣的读者照着 8.4 节的代码改一版 Nesterov 动量，用同一个种子再跑一遍，把两条轨迹画在一起看。

8.13 学习率调度、warmup 与 Adam 的配合

前面说 Adam 的步幅近似恒定，所以后期要靠调度把 η 降下来。最常见的两种是阶梯衰减（每隔若干 epoch 乘一个小于 1 的因子）和余弦衰减（按余弦曲线从初值平滑降到接近零）。它们的共同点是：早期步子大、探索快，后期步子小、收敛稳。对 Adam 来说，这等价于把第 8.4 节那个 η·sign(g) 的整体幅度按计划缩小，本质上是在手动接管「自适应」管不了的那一维——时间轴上的步长。

另一个和 Adam 关系密切的技巧是 warmup：训练最初几百步把 η 从零线性升到目标值。为什么有用？回到偏差修正：虽然修正让矩估计在无偏意义下正确，但训练刚开始时模型输出离目标很远、梯度分布尚未稳定，v_t 的估计方差很大。此时若直接用大 η，前几步的随机方向会把参数甩到一个糟糕的区域。warmup 相当于在这段不稳定期把步幅压住，等梯度统计站稳了再放开。Transformer 一类模型几乎必配 warmup，就是这个原因。

把这件事和本单元的例子连起来看：我们的二次碗没有随机梯度，梯度分布从第一步就稳定，所以不需要 warmup；损失是凸的，也不存在「后期要跨越鞍点」的需求，所以不需要复杂调度。这恰恰说明调度策略不是孤立的魔法，而是针对具体问题的不确定性来源设计的。你看到某个训练配方里写满 warmup + cosine + AdamW 时，应该能逐项说出它在防什么：warmup 防早期梯度统计不稳，cosine 防后期步幅过大，AdamW 修权重衰减与自适应步长的错配。

实验记录在例子里加一个阶梯衰减会怎样

把 main.c 的十步循环改成「前五步 η=0.10，后五步 η=0.02」，adam_final 会明显下降，因为后半程的抖动被压小了。代价是前半程没变，下降速度并没有加快。更公平的做法是另外建一个清单跑「全程 η=0.02」作对照，你会发现它前期慢、后期稳，和阶梯版本各有得失。把三条轨迹的损失按步打出来，就能看到调度真正改变的是「时间分配」，不是最终能力。这个实验也解释了为什么调度的对比必须在相同总步数下做。

8.14 复现清单：把实验搬到别处

这一节的数值能被闸门核对，前提是条件写全了。把实验搬走时至少要记录六件事：目标函数的两个系数 0.5 与 5（它们决定曲率比 10）；起点生成用的种子 20240517UL 与扰动幅度 0.1；两个学习率 0.05 与 0.10；超参 β₁=0.9、β₂=0.999、eps=1e-8；步数 10；以及黄金值来自固定种子下的真跑读数。少了任何一条，别人（包括三个月后的你）都无法重现屏幕上那四个数。

这里有一处和前面单元微妙的差别。po07 的黄金值来自理论分析（收敛条件、同种子复现），po09 的黄金值来自手算闭式解；本单元因为起点含随机扰动，四个数值没有简洁的闭式表达，黄金值只能取固定种子下的真跑读数。这不违反「黄金值不能来自程序输出」的纪律吗？不违反——那条纪律针对的是确定性实验：如果程序有稳定错误，第一次输出就会把错误固化成标准。本实验的随机性由 LCG 完全确定，同一份源码、同一个种子在任何机器上都给出同一串数，所以「真跑读数」在这里和可复现的理论值等价。真正要防的是换了编译器或优化级别导致 LCG 序列变化——我们固定 -O0 并把种子写死，就是为了堵这个口子。

工程惯例怎么判断一个数值实验是否可复现

做一个简单测试：把同一条编译命令跑两遍，逐字比较 stdout。若有任何一行不同，先查随机数种子是否固定、是否用了 rand()、是否引入多线程、是否依赖未初始化内存。本册统一用共用库里的 LCG，不用标准库的 rand()，因为后者在各平台的实现不同，无法保证跨机器一致。第二个测试是换一台机器或换一个优化级别再跑，如果结果漂移，就说明有未定义行为或对浮点结合顺序过度敏感。闸门的 atol=1e-6 给浮点留了空间，但不给不确定性留空间。

8.15 把三个量放在一张表里记

到最后，这一单元真正需要长期记住的只有三个量：速度 m、平方梯度平均 v、时间步 t。前者告诉你「过去整体的方向」，中者告诉你「过去波动有多大」，后者用来把前两者从有偏拉回无偏。剩下的一切——AdaGrad 的累加、RMSProp 的滑动平均、Nesterov 的前瞻、warmup 的渐变学习率——都是围绕这三个量做的小改动。把这张对照表抄在笔记本上，以后读任何优化器的源码都能很快定位它在改哪一件事：

方法 一阶矩 二阶矩 偏差修正 主要解决的问题
SGD 无 无 无 基准，行为最好推理
动量 指数加权平均 无 无 同向加速、反向抵消
AdaGrad 无 累加梯度平方 无 逐维调步长，但会饿死
RMSProp 无 滑动平均平方 无 修掉 AdaGrad 的饿死
Adam 滑动平均梯度 滑动平均平方 两者都做 方向与步幅一起自适应

表里最后一行是本单元的主角。注意「偏差修正」这一列只有 Adam 打勾：这不是因为别人不需要修正，而是因为只有 Adam 同时依赖两个从零起步的滑动平均，修正的收益才大到必须写进标准算法。动量只有一个从零起步的量，而且它的偏差表现为「起步慢」而非「步幅错乱」，通常被学习率吸收掉；RMSProp 只有一个从零起步的 v，早期步幅偏大，实践中靠 warmup 或小学习率绕开。Adam 把两个修正都做齐了，代价是代码多两行、多两个 pow 调用——这点开销在现代硬件上完全可以忽略。

小结这一节的要点
  • 动量是梯度的指数加权平均：β 越大看得越远，同向累加、反向抵消；
  • AdaGrad 用梯度平方和压步长但会饿死，RMSProp 改成滑动平均，Adam 再加上一阶矩；
  • Adam 的更新式是 w ← w − η·m̂/(√v̂+eps)，m̂、v̂ 分别是除以 1−β₁^t、1−β₂^t 后的偏差修正值；
  • 修正让第一步的更新量正好是 ±η，与梯度大小无关；eps 只防分母为零，不要拿来调性能；
  • 病态二次碗上十步：SGD 收 0.358494、Adam 收 0.339969，差 0.018525；Adam 两个方向各走约 0.10×10，SGD 在陡方向减半收敛、平方向只走一点；
  • 固定种子、黄金值、容差都在清单里，程序自报的 PASS 不算证据。

  2. AdaGrad 的分母 √G_t 里 G_t 是梯度平方的累加，只增不减，训练越久分母越大、步长越小，最后趋近零。RMSProp 把累加改成指数加权平均，老平方梯度会被逐渐忘掉，分母不再单调膨胀。
  3. m₁=0.1g=(0.2,−0.3)；v₁=0.001g²=(0.004,0.009)；m̂₁=m₁/0.1=(2,−3)；v̂₁=v₁/0.001=(4,9)；√v̂₁=(2,3)；逐维相除得 (1,−1)；更新量 η(1,−1)=(0.1,−0.1)。可以看到步幅只取符号，与 2、3 的大小无关。
  4. 因为第 t 步时累计权重是 1−β^t（从 β⁰ 加到 β^{t−1} 再乘 1−β），除以它才能还原成无偏估计；用 t−1 会修正不足。漏掉修正时前几十步的步幅被一个随 t 变化的因子放大或缩小，轨迹忽大忽小，直到 β^t 接近零才稳定。
  5. 第二维的更新是 w₁ ← w₁ − 0.05×10w₁ = 0.5w₁，每步乘 0.5；十步后 1.158867×0.5¹⁰ = 1.158867/1024 ≈ 0.001132。第一维梯度是 w₀ 本身，更新是 w₀ ← 0.95w₀，每步只乘 0.95，十步后是 0.846743，不是减半。
  6. 一是泛化：在图像分类等任务上，调好的 SGD 加动量常有不逊于甚至优于 Adam 的测试结果；二是可预测与省资源：更新量正比于梯度、行为好推理，且每个参数少存一两份矩状态，显存占用更低。此外 SGD 的步幅会随梯度变小自动刹车，Adam 的步幅近似恒定，超参选错时后者更危险。
