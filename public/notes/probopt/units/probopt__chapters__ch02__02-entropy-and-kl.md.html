5.1 先看工程长什么样

前面四个单元里，我们已经会用采样看期望、用似然看训练。这一单元换一个角度：不看「一次观测有多可能」，而看「整个分布有多难猜」。这件事在深度学习里有个极其具体的落点——分类模型的损失函数就是交叉熵，而交叉熵与 KL 散度只差一个熵项。

这一节先不谈公式，先看盘上多了哪些文件。共用库 common/ 从第 1 单元起就在，里面已经装好了 po_entropy、po_kl、po_cross_entropy 三个函数；本单元要做的，是把它们搬到一个能真跑的例子里，再加一层「逐格差分」的本地代码，好让恒等式不是一句口号，而是屏幕上能读出来的四行数字。

大白话先建立一个画面

把离散分布想成一张有四个格子的表格：每个格子写着一个结果的概率。熵问的是「这张表整体有多难猜」；KL 问的是「如果我以为分布是 q，真实却是 p，我平均要多惊讶多少」；交叉熵问的是「用 q 给 p 的结果打分，平均要付多少代价」。三句话看着不同，算出来却被一条恒等式牢牢绑在一起。

第 1 帧是这一节开始时的形态：ch02 的两个目录都还空着。第 2 帧是结束时的形态：多了 entropy_probe/ 一个项目，里面有头文件、本地算法、驱动和清单。注意共用库不在 + 标记里——它不是这一节新增的，前面四个单元一直在用。这是我特别想让你养成的读图习惯：只看带 + 的行，就能知道这一节到底往盘上加了什么；第 2 帧里那四个加号，正好对应清单 sources 里要写的几个文件的一部分。

清单里的 sources 写三样：src/main.c、src/entropy.c、../../common/src/probopt.c。头文件不进 sources，它靠 flags 里的 -Iinclude 与 -I../../common/include 被两个源文件找到。这个「声明放头文件、定义放源文件」的分家不是标准规定，是工程惯例：头文件说清「这一层能干什么」，源文件说清「到底怎么干」，驱动 main.c 只管打印。代价是你要学会写 include guard，还要保证头文件里的声明与源文件里的定义一字不差。

5.2 熵：给「难猜」记账

先给结论：熵是意外程度的平均值。用一个结果发生的概率 p 定义它的「惊讶度」I(p) = -log p。概率越大，惊讶度越小；必然事件的概率是 1，惊讶度是 0。这里的对数默认取自然对数，单位是 nat；取以 2 为底的对数，单位就是 bit，两者只差一个常数因子 ln 2。本册统一用自然对数，所以后面看到的熵都在 1 点几的量级，而不是几 bit。

为什么偏偏是对数？因为它把「独立事件的惊讶度可以相加」这件事写进了公式。两次独立抛硬币都出正面的概率是 ½ × ½，惊讶度却是 -log(½) + -log(½)——概率相乘，惊讶相加。这是对数唯一的定性选择：若你想要「独立则相加」，又希望惊讶度随概率单调下降，除了差一个正比例系数，只剩下 -log。

熵 H(p) 就是所有结果的惊讶度按概率加权平均：H(p) = Σᵢ pᵢ · (-log pᵢ)。这个求和符号有两种读法。代数读法：它是四个数加起来；概率读法：如果你反复从 p 里抽样，长期平均下来的惊讶度会趋近它。第二种读法把这一单元接回了第 1 单元的期望——熵就是随机变量 I(X) 的期望。

第 2 帧里我特意把「惊讶」和「贡献」分开写：惊讶只由这一格自己的概率决定，贡献还要乘上它出现的概率。很多初学者把两者混成一件事，于是算四格分布时会把四个 -log pᵢ 直接相加，得到 0.693+1.386+2.079+2.079=6.238，比正确答案大出五倍。第 3 帧的箭头提醒你：熵是加权和，不是裸和。

把本例的四格代进去，手算过程是这样的：p=(0.5, 0.25, 0.125, 0.125)。第一格 -0.5×log(0.5)=0.5×0.693≈0.346574；第二格 -0.25×log(0.25)=0.25×1.386≈0.346574；第三、四格各 -0.125×log(0.125)=0.125×2.079≈0.259930。四项加起来是 0.346574+0.346574+0.259930+0.259930=1.213008，正好是程序打出来的 h_p。这组数选得巧：前两项恰好相等，因为概率减半带来的惊讶增加，被权重减半抵消了。

工程惯例为什么均匀分布是「最不确定」的

四格分布里，熵最大的是四格各占四分之一，此时 H = log 4 ≈ 1.386294。这不是巧合，而是熵的基本性质：在格子数固定时，概率越平均，熵越大；概率越集中，熵越小；退化成某一格概率为 1 时，熵是 0——结果已经写死了，没什么可猜的。深度学习里常用它做直觉检查：一个 softmax 输出接近均匀分布，说明模型还没学会区分；输出接近独热，说明模型很确定。要注意「很确定」不等于「对」，模型也可能非常自信地错。

5.2.1 熵与编码长度：为什么「难猜」可以量成位数

如果觉得「惊讶度」太抽象，可以用一个更接地气的说法替代：熵是最优编码的平均长度。假设四个结果出现的概率分别是 0.5、0.25、0.125、0.125，你要给它们分配二进制码字，让接收方无歧义地解码。概率大的结果应该用短码，概率小的用长码，这才是划算的分配。

对这一组概率，一套最优的码长分配是 1、2、3、3 位：第一格用 0，第二格用 10，第三格用 110，第四格用 111。任何一个码字都不是另一个的前缀，所以读完一个码字就能立刻知道结果，不必等后面的位——这叫前缀码。平均码长是 0.5×1 + 0.25×2 + 0.125×3 + 0.125×3 = 0.5+0.5+0.375+0.375 = 1.75 位。把刚才算出的熵 1.213008 nat 换成 bit，除以 ln 2 ≈ 0.693147，得到 1.750000 bit，两者严丝合缝。

这不是巧合。香农的源编码定理说：对任意分布，最优前缀码的平均码长 L 满足 H₂(p) ≤ L < H₂(p)+1，其中 H₂ 是以 2 为底的熵。码长取 ceil(-log₂ pᵢ) 就能落在这个区间里，本例因为概率都是 2 的幂，-log₂ pᵢ 恰好是整数，所以取到等号。这条定理给了熵一个不依赖任何心理学术语的解释：它就是在告诉你，平均每个结果至少要写多少位。

工程惯例为什么深度学习不用 bit 而用 nat

以 2 为底时，熵直接等于最优编码位数，解释起来最漂亮；可是在求导时，底数为 2 的对数会多出一个 1/ln 2 的常数因子。深度学习里每一步反向传播都要算这个导数，带着它既不影响方向又平添噪声，所以框架默认用自然对数，于是交叉熵的单位是 nat。换算关系只有一条：bit 数 = nat 数 / ln 2。本例 1.213008 nat = 1.75 bit。读文献时若看到「每个 token 的熵是 3.2 bit」而你的程序打 2.22，先做这个换算，再怀疑实现。

5.3 从惊讶到 KL：两个分布差多少

现在问一个更实际的问题：真实分布是 p，我却用一个模型分布 q 去描述它，代价有多大？把「惊讶度」里的概率换成 q，但加权仍按真实出现的频率 p 来算，得到的就是交叉熵 CE(p,q) = -Σᵢ pᵢ log qᵢ。它回答的是：真实世界按 p 抛出结果，我按 q 的惊讶度去记账，平均账目是多少。

KL 散度则是这份账目相对于「用真实分布自己记账」多出来的部分：KL(p‖q) = Σᵢ pᵢ log(pᵢ/qᵢ)。把它拆开就是 Σ pᵢ log pᵢ - Σ pᵢ log qᵢ = -H(p) + CE(p,q)，移项得到本单元最重要的一条恒等式：

CE(p,q) = H(p) + KL(p‖q)

这句话值得读三遍。它说交叉熵由两块构成：一块是真实分布自己的熵，与模型无关；另一块是模型分布偏离真实分布带来的额外代价。训练模型时 p 是固定的数据分布，所以 H(p) 是常数——最小化交叉熵，等价于最小化 KL 散度。这正是「分类损失为什么是交叉熵」的第一层答案：它量的就是模型分布与真实分布的差距。

陷阱你会在纸上把 KL 当成「两个分布的差」

拿到 KL(p‖q) 这个写法，新手很容易以为它是某种对称的「距离」，于是写下 KL(p‖q) = KL(q‖p)。真相不是这样。取 p=(0.9,0.1)、q=(0.5,0.5) 手算：KL(p‖q)=0.9×log(0.9/0.5)+0.1×log(0.1/0.5)≈0.368064；反过来 KL(q‖p)=0.5×log(0.5/0.9)+0.5×log(0.5/0.1)≈0.510826。两个数差了将近四成。你会被坑到的地方是：把 q 当成「近似 p」时，用哪个方向决定了你惩罚哪种错误——KL(p‖q) 在 p 大的格子上更敏感，KL(q‖p) 在 q 大而 p 小的格子上更敏感。模型蒸馏里这两个方向对应不同的教学策略，不能随手交换。

5.4 四格分布：把恒等式按格拆开

现在把镜头拉到四个格子上。程序里 p=(0.5,0.25,0.125,0.125)，q=(0.25,0.25,0.25,0.25)。因为 q 是均匀分布，log qᵢ 对每一格都是 log 0.25 = -1.386294 的常数，于是 CE = -Σ pᵢ log qᵢ = 1.386294 × Σ pᵢ = 1.386294。这一格都不用逐项算，概率和为 1 就直接给出结果。熵刚才算过是 1.213008，两者相减得到 KL = 0.173287。三个数刚好构成一条可手算核对的证据链。

第 2 帧藏着一个极容易误读的现象：KL 的第三、四格贡献是负数 -0.086643。这并不违反「KL 非负」——非负说的是四项总和非负，不是每一项都非负。原因也很直观：pᵢ log(pᵢ/qᵢ) 里，当 pᵢ < qᵢ 时 log(pᵢ/qᵢ) 为负，这一格就在给总分「减分」；但概率更大的格子（这里是前两格）会给出更大的正分，最后总账仍是正的。前两格 0.346574 + 0 大于后两格 0.086643 × 2，净剩 0.173287。记住这个画面：KL 是「得分与扣分相加后的净账」。

本地算法文件 src/entropy.c 做的正是这件事：它不替换共用库，而是补上共用库没有的「逐格差分」。ent_cell_terms 把每一格的熵贡献和 KL 贡献分别写进两个数组，ent_identity_gap 则把共用库的三个函数组合起来算恒等式残差。

驱动 main.c 把四行关键数打出来，其余信息用冒号行给出。选冒号不选等号，是这一册反复强调的纪律：流水线把 key=value 行当数值行做容差对账，而 p:[0.500000,...] 不是合法数值，会被判成普通文字逐字比较。这样闸门只对四个真正的数值行做容差，其余行不该被误伤。

真跑得到的 stdout 贴在下面。identity_ce_eq_h 打印的是残差 CE - H - KL，不是布尔值；它等于零，才说明恒等式成立。用残差而不是「是/否」，是为了让闸门能用 atol=1e-6 对账——布尔值没法做数值容差比较。

实验记录闸门怎么证明这四个数不是编的

清单 po05-entropy.json 用 mode=numerical，在 expect.numbers 里写了四个黄金值：h_p=1.213008、kl=0.173287、ce=1.386294、identity_ce_eq_h=0.0，各给 atol=1e-6。闸门做三件事：按清单的三源文件命令真编译真跑；从 stdout 解析出四个 key=value 行；把真实值与黄金值、正文输出块与真实 stdout 分别比对。想在正文里把 ce 改成 1.4 让故事更顺，会立刻收到 numeric_value_mismatch。容差只写在清单，正文写「约等于 1.39」不算证据。编译命令是 gcc -std=c17 -Wall -Wextra -Wpedantic -O0 -g -fdiagnostics-color=never -Iinclude -I../../common/include src/main.c src/entropy.c ../../common/src/probopt.c -lm -o /tmp/po05-entropy.exe，你也可以手动跑一遍。

5.5 KL 为什么非负，又为什么不是距离

非负性不是实验观察，是能证明的。取不等式 ln x ≤ x - 1（等号仅在 x=1 时成立，因为 ln x - x + 1 在 x=1 取最大值 0）。令 x = qᵢ/pᵢ，两边乘 pᵢ ≥ 0 并对 i 求和：Σ pᵢ ln(qᵢ/pᵢ) ≤ Σ pᵢ (qᵢ/pᵢ - 1) = Σ qᵢ - Σ pᵢ = 1 - 1 = 0。左边正是 -KL(p‖q)，于是 KL(p‖q) ≥ 0，等号当且仅当每个格子 pᵢ = qᵢ。这条证明只用了对数的基本不等式，不依赖分布有多少格。

再看对称性。距离要求 d(p,q)=d(q,p)，KL 不满足，刚才 0.368064 与 0.510826 的例子已经说明。它还要求三角不等式，KL 同样不满足。所以数学上的正确名字是「散度」（divergence），不是「距离」（distance）。这个区别在工程里不是咬文嚼字：如果你要做「两个模型输出相差多少」的对称比较，用 KL 就要明确方向，或者改用对称化的 ½[KL(p‖q)+KL(q‖p)]。

第 2 帧的箭头提醒你：交换方向不是「换种写法」，是换了另一个问题。第 3 帧的对称化值 0.439445 只是把两个方向的数平均，它满足对称性，但严格说仍不保证三角不等式——如果你真的需要数学意义上的距离，请用 Jensen-Shannon 散度或 Wasserstein 距离。

陷阱别把「KL 的每一项非负」写进笔记

刚才四格分布的 KL 逐格贡献是 0.346574, 0, -0.086643, -0.086643，明明有负项。你会在两种场合被坑到：一是调试时看到负的逐格贡献，以为 log 算错了；二是写优化代码时想当然地给 KL 加「逐项 ≥ 0」的断言。真相是只有总和非负，证明用的也是求和之后才得到的 Σq - Σp = 0。逐项加断言的程序会在第三格直接报失败，而 KL 本身完全正常。

工程惯例一个常数带来的两种单位

若把对数换成以 2 为底，所有熵与 KL 都会除以 ln 2 ≈ 0.693147。本例的熵从 1.213008 变成约 1.750000，单位从 nat 变成 bit。惯例是：信息论课本偏爱 bit，因为和编码长度直接对应；深度学习框架偏爱 nat，因为求导时不带额外常数。这是惯例不是标准，代价是跨文献抄公式时容易漏掉换算因子——看到别人的交叉熵是你的 1.44 倍，先核对对数底，再怀疑实现。

5.5.1 用 KL 反证均匀分布的最大熵

前面说「均匀分布熵最大」靠的是直觉，现在可以顺手证明。令 u 是四格上的均匀分布，uᵢ=1/4。把 KL 的定义用在 p 与 u 上：KL(p‖u) = Σ pᵢ log(pᵢ / (1/4)) = Σ pᵢ log pᵢ + log 4 × Σ pᵢ = -H(p) + log 4。刚证明过 KL 总是非负，所以 -H(p) + log 4 ≥ 0，也就是 H(p) ≤ log 4 ≈ 1.386294。等号成立当且仅当 p = u。

这个证明好看在哪里？它把「最大熵」这个听起来要动用拉格朗日乘子的结论，变成了非负性的一次代换——而 KL 的非负性我们三行就证完了。更一般地，对 K 个格子的分布，上界就是 log K；格子越多，可能的分布越分散，熵的上限越大。这也解释了为什么一个词表为 5 万的分类器，其输出分布的熵最大约是 log 50000 ≈ 10.82 nat，而四格分布只有 1.386——上限随类别数对数增长，不是线性增长。

实验记录用四格数验证上界

本例 H(p)=1.213008，log 4=1.386294，差 0.173287；这正好等于 KL(p‖u)，也就是程序打出来的 kl。换句话说，屏幕上那个 KL 数值同时扮演两个角色：既是「用均匀分布近似 p 的代价」，又是「p 离最大熵还差多少」。程序里 q 选成均匀分布不是随便挑的，它让三个黄金值之间的算术关系变得一目了然。若你把 q 换成 (0.4,0.3,0.2,0.1)，ce 与 kl 都会变，但 ce - kl 仍等于 h_p；这正是恒等式的力量。

5.6 交叉熵为什么是分类损失

把恒等式接到训练上，逻辑链就闭合了。分类模型输出一个 softmax 概率 ŷ，真实标签在 K 个类别上是一个分布 y。把 p=y、q=ŷ 代入：CE(y,ŷ) = H(y) + KL(y‖ŷ)。训练时 y 是数据给的固定分布，所以 H(y) 是不随参数变化的常数，优化它没有任何自由度；剩下的 KL(y‖ŷ) 正是「模型分布偏离标签分布」的代价。这就是交叉熵损失的来源。

常见的独热标签让这件事更简单：如果 y 在第 c 格是 1、其余格是 0，那么 H(y) = 0，恒等式退化成 CE(y,ŷ) = KL(y‖ŷ) = -log ŷ_c。注意这里没有求和——所有 yᵢ=0 的格子都被权重抹掉了，只剩真实类别那一格。程序里的交叉熵函数也正是这么写的：它遍历所有格子，但只对 p[i] > 0 的项累加 -p[i] log q[i]，零概率格子不贡献。

第 2 帧说明了一个常被忽略的事实：即使你用的是独热标签，理论上仍然有「熵 + KL」两步，只是熵那一步恰好为零。第 3 帧的化简正是为什么分类交叉熵在代码里常写成一行 -log(softmax_logit[correct])。理解这一步，你才敢在标签平滑、知识蒸馏这些场景里把公式改回去：标签平滑让 H(y) 不再为零，蒸馏让 q 变成另一个模型的软输出，恒等式依旧成立，只是不能再省掉任何一项。

陷阱为什么不用均方误差做分类

你可能会问：预测概率和标签做差再平方，不也能训练吗？能，但梯度性质差很多。设 softmax 后面接均方误差，梯度里会带一个 ŷ(1-ŷ) 的因子；当模型非常自信地预测错（比如 ŷ≈0 而标签是 1），这个因子接近零，梯度几乎消失，模型反而学不动。交叉熵的梯度化简后是 ŷ - y（softmax 与 log 相消），错得越离谱梯度越大，正好是训练想要的形状。你会被坑到的场景是：看到 loss 一直不降，以为是学习率太小，其实是损失选错，梯度被饱和因子吃掉了。

实验记录在四格上验证「独热让熵项为零」

把本例的 p 换成独热 (1,0,0,0)，q 仍是均匀分布。此时 po_entropy(p,4) 返回 0，po_cross_entropy(p,q,4) 返回 log 4 ≈ 1.386294，po_kl(p,q,4) 也返回 1.386294——恒等式仍然是 CE = H + KL，只是左边的 H 变成了零。你可以把 main.c 里的 p 改掉，用清单同一条编译命令真跑一次，再把三个数值行的黄金值按真跑输出更新；不改清单黄金值就跑，闸门会报 numeric_value_mismatch，这正说明它对数值变化是敏感的。

5.6.1 softmax 与交叉熵的梯度为什么会相消

上一节说交叉熵的梯度不会饱和，这里把账算细一点，你会看到 -log 与 exp 是一对精心挑选的搭档。设模型最后一层的 logits 是 z₁…z_K，softmax 给出 ŷⱼ = exp(zⱼ) / Σₖ exp(zₖ)，损失是 L = -Σₖ yₖ log ŷₖ。先对外层求偏导：∂L/∂ŷⱼ = -yⱼ/ŷⱼ。再求 softmax 的雅可比：∂ŷⱼ/∂zₘ = ŷⱼ(δⱼₘ - ŷₘ)，其中 δⱼₘ 在 j=m 时是 1、否则是 0。

两项相乘并对 j 求和，用链式法则得到 ∂L/∂zₘ = Σⱼ (-yⱼ/ŷⱼ) · ŷⱼ(δⱼₘ - ŷₘ) = -yₘ + ŷₘ Σⱼ yⱼ。因为标签分布的总概率 Σⱼ yⱼ = 1，最后化简成 ∂L/∂zₘ = ŷₘ - yₘ。分母 ŷⱼ 被 softmax 雅可比里的因子 ŷⱼ 约掉了——这就是「相消」。梯度就是预测减真实，形式简单到几乎没有可写错的地方。

相反，若把损失换成 Σⱼ (ŷⱼ - yⱼ)²，外层导数是 2(ŷⱼ-yⱼ)，再乘 softmax 雅可比，得到的是带 ŷⱼ(δⱼₘ-ŷₘ) 因子的表达式。当 ŷₘ≈0 时整个梯度被压到几乎为零，模型对自己极度自信的错判反而收不到修正信号。你会被坑到的场景是：训练初期学习率设得偏大，softmax 很快饱和到接近独热，随后 loss 卡住不动；这时把损失从均方误差换成交叉熵，往往一步就救回来。

工程惯例这条推导在代码里长什么样

主流深度学习框架把「softmax 加交叉熵」合成一个算子，前向直接算 logsumexp(z) - z_c，反向直接返回 ŷ - y。合成的理由有两个：一是数值稳定，二是少一次显式的概率构造。本单元的例子把概率当作已知输入，所以可以坦然地调 po_cross_entropy；真正训练网络时要走融合算子的路。你现在记住的应该是那条最终梯度 ŷ-y——以后看反向传播代码，看到它从 softmax 层冒出来，就知道上游用的是交叉熵。

5.7 数值稳定：log 0 到底躲在哪里

公式里的 log 0 有两张面孔，必须分开看。第一张在熵里：-p log p 当 p→0 时极限是 0，所以数学上约定 0 log 0 = 0。共用库的 po_entropy 写得非常直白——先判 if (p[i] > 0.0) 再累加，零概率格子直接跳过。本单元本地文件里的 ent_safe_log 用同样的思路：对非正输入返回 0，让调用方不必到处写判断。程序最后那行 zero_cell:[...] 就是用冒号行提示这件事，因为它是说明文字，不该混进数值对账。

第二张面孔在交叉熵和 KL 里，危险得多。CE(p,q) 要对 log qᵢ 求值；若某个 pᵢ > 0 而 qᵢ = 0，这一项就是 +∞，整个损失爆炸。更隐蔽的是 softmax：如果 logits 很大，exp(logit) 可能溢出成 inf，再除一下得到 nan，nan 有传染性，一旦进 loss，后续所有梯度都变 nan。深度学习框架里的标准做法是 log-sum-exp 技巧：在算 softmax 之前先减去所有 logits 的最大值，保证指数不超过 1；再把交叉熵写成 logsumexp(logits) - logit[correct]，避开显式构造概率再取对数这一步。

第 2 帧的「下限裁剪」是把 qᵢ 夹到 [ε, 1-ε]，ε 取 1e-8 之类的小数；「标签平滑」是把独热标签混一点均匀分布，让 qᵢ 不至于真是零。两者都会在损失里引入一点偏差，这是为了数值稳定付出的代价，不能当成免费午餐。

工程惯例自己制造一次 nan 看看

在 C 里直接写 log(0.0) 不会崩，只会返回 -inf；再拿它参与运算，很容易得到 nan。你可以写三行临时代码验证：printf("%f\n", log(0.0));、printf("%f\n", 0.0 * log(0.0));，前者打 -inf，后者打 nan（IEEE 754 下 0 × ∞ 不是 0）。这解释了为什么共用库不直接写 p[i] * log(p[i])，而要先用 if 把零概率挡在外面——它防的正是这个 nan。注意本单元的输出块里没有任何 inf 或 nan 字样，因为数值行必须是有限十进制数，否则闸门报 numeric_value_invalid。

5.7.1 log-sum-exp：把稳定性做进公式里

现在把上一节提到的技巧写成公式。给定一组 logits z₁…z_K，直接算 log(Σ exp(zᵢ)) 有两个风险：zᵢ 很大时 exp(zᵢ) 溢出成 inf；zᵢ 很小且全部接近负无穷时求和下溢成 0，再取对数得到 -inf。解决办法是平移不变性：令 m = maxᵢ zᵢ，则

log Σᵢ exp(zᵢ) = m + log Σᵢ exp(zᵢ - m)

因为 exp(zᵢ) = exp(m)·exp(zᵢ-m)，提出 exp(m) 后对数把它变成加性的 m。平移之后所有指数都不超过 exp(0)=1，绝不会溢出；至少有一项等于 1，所以求和也不会是零。交叉熵于是写成 L = m + log Σᵢ exp(zᵢ-m) - z_c，其中 c 是真实类别。三个量都在有限范围内，这就是框架里融合算子的真实做法。

要强调一点：这个技巧改的是计算路径，不是数学函数。它算出来的值与朴素公式在实数域完全相同，只是每一步都不越过浮点的边界。本单元的例子没有走这条路，因为输入已经是合法的四格概率，不存在 exp 溢出；但只要你开始写自己的 softmax 交叉熵，它就从「可选的优化」变成「必需的防崩措施」。

陷阱先归一化再取对数，是最常见的错误顺序

有人觉得「既然 softmax 已经把 logits 变成概率，那我直接 log(prob[c]) 就好」。问题在于 softmax 内部若已溢出，prob[c] 本身可能就是 nan，再取对数毫无意义。正确顺序是让对数直接作用在 logits 上，也就是上一节的融合公式。另一个细节：exp(zᵢ-m) 里那一格等于 1，所以 log Σ exp(zᵢ-m) 至少是 0，整个损失不会凭空冒出负号。把这两条记住，你就避开了分类损失实现里最常见的两类数值事故。

5.8 三个最常见的误解

第一，把熵说成「一条消息的信息量」。熵是分布的期望惊讶度，不是某一条消息的属性。单次结果的惊讶度是 -log pᵢ，熵要把所有结果按概率平均。说「这句话的熵很高」在严格意义上不对，除非你先说清楚这句话来自哪个分布。

第二，把交叉熵和 KL 当成两个可以随便挑的损失。它们只差一个与模型无关的常数，优化上等价，但数值不同。读论文时若看到别人报的 loss 比你小一个固定值，先算算是不是少加了 H(p)，而不是怀疑训练技巧。

第三，以为「最小化 KL」一定让模型分布变尖。方向决定行为：KL(p‖q) 要求 q 在 p 大的地方不能太小， tends to 覆盖模式（mode-covering）；KL(q‖p) 要求 q 在 p 小的地方也不能大， tends to 聚集到主模式（mode-seeking）。变分推断里这两个方向对应 ELBO 与期望传播的不同取舍，词汇可以以后再学，方向感现在就要建立。

陷阱用采样估计 KL 会踩的坑

第 1 单元讲过期望可以用采样估计，于是有人写程序从 p 采样，用 -log(q(x)/p(x)) 的样本均值估 KL。这要求你能对任意样本算出 p(x) 和 q(x)，而且方差可能很大；更糟的是，如果样本里出现 q(x)=0 的点，单次估计就是无穷。本单元的例子直接用解析公式算四格分布，就是为了避开这个坑：格子少、概率已知时，解析求和既准确又便宜。采样估计留给维度高到没法求和的场合，而且要额外做平滑。

5.9 把这一节接回全书

往回看，第 1 单元的期望给了熵「长期平均惊讶度」的读法；第 4 单元的最大似然给了「乘积变和」的技巧，而交叉熵的 -Σ p log q 正是负对数似然的期望形式。所以分类训练里那句「最小化交叉熵等于最大化条件对数似然」不是巧合，是同一个 -log 在两种说法里的现身。

往前面看，第 6 单元讲凸性，会给这里的「最小化交叉熵」补上为什么能找到全局最优的回答：对线性模型加 softmax，交叉熵关于参数是凸的；但换上深层网络，凸性就没有了，只剩「交叉熵这个损失本身形状好」这一点仍然成立。第 8 单元讲动量与自适应方法，会在这条损失曲线上演示优化器怎么走。本单元的四个数值——熵、KL、交叉熵、恒等式残差——是后面所有这些实验的度量单位。

5.10 温度、蒸馏与策略约束：同一把尺子的三种用法

交叉熵与 KL 不只出现在分类器训练里，它们后面还有几条很活跃的支线，值得现在就看一眼，因为用的全是本单元的同一套公式。

第一条是温度缩放。给 logits 除以一个正数 T 再过 softmax，得到 qᵢ ∝ exp(zᵢ/T)。T>1 让分布更平，T<1 让分布更尖。直观解释是：除以 T 缩小了 logits 之间的差距，softmax 对差距敏感，于是差距被抹平。模型校准里用温度把过度自信的概率拉回来，常配一个小验证集来选 T；采样生成里调温度则是在「保守复现」与「大胆探索」之间滑动。注意温度不参与本单元四格例子的计算，它作用在 logits 上，而不是已经算好的概率上。

第二条是知识蒸馏。教师模型给出软分布 p，学生模型给出 q，训练损失里有一项 KL(p‖q)（常写 KL(p_T‖q_T)，两边都用同一温度）。因为教师的软分布里藏着「哪些类别比较像」的信息——比如一张猫图，教师给豹 0.2、给汽车 0.001——这种暗知识是独热标签没有的。蒸馏时通常会把 KL 项乘 T²，原因是在温度为 T 时 KL 的量级大致按 1/T² 缩小，乘回去才能让梯度与硬标签项的量级可比。这一条你只要记住「有一个 T² 的补偿因子」就够，推导留到以后。

第三条是策略模型里的 KL 约束。强化学习里更新策略时，不希望新策略偏离旧策略太远，否则一次坏更新就毁掉训练。做法是在目标函数里加一项 -β KL(π_old‖π_new)，或者干脆约束 KL 不超过某个阈值。这里的 KL 充当的是「信任区域」的尺子——它量的正是本单元说的「两个分布差多少」。方向依旧重要：用哪个方向的 KL，决定你更怕「新策略丢了旧策略的高概率动作」还是「新策略冒出了旧策略几乎没有的动作」。

工程惯例一把尺子贯穿三处

温度改的是分布形状，蒸馏改的是训练目标，策略约束改的是更新幅度，但它们的度量工具是同一个：概率分布之间的交叉熵与 KL。这就是为什么这一单元值得花 120 分钟——后面读到任何「用 KL 约束」「用交叉熵训练」的句子，你都能立刻还原出它在量什么、方向是什么、数值大概什么量级。反过来，如果只把交叉熵背成「分类损失的那个公式」，这些场景就都成了互相无关的黑话。

5.10.1 互信息：熵的下一步

还有一个概念会在后面的分册里反复出现，它就是互信息。定义很简洁：I(X;Y) = H(X) - H(X|Y)，意思是「知道 Y 之后，X 的不确定度减少了多少」。用本单元的语言说，如果 Y 对 X 毫无帮助，条件熵 H(X|Y) 就等于 H(X)，互信息为零；如果 Y 完全决定 X，条件熵为零，互信息就等于 H(X)。所以互信息的单位是 nat（或换算成 bit），它量的不是「相关性」而是「信息量的转移」。

互信息还有一个等价写法：I(X;Y) = KL(p(x,y) ‖ p(x)p(y))。右边是联合分布与「假设两者独立时的联合分布」之间的 KL 散度。这句话把这一单元的三样东西全串起来了：KL 量两个分布的差距，独立假设给出一个特定的分布，而互信息就是这个差距的名字。因为 KL 非负，立刻得到 I(X;Y) ≥ 0，等号当且仅当 X 与 Y 独立。回想第 2 单元讲过「独立必不相关，不相关未必独立」——互信息补上了这一课：它为零确实等价于独立，比相关系数强得多。

在深度学习里，互信息出现在几个地方。互信息神经网络训练里想最大化输入与隐表示的互信息，让表示尽量保留输入信息；信息瓶颈理论想最小化隐表示与输入的互信息、同时最大化与标签的互信息，逼出紧凑又相关的表示；聚类里的归一化互信息用来比较两个划分是否一致。这些应用的共同点是：它们都要估计一个高维分布之间的 KL，而精确求和不可行，于是又绕回采样估计——也就是第 1 单元那条路，但这次要面对方差大的麻烦。

工程惯例为什么相关系数为 0 不能说明独立

第 2 单元给过反例：取 X 在 [-1,1] 上均匀，令 Y=X²，两者显然高度依赖，但相关系数是 0——因为正负抵消了。互信息不会犯这个错：Y 一旦知道，X 的不确定度明显下降（只剩正负两个候选），所以 I(X;Y) > 0。你可以把这个例子记成一道分水岭：相关系数只看见线性依赖，互信息看见一切依赖，代价是它难估得多。本单元提供的工具是概念与公式，真要估计高维互信息时，请期待后面采样单元的进一步讨论。

小结这一节的要点
  • 熵是惊讶度 -log p 按概率的加权平均；均匀分布不确定度最大，确定事件熵为零；
  • CE(p,q) = H(p) + KL(p‖q)：训练时 H(p) 是常数，最小化交叉熵等价于最小化 KL；
  • KL 非负但不对称、不满足三角不等式，逐格贡献可以是负数，只有总账非负；
  • 独热标签让 H(y)=0，交叉熵化简为 -log ŷ_c；softmax 后接均方误差会因饱和因子导致梯度消失；
  • log 0 在熵里由跳过零概率格子解决，在交叉熵里要靠平滑或裁剪；数值行的 inf/nan 会被闸门拦下。

  5. 程序里 log(0.0) 与 0.0 * log(0.0) 分别得到什么？共用库的 po_entropy 用什么办法避开了它？
注自测题答案
  1. 逐格算：-0.5×log0.5≈0.346574，-0.25×log0.25≈0.346574，两个 -0.125×log0.125≈0.259930，合计 1.213008。前两格相等是因为概率减半使惊讶度增加 log2，但权重也减半，两者恰好抵消。
  2. 非负说的是四项总和非负，不是逐项非负。关键一步是用 ln x ≤ x-1，令 x=qᵢ/pᵢ 并乘 pᵢ 求和，得 Σ pᵢ ln(qᵢ/pᵢ) ≤ Σqᵢ - Σpᵢ = 0，即 KL ≥ 0；等号仅当逐格 pᵢ=qᵢ。
  3. 不相等。本例 KL(p‖q)≈0.368064、KL(q‖p)≈0.510826。方向决定敏感区域：KL(p‖q) 惩罚「p 大处 q 太小」，倾向于覆盖所有模式；KL(q‖p) 惩罚「p 小处 q 不小」，倾向于聚集到主模式，所以蒸馏时选哪个方向会改变学生模型的行为。
  4. 独热标签 H(y)=0，于是 CE(y,ŷ)=KL(y‖ŷ)=-log ŷ_c，只剩正确类别那一格。均方误差的梯度带 ŷ(1-ŷ) 饱和因子，模型错得越离谱、因子越接近零、梯度越小；交叉熵化简后梯度是 ŷ-y，错得越离谱梯度越大。
  5. log(0.0) 返回 -inf，0.0 * log(0.0) 得到 nan（IEEE 754 里零乘无穷不是零）。po_entropy 先判断 p[i] > 0.0，只对正概率格子算 -p log p，零概率格子直接跳过，从而避开这个 nan。
